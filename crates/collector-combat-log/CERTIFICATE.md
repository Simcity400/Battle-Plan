# Retained Combat Log certificate

The retained-history baseline belongs to the exact play-session load signal.
An attach, explicit refresh, branch change or lost publication revokes it.
Initial acquisition joins the existing manager/group walk and uses that walk's
authenticated group header and array order. Only battle indices reached by
those references are acquired. The active-combat census is independent of
this retained-history certificate.

| State | Complete mutation boundary | Acquisition |
|---|---|---|
| Group identity, manager country and order | Creation-only append call, group destruction | The appended result and manager operands; lookup hits incur no observation. Destruction removes the receiver and reproduces manager swap removal. |
| Own equipment month membership | Own pool and single-variant writers; result publication for the normal route's inline combat write | Only the settled last month header; quantities reuse CombatLogEquipment. |
| Recovered month membership | Recovered equipment writer | Only the settled last month header. |
| Enemy equipment | Enemy writer and result publication's inline enemy write | The settled reached month and its ordered variant entries. |
| Manpower | Manpower writer, including nonterminal callers | Only the settled last manpower entry and all three signed counters. |
| Templates | Total-counter mutation tap, shared by existing and newly appended entries | The writer's reached entry. Wins has settled; the displaced total increment is reproduced with native wrapping arithmetic. No history search. |
| Group references and acquisition count | Result publication, including normal results with no activity | Only the appended ordinal, side byte and reached slot identity. |
| Prefix pruning | Group prune before/after counts for its nine arrays | Nine counts before and after; remove only the corresponding retained prefixes. No payload scan. |
| Group destruction | Destructor entry, before native references and storage are released | Remove the receiver lifetime. Native reference releases are observed separately. |
| Battle record allocation/replacement | Battle allocator entry and return | Copy the source's scalar fields and its own serialized arrays before the native move. Associate its returned slot without reading any other slot. |
| Battle reference release and free occupancy | Reference-release return | Stage the reached slot identity. The acquisition worker reads each changed slot's settled count and occupancy once after deduplication. Zero-count records are invisible; the native allocator certifies replacement of a free slot. |
| Pool reset and save load | Pool reset and battle persistence loader | Reset drops the old lifetime map; loading invalidates the baseline. The next explicit full acquisition seeds the loaded state. |

Pool growth relocates existing objects without changing their value or slot
identity. The allocator's source is staged before it can be moved or reused.
Group addresses and month/template addresses are collector-private lifetime
keys. Destruction removes them before reuse. Native group ordinals, repeated
reference ordinals, full template and equipment handles, signed counters and
serializer omission gates are retained independently.

All producer storage is reusable and sized off-thread from the initial seed
and complete attempted event demand. Producers reserve individual fixed
elements without allocation or waiting. A capacity failure, guarded-read
failure, hook publication gap, overlapping writer/drain, unmatched allocation
or escaped unwind revokes the certificate; no partial interval becomes an
empty successful table. There is no dirty-group reread fallback. Conversion
consumes owned facts only and performs no deferred pointer dereference.

Hook publication authenticates each purpose-named sentinel before publishing
the complete family. Restoration covers every hook and tap executable range.
Active native calls and escaped unwinds prevent unloading. Storage replacement
excludes producers with the handoff gate and the active-call count; the worker
holds storage ownership across its drain. Replaced storage is freed off-thread.

The drain returns its own quiet revision with its loss counter. A later writer
cannot be silently included by taking a newer token after draining. Initial
seeding and count settlement require that same quiet revision throughout their
live reads; an overlap refuses the whole certificate. Reference-count capture
uses settled event demand rather than post-call values, so concurrent callers
cannot reorder stale count observations. Neither count reads nor decoder work
follow a game pointer from an earlier callback.


The existing active-loss census supplies live observer operands from its
already authenticated sides. Aggregate losses reuse its loss acquisition.
The existing finalizer copies supplemental observer operands after pending
damage flushes and before either side is deleted, into the existing reusable
land event word log. Its off-thread decoder requires one complete state per
side and rejects orphan terminal data. The active census publishes only an
operand-count capacity hint; there is no extra native sizing walk. Event
storage refusal invalidates that interval through the existing coverage row.
Publication and revision identities refuse before either integer wrap or the
publication lane's mark bits; lifetime identity can never silently repeat.

Acquisition transfers flat owned facts and settled counts in reusable frame
arenas. Only the explicit initial seed walks retained references. Recurring
acquisition neither applies the reducer nor validates or projects retained
rows. Batch sequence numbers advance before acquisition, so even a failed
acquisition that never publishes its batch cannot silently skip mutations.
Conversion rejects noncontiguous batches until a full seed, uses entry-identity
and manager-order indexes, and validates changed references and slots through
reverse membership. Prefix pruning rekeys only its affected collection;
destruction updates only the removed group and the manager's swapped group.
Replay row maps edit only reached entries. Encoder materialisation and old
snapshot retirement occur in conversion, outside acquisition and its lock;
pooled captures hold only flat facts, counts and projected cardinalities.
