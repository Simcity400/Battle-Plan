# collector-certificates

Writer certificates, dirty marks, owner-slice selection, sampled verification and held research drift. Stores require complete reads, stable epochs, successful publication and valid writer certificates. Native capture orchestration and collector feature defaults belong to the DLL host.

Fixed-width digest helpers inline across component boundaries so hourly
verification can specialize their eight-byte folds. The FNV byte stream,
length-prefixed text and signed-word representation remain unchanged.

Watch registries hash complete receiver keys, preserving dense country identities alongside aligned holder pointers.

Non-marking watch registries can transfer prepared growth under an exclusive native quiescent acquisition lease. The transfer preserves registered sequences, epoch and quiet token, allocates nothing, and retires storage for off-lease collection. Notifications, registration, boundaries and release are excluded during the transfer; offers, status and collection can continue. Marking registries retain their boundary protocol.

Read the [shared rules](../../AGENTS.md) and the [collector guide](../collector/README.md).

Run `cargo test -p collector-certificates` and `cargo clippy -p collector-certificates --all-targets -- -D warnings` for its synthetic checks.

Content reload forwarding shares the equipment and technology command boundaries
with dependent baselines. Both patch owners must be enabled; an absent receiver
adds no native reads or allocation.
Grouped comparisons can report every difference against the borrowed previous fixed-size entry before replacing it. Research retains separate list counts and per-kind counts/identity/value digests; the entry has 110 u64 groups (880 bytes per held country). The report callback runs only on a certified mismatch, without another snapshot allocation.
A running hook can inspect a registered dependency stamp only while its guard is the sole active writer and the registry state stays stable across the lookup. This supports before/after change proofs without admitting native acquisitions while any writer runs.

Bitmap notifications retain sequentially consistent entry/return marks and writer
counts. An already-set bit needs only its sequentially consistent load: an
earlier take needs the OR unless another writer already reasserted the bit,
and a later take consumes the existing mark.
Repeated writers therefore avoid redundant locked ORs without losing a return
mark, a sibling bit, or the running-writer refusal.

A marking notification exposes whether it found a prepared receiver slot. That
attributes a lost callback without another lookup; it does not certify a quiet
registry or a stable epoch, and absence is meaningful only under the consumer's
complete registration/publication proof.

Passive watch-sequence lookups certify only already registered receivers and never
register, drain marks or count refusals. The hinted passive lookup validates its
receiver against the current table and epoch, falling back to ordinary probing
without admitting a cold receiver. Presentation ranges use that certificate
directly: an already registered receiver needs no second, no-op registration.
Cold/full-table admission stays ordered. Frozen observations may then settle owned
rows on decode
without registering a receiver late or consuming another hour's marks.
