# dashboard-factions

One `faction_state` prepared family serves `faction-state` influence, rules and
manpower histories. It shares typed selected-hour readers with dashboard-base;
native row methods remain the numerical authorities.

Account shares are stored once per native account/country identity. Membership
is separate; retained associations need a supplying faction or preceding
membership witness. Gaps and replacements break continuity. Manpower keeps
repeated occurrences and its signed i32 wrapping total.

The shared block pre-pass folds changed inputs in order. Selection channels share
owner/ordinal validation and typed lane kinds. Fallback comparisons retain only
six shared faction table views, not whole frames. Series accumulators, catalogue
patches and continuations handle atomic publication and resume.

Queries read selected faction keys through the shared caches, preserve independent
known/read coverage and cold/pending prefixes, and check cancellation and the
reply budget. They never walk the branch. Selections are observed states, not
adoption or vote dates; programme names use their actual daily supplier. Content
failures retain the raw facts and counted warnings.

Run `cargo nextest run -p dashboard-factions` for the synthetic checks.
