# installed-content

Rust readers for the installed content used by recording, playback and save comparison. This crate owns content layers, identity verification, asset parsing and text-save parsing. It does not read live game memory.

## Responsibilities

Use the existing parsers under [src](src/) rather than adding a second parser in a consumer. Clausewitz text, descriptors, localisation and saves should keep consistent parsing rules; binary assets use their corresponding loaders. The application should not acquire a Python runtime dependency to parse installed content.

Script keys have one keyword test, `parser::Item::keyword`/`keyword_is`: the lexer gives a quoted key the token 0xF, never a keyword, and folds a bare one, so a reader asks the helper and never compares key bytes (a test in `parser.rs` checks the content readers; the few text compares it allows name their address). Items keep their operator (`=`, `<`, `>`, each one character to the lexer) and both token kinds.

Script content has one reader model, the token-level reader replay `parser::native`: CTextLexer::read_token (1424A7A90), ReadKeyOperatorValue (1424AC5E0), the CPersistent::Read loop (1424A9730) and the reader's `@name` table (1424AC830, 1424AB540), each file with its reader's own field dispatch (`native::Shape`) and its loader's lexer mode (`native::Mode`: only mode 1, which the character, name-list and division-name loaders use, skips a leading byte-order mark; the other content loaders use mode 0, where its bytes start the first token). The lexer reads a byte 0xFF as the end of the text and reads on after it, so a block's loop ends there and the reader around it goes on. Where the text leaves the tree's shape the reading follows the game's and names the place (`Read::misreads`). In a trigger body a coded trigger's key is read by its class's own value reader, one value or a body, from the executable's table ([trigger_keys.rs](src/trigger_keys.rs) `TRIGGER_CLASSES`). Known gap: a key that names no coded trigger (a scope, a content count or scripted trigger, or nothing), a coded trigger with a reader of its own, and every effect key are still read by key, because the content names and the effect classes are not known where those blocks are read; a block read by key (`Shape::ByKey`, `Shape::ByKeyAs`) holding a value without a key and a definition could be a list reader's or a reader by key's, so the rest of that file is `Read::unsettled` and refused by name, and a block the game skips as an invalid key has its definitions registered (the lenient side). A block under a modifier name is read as the recorded modifier registry decides (`modifiers::shape` with a `modifiers::Registry`: the modifier's value when the name is registered, else the skip), and refused by name (`modifiers::Undecided`) where the registry does not say. The GUI, sprite, font, effect and settings.txt readers (`gui::native`, `pdxshader`, `settings::SettingsKeys`) walk the same lexer and CReader (`parser::native::Reader`) token by token, and every integer and float conversion goes through `crt` and `fixed5`: one lexer, one CReader, one keyword table (`gui::native::keywords`) and one CRT for every script read. `parser::parse` (the tree) keeps its own lexer by the standing parser-unification decision: it is a different grammar (balanced blocks, machine-written saves, whose brace mismatch is corruption to refuse), and reads saves, the `.gfx`, `.asset`, `.font` and `.mod` formats for the consumers not on the native readers, and pdx_settings.txt. Content readers not yet moved onto the replay (the map, building, focus and technology readers and the viewer's map presentation readers) still read through the tree, which takes an `@name` as its own text.

Resolve content in recorded order: vanilla, DLC and mods. Support folder/archive layers and honor `replace_path`. Do not sort layers into a new order or let a convenient local file silently override the recorded content.

Content identity uses the versioned coverage policy and layer hashes. A local cache can avoid redundant hashing, but it must not weaken verification. Machine paths are local configuration, not portable replay identity.

A new recording takes the engine's mod order, not the launcher's list order: dependencies first, then descriptor path bytes (`native_mod_order` in [content.rs](src/content.rs), with the native addresses). Enabled mods that share a display name, which the engine mounts only one of, are an order note and leave the session unverified. The recording keeps the ordered DLC IDs and hashes, and each mod's Workshop `remote_file_id` (or local descriptor filename), display name, declared version and hash.

The collector verifies a session, modded or not, only when the game's successful search path equals the recorded layers in priority order, and the active DLC and mods are exactly the recorded ones. Memory names a mod by its descriptor file, so the recorder passes the file it resolved and hashed each mod from (`GatheredContent::mod_descriptors`), and the active set must be exactly those files. A verified session records the proven rosters in content IDs. Mount paths and descriptor files stay in the local `content.json` sidecar and collector configuration, outside the portable identity.

## Refuse mismatches clearly

The viewer must refuse missing or mismatching recorded content. An unverified identity is also refused unless the user explicitly enables `--allow-unverified-content`. That override does not waive hash checks. Its warning shows in the viewer's diagnostics mode and in the machine-readable outputs, and exported and captured images keep their UNVERIFIED CONTENT banner (owner decision, 2026-09-25).

Keep absent files, unknown data and parse failures distinct from valid empty values. Preserve exact fixed-point and integer representations for save comparisons. Do not fill missing runtime caches from guesses just because a text save cannot represent them; the oracle should state the limitation.

## Asset contracts

Loading an asset does not prove its bytes were verified. [content.rs](src/content.rs) owns the versioned coverage roots. `ResolvedLayers::read_uncovered` can load visual assets outside those roots, but those bytes are not hash-verified and the viewer must say so: in diagnostics mode and in the machine-readable outputs (owner decision, 2026-09-25). Covered paths still use normal verification. Do not remove this warning or expand the coverage policy incidentally during a rendering change.

Layer paths are bytes (`content::LayerPath`), as the game's virtual file system compares them: an archive member is indexed by its central-directory name bytes as PhysFS enters it (no code page, not the Info-ZIP Unicode path field; `\` made `/` only for a FAT-made member; the name ending at its first NUL) and found by exactly the requested bytes, a folder file by its UTF-8 name in any ASCII case, and `replace_path` is kept as the descriptor's bytes. `read_path` and `read_uncovered_path` look a path up by its bytes (`read` and `read_uncovered` are those of a text path); a path that is not UTF-8 opens no folder file, as PhysFS's UTF-16 conversion makes each invalid byte `?`. `listed_layer_paths` enumerates as the game does, by the layers' bytes: every archive member whatever its name, and every folder file, whose name is always UTF-8 (a folder path that is not UTF-8 never opens, so it is never listed); the GUI and GFX readers (`gui::native::read_layers`, `sprites::gfx_order`, through `defines::load_order_paths`) enumerate and read through it. The text listings (`paths`, `listed_paths`, `descriptor_paths`, `directory_files`) serve the text databases and list only the paths that are text. The layer hash frames each path's bytes, so an archive whose member names hold bytes above 0x7F without the UTF-8 flag (or a NUL, or a `\` from a non-FAT host) now hashes the names the game uses rather than the `zip` crate's code-page spelling: its layer hash changed with this, and a recording made before it does not verify against such an archive. That is accepted: recordings are not stable across formats before release.


Preserve palette indices and image origin in [BMP](src/image/bmp.rs), and authored mip levels, cube faces and original extents in [DDS](src/image/dds.rs). The viewer chooses linear or sRGB sampling for each resource's role; there is no correct blanket conversion for all textures.

A GUI texture is decoded only by [image/native](src/image/native/mod.rs), the game's `DecodeTextureImage` in its order: the engine's DDS loader, its own Targa loader for a `.tga` name, then the game's FreeImage 3.17 (content sniff over its six plugins; the BMP, ICO, JPEG, PNG, TARGA and DDS loaders with their conversions; libjpeg 9a as FreeImage drives it, libpng 1.6.16's transforms and colour-space checks). It reproduces what the game's loaders do rather than what the file format intends (a block texture's extent rounded to whole blocks, a 32-bit DDS read as BGRA whatever its masks, FreeImage's fast JPEG transform without fancy upsampling, its PNG transparency and gamma, an ICO drawn without its AND mask). Its tests hold vectors decoded by FreeImage 3.17.0's own release build. Every result is a texture, the game's own failure, or an outcome the file does not determine (uninitialised or out-of-bounds memory, the device), named with its cause; never a guess. The caller passes the client's `force_pow2_textures` (`image::native::Decode`, from `settings::SettingsKeys::texture_decode`): set, `pad_power_of_two` zero-pads each side to the next power of two, every mip level and block included, and the padded extent is the texture's size, which every sprite size and UV divides (the padding samples as the native format's zeroed texel: opaque black for 24-bit and 5-6-5 formats, transparent otherwise). A 16-bit DDS keeps its words as the game keeps them (`dds::TextureFormat::B5G6R5` and `B5G5R5A1`, the game's `B5G6R5_UNORM` and `B5G5R5A1_UNORM`, `X1R5G5B5` promoted to the latter): each channel samples as its value over its largest (`TextureFormat::sample_16`: a 5-bit 1 is `1/31`, never an 8-bit `8/255`), and the viewer uploads those exact `f32` values as `Rgba32Float`, on a device offering `FLOAT32_FILTERABLE` (else it is not drawn, never quantized: a viewer hardware requirement, named at start-up and in the viewer's diagnostics).

[Mesh and entity loading](src/mesh.rs) preserves field-by-field clone inheritance, subobjects, skeletons and attachment transforms. Unlabelled subobjects are not interchangeable with LODs. [Bitmap fonts](src/fonts.rs) and [localisation](src/localisation.rs) retain authored metrics, colour runs and glyph assets rather than approximating them with a system font.

## Native GUI reader

[gui/native.rs](src/gui/native.rs) reads the `.gui` files the way the game's GUI parser reads them, so a modded layout is read exactly as the game reads it. `gui::native::read_layers(&layers)` reads every file in the game's load order (`interface/load_screen.gui`, then every other `interface/**/*.gui`, each directory's files before its subdirectories) with one `Context`, whose counter names unnamed elements `unnamed_gui_<n>` across files as the game does, and runs the post-load pass; `Context::read(&bytes)` reads one file after the ones before it, and `read(&bytes)` one file as the first. A `Gui` finds a template as `CGui::FindGuiType` does (case-insensitive; a block's templates inserted in the game's batch order, a later block or file replacing), and each `Element` has its kind, native name (bytes), full path, `hide`, its `CGuiType` fields (`common`: tooltip hashes and anchor, hint tag, bound tooltip), typed fields with the native defaults, and its kept children in declaration order. `find(kind, name)` is the window-local lookup of one kind and `find_list_recursive` is `FindOverlappingElementsBoxRecursive`. Text fields are the token's bytes up to its first NUL, as the game's C strings hold them. `refusals()` and `subtree_refusals()` list what the game itself does not define (an invalid or undefined read, a walk that never ends, a crash, a heap overflow) or what depends on a value the replay does not hold (a heap or load address a component overwrote), each with the element's path, the key and the native address; a consumer refuses what it draws from an element with such a refusal. Every component a spill writes is followed to the end of its object or frame; none is refused because the reader stops. The native addresses are cited in the module; the lead's census (`gui_key_census.md`, section "Completions and corrections") tables every switch.

- Keywords. [gui/native/keywords.rs](src/gui/native/keywords.rs) is the lexer's keyword table: the 10,765 names `register_authored_keys@140082CB0` registers (`keywords.tsv`, this build's), then the startup dynamic tokens of the stack's `common/synchronized_dynamic_tokens` (`DynamicTokens::read`, added before any interface file is read). A key dispatches only when the table names it (`keyword_of`, bytes folded as the lexer folds them); a reader that tells a registered word from a string (0xF) asks `keywords::class`.
- Tokens. The one lexer, `parser::native::lex` (`lex_effect` for an effect file's `[[ ]]` code), in mode 0, the mode every GUI, sprite, font, effect and settings loader constructs it with: no byte-order mark is skipped (its bytes join the first word, so that key is unknown); a word whose first byte is a digit or `-` is a number before any keyword lookup (so `3dposition` never reaches its case); a NUL is a word byte, each consumer reading to it; a byte 0xFF is one end of the stream and reading goes on after it; at the stream's end the current token stays the last one.
- Key loops. [gui/native/reader.rs](src/gui/native/reader.rs) walks the one CReader, `parser::native::Reader` (its slots, script variables, loop step and skips), token by token. Every level is `CPersistent::Read`: a `}` or the end of the stream ends it; anything else goes through `ReadKeyOperatorValue`, whose key, operator and value persist across calls. An unknown key, or a kind a parent does not build, is logged and its block skipped; a key whose reader does not read the block it was given leaves the block to be read as further keys. Every reader runs on a stack of its own, so nesting is followed as deep as the file goes, and an element tree is dropped the same way.
- Numbers go through the one CRT, [crt.rs](src/crt.rs): `%i`, `%u` and `%x` accumulate at 64 bits (saturating on overflow) and store the low 32; `%f` reads decimal and hexadecimal floats straight to `float`, overflow giving an infinity, the failure forms storing nothing; `truncate_f32` is `cvttss2si`, `i32::MIN` for what it cannot convert. `atoi` is `fixed5::decimal_i32` and `ReadFixed5` `fixed5::script_fixed5`, digit by digit.
- Spills. `read_axis_components` and `ReadIntComponents` write component `i` at `start + 4 i` with no bound; [gui/native/spill.rs](src/gui/native/spill.rs) is the one place those writes land: each receiving object (a sprite type, a font, the gfx reader's frame, a grid, an edit box, a scrollbar type, a browser or curve graph) describes its bytes, so a component is stored into the field it lands on, is nothing when the game rewrites that field before reading it, and is refused only where it corrupts what the game later reads (a pointer, a vtable, a vector the destructor frees) or leaves the allocation. An MSVC `std::string` reached this way (`CxxString`) keeps its buffer, size and capacity as the game's string code reads them.
- Points. `ReadIntPoint` reads seven tokens through one uninitialised local: an icon's position, a button's `borderSize`, an edit box's `cursor` and a text block's points start from zero (the icon's then stored as floats), every other caller writes its field directly; a first value `%i` stores nothing of stores stack bytes, refused as undefined.
- Families. Every kind a container, a window or `guiTypes` builds is read with its own switch and kept: containers (with their hover, scroll, drag and sound keys), icons, the `CButtonType` kinds (`buttonType`, `checkboxType`, `guiButtonType`, `multiSpriteButtonType`, backgrounds and scrollbar or drop-down parts, every key), instant text boxes (with `bound_text`/`context_aware_text`), grids (a fifth `max_slots` component writing `add_horizontal`'s byte), overlapping lists, position types, list boxes, edit boxes (the components' slots as the game lays them), scrollbars (their children, the last of a name), extended scrollbars, drop-downs (their inner container), browsers, curve graphs, windows (every child kept; `Window::unlisted` names the `guiButtonType` and `multiSpriteButtonType` children read while `background` already named them, which go into no list), and `textBoxType` with its `CTextBlock`s. `CBoundLocalization` is read as its tree of nodes and arguments. The template-only kinds no parent builds (`radioButtonGroupType`, `scrollbargroupType`, `layout`, `dropDownMenuType`) are refused by name.
- The post-load pass. `CButtonType::vf10` copies an empty sprite through the `parent` chain in the parent's own name tree (a check box too) and parses the orientation text; a container's or grid's background, which no `vf10` reaches, keeps its orientation unset, while an extended scrollbar's background gets the lookup its scrollbar was given (`14235EB7F` keeps the incoming `RDX`). `CScrollbarType::vf10` copies unset fields through its chain. `CWindowType::vf10`, after its children's, copies whichever of `size`, `position`, `background`, `verticalBorder` and `horizontalBorder` is unset (a zero coordinate, an empty name) through its `parent` chain, a parent passed earlier giving its own result, then gives a `fullScreen` window the root's extent; a `max_resolution` axis is tested (and copied) as the value it holds, the reading client's own load-time GUI viewport less its number: `read_layers_at`/`read_at` take that viewport (the viewer's native GUI viewport, a dump's resolution); without it (`read_layers`, `read`) such a window is refused with `Cause::Unrecorded`. `Guis::text_box_named` tells whether a `textBoxType` has a name, which `create_sprite` may register as a sprite. A missing parent (a crash), a chain that ends or turns back (a hang), a parent of another kind (a type-confused read), and any list box with a `parent` (whose walk never ends) are refused.
- Map icons take no pointer (`map_entity_pass_b` passes no hit list), so their interactive fields are kept but inert.

## Native sprite, font and effect facts

[gui/native/sprites.rs](src/gui/native/sprites.rs) reads `interface/**/*.gfx` with the same lexer, key loop, scanners and variables: `read_sprites(&bytes)` per file (`read_sprites_with` adds the stack's dynamic tokens) and `read_layers(&layers)` over the stack in the game's order (the three bootstrap files, then the rest). Every sprite kind keeps every field its reader stores (`SpriteKind`): the plain family (`Plain`: texture, `%i` frames, the frame direction as the `+0x10C` integer, masking texture, `legacy_lazy_load`, the animation records the readers see, `dx_offset`, `anchor` and every field further components write: stretch, V scale, frame step, U flip, the texture id, the flags, each kind's tail; effect), the frame-animated, tile and masked-shield kinds over it, the cornered tile, the progress bar (both textures, both `CColor`s, size, steps, `horizontal`), the text sprite, the resizeable kind (`defaultAnimationTime` aliasing its frames), the circular progress bar, and the pie and line charts. The object kinds (`arrowType`, `animatedmaptext`, `pdxmesh`, `pdxparticle`) are walked as their readers walk them; a `meshsettings` key the table registers but `SMeshData::vf4` does not take skips its block, while a string key (a word the table misses, or quoted) skips nothing, so its block's `}` ends the settings early.

[gui/native/fonts.rs](src/gui/native/fonts.rs) keeps each `bitmapfont`'s facts (its file list as its `path` and `fontfiles` operations leave it, `color`, `border_color`, `icons_add_height`, `icon_scale`, its `textcolors`, its offsets), applies `bitmapfont_override` to the font the game finds when it is read, registers fonts in the game's 511 buckets (`Fonts::get_or_fallback` is `GetFontOrFallback`, fallback included), selects a language's family, and loads a family's glyph set from its `.fnt` files as `load_font` reads them (token by token, the first file winning per codepoint and kerning pair).

[gui/native/shader.rs](src/gui/native/shader.rs) names the one effect reader, [`pdxshader`](src/pdxshader/mod.rs), which reads an effect's `.shader` (its first `.lua` replaced) and includes from the stack (outside the hash's coverage, so unverified, as `read_uncovered` states): every stage's samplers (every key), constant buffers, vertex structs and code, the file's techniques and blend, depth and rasterizer states, and the SHA-256 identity of the file and each include. `Effect::sampler_slots` fills the slots as the game does (the common stage, then the pixel stage), `technique` and `blend` resolve under `_stricmp`. A missing file is `None`, the zeroed record the game falls back to, whose draw keeps the previous program and sampler.

[gui/native/resources.rs](src/gui/native/resources.rs) is the one resource path a GUI consumer draws through: `Registry::load(&layers)` holds every declaration (the latest of a name), the fonts and the global colour table; `create(name)` is `CreateGuiObjectBySpriteName` (the name, else `GFX_default_fallback_texture`, else nothing); `stack_texture` loads the texture a name resolves to (`.dds`, `.tga`, then the name, each opened by its bytes) through [image/native](src/image/native/mod.rs) under the client's `Decode`, or names why a defined sprite has none, telling the game's own failures (`native_failure()`: no name, no extension, no file, past 16 MiB, every decoder refusing the bytes) from an outcome the file or the recording does not determine (`Undefined`, `Device`), which a consumer refuses; `frame_extent` is the queried integer extent (truncating) and `frame_geometry` the floating frame size `build_geometry` draws; `Effects` caches effects.

Mesh material overrides use the first matching `meshsettings` row. An empty name matches any submesh; a named row matches the raw child ordinal or the signed `-1` wildcard. Empty texture/shader strings leave the original material field intact. A nonempty `shader_file` overrides every material variant's source. The reader distinguishes an absent material shader key from an authored empty value and retains raw child ordinals so auxiliary nodes cannot shift overrides onto the wrong material.

The compiled mesh adapter uses `native_skeleton`: the first nonempty source skeleton, with source-order records, byte parents and importer-scaled inverse-bind translations. It does not combine repeated LOD skeletons or reorder by `ix`. `Animation::frame_trs` exposes authored channels before matrix conversion. Entity `game_data` preserves texture animation speed, atlas dimensions and native allocation defaults; unsupported operands carry a named error for the shader consumer.

## Checking changes

Use existing parser and synthetic input tests plus the [shared local checks](../../AGENTS.md). Changes affecting layer resolution must exercise order, replacement and identity failures. Asset interpretation changes also need review against the [viewer rendering rules](../viewer/README.md#rendering-rules).

Localisation verifies and parses independent files with a fixed small worker pool, then merges results in the original layer/path order. Replace-file precedence and duplicate diagnostics remain unchanged; filenames never substitute for language-header parsing. Values are held as the game stores them (its five control bytes, doubled patterns as literals), so every consumer reads them through `Localisation::localise`/`localise_with` (the game's localiser, every argument form of its formatter included: the `*` and `^` thousands forms too) or `localise_bytes` (the localiser's raw output, for a text path that decodes it as the game's text path does) and `pieces` (its text layout) rather than looking for `§` or `$` itself.

Vanilla with the relevant DLC is the established first validation path; mod identity support is not proof that every mod combination has been tested. Live captures and large reference assets stay outside source control.

## Local cosmetic overrides

[content/visual.rs](src/content/visual.rs) reads installed mod descriptors using the shared parser, including folder and archive sources (archives through the same PhysFS reader, by their records' byte names). Eligibility uses the installed game's checksum_manifest.txt independently of the replay's broader content hash policy. A checksum-sensitive file conservatively excludes a mod; this is a file-policy check, not a live engine checksum comparison. Unsupported manifest forms are refused rather than guessed.

Cosmetic eligibility and renderer compatibility are separate: the initial overlay supports existing DDS/TGA/PNG/BMP artwork under gfx and map/terrain. Shader programs, GUI layouts, non-artwork files and replace_path mods are reported as unavailable instead of silently partially applied. File listing is bounded and cancellable; asset bytes are read only while constructing a selected map. The selector does not download Workshop content or edit the game's enabled-mod list.

Original layer hashes are verified before presentation overrides. Explicit selections remove supported recorded cosmetic layers from the presentation copy and overlay selected artwork in order; gameplay layers remain intact. Missing/invalid selected assets fail visibly. These overrides carry their own diagnostic warning and are not represented as recorded artwork.

[settings.rs](src/settings.rs) provides bounded, read-only access to the configured user folder's settings.txt through the shared Clausewitz parser. The desktop and map use this for inherited preferences; it never modifies the game file or reads live game memory. Every `settings.txt` key goes through `settings::SettingsKeys` (`read_keys`), which walks the file as the game does: the GUI reader's mode-0 lexer and `CPersistent::Read` key loop, each key folded and looked up in the registered keyword table (a key in any case dispatches, a quoted one does not), each object's cases as its `read_token` has them, and the `graphics` and `mapRenderingOptions` sub-objects walked by their own cases on the same reader (`size`/`min_gui` through `ReadIntPoint`). `assignments_at(path)` gives every occurrence in file order; `bool_at`, `i32_at`, `f32_at`, `string_at` and `point_at` give what the field holds once the file is read (a conversion that stores nothing keeps the field). The language, `camera_tilt`, `draw_map_full_res`, `force_pow2_textures`, the display settings and the dashboard's and desktop's inherited preferences are read through it; the generic parser reads only `pdx_settings.txt`.

For the map UI scale, `settings::Display` reads settings.txt's `graphics` block and then the launcher's pdx_settings.txt, in the engine's order: the scale is clamped at the end of every `graphics` block (`CGraphicsSettings::finalize_read@142214530`, each on the fields as that block left them; `Display::clamps`), pdx_settings.txt entries then change the mode, monitor and size in file order, and the window and interface layout follow the native rules cited beside the code. A field no conversion stored keeps the engine's constructor value and pdx values read as its `atoi` does; a stored value the viewer cannot lay out with, and `ReadIntPoint`'s uninitialised read, are refused. The game's command-line display overrides are not visible and not applied. `settings::desktops` lists the monitors in SDL's display order with their physical modes and effective DPI, which is why this crate depends on `windows-sys` on Windows; it refuses a thread that is not per-monitor DPI aware and a monitor whose DPI cannot be read, and it walks every display adapter, so callers read it off the frame path.

`focus.rs` reads national/shared/joint/continuous focus presentation definitions with the shared parser and recorded layer ordering. It reports malformed files individually. It also reads authored costs and literal focus-day defines; scripted values remain unavailable rather than executing Lua. Conditional icon scripts remain unavailable unless a static icon is authored. `image/rgba.rs` expands the shared DDS reader's BC1/2/3 blocks for bounded UI artwork, preserving alpha and cropping partial blocks; native map uploads retain their compressed path.

[defines.rs](src/defines.rs) evaluates every `common/defines/**/*.lua` of the stack on vendored PUC Lua 5.1, the game's runtime, in the native load order (byte-ordered names, files before subdirectories). The sandbox has no `io`, `os`, `package`, `debug` or file loaders and bounds the instruction count; a failing script refuses the reader rather than falling back to vanilla values. `fixed5` and `int32` reproduce the native fixed-point and integer getters; `text` reads string defines such as entity names. [flags.rs](src/flags.rs) is the engine's flag decoder, shared by counters, the combat UI and the dashboard: exact define-sized uncompressed Targas, always read bottom-up. `ResolvedLayers::uncovered_from_base` tells whether an uncovered file is still the base game's own.

Coverage policy 2 adds every `.asset` and `.gfx` below `gfx`: the engine registers entities, meshes and particles from all of them, so a mod that changes one changes the content identity. Meshes, animations and textures stay uncovered. [mesh.rs](src/mesh.rs) `Roster` reads every descriptor in recorded (layer, path) order and names repeated or cross-file-cloned entries, which consumers refuse; `TextureIndex` is the engine's `gfx/models` basename index for material textures, and a texture it cannot resolve refuses the mesh. [buildings.rs](src/buildings.rs) reads building types (including the authored `disable_grow_animation` popup exemption) and spawn buckets in the engine's database order, matches every bucket reference under the lexer's ASCII case fold, names the buckets a differing repeated declaration makes ambiguous, and keeps every declaration of such a type so a consumer can refuse it by name. Empty/comment-only declaration files contribute no types, including mod replacements; the complete database must still contain types. `Buildings::slot` is the one resolver of `map/buildings.txt` slot names and bucket references, as the engine resolves them: the first bucket, generated before explicit, whose name matches under the fold; a bucket a differing repeated declaration reaches is ambiguous and refused.

`ResolvedLayers::directory_files` lists one directory as a database loader does: no recursion, byte order of names. [train_gfx.rs](src/train_gfx.rs) reads the supply-train database and the graphical-culture registry with the engine's merge and lookup rules; the equipment types and archetypes its lookup names come from [equipment.rs](src/equipment.rs).

[equipment.rs](src/equipment.rs) is the one equipment reader. `Database` is `CEquipmentDatabase` as it loads: the three directories without recursion (`upgrades`, `modules`, then the root), every top-level reader of each file through the reader replay, a redefinition reset and read again, the duplicated archetypes generated where the file loop generates them, and what finalize sets after the last file (the default modules' categories, the model priority and parent depth). It keeps what every consumer reads: names and aliases (found without case, aliases installed after each definition and removed on redefinition), archetype, parent and family links, categories and allowed types, module slots and default modules, model, sprite and visual levels, and stats. `Groups` is `common/equipment_groups` as its reader keeps it, expanded as the game expands a member list, and `Database::group_admits` is the game's membership test. A form the replay does not model is refused by name, with the rest of the database unknown, and `load_complete` refuses such a database. The combat convoy bound, raid requirements and arrows, unit model selection, aircraft, trains and the save oracle all read it; no consumer re-reads or re-expands equipment files.

[weather.rs](src/weather.rs) resolves the `common/weather.txt` `weather_effects` entities to particles; the snow ceiling and permanent snow are recorded, not derived. [particles.rs](src/particles.rs) registers `pdxparticle` objects in gameplay load order: the three native startup interface files, the remaining `interface` descriptors, then `gfx`, with bytewise files-before-subdirectories traversal. The catalog preserves each object's type registration ordinal, independently of its particle-block name or texture. Every declaration consumes an ordinal; a later exact-name object registration replaces the lookup target, matching the native prepend-and-first-match registry. Case variants stay distinct. Particle blocks resolve by `name` from every `gfx/particles/**/*.asset`; a name declared twice is refused. `ResolvedLayers::descriptor_paths` lists effective descriptor files whatever the coverage policy.

The particle reader also preserves shader-facing subsystem metadata: native file/shader string bounds, signed texture tile counts, local-space flags and the `Trail` then `NoBillboard` technique suffixes. Consumers retain this identity even when several subsystems share a texture. Particle simulation, instance generation and retained GPU state belong to the viewer.

[ambient.rs](src/ambient.rs) reads the ambient file named by `map/default.map`, including native type defaults, fixed-point placement conversion and source-order routing into the always-visible list. Routing is distinct from the final type flag. Duration, signed spawn limits and DLC triggers survive for the consumer's admission logic; parsing them does not reconstruct an actor's presentation history.

[movement.rs](src/movement.rs) reads the static province movement map once from the files `map/default.map` names: native ordered neighbours (raster scan plus authored adjacencies, shared with `RailwayAdjacency`), each neighbour's fixed5 distance, crossing kind and arrow crossing, and each province's terrain flags and ordinal. `common/terrain/*.txt` is one database, read once by `terrain::read_definitions` in native order (`directory_files`): a redeclared category appends another entry, a lookup takes the first case-insensitive match, a graphical terrain's `type` resolves against the categories read before it and the last palette writer wins; river kinds use the define index ranges. A missing `adjacencies` key or file means no authored adjacencies, as in the engine. Unsupported content (definition IDs that differ from record positions, unknown kinds, non-8-bit rivers) is refused with a reason, and a neighbour whose sampling fails is listed as unavailable rather than guessed. The native evidence is in the module comments.

[resources.rs](src/resources.rs) reads each strategic resource declaration's icon frame from `common/resources` in load order, keeping a repeated token as another declaration as the game does; which resources exist and their order come from the recording.

`technology.rs` reads unambiguous equipment unlocks from authored technology definitions for generic name/description fallback. Multiple or scripted unlocks remain unavailable; later definitions without an equipment link clear earlier links. Resolution uses the shared parser and recorded layer ordering.

Politics content readers share [script_files.rs](src/script_files.rs) (a content folder's resolved files in native filename order) and [modifiers.rs](src/modifiers.rs) (the modifier readers' dispatch, `modifiers::shape`, and modifier blocks kept as authored: numbers and `yes`/`no` flags, values resolved as the replay reads them; `hidden_modifier` values are kept apart because they apply without showing; anything else, such as `[?value]`, stays `Unsupported` with its text):
- [ideas.rs](src/ideas.rs): `common/idea_tags` categories (slots, character seats, type, `politics_tab`, ledger, costs) and `common/ideas` ideas (group, law/designer/default, name override, picture, modifiers, targeted modifiers, equipment and research bonuses, traits, costs). A later definition of a token replaces the earlier one, with a warning. Conditions and effects are not evaluated.
- [characters.rs](src/characters.rs): advisor roles by idea token, country leader roles by (character, ideology), names and portraits by (category, size). Conditional `instance` alternatives are used only where they agree; an advisor role they disagree on is taken from the template a recorded holder was built from (`held_advisor`, by the file and line the game stores on it), else refused by name. The viewer's headquarters portraits use the same parser. `leader_templates` lists every character template the game builds (one per character block or leading `instance`, in the database's file order) with the file and line the game stores on it and its unit leader role `visible` trigger, so the raid triggers evaluate the template a recorded character was built from; [parser.rs](src/parser.rs) `parse_unclosed_lines` gives the block lines it needs. Forms the loader would misread are refused by name.
- [leader_traits.rs](src/leader_traits.rs): `common/country_leader` traits (country leaders and advisors) with their modifiers, equipment bonuses and targeted modifiers. Name and token lookups keep the first native match; only an earlier unread suffix can hide that match.
- [ideologies.rs](src/ideologies.rs): ideology groups, their colours (`{ r g b }` or `rgb { }`; `hsv` stays unavailable) and sub-ideologies.
- [modifier_definitions.rs](src/modifier_definitions.rs): scripted modifiers' display fields. Built-in modifiers are defined in the executable; their display comes from the recording.

[combat_tactics.rs](src/combat_tactics.rs) is the one reader of `common/combat_tactics.txt`: tactic IDs in source order, phases, each tactic's resolved fields and its six effects as their native number readers leave them. Each field goes to its own native reader (the trigger through CTrigger::LoadBody with the evaluated single-value triggers read as one value, the weight and its modifiers); where the text leaves the tree's shape the reading follows the game's and is noted. Only a block the port cannot settle leaves the tactic being read unproven, and no later tactic is known.

[unit_leader.rs](src/unit_leader.rs) also holds the one trait-name inventory (`Traits::registered`, the native append pass) and the one sub-unit database reader (`sub_units`: indices and `is_artillery_brigade`), each with where its reading cannot be followed. [scripted_triggers.rs](src/scripted_triggers.rs) is the one reader of `common/scripted_triggers`, in the game's two passes: names from the directory's own files (the first wins), bodies from every file below it (the last wins, every body read kept in order so a form found later to leave the text is found in a replaced body too), each read as a tactic trigger is; a mismatch reads on from its value as the game does. A trigger key reaches a template by its text without case (CTrigger::LoadKey 1405434F0 -> 140AA78C0) after [trigger_keys.rs](src/trigger_keys.rs): the coded-trigger registry (140543E30), whose token IDs are static keywords and so known by name (register_authored_keys 140082CB0), each with its class's accepted scopes and value reader (`TRIGGER_CLASSES`, read from each registrar's class vtable), the equipment-category tokens (140F731B0) and the building and ideology names (`CountTriggerNames`), folded from the databases the caller already loaded; resources are the recorded `ResourceDefinitions`. `TriggerNames::dispatch` is the one classifier of that order, for the content read and for `dashboard::triggers`. Trigger bodies are data, never evaluated here: [triggers.rs](src/triggers.rs) holds them as the content's reader read them (`Vec<Item>`). [tag_aliases.rs](src/tag_aliases.rs) reads `common/country_tag_aliases` in the game's two passes, each alias's body by its key reader (140714870), the first definition by file order kept and names found by token (without case). Every `country_score` block joins the one score; a body the reading cannot be followed through, and every later one, is refused by name.

Ideas, characters and leader traits read each file as the game's one reader does, through the replay: in document order, with definitions registering wherever the game reads by key, conditions and effects included. A block the replay cannot settle (`Read::unsettled`, or a modifier block the content does not decide) refuses the trait or character it is in, or every idea of the group it is in, and every later one in the file, with a warning naming them and why.

The [save parser](src/save.rs) reads a task force's motion fields as `CUnit::Serialize@140BF7010` writes them: `path` (the ordinary route), `support_attack` (token `0x2EDA`, the movement target, omitted when null) and `full_path` (token `0x362C`, the alternate route, omitted when empty). The writer saves no combat list for a unit; each naval combat side's repeated `unit` references (`CNavalCombatant::Serialize@14160FF40`) are that side's participants in array order.

[states.rs](src/states.rs) replays state templates in native file order, keeping positive signed IDs and the first definition of each ID. Names use the shared native string conversion. If a file cannot be followed to its end, loading refuses the state inventory by file and line: naval battle naming needs every candidate province, and a later file cannot safely replace an unknown earlier state.

## Map movement and raids

[province_geometry.rs](src/province_geometry.rs) builds the engine's own province records from `definition.csv` and `provinces.bmp`: record order, invented provinces for unclaimed colours, u16-narrowed ids and runs, integer centroids and bounding boxes, in the engine's bottom-up coordinates with x wrapping. [province_graph.rs](src/province_graph.rs) derives the native neighbour table from that raster and the authored adjacencies, each edge's distance from the [terrain movement costs](src/province_graph/terrain_cost.rs) sampled along the native line, and the authored crossings; it also ports the raid path searches and derives each state's neighbour states, which the engine builds once at load from this table and the `history/states` province lists. `default.map` has no default name for `adjacencies` or `adjacency_rules`, so a map without either key, or a file that cannot be read, is refused by name. [adjacencies.rs](src/adjacencies.rs) holds both readers of `adjacencies.csv`: the strict one the map passes use and the engine's row loop the graph uses. [adjacency_rules.rs](src/adjacency_rules.rs) reads the rules crossings name; a rule it cannot read is refused on its own, and a crossing that names it answers unknown.

The movement costs and the map palette read the same files: `common/terrain`'s own `.txt` files in name-byte order. The costs keep their own native number and key rules until the terrain reader replaces them. `ResolvedLayers::directory_files` is the database loaders' one-directory listing, which scripted triggers, raids and terrain share. Script numbers use the reader's fixed5 conversion, not the save-file decimal parser.

[unit_path.rs](src/unit_path.rs) ports division movement admission and the path search behind the raid launch gate. Every live fact comes from a `MoveWorld` that the consumer answers from recorded state; a fact it cannot give makes the answer unknown, never guessed. `MoveGraph` resolves the content once into dense tables. The search is a flood fill, which reaches what the native A* reaches because that search drains its heap and gates on no cost but a raw zero edge. One `Reach` per army key answers every source; an edge whose admission is unknown reaches its neighbour only possibly. The invasion request uses [the native A*](src/unit_path/invasion.rs) through the same `MoveWorld`: forced port links, raw adjacency costs, the native heuristic and heap order. It keeps land-port dead ends because they can change equal-cost heap ties. Unsupported movement content and unavailable recorded facts return named errors.

[defines.rs](src/defines.rs) also reads boolean defines, such as the raid gate's army transfer rule.

[raids/tooltips.rs](src/raids/tooltips.rs) reads raid preparation and the ordered success mappings; [raids/names.rs](src/raids/names.rs) reads the naming groups selected by recorded raid units and source ships. Literal authored names stay literal; the viewer refuses runtime localised names whose provenance is lost.

## PdxShader source contract

[`pdxshader`](src/pdxshader/mod.rs) reads the native effect language independently of GUI layout. Its source assembler preserves child-first include order, repeated-key semantics, raw code, stage declarations, caller/effect defines, state tables and entry lookup, with executable addresses beside the rules. Every file resolves through the recorded content stack; a missing root produces the native empty technique record, a present root requires the DX11 header, and missing includes contribute empty content and a diagnostic as the engine does. The assembled program carries a SHA256 identity covering all resolved inputs. Effect artwork is currently outside recording hash coverage: its current stack identity is explicit and is not represented as recorded verification. UTF-8 source conversion or compilation failures name the effect. Execution, persistent caches and resource binding belong to [shader-pipeline](../shader-pipeline/README.md).

[scripted_localisation.rs](src/scripted_localisation.rs) retains ordered text alternatives and their triggers after the native reader replay. Later entries of the same exact name replace earlier ones; an unreadable suffix prevents claiming that an earlier definition remains effective. The consumer evaluates these entries through the recorded trigger evaluator and the shared localiser.
