# replay

The shared recording contract. This crate owns tables, rows, frames, cadence, sample provenance, spool records, replay containers, branches and codecs. Recording and playback must agree here; consumers must not invent their own interpretation of the bytes.

## Sources of truth

Start with [src](src/), especially [format.rs](src/format.rs) for format support and [cadence.rs](src/cadence.rs) for scheduling. Keep version numbers, table counts, IDs and slot assignments in code rather than copying catalogs into READMEs.

Rows preserve engine-native identifiers and numeric representations. Encoding is explicit and lossless. Reject malformed, out-of-range or noncanonical inputs rather than silently coercing them. Compression and deltas may save space; reduced precision may not.

## Values, availability and freshness

Country references in rows are not necessarily canonical slot numbers. Resolve raw references through the frame's `CountryLinks`; physical country slots can be reused. Preserve the recorded raw ID and do not turn an unresolved link into a guess about the current country.

A frame belongs to one hour on one branch. Tables can be snapshots, deltas, unchanged, truncated or unavailable. Missing data is not an empty successful table. After losing a complete baseline, a later successful table needs a snapshot before deltas can resume.

Value equality and sample freshness are separate:

- A fresh successful acquisition may equal the previous values and encode as `Unchanged`, while advancing its sample origin.
- A carried table retains the original sample hour, even though it appears in a later frame.
- Failed, truncated or skipped acquisition must not be marked as a fresh complete sample.
- Sliced tables (`Cadence::Sliced`) are read one owner slice per hour; owners are native country IDs, canonical country slots or native state IDs, one kind per family. Each hour replaces only the rows of the owners read at that hour, so one complete table mixes rows read at different hours. SliceReads holds each owner's read hour per table (`sliced::read_hour`); rows carry no hour, so an owner's unchanged rows stay unchanged when it is read again. The owner's read hour, never the frame's hour, is when its values were true. TechnologyDefinitions is the one keyed sliced table: it has no owner or read hour; a complete read replaces it, and an incomplete read replaces only the rows whose keys it returned.

Keep those distinctions through encoding, decoding, inspection, analytics and oracle joins. Do not infer freshness from a sibling table or the current frame's hour. Startup and branch/load transitions retain the full-refresh behavior required by the format. Keyframes stay self-contained, but a recorder may build them from the complete rows it already holds instead of reading every table again: a carried table in a keyframe is a snapshot of its last read, not a new sample, and its table cost is zero.

`Replay::read_block_parallel` decodes a block's frame payloads on the caller's worker threads once their boundaries are known. It returns the same frames and the same first error as `read_block`. Only a caller that owns spare cores uses it, such as the viewer's playback read-ahead; the collector and the recorder read sequentially.

Consumers that need only a few tables can use `FrameDecoder::for_tables`. It applies the same baseline and recovery rules to those tables and reports omitted tables as unavailable. The selection is fixed for the decoder lifetime; ordinary `FrameDecoder::new` still reconstructs every table. `Replay::read_block_selected` complements this by retaining only selected updates during parsing. All updates still go through the same decoder and validation before unselected ones are discarded; frame ordering, bounds, keyframe and compression checks remain shared with the full reader. The decompression buffer reserves the bounded size from the block index once. Neither selection API changes the recording format.

ScriptFlags keeps every scope's flags, read every hour: the global scope, each country (raw country reference), each state and each character (`scope_kind` 3, keyed by the Characters id; the character's own flag manager). The row's doc comment in [politics_research.rs](src/extended_rows/politics_research.rs) names the scope kinds. Every complete table holds every scope, so a character without a row has no flags. Effects set and clear flags at any hour, and the triggers that read them see the change in that hour, so the table is hourly; so is ActiveIdeas, for the same reason.

ScriptVariables keeps every persistent script variable store the triggers read, read every hour for the same reason: the global store, each country's, each state's and each roster character's (`scope_kind` 3, the character's embedded store). A complete table holds a row for every walked store, empty ones included, each key exactly as stored with its fixed5 value. Built-in game variables are computed by the game on demand, not stored, and are not recorded.

Characters also keeps the identity of the template each character was built from (`CCharacter+0x20`), which only its build and a save load write: whether it has one, the template's tag token, and the file and line its read began at and its generated byte, exact as stored (an `instance` records the line closing its leading `allowed`; a template the loader never read keeps an empty file and line -1). The viewer finds the content template by file, line and tag; the save writes only the tag.

LeaderPortraits and LeaderPortraitPaths hold the distinct leaders of every orders group with both an HQ provider and a leader, for all countries, independent of the recording client's country and camera. A registered leader outside that scope has no row; that is not evidence of an empty portrait. CharacterPortraits keeps the full character roster.

SentVolunteers preserves each country's raw ordered division handles by country and ordinal, including null and unresolved references. An empty complete table means no sent references; an unavailable table does not. Consumers resolve only live references through the complete Divisions census.

## Compatibility and recovery

A format change updates all affected writers, readers and consumers together. This release reads and writes only the current format. Reject other replay versions at the header and incompatible spool records explicitly; do not infer or silently translate an older layout.

Every spool record carries the current recording version; recovery checks it before decoding the payload and keeps only valid CRC-checked prefixes. Replay finalization and append must not destroy an existing good file when interrupted. Preserve session/branch identity and never join branches through merely probable parentage.

File spools keep record writes ordered while allowing one periodic durability request per segment to run in the background. Pending errors are checked before subsequent writes and on idle polls; a failed segment is abandoned through the existing recovery path. Segment creation, forced boundaries and detach remain synchronous durability barriers. Every outstanding worker is joined before its sink is destroyed. On Windows the durability handle reopens the existing file through its handle, separately from the synchronous writer; no path-based replacement or extra capture-buffer queue is involved.

The replay stores content identity, ordered layer hashes and the coverage policy, not game assets or machine-specific paths. Asset resolution belongs in [installed-content](../installed-content/README.md).

## Checking changes

[fixed_layout.rs](src/fixed_layout.rs) lists which recorded tables and playback calculations use each fixed modifier key and static token, and checks playback keys against complete ModifierDefinitions and LexicalTokens. A missing row or dictionary, a registered gap or a different script spelling produces a named refusal. Expected names live only in engine; collector refusals use the existing unavailable-table encoding, so the format is unchanged.

Use existing round-trip, delta/baseline, malformed-input, version-rejection, provenance, branch and recovery tests. Validate affected collector, recorder, viewer and analytics consumers in the same change, each with the shared [build commands](../../AGENTS.md#build-commands).

CountryAppearance keeps each country's stored map colour and name operands, its 3D and 2D graphical cultures, its current UI colour (`CCountry+0x390`, four raw `f32` bit patterns, which counter plates take in country-colour mode through the subject-colour chain), and the ruling party's first country leader: its ideology token and CCharacter id. The id is missing, never zero, when there is no such leader or its character could not be read. CountryCounterInputs also keeps each country's controlled-state count (`CCountry+0x46C`), which `num_of_controlled_states` returns; the oracle compares it with the saved states the country controls.

PoliticalParties keeps each party's naming operands: its own tag index, the default-name flag and the stored name and long-name localisation keys. With the flag set, the game names a party `<tag>_<ideology group>_party` (and `…_party_long` for the long name, when that key exists), then with the country's original tag, then by the ideology group's own name; with it clear, it localises the stored keys. Consumers resolve the keys through the recorded content stack. PartyLeaders keeps, hourly, each party's country leaders in native vector order, keyed by raw country, party ideology ID (PoliticalParties' `id`, whose `is_ruling` marks the ruling party) and ordinal: the leader's character id (missing for a null parent), its role `id` (`CCountryLeader+0x148`, -1 unless set) and its signed key in the character's role map, found by leader pointer. That key locates its CharacterRoleTraits row even after an ideology change; `has_country_leader_with_trait` compares the recorded definition ordinals, as the game compares pointers. The party writer saves the leaders in order without the role id, which the oracle takes from the leader's saved role. CountryCivilWars keeps, hourly, each country's civil-war array (`CCountry+0x12F0`), keyed by raw country and ordinal: the raw tag references as stored, in native (sorted) order. The save writes one `civil_war_target` per entry in that order. AdvisorTokens keeps, hourly, the character manager's advisor idea-token set (`CCharacterManager+0x60`), which `has_idea` consults first: each key exactly, sorted by its bytes (the table's bucket order has no meaning), keyed by rank. No writer saves the set; the oracle compares it with the set loading the save builds: the idea tokens of the saved advisor roles of every character a country's `character_status` marks `advisor=yes`, and of every character in a country's `retired_character_status` (retiring keeps a character's tokens). That is exact at a load hour; at any other hour a recorded token whose characters are in neither saved list is a runtime-only limitation, since reusing a dynamic country drops its character lists without erasing their tokens. FactionAdvisors keeps, hourly, each faction's occupied advisor slots (`CFaction+0x8D0`, the upgrade status's slot array), keyed by the faction's full reference and the slot's ordinal (an empty slot has no row): the slot advisor's idea token. The save writes the slots under `upgrades` with the advisor's character token, not its idea token; the oracle compares occupancy and the character's saved advisor roles.

ModifierDefinitions keeps each registered modifier key's native metadata by index, with its script name as a lexer token resolved through LexicalTokens; consumers decode the flag words. HiredAdvisors keeps each country's appointed advisors in native order, keyed by raw country reference and ordinal; resolve the country through CountryLinks like any other raw reference. CountryCharacters keeps, hourly and keyed the same way, each country's active-character records (`CCountryCharacters+0x10`) in native order, sorted by the character's name token: the character id, missing for a null record. The save writes them as `character_status` through a map, so the oracle compares them as a set. CountryRetiredCharacters keeps each country's retired records (`CCountryCharacters+0x28`) the same way, which `IsRetired` searches by the character's name token; the save writes them as `retired_character_status`.

CharacterRoleTraits keeps, hourly, the trait tokens of every character's roles, keyed by character, role kind and role: each country-leader role's (`CCountryLeader+0x50`, by its ideology key, CountryLeaderRoles' `ideology`), each advisor role's (`CAdvisor+0xC8`, by position, AdvisorRoles' `ordinal`) and the scientist role's (`CScientist+0x30` of `CCharacter+0xC0`, whether or not a roster holds it); a role with no traits has no row. A country-leader or advisor row also keeps each trait's database ordinal (`CCountryLeaderTrait+0x1A0`), because the database keeps a repeated trait name as another definition and `has_trait` compares definitions, not names. CharacterOperatives keeps, hourly, each character's nonzero unit-leader reference (`CCharacter+0xC8`), which `GetUnitLeader` resolves when the character has no direct unit leader (`+0xA8`), with the resolved leader's category, owner (`+0x120`), skill level and assigned trait definitions; an unresolved reference keeps only the reference. A character-scope `has_trait`, `skill` and `tag` read them; the save keeps each role's traits and the reference (`operative`), not the resolved leader's operands.

RaidSpeedInputs keeps, hourly, the stored inputs of `CalculateRaidUnitSpeed` for each raid in flight (phase 4, and an ended, not cancelled raid whose `end_hour` is at most an hour back); the viewer computes the speed from them, content defines and the raid type's `speed_multiplier`. A living ace's two country terms are not read again: the row names the ace's owner and the wing's country by canonical slot (`ace_owner`, `wing_country`), and the viewer joins CountryCommandPower at the same frame. CountryCommandPower holds, every hour for every country, the per-country modifier totals the raid code reads live (the command power pair, `ace_effectiveness_factor` and `air_ace_bonuses_factor`) with the allocated command power; RaidCountryInputs keeps only the daily launch range keys. RaidSpeedInputs' `transport_speeds` are the one reader of variant stat 0x3e besides VariantStats, a documented exception to one reader per stored value: VariantStats is daily, while the game reads the stat every hour a raid flies and its writers are not proven daily-only.

RaidEquipment keeps, hourly, each raid pool's entries, nuke count and per-archetype totals (the totals the equipment requirement check reads, recorded as stored) for every raid before launch and in flight. The save writes only the entries and nukes; the oracle compares each total exactly with its archetype's saved entries summed by `VariantDefinitions.archetype_token`, and states a limitation only where the total, a contributing entry or their sum reaches the clamp bound `L` (`±0x53E2D620FB40` raw, about 9.2e8 units), which `AddVariantQuantity` applies to a total and an entry separately. The one case it cannot see is a clamp that later unwound: adding ¾L to two variants of one archetype and removing one leaves a native total of ¼L below the entries' ¾L with nothing at the bound. That needs a pool that once held at least L of one archetype, and would surface as a reported difference.

InvasionPreparations keeps, hourly, one row per naval invasion order (type 3), keyed as ArmyOrders: the order's accumulated preparation (`progress`) and the stored operands of `GetRequiredInvasionPreparationHours`, which the game computes on demand and never stores. The target is the first path province's state controller (zero without a path); the country, relation and leader terms and the days term are effective modifier values, the relation terms absent when the game adds none and the leader term counted only when `leader_applies` (the HQ provider's root order is this order). The viewer computes the required hours with `NAVAL_INVASION_PREPARE_DAYS` from content; the row's doc comment in [movement.rs](src/extended_rows/movement.rs) gives the formula. The save writes only `progress`, which the oracle compares.

NavalProvinceCombats keeps each province's whole combat vector with each entry's class (land, border war, naval) beside its handle. NavalCombatTransfers keeps a combat's transfer handles raw, zero and stale ones included; NavalTransferUnits keeps only a transfer's live unit handles. Each NavalCombatDetails side keeps its task-force handles (`CCombatant+0x20`) in stored order, which the engaged flag's derivation compares hour over hour.

CountryStabilityInputs keeps one row per country of the stability, war support and maximum command power operands in native representation (fixed5, Q15 penalty words, raw predicates, loaded defines, tracked modifier totals with their resolved key indices, and the game language); consumers compute the displayed values. The maximum command power's other operands, `max_command_power`, its multiplier and the command power reserved by allocators, are CountryCommandPower's (read hourly), joined by canonical slot at the same frame; the maximum the game shows and clamps the balance to is `GetMaxCommandPower` minus that reserved amount. The stability row is as of its SliceReads hour; the command power row is the frame's own. CountryStabilityLines keeps each modifier tree child's value per tracked key, keyed by country, tree position and native key, with the source kind and identity the recorder proved; only an unpaired line keeps the game's display text. Both are sliced by country; use each row's SliceReads hour.

CountryFuel keeps each country's fuel status scalars in native representation (the current, maximum and lend-lease quantities in /32768 units; gains, cost and gain per oil in fixed5) with the history cursor, and the exact sums of the game's 24 hourly fuel history slots (gain, consumed, other, and requested and received per consumer). The sums cover the 24 hourly updates before the read, not a calendar day: reads 24 hours apart tile time exactly and a read at another hour overlaps. The per-hour entries and the pending entry of the hour in progress are not recorded. CountryFuelConsumers keeps the consumer entries by array position; both tables come from one read of each status.

TaskForceMissions keeps one row per task force whose naval mission has a current strategic region or accessible regions, with the mission's raw owner reference, the current region (0 for none) and the accessible region ids in native order with repeats. A task force with neither has no row, so a row is never empty; resolve the owner through CountryLinks.

LogisticsEquipment keeps one row per equipment archetype for each country the game computes it for, from the current daily record of its logistics history: the balance, which is the surplus (positive) or deficit the Logistics screen's "Stored" column shows, and the stock the daily update counted, both fixed5. Rows are keyed by the country's raw reference and the archetype's record index (its position in the equipment database), with the archetype's script token. The game computes the balance only for countries that are not AI-controlled, so in a complete table a country without rows was AI-controlled at the read; it is not a country without equipment. The value is the one the daily update stored: the screen recomputes it at each refresh from live demand, so it can differ later in the day. The screen's category rows, which sum a section's archetypes, also add incoming lend-lease, which is not recorded.

Factions keeps each faction's literal name, its template as a lexer token (the save's `template`, spelled by LexicalTokens; none when the faction has no template, whose localised name the game shows when the literal name is empty), its colour as the four raw f32 bits of the native `CColor` (the save writes each of red, green and blue as `(int)(c * 255.0f)` and alpha only when it is not 1.0), and the raw colour-override byte (the save's `is_color_overridden`; zero when the colour was taken from the leader's country colour). The template's localised name is not recorded; the content's faction templates give it.

CountryFactories keeps each canonical country's stored factory totals, keyed by raw country reference and read hourly; consumers join through CountryLinks and a missing row is unknown. It keeps the numbers the game's own top bar, factory tooltips and triggers read: for the military, naval and civilian groups the building levels counted, the total, controlled, owned and damaged factories (fixed5, since each building's level is weighted by its state's output factor), the factories assigned to lines or constructions, the withheld ones and the subject and other-country transfers; the civilian licence and trade exports; and what each civilian consumer took (consumer goods, national projects, licence imports, trade imports, market contracts). Buildings count toward a group through their content flags (`military_production`, `naval_production`, `general_production`), in the states the country controls and its offsite buildings. With `trunc(x)` the game's `(int)(x / 100000)` and T, D, C and O the truncated total, damaged, controlled and owned: the construction tab shows civilian Total T, Owned O, From occupation C - O, Damaged D, Unused max(0, T - used - unavailable - D) and In use D - (used + unavailable), and lists each withheld line (consumer goods, contracts, projects, licence and trade imports, overlord and other countries, construction); its header shows (T - D - max(0, T - D - unavailable - used)) / (T - D); the top-bar tooltip shows, per group, T - D - to_overlord - to_others as the total and min(that, unavailable + used - to_overlord - to_others) as used, with From trade the licence plus trade exports; the top-bar number is T(military) + T(civilian) + T(naval) - civilian trade and licence exports - the civilian and military to_overlord and to_others. `unavailable` already includes every consumer and both transfers out. The consumer goods count is the game's allocation, not a percentage to round. `num_of_controlled_factories` and scripted-text seeds sum the three stored group-head levels with native i32 wrapping, not the fixed5 totals. No group field has a text-save counterpart; the [oracle](../recorder/README.md#inspect-and-compare) compares levels only with saved building inputs.

ProductionLines keeps each line's current efficiency as the production view shows it, in Q15 (100% is 3276800): the game's average of its first min(active, maximum) per-factory efficiencies, which the row rounds to a whole percent. The maximum factories, the average's clamp, is kept beside it; the per-factory values are not recorded. `produced_raw` is progress toward the next unit, not a count of units produced.

VariantDefinitions keeps each variant's raw icon entry: active byte, kind (0 a GFX sprite name, 1 a texture path) and string. The production row (BindEquipmentVariantIcon, 140b371f0) picks the icon from it and from content in this order; every sprite is looked up by name through the content stack's interface files, and every country comes from the variant, never from the viewer:

1. An active entry that is not the path `"."`: a kind-0 sprite that exists, or a kind-1 path whose file exists. Otherwise continue at step 3.
2. An active `"."` (auto-designed variants): the graphic pool lookup below for the creator country (`creator_link`), with its ruling party's ideology group (the PoliticalParties row with `is_ruling`) and its `graphical_culture` (CountryAppearance). Without a result, continue at step 3.
3. Let L be `origin_link` when positive, else the creator's original tag when the creator is a dynamic country (CountryAppearance `name_tag`), else the creator; `tag` is L's tag and S is `_medium`. A capital ship is `classifier_flags` bit 6.
4. For the equipment type T and then its archetype A: `GFX_<tag>_<name><suffix>`, then `GFX_<name><suffix>`, with the suffix `_capital` + S first for a capital ship, then S.
5. When exactly one technology enables T (then A), for its id and its alternate name n: `GFX_<tag>_<n>_medium` (the original tag when L is dynamic), `GFX_<2D culture of L>_<n>_medium` (CountryAppearance `graphical_culture_2d`), `GFX_<n>_medium`, capital-suffixed first for a capital ship.
6. T's `family`, when it differs from T: steps 4 to 8 for it.
7. The graphic pool lookup for country L without ideology or culture.
8. Otherwise the row shows no icon.

The graphic pool lookup reads `gfx/interface/equipmentdesigner/graphic_db` in content order. It collects, for the country, its tag's root, then `FACTION_<member>` for each member of its faction in order (FactionMembers), then its capital's continent (Politics `original_capital` when nonzero, else `capital`), then `default` (only `default` without a country); in each root, the pools under T and then under its archetype, last declared first; and the whole collection again for T's family when it differs. A pool counts when its `limit` holds (vanilla limits test DLCs), it has no `sub_units` filter, and its ideology and culture filters, when present, contain the key's. Pools are stably sorted by `icons_weight` (or `weight` when that is zero), highest first, and each pool's `icons` are tried last to first; the first existing sprite or path wins. The native evidence for every step is beside the icon entry in the engine's [`cequipment_variant.rs`](../engine/src/cequipment_variant.rs).


ProductionLineOutput keeps the units each production line has completed, which the game counts nowhere per line. The collector observes every production tick and totals it per recording branch, so every total restarts at a branch: `since_hour` is the sample that began the observation. Rows are keyed by the line's handle (`ProductionLines.handle`) and an ordinal. Each row is one (producing country, variant, organisation) tuple the line produced under, in first-seen order, because a replay key holds at most 128 bits; a line's total is the sum of its rows. `country` is the producer's raw country reference, resolved through CountryLinks. The hook reads it from the line's production status at the tick, so even a line without an organisation that completes and disappears between censuses keeps its producer; the variant's creator does not supply it. Zero rows seeded by the census use that census's country. `units` counts delivered units. `mio_credit` counts what the game credited the organisation, the count IndustrialOrganisationHistory adds. The two differ exactly when a naval line that cannot deploy for lack of manpower credits without building, or a tick credits a non-positive count. A conversion clamped to zero is exact when its delivery and credit both contain zero and otherwise pair. With `observed_since_creation` set, the line was first seen after the branch's first complete ProductionLines census, so its totals cover its whole life; otherwise a consumer shows them as "since `since_hour`". An `ended` line has left ProductionLines: its final rows are published once and then dropped, unless the frame holding that publication failed to write, in which case the next publication repeats them. Every live line has at least one row, zero until it produces. A row whose `exact` is clear had a tick that could not be counted exactly; its `units` leave that tick out. The table shares the lines' daily slot. It is unavailable for the rest of a branch once a tick has gone unobserved, never partial.

NavalMissionTaskForces keeps the stored strike/invasion range and convoy-efficiency operands, including the embedded mission owner when TaskForceMissions has no region row. NavalMissionLedgers keeps every nonempty native navy ledger in its stored order, including repeats, with the region's escort presence inputs. NavalMissionCountries and NavalMissionCommanders carry the held country modifier/hub and leader/HQ slices with SliceReads witnesses. The cadences are defined in [cadence.rs](src/cadence.rs); [naval_mission_derive.rs](src/naval_mission_derive.rs) ports the native arithmetic, and the fixed-layout family withholds all four tables when the registered modifier layout differs.

The hourly research tables (ResearchInputs, ResearchAppliedBonuses and ResearchModifiers) keep slot-local inputs, applied-bonus attribution and modifier operands as native values. Country-wide modifier rows share one reserved slot index; slot rows identify the exact technology and retain speed components, source text, sharing witnesses, category filters, eligibility metadata and define values. The codec owns its kind tags.

`DivisionEtaInputs` publishes a complete moving-division table each hour, including carried rows. Its per-row `sample_hour` is the latest full operand read; consumers use `DivisionEtaInputsRow::valid_at` before deriving. A seek needs no earlier witness state. This owner-approved five-hour operand cadence is an exception inside the hourly table, not a new table cadence. See the [collector limitation](../collector/README.md) and [viewer fidelity limits](../viewer/README.md#fidelity-limits).

NavalCombatAirBaseWingHandles rows hold, per combat-referenced air base, its dense wing occurrences in native order with repeats; an empty list is a referenced base without wings, not a missing row.

TaskForceCounterInputs also keeps each task force's received-supply ratio (signed fixed5), which the port and at-sea counters' low-supply child reads. TaskForceMapMotion keeps, hourly and keyed by task-force handle, the movement target (zero for none), the first combat's role (0 none, 1 attacking, 2 defending) and both routes in native order; the viewer derives the stack kind and the settled route point from these and the content, so nothing of the map entity is recorded.

InvasionPreparations retains each invasion's route unit owner and that owner's path-cost operands: its slot-zero war-pointer presence, the pointed relation's raw retired byte (zero without a war), the raw slot-zero co-belligerent byte, and the ascending target slots whose co-belligerent byte is nonzero. A slot absent from a complete row's list is zero; an unavailable table never means zero. See [the native reader](../engine/src/invasion_preparations.rs) for the unit selection and candidate-set evidence. These runtime values have no save comparator; the oracle reports that limit explicitly. CountryCounterInputs keeps the handle of the division in the country roster's first slot (zero for an empty roster), the invasion route's last unit fallback; the save writes that roster in order, so the oracle compares it with the country's first saved division.

LocalPlayer preserves the recording client's playing country and observer-view country as raw references. Resolve its native viewpoint choice through the same frame's CountryLinks; Players describes the whole human roster and cannot identify the recording client. Missing or partial LocalPlayer data is not an observer or a guessed participant. The references change only between ticks, so an hour's sample holds what the following tick uses. A local tag switch rebuilds the engaged flags at once, so the same sample shows them; a viewing change the switch command does not rebuild for (a new observer view) is rebuilt by the next tick and shows in the next hour's sample.

Scripted-localisation operands include the stored character gender enum, country manpower residual, state available manpower, agency name bytes and created byte, and CountryAppearance's retained old names (absent, not empty, when they could not be read). Readers retain these values without converting gender to a boolean or manpower to an aggregate. The old names and agency names are text in the recording client's language, which the identity records. The format and cadence definitions in code govern compatibility and sampling; agency names and balance-of-power presentation refresh with the hour.

Table IDs use u16; frame tables remain in declaration order.

Saved-global target rows preserve registry ordinal, duplicate names, stored selectors, character IDs and one live-kind mask, with character-to-leader lookup results. The ordinal is the key, so clearing a name deletes its record rather than retaining a previous target. Cadence and acceptance are defined beside the other tables in code.
