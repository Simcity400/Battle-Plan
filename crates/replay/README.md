# replay

The shared recording contract. This crate owns tables, rows, frames, cadence, sample provenance, spool records, replay containers, branches and codecs. Recording and playback must agree here; consumers must not invent their own interpretation of the bytes.

## Sources of truth

Start with [src](src/), especially [format.rs](src/format.rs) for format support and [cadence.rs](src/cadence.rs) for scheduling. Keep version numbers, table counts, IDs and slot assignments in code rather than copying catalogs into READMEs.

Rows preserve engine-native identifiers and numeric representations. Encoding is explicit and lossless. Reject malformed, out-of-range or noncanonical inputs rather than silently coercing them. Compression and deltas may save space; reduced precision may not.

## Values, availability and freshness

Country references in rows are not necessarily canonical slot numbers. Resolve raw references through the frame's `CountryLinks`; physical country slots can be reused. Preserve the recorded raw ID and do not turn an unresolved link into a guess about the current country.

A frame belongs to one hour on one branch. Tables can be snapshots, deltas, unchanged, truncated or unavailable. Missing data is not an empty successful table. After losing a complete baseline, a later successful table needs a snapshot before deltas can resume.

Value equality and sample freshness are separate:

- A fresh successful acquisition may equal the previous values and encode as `Unchanged`, while advancing its sample origin.
- A carried table retains the original sample hour, even though it appears in a later frame.
- Failed, truncated or skipped acquisition must not be marked as a fresh complete sample.
- Sliced tables (`Cadence::Sliced`) are read one owner slice per hour; owners are native country IDs, canonical country slots or native state IDs, one kind per family. Each hour replaces only the rows of the owners read at that hour, so one complete table mixes rows read at different hours. SliceReads holds each owner's read hour per table (`sliced::read_hour`); rows carry no hour, so an owner's unchanged rows stay unchanged when it is read again. The owner's read hour, never the frame's hour, is when its values were true. TechnologyDefinitions is the one keyed sliced table: it has no owner or read hour; a complete read replaces it, and an incomplete read replaces only the rows whose keys it returned.

Keep those distinctions through encoding, decoding, inspection, analytics and oracle joins. Do not infer freshness from a sibling table or the current frame's hour. Startup and branch/load transitions retain the full-refresh behavior required by the format. Keyframes stay self-contained, but a recorder may build them from the complete rows it already holds instead of reading every table again: a carried table in a keyframe is a snapshot of its last read, not a new sample, and its table cost is zero.

`Replay::read_block_parallel` decodes a block's frame payloads on the caller's worker threads once their boundaries are known. It returns the same frames and the same first error as `read_block`. Only a caller that owns spare cores uses it, such as the viewer's playback read-ahead; the collector and the recorder read sequentially.

Consumers that need only a few tables can use `FrameDecoder::for_tables`. It applies the same baseline and recovery rules to those tables and reports omitted tables as unavailable. The selection is fixed for the decoder lifetime; ordinary `FrameDecoder::new` still reconstructs every table. `Replay::read_block_selected` complements this by retaining only selected updates during parsing. All updates still go through the same decoder and validation before unselected ones are discarded; frame ordering, bounds, keyframe and compression checks remain shared with the full reader. The decompression buffer reserves the bounded size from the block index once. Neither selection API changes the recording format.

ScriptFlags keeps every scope's flags on its daily slot: the global scope, each country (raw country reference), each state and each character (`scope_kind` 3, keyed by the Characters id; the character's own flag manager). The row's doc comment in [extended_rows.rs](src/extended_rows.rs) names the scope kinds. Every complete table holds every scope, so a character without a row has no flags; a flag an effect sets or clears between two reads shows up to a day late in every scope.

Characters also keeps the identity of the template each character was built from (`CCharacter+0x20`), which only its build and a save load write: whether it has one, the template's tag token, and the file and line its read began at and its generated byte, exact as stored (an `instance` records the line closing its leading `allowed`; a template the loader never read keeps an empty file and line -1). The viewer finds the content template by file, line and tag; the save writes only the tag.

LeaderPortraits and LeaderPortraitPaths hold the distinct leaders of every orders group with both an HQ provider and a leader, for all countries, independent of the recording client's country and camera. A registered leader outside that scope has no row; that is not evidence of an empty portrait. CharacterPortraits keeps the full character roster.

SentVolunteers preserves each country's raw ordered division handles by country and ordinal, including null and unresolved references. An empty complete table means no sent references; an unavailable table does not. Consumers resolve only live references through the complete Divisions census.

## Compatibility and recovery

A format change updates all affected writers, readers and consumers together. This release reads and writes only the current format. Reject other replay versions at the header and incompatible spool records explicitly; do not infer or silently translate an older layout.

Every spool record carries the current recording version; recovery checks it before decoding the payload and keeps only valid CRC-checked prefixes. Replay finalization and append must not destroy an existing good file when interrupted. Preserve session/branch identity and never join branches through merely probable parentage.

File spools keep record writes ordered while allowing one periodic durability request per segment to run in the background. Pending errors are checked before subsequent writes and on idle polls; a failed segment is abandoned through the existing recovery path. Segment creation, forced boundaries and detach remain synchronous durability barriers. Every outstanding worker is joined before its sink is destroyed. On Windows the durability handle reopens the existing file through its handle, separately from the synchronous writer; no path-based replacement or extra capture-buffer queue is involved.

The replay stores content identity, ordered layer hashes and the coverage policy, not game assets or machine-specific paths. Asset resolution belongs in [installed-content](../installed-content/README.md).

## Checking changes

[fixed_layout.rs](src/fixed_layout.rs) lists which recorded tables and playback calculations use each fixed modifier key and static token, and checks playback keys against complete ModifierDefinitions and LexicalTokens. A missing row or dictionary, a registered gap or a different script spelling produces a named refusal. Expected names live only in engine; collector refusals use the existing unavailable-table encoding, so the format is unchanged.

Use existing round-trip, delta/baseline, malformed-input, version-rejection, provenance, branch and recovery tests. Validate affected collector, recorder, viewer and analytics consumers in the same change. See [AGENTS.md](../../AGENTS.md) for commands.

CountryAppearance keeps each country's stored map colour and name operands, and the ruling party's first country leader: its ideology token, CCharacter id and trait tokens (`leader_traits`, lexer ids in the leader's array order, which `has_country_leader_with_trait` searches). The id is missing, never zero, when there is no such leader or its character could not be read. CountryCounterInputs also keeps each country's controlled-state count (`CCountry+0x46C`), which `num_of_controlled_states` returns; the oracle compares it with the saved states the country controls.

PoliticalParties keeps each party's naming operands: its own tag index, the default-name flag and the stored name and long-name localisation keys. With the flag set, the game names a party `<tag>_<ideology group>_party` (and `…_party_long` for the long name, when that key exists), then with the country's original tag, then by the ideology group's own name; with it clear, it localises the stored keys. Consumers resolve the keys through the recorded content stack. PartyLeaders keeps, hourly, each party's country leaders in native vector order, keyed by raw country, party ideology ID (PoliticalParties' `id`, whose `is_ruling` marks the ruling party) and ordinal: the leader's character id (missing for a null parent) and its role `id` (`CCountryLeader+0x148`, -1 unless set). The party writer saves the leaders in order without the role id, which the oracle takes from the leader's saved role. CountryCivilWars keeps, hourly, each country's civil-war array (`CCountry+0x12F0`), keyed by raw country and ordinal: the raw tag references as stored, in native (sorted) order. The save writes one `civil_war_target` per entry in that order. AdvisorTokens keeps, hourly, the character manager's advisor idea-token set (`CCharacterManager+0x60`), which `has_idea` consults first: each key exactly, sorted by its bytes (the table's bucket order has no meaning), keyed by rank. No writer saves the set; the oracle compares it with the set loading the save builds: the idea tokens of the saved advisor roles of every character a country's `character_status` marks `advisor=yes`, and of every character in a country's `retired_character_status` (retiring keeps a character's tokens). That is exact at a load hour; at any other hour a recorded token whose characters are in neither saved list is a runtime-only limitation, since reusing a dynamic country drops its character lists without erasing their tokens. FactionAdvisors keeps, hourly, each faction's occupied advisor slots (`CFaction+0x8D0`, the upgrade status's slot array), keyed by the faction's full reference and the slot's ordinal (an empty slot has no row): the slot advisor's idea token. The save writes the slots under `upgrades` with the advisor's character token, not its idea token; the oracle compares occupancy and the character's saved advisor roles.

ModifierDefinitions keeps each registered modifier key's native metadata by index, with its script name as a lexer token resolved through LexicalTokens; consumers decode the flag words. HiredAdvisors keeps each country's appointed advisors in native order, keyed by raw country reference and ordinal; resolve the country through CountryLinks like any other raw reference. CountryCharacters keeps, hourly and keyed the same way, each country's active-character records (`CCountryCharacters+0x10`) in native order, sorted by the character's name token: the character id, missing for a null record. The save writes them as `character_status` through a map, so the oracle compares them as a set.

RaidSpeedInputs keeps, hourly, the stored inputs of `CalculateRaidUnitSpeed` for each raid in flight (phase 4, and an ended, not cancelled raid whose `end_hour` is at most an hour back); the viewer computes the speed from them, content defines and the raid type's `speed_multiplier`. A living ace's two country terms are not read again: the row names the ace's owner and the wing's country by canonical slot (`ace_owner`, `wing_country`), and the viewer joins CountryCommandPower at the same frame. CountryCommandPower holds, every hour for every country, the per-country modifier totals the raid code reads live (the command power pair, `ace_effectiveness_factor` and `air_ace_bonuses_factor`) with the allocated command power; RaidCountryInputs keeps only the daily launch range keys. RaidSpeedInputs' `transport_speeds` are the one reader of variant stat 0x3e besides VariantStats, the only documented exception to one reader per stored value: VariantStats is daily, while the game reads the stat every hour a raid flies and its writers are not proven daily-only.

RaidEquipment keeps, hourly, each raid pool's entries, nuke count and per-archetype totals (the totals the equipment requirement check reads, recorded as stored) for every raid before launch and in flight. The save writes only the entries and nukes; the oracle compares each total exactly with its archetype's saved entries summed by `VariantDefinitions.archetype_token`, and states a limitation only where the total, a contributing entry or their sum reaches the clamp bound `L` (`±0x53E2D620FB40` raw, about 9.2e8 units), which `AddVariantQuantity` applies to a total and an entry separately. The one case it cannot see is a clamp that later unwound: adding ¾L to two variants of one archetype and removing one leaves a native total of ¼L below the entries' ¾L with nothing at the bound. That needs a pool that once held at least L of one archetype, and would surface as a reported difference.

InvasionPreparations keeps, hourly, one row per naval invasion order (type 3), keyed as ArmyOrders: the order's accumulated preparation (`progress`) and the stored operands of `GetRequiredInvasionPreparationHours`, which the game computes on demand and never stores. The target is the first path province's state controller (zero without a path); the country, relation and leader terms and the days term are effective modifier values, the relation terms absent when the game adds none and the leader term counted only when `leader_applies` (the HQ provider's root order is this order). The viewer computes the required hours with `NAVAL_INVASION_PREPARE_DAYS` from content; the row's doc comment in [extended_rows.rs](src/extended_rows.rs) gives the formula. The save writes only `progress`, which the oracle compares.

CountryStabilityInputs keeps one row per country of the stability, war support and maximum command power operands in native representation (fixed5, Q15 penalty words, raw predicates, loaded defines, tracked modifier totals with their resolved key indices, and the game language); consumers compute the displayed values. The maximum command power's other operands, `max_command_power`, its multiplier and the command power reserved by allocators, are CountryCommandPower's (read hourly), joined by canonical slot at the same frame; the maximum the game shows and clamps the balance to is `GetMaxCommandPower` minus that reserved amount. The stability row is as of its SliceReads hour; the command power row is the frame's own. CountryStabilityLines keeps each modifier tree child's value per tracked key, keyed by country, tree position and native key, with the source kind and identity the recorder proved; only an unpaired line keeps the game's display text. Both are sliced by country; use each row's SliceReads hour.

CountryFuel keeps each country's fuel status scalars in native representation (the current, maximum and lend-lease quantities in /32768 units; gains, cost and gain per oil in fixed5) with the history cursor, and the exact sums of the game's 24 hourly fuel history slots (gain, consumed, other, and requested and received per consumer). The sums cover the 24 hourly updates before the read, not a calendar day: reads 24 hours apart tile time exactly and a read at another hour overlaps. The per-hour entries and the pending entry of the hour in progress are not recorded. CountryFuelConsumers keeps the consumer entries by array position; both tables come from one read of each status.

The hourly research tables (ResearchInputs, ResearchAppliedBonuses and ResearchModifiers) keep slot-local inputs, applied-bonus attribution and modifier operands as native values. Country-wide modifier rows share one reserved slot index; slot rows identify the exact technology and retain speed components, source text, sharing witnesses, category filters, eligibility metadata and define values. The codec owns its kind tags.

`DivisionEtaInputs` publishes a complete moving-division table each hour, including carried rows. Its per-row `sample_hour` is the latest full operand read; consumers use `DivisionEtaInputsRow::valid_at` before deriving. A seek needs no earlier witness state. This owner-approved five-hour operand cadence is an exception inside the hourly table, not a new table cadence. See the [collector limitation](../collector/README.md) and [viewer fidelity limits](../viewer/README.md#fidelity-limits).
