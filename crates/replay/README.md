# replay

The shared recording contract: rows, tables, frames, sample provenance, branches, spools and `.battleplan` containers. Recording and playback agree here; consumers must not invent meanings for the bytes.

## Values, availability and freshness

Preserve native IDs, signed quantities, fixed-point words, ordered occurrences and stored text losslessly, except drifting values the game displays: by owner decision 2026-10-11 those are stored at the precision the game shows them, rounded as its formatter rounds ([display.rs](src/display.rs)). A row or nested value declares such a field's step beside it (`I64 @ STEP` in `typed_codec!`, `field @ STEP: i64` in `value_struct!`) with the native evidence; the column holds whole multiples of the step and its wire holds the value divided by the step, so field counts and widths are unchanged and older formats decode exact. Capture and the encoder round owned rows, so a row that drifted only below its step encodes no change. A division's remaining supply grace, which the game shows only as a whole percent of its share over the live `NMilitary.SUPPLY_GRACE`, is stored at that percent (`DivisionStatusRow::displayed_grace`), a multiple of its 0.01-hour wire step. The sentinel words `i64::MIN`, `i64::MIN + 1` and `i64::MAX` stay exact. Fixed-step counters, identities, handles, counts, dates, seeds and values a discrete decision reads (a glyph threshold, a content define comparison) are never stepped; derived displays read the stepped values and can differ from the game in their last digit at boundaries. Encoding is explicit little-endian, never Rust memory layout. Reject malformed, out-of-range or noncanonical input. Compression/deltas may reduce size, not precision; collector-reachable buffers use engine's checked growth.

Resolve raw country references through the frame's `CountryLinks`; slots can be reused. Preserve raw IDs and leave unresolved links unknown. Stored names obey the recording client's language; token spelling cannot reconstruct missing cached text.

A frame belongs to one hour/branch. Missing, truncated and unavailable tables are not complete empty tables. Losing a complete baseline requires a snapshot before deltas resume. Equality and freshness differ:

- Successful equal acquisition can encode `Unchanged` while advancing sample origin.
- Carried tables retain their read hour. Failed, truncated or skipped acquisition is never a fresh complete sample.
- Sliced tables replace only acquired owners and can mix read hours. Use `SliceReads`/`sliced::read_hour`, not the containing frame's hour. A producer whose held rows are the encoder's shared baseline may submit the read as a [`SliceUpdate`](src/sliced/update.rs): it encodes and commits exactly as the merged complete table, visiting and replacing only the read owners' rows.
- Startup/load/branch/gap transitions preserve full-refresh/baseline rules. A self-contained keyframe encodes held rows, including carried ones; it is not a full acquisition.

Preserve these distinctions through inspection, analytics and save joins. Sibling timing is not freshness proof; scheduling/merge rules live in [cadence.rs](src/cadence.rs) and [sliced.rs](src/sliced.rs).

Packets nested in hourly host rows store no read hour ([`PacketHour`](src/extended_rows/packet_hour.rs); hosts in `PACKET_HOUR_HOSTS`). Hourly tables are never carried, so a packet in an hour's complete or truncated host rows was read at that hour, including at keyframes and seeks; an unread packet is its refusal, never an earlier packet. Equal acquisitions encode `Unchanged`. Consumers admit a packet with `PacketHour::fresh_at(frame.hour)`. Older recordings decode their stored per-packet hour as `PacketHour::Stamped`, which still decides freshness and is never written.

`SharedView::sampled_at` certifies complete acquisitions with that table's own nonzero read timing. Spool frames keep read times in nanoseconds; replay blocks keep only which tables were read, as `READ_TIME_NOT_RECORDED` (`Metrics::stored`), so read hours are identical. Interleaved blocks keep their nanoseconds and earlier format-102 grouped blocks their microseconds. Equal timed reads advance it without copying rows; unchanged carries retain it. Untimed replacement snapshots/deltas, carried keyframes, failures and local mutation leave it unknown. Uncharged shared reads require their producer-specific provenance. Row equality and allocation identity exclude the sample hour.

A witnessed native world invalidation splits branch continuity even when stored clock and load timestamp values agree. The collector supplies this fact to `BranchTracker`; the existing branch controls preserve it without replacing native clock values.

`FrameDecoder::for_tables` fixes its selection for its lifetime; omitted tables are unavailable. `Replay::read_block_selected` decompresses and validates only the selected tables' sections of a grouped block (each section carries its own checksum). In an interleaved block it validates every update's wire grammar before discarding unselected ones: compatible omitted deltas borrow field values and retain only keys for ordering/overlap checks; retained deltas own their values. Snapshots retain typed row validation, while delta nested validation and baseline arithmetic remain reconstruction work. `Replay::visit_block` (and through it `read_block_selected` and `seek_selected`) decodes a grouped block's selected tables whole, and inflates and decodes an interleaved block one frame at a time and may stop early; an interleaved block is checksum-verified by inflating it to its end once, after which reads stop at their hour. Both keep ordinary baseline/recovery rules. `Replay::read_block_parallel` preserves sequential frames/first error and requires caller-owned spare workers; it decodes a grouped block's tables, or an interleaved block's frames, in parallel. Collector and recorder read sequentially.

## Row contracts

Keep keys, field order, native evidence, census/coverage and save joins beside each row. A value two tables would copy from the same read is recorded once: a division's received supply ratio and grace live in DivisionStatus, and DivisionLandInputs keeps manpower and naval transfer. Recorded values are those a map, counter, window, widget or hover shows and the operands they need. A breakdown is recorded as the inputs its native builder reads, and playback ports the builder; a value only the fresh-save oracle reads is not recorded, except as a diagnostic build's witness. The division supply footer is the exception (owner decision 2026-10-11): DivisionStatus records every division's per-source supply breakdown at the precision the footer prints ([`DivisionSupplyFooter`](src/extended_rows/movement.rs)), since it is the output of the game's hourly supply solve and playback cannot derive it. Recorded values are those a map, counter, window, widget or hover shows, or the inputs the replayer needs to compute them: a breakdown or preview the game builds on demand is recorded as its rarely changing inputs, change-driven where possible, and derived on playback by a port of the game's builder rather than captured for every entity every hour. A value only the fresh-save oracle reads is not recorded, except a unit's experience, which is recorded at its display step (owner decision 2026-10-11: a ship's `Ships.experience`). A row records what its consumer's native decision takes from the object when that is all it uses: DivisionStatus keeps the acclimatization category selected for a division's model camouflage, decided at capture with the live define, not every weight; older recordings keep their weights and consumers decide from them with the same port. LandCombatDivisions likewise keeps each reserve's reinforcement speed share (clamped to [0, 2] with the live `SLOWEST_SPEED`), not the hourly movement-speed operands it is composed from. A nested record whose numbers drift on their own is a numeric field each, so the grouped layout predicts every one from its own changes: LandCombatDivisions stores fuel and capacity, the five stats and the four scales that way, and reads older recordings' packets of them through `LandCombatDivisionRow::fuel_inputs`, `stat_values` and `scales`. Each combat member's ordered modifier entries are a LandCombatDivisionModifiers row, keyed as its LandCombatDivisions row, so an hour that changes one division's entries stores only that row; LandCombatModifiers keeps a row per side with its border values, published with the modifier context read alone. Likewise each element of a country's current fuel demand pack is a FuelDemandParts row keyed by its list and identity, with its list position; the pack in CountryFuel keeps its header, and its hour is a tag that a pack read with its row leaves unchanged ([`with_demand_parts`](src/extended_rows/fuel_demand.rs) puts the lists back). LandCombatDetails keeps each side's CAS and commander hover inputs (`LandCombatSideInputs`: anti-air, prevented damage, skill progress, offence and defence, description, timed and shown learning traits) in their own field at display precision, so the side's hourly window operands do not re-encode them. Each LandCombatDetails side keeps its organisation loss as the sum of its 24 samples, the one figure the marker's survival estimate, their only displayed reader, takes from them. The side marks that layout by storing its committed division count inverted, above 2^31 where a plain count is below: older recordings, including format-102 captures written before the sum, still open in new readers, which sum their 24 samples. A reader built before the sum (`LOSS_SUM_FORMAT`) refuses the whole block holding a marked side with the payload error `nested collection length exceeds remaining payload`; it never misreads it. Start with [rows.rs](src/rows.rs), [extended_rows.rs](src/extended_rows.rs) and its [domain modules](src/extended_rows/). Dedicated contracts include [combat_rows.rs](src/combat_rows.rs), [land_rows.rs](src/land_rows.rs), [modifier_breakdown_rows.rs](src/modifier_breakdown_rows.rs), [naval_mission_rows.rs](src/naval_mission_rows.rs), [production_modifier_rows.rs](src/production_modifier_rows.rs), [politics_rows.rs](src/politics_rows.rs), [peace_rows.rs](src/peace_rows.rs) and [event_feed_rows.rs](src/event_feed_rows.rs). [naval_trees.rs](src/naval_trees.rs) joins a naval combat's sides and ships to their recorded source trees (NavalModifierTrees). Playback arithmetic lives in [eta_derive.rs](src/eta_derive.rs), [naval_mission_derive.rs](src/naval_mission_derive.rs), [day_night.rs](src/day_night.rs), [temperature.rs](src/temperature.rs) and [directed_war_derive.rs](src/directed_war_derive.rs), which derives every direct-war cell from the hour's WarRelations. Division arrival times in eta_derive are estimates: the native walk over the recorded route with every edge at the speed of the division's recorded stat-block base speed, so they drift from the game wherever its per-edge, organisation and fuel terms apply.

## Derived on playback

A value the game computes from the hour, the content and rarely changing state is derived on playback instead of recorded, by a port of the native writer that equals what the game holds at that hour; the row records explicitly when the writer did not run. Consumers resolve content through the recorded stack. `recorder derived` compares each derivation with the values a recording holds.

- Province day/night clocks ([`DayNightClock`](src/extended_rows/naval_weather.rs), [day_night.rs](src/day_night.rs)): a row whose record the hourly update rewrote stores only that; slot 0, a suspended weather manager and an unread gate store the held clock. Format 101 recorded every clock, which reads as held.
- The selected army's attack modifiers ([attack_derive.rs](src/attack_derive.rs)): the list built for a division against a move (river, fort, snow, fort base and terrain attack), from the rarely changing operands the rows hold and the hour's own tables. DivisionStatus `attack_stats` holds the stat block's terrain entries and river, fort, snow and night scalars, carried until the active-stat refresh rewrites the block, and `weather_factor` the acclimatization factor; OrdersGroupCounterInputs `commander_attack` holds the direct commander's attack values; CountryCounterInputs `attack_modifiers` holds the raw `land_night_attack` and `land_bunker_effectiveness_factor` entries, made effective with the recorded definitions; Provinces `fort_bunker` holds the state's `land_bunker_effectiveness_factor`; WeatherRegions `combat` holds the region weather's raw army attack and breakthrough factors. Terrain categories and their adjusters, crossings, regions, fort levels (ProvinceBuildings with the content's land fort), snow, night, war, enemy air (RaidAirScores) and defines (SimulationFeatures) come from the hour and the recorded content. Each list entry refuses alone when an operand it reaches is missing. Format 101 recorded the native operands themselves as `attack` packets of the same tables ([`Witnessed`](src/extended_rows/attack_inputs.rs)); they are read when the hour holds no format-102 operands, and current writers store none unless the collector's `attack_witness` diagnostic read a division's.
- Province temperatures ([`ProvinceTemperature`, `TemperaturePass`](src/extended_rows/naval_weather.rs), [temperature.rs](src/temperature.rs)): rows hold every province record's temperature words at an anchor and slot 0 the hourly pass's inputs since, one seed per ordinary pass and none for a suspended hour, with the checksum of the temperatures read at the frame's hour. The collector starts a new anchor whenever an hour does not prove one ordinary pass or a suspended one, and every two `KEYFRAME_INTERVAL`s, so a frame derives alone from at most that many hours of passes, and the keyframe between two anchors repeats its anchor's words, which its anchored keyframe stores at a few bytes. `Memo` steps from the anchor through the recorded hours with the content and refuses every temperature of a frame whose derivation does not reproduce its checksum; a frame without a pass refuses them by name. Format 101 recorded each hour's temperature.
- Retained regional air-combat records ([`AirRegionCombatRow`](src/extended_rows/air.rs), [air_region_derive.rs](src/air_region_derive.rs)): a row holds one holder of a country air object's region table (`+0x170`) as the game held it when the collector last read it: at the latest hour the record updater touched it or a sampled check read it whole. Playback applies the daily passes since: pruning at the latest hour divisible by 24 removes each vector's leading records dated before that hour less `NGame.AIR_LOG_TIMEOUT_HOURS` from the recorded defines, so a frame needs no history. The daily pass prunes only countries owning a state (the retained simulation roster at `+0x9A0`), so a holder whose container country owns none refuses by name. `received` ports the strategic air view's aggregation (the window's records by mission mask and classification, damage summed by cause, cause 3 replaced by the planes ratio per scan) and `grids` the default view's air and ground received-damage lists. The retired AirRegionHistory and AirRegionDamage tables recorded every holder daily without the damage's record; they stay retired.
- Power-balance description trees ([`PowerBalanceModifierBreakdownRow`](src/modifier_breakdown_rows.rs), [power_balance_derive.rs](src/power_balance_derive.rs)): rows hold each record's static-modifier sources, and playback builds the cached `+0xC8` trees the power-balance description formats from them and the content's static modifiers. Trees a row also holds are native witnesses (every row of recordings made before the derivation, the sampled slice of a `breakdown_witness` collector build since), which `recorder derived` compares and nothing displays.

Values another recorded field of the same hour already determines are derived from it instead: a land combat's progress and marker direction from LandCombats, Divisions and DivisionMovement, a division's attrition glyph from its DivisionStatus value and threshold ([`DivisionStatusRow::has_attrition`](src/extended_rows/movement.rs)), and a combat division's commander name, skill and traits from UnitLeaders and UnitLeaderTraits. Older recordings' copies of these values are discarded with the other retired fields.

The [weather boundary packet](src/extended_rows/naval_weather.rs) retains native snow/mud planes and refresh operands. Its refresh identity is an equality witness, never playback animation time. Historical absence remains distinct from a known empty optional packet.

Event feed actions keep event dates separate from supplying reads; incomplete history can retain known actions without proving absence. Each event records its cause ([`EventFeedCause`](src/event_feed_rows.rs)): the native operation it happened in, named by the call site that reached it (`EventFeedRoute`), the operation that one ran inside, the nearest peace conference's reference and the operands the game passed; a fact the collector did not observe is absent, and older recordings hold no cause. Rocket totals survive site removal with independent spending/delivery coverage; coverage-only rows add no amounts. [Air events](src/extended_rows/air_ledger.rs) retain signed corrections and native dates; zero health change is not a bombing event. [Nuclear strikes](src/nuclear_rows.rs) hold one row per impact: launcher and state owner with their full native IDs at the impact, type, province, state and controller, with the war support, building health, unit, wing crew and pool changes it applied; a part named in a row's refusals is incomplete, and a complete empty table is an hour without strikes.

Identity stores ordered layer hashes and coverage policy, not assets or machine paths. [installed-content](../installed-content/README.md) resolves content. Older supported policies retain their verification roots; newer-only reads produce uncovered-read notes, and unsupported policies are refused.

## Blocks

Writers emit H4GC chosen grouped blocks ([container/grouped.rs](src/container/grouped.rs)). A grouped block holds one branch's consecutive frames as independently compressed sections (zstd frames, each with its checksum: the writer chooses between encodings at level 9 and stores each chosen section at level 19 where that is smaller) listed in a CRC-checked directory: a header (hours and which tables have an entry each hour), diagnostics (exact callback total, pool bytes and dropped-frame counter, and the set of tables read), and each table's keyframe entry and later entries. Table sections are split into columns (control, keys, masks, one per field). The magic alone identifies the layout; the directory begins with its frame count.

Entries rearrange the plain update wire without changing what it says. A baseline equal to the previous frame's hour is implied. A delta against the previous frame may be a residual entry, stored against its fields' predictions ([container/grouped/predicted.rs](src/container/grouped/predicted.rs)): writer and reader follow each table's plain updates through the block. A numeric field that changed by the same amount in two consecutive frames is predicted to change by it again (a different one-off change keeps the prediction; a stop or None ends it), and one whose change grew by the same amount over three consecutive frames is predicted to keep growing by it. In a chosen block a numeric field that changes in two hours in a row by amounts the repeated change does not predict also keeps its rate ([container/grouped/ramp.rs](src/container/grouped/ramp.rs)): from its last 32 hours, unchanged ones included, the open interval of rates (in units of the greatest common divisor of its changes) every pair of them allows, and the simplest fraction in it, so a value moving a fractional number of display steps an hour (organisation 1, 1, 2, 1, ..., an acclimatization factor -8, -7, ...) is predicted exactly once learned. Each field takes whichever prediction was right in more of its last eight hours, the repeated change on a tie, so an irregular value costs no more than before; the rate predicts nothing before two changes, keeps itself through a one-off change, starts again at a second one in a row, and forgets a field unchanged for 8 hours. A byte field whose encoding kept its length and changed by the same little-endian difference twice is predicted to change by it again. A residual entry stores only the rows with a field that did not move as predicted, with those fields' corrections, so a frame whose changes are all predicted, or an unchanged table with nothing predicted, has no entry. Predictions restart at each block's keyframe and after any other entry, so a block still decodes from its keyframe alone. Per table and block, the writer keeps residual or plain entries, whichever compresses smaller.

Later deltas and residual entries name their rows against the table's rows at the frame before ([container/grouped/keyed.rs](src/container/grouped/keyed.rs)), which writer and reader follow from the plain updates: those of a keyframe stored as a snapshot, none after a keyframe stored as an anchored change, then each update's inserted and deleted rows. Each way of writing a table's later entries keeps two pairs of keys and masks, fed from the same row calls. One pair stores rows and masks as binary decisions of an adaptive context model ([container/grouped/modelled.rs](src/container/grouped/modelled.rs)), range coded into the masks column (LZMA's carry-propagating coder, 12-bit probabilities, integer arithmetic only): how many rows the entry inserts, each inserted key in the keys column as its distance past the one before; for each row the last two entries stored, whether it changed, until every changed row the table held is found; the others as adaptive Exp-Golomb counts of the rows not stored by those two entries that each skips; and each mask as its place in a list of the row's last mask and then the masks stored most recently, or bit by bit in the context of the same field in the row's masks of the last two entries and its last. A row that keeps changing, or a mask a row or the table keeps storing, then costs a fraction of a bit. The listed pair names each changed row among the rows at the frame before by how many it skips since the key before it, or an inserted row by its distance past that key, and each mask by its place among recent masks or as itself. Deleted keys use the listed coding in both pairs; entries without coded rows, control and field columns agree. The writer keeps whichever whole later section compresses smaller at level 9, with model decisions winning a tie, before choosing residual or plain entries. The masks column starts with a coding byte: 0 for modelled, 1 for listed. A missing byte or any other value is refused by table name. Each choice depends only on the block's own bytes.

A changed string, list or nested record may be a byte patch ([container/patch.rs](src/container/patch.rs)) against the same field's previous plain encoding in the block, or against its prediction: copy/insert hunks, so an edited, inserted or shifted part re-sends only its new bytes. In later entries, each byte field column keeps either those patches or the same patches with each in-place byte stored as its difference from the byte it replaces, whichever compresses smaller. A list field (`U32List`, `U64List`) that is its patch base without its first element, as a moving division's remaining path is when it reaches the next province, is one tag. The chosen layout holds that tag. In the current layout a moving division's DivisionMovement source, which becomes the province it leaves, is stored against the change that takes it to the element its path dropped before the latest, which the writer and reader follow in the block's patch bases. Writer and reader derive patch bases and predictions from the plain updates themselves, so they always apply to the source format's bytes.

A keyframe entry may be a change against an earlier keyframe of the same table anywhere earlier in the file (its anchor), named by how many blocks back it is, so loaded branches and appended sessions start from what earlier ones stored: a table that does not change, a static one included, is stored once per file and costs each later keyframe a few bytes. Appending takes its anchors from the file's last block. The anchor is the table's latest keyframe stored as a snapshot, or its latest keyframe while the chain stays cheap to read (`chain_charge`): the anchored keyframes a reader rebuilds, the block's own included, each counted as its raw section bytes plus a sixteenth (`REBUILD_SHARE`) of its snapshot's, total at most the snapshot's raw bytes. A seek therefore inflates at most twice a table's snapshot section and rebuilds its rows at most sixteen times, however many blocks back the snapshot is; readers refuse a longer chain. The writer keeps the snapshot or the smaller change. Readers materialize anchored entries as ordinary keyframe snapshots; a block whose anchor is damaged or missing is refused, never read as empty. A grouped block never decodes one table, or its plain frame headers, to more plain bytes than `MAX_BLOCK_RAW_BYTES`, nor stores more section bytes; its writer splits blocks by the same bounds, so blocks follow the keyframe cadence until a single table would exceed one. `Replay::block_sections` reports stored sections and `Replay::block_columns` their table sections' columns; `Replay::reencoded` writes a current-format recording's frames again for size attribution.

Writers pack blocks on half the machine's logical CPUs, at least one, the writing thread included ([container/pack.rs](src/container/pack.rs)). The writing thread reads, decodes and encodes every frame in recorded order and decides there everything a block's bytes depend on beyond its own frames: its boundaries (sessions, branches, spool keyframes, the hour interval and the size bounds, which read the block's encoded bytes so far), its position in the file, and each keyframe entry, chosen by level-9 size among the snapshot and the anchor candidates the blocks before it left. Everything else a block's entries depend on (patch bases, predictions and their ramp windows, row keys, mask lists and the context model) restarts at its keyframe and follows only its own frames. A finished block, freed of the state only writing it reads (patch bases, predictions, row keys and mask lists; its context models stay until compression finishes their streams), waits for a worker; at most one waits, so a pack holds at most its workers' blocks, that one and the block being handed over or written. Compressing it reads nothing else: each table's choice of column encodings and of residual or plain entries, the header, the diagnostics and each section's level-19 storage, every section a zstd frame compressed alone, without dictionaries or zstd's own threads. Threads helping a keyframe's tables choose their entries, or a block's tables and sections compress, take only CPUs no other pack thread holds, and a worker starts a block only once one is free, so a pack never keeps more threads busy than its workers. Blocks keep their order, so a recording's bytes are the same on any number of threads, and so is a failure: the first block in order that fails to pack, else the writer's own error, as compressing each block before reading on would give. Writing goes on past a block that is still packing, so the frame observer and reader may see frames after the block that fails.

Finalization uses two streaming spool passes and compresses blocks before the shared decoder size bound, which applies to each table. Split hours become keyframes, anchored like any other, with original metrics and sample hours; an oversized frame or a split with a truncated table is refused by name. Allocation and I/O failures abort finalization and retain the spool. Repeated finalization compares complete decoded values, availability and metrics, then syncs the matching destination file and parent directory before acknowledging success without changing recording bytes or modification time. A sync failure retains the spool and reports failure.

Recording publication writes and syncs a `<destination>.tmp` sibling before atomic replacement; one publisher owns that fixed sibling at a time. On Windows, POSIX rename replaces a recording while readers hold it with `FILE_SHARE_READ | FILE_SHARE_DELETE`. Held readers keep the complete old revision until close; new opens see the complete new revision. A reader without delete sharing blocks publication with a sharing error. Unsupported rename errors alone select `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`; open readers can block that fallback. The rename syscall and unsupported-volume policy are shared with collector status publication.

POSIX publication acquires writable source and parent-directory handles before rename, then flushes the renamed file and common parent directory before returning success. An access or pre-rename error preserves the destination. A post-rename flush error reports failure with the complete new revision already visible. The writable handles require appropriate directory permissions and can briefly block new deny-write readers until flushing completes. Process termination after temp sync leaves the old destination; after rename it leaves the new destination. These process-crash checks do not establish power-loss durability.

`publication::posix_delete` removes a file name while delete-sharing readers retain its bytes until close, then flushes the parent directory. Unsupported POSIX deletion reports an error without a deferred-delete fallback. The prepared-data store uses this for Clear and unlisted-file cleanup.

## Recorder settings

[RecorderSettings](src/recorder_settings.rs) stores shared preferences at `%LOCALAPPDATA%\HOI4Replay\recorder\settings.json`: record every campaign, the recordings folder both programs use, the Paradox user folder, start with Windows or with Battle Plan, and the optional capture families. The recordings folder is read through `effective_save_folder`, with `default_save_folder` when none is chosen. Per-campaign choices keyed by recorded campaign id select automatic recording, Continue or New file, the current folder and the sidebar flag. Display names are keyed by normalized recording path.

First run uses the settings defaults; optional choices remain absent until chosen. `RecorderSettings::update` holds a short OS lock on `settings.json.lock` while it loads the current file, applies one writer's change and replaces the file atomically, so the recorder and the app preserve each other's owned fields. Campaign entries left with no choice are dropped.

`Replay::read_hour_span` reads a finished recording's first and last recorded hours across all branches from the checksummed trailer's block index, without inflating blocks.

## Compatibility and recovery

Container extents and collection counts are checked against their byte backing.
Trailer buffers reserve their actual byte extents fallibly. Whole-block
inflation reserves the declared raw length exactly, within the decoder's existing
raw-byte bound, and decompresses directly into that storage. Reused frame payload
buffers grow fallibly with the native geometric allocation policy and reuse
initialized storage. Mismatched inflated lengths remain errors. Index storage, verification flags,
frame collections and parallel decode results use checked allocation. Frame
counts and hours must fit their recorded block range; row copies during baseline
reconstruction return allocation errors and copy admitted snapshot rows without
repeating nested validation. Cancellation and allocation failure stop streamed
reads without draining the remaining block; selected seeks return these errors,
while actual recording damage retains gap recovery. Generated damage diagnostic
excerpts are bounded before fallible formatting; recorded messages and values
remain lossless.

Partial metadata can be read through `Replay::read_partial_from` from a seekable
stream with its actual length; it validates that length before reading the
trailer. A checksum failure or extra trailer bytes produce read-time warnings
when the metadata remains readable. Invalid indexed blocks are skipped, with
known hours recorded as gaps; remaining blocks retain their original bytes.
Conflicting session/branch context and undecodable header/trailer framing still
refuse the recording. Invalid gap, control and recovery-note records are withheld
at their length boundaries with warnings and damage counts. Record-list framing
remains strict. Recordings that needed read-time recovery cannot be continued,
appended to or rewritten; recorded partial captures and spool recovery notes alone
do not prevent writing.
Blocks admit exactly one zstd frame, retain the decoder
window and raw-byte bounds and refuse trailing data. Ordinary damage retains the
existing named block/table refusal and recovery boundaries. These checks change
neither the wire format nor historical table admission.

The independent [fuzz package](../../fuzz/README.md) exercises all these reader
entry points with generated synthetic seeds. Its guide describes nightly,
cargo-fuzz and native C sanitizer setup. Run dependency advisories through the
root [cargo-deny configuration](../../deny.toml) after dependency changes and
before releases.

Update affected readers, writers and consumers together when bytes or recorded meanings change. A branch's format is provisional **main + 1**. Allocate new TableIds densely after main's catalog; reconcile/renumber provisional additions at merge. Never reuse or shift published IDs, including retired entries.

Writers emit only the current format. Older recordings still open when today's readers decode unchanged contracts correctly within the proven [compatibility history](src/rows/compatibility.rs). Refuse changed layouts/meanings at their affected scope: a table becomes unavailable by name; incompatible file headers/framing refuse the file. Age alone must not reject an unchanged contract. Add no migrations, translations or old row decoders.

Appended fields decode through the source prefix and delta-mask width. `Recorded::NotRecorded` differs from native empty, zero or absence, including `Recorded::Value(None)`. Only dependent features receive named, counted refusals; readable prefixes remain usable. Opaque nested records retain source-format context even when the parent field count is unchanged. Inspection counts recorded bytes and nested gaps without rewriting rows.

Older air-history, naval-base and construction-output prefixes remain readable with their absent scenario channels and native oracle witnesses reported as field gaps. The changed technology occurrence keys require named whole-table refusals for research inventories and technology definitions.

A division supply footer (DivisionStatus.supply) stores each received amount as the display steps it fell short of its asked or requested amount by (`SUPPLY_SHORTFALL_FORMAT`), so a supplied division's received words repeat while its asked and requested words drift. The shortfall is an exact bijection against a field of the same value, never a neighbouring row or the key, and older formats decode the amounts themselves. The footer marks the shortfalls by tagging its origins list `2` or `3` instead of `0` or `1`. Within the format the reader tells the two layouts apart by the tag and decodes both exactly; a reader built before the shortfalls refuses the whole block holding a marked footer with the payload error `invalid nested option tag`; it never misreads it.

Lifetimes determine timing entries/updates. Absent new tables are not recorded, not empty; retired tables (`RETIRED_TABLES`) retain IDs/framing for named discard, every recording refuses them by name, and the collector never walks them ([`cadence::should_walk`](src/cadence.rs)). A retired row field keeps its position as a [`Retired`](src/rows/retired.rs) tombstone listed in `RETIRED_FIELDS`: current writers store an empty payload and older payloads are discarded through their framing; a fixed-width tombstone (`RetiredI64` and its siblings for the other scalar kinds and `U32List`) keeps its kind, current writers store zero, and older values are decoded through their deltas but never exposed; a retired part of a nested value is a `RetiredNested` placeholder that decodes older bytes through their source format and drops them. A whole Opaque field restored after a provisional retirement (`opaque_value!(T, restored)`, DivisionStatus.supply) decodes every earlier layout's payload again and reads the tombstone's empty payload, which no recorded value encodes, as `Recorded::NotRecorded`; writing such a row again stores that empty payload, so those recordings re-encode byte for byte. Append requires current format. Check each spool record's version/contract before decoding; incompatible old spools stay on disk, refused for finalization/append and never re-encoded. Recovery keeps CRC-valid prefixes, preserves existing good files and never joins branches through probable parentage.

A same-process reattach that continues its branch records an event loss (`ControlRecord::EventLoss`, `Replay::event_losses`): the collector was detached for part of the interval between the read of the detached session's last frame and the read of the reattached session's first observation, so every event family's record of that interval is incomplete, while events it did record there remain observed. The two hours are read anchors, not hook removal and installation times. An event loss is not a gap: a frame lost at its second read is a gap of its own. A reattach whose first observation starts another branch records none, since that branch's first interval is its own. A writer retries an event loss whose segment failed after writing it; finalization keeps one, and opening refuses a replay holding the same loss twice. Older recordings hold no event loss.

A validated terminal failure produces a replay prefix with a visible `Partial` control. Only known attributable unrecorded attempted hours become `Gap`s; missing context invents no hour, clock or branch. A prepared identity-only witness is not failure evidence. Validate terminal identity/context and committed/pending spool bounds in [witness.rs](src/witness.rs) and [recorder recovery](../recorder/src/replay_io.rs). Partial notices cannot make coverage complete.

The frame encoder can take tables encoded beside the frame, on any thread, as `TableSegment`s in the context of that frame, and writes the bytes it would encode itself; `commit_retiring` hands back the baselines, rows and inputs a commit no longer holds so the caller frees them elsewhere.

Spool writes stay ordered. Periodic durability runs on one persistent worker per open segment, started by its first request; segment creation, forced boundaries and detach are synchronous barriers. Check pending errors before writes/idle polls and join workers before destroying sinks. Publish complete-record bounds before durability; promote baselines only after complete encoding. Collector allocation-failure diagnostics must not allocate; see [codec.rs](src/codec.rs) and [engine allocation](../engine/src/allocation.rs). `FrameEncoder::committed` lends a table's latest committed complete rows and their hour; a truncated or unavailable sample leaves none.

The selected transport preview is not recorded. Its split tables (`RESERVED_SPLIT_TABLES` in [reserved_split.rs](src/extended_rows/reserved_split.rs)) are retired tables, refused by name in every recording; the transport value types beside them keep only those tables' framing. Its row fields and the earlier selected-route packets (`Provinces.selected_areas`, `DivisionMovement.selected`/`transport`, `RailwayGunCounterInputs.transport`, `CountryCounterInputs.movement`, `CountryAppearance.transport_convoys`, `AirBaseRegistrations.transport_planes` and the reserved singleton's movement, observation and transport packets) are `Retired` tombstones listed in `RETIRED_FIELDS`. The selected route's areas are recorded in Provinces' appended fields: `controller_area` and `owner_area` label each province's controller/owner area at `+0xD0`/`+0xD8` by its smallest member province (zero for null), and `area_node` ([`ControllerAreaNode`](src/extended_rows/selected_routes.rs)) holds a controller area's representative and ordered contacts on its label province's row alone. An area's land count is the number of provinces with its label and its first land's nonsea index is map content, so neither is stored. Format 101 and earlier lack these fields and refuse the search by name.

## Capture exceptions and limitations

- `RaidSpeedInputs` reads transport speed separately from daily variant stats because flying raids reach it hourly: the exception to one reader per stored value. See [raid rows](src/extended_rows/raids_projects.rs).
- Native war groups have no native group ID or participant join/leave dates. Derived continuity must preserve unobserved stretches; see [war rows](src/extended_rows/war_overview.rs) and [the wars product](../dashboard/src/products/wars/README.md).
- Cumulative output starts with branch observation, not line creation. Respect observation start, exactness and coverage; a linked partner's unknown share is never zero. See [economy rows](src/extended_rows/economy_construction.rs).
- Event application time can differ from frame time. Complete empty batches certify only their capture scope; missing batches/partial intervals/lost drains never prove zero. Domain rows own these contracts.
- [fixed_layout.rs](src/fixed_layout.rs) owns fixed-key/token families and named refusals. Verify complete recorded dictionaries and registered spelling/layout; dynamic keys remain content-driven.

Fixed modifier-name authentication requires initialized executable metadata and reports a family-scoped refusal when it is unavailable. Raw recording histories remain readable. Its name-dependent tests initialize from `BATTLE_PLAN_GAME_DIR`; format and index-membership fixtures use synthetic data without an installation.

Research inventories and definitions key each native template occurrence by database index. Slot inputs append exact occurrence identity with historical absence retained by `Recorded`; equal handles cannot establish assignment continuity. The inventory also retains the native serializer's applied-bonus-count inclusion operand.

## Add or change a table

1. Document native key, exact representations, ordering, observation boundary, completeness and refusals beside the row. Add it to its domain module with `RowCodec`/`row_codec!`, existing lossless value codecs and validation.
2. Register it in `define_tables!` in [rows.rs](src/rows.rs), including dispatch/size handling. Keep provisional IDs dense. Appended fields retain keys, prefix order/kinds and historical mask framing; use `Recorded` for historical absence.
3. Update [rows/compatibility.rs](src/rows/compatibility.rs) for lifetimes, fields, nested records and layout/meaning changes, and the current writer version referenced by [lib.rs](src/lib.rs). Retain retirement framing; add no legacy decoders.
4. Wire scheduling/carry in [cadence.rs](src/cadence.rs) (a table changing cadence adds its earlier cadence to `EARLIER_CADENCES`, which `cadence_in` returns for older recordings), sliced owner reads/merges in [sliced.rs](src/sliced.rs), and fixed-key/token dependencies in [fixed_layout.rs](src/fixed_layout.rs).
5. Wire acquisition/capacities/conversion in [collector](../collector/README.md) and affected frame/container/spool handling, [recorder](../recorder/README.md), [viewer](../viewer/README.md) and [dashboard](../dashboard/README.md) consumers together. New inputs need a save comparison or named limitation.
6. Add synthetic fixtures and fault-campaign coverage in [acceptance.rs](src/acceptance.rs). `DOMAIN_TABLES` plus direct fixtures must cover each table exactly once. Exercise snapshots/deltas, unchanged/carried freshness, missing/truncated reads, baseline recovery, malformed input and readable older prefixes as applicable.
7. Run scoped [AGENTS.md checks](../../AGENTS.md) and relevant [fresh-save/load and smoke checks](../recorder/README.md#inspect-and-compare). Reconcile provisional version/IDs against current main at merge.

## Checking changes

Use existing round-trip, delta/baseline, compatibility, provenance, branch, recovery and fault-campaign tests with synthetic fixtures. Exercise affected consumers together; decoding success does not certify capture or display fidelity. Follow [AGENTS.md](../../AGENTS.md) and the [live-check guide](../recorder/README.md#live-checks-and-performance). Documentation-only changes need link/diff checks.
