# viewer-world

The GPU scene, world labels, immutable scene content, draw passes and native shader adapters, political fill, terrain and weather, borders, names, rivers, trees, static and animated model rendering, model selection, buildings, railways, trains, strike effects, floating map text and post-processing. Content and shader sources resolve through the recorded installed-content stack.

[Terrain](src/map/terrain.rs) is the approved uniform grid for the game's camera and, for a free camera, the content shader's 64-cell blocks at the coarsest step their distance allows with snapped edges, on every map copy the view reaches; a free camera over a map whose sides are not whole blocks refuses its terrain pass by name. A free camera's [shadow](src/map/shadow.rs) light is fitted as the game camera's is, to its capped water-plane footprint with the same padding and backoff, and never extended for casters; its shadows turn on and fade by eye height against `DRAW_SHADOWS_CUTOFF` and `DRAW_SHADOWS_FADE_LENGTH`.

Aircraft and unit figures retain their own admission, pose and model selection; the walking mode's figure is the viewing country's infantry by the land ladder ([`UnitModelAssets::infantry_figure`](src/map/unit_models.rs)). `AircraftAssets::player` bakes a chosen aircraft for Fly mode on first use from the same roster, refusals and lazy library as recorded flights, and names why one cannot be flown, including the error of a mesh that does not load. The host supplies concrete air-base and region tables and shared recorded air/unit reads from foundation, and composes the GPU scene with counter and raid outputs. These passes consume concrete resources and draw operands, with shared upload, camera, GUI and visibility contracts from viewer-foundation. Selected movement routes and composed battle-plan/raid ribbons arrive as concrete draw data; world owns their GPU submission. [Strike effects](src/map/strike_effects.rs) play the content's nuclear and critical-bombardment entities from recorded `NuclearStrikes` and `MapEvents`, and its missile explosion entity where an aircraft missile bombing scenario finishes or in the mission region of a launch-flagged launch effect whose entity finishes. [Floating map text](src/map/animated_map_text.rs) prepares each hour's recorded map events per viewing country by the game's own filters on the hour builders, presents each event once, and draws them with the content's animated map text types in per-province queues; a free eye shows each text standing at its origin as it shows map icons. The scene's overlay request says whether the map's interface that stands in the world draws (borders, demilitarised zones, straits, plans, arrows, floating text and names); hidden, it still steps. The map frame's ambient objects with `use_animation = no` play their entity's `default_state` from when they appear, as the game creates every entity instance in that state ([models.rs](src/map/models.rs) `prepare_default_states`); one that can reach a state with several variants stays still and is counted, since the game draws that variant from a per-entity counter no recording holds. Pass-local caches, retained shader bindings, native traversal and animation clocks belong to their existing owners.

The [scene](src/map/scene.rs) draws the model a free camera mode's user steers (`Scene::set_player`, [scene_player.rs](src/map/scene_player.rs)) as one entity in its own pass, animated, lit and casting shadows apart from the unit cutoffs and display switches, and wherever it flies: it draws on every map copy its own bounds reach inside the view volume, however high above the band the map's objects are admitted in. It casts as every caster does, on the canonical and each seam view with the light matrix translated for each. A frame that does not move it changes nothing, and a moved one rebuilds its one-instance field in the storage it keeps.

`slow-tests` preserves installation and GPU gates. Shared synthetic GPU inputs come from foundation's opt-in `test-support`; world test helpers are enabled through the same feature for host composition tests. Follow the workspace [working rules](../../AGENTS.md).

Aircraft declaration admission uses `Roster::refused_declaration` for ordinary and lazy bakes, recorded-roster fallbacks, recorded mesh retries and draw counterparts. Fly resolves through that same admission before requiring geometry in the accepted bake, so a plane recovered from the recording can be flown too; meshless actors still retain their events in recorded flights.
