# viewer-world

The GPU scene, world labels, immutable scene content, draw passes and native shader adapters, political fill, terrain and weather, borders, names, rivers, trees, static and animated model rendering, model selection, buildings, railways, trains, strike effects, floating map text and post-processing. Content and shader sources resolve through the recorded installed-content stack.

[Terrain](src/map/terrain.rs) is the approved uniform grid for the game's camera and, for a free camera, the content shader's 64-cell blocks at the coarsest step their distance allows with snapped edges, on every map copy the view reaches; a free camera over a map whose sides are not whole blocks refuses its terrain pass by name. A free camera's [shadow](src/map/shadow.rs) map fits the receivers near its eye.

Aircraft and unit figures retain their own admission, pose and model selection. The host supplies concrete air-base and region tables and shared recorded air/unit reads from foundation, and composes the GPU scene with counter and raid outputs. These passes consume concrete resources and draw operands, with shared upload, camera, GUI and visibility contracts from viewer-foundation. Selected movement routes and composed battle-plan/raid ribbons arrive as concrete draw data; world owns their GPU submission. [Strike effects](src/map/strike_effects.rs) play the content's nuclear and critical-bombardment entities from recorded `NuclearStrikes` and `MapEvents`, and its missile explosion entity where an aircraft missile bombing scenario finishes or in the mission region of a launch-flagged launch effect whose entity finishes. [Floating map text](src/map/animated_map_text.rs) prepares each hour's recorded map events per viewing country by the game's own filters on the hour builders, presents each event once, and draws them with the content's animated map text types in per-province queues. Pass-local caches, retained shader bindings, native traversal and animation clocks belong to their existing owners.

`slow-tests` preserves installation and GPU gates. Shared synthetic GPU inputs come from foundation's opt-in `test-support`; world test helpers are enabled through the same feature for host composition tests. Follow the workspace [working rules](../../AGENTS.md).
