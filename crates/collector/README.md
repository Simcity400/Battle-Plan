# Collector

`collector` is the DLL the recorder injects into `hoi4.exe`. It captures scheduled native data at the hourly sampling boundary, then hands owned payloads to off-thread decoding, diffing and replay output.

Native layouts, offsets and guarded readers belong in [`engine`](../engine/README.md). Replay schemas, cadence and encoding belong in [`replay`](../replay/README.md).

Live-sized and potentially large rows, arenas, byte buffers, decode pools,
staging, slicing, encoded records and status JSON use the shared checked-growth
helpers in [engine](../engine/src/allocation.rs). Batch reserves cover subsequent
appends. Terminal errors use static codes; borrowed status snapshots serialize
once into recycled byte buffers without building JSON trees. Raw plans install
only after complete construction, decoded frames publish only after the terminal
gate, and encoder baselines advance only after a complete spool record.

Accepted residuals are main's small fixed storage and attach-time machinery:
standard Arc/Weak control blocks, path/OS-string and filesystem handle storage,
thread names/handles and std spawn internals, fixed pack/verifier/fingerprint
boxes and Part collections, standard hasher initialization, short ordinary diagnostics,
JSON config parsing, module/event path buffers, retour hook installation and
teardown, fixed ArrayQueue construction, worker lists, and attach-only replay
history discovery/inflation. Large data owned by those objects remains checked.
These residuals are outside the fault sweep's checked-growth scope.

Recorded `pool_bytes` keeps the existing storage estimate. Its executor part
uses the prior shared layout and standard thread-handle accounting, excluding
the added failure context. Recovery therefore
does not change healthy Metrics values.

The first allocation failure stops admission and abandons incomplete work while
the original game tick continues. Before hooks are installed, the recorder
creates the [terminal witness](../replay/src/witness.rs) and the collector opens
its handle. Failure writes a fixed, versioned, checksummed record without heap
growth. That witness is authoritative over periodic status. After confirmed
unload, the recorder keeps the CRC-valid prefix as a visibly partial replay and
uses the witnessed attempted hour for an explicit gap; idle failures invent no
hour. Missing or invalid evidence leaves the spool incomplete and retained.

The optional `alloc-fault-injection` feature enables the recorder's
`--alloc-fault` option. The default build refuses that option. Allocation phases
and static failure codes are defined in [witness.rs](../replay/src/witness.rs).

[equipment_destruction.rs](src/equipment_destruction.rs) observes land damage,
attrition's actual subtraction call, aircraft destruction and garrison
resistance for every native owner, without player or orders-group predicates.
Pre/native/post reads and bounded appends run on the writer's thread; buffer
growth uses the live country registry and saved design census off-thread. A
try-lock never waits: overlap, refusal, overflow or lost publication withholds
the table for the rest of that branch. First/load/discontinuity intervals are
partial and unavailable. The hourly game thread drains owned rows; aggregation
and encoding run off-thread. The engine maps supported writer return PCs to
semantic causes before recording; an unknown caller records `unknown` and is
counted without guessing. Status exposes each hook, cumulative failure and
unknown-caller counters, and the highest interval event count with its buffer
capacity (including partial or refused intervals). Failed off-thread sizing
observations count `prepare_failures` and skip growth without invalidating the
existing branch observation. Both detach quiescence checks include every
writer's ACTIVE counter, including while its original is running outside the DLL.

Run the ignored `equipment_destruction::tests::destruction_scale_bench` test in
release through the build wrapper, with `--ignored --nocapture --test-threads=1`.
It exercises the actual callback and SEH-guarded reads at the design and stress
country scales. Synthetic timing does not certify game slowdown or live cost.

## What to collect

Collect the least data the viewer and dashboard need to display, so recording costs the game as little as possible. Record the value the game already stores for what is displayed. Capture inputs instead only when the game does not store the result (it computes it on demand), when the result depends on the viewing country or camera, when it is text the game has already localised (display text follows the viewer's language, not the recording client's), or when it is much larger than its inputs. Every new table, field or cadence increase must serve something visible and be measured against its capture cost.

Raid naming, capture and save comparison follow the [raid tooltip contract](../viewer/src/map/raids/tooltips/README.md).

The naval details pack follows the [naval modifier tree contract](../replay/README.md#naval-modifier-breakdowns); future reuse needs the writer coverage described below.

Its tree arenas start empty and grow on the spool thread from capture demand.
A short arena still counts every request, root, node, display byte and depth
in the same capture pass. When requests do not fit, allocation-free request
re-enumeration selects each distinct accumulator and its actual key union;
each tree is walked once, so demand matches a full capture. When
depth scratch is short, borrowed worker-stack ancestor frames finish the walk
and check cycles. A check of the worker's actual stack reservation leaves
64 KiB of safety headroom before recursion; exhaustion is a named, counted
refusal, never an abort or a content-depth cap. One short-arena hour reports
all demand; after spool-side growth, the next unchanged population captures
completely. A later rise costs the same single refusal while the spool keeps
up; frames captured before the spool grew from the refusing one refuse too, so
a backlog of k frames can cost up to k+1 refused hours. No partial tree is
published, no population cap is imposed, and capture allocates no tree storage.
Uses share the request arena; their replay projection allocates off-thread.
The production loan/restore/growth regression includes broad four-level trees
and carrier/escape requests and requires exactly one counted refusal.
Growth consumes every captured hour's demand before reset, including after
earlier complete captures. A later-rise regression exceeds all five arenas,
then requires one refusal, complete capture after growth, and no further
refusal when demand falls and rises within retained capacity.

`status.json.naval_modifier_breakdowns` counts sampled, available and refused
hours, groups refusals by their exact names, and reports each arena's latest
required and allocated lengths (text in bytes). The spool worker observes these
before growth, including captures whose frame is subsequently rejected;
clockless frames do not recount an earlier capture.

Ship modifier inputs still read afresh at combat cadence. Their selected sources
include independently mutable medals, doctrine, fuel, HQ membership and leader
adjusters ([native writer evidence](../engine/src/naval_ship_modifier_inputs.rs));
the country/ship/leader modifier rebuilds alone cannot certify those inputs.
Future reuse needs complete writer and receiver-lifetime coverage before hooks
can certify it, followed by fresh-read verify mode and coordinated burn-in under
the watched-writer rules below. A limited trace with no mismatch does not prove
unexercised writer paths.

The ignored `naval_window_operand_scale_bench` release test runs the real naval
details capture and measures owned projection separately. Its quiet, typical
and all-changed fixtures keep the same population and mutate values outside
the timers. They measure synthetic callback cost, not live gameplay slowdown.

## How an hour is captured

[hook.rs](src/hook.rs) detours `CGameState::HourlyUpdate` at its entry. The game mutates state immediately after that entry: **there is no free, stable interval after the trampoline**. `sampling.rs` resets the frame, takes the country snapshot, dispatches and joins acquisition jobs, then returns into the game's hourly update. Required native reads must finish before that return, including reads performed by workers.

This boundary holds the simulation thread, not every native writer. Graphics caches and the token dictionary retain their targeted consistency checks. A detected overlapping change makes the affected data unavailable; capture never waits for those writers or retries their reads.

There are two capture paths. **Raw-copy jobs** stage spans in a `RawLog`; the decode thread replays the typed walk against owned memory. The pack's `raw_mode` tells `capture_tables` not to repeat that walk against live memory. **Typed-walk jobs** fill pack buffers directly, borrowing them through `take_*_request` and returning them through `restore_*_request`. Packs own their rows and arenas; conversion happens off the game thread.

Owned copies must be sufficient for deferred work: decoding must never follow live game pointers. Guard every native read, and preserve source order, identity checks, meaningful pointer occurrences, bounds and the first independent failure. Address equality alone does not identify a table or read occurrence; shared acquisition and raw-log lookups must retain each consumer's scope, including empty and overflow paths.

A failed or short read is not an empty table, a zero value or a complete row. Never call engine functions to obtain values, wait for memory to change or retry to hide a failure.

## Scheduling, buffers and failures

AirRegionalMissions joins the wing census to ordinary regional registrations. Carrier combat regions can be listed with an empty ordinary vector and count as zero ([field evidence](../engine/src/cair_regional_mission.rs)). A failed census withholds its dependent joins instead of publishing empty rows, and its reason names the first known country slot and region.

Keep typed walks in pool jobs. Document necessary game-thread exceptions beside the code; for example, the state-flags walk depends on the States rows. The States job also copies each state's two display-name strings (CState+0x38 and +0xE8, `cstate::read_names`) into the frame's own name arena at their native lengths; a row that does not fit truncates the table for that hour and the spool thread grows the arena, as it does for faction names. Dispatch according to dependencies, not merely available workers:

| Dependency | Dispatch rule |
|---|---|
| Live memory only | Eligible for the first dispatch burst; use the appropriate ordinary job. |
| Shared division inputs | Wait until the input packet is available to its consumers. |
| Raw-copy verdicts used by `GatedPacks` | Join the required raw jobs first, then dispatch `GatedPacks`. |
| Map-sample visitors, such as wing sources and order roots | Dispatch `LatePacks` after the map sample. |
| The wing census alone (registered missions, naval-patrol combats) | Dispatch AirMissions once the census is installed: before the map sample for the owned census, after it for a typed one. Join it before `LatePacks`, which reads its registrations. |

**The Gated ordering prevents a specific ownership bug.** Multi-pack jobs swap the live packs with spare sets. Dispatching before a required raw verdict is installed makes the flag land on the spare set, not the pack already loaned to the worker; that pack then walks without the verdict.

`Role::priority()` orders queued jobs by their dependencies, lower first and FIFO among equals. The character role jobs are dispatched after the roster join, with the portrait shares, and joined at the typed-fallback boundary. Short, early-joined jobs must not wait behind large, late-joined jobs; the exception is the longest hourly jobs (World, Governance, Research), which claim first because the block cannot end before they do. With few workers, early-joined short jobs can then wait for one of them, so check the callback join waits on a constrained machine when changing this order. A join waits only for its own job: it must not execute unrelated queued work, and jobs must not submit other jobs. The pool has one worker per logical CPU in the game's process affinity, less one for the callback. A join spins on its own running ticket, for at most the recorder's per-hour budget, while another worker is idle, because a parked game thread can wait for a free CPU long after its job finishes; with every worker busy it parks at once. The decode and spool threads run below normal priority except while the capture buffers are backlogged, when the game thread may be waiting for them; `background_priority` in `status.json` counts the changes. The collector never changes a game thread's priority or affinity.

Tables with one or a fixed few rows per country slot are sized from the live country registry, never from a vanilla count: once before the hook is installed and again whenever the spool thread sees the registry grow (a save loaded after attaching at the main menu fills it before its first hourly tick). [country_scale.rs](src/country_scale.rs) owns the per-table factors; the same observation presizes the country authentication cache, which the hook swaps in without allocating, and the raw-copy job censuses. Nothing caps the country count below the engine's own u16 slot ceiling. Arenas whose per-country demand content decides are sized from that live demand instead: the raid type tokens of every raid parent and the player cache, and every country's convoy reservation words (`country_scale::observe_raid_arenas`), before the hook and whenever the spool thread sees the demand grow (at most once a second, like the CountryIntel total). A full hour, whose sliced reads have no earlier rows to merge into, must read every row, so these are never left to the walk's own growth. The same holds for Characters, sized from the live roster's rows and its names' and template files' bytes, and for ScriptFlags, sized from every flag manager's own count, characters' included (`country_scale::observe_characters`, on the same schedule). The political tables whose sizes content and play decide are sized from their own walks run with no row storage, which count every row from array headers (`country_scale::observe_politics`, on the same schedule): CountryCharacters and CountryRetiredCharacters from every country's active and retired records, the character inputs from their own roster walk, PartyLeaders from every party's leader vector, CountryCivilWars from every country's civil-war array, AdvisorTokens from the set's keys and their bytes, FactionAdvisors from every faction's occupied advisor slots and their tokens. CountryCharacters and CountryRetiredCharacters are read hourly in the Slow job's hired advisors pack, in one walk of the same per-country character object; HiredAdvisors keeps its daily slot. CharacterRoleTraits and CharacterOperatives are read hourly in the Slow job's character inputs pack, from one pass over the character roster: its pointers in pages and each page's identities and role fields in one guarded gather, then only the nonempty role maps, scientist roles and nonzero unit-leader references. PartyLeaders is read in the governance family's hourly politics walk, from the same authenticated political status as Politics and PoliticalParties, and charged to its own table. CountryCivilWars is read in the country counter pack, over the same country census as CountryCounterInputs. AdvisorTokens is read hourly in the hired advisors pack (the advisor family) and published sorted by its keys' bytes. FactionAdvisors is read hourly in the faction theatres pack, over the same faction roster.

The production-tick log and its drain buffers follow the live equipment-line population (`country_scale::observe_production_lines`), counted by ProductionLines' existing walk with no row storage. The loader sizes them before installing the production hooks; the spool observes the rosters on the same schedule as the arena demand, even when the country registry is unchanged. [line_output.rs](src/line_output.rs) reserves two daily passes, leaving room for entries a short drain keeps waiting while its storage grows. After draining, the hourly callback installs an offered larger log only when it is empty and no writer is active, preserving cursor and epoch; the spool frees the retired log. Capacity only rises, with no population ceiling. An actual overflow or unobserved tick still withholds the branch's output; `line_output.capacity` and `swaps` in `status.json` report the installed log.

Reuse spare sets and return loaned buffers through the matching restore path. Their boxes hold allocation-free vacant packs while parked; the real preallocated packs move into the worker and back. Do not fill spare placeholders with default-capacity buffers. Keep allocation and capacity growth off the game thread.

Keep these outcomes distinct:

| Outcome | Required behaviour |
|---|---|
| Submission rejected, such as a full pool | Run inline exactly once at that job's join, except worker-only Governance, Variants, Orders, Ordinary, Presentation and the AirCountryRelations and AirNavalPatrolHistories parts: publish `Unavailable` without live reads (a rejected relation part also withdraws its certificates; a rejected history part fails its hour, whose settle withdraws every part's certificates). |
| Accepted job panics or is stopped | Terminal for that hour: publish `Unavailable` with the failure reason, do not retry live reads, and do not convert partial rows. |
| Raw staging overflows | Grow staging capacity off-thread. Before a prepared source observation, the existing typed fallback is allowed; afterward, fail the capture without repeating live reads. This is not an accepted-job panic or stop. |
| A job's staging is too small for headers it has already read (AirCountryRelations) | Grow it on the pool worker (the parts never run on the game thread) with a fallible allocation, and grow the other buffers off-thread from that demand. A header longer than the live country-link count, or an allocation failure, fails the part `Unavailable` with a named reason; it never aborts the game. |
| Bounded walk truncates | Publish `Truncated { len, unread_rows }`, preserve growth demand and grow buffers off-thread. |

A Rust panic in callback coordination stops acquisition for that attachment. The incomplete buffer remains owned until unload; subsequent hours become explicit losses while the loader restores the hook, drains completed captures and reports the terminal failure.

Native-original callback risks include the portrait, advisor, relation, history
and opinion observer families, and equipment destruction's `land`, `air`,
`garrison` and `attrition` callbacks in
[equipment_destruction.rs](src/equipment_destruction.rs). They invoke native
originals from `extern "system"` callbacks with a non-unwinding ABI. A Rust panic
or native exception unwinding through those boundaries can terminate the game
process; native exception safety is unverified for these existing observer
patterns.

The longest hourly jobs leave first: the ShipModels census, World, Research and, off the Focus slot, Governance at the highest claim priority. The callback joins the short census before the World join and dispatches the ShipModels details at the next claim priority, so a worker-only family such as Governance never queues behind them on a small pool: one part per 512 ships of the live census, at most four (a part no worker takes runs inline when the callback joins it), each over a contiguous census range with its own capture, memos and snapshot arena, bounded by the whole read ceiling as the unsplit walk was. Part captures grow with the family (`part_rows`), so every range fits; a range that does not is a broken invariant and publishes the family unavailable. The callback joins the parts last-dispatched first, so queued parts run inline instead of parking. Rows and outcomes join in census order, so the first failure keeps its position; an interrupted part is terminal for the family. The game never stores a ship's maximum organisation (hoi4re note on 140c28730), so the details recompute it and the split, not a stored-value read, shortens the path. Governance otherwise waits for the World join, which decides whether World delegated that hour's Focus walk; off that slot nothing is delegated. The variant registry and its detail tables run in their own daily Variants job, off the Governance critical path, and leave in the first burst on their slot only. Governance, Variants, Orders, Ordinary, Presentation, AirMissions, every ETA range and each air relation and history part have reserved pool slots and batch tickets. Their building, variant, order, combat and membership payloads can grow from already-read counts during acquisition, so the callback must never execute them, including fallback and unwind paths. Growth keeps the original observation; it does not restart the walk. Restore Gated before Governance returns its building buffers to construction; consume the building and variant timings once during final table assembly.

## Cadence and freshness

Clocked acquisition checks the complete built-in modifier layout (every built-in row and the gap) and the static lexer tokens ([fixed_layout.rs](src/fixed_layout.rs)) until one check completes consistently, then keeps that result for the attachment; an hour whose check was interrupted refuses every consumer and checks again. The check waits for a clocked hour because a recorder waiting for the game injects during startup, while built-in and dynamic keys may still be registering. The built-in layout is one contract: a mismatch in any row, used by a reader or not, refuses every table that reads a fixed modifier key; a failed static token refuses the tables that use it. `status.json.fixed_layout` shows the static token maximum, every mismatch (`layout_failures`) and each named refusal. Conversion replaces only those tables, after slice merging and carried-data recovery, so no held baseline restores an unchecked value, and refusals never request a full refresh.

[cadence.rs](../replay/src/cadence.rs) is the authority. There are three cadences: hourly, daily and static. Map data is hourly. Relations (opinions and relation tuples) are read once a day, one owner slice per hour through the slicing framework, so an opinion or relation changed by an event can show up to a game day late; the owner accepted that lag. Province names are daily, so a rename can also show up a day late. Buildings are hourly: bombing changes a building's mesh and fire within the hour. Land theatre headers are hourly because battle plans draw in the theatre roster order an hourly orders group names; theatre groups, members and air theatres keep their shared daily slot. Character identities, unit leaders, persistent character roles, unit-leader traits with their experience, and scientist rosters are hourly: effects, commands and the hourly experience pass change them at any hour, and a tactic's `has_trait` reads them. ScriptFlags (every flag scope, the characters' included) and ActiveIdeas are hourly: effects set and clear flags and add and remove ideas at any hour, and the triggers that read them see the change in that hour. A character's role traits, its unit-leader reference with the operands of the leader it resolves to, and each country's retired records are hourly for the same reason (the character inputs pack and the hired advisors pack in the Slow job). Each country's appointed-advisor list (HiredAdvisors) keeps a daily slot; the advisor roles are also read at that hour, so an appointed advisor's role comes from the same refresh. CountryResources is hourly: effects, commands and building level changes rewrite its produced and adjustment pools at any hour, and a tactic's resource count reads them. ResourceExchanges is hourly too: trade commands, effects and the AI create and cancel deals at any hour, and the game's hourly trade task rewrites their deliveries. The resource census is walked with them every hour and published in its daily slot ([economy.rs](src/extended/economy.rs)). Other panel data uses daily slots too. Keep shared-source families together and preserve the approved cadence when comparing capture implementations.

Static means the **whole table** cannot change after a save loads. Static tables are captured on full hours: branch start, load, gap, or an hour requested with `recorder refresh`. The hook-certified captures read everything afresh on an invalidating hour (branch start, load, gap, or the recovery hour after a failed or dropped one): AirCountryRelations copies every country's vectors there, and the naval-patrol history parts copy every held history (AirNavalPatrolHistories). The owner's load-hour exemption from the per-hour budget covers these hours, and every other hour stays hook-driven: a watch-table install or clear waits for such an hour (see `relation_changes` below). A periodic encoding keyframe is not a full hour: the spool builds it from the complete rows it already holds for every staggered and sliced table on the branch, so the keyframe hour reads no more than any other hour. Character portraits remain hourly because new generals can appear even when an existing character's portrait tokens do not change.

A sliced table (`Cadence::Sliced`) is refreshed one owner slice per hour, so no hour reads the whole table. Owners are native country IDs, canonical country slots or native state IDs, one kind per family. A family is registered in [slicing.rs](src/slicing.rs) (`FAMILIES`, with its owner kind and tables) and has its own `SliceSelection` per frame and its own `SliceFingerprints` store for the attachment, so a country and a state with the same ID never share a bit. Each hour the family reads the owners of that hour's slice (`cadence::slice_active`), every owner on a full hour, and every owner whose change fingerprint differs from its last observation, including an owner seen for the first time (a new or re-aliased ID) and every owner after the store is forgotten. The fingerprint is family-specific and only adds reads. A read that is selected but not published (a failed or truncated table, a failed job, or a frame dropped before decode) is invalidated so its owners are read again at the next hour; a failed job forgets the store, and so does a walked read the spool could not convert or merge (for example duplicate keys, an out-of-arena name or an unselected owner's row), since the game thread saw it succeed; the spool then drops that family's earlier rows, so no hour merges rows from before the failure until a full read replaces them. A fingerprint that cannot be read certifies nothing, so its owner is read at every hour until it reads again; a fingerprint pass that fails or truncates reads every owner that hour. Owners above the fingerprint range (the u16 slot range) have no fingerprint and are read at every hour; they are counted in `status.json` `slices.<family>`. Rows carry no hour: the spool records the hour each owner's rows of each owned sliced table were read at in the SliceReads table (one row per table and owner, updated only for the owners read at that hour), so an owner's unchanged rows stay unchanged when it is read again. Register the row type in [sliced.rs](../replay/src/sliced.rs) (`SlicedRow`, `merge_slice`); consumers use `replay::sliced::read_hour`. A family may also have a keyed table without owners (TechnologyDefinitions): a complete, non-empty read replaces it (`replay::sliced::replaces_whole`), an incomplete read replaces only the rows whose keys it returned, and an empty read keeps it. The spool merges each read into the previous complete table on the branch (only the read owners' rows are replaced, so the encoder emits changed rows only). The scan also records the live owners; after a complete census the merge drops the rows of owners it no longer sees, so a vanished or re-aliased owner's rows leave at the next hour rather than at its next slice, and the store forgets them, so a returning or reused ID is read at once. Without earlier rows it publishes the table unavailable and requests a full refresh. A truncated read replaces only the owners it returned rows for; the others keep their earlier rows in that truncated view, and because the view is not the base for the next merge, an owner's read hour can move back by one hour in the following frame until its re-read completes.

A family's fingerprint may be exact, deliberately cheap or constant. The raid input families (launch inputs by country slot, state inputs and state cores by state, building resource overrides by country), the commanders' retreat bans (DivisionRetreatBans, by the canonical slot of each division's roster owner, read in the Presentation job) and relations use a constant one: each owner is read at its daily slice, and at once only when it is new to the census or its last read was not published. Owner rule: capture no harsher than the game, which re-checks raid offers in a rolling sweep, so a raid input can lag up to a day. A retreat ban is recorded whatever the division's combats; the reader applies it only while the division is in one. The save does not serialize the commander's cached modifier block, so DivisionRetreatBans is unverified against saves. CountryCommandPower, the hourly per-country modifier totals the raid code reads live (the command power pair the stability dashboard shows, and the ace country modifiers every flying raid and launch range reads), is read every hour for every country in the launch walk; an unselected country evaluates only those keys. RaidSpeedInputs names an ace's countries by canonical slot instead of reading those totals again, so each stored value keeps one reader; its `transport_speeds` remains the documented exception (see the [replay README](../replay/README.md)).

RaidAirScores is hourly, but the game rewrites a strategic region's air scores only in that region's phase hour, one hour in `2 * NAir::HOURS_DELAY_AFTER_EACH_COMBAT` ([raid_air_scores.rs](../engine/src/raid_air_scores.rs)). After one complete read, each hour reads only the regions rewritten that hour and carries the rest from a held table, which the Late job borrows from `Shared` like the ETA cadence stores. A full-refresh hour, a skipped or failed hour, a changed define or region roster, and any country whose score array moved read everything again.

Off-slot hours record `SKIPPED_REASON`; replay carries the previous data forward. Truncated staggered tables and failed static tables set `Shared.force_next`, forcing a full capture next hour with buffers grown off-thread. The lexer's maximum token ID is checked hourly; a change triggers another token-dictionary capture. The modifier definition table's header (data pointer and row count) is checked the same way; a change, which only a database loader's registration causes, triggers another ModifierDefinitions capture on that hour's Slow job.

Record `DivisionEtaInputs` and let replay derive ETA. **Five-hour ETA operand staleness (accepted limitation):** every moving division has an hourly witness of each order and path field the reader takes from the census: the exact ordinary route IDs (native writers refill it in place), target, source, location, owners, orders group, template, stat block, retreat, strategic redeployment and naval transfer, plus the combat vector header, so entering or leaving combat reads at once. A new division, changed witness, or its stagger slot (full handle modulo five) refreshes all operands; unchanged divisions carry their latest row and `sample_hour`. Organisation, fuel, combat progress and modifier changes wait for the slot. Attach, load, hour gaps, forced full refreshes and failed acquisitions re-read every moving division, so each partition's buffers grow to its whole moving census, not to one hour's selection. Stable handle partitions keep each division with the same worker when other divisions arrive, leave or reroute. Each worker retains its own store across frame-buffer reuse and publishes complete latest rows, so lost frames need no incremental merge. These jobs are worker-only; rejected jobs report unavailable without callback allocation or live retry.

The ETA cadence contribution to recorded `Metrics.pool_bytes` retains its logical-entry estimate for recording compatibility. The formula stays beside [cadence.rs](src/extended/division_eta_inputs/cadence.rs), and checked batch reservations preserve the prior selected-row and carried-row capacity schedules. It is not an exact retained-heap measurement: checked entry slabs keep spare capacity after deletions, while deleted witnesses and row owners are released. The estimate can therefore undercount actual retained storage.

The five-hour allowance follows the native counter cache TTL seed (`140be98e0`) and hourly expiry (`140bf0300`). **This does not reproduce the native cache history or its pathfinding estimate.** The viewer derives stored-route ETA from the latest operands and current movement/progress and shared hourly map data; rows are zero to four completed hours old between refreshes. Do not source these operands from daily tables. The fresh-save oracle checks every row's moving census, provenance and route-bounded spans, and counts carried rows separately; a carried row's route is witnessed, so a span failure there is a missed change.

DivisionMovement samples strategic-action operands only on the reached branch.
The movement projection preserves per-row query refusals and modifier-only
changes. A refused query leaves movement and other divisions available.
See the [shared reader contract](../engine/README.md#strategic-action-operands).

## Reducing capture cost without changing data

**Reduce guarded calls, not just bytes.** `engine::Memory::copy` is an in-process, SEH-guarded copy. `copy_records` and `copy_scattered_prefetched<N>` gather multiple spans inside one guarded frame, avoiding repeated guard overhead. Divide per-table calls by row count to find repeated per-object work. Use a `const RecordLayout` for fixed-shape fields (`DIVISION_SEED_FIELDS` and `UNIT_ORDER_LAYOUT` are examples), scatter reads for independent fields, and `read_slice` for contiguous arrays. Batch predictable pointer enumeration; retain individual reads for unpredictable pointer chases. Preserve fault scope and ordering when batching.

**Reuse inputs at their proved lifetime.** Existing patterns include supply outer-map reuse (`InnerMemo`), ship doctrine and modifier metadata (`OrganisationMemo`, `DefinitionMemo`), province authentication (`ProvinceMemo`), geometry (`StaticGeometry`), the relation opinion baseline (`crelation_status::Baseline`, below), and the land combat walk's census participants, commander selections, per-source division results and batched division fields (`combat_details`). A batched division-field gather that fails for one division serves it nothing: that division's own reader then reads each field once itself, where it would have read it, and meets its own failure there. That is the unbatched read, not a retry of the failed gather's value, and nothing read successfully is read twice. #71's division image behaves the same way. Key reuse by what invalidates it, such as module base, game state, play session or census header—not just a reused address. Reloadable defines, weather structures and mutable definitions are not automatically session-static. Shared inputs must preserve each consumer's identity and failure behaviour.

A character's template identity (tag, file, line and generated byte) is read once per template pointer. The pointer rides in the name token span every character view copies each hour, and only a character's build and a save load write it; the roster job keeps the identities its decodes produced (`TemplateCache`) and reads a template again only for a new or changed pointer, on a full hour or in another game state. The decode supplies a kept identity exactly where the copy skipped the read, and the kept identities' generation keys the prepared program, so a program never skips a read its decode needs.

The character reader prepares its validated read geometry on recycle in [raw_plan.rs](src/raw_plan.rs). Each execution still acquires fresh character, role and leader values, including both name strings. Changed controls resume the ordinary producer from the exact acquired prefix; a failed native read is never retried. Prepared metadata and memory hints remove repeated discovery work without assuming that names or role definitions are immutable. The trait capture also retains the vector-source bindings selected by those checked controls. It freshly acquires every trait vector, definition and experience value on its scheduled refresh; only a complete acquisition at matching capacities can seed those bindings. Partial or exhausted binding storage keeps the ordinary producer, and allocation stays on recycle. Empty fields create no source observation and are omitted from prepared programs; nonempty observations retain their order, table scope and exact failure continuation.

Separate jobs acquire the character roster and unit leaders, country-leader roles, advisor roles, and traits. Each has its own reusable storage and prepared program. The decode worker merges only the tables owned by each part; a failed part cannot erase another part or retry a failed native read. Only the roster is joined before portraits and role jobs; role and trait verdicts wait until the typed-fallback boundary, letting unrelated jobs start sooner. Worker durations overlap: measure the callback wall directly, rather than summing table timings.

The ordinary advisor job executes historical and generated rosters sequentially with separate prepared programs. Both current roster headers are authenticated before either body; growth or relocation of one vector invalidates only that section's geometry. Every pointer, character identity, advisor map, role and string is acquired fresh, including inactive roles. Owned decoding retains section scope, original occurrence order and the first failure. Exhaustion after an earlier prepared source observation cannot restart the table against live memory. Section diagnostics distinguish complete prepared executions from rediscovery; neither section is an extra scheduled job.

The default `advisor_changes` feature uses an owned per-character definition cache in [characters/advisors.rs](src/extended/characters/advisors.rs). Each scheduled acquisition freshly checks the complete roster, identities, countries, map headers and sentinels; with an admitted role census (below) the census supplies all but the sentinels. Only unchanged entries with uninterrupted observed mutation revisions reuse their role rows and literal bytes; current country values are applied independently. Historical and generated rosters have independent prepared control plans. An unchanged section certifies its owned result in one guarded execution; a changed or failed control supplies its already-observed prefix to rediscovery without retrying memory. Plans are compiled on recycle after a complete, fully watched capture, including the first one. Role payload reads are omitted from control discovery and retain the native batched source path; their reuse is certified by mutation revisions. Country values are still read and fault-checked on every pass, but are applied to owned rows as fresh data instead of triggering equality-control rebuilds. Each country binding preserves its exact roster occurrence. Generated-roster growth cannot invalidate the historical plan. Pointer-selected prefetch hints overlap independent memory latency and remain behind their selecting control comparisons; they acquire no data. All characters and roles remain included. Separate source and destination arenas let one role grow without invalidating later characters' cached bytes. Capacity growth and replay conversion stay off the callback. The payload pool retains these typed buffers even though they have no raw-log spans.

[advisor_changes.rs](src/advisor_changes.rs) observes the pinned construction, destruction, role-field and map mutation boundaries documented in [advisor_mutations.rs](../engine/src/advisor_mutations.rs). Shared map helpers only notify exact registered map addresses. Notifications perform bounded atomic bookkeeping and, for role receivers, one guarded owner lookup; they do not capture or serialize roles. A quiet whole-domain revision avoids redundant per-character watch lookups. Loads, gaps, recovery and watch failures revoke reuse; detachment drains these callbacks before freeing their code. `advisor_verify` freshly reads every proposed hit and checks exact rows, byte content and order. Mismatches disable reuse for the attachment. Diagnostic status records verification, changed/reused work and notification overhead separately from capture wall time. Exercised-path verification does not substitute for native writer coverage. The optional `advisor_profile` feature retains a bounded set of per-section wall ticks, thread cycles and prepared-read stop details, including initial attachment; it adds no timing calls to the default path.

The default `opinion_changes` feature keeps the relation opinions between relations refreshes. [opinion_changes.rs](src/opinion_changes.rs) observes the opinion writers proved in [opinion_mutations.rs](../engine/src/opinion_mutations.rs). `RecomputeOpinion` and `Reset` append a status to a bounded lock-free log when the opinion they leave differs from the one they found; they also run on the daily TBB workers. Each entry also holds the status's owning diplomacy (`CRelationStatus+0x1F0`), which the detour reads from the status it is writing. Only the status constructor writes that field, and it equals the owner's `CCountry+0xF88` (proof in `captures\hooks\writers.md`, "Relation opinions"). `LoadToken` and the constructor, which run only while a game state is loaded or rebuilt, start a new epoch instead, as do loads, gaps, recovery and every hook state change. Pooled relations jobs borrow one shared `crelation_status::Baseline`, which keeps rows and pending marks per owner. Relations are read one owner slice per hour, so an opinion refresh drains the log and files each mark under its owner without reading memory. A mark then waits for that owner's slice. At its slice, an owner that is still valid and whose country, diplomacy and matrix header are unchanged replays its recorded rows, with each of its marked statuses authenticated (its vtable, owning diplomacy and target, and the owner's matrix entry at that slot) and re-read. Owners are valid one by one. A changed owner, or one whose rows or pending marks did not fit, becomes invalid alone. A lost observation (the log overflowed, a writer was mid-append, a mark failed to authenticate or the epoch moved) makes every owner invalid. An invalid owner is read in full at its next slice, and its rows become its baseline from then on. Rows, order and truncation are those of a walk that reads every status of the slice. `opinion_verify` walks every status of the same slice after each replay and compares; a mismatch poisons the observation for the attachment and keeps the reference rows. Verify mode never publishes a replay it could not compare: until its storage holds the job's rows, the walk reads every selected owner in full. `opinion_verify` is in the default features until the burn-in passes, as the owner's rule requires. Opinions have this exact full-read fallback, so unlike the portrait and advisor hooks, an unrecognised writer prologue or a detour that cannot be created leaves the opinion hooks uninstalled rather than refusing to attach: every refresh then reads every status. Counters, including that reason (`unhooked`), live under `opinion_changes` in `status.json`.

The game counts no line's output, so ProductionLineOutput comes from hooks. [line_output.rs](src/line_output.rs) detours the two sites in [line_output_sites.rs](../engine/src/line_output_sites.rs). Each detour is reached through a two-instruction naked entry that passes the game's return address in the free fourth argument register. The delivery site, called from one of the four ProduceEquipment call sites, leaves its amount pending on its thread; the rocket line's delivery, and any other caller's, leaves nothing. The credit site takes that pending delivery and appends the line's handle, producing country, variant and organisation, the delivered units and the credited count to a bounded lock-free log. An entry is exact only when its credit came from one of the four ProduceEquipment call sites and any pending delivery came from the same ProduceEquipment, for the same variant, without a second pending delivery, in nonnegative whole units equal to the credit. That includes a military conversion clamped to zero, which delivers and credits zero; a credit without a delivery (a naval line that cannot deploy, or a tick that completes nothing) is exact too. The producer is read through the line's production status to its country, with guarded reads checking the line, status and country vtables, the line's handle, the country's nonzero id and its status backlink. A failed producer read starts a new epoch, withholding the table until the next branch; `failed_producer_reads` counts these failures. No game function is called. Every clocked callback drains the log into its frame's preallocated `line_output` entries, advancing only past what it copied, so a short buffer leaves the rest for a later hour after off-thread growth. The spool's `extended::line_output::Totals` adds each frame's entries to the current branch's per-line totals. A new branch starts at its first drain's log position. A later drain must continue the log exactly: a dropped frame, an overflowed log, a new epoch or an unobserved drain makes the table unavailable from that hour, carried or not, until the next branch. The table is published with the frame's ProductionLines census, which decides which lines ended and which were created after the branch's first census. An ended line is dropped only after a written frame has held its final rows, published or carried, so a failed write cannot lose them. It is carried when the census is skipped, and unavailable when the census is incomplete or ticks before the sample are still in the log. The table has no full-read fallback: an unrecognised prologue leaves the hooks uninstalled and the table unavailable with the reason. Counters live under `line_output` in `status.json`.

ConstructionLineOutput observes building and railway daily advances through [construction_ic.rs](src/construction_ic.rs), reading only receivers and the two named globals and separating factory construction, repairs, CIC-bank draw, instant progress and railway carries; every matching building advance counts as a tick, including zero-IC advances and natural repairs. The primary entry retains the partner's CID: both rows are linked, and the partner's amount is an inexact unknown share of the primary's combined output, never an exact zero. It shares [output_log.rs](src/output_log.rs), [hook installation](src/output_hooks.rs), drain storage, branch totals, first-census provenance and written-publication retention in [output_continuity.rs](src/extended/output_continuity.rs) with ProductionLineOutput, publishes beside the construction census, and preserves refusal reasons in the table and `status.json`; the ignored `construction_ic_scale` release test measures synthetic incremental hook/drain cost.

Each character job reserves storage for the tables it owns; only the trait owner allocates trait definitions and occurrence buffers. Initial raw and preparation capacities follow the job's shape. Larger captures retain the existing bounded fallback and off-thread growth paths, rather than imposing a smaller data limit.

A complete prepared acquisition loans its immutable span geometry to owned decoding by swapping buffers. Recycle returns the geometry before clearing or retiring the plan; no descriptor list is copied on the callback. Source values remain fresh. Character acquisition diagnostics distinguish prepared backend wall time from the remaining capture work; these overlapping job intervals are not an additive callback breakdown.

Capture-buffer reuse depends on the entire downstream pipeline, not just decode queue depth. After conversion has produced owned replay input and diagnostic snapshots, the spool worker grows and returns the capture buffer before encoding and writing. A truncated input retains its buffer until a successful write publishes the required full-refresh request. Prepared input must be written before preparing another frame or flushing because comparison tokens refer to the current encoder baseline. The spool worker reports buffer service through recycling and idle-flush wall time separately. Periodic disk synchronization runs on a bounded durability worker; initial segments, forced boundaries and detach still wait for completed synchronization. File-write delays can still hold up conversion of queued frames and exhaust the finite capture pool, so buffer-wait counters and callback tails remain required performance checks.

The roster job also owns a bounded [portrait census](../engine/src/ccharacter_manager.rs): authenticated pointer/identity occurrences with successful country reads, in roster order. The callback joins only this producer before dispatching portrait shares, allowing portrait reads to overlap the remaining character jobs, and loans only a complete current census. A successful prepared character pass certifies the retained occurrence sequence through fresh pointer and identity checks. A partial diagnostic pass preserves that association only when every occurrence is identical; a changed census retires the old plan. Without an admitted census, portraits take their independent primary path. Every loan returns before the character job can be recycled.

On hours when a role job runs, the roster job also gathers a [role census](src/extended/characters/census.rs) after its pass: for every occurrence of its complete, freshly certified portrait census, the country, both role-map headers and the unit-leader pointer, in one guarded record gather. It is admitted only when every field of every occurrence copies; a retained loan, a short census or an unreadable field leaves it unadmitted, and storage grows off-thread. The role jobs borrow an admitted census instead of walking the roster, pointer pages and character views again; without one they walk the roster independently. Country-leader roles and traits record exactly the reads, failures and order the independent walk makes from each map header or unit pointer on; their decode replays those reads over the census occurrences, so rows, arenas, outcomes and demand are identical. Every map sentinel is still read and checked, including empty maps; sentinels are gathered in batches of up to 128 ahead of their maps, and a batch ends at a header that fails before its sentinel read. An empty leader map with a valid sentinel yields no row and no decode read, so it is not retained. The advisor cache keeps its reuse and verification rules; its prepared plan then traces only sentinels, and certification also requires every occurrence, identity and map header to repeat. The feature-gated advisor section reader keeps its independent roster walk.

The `portrait_changes` feature observes native portrait writers and lifetimes in [portrait_changes.rs](src/portrait_changes.rs), with pinned writer evidence in [ccharacter_portraits.rs](../engine/src/ccharacter_portraits.rs). Every hourly occurrence still has fresh ownership, identity, country readability and array-header validation. Only descriptor entries with the same owner, arena position and uninterrupted quiet mutation revision can reuse owned bytes. The bounded watch registry keeps exact addresses; collisions never invalidate unrelated entries, and watch exhaustion falls back to fresh descriptor reads. Native callbacks execute the original function and only update atomic metadata.

[snapshot_plan.rs](src/snapshot_plan.rs) prepares portrait dependency checks only from a fully reused warm walk, so a cold descriptor read cannot accidentally become permanent hourly work. A quiet, unchanged pass retains the owned sorted rows. Shared-census passes first match every current pointer/identity occurrence, then acquire fresh headers with bounded lookahead hints. Partial or failed walks invalidate their cache. Loads, gaps and recovery invalidate the observer epoch; a continuous encoding keyframe retains certified native inputs while still emitting a complete replay snapshot.

`portrait_verify` retains the ordinary descriptor reads and compares every proposed hit with current data. A mismatch permanently disables reuse for that attachment. Its counters live in `status.json`, outside replay data. This checks exercised paths, not unexercised writer coverage. The observer is disabled before its detours are removed, and callback return paths drain before their trampolines or DLL can be freed. A future rolling refresh needs explicit observation provenance; it cannot use this mutation-certified current-value contract to label older unchecked rows as fresh.

`CountryTacticUnlocks` is read whole every hour: one row copy and one list copy per country from the callback's authenticated roster (about 0.31 ms at 5,000 countries x 32 unlocks, synthetic, release). No list is reused between hours, because the doctrine tactic vector's writer set is not proven; [country_tactic_unlocks.rs](../engine/src/country_tactic_unlocks.rs) lists the known writers.

The leader portrait and picture-directory packs (LeaderPortraits, LeaderPortraitPaths) run in the Late job and borrow that hour's complete orders-group census. They read only the leaders of groups with both an HQ provider and a leader, which is the viewer's HQ predicate for every country and camera, deduplicate them and copy their stored strings fresh each hour. An incomplete census withholds both tables and its demand grows storage off-thread. CharacterPortraits keeps the whole character roster for the dashboard.

The Orders job walks the army order census (ArmyOrders) and, over that same census, the plan operands (ArmyOrderPlans, OrdersGroupPlans, Fronts) and InvasionPreparations ([plans.rs](src/extended/plans.rs)). The invasion walk reads each census order's type and, only once it meets a naval invasion, the country and province tables of the hour's game state; an incomplete census withholds the table, a read failure makes only InvasionPreparations unavailable, and rows that do not fit are counted and grow storage off-thread.

The default `relation_changes` feature observes the writers of the country vectors AirCountryRelations records ([relation_changes.rs](src/relation_changes.rs), evidence in [diplomacy_mutations.rs](../engine/src/diplomacy_mutations.rs)). [air_relations.rs](src/extended/air_relations.rs) splits the hour into parallel pool jobs, each owning every eighth country slot. A job copies only the raw vectors of countries a writer touched, or whose slot changed, into its staging buffer, in batched gathers and scattered copies; a quiet hour copies nothing. The decode thread turns the copies into held rows in hour order and emits the table by slice and on change ([slicing.rs](src/slicing.rs)), so row building, the diff and the emission stay off the game thread. A frame dropped before decoding withdraws the certificates its copies advanced. The watched receivers live in the shared [watch registry](src/watch_registry.rs), sized from the country registry before the hooks are installed and regrown off-thread as it grows. At the hourly callback, before any capture and only while no notification is running, it installs a larger table or clears the current one (after a load, gap or recovery, or once dead receivers fill half of it); both start a new epoch, so no dropped registration can certify anything. An epoch makes every receiver be read afresh, so an install or a clear waits for the next invalidating hour (attach, load, gap or recovery, the recorder's full hours, which already read everything afresh), and so does one a running notification blocks at such an hour; until then a receiver the table refuses is read afresh every hour, and `status.json` counts the held boundaries (`held_for_full_hour`). No row is ever reused without a matching certificate, so a held hour stays exact. At worst, with every receiver refused, it copies every country each hour, the same cost as a full hour; the relation benchmark's held-table hours measure that. Only the first table installs at once, since nothing is certified without one. A full table refuses a registration, which `status.json` counts; that receiver is read afresh every hour. `relation_verify` also copies every country afresh each hour in the same parts and, on the decode thread, compares that copy with the held rows once the hour's copies are applied. Mismatches are counted in `status.json`, and the first one disables reuse for the attachment. This checks exercised paths, not unexercised writer coverage. `relation_verify` is in the default features until the burn-in passes, as the owner's rule requires.

The default `history_changes` feature observes the two writers of the country air histories that naval-patrol scenarios read ([history_changes.rs](src/history_changes.rs), evidence in [air_history_mutations.rs](../engine/src/air_history_mutations.rs)). The AirMissions job captures the registered missions and the naval-patrol combats and opens the hour in [air_histories.rs](src/extended/air_histories.rs): every part gets the patrolled regions and one quiet and site verdict against the last complete hour. Parallel worker-only AirHistories jobs, dispatched with the Late job and each owning every eighth slot, then only copy, each into its own staging with its own certificates. A quiet hour with the same regions and country air objects copies nothing. Otherwise a country whose air object a writer touched, or whose object changed, is authenticated (64 air objects to a gather) and copied afresh; every add goes through the country-marking writer, so a history of an unmarked country changed only by the advances its own hook counted, and those are staged as counts without a read. A history whose count was not observed is copied on its own, and a newly wanted region is copied for every country. All reads are gathers batched across countries and histories. The game thread certifies an hour only when every part completed: a failed part or AirMissions job withdraws every part's certificates before the next hour opens, and so does a frame dropped before decoding. The decode thread applies all of an hour's copies and advances to the held histories in hour order, or none of them for a failed hour, which it publishes unavailable (an advance moves the current slot, wraps and zeroes the record moved to). It emits the table by slice and on change ([slicing.rs](src/slicing.rs)); an advance shifts every summation index, so a country holding histories is emitted again on the day they advance. The watches are their own domain of the shared [watch registry](src/watch_registry.rs), cleared only on a load, gap or recovery, because a clear starts an epoch and the next hour would copy every held history again. The table is presized for each country slot's air object and a history in every strategic region of the content, from the live country registry and the live strategic-region roster (`CGameState+0x2E0`, [cgame_state.rs](../engine/src/cgame_state.rs)), before the hooks are installed and whenever either grows. With fixed, readable rosters, visiting more of the known regions therefore installs no larger table. A roster that grows mid-campaign, an unreadable roster or accumulated dead receivers can still call for a larger table, grown off-thread from each hour's air objects, wanted regions and registrations; as for the relation watches, it is installed only at the next invalidating hour, which already copies every held history afresh, and until then a refused receiver is read afresh every hour; a full table refuses a registration, which `status.json` counts. `history_changes.restarts` in `status.json` counts the hours that copied every held history afresh, by cause: `invalidation` (a load, gap, recovery or attach), `table_install` (the first table, installed at once when none was ready at the invalidating hour) and `failed_hour` (the hour before failed a part or its AirMissions job, or was dropped before decoding). Staging is presized from the registry and grown on recycle from what an hour used; a copy larger than any before grows in its job. Each part presizes its certificates inside its own job when the capacities rise, so no job waits on a lock the spool thread holds, and a steady hour allocates nothing. `history_verify` also copies every part afresh each hour and disables reuse on a difference. It is in the default features until the burn-in passes, as the owner's rule requires.

TaskForceMissions shares the hourly fleet walk of [naval_counters.rs](src/extended/naval_counters.rs) with the task-force and fleet counter inputs and the task-force motion, and its time is charged to the task-force table. For each task force the walk has authenticated, it authenticates the embedded mission itself (vtable and task-force back-pointer, the check the counter row shares, so a full counter buffer does not skip it) and copies the mission's owner, current region and accessible regions (in order, with repeats) into a row buffer and a region arena, skipping a mission with neither region. A buffer that is too short truncates the table with its demand, and both grow off-thread; a failed walk, or a region that is not the one registered at its own roster slot, makes the table unavailable.

**Split only measured bottlenecks.** Workers contend for cores and memory; more parallelism is not automatically faster. For country-grouped walks, interleave outer units by every n-th slot rather than taking contiguous ranges, because large countries occupy neighbouring slots. Each share repeats header and first-fault work. Keep separate rows and arenas per `Part`, put once-per-family work in part 0, and restore single-walk row order at conversion. Merge outcomes so any `Unavailable` wins; otherwise sum lengths and unread counts. Preserve duplicate occurrences and capacity demand.

## Changing a capture path

**Add a table.** Add its replay row and ID in [rows.rs](../replay/src/rows.rs) or [extended row modules](../replay/src/extended_rows/), its cadence entry, and an `extended/<pack>.rs` pack with `N`, `TABLES`, `READ_GROUPS`, `Capacities` and `Captured`'s `capture`, `outcomes` and `tables`. Register it in `packs!` in [extended/mod.rs](src/extended/mod.rs), then wire acquisition and conversion through the appropriate job. Change the [format](../replay/src/format.rs) version when the wire or recorded observation semantics change. Only the current format is supported; update its writers and consumers together.

**Move a pack into a job.** In [extended/packs.rs](src/extended/packs.rs), wire its `Captured` through the matching multi-pack struct, `spare()`, `capture`, `swap_*` and take/restore paths; remove the former inline walk without breaking the failure distinctions above. A dedicated job also needs `Job`, `Report`, `Role`, `read_anchor`, `priority`, `ROLE_COUNT`, `ROLES`, `Job::role`, and dependency-correct dispatch/join points in `sampling.rs`.

**Change native readers in `engine`.** Read the [reverse-engineering guide](../../tools/re/README.md) first. Keep one source file per native struct, with evidence beside constants: native writer, serializer or function, width, signedness and confirmation. Use `C:\Tools\hoi4_mcp\hoi4re.cmd` and save established names, fields and notes. If decompilation drops arguments or arithmetic, inspect indexed instructions; distinguish virtual addresses from image-relative RVAs. Old readers, including `archive/pre-rewrite-2026-09-09`, are research leads, not proof. Stored fields, calculated getters and renderer caches are different sources; similar save values are not interchangeable evidence.

## Testing and measurement

Use existing synthetic-memory fixtures to check aliases, invalid pointers, short reads, exact first failures, capacity and growth demand, and owned-versus-direct equivalence. Share splits repeat first-fault reads and cache keys add reads; update counted expectations deliberately. Check each changed crate with the shared [build commands](../../AGENTS.md#build-commands). New capture domains need collector/replay integration and an oracle comparison or an explicit limitation. See the [recorder guide](../recorder/README.md#inspect-and-compare) for hourly-sample versus later-save limits and the separate live smoke workflow.

Use [tools/bench.ps1](../../tools/bench.ps1), frozen builds and a same-run no-recorder baseline. Do not compile during timed windows or trust throughput percentages from a locked desktop or collapsed baseline. Acquire `%TEMP%\claude\hoi4_game.lock\owner` before controlling the game; release it by renaming the lock directory to `hoi4_game.lock.released-<stamp>-<why>`. Leave the game running and paused.

`status.json` and `content.json` are written on their own thread ([status_writer.rs](src/status_writer.rs)), owned by the loader. The spool thread only hands over the latest snapshot and never waits on their I/O: a slow disk or a blocking reader coalesces snapshots instead of holding the capture buffers the game thread waits for (#94). The writer also measures `spool_bytes`, so building a snapshot touches no file. A failed write is retried later unless a newer snapshot replaced it. `status_writer` in `status.json` counts writes, failures and coalesced snapshots, and `spool_work.status_update` is now only building the snapshot and handing it over. The loader joins the writer only after the spool thread has returned and callbacks are quiescent. The spool thread's other I/O is unchanged: replay segment writes and durability barriers, the once-a-second `recorder refresh` request check, and the detach drain. `status.json` is rewritten about every second, through a temporary file and an atomic POSIX-semantics rename, which succeeds while a reader holds the old file open with delete sharing. Output directories that do not support POSIX rename (network shares, FAT) fall back to a classic replace, which any open reader blocks, even one that shares delete; the collector remembers that for the attachment. Read it with delete sharing (Rust `std::fs` does; in PowerShell open a `FileStream` with `FileShare.ReadWrite -bor FileShare.Delete`). `Get-Content` and `[IO.File]::ReadAllText` do not share delete: a slow read then blocks the replacement; the writer thread retries it later, and the failure is kept as the recording's warning. The smoke and bench scripts read it with delete sharing.

The blocking acquisition time is the primary diagnostic. In the documented instrumentation, `status.json` exposes `acquisition_work.mean_ns` (`collect_wait`), `block_phases.segments_mean_ns` and `join_wait_by_role_mean_ns`; `SEGMENTS_SCOPE` names the segments. Inspect p50, p95 and maximum as well as means. Earlier benchmark evidence found extra smoothing frames during long ticks, with a threshold around a 16 ms block; remeasure that threshold rather than treating it as universal.

The optional `callback_profile` feature retains a bounded set of slow hourly callbacks in `status.json`, with the game hour, wall time, game-thread cycles, disjoint acquisition phases, fixed segments and job-join times. It records no extra native game reads, takes no lock and allocates no storage on the callback. Cycles are not milliseconds; compare them with wall time to investigate waiting or descheduling. A join that spins on its running job (see Scheduling) counts as game-thread cycles, not as waiting; the pool's `spins` counter in `status.json` shows how often that happened. The default build has no profiling calls. Per-hour evidence is needed to explain a particular spike; cumulative means cannot reconstruct it.

Skipped hours contribute zero to per-table means. For a table captured once every 24 hours, its per-walk cost is 24 times the all-hour mean; extra full captures change that frequency. Compare job durations per completed call, not just averaged join waits. The documented `workers.roles[].ticks` uses 10 MHz ticks; use the checked-out branch's actual units and counter definitions.

Attribute native reads with `read_accounting::table(TableId)` and keep `table_ns` timings truthful. Decoding owned memory is not another native read. Performance counters belong in `status.json`, not replay schemas or the spool; do not add runtime verification windows or second reads to those outputs.

Record measured block and throughput changes in the commit or PR, separately from fixture read-count savings. Keep simple, demonstrated reductions in work even when throughput variance hides their individual effect; say what was proved. The naval combat icon sources (NavalProvinceCombats, NavalCombatTransfers, NavalTransferUnits) are hourly. Each province's combat vector is copied whole with every entry's class, since the progress size counts engaged combats of any class; a combat's transfer vector is copied raw; a transfer's units keep only the handles that resolve to a unit, as the native placement test and the save do. Distinct transfers are found by sorting in the caller's row buffer and the retained results' province ordinals come from one pass over the result map, so both walks are linear in guarded reads; synthetic fixtures count them at 1,500 and 5,000 entries.

[unit_scale_tests.rs](src/unit_scale_tests.rs) measures unit populations independently of country count using the [engine fixture](../engine/tests/support/unit_world.rs) and extended order fixture. Run `cargo test -p collector --release unit_scale -- --ignored --nocapture --test-threads=1` through the build slot. `BATTLE_PLAN_UNIT_SHAPE=design|stress` isolates population peaks; `BATTLE_PLAN_UNIT_VALIDATE=1` validates rows without timed repetitions. Report callback seed/copy work separately from overlapping worker passes, full refresh separately from ordinary hours, and fixture memory separately from retained capture capacity. The activity and equipment topology are declared in the fixtures; empty combat/request lists do not benchmark populated ones.

Research inputs, applied-bonus attribution and modifier breakdowns belong to the governance family but run in their own Research job, which walks its own country census. They are the `research` sliced family, owned by countries. The fingerprint (`engine::research_inputs::fingerprint_country`) covers every research slot, each slot's technology, applied days and speed, and each assigned technology's level, classifier and applied bonuses, but not daily progress, banked days or modifier sources. So a new, cancelled or completed assignment, a slot added or removed, and a new country are read within the hour, while a change that only moves a research modifier (an idea, law, advisor, decision, scientist, licence or sharing change) waits for the country's slice. hoi4re records the writers (research audit 2026-09-25): research is not daily-only. That keeps the family's largest hourly walk off the Governance critical path; the rows return into the family before its tables are published, and a failed Research job cannot erase the rest of the family. Rows are preallocated and converted outside capture; the bonus roster is read once per country only when applied IDs need resolution, and the modifier table fails independently of inputs and bonuses. Synthetic memory tests cover read calls, failure isolation and truncation.

Stability inputs and tree lines (CountryStabilityInputs, CountryStabilityLines) are the `stability` sliced family, owned by countries and read in the Slow job, which carries the family's fingerprint store. The fingerprint (`engine::country_stability::fingerprint_country`) covers the bases, the stored penalty and coastal terms, the ruling party's popularity, the diplomacy war counter, the tree's child header, the tracked keys' root entries, the identities of the replayed sources (active ideas, the ruling party and its first leader, appointed advisors, and each dynamic modifier entry's definition, scope and enabled state), so a modifier recalculation, a weekly base change or a source replaced by one with the same tracked values is read within the hour; a change of only the war predicates or world tension waits for the country's slice. The tracked keys are resolved by name once per modifier definition table header. The allocated command power and the command power maximum's modifier totals are CountryCommandPower's, read every hour for every country by the raid launch inputs job, not here. A country whose lines do not fit writes none and is counted, so its earlier lines stay in the truncated view. A failed Slow job forgets the store, an incomplete read invalidates its selection, and without a loaned store (the inline fallback) only the hour's slice is read.

The economy family's fuel walk fills CountryFuel and CountryFuelConsumers from one read of each country's fuel status, in the typed walk and in the raw copy alike. CountryFuel's ring sums need the 24-entry history ring, which the raw copy stages under CountryFuel's fault bit; the consumer entries carry their own, so a failed ring withholds only CountryFuel. Consumer capacity scales with the country registry by the engine's fixed consumer count, and a country's consumers are stored whole or counted unread. The economy-rest raw copy times its shared read under the hourly ProvinceSupply, so at the daily slot hour of CountryFuel, CountryFuelConsumers, CountryExperience, HubMotorization, DisruptedSupply, ForeignHomebases and PurchaseContracts none of them is timed; only full hours time them. Readers date these reads by the cadence's slot hour (`dashboard::metadata::slot_read`), never by their timing alone.

The logistics pack (LogisticsEquipment) runs in the Slow job on daily slot 0, the first sample after the daily update that writes the logistics records. It evaluates the AI-control predicate for every country but follows the logistics history only of countries it rejects, the only ones the game computes the balance for, so its rows do not scale with the country registry: capacity starts at a few such countries' archetypes and grows off-thread after a truncated read. A country's rows are stored whole or counted unread.

The Combat Log pack (CombatLogEquipment, CombatLogState, LendLeaseEquipment) runs in the Slow job. CombatLogEquipment is the `combat_log` sliced family, owned by countries, without a fingerprint store: each hour reads its slice's countries. A country whose last complete read was in this or the previous calendar month is read through each array's last two month entries; a country never read completely in this session or read earlier, and every country at a full hour, is read whole. A failed Slow job, a dropped frame or a Combat Log family the spool could not publish (`combat_log::forget_reads`) forgets every country's last read. At the last sample before the daily update (raw hour `% 24 == 23`) it also reads every country holding a log whose orders group is gone. Orders groups can also be deleted inside that update's own tick, after the sample, so [combat_log_prune.rs](src/combat_log_prune.rs) detours the prune (`engine::ncombat_log_cmanager::PRUNE_RVA`) and, before the original runs, copies each log about to be deleted into a bounded multi-producer log (the prune may run on the daily workers; writers touch only the rows they reserved, through raw element pointers), each row tagged with the session's load signal. The next sample drains its own session's rows, and each final row is published once, with a read of its country, then kept for a day (`RETAIN_HOURS`) and published again after any sign that a read went unpublished or at a full hour. The finals and the last reads are one store shared by every capture buffer, for one session: a load starts it afresh and discards the rows the left session logged. A log that fills, a read that fails, or a hook not installed or enabled makes the hour's `CombatLogState.prune_observed` 0; the detour only reads and calls the original, and counters live under `combat_log_prune` in `status.json`, including cumulative `observe_total_ns` and maximum `observe_max_ns` wall time on the executing daily-task thread, outside hourly callback timing. The task path and roughly 60 KB nested stack footprint are cited in the module; the executable reserves 4 MB, while the TBB worker reserve still needs verification. CombatLogState (the native country-gate operand and that flag) explains why the game did not keep a country's land losses; it never selects capture. The writer additionally requires an orders group and a runtime feature-enable operand recorded separately by SimulationFeatures, so this state alone cannot certify complete coverage. Every country's held records are read regardless of player, human, AI or viewpoint status. It is read every hour; LendLeaseEquipment on daily slot 23. Rows follow the logged countries' orders groups, months and variants, not the country registry; capacity starts at 4096 rows and grows off-thread after a truncated read. Synthetic release costs are in the engine benchmark; live cost is unmeasured.

The faction walk reads each faction's template pointer (CFaction+0x568), its whole `CColor` (+0x9d0: vtable and four f32 at +0x10) and the colour-override byte (+0x9c0) in one guarded record copy with its literal name, hourly, then a templated faction's template vtable and lexer token (+0x08) in one span; the template is authenticated by `CFactionTemplate`'s vtable and the colour by `CColor`'s, and a foreign template or colour fails the table rather than being guessed. The offsets are cited beside the engine reader (`engine::cfaction`).

CountryFactories is its own pack in the Slow job: one row per canonical country, read hourly (the game recalculates the totals within any hour), sized by the country registry. The walk makes two guarded calls per country and fails whole; native reads and time are charged to this table. Its stored group-head levels drive `num_of_controlled_factories` and scripted-text seeds through the unified trigger evaluator. Row storage grows off the callback; its cost has not been measured live.

ProductionLines' efficiency comes from the same line read. The production-rest raw copy stages each line's efficiency header with its other fields, then what the line's maximum factories need (the variant's type link and classifier, the type's and its archetype's optionals, and the six defines once, at the first line that needs one) and the clamped efficiency entries, so the replayed walk reads exactly what the typed walk reads.

IndustrialOrganisations and IndustrialOrganisationHistory come from one typed walk of every country's organisations in the Slow job, on the production lines' daily slot, so a line and the organisation it names come from the same hour. Capacity presizes a few rows of each per country slot and grows from truncation off-thread.

Technology rosters (ResearchTechnologies) are the `technologies` sliced family, owned by countries and read in the Governance job's country walk; the family's store is loaned with that job. A roster changes daily for every country (progress), so a change fingerprint would cost as much as the walk: the family scans a constant fingerprint, which reads a new country and a selected but unpublished read at the next hour and otherwise waits for the country's slice. A completed technology therefore reaches ResearchTechnologies at the country's slice, as it did at the old daily slot; the research family still reads the completing assignment within the hour. TechnologyDefinitions holds the templates the hour's rosters reach. Every roster covers the whole template database, so a complete read replaces the table (templates removed by a reload leave with it) and only an incomplete read is merged by technology handle. Templates are not static: hoi4re shows that the console command `reloadtechnologies` re-parses the database after a load (template writer audit 2026-09-25, note on `140abcfc0`), and every roster covers the whole database, so any hour with a live country in its slice refreshes every definition. The research conversion memo was removed with the daily table: a sliced read never repeats the previous hour's native rows, and unchanged definition rows already encode as no change.

[naval_details.rs](src/extended/naval_details.rs) also captures NavalCombatAirBaseWingHandles: one row per air base a captured naval combat references (a ship's weapon context or a plane's base), in first-reference order, with every dense wing occurrence including repeats; a referenced base with no wings keeps an explicit empty row. A full row buffer or wing arena truncates the table and grows off-thread to the reported demand.

[naval_counters.rs](src/extended/naval_counters.rs) serves TaskForceCounterInputs, FleetCounterInputs and TaskForceMapMotion from one country, fleet and task-force walk, whose time is charged to task forces. The motion rows take every task force the walk authenticates, with their routes in one arena: a full row buffer or arena truncates the table and grows off-thread to the reported demand, and a failed fleet walk leaves the motion census unavailable. A handle in two fleet rosters is a torn census, found off the game thread, and makes the table unavailable. First-combat answers use the capture's own memo, reserved off-thread and cleared for each capture.

The country-counter walk copies the handle of each country's first roster division, the invasion route's last unit fallback. The InvasionPreparations walk (Orders job) copies the sea-route cost operands of each invasion's route unit owner: its slot-zero relation and the nonzero co-belligerent bytes named by its wartime-ally and enemy vectors, read once per owner per hour. Only owners with an invasion are read, so the cost scales with invading owners times their allies and enemies, not with every country pair. The co-belligerent slots share one arena that grows off the callback.

LocalPlayer is captured in the visibility worker with an independent failure outcome. It copies the two adjacent stored client references once per hour. Their writers run between ticks, so a tag switch, MP controller assignment or observer selection appears at the next sample, which holds exactly the references that tick's combat manager tests. The acquisition is one guarded eight-byte read, with constant storage independent of country count; live cost remains to be measured.

Agency-name storage is also presized from live string demand by `country_scale::observe_politics`, then grows from the walk's exact required bytes. The hourly appearance walk also copies each country's three retained old-name strings. Gender is a Characters-only span in the shared character copy plan; its failure leaves independent role spans usable. Country and state manpower operands are copied with their existing hourly rows, and the country projection includes the residual in change detection.

Naval mission icon operands ([naval_mission_inputs.rs](src/extended/naval_mission_inputs.rs)) run in the Slow job. One authenticated fleet walk gathers strike, raid, escort and invasion-support operands and the complete task-force census. Ledger discovery scans each navy's live region headers, independently of the narrower accessible-region list, preserving registrations in order with repeats. Presence is read for every nonempty ledger: the icon also updates unlisted escort entries while they fade out. Country modifiers/hubs and fleet-leader/HQ accumulators use the `naval_missions` daily sliced family, with SliceReads witnesses; new countries or changed leader/commander references are refreshed within the hour. Arenas grow off-thread to live demand, and partial walks cannot publish the dependent family. The ignored `naval_mission_bench` test measures the synthetic capture at country scale; it does not establish live recorder cost.

The naval mission commander slice includes explicit rows for successfully read references
that contribute zero. Missing commander rows remain unknown in playback. An unresolved
mission or expeditionary owner keeps its raw reference in the operand row and is excluded
from the sliced family census. Playback names the missing link; the ledger and other
country and commander inputs remain available.

The saved-global target pack sizes both its row buffer and name arena from the live registry header and stored string lengths before capture, and raises demand off-thread after growth. Its hourly worker reads no event-chain targets and performs no allocations or game calls. Capacity shortages withhold completeness and retain exact demand; the synthetic collector test covers 5,000 saved country targets.

DivisionCensus records hourly grouped and ungrouped division counts for every country, including countries with no divisions, from the existing authenticated division census and core projection in [division_census.rs](src/division_census.rs). The count uses the Combat Log writer's signed-positive expeditionary owner, otherwise the roster owner; distinct raw aliases keep their own rows and resolve through CountryLinks. No player-status filter or second division walk is used. A failed or incomplete core census withholds the counts; terminal job failures retain their raw reason and pending row growth demand. An owner outside the live country-link array is unavailable with that reason, not a capacity shortage. Country storage follows the live registry and grows off the callback; no partial country total is certified complete. Native reads and accumulation time are charged once to the shared Divisions read group, with no extra native reads; spool conversion is charged to its own pack. Synthetic accumulation cost is measured by `division_coverage_counts_scale`; live cost remains unverified. Every complete hourly census is a read, including equal reads; unavailable hours cannot carry certified coverage.

Province-hover border inputs reuse the States worker and the existing hourly tables. [StateFlags](src/extended/state_flags.rs) reads the adjacent DMZ/active bytes for every authenticated state and acquires ordered country pairs only from active state trees. After States, Provinces, ProvinceUnitOrder and Presentation join, [border_inputs](src/extended/border_inputs.rs) uses every active state as the perspective-independent demand union. It copies only their class0 armies' cached defense/soft/hard attack and every active province controller's stored land-doctrine level, including controllers of empty provinces. Existing country and unit censuses supply identities; no second census or all-country scalar scan occurs. Optional payloads are absent only outside demand; a failed shared demand census withholds both dependent tables, while doctrine faults withhold only Countries and army-stat faults only DivisionStatus. Pre-existing truncated or unavailable census outcomes retain their original reasons. The native cache values and runtime state-tree order need later matched evidence because text saves do not certify them.
