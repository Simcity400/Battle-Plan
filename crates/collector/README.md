# Collector

`collector` is the Windows x64 DLL the [recorder](../recorder/README.md) injects into the supported HOI4 process. It captures native state and hands owned data to off-thread decoding and replay output.

Read the [shared rules](../../AGENTS.md). Native layouts and guarded reads belong in [engine](../engine/README.md), schemas and cadence in [replay](../replay/README.md), and content resolution in [installed-content](../installed-content/README.md). Per-capture behaviour stays beside code.

## How it works

The loader worker prepares the process-wide executable tables from the verified game module and its shipped documentation before publishing hooks. Modifier spelling checks use scratch storage sized from those tables before callback admission; callbacks perform no metadata loading or allocation.

Hourly callback → acquisition jobs → owned buffers → decode/conversion → diff/encode → recoverable spool. `DllMain` defers initialization to a worker outside the loader lock.

The spool thread converts with two persistent [helpers](src/spool_helper.rs): the first converts the map tables and lane 0 of the packs carrying a helper marker in [extended/mod.rs](src/extended/mod.rs), the second lane 1, while the spool thread converts the core tables and the other packs, then merges; a lone helper converts both lanes. `@helper` and `@helper_b` packs must be statically `Sync`, as must what `@helper_appearance` (country appearance) reads; the lane-0 `@helper_exclusive` pack (division presentation) and the `@helper_cached_*` packs (characters, intel, character portraits) may hold interior mutability only because no other thread touches them while their lane converts. The spool thread lends the character and intel conversion caches (shadows and the script-variable comparison) to the lane converting those packs for the join; other helper packs use only the projection, whose scratch is locked per table. Output lands in the serial slots and the failed-ordinary-job refusal follows the merge. Before encoding, the spool thread and the helpers [compare](src/spool_compare.rs) each complete hourly table with the encoder's baseline for exactly that hour: an equal table becomes `ComparedEqual`, one whose keys all keep their baseline positions with at most three quarters of its rows differing carries only the differing rows, and anything else stays complete; a densely changed table is not compared again for a game day, since replacing most rows costs the encoder more than its full path. The encoder writes the same bytes for each form, so frames are identical with any number of helpers. A sliced table whose held rows are the encoder's shared baseline for the hour reaches it as a slice update of those rows rather than a merged copy, so only the read owners' rows are compared and replaced; the cache follows the write's outcome, taking the merged rows when it fails. The spool thread and the helpers then [encode](src/spool_segments.rs) the frame's tables with at least 64 rows to compare or write at once, largest first, and the spool thread assembles the frame in table order. Each commit hands back the baselines, rows and inputs it no longer holds, and the sizing thread frees them. A persistent sizing thread beside the spool thread runs the live sizing reads, the capture-buffer growth they request and the between-tick observer preparation, after each hour and on the spool's idle cadence; the spool thread returns each buffer and raises capacities under the same capacity lock, records the sizing thread's refusals in its status, hands it the latest allocation context for a terminal witness, ends on its terminal failure, and sizes inline when the thread cannot start. Decode, spool, helper and sizing threads reserve explicit 16 MiB stacks, run below normal priority, at normal only while capture buffers are backlogged, and never take dynamic wake-up boosts.

After each committed frame, `status.json` names the recording client's viewed country for Battle Plan Recorder as `player`: its own tag, cosmetic tag, original-or-own tag and ruling ideology group, the operands that pick its flag. They come from the encoder's committed `LocalPlayer`, `CountryLinks`, `Countries`, `CountryAppearance`, `Politics` and `PoliticalParties` rows through [replay's country_flags](../replay/src/country_flags.rs); nothing is read from the game for them. The text is copied with checked allocation only when it changes, and `player` is omitted while any of those rows is unavailable.

The hook enters the hourly update before the clock advances; the sample is the settled end of the labelled hour. Every live read, including worker reads, finishes before the trampoline runs. There is no stable interval after it. The boundary holds the simulation thread, not every native writer: retain consistency guards for concurrent caches and dictionaries, refusing overlapping changes without waiting or retrying.

Campaign text, cadence identity and retained loss text are prepared from the native stored length by the loader/spool. A callback parks for longer text preparation before reading its payload; preparation uses queue leases and a try-only spool gate so frame backpressure can still drain. Observer identity epochs advance only on exact full-byte campaign changes. Optional clock polling is advisory; a parked capture's required destination is checked capture storage. Clock faults and advisory misses are named and counted in status.

Raw-copy jobs stage spans in a `RawLog` for typed decoding over owned memory; typed jobs fill preallocated rows and arenas. Deferred work never follows live game pointers. Use matching take/restore paths and allocation-free parked spares. Install raw verdicts before loaning dependent packs; join shared-source producers before dispatching consumers. A job's only dispatch edges are the outputs it reads: every job that needs no other job's output leaves in the first burst, which queues without waking the pool and is released with one wake (`Batch::hold`/`release`), except the slack burst below, the jobs other jobs wait for, the World job (the production and construction rests) and the Economy job (the economy rest), the last two joined together in the fifth segment, after the raw-copy joins (the final borrowers read the economy and production rests; the construction rest's verdict is set before the Gated dispatch), claiming first, then the longest independent jobs ([`Role::priority`](src/acquisition_jobs.rs)); each dependent job leaves right after the last join it reads, and the game thread joins the producers in the order they are expected to finish. Both add their worker time to `world_acquisition_ns`, and the Economy job, which runs every hour, observes the country cache (`world_country_cache`). The Ordinary family runs as independent parts (land combat, naval combat, map counters, task forces, and the physical navy pass with the naval mission ledgers that borrow it), all but the task forces in the first burst; only its counter part, which reads the reserved naming the Countries job leaves in the appearance pack, waits for that join. The navy pass fills its own reserved launch sources, installed into the appearance pack when the family returns; a failed or refused part refuses the whole family's tables, as one job did. The template job (DivisionTemplates and DivisionTemplateIcons) leaves in the first burst beside Countries, reading the shared country cache and each template's icon and demanded names directly; the game thread joins it after the relation joins and takes its preacquired walk before the tables. The war overview (WarOwnedRelations, WarRelationGoals, WarOverviewCountries and WarNameRules) is its own first-burst WarOverview job beside Slow, the daily production slot's IndustrialOrganisations and the production modifiers (CountryProductionModifiers, ProductionLineModifiers) are the first-burst ProductionDaily job at that slot only, joined last before the table assembly (off the slot they are skipped without a read); on the slot the production modifier capture is split into up to four consecutive census slot ranges balanced by the previous slot's countries and lines, the first in that job and the others in ProductionModifierPart jobs joined right after it, each range's rows being the whole walk's for its slots and the define context read once on the game thread for all of them, and the tables walk the ranges in slot order, the first failed range refusing them with its reason, and CountryStabilityInputs and CountryStabilityLines are another, the Stability job, with the `stability` family's fingerprint store on loan. Both are queued after Slow, the war overview first, and the game thread joins them in that order right after Slow; a war overview failure refuses only its four tables, and a stability failure refuses both stability tables and forgets the store. The AirMissions job leaves as soon as the air wing job joins and also joins the registered missions with the wing census (AirReferenceWitnesses, the sortie inputs and NavalMineLevels), which read nothing else, so the Late job keeps them and a Late failure no longer fails them; the joins take country bytes from the hour's snapshot (`Cache::bytes_view`) and read each registry header, the air manager's province lists and the province roster once per pass; the air statistics and base verdicts, which only the Late job reads from the same pack, are installed when it returns. The Presentation, Intel and ProvinceUnitOrder jobs leave as soon as the division inputs join, the Presentation job as two: its status side (DivisionStatus's status and naming passes, DivisionRetreatBans and the attack operands) and the PresentationMovement job beside it (DivisionLandInputs, DivisionMovement and DivisionStatus's dig-in factors), which reads nothing of the status side and returns its storage at the Presentation join. The dig-in pass reads every census division and is cut there to the status pass's rows, which is what reading only those rows publishes, since each factor is its own division's reads. A failed or rejected job on either side fails the whole presentation. The status side claims a worker first among the waiting jobs, being the longest job that waits for another. ProvinceUnitOrder takes each division occupant's handle and backlink from that census (a class-zero CArmy in a country roster, gathered at the same boundary) instead of reading the unit and its registry entry, and reads every other occupant, or every occupant without a completed census, as before. RaidAirScores and the shared rail tables (RailCooldowns, RailEdges and the selected rail building inputs) read only the game state and the hour: their own job leaves in the first burst with the held score table and rail store on loan, and joins right before the Late dispatch, once the AirMissions job has returned the air pack, installing its tables in the packs the Late job loans, which keeps them; a Late failure no longer fails them, and their own failure fails them, rereads every score pair next hour and forgets the rail store. ArmyIconInputs, which reads only the division sources and the seeded unit inputs (whose census gathers both icon fields), is its own job too: it leaves as soon as the Divisions join installs the sources, borrowing them with the icon pack, and joins before the Late dispatch, which keeps its rows. The air wing job leaves in the first burst: it bounds its naval memberships by the naval payload's membership capacity, taken before the root census borrows that payload, which only reserves its roots. The order census and its plan walk run in parts over consecutive ranges of the handle-sorted order groups (`orders_parts`): the Orders job walks part 0 and an OrdersPart job each other part, all leaving as soon as the root census joins, which the callback joins before the division inputs (a registry walk, it is in long before them). The root census job gives each part this pass's roots and its range. The next hour's part count is this hour's measured census and plan-walk time, at the session's QPC frequency, over a 0.25 ms part target, bounded by the eight reserved part slots, and its ranges cut the groups where this hour's per-group work divides evenly; the callback carries that split to the next hour whichever pooled frame it uses, and the first hour, or one after an hour whose stitch planned none, walks one part. When the Orders job and all its parts have completed by the AirMissions dispatch that follows the wing join, the game thread joins them there, without waiting or running any of them itself, and the OrdersStitch job leaves at once, beside the following joins; otherwise they are joined, and the stitch leaves, behind those joins. The stitch joins behind the Naval join and settles there as if submitted there: it contains its own panic, which stops the pool only at that join, so no job dispatched before it is cancelled or refused for it, and a pool already stopped there gives a stitch that did not complete the admission reason a refused stitch has. It stitches them into the census and plans one walk over all groups takes (`corder_instance::stitch_census`, `stitch_plans`: rows, geometry, census order, the first failure in group order, an order two parts enter refused as one walk refuses it) and runs every other pass over them as one job did: the group plans, the execution operands, the child-front areas, the front bindings and the invasion preparations. A part the pool refuses fails the census with the admission reason a refused Orders job has, and a part that fails while running with the reason of a failed Orders job, unless the census already failed. The jobs that need no other job's output but join longest after their bodies end (the Ordinary task-force part, Provinces, States, Weather, Capitulation, Wars and Relations) leave in the slack burst, one held burst right behind the Orders parts and the Naval copy, so that those claim the workers first; each takes the same request and stores and reads the same sources, and only its place in the queue differs from the first burst. The Naval copy leaves right after the root census too, beside the Orders job and its parts, since its raw phase reads no wing value: the callback installs the wing census when it joins the copy (a copy that walked the theatres without one, the wing job having failed, is refused). Its order-of-battle copy takes each root's member and child entries in runs of up to 64 per guarded copy and each member's host identity and group backlink in one, logging every span as its own take logs it ([theatres.rs](src/extended/naval_history/theatres.rs), `order_of_battle` in `batch_fallbacks`). A run is batched only when its whole worst case (each entry's span and eight bytes, a failed entry's span, and each entry's member or child reads at their largest) fits the storage the log already holds; any other run is taken entry by entry exactly as the per-entry copy takes it. Only the child fronts' army-group operands read the Naval copy, so the ChildFronts job completes them once the OrdersStitch and Naval jobs join, and the Late job, which reads the completed census and plans, leaves after it. The Fronts job reads the bound fronts, their sections and pairs as soon as the OrdersStitch job joins: nothing before the tables reads them, so it runs beside the ChildFronts and Late jobs, off their path, and the plans take the fronts back after the Late join. The final borrowers leave as soon as their packs are back: after the character parts, the restored Variants (production), Session, the Intel and relation joins (with the residual Intel report settled first, as the table assembly would) and the division sources, which the Late job no longer loans. The game thread joins those producers right after the Session join and dispatches them there, the hour's last dispatch, before the core, slow, gated, governance, research, Ordinary and Late joins and the table assembly, none of which holds or reads their packs. The order transport the Late job returns is installed after the Presentation join. The Gated packs (fog, projects and the construction rest) leave with the Intel job, after the division inputs join and before any join: the verdicts installed in them (radar, AirBases registrations, projects and UnitIntel) are only raw modes, which their queued jobs always settle (each join stages a payload or a failure), and World's construction verdict is whether its part was scheduled, so all are set before the packs leave; the air pack's bases verdict is likewise set before its install, and the AirBases and Intel jobs themselves join after the late assembly, at their failure handling; the character inputs read only the roster's role census and are their own job beside the role jobs. The game thread joins the root census first, then the unit inputs and their parts, the ShipModels census and Countries; then it joins the roster and dispatches its consumers (the portrait shares, the role jobs and the character inputs); after the wing join it dispatches AirMissions, joins the Orders job and its parts and dispatches the stitch if they have all completed, then joins the Gated verdicts, Economy and World, and what the map sample and the Late job read, dispatches the Late chain, and only then joins the verdicts that only the assembly and the final borrowers read.

Variable snapshot storage starts empty or from live attach and cadence hints. `DivisionInputs` grows the original roster before lending seeds. Its country roster walk and seed gather are split, by the previous hour's census, into up to four parts over consecutive country slots of about 1,500 divisions each: `DivisionInputs` walks the first and `DivisionInputParts` jobs, queued with it in the first burst, the others; the game thread joins them into one census in slot order ([`Census::absorb`](src/division_census.rs)), which equals one walk of every slot, its first failure included, and a part that did not run fails the hour's inputs. The AirWing wing census is split the same way, by the previous hour's wings and owners (one part per 384, at most the pool's workers), into `AirWing` jobs over consecutive owner slots, all in the first burst; each reads the shared manager and roster headers and builds its own mission identities and naval memberships, and the game thread joins them in slot order ([`AirWingJob::join_parts`](src/extended/air/wing.rs)) as one walk would have left the census: nothing joins after a part whose walk ended, and once the AirWings, source and naval projections fail only score leaves and owners join. `AirBases` takes its country census spans, and RaidAirScores reads the countries it resolves, from the hour's country snapshot bytes (`Cache::bytes_view`: every country is still resolved as on the game, an alias of the reserved country included); `OrderRoots` grows the original group registry before its consumers run. `MapCombats` owns battle rows, participants and casualty visitors. After the source and movement jobs join, `FinalInputs` captures the remaining original borrowers and typed fallbacks. Missing, failed or short source packets stay unavailable without another native census. An attempted raw copy cannot become a callback retry.

`ObserverBoundary` drains complete owned producer counts on a worker while the native hourly call remains parked, then seals the completion and political lanes in the same job, all while the game thread takes the country snapshot and prepares the hour (`prepare_hour`, the refresh flags, the lexical, modifier table and division counter marks). Nothing there reads what the job writes, and any job may, so the game thread joins it right before the first burst: a held job can still run. The seal runs before the hourly trampoline returns to the native update, as it did inline after the snapshot: the operation completion writer (reached from the pre-hourly update) and the political writers run in the native update, and nothing the game thread does before the join calls native code that appends to a lane. A drain that fails refuses the lanes it did not reach as stopped, as their own later job was refused when the failure stopped the pool. Destination rows, text, words and lane cursors grow before handoff; callbacks append only into previously prepared producer storage. Rejected bursts retain full demand for off-thread preparation. Lost native events still withdraw interval coverage; later storage growth cannot reconstruct them.

Shared native addresses have one patch owner and dispatch all dependent observers through it; [a test](src/hook_sites_tests.rs) lists every family's sites with the bytes each patch replaces and refuses a shared or overlapping site. The unit-deletion queue hook lives in [equipment_destruction.rs](src/equipment_destruction.rs). A failed or still-unready installation names its family in `installation_error` and in the terminal error the recorder prints.

Between-tick observers use a bounded store/log → hourly drain into owned frames → off-thread aggregation and encoding. Callbacks preserve original execution, never refresh caches or write game data, and use try-only storage leases. Preserve cursors, epochs, identities and branch continuity; loss breaks coverage until explicit recovery. Swap storage only at an empty, writer-free boundary, free retired storage off-thread, and retain sampled events until their output outcome is known. Between-tick facts after the last captured hour are outside recorded coverage; detach invents no sample. See [output_log.rs](src/output_log.rs) and [event_ledger.rs](src/event_ledger.rs).

Order-independent observers ([experience gain](src/experience_gains.rs) sums) add concurrent native writers into live-sized lock-free tables. Writers never exclude one another or meet storage preparation; growth is offered off-thread and adopted at the drain. The drain closes a writer gate and proceeds only when no writer lease remains: a writer arriving at the closed gate, or a lease spanning it, fails that interval rather than being placed on either side of the boundary.

The direct-war and full-country visibility predicates are not observed between ticks: playback [derives their cells](../replay/src/directed_war_derive.rs) from the hour's WarRelations.

[Land events](src/land_events.rs) pair each destruction entry with its selected killer by the reserved observation cursor. Repeated division handles retain every native invocation, including nested entries; missing paired observations refuse the interval. Live staging demand includes both the entry and its separate killer witness. Consumers can observe several destruction entries for one eventual unit deletion.

[Logistics availability](src/logistics_balance.rs) retains the operand of balance writes that run concurrently across countries. Each write binds its cell (country history and archetype) before the native store, in the published storage and in one being published. A refused write withdraws only the cells it could reach until their next clean write: overlapping writers of one cell certify neither, a history change withdraws its country's cells, and only a store whose cell cannot be identified withdraws every cell.

## Acquisition rules

[world_lifetime.rs](src/world_lifetime.rs) observes native reset, deletion and construction before retirement or publication, and the state nudger's reload, which rebuilds every live state and its template, on entry and on return. Invalidation closes admission for occurrence-aware observers; the next readable hourly boundary starts a partial interval, forces fresh acquisition and splits replay branch continuity even if stored clock fields agree. Event feed, production, air loss, bombing, naval result and operation completion post reads require the same occurrence. The signal does not lock native objects or certify successful load completion; other families retain their native identity and consistency guards. The signal remains published until the other observer families and their older native invocations are quiet.

[Nuclear strikes](src/nuclear_strikes.rs) are an hourly event ledger opened by the impact's entry on its thread and closed at the notification's entry, before authored `on_nuke_drop` effects. The family reads each damaged unit before and after its own unit damage site; the owners of the other writers forward them on the open strike's thread: war support from `country_input_changes`, building damage from `building_changes` and division and wing pool differences, with each wing's lost crews, from `equipment_destruction`. Its detours and originals use the unwinding ABI; a call a native exception unwinds stays counted active, which keeps the collector at detach. A part whose owner does not forward, whose read fails or whose writer call goes unobserved is named in the strike's row as refused, never recorded as nothing. The ledger is sized from the building census and the country roster and grows from overflow demand.

A reattach to the same game process resumes its recorded branch ([`CampaignHistory::tracker_for`](../replay/src/container.rs)); when its first observation continues that branch, the [spool](src/spooling.rs) writes an event loss between the branch's last recorded read and that observation with the branch's context, because no hook observed events while the recorder was detached. It ends at that first observation even when its frame is lost (a queue overflow or failed write, recorded as a gap), and is written again with the context until a frame succeeds; finalization keeps one.

[Event feed](src/event_feed_observer.rs) copies pointer-free facts into each hourly frame and keeps them until the spool returns an exact receipt for that batch; an uncertain write keeps its facts. [Provenance](src/war_provenance.rs) gives every event its cause: each observed operation (a join, a war's end, a conference's creation, start or application, an annexation, a release, and the diplomatic dispatch and civil war start the politics family forwards) sets a thread-local context for as long as its original runs and restores the enclosing one on return or unwind, so the native stack is the operation stack. Ended war relations, releases, peace conferences and each state's owner change (forwarded from the territory family's state owner setter detour) are events of their own. The event feed family owns the eight entry detours (timed as `event_feed_provenance`); an interval is partial while the politics or territory forward is not enabled, and an unclassified caller or unread cause operand leaves that fact unrecorded and counted (`event_feed.provenance`). At detach, facts after the last recorded hour and known-failed batches are released and counted in session status (`event_feed_detach`); only uncertain receipts, tickets and native flights keep the collector loaded. [Rocket output](src/extended/rocket_output.rs) shares the [production hook owner and drain](src/line_output.rs), with independent known amounts and refusals.

Converted rows are rounded to their [display steps](../replay/src/display.rs) once per hour before merges, carries and comparisons, and projections compare stepped fields rounded, so a value that drifted only below the precision the game shows keeps its row unchanged. Collect the least data needed by a visible feature. Prefer stored values, including stale caches and retained name bytes. Capture operands for on-demand results, viewpoint/camera dependence, viewer-language text or results much larger than their inputs. Keep cached text's language provenance.

The spool resets a returned frame's verdicts after growth, so the callback only takes it; the CountryIntel buffer the frame borrowed still returns to the frames' shared home at the next callback, so another frame's walk finds it held exactly as long. The observer boundary drains on a worker while the game thread takes the country snapshot and prepares the hour.

Keep the ordinary-hour game-thread block within the **2 ms target** documented in [acquisition.rs](src/acquisition.rs), including buffer backpressure and joins. Load and invalidating full-refresh hours have the approved exemption; measure them separately. Collector coordination allocates and frees nothing on the game thread. Conversion, encoding, diffing, I/O and growth stay off it. Allocating acquisition jobs are worker-only through fallback and unwind; growth continues from acquired headers without restarting reads. Worker-only is decided per job: a ChildFronts pass whose owners demand no army-group operand builds no OOB index and grows no section, so the joining thread runs it if no worker has claimed it.

The game thread's stack is the game's: its main thread reserves 4 MiB and is already deep in its own frames when the hourly hook enters. The hourly body holds a ticket per pending join; a request the pool rejects is parked in a free pool slot (`MAX_JOBS` bounds accepted and parked requests together) and taken back at its join. However the callback exits (a return, a panic, a terminal allocation failure before or during its drain), the hour's `Batch` drop collects every retained ticket unconditionally, a contained panic in one collection leaving the others to drain, and then settles the pool (`Pool::settle`: still-queued jobs are cancelled unstarted and running ones awaited), so no job reads native memory after the callback returns to the game. Requests are built, submitted and collected out of line, and joins that move a large request run in their own frame (`out_of_line`), so no job, completion or large request accumulates in the body's frame. The hour's decode job is filled in place in a preallocated decode-queue slot, and read counts are captured, merged and snapshotted in place.

Acquire each scheduled table once from the first hour. Freeze activity before dispatch; inactive tables do not start or retire work, and a retired table is never active ([`cadence::should_walk`](../replay/src/cadence.rs)). Charge shared sources once. Joins handle only their own job; workers never submit or wait on other jobs. Preserve FIFO retirement and return loans before recycling their producer.

[cadence.rs](../replay/src/cadence.rs) owns scheduling; [slicing.rs](src/slicing.rs) owns sliced-family selection. The supply trains' SupplyNodes and TrainInventory are the sliced `supply_trains` family (owner decision 2026-10-11: decorative trains and panel-only vehicle operands): each hour reads the supply companions of its country slice, of new countries and of countries whose last read was not published, skipping every other country's supply objects ([supply_trains.rs](src/extended/supply_trains.rs)); a sliced read is converted whole and merged by owner, never compared with the encoder's complete baseline. Preserve full-refresh and invalidation rules. Encoding keyframes use held rows without extra reads. Successful acquisition establishes freshness even when values encode unchanged; carried data keeps its prior read hour. Packets on hourly host rows store no hour ([`PacketHour`](../replay/src/extended_rows/packet_hour.rs)): publish only a packet read for the frame's hour, refuse any other, and compare packet contents only. Failed or unpublished reads cannot certify reuse or erase independent sibling outcomes. [fixed_layout.rs](src/fixed_layout.rs) authenticates native modifier and lexer layouts; apply its refusals after merging so carried rows cannot bypass the checks.

Size rows, arenas, logs and watches from live registries and content demand before installation; raise capacity off-thread as demand grows. `country_scale.rs` coordinates hints. Short walks report exact demand; failed sizing observations are named and counted, adding no fabricated zero hint. A failed or racing hint loses no data, so it never becomes the session warning; any resulting shortage surfaces as its capture's own named refusal. Use checked growth for large storage, with no chosen population, text or tree-depth cap. Scale requirements live in [AGENTS.md](../../AGENTS.md).

The loader prepares DLC/mod roster names, descriptors and mount paths from native stored lengths before publishing `Shared`. The once-only roster callback reauthenticates and copies current values without allocating. Preparation supplies storage only; a changed control, unreadable value or unprepared span remains a named roster refusal.

[Table storage hints](src/country_scale/table_demand.rs) size complete rows, text and graph storage from native registries and pools at attach and on the input-demand cadence. Independent hint failures retain earlier floors and appear in `country_scale_demand.table_storage`. Allocating acquisitions stay worker-only; owned rows and arenas grow from their original observations before publication, with displaced storage returned off-thread. ## Hook and patch safety

- Authenticate the executable, instruction span and sentinel bytes. Keep sentinels inside the owned function, exclude incoming branches and native return PCs from overwritten instructions, and preserve continuation and handler scope.
- Publish/restore a family under one thread suspension, validating every site before any write. Detach restores the plain families (those whose `set_enabled` publishes once through `Hook::set_family_enabled_shared`) in shared rounds ([shared.rs](src/hook/shared.rs)): a collect pass records each unrestored family's publication, one census and suspension checks, writes and verifies each family with its own checks, and a report pass gives each family its outcome in its usual order. Each family stands on its own: one a thread holds, or whose bytes, verification or protection refuse, gets its own outcome while the others publish, and is retried next round. Page protections are restored once, after every write and flush, and nothing reopens a page before the threads resume, so a page shared by several families keeps its saved protection when any of their restores of it succeeds. Two failures are shared: a failed instruction-cache flush restores every family written in the round and each reports it, and a failed thread resume is reported by every family of the round. Attach installs every family on its own, in chain order, so a chain that stops has written nothing after its stopping family. Taps, split and multi-step families, the hourly hook and the world lifetime family also restore on their own. Prepare storage, protections and handles first; query a prepared system-information buffer after suspension and hold newcomers until the set is stable. A short census buffer resumes every hold before growth and retries within the same bounded rounds; insufficient prepared thread storage refuses before writing. No allocation, formatting, locks or destruction while suspended. Flush the instruction cache and verify bytes. Failed publication rolls back the family and retains executable storage until safe. Never overwrite foreign bytes at sites the family did not own.
- Use existing relocation/trampolines. Preserve arguments, return values, live registers, flags and SIMD state, Win64 alignment and shadow space. Interior bridges clear DF for observers and restore native state before relocated instructions execute.
- Register correct Windows unwind records before publication; preserve canonical prologues/epilogues and native return locations, and unregister before freeing their page. [Tap](src/hook/tap.rs) uses `extern "system-unwind"`; unsupported forms refuse installation. SEH-guarded reads and caught Rust panics do not prove foreign exception safety through originals called from a non-unwinding ABI.
- In-flight counts cover native originals outside DLL code; suspended-IP checks cover uncounted stub entry/exit. Buried return PCs can reference patched code. Rust cleanup cannot prove a stub finished foreign unwind: retain its flight without a safe completion witness. Generic Tap flights finish after the copied span, preserving flags through a separately registered completion frame. Every observer joins both runtime quiescence checks, including all relay, trampoline and bridge ranges.
- Escaped equipment, LAND and operation callbacks retain their active claims across load/detach, including disabled capture; only proved normal completion retires them. An unresolved OS resume retains suspension handles and publication storage until resume or thread exit, regardless of detach deadlines.

## Detach and failure handling

[Runtime](src/runtime.rs) owns the order:

1. Cancel buffer waits, restore the hourly entry, close acquisition admission and wait for admitted leases.
2. Restore all owned observer families; one failure must not skip others. Wait for callbacks, originals and executable ranges, excluding only registered collector workers from this first IP check.
3. Join acquisition workers, drain decode FIFO, drain/join the spool (which joins its conversion helpers and sizing thread), and finish status and required durability work.
4. Repeat full quiescence without worker exclusions, release stores/trampolines/unwind registrations, clear shared state, then self-unload. The recorder confirms DLL absence before finalization.

The runtime thread appends every attach and detach step to `progress` in the session directory (each shared restore round as `restore_shared` with its microseconds, and each family's restore with the microseconds of its own checks and writes in it) ([progress.rs](src/progress.rs), allocation-free): each family installed or restored with its outcome, each wait passed or refused, the decode and spool drains as they advance, and `done` before it signals. The recorder waits while the log grows and names its last line when it stops.

Observer restoration and quiescence share a bounded wait for every family; a timeout names the family and retains the collector. Unproved restoration, publication, unregistering or quiescence retains reachable code/storage and reports refusal. Never reset stranded flights to pass detach. Process-detach callbacks do not flush output. Preserve recoverable spool prefixes on process, allocation and write failures; recorder/replay own partial-file recovery.

## Diagnostics

`status.json` counters are cumulative since attach, so the difference between two snapshots measures a window. [bench.ps1](../../tools/bench.ps1) reports that difference per game hour as `status_delta.collector_cost`.

The `breakdown_witness` feature, off by default, also records the native values playback derives a breakdown from (the power-balance description trees) for the hour's sampled slice ([sampled_verify.rs](src/sampled_verify.rs)), as witnesses for `recorder derived`; production capture reads only the breakdowns' inputs.

`acquisition_work.game_thread` splits the game thread's own parked work per acquired hour (QPC means): frame reset, the observer boundaries, the country snapshot, job submission (jobs, the wakes that release held bursts), join waits, the map sample and table assembly. The pool's workers run at normal priority without Windows' dynamic wake boost, so a worker readied by a submission or release waits for a free CPU instead of preempting the game thread inside the wake; a release wakes one idle worker per job it releases, or every idle worker for a burst at least as large as the pool. `acquisition_work.workers.executor.wake_boost_refusals` counts workers whose boost could not be disabled. Under CPU contention from outside the game an unboosted worker can wait longer for a CPU, lengthening a join that awaits it; the executor also reports joins since attach with their summed and longest wall (`joins`, `join_wall_ns`, `join_wall_max_ns`, caller execution of an awaited queued job included) beside `wake_boost_refusals`. `acquisition_work.block_phases.role_timeline` gives each pool role's collected jobs and the mean offsets from the acquisition body's entry of their queueing, body begin and end, and join begin and end, so a role's join wait splits into an unfinished body (the join begins before the body ends) and collection or scheduling (it begins after). Its `joins_waiting_over_250us`, `_1ms` and `_4ms` count the role's joins whose wait reached each threshold (one increment at most per join), so a mean wait made of a few long hours shows apart from a steady one.

`acquisition_work.join_costs` splits the collection part out of every join, over every hour: per role, the collector's first wait for the pool's queue mutex, the stall from the later of the join's begin and the job's publication to its collection (the mutex, the wake and rescheduling), the worker's wait from its body's end to publication, the jobs already published when their join began, and the stalls of at least 0.25 and 1 ms. The executor stamps each completion's publication and collection and times the collector's first lock in every build. The division input census's first part and the orders-group root census report as their own roles, `DivisionInputs` and `OrderRoots`, apart from the `Divisions` and `Orders` jobs they lead to.

`hook_timing` covers every hook family under its status key: `hourly` and each between-tick family, with the politics taps as `politics_capture_taps`. `calls` counts exact entries into the family's Rust callbacks. Split families (`kind: "split"`: production output, air losses, bombing and event feed) also count `returns`, the half after the stub-run original. The air loss CALLs' leaf target passes the writer's no-write calls (a null region, or a credited cause-3 loss: air loss bookkeeping writes nothing for either) straight to the writer, counted only as `air_losses` status `fast_zero_writes` (included in its `calls` and `zero_writes`), so `hook_timing` counts and times only the calls the observer enters. One call in `sample_period` per hooked thread and family, including each thread's first call and every hourly call, is timed with the TSC: `sampled_detour_ns` is collector time in those calls, excluding the original, and `estimated_detour_ns` scales each thread's samples by its calls per sampled call. Detour and mixed families also time the original they call (`sampled_original_ns`, `estimated_original_ns`); taps and split families report null. The timed span starts and ends inside the Rust callback, so tap bridges, entry stubs and the retour relay are outside it. A family reached inside another family's original is timed by its own entries, and the hourly original contains every between-tick hook the native tick reaches. `tsc_hz` is calibrated against QPC since attach. A sampled span also contains the timer's own reads (at entry and exit and around each timed original), which unsampled calls never make; attach estimates them once through the same span path (`approximate_timer_overhead_ticks`, the fastest of 512 empty spans), each sampled call records that estimate capped at its own detour, and `approximate_timer_overhead_ns` and `approximate_net_detour_ns` split the estimate into the timer's share and the rest. These are diagnostic approximations, not bounds: subtracting them may also remove some collector work. Per game hour, a family costs Δ`estimated_detour_ns` / Δ`families.hourly.calls`, the conservative figure; [bench.ps1](../../tools/bench.ps1) reports the approximate net beside it (`approximate_net_detour_ms_per_hour`, `direct_approximate_net_ms_per_hour`).

`collector_thread_cpu` lists the runtime, decode, spool, status and acquisition threads with QueryThreadCycleTime `cycles` (`cycle_ns` through `tsc_hz`) and GetThreadTimes `user_ns`/`kernel_ns`, then `collector_total` and the whole game `process`. A thread whose id now names a different thread is unavailable.

`spool_work.phases` partitions the spool thread's loop into non-overlapping [phases](src/spool_phases.rs) (buffer receipt, conversion of core and pack rows, the wait for the conversion helpers, merges and carry, buffer return, comparison before encoding, encoding, record writes, commit, observer preparation, sizing hand-over, durability checks, status and idle wait), each with `calls`, QPC `wall_ns` and the thread's own `cycles`; `helper_phases` sums the helpers' map and pack conversion and their shares of the comparison and encoding on their own threads, `sizing_phases` holds the sizing thread's reads, observer preparation, freeing of what commits handed back and idle wait, and `pack_cycles` splits pack conversion on any thread. `spool_work.comparison` counts each table's comparison decisions and the comparing threads' cycles. Per game hour, a phase costs Δ`cycle_ns` / Δ`hours`. The spool loop does not poll: decode publication, a callback parked for clock preparation and the stop request wake it, and its idle wait is bounded so durability checks keep their cadence while no hour arrives; the spool wakes the sizing thread after each hour, and its own bounded wait keeps observer preparation and throttled sizing reads on cadence.

## Checking changes

The Orders parts differential tests in [plans.rs](src/extended/plans.rs) compare census identity order, rows, geometry, arenas and projected tables with a single walk. Their [nonempty fixture](src/extended/plans/orders_parts_fixture.rs) spans every part count with shared fronts, sections and directed pairs, child-front areas completed from a same-pass Naval OOB copy, assigned divisions and invasion preparations. It requires complete nonempty outcomes and repeats each split with retained storage and reversed part acquisition order. The scale fixture covers 1,500 and 5,000 countries.

New packs need replay rows/cadence, registration in `extended/mod.rs`, live-sized owned buffers, dependency-safe jobs and off-thread conversion. Follow adjacent take/restore paths and update affected writers/consumers together under the [replay guide](../replay/README.md).

Use existing synthetic-memory, pipeline, scale and fault tests for aliases, first faults, truncation/growth, sibling isolation and owned-versus-direct equivalence. Hook changes need publication, register/unwind and lifetime checks; the `hook_cost_` release benches (`cargo test -p collector --release --lib hook_cost_ -- --ignored --nocapture --test-threads=1`) time the hottest families' detours per call against synthetic native callers. Changes to the hourly path need `python tools/stack-frames.py .cargo-target/release/collector.dll --check` on a `--release` build: every function the hourly hook reaches through direct calls keeps its frame within 64 KiB and the deepest such chain within 384 KiB. Follow the [shared build checks](../../AGENTS.md); documentation-only changes need link and diff checks.

Measure the whole game-thread wall block and tails, including buffer waits; overlapping worker timings cannot be summed. Keep native reads, off-thread work, retained memory, encoded size and throughput separate. Charge reads once through [read_accounting.rs](src/read_accounting.rs); diagnostics stay in `status.json`, including the per-phase CountryCounterInputs acquisition wall in `country_rosters.acquisition_phases`. Batches preserve healthy output and never withhold more under faults than the serial walk; failed batches take one counted serial fallback as described in the engine's reader-safety rule. Split only measured bottlenecks.

Integration needs the [fresh-save oracle](../recorder/README.md#inspect-and-compare) and [smoke/performance workflow](../recorder/README.md#live-checks-and-performance): matched saves, frozen builds, same-run baseline, ordinary/full hours, constrained pools and downstream buffer pressure. Fixture timing is not live slowdown; a passing build is not capture acceptance.
