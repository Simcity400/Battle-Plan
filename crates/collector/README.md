# Collector

Faction accounts use `faction_accounts` and prepared atomic operand storage. Influence terms carry independently. Projection derives from supplying pre-division products, a factory component, returned unit counts and loaded coefficients. Passive initiative derives from sparse set/spend/reset anchors, canonical supplying increments and refresh counts. Shares and member rank retain their supplying input versions and explicit refresh boundaries; stale cohort lifetimes keep sparse anchors. Contribution, gains and prior score remain independent scalar operands. Ordinary acquisition drains changed cells without native account scans; array lifetimes establish baselines and sparse selection/history changes read only the demanded account.

`faction_pools` derives influence totals from the refresh cohort plus sparse awards, retaining an anchor when that cohort's input lifetime ends. An extraction routine completion observer reads each registered faction/system pool's final amount words once after the native rebuild, preserving slot zero from the lifetime baseline. Shared resource helpers are untapped. Separate `faction_resource_rebuild` and `faction_refresh_phases` timing families expose callback cost. Embedded faction variables and research sharing use non-consuming certificates forwarded from existing observers. Minimum-upgrade and doctrine-folder selections have separate sparse domains. Advisor slots use structural and per-slot certificates for initialization, load, resize, selection, departure clearing and modifier/name initialization; the existing faction visitor reads only changed slots and retains unpublished changes across refused publication.

The existing asynchronous wing census adds independent current/maximum fuel operands. It reads no fuel leaves in the synchronous fallback, forwards current execution to the mission worker instead of rereading it there, and performs no additional wing walk, hook or per-wing allocation.

`collector` is the Windows x64 DLL the [recorder](../recorder/README.md) injects into the supported HOI4 process. It captures native state and hands owned data to off-thread decoding and replay output.

Faction goals share the existing worker-only Factions acquisition and its authenticated owner visitor. `faction_goal_changes` observes structural mutations, actual pending/final status stores and one-goal progress cache changes. Progress-only notifications read only the selected goal scalar and active-section vector; structural owner certificates carry histories, geometry, definitions, slots and dates. Quiet hours inspect no per-goal certificates. Native cache refusals carry until their own writer changes; prepared watch shortage retries only uncertified caches. Unchanged owners read no native goal bytes; missing observation refuses `FactionGoalStatus` and `FactionGoalEntries`. `faction_goals` retains native snapshots and shared scalar-occurrence tables, recycling allocations off the callback. Prepared watch growth transfers live certificates under the worker's native quiescent lease.

`faction_companion_changes` has independent rule, programme-reference, manpower and access-unlock writer domains. Unlock taps mark the resolved faction at its two actual byte stores; only changed factions copy those bytes. Hook construction, sentinel and publication failures identify their family, site and underlying cause. `faction_companions` reuses the same authenticated worker visitor, reading only changed owners and carrying stable values or read refusals. Each list publishes an independent table; a failing list does not suppress its siblings. The sparse callbacks only mark their native receiver.

Read the [shared rules](../../AGENTS.md). Native layouts and guarded reads belong in [engine](../engine/README.md), schemas and cadence in [replay](../replay/README.md), and content resolution in [installed-content](../installed-content/README.md). Per-capture behaviour stays beside code.

Combat Log active observers share the existing land-loss census and its
authenticated sides. Resolution copies the remaining observer operands into
the existing event-word log before side deletion, reusing terminal loss
operands. Both staging arenas reuse capacity; the active census supplies the
terminal log's off-thread capacity hint without another native walk.

## How it works

Retirement-only sizing-thread wakes free the retired encoder storage without
repeating live preparation before its next idle deadline. Explicit spool passes
still request preparation immediately, and the existing ten-millisecond idle
poll and observer/capacity-census schedules remain in place. Incremental slice
provenance enumerates fresh owners only, retaining unread live owners' existing
sample hours, including owners whose last complete read returned no rows.

The extended table inventory includes the physical navy census's seven repair/refit outputs;
their costs stay with Fleets, TaskForces and Ships. The NavalBases pack owns the other two repair outputs.

The loader worker prepares the process-wide executable tables from the verified game module and its shipped documentation before publishing hooks. Modifier spelling checks use scratch storage sized from those tables before callback admission; callbacks perform no metadata loading or allocation.

The recorder supplies scripted-map content demand before attachment. The States
worker reads cached victory-point choices only for reachable map hover functions,
and cached controller single-group predicates only for state-controller layers'
potential target states. Explicit numeric target lists narrow that set. Both values
travel with the held names under the territory writer certificate; their optional
writer hooks are absent without demand. An unavailable certificate refuses these
operands. The hourly manpower record contains no scripted-map fields.

Hourly callback → acquisition jobs → owned buffers → decode/conversion → diff/encode → recoverable spool. `DllMain` defers initialization to a worker outside the loader lock.

Every spool worker entry point, including preparation, loss handling, durability and detach, retains validation reasons. The spool worker owns that text using checked formatting; the game-thread callback does no diagnostic formatting. `status.json`'s `last_error` retains the first spool failure and `write_errors` continues counting later failures. The order-counter witness also keeps its first write and subsequent I/O failure details, so cleanup cannot replace their cause.

The spool thread converts with two persistent [helpers](src/spool_helper.rs): the first converts the map tables and lane 0 of the packs carrying a helper marker in [extended/mod.rs](src/extended/mod.rs), the second lane 1, while the spool thread converts the core tables and the other packs, then merges; a lone helper converts both lanes. `@helper` and `@helper_b` packs must be statically `Sync`, as must what `@helper_appearance` (country appearance) reads; the lane-0 `@helper_exclusive` pack (division presentation) and the `@helper_cached_*` packs (characters, intel, character portraits) may hold interior mutability only because no other thread touches them while their lane converts. The spool thread lends the character and intel conversion caches (shadows and the script-variable comparison) to the lane converting those packs for the join; other helper packs use only the projection, whose scratch is locked per table. Output lands in the serial slots and the failed-ordinary-job refusal follows the merge. Before encoding, the spool thread and the helpers [compare](src/spool_compare.rs) each complete hourly table but Clock and MapEvents, whose rows name their own hour and so never equal the preceding hour's, with the encoder's baseline for exactly that hour: an equal table becomes `ComparedEqual`, one whose keys all keep their baseline positions with at most three quarters of its rows differing carries only the differing rows, and anything else stays complete; a densely changed table is not compared again for a game day, since replacing most rows costs the encoder more than its full path. The encoder writes the same bytes for each form, so frames are identical with any number of helpers. A sliced table whose held rows are the encoder's shared baseline for the hour reaches it as a slice update of those rows rather than a merged copy, so only the read owners' rows are compared and replaced; the cache follows the write's outcome, taking the merged rows when it fails. The spool thread and the helpers then [encode](src/spool_segments.rs) the frame's tables with at least 64 rows to compare or write at once, largest first, and the spool thread assembles the frame in table order. Each commit hands back the baselines, rows and inputs it no longer holds, and the sizing thread frees them. A persistent sizing thread beside the spool thread runs the live sizing reads, the capture-buffer growth they request and the between-tick observer preparation, after each hour and on the spool's idle cadence; the spool thread returns each buffer before growing idle buffers, records the sizing thread's refusals in its status, hands it the latest allocation context for a terminal witness, ends on its terminal failure, and sizes inline when the thread cannot start. Decode, spool, helper and sizing threads reserve explicit 16 MiB stacks, use THREAD_PRIORITY_LOWEST with execution-speed EcoQoS while keeping up, and restore THREAD_PRIORITY_NORMAL with EcoQoS explicitly cleared when at most one of the four reusable buffers is free (two in flight is the steady decode-then-spool pipeline); dynamic wake-up boosts stay disabled. While keeping up they also select the CPU sets of the two least preferred physical cores (lowest scheduling class, then lowest efficiency class, then highest core index) when a single-group machine has at least four, so their work avoids the cores Windows prefers for game threads; CPU sets are soft affinity, so this is placement, not an exclusive reservation. A backlog clears that selection with the priority. Machines with several processor groups, fewer than four physical cores, or a failed topology query or allocation stay unconfined until the collector reloads, and no selection call is made. `background_priority` counts successful priority/EcoQoS/confinement applications and independent failures, which retry between work items, and how many logical processors the confinement selects. Only those collector threads change policy; game threads, their priorities and affinities stay untouched.

Capture-capacity raises, returning-buffer and idle-buffer growth, and combat-hint growth run under the capacity mutex. The admitted table and live-input hints copy the capacities under it, read live demand outside it, then publish the proposal if the capacities still equal that copy; a concurrent raise makes them re-read once on the current capacities under the mutex. Only the published attempt's failures reach the session's sizing errors, after release. Advisor hints and advisor-pool preparation and land-event preparation are monotonic; nested demand diagnostics count each read attempt, including a fallback. Whoever raises the capacities grows every idle buffer before releasing the mutex. The spool grows and publishes its returning buffer to the free queue under the same hold before growing idle buffers. After any raise completes, every buffer is grown to at least the raised capacities or is in flight and grown on its return. The spool measures frame-owned bytes across conversion and growth; returning and idle growth measure shared CountryIntel bytes only across their own capacity hold, so each expansion is charged once to `pool_bytes`. Country-cache offers and clock preparation charge their own allocations separately.

Capacity-only sizing censuses back off after quiet passes, from one second through two and four to five seconds; attach still runs every census, and any capacity raise, sizing refusal, world invalidation or load preparation restores the one-second cadence. Only censuses whose acquisition or decode grows from the current boundary's own observations before publication back off, so a skipped hint supplies no recorded value or failure: most table-demand groups, the state-name, faction-member and war source walks, the CountryIntel, name, presentation, game-score, raid, saved-target, reserved-visibility and combat-detail registry polls, and the advisor-modifier, production-modifier and fuel-unit live inputs. Censuses that prepare observers or fixed arenas before native writers run keep their cadence: the division-template, industrial-organisation, naval-counter, division-name, group-counter and economy table passes, the registry floors, the map, politics and character polls, land-event words, and every bounded event log (equipment destruction, losses, bombing, nuclear strikes, output, fuel awards, peace and naval-result sources). Combat-hint growth charges `pool_bytes` with the selected combat packs' own growth. Sizing-attempt diagnostics (`country_scale_demand`, sizing-derived `input_demand_errors`, combat-hint and game-score sizing counters) follow the backed-off cadence.

After each committed frame, `status.json` names the recording client's viewed country for Battle Plan Recorder as `player`: its own tag, cosmetic tag, original-or-own tag and ruling ideology group, the operands that pick its flag. They come from the encoder's committed `LocalPlayer`, `CountryLinks`, `Countries`, `CountryAppearance`, `Politics` and `PoliticalParties` rows through [replay's country_flags](../replay-data/src/country_flags.rs); nothing is read from the game for them. The text is copied with checked allocation only when it changes, and `player` is omitted while any of those rows is unavailable.

The hook enters the hourly update before the clock advances; the sample is the settled end of the labelled hour. Every live read, including worker reads, finishes before the trampoline runs. There is no stable interval after it. The boundary holds the simulation thread, not every native writer: retain consistency guards for concurrent caches and dictionaries, refusing overlapping changes without waiting or retrying.

Campaign text, cadence identity and retained loss text are prepared from the native stored length by the loader/spool. A callback parks for longer text preparation before reading its payload; preparation uses queue leases and a try-only spool gate so frame backpressure can still drain. Observer identity epochs advance only on exact full-byte campaign changes. Optional clock polling is advisory; a parked capture's required destination is checked capture storage. Clock faults and advisory misses are named and counted in status.

Raw-copy jobs stage spans in a `RawLog` for typed decoding over owned memory; typed jobs fill preallocated rows and arenas. Deferred work never follows live game pointers. Use matching take/restore paths and allocation-free parked spares. Install raw verdicts before loaning dependent packs; collect published shared-source producers before dispatching consumers. A job's only dispatch edges are the outputs it reads: every job that needs no other job's output leaves in the first burst, which queues without waking the pool and is released with one wake (`Batch::hold`/`release`), except the slack burst below. Variable snapshot storage starts empty or from live attach and cadence hints. `DivisionInputs` grows the original roster before lending seeds. Its country roster walk and seed gather are split, by the previous hour's census, into up to four parts over consecutive country slots of about 1,500 divisions each: `DivisionInputs` walks the first and `DivisionInputParts` jobs, queued with it in the first burst, the others; the game thread joins them into one census in slot order ([`Census::absorb`](src/division_census.rs)), which equals one walk of every slot, its first failure included, and a part that did not run fails the hour's inputs. The AirWing wing census is split the same way, by the previous hour's wings and owners (one part per 384, at most the pool's workers), into `AirWing` jobs over consecutive owner slots, all in the first burst; each reads the shared manager and roster headers and builds its own mission identities and naval memberships, and the game thread joins them in slot order ([`AirWingJob::join_parts`](src/extended/air/wing.rs)) as one walk would have left the census: nothing joins after a part whose walk ended, and once the AirWings, source and naval projections fail only score leaves and owners join. `AirBases` takes its country census spans, and RaidAirScores reads the countries it resolves, from the hour's country snapshot bytes (`Cache::bytes_view`: every country is still resolved as on the game, an alias of the reserved country included); `OrderRoots` grows the original group registry before its consumers run. `MapCombats` owns battle rows, participants and casualty visitors. After its source producers publish, `FinalInputs` captures the remaining original borrowers and typed fallbacks. Missing, failed or short source packets stay unavailable without another native census. An attempted raw copy cannot become a callback retry.

`ObserverBoundary` drains complete owned producer counts on a worker while the native hourly call remains parked, then seals the completion and political lanes in the same job, all while the game thread takes the country snapshot and prepares the hour (`prepare_hour`, the refresh flags, the lexical, modifier table and division counter marks). Nothing there reads what the job writes, and any job may, so the game thread joins it right before the first burst: a held job can still run. The seal runs before the hourly trampoline returns to the native update, as it did inline after the snapshot: the operation completion writer (reached from the pre-hourly update) and the political writers run in the native update, and nothing the game thread does before the join calls native code that appends to a lane. A drain that fails refuses the lanes it did not reach as stopped, as their own later job was refused when the failure stopped the pool. Destination rows, text, words and lane cursors grow before handoff; callbacks append only into previously prepared producer storage. Rejected bursts retain full demand for off-thread preparation. Lost native events still withdraw interval coverage; later storage growth cannot reconstruct them.

Shared native addresses have one patch owner and dispatch all dependent observers through it; [a test](src/hook_sites_tests.rs) lists every family's sites with the bytes each patch replaces and refuses a shared or overlapping site. The unit-deletion queue hook lives in [equipment_destruction.rs](src/equipment_destruction.rs). A failed or still-unready installation names its family in `installation_error` and in the terminal error the recorder prints.

Between-tick observers use a bounded store/log → hourly drain into owned frames → off-thread aggregation and encoding. Callbacks preserve original execution, never refresh caches or write game data, and use try-only storage leases. Preserve cursors, epochs, identities and branch continuity; loss breaks coverage until explicit recovery. Swap storage only at an empty, writer-free boundary, free retired storage off-thread, and retain sampled events until their output outcome is known. Between-tick facts after the last captured hour are outside recorded coverage; detach invents no sample. See [output_log.rs](../collector-observers/src/output_log.rs) and [event_ledger.rs](../collector-observers/src/event_ledger.rs).

Order-independent observers ([experience gain](../collector-experience-gains/src/experience_gains.rs) sums) add concurrent native writers into live-sized lock-free tables. Writers never exclude one another or meet storage preparation; growth is offered off-thread and adopted at the drain. The drain closes a writer gate and proceeds only when no writer lease remains: a writer arriving at the closed gate, or a lease spanning it, fails that interval rather than being placed on either side of the boundary.

The direct-war and full-country visibility predicates are not observed between ticks: playback [derives their cells](../replay-derive/src/directed_war_derive.rs) from the hour's WarRelations.

Keep the ordinary-hour game-thread block within the **2 ms target** documented in [acquisition.rs](src/acquisition.rs), including buffer backpressure and joins. Load and invalidating full-refresh hours have the approved exemption; measure them separately. Collector coordination allocates and frees nothing on the game thread. Conversion, encoding, diffing, I/O and growth stay off it. Allocating acquisition jobs are worker-only through fallback and unwind; growth continues from acquired headers without restarting reads. Worker-only is decided per job: a ChildFronts pass whose owners demand no army-group operand builds no OOB index and grows no section, so the joining thread runs it if no worker has claimed it.

The game thread's stack is the game's: its main thread reserves 4 MiB and is already deep in its own frames when the hourly hook enters. The hourly body holds a ticket per pending join; a request the pool rejects is parked in a free pool slot (`MAX_JOBS` bounds accepted and parked requests together) and taken back at its join. However the callback exits (a return, a panic, a terminal allocation failure before or during its drain), the hour's `Batch` drop collects every retained ticket unconditionally, a contained panic in one collection leaving the others to drain, and then settles the pool (`Pool::settle`: still-queued jobs are cancelled unstarted and running ones awaited), so no job reads native memory after the callback returns to the game. Requests are built, submitted and collected out of line, and joins that move a large request run in their own frame (`out_of_line`), so no job, completion or large request accumulates in the body's frame. The hour's decode job is filled in place in a preallocated decode-queue slot, and read counts are captured, merged and snapshotted in place.

Acquire each scheduled table once from the first hour. Freeze activity before dispatch; inactive tables do not start or retire work, and a retired table is never active ([`cadence::should_walk`](../replay-data/src/cadence.rs)). Charge shared sources once. A join runs its own queued job only when caller execution is allowed; `executor_join_help` also permits the bounded help described below. Workers never submit or wait on other jobs. Preserve FIFO retirement and return loans before recycling their producer.

The acquisition workers run above normal priority without dynamic wake boosts: they work only while the hourly callback holds the simulation, so other processes cannot lengthen that pause, and between hours they wait without CPU; `acquisition_work.workers.executor.priority_refusals` counts workers left at normal priority. The acquisition executor preallocates its queue metadata, payload cells and per-slot atomic state words before workers start. Admission writes a job once; a claimant marks its generation running and executes in its cell after releasing the queue mutex, then publishes its completion without that mutex. An acquire CAS transfers a published completion to exactly one collector, which moves it directly into its output and releases the vacant cell for reuse. A pending join takes the queue mutex once to validate its ticket and optionally claim exactly its awaited caller-eligible job. Otherwise it rechecks the ticket's current running generation, the pool's stop state and whether a worker is idle before every spin. The first spin sets a 2 ms deadline that is never extended; an episode polls to publication or that deadline even if the pool becomes busy. A sleeping join with a remaining spin opportunity registers for its ticket's claim and idle-worker transitions. Those wakes and its own publication advance a shared wake sequence, so `WaitOnAddress` also returns when a wake precedes the actual wait. Without that registration, only its own publication wakes the slot-word wait. Every return rechecks eligibility without the queue mutex. `settle` cancels still-queued work under the mutex and waits on the atomic active count for running bodies and publication to end. A held burst notifies one worker; each claim relays at most one remaining peer notification before its body, keeping fan-out off the callback and preserving claim priority. Workers wait on the work-queue condvar only when there is no ready job. Parked rejected requests never run or count as uncollected admissions. Each cell's teardown contains a destructor panic independently and continues draining, forgetting the panic payload so its destructor cannot interrupt the drain. `Metrics.pool_bytes` includes the executor's actual allocation sizes and capacities: its Arc shared allocation, payload cells, atomic words, metadata, ready queue, thread ids, join handles, boxed runner and enabled help history arrays.

The dependency scheduler waits for any producer publication using a registered address-wake sequence, rechecking complete barriers after registration and before sleeping. Before registering, it polls the same barriers for at most `JOIN_SPIN`, without collecting or executing work; `executor_no_join_spin` disables this too, and `executor_spin_until_pool_busy` ends the readiness spin when the pool is busy. Readiness spins share the executor's `spins` and `spin_wall_ns` counters. Readiness neither collects nor runs a request. Only the callback installs reports, verdicts and loans, then queues consumers through the existing priority and held-burst paths; split walks still merge in slot/group order. Published report inspection copies only the report under the existing collection CAS, leaving its request owned by its ticket. Rejected jobs remain ready for their existing refusal/eligible-inline path. Clean stitches release fronts immediately; failed stitches retain the pre-Naval admission decision and settle only after Naval returns and its wing inputs are installed, so they cannot cancel queued work early. `Batch` drains admitted jobs, temporarily parked stitched orders and parked presentation preparation on every exit. `block_phases` segment 1 now spans this readiness loop through Late/history dispatch; segments 2-7 are unused, and segment 8 starts with the assembly-only joins. Readiness wait wall is included in the game-thread join subtotal; per-role join offsets still describe actual collection.

The off-by-default `executor_join_help` feature lets a join awaiting a running worker claim one other queued caller-eligible job at a time, in claim-priority order among eligible candidates. Help uses `try_lock` and skips queue contention. Both roles need body-time history: an atomic exponentially weighted mean (one eighth of each new sample) predicts only the awaited body's remaining time, subtracting elapsed body time. The candidate role's atomic decaying maximum, updated as `max(sample, old - old/16)`, must fit half that remainder. Each join has at most four help attempts, including unsuccessful or contended attempts after spurious wakes, and a cumulative predicted help budget of half its first valid remainder, charged by each admitted candidate's maximum. A spent budget permits no further help. A helped body cannot be preempted and can exceed its learned maximum, so this bound is a heuristic. The off-by-default `executor_spin_until_pool_busy` feature ends the single idle-started spin episode as soon as every worker is active, instead of continuing to publication or the deadline. The off-by-default `executor_no_join_spin` feature sets the spin budget to zero and takes precedence over that policy switch, for an SMT/wake-latency A/B. These features change no affinity. `acquisition_work.workers.executor` reports `join_help`, `help_executed`, `help_ns` (helped body wall, also counted as caller execution), `join_spin_budget_ns`, `join_spin_policy` (`until_deadline`, `until_pool_busy` or `disabled`), `spins`, `spin_wall_ns` (spin wall including descheduling) and `join_sleeps` (address-wait calls, including spurious returns).

## Hook and patch safety

- Authenticate the executable, instruction span and sentinel bytes. Keep sentinels inside the owned function, exclude incoming branches and native return PCs from overwritten instructions, and preserve continuation and handler scope.
- Publish/restore a family under one thread suspension, validating every site before any write. Detach restores the plain families (those whose `set_enabled` publishes once through `Hook::set_family_enabled_shared`) in shared rounds ([shared.rs](../collector-hooks/src/hook/shared.rs)): a collect pass records each unrestored family's publication, one census and suspension checks, writes and verifies each family with its own checks, and a report pass gives each family its outcome in its usual order. Each family stands on its own: one a thread holds, or whose bytes, verification or protection refuse, gets its own outcome while the others publish, and is retried next round. Page protections are restored once, after every write and flush, and nothing reopens a page before the threads resume, so a page shared by several families keeps its saved protection when any of their restores of it succeeds. Two failures are shared: a failed instruction-cache flush restores every family written in the round and each reports it, and a failed thread resume is reported by every family of the round. Attach uses the same publisher in three ordered rounds: world lifetime through peace settlements (34 families), Event feed through politics (four), and air losses through map events (four). Each round checks and writes only its longest ready prefix under one stable thread snapshot. Each family flushes, verifies and restores its protections before the next writes; a later family reopens its own sites if an earlier restore covered their page, using the immutable saved protection for every restore. A failed flush rolls back all families written in that round, including earlier successes; rollback reopens their pages, and a failed reopen leaves the affected bytes alone and retains executable storage for detach. Atomic preparation runs once when a family is reached; admission, forwarding and native exception-handler registration run in report order after resume, before the hourly entry installs. A collect refusal is kept with its family and never retried within that attempt. Failed recording storage abandons the whole batch and uses the serial chain. Land events stay serial for their pre/post escaped-unwind checks, construction IC for its optional rollback, equipment destruction for its dependent original/supplemental publications, logistics and naval result sources for their ordered per-site outcomes and bookkeeping, combat log prune as a single family between those boundaries, and hourly for final callback admission. The outer chain retains its 1 ms not-ready retry and 15 s deadline and names its stopping family. Detach participation stays limited to the plain shared families; the other families restore on their own. Prepare storage, protections and handles first; query a prepared system-information buffer after suspension and hold newcomers until the set is stable. A short census buffer resumes every hold before growth and retries within the same bounded rounds; insufficient prepared thread storage refuses before writing. Each synchronization round captures every held thread into prepared aligned context scratch and retains its instruction pointer beside the owned handle. Only a synchronized census with no newcomer certifies that snapshot; site, relay, trampoline and stub checks reuse it until resume. Every newcomer round captures the full held set again, and resume or storage growth invalidates every observation. A cached collision probes the owned handle for exit before refusing; a proved exit discards that IP and preserves the resume/error path. No allocation, formatting, locks or destruction while suspended. Flush the instruction cache and verify bytes. Failed publication rolls back the family and retains executable storage until safe. Never overwrite foreign bytes at sites the family did not own.
- Use existing relocation/trampolines. Preserve arguments, return values, live registers, flags and SIMD state, Win64 alignment and shadow space. Interior bridges clear DF for observers and restore native state before relocated instructions execute.
- Register correct Windows unwind records before publication; preserve canonical prologues/epilogues and native return locations, and unregister before freeing their page. [Tap](../collector-hooks/src/hook/tap.rs) uses `extern "system-unwind"`; unsupported forms refuse installation. SEH-guarded reads and caught Rust panics do not prove foreign exception safety through originals called from a non-unwinding ABI.
- In-flight counts cover native originals outside DLL code; suspended-IP checks cover uncounted stub entry/exit. Buried return PCs can reference patched code. Rust cleanup cannot prove a stub finished foreign unwind: retain its flight without a safe completion witness. Generic Tap flights finish after the copied span, preserving flags through a separately registered completion frame. Every observer joins both runtime quiescence checks, including all relay, trampoline and bridge ranges.
- Escaped equipment, LAND and operation callbacks retain their active claims across load/detach, including disabled capture; only proved normal completion retires them. An unresolved OS resume retains suspension handles and publication storage until resume or thread exit, regardless of detach deadlines.

## Detach and failure handling

[Runtime](src/runtime.rs) owns the order:

1. Cancel buffer waits, stop and join the diagnostic sampler when enabled, restore the hourly entry, close acquisition admission and wait for admitted leases.
2. Restore all owned observer families; one failure must not skip others. Wait for callbacks, originals and executable ranges, excluding only registered collector workers from this first IP check.
3. Join acquisition workers, drain decode FIFO, drain/join the spool (which joins its conversion helpers and sizing thread), and finish status and required durability work.
4. Repeat full quiescence without worker exclusions, release stores/trampolines/unwind registrations, clear shared state, then self-unload. The recorder confirms DLL absence before finalization.

The runtime thread appends every attach and detach step to `progress` in the session directory (each shared restore round as `restore_shared` with its microseconds, and each family's restore with the microseconds of its own checks and writes in it) ([progress.rs](src/progress.rs), allocation-free): each family installed or restored with its outcome, each wait passed or refused, the decode and spool drains as they advance, and `done` before it signals. The recorder waits while the log grows and names its last line when it stops.

Observer restoration and quiescence share a bounded wait for every family; a timeout names the family and retains the collector. Unproved restoration, publication, unregistering or quiescence retains reachable code/storage and reports refusal. Never reset stranded flights to pass detach. Process-detach callbacks do not flush output. Preserve recoverable spool prefixes on process, allocation and write failures; recorder/replay own partial-file recovery.

Decode panics retain their first payload, Rust source location (file, line and column), worker/drain stage and character part when applicable. While decode owns a frame, the diagnostic names its frame index, capture sequence, hour, full-refresh flag, load signal and recorded world generation. Branch numbers are assigned later by the spool; correlate the load signal and sequence with its clock witnesses rather than guessing a branch from current game state. This text survives later drain failures in terminal `error` and `decode_failure`; failed restoration also retains the Event feed's existing flight/fault/provenance status in `event_feed_failure`. Context updates run only on decode/drain workers; formatting and text allocation occur only on panic. The chained panic hook is restored before safe unload and retained with workers on a pinned detach. A panic never publishes the interrupted frame or certifies a later drain as safe restoration.

## Diagnostics

`status.json` counters are cumulative since attach, so the difference between two snapshots measures a window. [bench.ps1](../../tools/bench.ps1) reports that difference per game hour as `status_delta.collector_cost`.

`stability_walk_ns` contains cumulative Stability worker wall nanoseconds in `[inputs, children, candidates, pair+emit]` order for recorded frames, including countries whose walk refused. Inputs includes shared context and selection, between-country bookkeeping and the final fold. Four QPC reads per complete country reuse the job's existing start and end reads; refused walks retain only attempted phases, and skipped or failed jobs contribute no stale timing. The status field changes no replay table or format.

`callback_tail` keeps a cumulative histogram of `callback_work` at 0, 2, 4, 8, 16, 32, 64, 128 and 256 ms floors, and the 16 slowest successfully recorded hours, with hours recorded earlier first on ties. Each hour names its staggered daily slot, body-entry `qpc` (raw session QPC; divide by `callback_tail.qpc_frequency` to align a frame capture such as PresentMon `--qpc_time`), entry wall outside the body, buffer wait, setup/parallel/residual phases, parallel segments, slowest join and collection stall, joins stalled at least 1 ms, checked heap growths on the game thread and in its joined jobs, and first/continuous/full/recovery/refresh flags. The executor stamps each job's growth count; a job run by the game thread is counted once. [bench.ps1](../../tools/bench.ps1) reports the window's histogram counts beside the session callback p50, p95, p99 and maximum.

`decode.hook_publication` retains attach publication measurements ([publication.rs](../collector-hooks/src/hook/publication.rs)), including in normal drained terminal status; fallback and refusal terminal paths also expose top-level `hook_publication`. Serial publications are attributed to their install-stage family; every shared attach round is attributed once to `families.attach_shared`, which aggregates the three batch positions and their retries. Participating families receive no copy of the batch hold. Summing `total_hold_ns` across the entries therefore counts the actual held time once. Each entry has exactly six cumulative values: `attempts` (completed real controller publications, including busy/errors), `total_hold_ns` (sum of held intervals), `longest_hold_ns` (longest uninterrupted interval), `longest_synchronization_ns` (longest context sweep), `slowest_context_ns` and `slowest_context_thread_id` (the slowest context target). Empty publications requiring no controller are excluded; a serial fallback is attributed to the families it actually publishes.

A held interval starts immediately before the first successful suspension call, after its exit precheck, and ends when the last owned hold is resumed or proved exited, including recovery. These call boundaries do not observe the kernel's exact suspension instant; nanosecond wall times include descheduling and synchronous OS waits. Resumed resize/growth gaps are excluded. Measurements merge only after all holds resolve, and progress emits one cumulative line per measurement entry after the attach loop decides success or refusal. `snapshot_available` is false if optional aggregate storage or the owned snapshot copy could not be prepared; progress then adds one unavailable line. Diagnostic storage failure adds no publication refusal.

The `breakdown_witness` feature, off by default, also records the native values playback derives a breakdown from (the power-balance description trees) for the hour's sampled slice ([sampled_verify.rs](../collector-certificates/src/sampled_verify.rs)), as witnesses for `recorder derived`; production capture reads only the breakdowns' inputs.

`acquisition_work.game_thread` splits the game thread's own parked work per acquired hour (QPC means): frame reset, the observer boundaries, the country snapshot, job submission (jobs, the wakes that release held bursts), join waits, the map sample and table assembly. The pool's workers run above normal priority without Windows' dynamic wake boost. A held-burst release notifies one worker; workers relay the remaining notifications before their bodies, moving the wake fan-out off the game thread. `acquisition_work.workers.executor.wake_boost_refusals` counts workers whose boost could not be disabled. CPU contention can still lengthen worker scheduling and joins; the executor also reports joins since attach with their summed and longest wall (`joins`, `join_wall_ns`, `join_wall_max_ns`, caller execution of an awaited queued job included) beside `wake_boost_refusals`. `acquisition_work.block_phases.role_timeline` gives each pool role's collected jobs and the mean offsets from the acquisition body's entry of their queueing, body begin and end, and join begin and end, so a role's join wait splits into an unfinished body (the join begins before the body ends) and collection or scheduling (it begins after). Its `joins_waiting_over_250us`, `_1ms` and `_4ms` count the role's joins whose wait reached each threshold (one increment at most per join), so a mean wait made of a few long hours shows apart from a steady one.

`acquisition_work.join_costs` splits the collection part out of every join, over every hour: per role, the collector's first queue-lock wait when the initial collection CAS failed (zero for an already-published fast-path collection), the stall from the later of the join's begin and the job's atomic publication to its collection (atomic handoff, address wake and rescheduling; helped bodies can also defer collection when enabled), completion bookkeeping from body end to publication (a failed runner also stops and cancels under the queue mutex), the jobs already published when their join began, and the stalls of at least 0.25 and 1 ms. The publisher stamps immediately before releasing its word; the collector stamps after its acquire CAS, and times only its first queue-lock acquisition in every build. The division input census's first part and the orders-group root census report as their own roles, `DivisionInputs` and `OrderRoots`, apart from the `Divisions` and `Orders` jobs they lead to.

`hook_timing` covers every hook family under its status key: `hourly` and each between-tick family, with the politics taps as `politics_capture_taps`. `calls` counts exact entries into the family's Rust callbacks. Split families (`kind: "split"`: production output, air losses, bombing and event feed) also count `returns`, the half after the stub-run original. The air loss CALLs' leaf target passes the writer's no-write calls (a null region, or a credited cause-3 loss: air loss bookkeeping writes nothing for either) straight to the writer, counted only as `air_losses` status `fast_zero_writes` (included in its `calls` and `zero_writes`), so `hook_timing` counts and times only the calls the observer enters. One call in `sample_period` per hooked thread and family, including each thread's first call and every hourly call, is timed with the TSC: `sampled_detour_ns` is collector time in those calls, excluding the original, and `estimated_detour_ns` scales each thread's samples by its calls per sampled call. Detour and mixed families also time the original they call (`sampled_original_ns`, `estimated_original_ns`); taps and split families report null. The timed span starts and ends inside the Rust callback, so tap bridges, entry stubs and the retour relay are outside it. A family reached inside another family's original is timed by its own entries, and the hourly original contains every between-tick hook the native tick reaches. `tsc_hz` is calibrated against QPC since attach. A sampled span also contains the timer's own reads (at entry and exit and around each timed original), which unsampled calls never make; attach estimates them once through the same span path (`approximate_timer_overhead_ticks`, the fastest of 512 empty spans), each sampled call records that estimate capped at its own detour, and `approximate_timer_overhead_ns` and `approximate_net_detour_ns` split the estimate into the timer's share and the rest. These are diagnostic approximations, not bounds: subtracting them may also remove some collector work. Per game hour, a family costs Δ`estimated_detour_ns` / Δ`families.hourly.calls`, the conservative figure; [bench.ps1](../../tools/bench.ps1) reports the approximate net beside it (`approximate_net_detour_ms_per_hour`, `direct_approximate_net_ms_per_hour`).

`collector_thread_cpu` lists the runtime, decode, spool, status and acquisition threads, the spool's helpers and sizing thread, and the sampler when its feature is enabled, with QueryThreadCycleTime `cycles` (`cycle_ns` through `tsc_hz`) and GetThreadTimes `user_ns`/`kernel_ns`, then `collector_total` and the whole game `process`. A thread whose id now names a different thread is unavailable.

`spool_work.phases` partitions the spool thread's loop into non-overlapping [phases](src/spool_phases.rs) (buffer receipt, conversion of core and pack rows, the wait for the conversion helpers, merges and carry, buffer return, comparison before encoding, encoding, record writes, commit, observer preparation, sizing hand-over, durability checks, status and idle wait), each with `calls`, QPC `wall_ns` and the thread's own `cycles`; `helper_phases` sums the helpers' map and pack conversion and their shares of the comparison and encoding on their own threads, `sizing_phases` holds the sizing thread's reads, observer preparation, freeing of what commits handed back and idle wait, and `pack_cycles` splits pack conversion on any thread. `spool_work.recycle_capacities_wait` measures the spool's wait for the capacity mutex while it holds the returning buffer. `sizing_capacities_hold` measures sizing's mutex holds for raises, idle-buffer and combat-hint growth, live-hint copies and publication, and a live-hint re-read after a concurrent raise; it excludes the initial live-hint reads, lock acquisition and diagnostic hand-over (inline on the spool thread when the sizing thread cannot start). Both report cumulative calls, total, mean and maximum wall since attach. `spool_work.comparison` counts each table's comparison decisions and the comparing threads' cycles. Per game hour, a phase costs Δ`cycle_ns` / Δ`hours`. The spool loop does not poll: decode publication, a callback parked for clock preparation and the stop request wake it, and its idle wait is bounded so durability checks keep their cadence while no hour arrives; the spool wakes the sizing thread after each hour, and its own bounded wait keeps observer preparation and throttled sizing reads on cadence.

## Profiling worker CPU

The off-by-default `worker_sampler` feature samples active collector threads by role and pool job, and the game thread only inside the hourly callback. It captures the instruction pointer and atomic job label in a suspension window with no allocation, user-mode locks, formatting or stack reads. The callback closes its sampling gate before the native original, including on unwind; its exit spins for at most 25 us before yielding until an owned capture resumes. Failed resumes retain the handle and retry until resume or proved thread exit. The sampler joins before hook restoration and every sampled collector thread's exit. Status reports achieved cadence, written samples, drops, suspension duration, resume retries, callback spins/yields and stop errors; sampler CPU is in `collector_thread_cpu`.

From the repository root, build with function symbols and install the Python reader's dependency:

```powershell
cargo build -p recorder -p collector --release --features collector/worker_sampler --config crates/collector/profile-symbols.toml
python -m pip install numpy
```

Keep `collector.dll` and `collector.pdb` from this build together in `.cargo-target/release`; the reader checks the PDB GUID and age against the recording. Choose a fresh capture directory outside Git and your recording client's user directory, then follow the [recorder guide](../recorder/README.md#record-a-campaign) to end the session:

```powershell
$capture = Join-Path $env:LOCALAPPDATA 'HOI4Replay\captures\worker-profile-YYYYMMDD'
$userDirectory = 'C:\path\to\your\Paradox-user-directory'
$env:BATTLE_PLAN_WORKER_SAMPLER = 'interval_us=250'
& .\.cargo-target\release\recorder.exe record --once --out $capture --user-dir $userDirectory
```

The recorder forwards `BATTLE_PLAN_WORKER_SAMPLER` verbatim for both CLI and in-process captures. A profiling build defaults to 250 us; comma-separated `interval_us=<positive-u32>` changes the period and `off` disables sampling. A nonempty setting requires this collector feature. Each session writes `$capture/sessions/<session-directory>/worker-samples.bin`, beside `status.json`; `active.json` names that session directory while attached. After the recorder finishes, use its actual session directory and recorded game-hour count:

```powershell
$sessionDirectory = 'C:\path\to\capture\sessions\session-directory'
$hoursRecorded = 100 # Replace with this session's recorded game-hour count.
python tools/worker_profile.py "$sessionDirectory/worker-samples.bin" --pdb-dir .cargo-target/release --dll .cargo-target/release/collector.dll --hours $hoursRecorded
```

The table prints self CPU costs by function, role and job in estimated cycle ms per game hour. Cycle weights cover CPU since the thread's previous check, which may precede the sampled function or callback. Missing TSC frequency makes ms/h unavailable. An interrupted file retains complete records and names missing trailer metadata. The reader streams chunks and spills its address cache outside Git; `--self-test` checks synthetic input, attribution, PDB refusal and ten million records. [bench.ps1](../../tools/bench.ps1) accepts `-WorkerSampler 'interval_us=250'` for recorder candidates built with the feature, placing each sample file in the candidate recording's session directory and restoring the parent environment after launch. Clear `BATTLE_PLAN_WORKER_SAMPLER` before recording with a default collector build.
