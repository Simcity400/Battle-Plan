# viewer-raids

Raid offers, reach and path queries, ribbon production, recorded unit and source operands, hover text and retained icon history, and the Operatives map mode's intel icons. Content and every asset resolve through the recorded installed-content stack. Shared GUI, texture, visibility and worker contracts come from viewer-foundation.

The viewer host appends raid ribbon data to battle-plan buffers in draw order; world owns GPU submission and model animation. Shared pose, track and ribbon contracts belong to foundation. This crate evaluates offers and tooltips without depending on the host or other viewer features. Its content identity, rolling offer cursor, per-hour query caches and native refusal order remain local to the raid implementation.

The intel icons ([intel_icons](src/map/intel_icons/mod.rs)) build one `intel_map_mode_map_icon` container per state for the viewing country each hour: its friendly countries' counterintelligence shields, its operatives' missions and the operation instances admitted by the recorded shared client UI buffers. Operation admission visits completed, running, ready-preparation and unready-preparation buckets in native order before applying each state's slot bound; it never enumerates saved instances to infer membership. Stale and empty buffers remain as recorded, and unavailable buffers withhold operation entries with a named refusal, with each entry's hover text. A view keeps each container's and entry's window from frame to frame, places the entries in the container's overlapping list, draws each container under its own layer, and keeps each entry's hover shapes: the union of its own hit-taking children. Transparency-checked children read a shared mip-0 CPU mask: alpha-zero texels pass through, positive alpha takes the pointer, and a texture without a mask keeps its rectangular hit. Each child tests independently before the entry takes its tooltip. The shield rating and an operative's counterintelligence contribution share the raid tooltips' counteroperative stacking. Operative portraits supply their recorded sprite texture through the shared lazy portrait store while retaining the entry icon's authored mask and effect. A part whose operands the hour lacks is hidden and counted by name. Unrecorded UI state produces named runtime refusals: one per hidden operative selection/warning highlight, and one view-level refusal for operation offers (whose cached count is itself unrecorded).

`test-support` exposes the existing synthetic raid inputs and a prepared icon fixture to the host's route and GUI composition tests. Fixtures that evaluate authored triggers initialize executable metadata from `BATTLE_PLAN_GAME_DIR`. Follow the workspace [working rules](../../AGENTS.md).
