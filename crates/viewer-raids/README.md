# viewer-raids

Raid offers, reach and path queries, ribbon production, recorded unit and source operands, hover text and retained icon history. Content and every asset resolve through the recorded installed-content stack. Shared GUI, texture, visibility and worker contracts come from viewer-foundation.

The viewer host appends raid ribbon data to battle-plan buffers in draw order; world owns GPU submission and model animation. Shared pose, track and ribbon contracts belong to foundation. This crate evaluates offers and tooltips without depending on the host or other viewer features. Its content identity, rolling offer cursor, per-hour query caches and native refusal order remain local to the raid implementation.

`slow-tests` retains installation and benchmark gating. `test-support` exposes the existing synthetic raid inputs and a prepared icon fixture to the host's route and GUI composition tests. Fixtures that evaluate authored triggers initialize executable metadata from `BATTLE_PLAN_GAME_DIR`. Follow the workspace [working rules](../../AGENTS.md).
