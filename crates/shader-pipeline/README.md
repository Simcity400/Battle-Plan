# shader-pipeline

The shared executable PdxShader backend for map passes and native GUI. Source parsing belongs to `installed_content::pdxshader`. This crate has no GUI layout dependency. Map-pass migration is a separate PR; the API does not select a replacement shader by filename.

## Runtime contract

`Library` owns one resolved content stack. `load` parses the requested effect and its includes; `Effect::select` compiles only the technique first used. Vanilla and mods take the same path. Selecting from a missing file or selecting an undeclared technique returns `None` for the native retained-program transition; malformed source or a declared technique that fails is an error naming the effect, technique and compiler reason. `cache::Diagnostics`, `Library::refused`, `gpu::Cache::refused` and `Stream::refused` count failures. Consumers surface those alongside their normal missing-input diagnostics and omit only the affected draw.

`load`'s defines are the complete caller list. On a cache miss `engine_shader_effect_lookup@1423F4EC0` puts the renderer's global defines (written by `140A4DDE0`: map size, power-of-two scales and `GRADIENT_BORDERS`) before the caller's own, for every effect, GUI included, and `142344DF0` appends the technique's `Defines`. `library::globals` builds that list from the provinces bitmap's size in the native order and `%.3f` format (`1424B5850`), taking the power-of-two branch for `force_pow2_textures = no`, the settings default, since the recording holds no user settings; `Library::with_globals` prepends it to every load, so a mod effect that reads them (or includes a file that does) compiles as it does in the game, GUI and map alike.

The CPU cache is `%LOCALAPPDATA%/HOI4Replay/shader-cache/v2/<sha256>.json`. Its key covers the resolved root and every ordered include (including missing files), the DX11 header, the emitted vertex/pixel sources including caller/effect defines, and the compiler/translation ABI. Paths and lengths are framed before hashing. Each entry carries the ABI, key and a payload checksum. Source, include, define or ABI changes invalidate it; corrupt entries recompile. Temporary files are renamed after writing. Cache write failures are warnings and do not refuse a successfully compiled draw. Failures are cached only in memory, so installing a missing compiler permits a retry in the next content load/process. The in-memory once cells serialize identical concurrent requests; separate processes race only on the rename, and either complete entry is valid. There is no eviction: the installed vanilla GUI family is 70 entries (0.36 MB), and each game version or mod stack adds its changed sources. GPU objects are separately cached per device, effect, technique, sampler and complete pass state.

`gpu::Pass` accepts arbitrary vertex/instance buffer layouts, topology, culling, depth/stencil, multisampling and colour targets. `gpu::blend`, `gpu::depth_stencil` and `gpu::primitive` lower authored states as the engine does (`1423FCB30`, `1423FCFC0`, `1423FD2F0`; `Program::blend`, `depth_stencil` and `rasterizer` find a technique's named state or the reader default); each applies independently, so a pass can keep an engine-forced state instead of the authored one. The stencil reference and scissor enable they return are the caller's dynamic commands. `gpu::State` supplies native samplers; `Pipeline::bindings` accepts arbitrary constant-buffer bytes and texture views by `binding(slot, stage)`, with independent VS/PS namespaces. Callers issue their own vertex/index binding, draw, viewport, scissor, stencil-reference and blend-constant commands.

Uploads go through the owner's `gpu::Arena`, one per frame being encoded: constant blocks (zero-filled to their declared size, as D3D11 reads past a bound buffer's bytes) and repacked vertex streams are staged on the CPU and bound at offsets into a few persistent buffers. The owner calls `Arena::flush` before submitting commands that bind its uploads (it writes what was staged since the previous flush) and `reset` before encoding the next frame; bindings stay valid until the reset. `Arena::write` defers a write into a caller-owned buffer to the next flush. Every constant buffer is bound at a dynamic offset, so a program declaring more than the device's `max_dynamic_uniform_buffers_per_pipeline_layout` is refused by name; consumers request the adapter's limit. Each pipeline caches its bind groups by resource identity (arena buffer, texture views; samplers are fixed per pipeline) and drops an entry unused for a whole frame, so a draw creates no buffer and no bind group. `Bindings::bind_after` sets only the groups that differ from the previous draw of the same pipeline, since each set merges the group's resources into the pass. `Cache` hits compare the pipeline key by reference, so they clone nothing. Vertex reflection preserves float/signed/unsigned scalar kinds as well as semantics, locations and widths; the packed helper uses the corresponding GPU formats. Reflection supports 2D, cube and volume sampled textures. `142411AB0` declares `Type = cube` as `TextureCube` and every other type, `3d` included, as `Texture2D`; a volume is the authored code's own `Texture3D` on a declared register. The engine binds only declared registers, so a resource raw code declares on any other register (which would read whatever an earlier draw left bound) is refused by name. D3D11 links vertex outputs to pixel inputs by register, that is declaration order; a pixel signature that is not the vertex output's order (reordered, or a subset that is not a prefix) is refused rather than linked by semantic. Registers past D3D11's slots (`b14` and up, `s16`/`t16` and up) are refused by name. Samplers wrap W as `1423FD550` does, and MipLODBias applies to explicit-LOD samples too (D3D11.3 7.18.11).

wgpu has no `MIRROR_ONCE` address mode, so `sampling.rs` lowers it in the generated WGSL. An isotropic sample without a texel offset reads `abs(uv)` with the original coarse derivatives, which is exact by symmetry (only the derivatives' lengths choose the level). A gather reads its four footprint texels with `textureLoad` at `floor(uv * size - 0.5) + offset`, each axis addressed as D3D11 does, in gather order; it has no filtering or LOD, so it is exact. A sample with a texel offset needs the offset in texels of each level read, before mirroring, so its texels are filtered in the shader with `textureLoad` and D3D11 addressing per axis. A clamped LOD above zero minifies, otherwise it magnifies, each with the sampler's own point or linear filter. Point mip reads `floor(LOD + 0.5)`; linear mip blends the two levels by the LOD's fraction, and a single-mip texture is one level. The LOD follows 7.18.10-11 (isotropic `log2(max(|dX|, |dY|))` over coarse derivatives, plus MipLODBias and any instruction bias, clamped to MinLOD/MaxLOD). D3D's own derivative and LOD arithmetic is implementation-defined, so this matches it as closely as another conforming GPU. Anisotropic filtering through `MIRROR_ONCE` is refused by name: the hardware mirrors each tap of the footprint, folding it where it crosses zero, which no wgpu sample reproduces. It is a platform gap, not a native failure. No vanilla shader and none of the owner's installed mods use `MIRROR_ONCE`. Unsupported resource types are named errors, never silently treated as 2D. `Stream` additionally models the engine's retained program/layout, samplers, textures and constant buffers for ordered draws. The predefined Sprite/Text/Circular vertex decoders are conveniences, not a limit on `Pass`.

The binding layout follows the compiled image/sampler pairs, including raw HLSL that pairs different register numbers. All-point samplers use nonfiltering bindings; a float texture requires filterability only when a paired sampler filters it. Native point-sampled float32 inputs therefore work without the optional `FLOAT32_FILTERABLE` device feature. Linear sampling of float32 still requires that feature.

`Buffer::reads` reports conservative component byte reads after DXC elimination, excluding unused fields and layout padding. Dynamic array indices cover every possible element. A vector load consumed only by projections requires those components; other operations conservatively require the whole loaded value. Uniform pointer parameters conservatively require all uniform bytes. `Pipeline::check_initialized` checks these reads against a physical allocation and its known ranges. Out-of-range D3D11 reads remain zero; reads of unknown bytes inside the allocation refuse with the stage, slot and byte range. `Stream::bind_partial_constants` retains this validity with the bytes across null binds and scoped inheritance; a complete later upload replaces it. Consumers must supply the native physical size and known ranges: a short initialized prefix is not itself the allocation size.

## Compiler and packaging

`Stream::bind_vertex_stride` tracks native buffer strides independently of the program's input declaration. A missing technique retains that declaration while later vertex-buffer binds can replace individual strides; untouched slots retain theirs. `vertex_layouts` exposes the effective layouts for caller-owned buffers and offsets. Scoped inheritance copies these bindings and invalidation clears them. This does not infer missing buffers or native data outside supplied uploads.

`prepare_native_pass` repacks the fetched records of native vertex-buffer allocations for declarations whose attributes overlap the bound stride, which WebGPU cannot express directly, into arena streams. A `NativeBuffer` is an allocation's physical size, its written prefix and the sorted known byte ranges within it, so a ring or a large allocation is never copied or uploaded whole. Repacking copies attribute bytes without changing their formats, respects independent per-vertex/per-instance stepping and bound offsets, zeros out-of-allocation fetches (D3D11.3 section 8.19.2), and refuses unknown bytes within an allocation. An omitted buffer is unknown; an explicit null buffer supplies zeros. Repacking leaves the retained native declaration and strides intact.

`Stream::bind_program` retains arbitrary vertex/instance declarations along with the selected program; a null selection changes neither. `bind_depth_stencil`, `bind_rasterizer` and `bind_blend` are independent native handle updates. `prepare_pass` uses those retained handles and resource bindings with a caller's attachment formats, topology and multisampling, returning the cached pipeline, bindings and any required dynamic stencil reference/scissor enable. Vertex/index buffers, draw commands, viewport, scissor rectangle and blend constants remain caller-owned. Missing constant/texture bindings refuse by name; explicit null textures sample zero. `inherit_bindings` also copies native declarations and depth/raster handles without sharing later mutations. The existing packed GUI `prepare` remains available. This API does not establish a consumer's submission order or unknown constant-buffer padding.

`Effect::variant` lazily selects another caller define set (`Effect::caller` is the current one) while retaining the same resolved source, the library's global defines and the persistent cache. Repeated requests return the same handle, preserving GPU pipeline identity. `Stream::bind_blend` applies an independent renderer blend handle after effect selection; this supports native multipass consumers such as text-sprite baking (background blend off, glyph alpha MAX) without modifying the authored effect. `Stream::inherit_bindings` starts a scoped render-to-texture pass from the caller's retained state while keeping a separate device cache; restoring the caller is then implicit.

Every desktop release stages `shader-tools/dxc/` beside `viewer.exe`: `dxc.exe`, `dxcompiler.dll`, `dxil.dll`, `LICENSE-LLVM.txt`, `LICENCE-MIT.txt` and `LICENSE-MS.txt`. `tools/desktop.mjs build` invokes [the pinned installer](../../tools/install-shader-compiler.ps1), verifies the official archive SHA256, and copies only those named members. Copy the complete directory with the two application executables. Development may use `BATTLE_PLAN_SHADER_COMPILER` as an explicit executable override; there is no PATH search or implicit SDK fallback. Otherwise discovery uses exactly the sibling directory. Discovery runs `dxc --version` and refuses any build but the pinned `1.9.0.5402 (0d3ee6b55)`, which the cache ABI names, so no other compiler can write or reuse entries. An absent executable produces `DXC not found at <path>` only on a cache miss; the whole view remains usable. A wrong version, DLL/launch and compiler failures likewise carry the named technique's reason. Discovery happens once per cache (one content load). No runtime download occurs.

The official v1.9.2607 archive (SHA256 `a1dfb116…cd241`, the digest GitHub publishes) carries three licences, all shipped unmodified: LLVM's University of Illinois/NCSA licence, Microsoft's MIT licence for its own changes, and the Microsoft DirectX Shader Compiler terms, whose distributable-code conditions refer to a distributables list the archive does not contain. `dxil.dll` is only DXIL validation and signing: SPIR-V output is byte-identical without it. It ships because the packaging decision bundles the complete compiler runtime. A future installer must retain all three licences and the Microsoft distribution terms. The current desktop build makes a directory of executables, not an installer.

`1423FBC10` calls `D3DCompile` with entry `main`, `vs`/`ps_4_0`, `4_1` or `5_0` by feature level (`1423FC740`, `1423FC3C0`), no defines array and flags `0x8000` (`D3DCOMPILE_ENABLE_BACKWARDS_COMPATIBILITY`, so matrices pack column-major, DXC's default). DXC compiles `vs_6_0`/`ps_6_0` with HLSL 2016 and has no backwards-compatibility mode: legacy DX9 syntax the flag admits is a named compiler refusal. DXC emits SPIR-V with Vulkan 1.0 and DX constant-buffer layout; naga 30.0.1 (pinned exactly) validates and emits WGSL. Naga is already in the viewer's wgpu tree. Engine DX11 assembly is `142411430`; `142411840` emits constant buffers and `142411AB0` samplers. `1423FBC10` calls D3DCompile with a null include handler, so active raw HLSL `#include` is refused instead of searching the host filesystem. PdxShader Includes use the recorded content stack. Engine OpenGL builder `142414D70` emits GLSL 1.20 plus `PDX_OPENGL`, stage and caller/effect defines, `defines_glsl.fxh` and texture-LOD extension switches; `14240B6A0` compiles with the driver. No reusable portable IR was found in the inspected install/compiler paths. That legacy GLSL path is a worse fit for wgpu than the verified DXC route. The machine's SDK/RenderDoc DXC omit SPIR-V despite listing the flag; RenderDoc glslang failed the native sampler-wrapper structures.

## Verification

Run checks through the shared check slot. Unit tests cover parser order, source assembly, lazy technique selection, named failures and cache reuse across two independent cache lifetimes, including changed includes/defines and obsolete ABI entries. Set `BATTLE_PLAN_GAME_DIR` and `BATTLE_PLAN_SHADER_COMPILER` for `cargo test -p shader-pipeline -- --ignored --skip installed_vanilla_persistent_cache_across_processes --nocapture --test-threads=1`: this compiles the installed vanilla GUI variants and creates pipelines, renders synthetic authored code, sampler/null-texture cases, and a general pass with an integer instance stream and an authored volume texture. Unit tests also cover the native depth-stencil and rasterizer lowering. GPU tests are offline and do not launch the game. GUI-specific model comparisons remain in the GUI integration tests, using the same compiled core against W2's test fixtures. Compiler success, identical-input pixel equality and a live matched game frame are separate claims.

The disk-cache process check deliberately runs separately. Set `BATTLE_PLAN_CACHE_TEST_DIR` to a new scratch directory outside the source tree, then invoke `cargo test -p shader-pipeline installed_vanilla_persistent_cache_across_processes -- --ignored --nocapture` twice through the check slot: first with `BATTLE_PLAN_EXPECT_COMPILES=1`, then with `BATTLE_PLAN_EXPECT_COMPILES=0`. Both compile every installed vanilla GUI effect, technique and define variant; the second process's backend fails if compiler discovery is attempted. Map effects also need the map-derived global defines, which their consumer supplies. The test override isolates its files; normal runtime uses the `%LOCALAPPDATA%` location above. Source/include/define and ABI invalidation are covered by the ordinary cache unit test.
