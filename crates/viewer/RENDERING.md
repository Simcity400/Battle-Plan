# Map rendering: making the replay map match the game

Owner instruction 2026-09-13: the viewer's map must look like the game's map at the same hour and camera (terrain, water, rivers, borders, names, icons, lighting, day and night, weather effects) closely enough that the two are indistinguishable. The game's own interface is out of scope; on-map unit counters (divisions and their movement) are in scope. This document is the shared design for that work. Status and evidence stay in `PLAN.md`; this file holds the design, the layer plan, the asset and data contracts and the evidence pointers.

## 1. Approach

The game composites its map with readable shader source under `gfx/FX/` (`pdxmap.shader`, `pdxwater.shader`, `river.shader`, `border.shader`, `mapname.shader`, `strait.shader`, `fow.fxh`, `standardfuncsgfx.fxh`, `constants.fxh`) driven by assets under `map/`, `map/terrain/`, `gfx/`, `interface/` and constants in `common/defines/00_graphics.lua`. We port that pipeline to wgpu/WGSL one pass at a time, sample the same textures with the same math, and reproduce the intermediates the engine generates at runtime (terrain id map, gradient border fields, border meshes, name curves, unit stacks) from the same inputs. Where the engine's own computation is not visible in assets (camera model, sun position, name placement, border field thickness), the decompiled a729 build in `<local-path>` is the evidence, and a fit against a game screenshot at a recorded hour is the check.

Rules that carry over from `PLAN.md`: data is exact and comes from the replay; visuals come from the game's own files with our compositing; nothing is interpolated between hours; unavailable tables are shown as such; the headless `--dump` path renders through the same pipeline as the window; no game data or assets are stored in the replay or the repository.

## 2. Reference pairs and scoring

A reference pair is a game screenshot at a paused, saved hour with a known camera, and the viewer's headless render of the same hour on the same camera. Pairs live in `reference/NN.md` with both images; captures and saves stay under `captures\`.

Existing material: `reference/01.md` (1936, format-1 replay, no longer readable). `captures\m21_takeover_20260913\array_loaded.png` is the game at 19:00 23 Aug 1943 (hour 60826314, the loaded save `GER_1943_08_23_19.hoi4`) at the load camera; the `array` replay's branch 2 starts at 60826315. `checkpoint2_save1_menu.png` shows 14:00 26 May 1944 (60832933, recorded on `checkpoint2` branch 1) behind the save dialog. Those are comparable framings until fresh pairs are captured with the game idle (the game lock `C:\Users\Example\AppData\Local\Temp\claude\hoi4_game.lock` belongs to the 2.1 performance track while it exists).

Scoring: the viewer gains a `--compare <game.png> <viewer.png>` mode that prints a per-region and overall similarity (mean absolute error in gamma space, structural similarity on a luminance pyramid) and writes a difference image. Masks exclude the game's UI bars, tooltips and dialogs. Targets are set per layer as the layers land; the acceptance in `PLAN.md` 2.4 is five pairs.

## 3. Pipeline

Coordinate systems (confirmed by research R1, `<local-path>`): map pixel space is `provinces.bmp` (5632 x 2048, origin top-left, x right, y down). Game world space is x = pixel column, z = 2047 - pixel row, y = heightmap byte x 0.1 with sea level at `WATER_HEIGHT = 9.5` (byte 95). `map/unitstacks.txt` and `map/buildings.txt` positions are world x, y, z. Shader `uv` is pixel/size; `uv2` flips y; every `*_POW2_*` define is 1.0 on this profile and `MAP_SIZE_X/Y` are 5632/2048; the FOW and snow/mud grid is `MAP_SIZE / 6` (939 x 342 texels).

Camera (exact, from the binary, fitted to `array_loaded.png` at rms 1.3 px over 21 cities): left-handed look-at with up +Y, vertical field of view 0.785 rad, near 5, far 4000, aspect w/h; `eye = (cx, h, cz - 30)`, `look_at = (cx, 9.5, cz)` where the 30 is `camera_tilt x 0.3` and does not depend on height. The load camera targets the player capital's unit-stack type 0 position at height about 310.2; the reference frame is `centre (3010, 1568), height 310.178`. `Camera` therefore keeps `center` (world x, z) and `height`; `--camera x,y,span` is replaced by `--camera x,z,height` in world units (the old flat form is removed with the old renderer).

Reference profile facts (R1 section 0): the game renders at 2048 x 1152 borderless and the screenshots are 1.25x bilinear upscales, so comparisons render at 2048 x 1152 and upscale by 1.25; `draw_postfx=no` (no LUT, tone mapping or exposure), `multi_sampling=4`, `shadows=no`, `texture_quality=0` (`atlas0.dds` 2048 squared). Day/night: `DayNight_Hour_SunDir.x = (hour mod 24) / 24` with the raw replay hour, sun direction `(0, -sin d, cos d)` with d measured at +1.62 degrees on 23 Aug 1943 (seasonal law unknown); the terminator fits the screenshot at rms 0.9 px. Constant-buffer values, sun and moon virtual positions, the terrain ambient basis and the HSV-defined light colours are tabulated in the report's "Formulas for implementers".

Frame constants (bind group 0), mirroring the game's `ConstantBuffer(0,0)`: view-projection and inverse, camera position and look direction, gradient-border camera-distance overrides and outline cutoffs, sun and moon virtual positions (two each), `DayNight_Hour_SunDir`, `vFoWOpacity_FoWTime_SnowMudFade_MaxGameSpeed`, ambient cube, `HdrRange`, sun and moon diffuse intensity, `GB_TextureHeight`, global time. Values come from `00_graphics.lua` and research R1.

Pass order (each pass a module under `crates/viewer/src/map/`, registered in one list):

1. `terrain`: heightmap mesh (LOD quads as in the game or a single tessellated grid), `PixelShaderTerrain` port: terrain id map with the four-neighbour blend and the +100 "all same" trick, atlas diffuse and normal (`atlas0..2.dds`, `atlas_normal0..2.dds` selected by `texture_quality`), colormap overlay, snow and mud from the weather tables, gradient borders, secondary (occupation) mask, sun/moon Blinn-Phong, ambient cube, city lights at night, distance fog, day/night desaturation. Underwater terrain (`PixelShaderUnderwater`) below water.
2. `water`: `pdxwater.shader` port: flat plane at `WATER_HEIGHT`, LEAN normal maps (`lean1/2.dds`), specular map (`fow_rgb_waterspec_a.dds` alpha), refraction of the underwater pass, cube reflection (`reflection.dds`), ice, gradient borders for sea provinces, shore alpha from the heightmap, dominance effects only when recorded data exists.
3. `rivers` and `straits`: river meshes from `rivers.bmp` (source, flow, width classes) with `river.shader`; strait quads from `adjacencies.csv` with `strait.dds`.
5. `names`: country names on curves (engine placement reproduced from research R2; `hoi_mapfont4`), victory-point and capital labels (`victory_point_mapicon`, `capital_mapicon` in `interface/mapicons.gui`, `GFX_onmap_victorypoints_strip` frame by value, font `hoi_20bs`), province names within `PROVINCE_NAME_DRAW_DISTANCE`.
6. `icons`: screen-space sprites anchored to world positions: unit counters at unit-stack positions (frame, flag stripe, count, organisation and strength bars, `unit_counter` layout at `interface/mapicons.gui`), naval counters for task forces, air base and naval base icons with counts, land combat icons, front lines and order arrows from `ArmyOrders.path`.
7. `post`: the game's post pass (`map/post.rs`): log-luminance adaptation, exposure, Uncharted 2 tone mapping, gamma, the volume-selected LUT (`gfx/posteffect_volumes.txt`, `EuropeandRussia` over the reference camera), season HSV and colour balance, `Levels(0.04, 0.80)`. The reference screenshots are graded despite `draw_postfx=no` in the settings file (the ungraded map is green and bright; the chain reproduces the game's hue), so it is on by default with `--postfx off` as the switch. All four `HDR`/`COLOR_LUT` combinations were measured against both fresh pairs and the shipped pair is the best on both, so no stage is turned off by `draw_postfx=no`; bloom is not ported and, measured on the CPU with the volumes' own thresholds, would move either pair by less than 0.05 mean absolute error. The chain's exposure is not fitted: both reference frames have their adapted luminance pinned by the `hdr_*_adjustment` clamps, so it is `tonemap_middlegrey / MIN_HDR_ADJUSTMENT` exactly. The one fitted constant is `SCENE_BRIGHTNESS = 0.32` (`map/post.rs`), and it is a statement about the scene rather than about this pass: the same value is the joint optimum on the November day pair, the November night pair and the May menu-dimmed day pair, so the map passes hand the chain a scene about 3.1x brighter than the game's. The rest of the daylight gap is upstream too and provably out of this pass's reach: between the scene and the colour cube the chain is monotone per channel, so it cannot give the game's land the blue-over-red ordering its colours require, and a fitted per-channel gain on the scene asks the daylight scene to be 1.46x greener and 2.46x bluer relative to its red while the night scene is already balanced. Both are recorded with their measurements in `map/post.rs`.
8. `trees`: tree canopy tiles instanced from `trees.bmp` on the engine's 3.4133-unit lattice with `tree.shader`, fading out between heights 250 and 350 (R3).
8b. `sprawl`: city-sprawl houses, the first of the close-zoom 3D layers the engine gates off above heights 120 to 300 (R3 section D). The shared static-mesh machinery is `map/models.rs` plus `pdxmesh.wgsl`, a port of `pdxmesh.shader`'s `VertexPdxMeshStandard`/`PixelPdxMeshStandard` with the effect `Defines` kept as a per-material flag word and `ComposeLightMesh`'s separate unit-ambient basis; every close-zoom mesh layer is one `ModelPass` over one `ModelLibrary`. `map/sprawl.rs` walks the `spawn_city` blobs of `terrain.bmp`, takes the architecture from `cities.bmp` and the ring mesh from the pixel's distance to the blob edge, and despawns the whole layer above camera height 220 + `WATER_HEIGHT` (`CITY_SPRAWL_SHRINK_DISTANCE`, a binary switch rather than the scale its name suggests). Two readings the frames settled rather than the files: `Descriptors::resolve` has to prefer the entity table, because `westerngfx_house_1_1` names both a pdxmesh and the entity that carries its `scale = 1.4`; and `pixel_step` is a stride in half map pixels, because the whole-pixel reading covers at most 37 % of a blob where `pairD_in10.png` shows Berlin built over completely. 8c. `map_buildings`: factories, air bases, naval bases, radar, forts, anti-air and the rest, placed at `map/buildings.txt` slots from the recorded `StateBuildings` and `ProvinceBuildings` levels through the same `ModelPass` (`map/map_buildings.rs`). Two findings the files and R3 did not carry. The first field of `map/buildings.txt` is **always a state**, not a state-or-province, and a province building gets one slot per qualifying province of its state; a slot stands inside its province, so `map/provinces.bmp` names it, which places 10,154 of 10,154 `supply_node`, 10,153 of 10,154 `bunker`, 2,348 of 2,362 `coastal_bunker` and 2,310 of 2,362 `naval_base_spawn` slots in a province of the state they are keyed to, and leaves 46 of 3,796 recorded rows unplaced instead of 1,692. And the `always_shown` exemption from the 180 cutoff is read but not reproduced: the game draws no mesh at Berlin's own `supply_node` slot in `reference/03-game.png`, so drawing the exempt subset there only cost the daylight pair 0.009 of mean absolute error. The level is spread over the type's `show_on_map` slots proportionally to its `level_cap`, which `pairD_in10.png` supports over `min(level, slots)`: Brandenburg's `arms_factory` slot at world (3029, 1569) is bare in the game and `min` fills it. Damaged and destroyed states and the factory smoke particle are not drawn and the viewer says so. 8d. `railways`: the authored rail network of `map/railways.txt` as a textured strip, with its own effect rather than a mesh one --- `gfx/models/supply/railroad.shader` is a complete shader sitting outside `gfx/FX/`, ported in `railroad.wgsl`, and it turns the depth test off so the rails paint over the canopy, the sprawl and the buildings. `railroad.dds` is 64 x 320: five 64 x 64 tiles, one per rail level, so the strip's `vUV.y` picks the level's band and its own edge, which is what the shader's `if ( vUV.y < 0.0 || vUV.y >= 1.0 ) discard` is for. The curve is a centripetal Catmull-Rom through the provinces' type-0 anchors at `RAILWAY_Y_OFFSET = 0.9`, and the layer switches off above `RAILWAY_CAMERA_CUTOFF = 300`, ten units above both reference pairs, which is why neither shows a rail. The strip width is the one fitted number in the layer (0.7 world units to the nearest 0.1, from the game's own sleeper period and track width in `pairD_in10.png`); no define carries it. Bridges are placed where a curve crosses water, one `bridge_railway_entity` per `RAILWAY_BRIDGE_WIDTH = 4.0`: a river is painted rather than carved, so the crossing test is `map/rivers.bmp` as well as the heightmap --- a sea-level test alone found no crossing in Germany at all. Trains are not drawn and cannot be: no recorded table carries one. Nor is the network as it stands at the hour, because none carries that either; these are the 1936 authored rails. 8e. `unit_models`: one division figure per land stack, on the same `Standstill` anchor the counter layer uses, gated on `UNITS_DISTANCE_CUTOFF = 120` against the raw camera height, drawn through `map/models.rs`. **Which figure is a stated fallback.** The entities are named `<TAG>_<subunit>_entity` and no division-template table is recorded (section 5 above), so nothing recorded can name the sub-unit: every land stack shows rifle infantry, `<TAG>_infantry_entity` for the eight tags that ship one and the generic `infantry_rifle_entity` otherwise, and the viewer prints both counts and the tags that fell back. A tank division looks like a rifleman. The figures stand in their bind pose without their attached weapons: no `.anim` is read and no skeleton is evaluated, so the game's posed, rifle-carrying soldier and the viewer's unarmed one differ in pose while standing on the same anchor to about a screenshot pixel. Ships in port are not drawn: the placement is cheap (`SHIP_IN_PORT_SCALE = 0.25` on the type-19 anchor) but a ship's entity follows its hull and refit, which the recorded `Ships` table does not name. Ambient objects are still not drawn; none is in any reference frame.
9. `overlay`: egui only: timeline, warnings, table status; nothing of the map is drawn by egui.

Fog of war: the recorded fog inputs exist (D102) but v1 is omniscient (`PLAN.md` section 2); the FOW pass is built with the shader but disabled until per-country perspective is scheduled.

Facts recovered after the first render round (each recorded in the module that uses it): layer 2 of the gradient fields is empty in political mode (the `GRADIENT_BORDERS_*` overrides are per map mode, not per channel); the game's dark boundary line width already matches; the counter layer draws 1:1 in device pixels; unit counters group per level (province above 90, state above 180, strategic region above 350) at the mean of their members' anchors with no push-apart pass (`map/counter_groups.rs`); a war with no end carries the null date 43808760 in `end_hour`; `SnowMudData` is `MAP_SIZE / 4` (1408 x 512) filled as a 4 x 4 mean of per-province bytes with `snow_visual_min = 128` and the `perm_snow` terrain flag (`map/weather.rs`); `rivers.bmp` traces 4-connected from source pixels with junction stitching (`map/rivers.rs`); the engine swap chain and textures are linear UNORM, not sRGB.

## 4. Asset contracts (crate `installed-content`)

All readers take `&ResolvedLayers` and return owned data; parsers take bytes and are unit-tested on synthetic input. Coverage: `map`, `common`, `history`, `localisation`, `interface`, `gfx/flags`, `gfx/interface` are hash-verified. Fonts (`gfx/fonts`), LUTs (`gfx/world`) and map items (`gfx/mapitems`) are outside the coverage policy; `ResolvedLayers::read_uncovered` reads them from the resolved layers in load order without hash verification and the viewer states that limitation once. Changing the coverage policy changes every layer hash and belongs to the recorder track, not here.

- `image::dds::decode(bytes) -> Texture { format: Bc1 | Bc2 | Bc3 | Rgba8, width, height, faces: 1 | 6, mips: Vec<Vec<MipLevel>> }`; block-compressed data is kept compressed for direct GPU upload; uncompressed 16/24/32-bit and 8-bit formats convert to RGBA8; cube maps keep six faces.
- `image::bmp::decode_indexed(bytes) -> IndexedImage { width, height, indices, palette: [[u8; 4]; 256] }` for `terrain.bmp`, `rivers.bmp`, `trees.bmp`, `cities.bmp`, `heightmap.bmp` (8-bit); `image::bmp::decode_rgb(bytes) -> Rgba8Image` for `world_normal.bmp`; rows always top-left first.
- `image::tga::decode(bytes) -> Rgba8Image` (uncompressed and RLE, 8/24/32-bit) for flags, fonts and LUTs.
- `fonts::parse_fnt(text) -> BitmapFont { line_height, base, scale, pages, glyphs: id -> Glyph { x, y, width, height, xoffset, yoffset, xadvance, page, channel }, kernings }` and `fonts::read_definitions(layers) -> name -> FontDefinition { path, color, border_color, overrides }` from the `bitmapfonts` blocks in `interface/*.gfx`.
- `localisation::read(layers, language) -> Localisation` with `get(key)`, precedence per the game's rules (research R2 confirms `replace/` and duplicate handling); color codes (`§Y...§!`) are kept in the string and stripped at layout.
- `states::read(layers) -> id -> StateDefinition { name_key, category, provinces, victory_points: Vec<(province, value)>, state buildings, province buildings, impassable }` from `history/states`.
- `regions::read(layers)` for `map/strategicregions` (id, name key, provinces).
- `cities::read(layers) -> (Cities { types_source, pixel_step_x, pixel_step_y, groups: Vec<CityGroup { color_index, density, buildings }> }, IndexedImage)` for `map/cities.txt` and the style bitmap it names; `buildings::read(layers) -> Buildings` for the `show_on_map`, `show_on_map_meshes`, `always_shown`, `spawn_point` and `level_cap` keys of `common/buildings`; `railways::read(layers) -> Vec<Railway { level, provinces }>` for `map/railways.txt`.
- `positions::read_unit_stacks(layers) -> Vec<UnitStack { province, kind, x, y, z, rotation, scale }>` and `positions::read_buildings(layers) -> Vec<BuildingPosition { state, kind, x, y, z, rotation, adjacent_sea }>`.
- `terrain::read(layers) -> TerrainDefinitions { categories: name -> { color, is_water, naval }, palette: index -> { category, atlas_index } }` from `common/terrain/00_terrain.txt`, plus `map/default.map` keys.
- `adjacencies::read(layers) -> Vec<Adjacency { from, to, kind, through, start, stop, rule, comment }>`.
- `gfx::sprites(layers) -> name -> SpriteType { texture, frames, ... }` from `interface/*.gfx` `spriteTypes`, and `gui::read(layers, file)` returning the parsed `.gui` tree for layout constants.

## 5. Replay data used by the map
