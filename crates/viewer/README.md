# viewer

When embedded in the desktop shell, the web UI owns map controls and the timeline. Its bounded `MapAction` commands update the same viewing-country, fog and capture state as the standalone controls. The old embedded egui panels are omitted; on-demand diagnostics are returned to Settings through `MapDetails`, and diagnostics mode (below) draws them over the embedded maps. Native battle-marker/detail interaction is unchanged.

The native map and playback application. It resolves the recording's game assets and renders its recorded state. The desktop host embeds this same viewer; there is not a separate web map renderer.

## Use and export

From the repository root:

```powershell
cargo build -p viewer --release
.\.cargo-target\release\viewer.exe <campaign.battleplan>
.\.cargo-target\release\viewer.exe --dump <campaign.battleplan> --hour <n> --branch <id> --out <frame.png> --camera <world-x,world-z,height>
```

On first run, choose the game and Paradox user folders. Local settings are stored beside the executable in `viewer.json`. Playback provides branch selection, a timeline, play/pause/speed, pan and zoom. Select a branch explicitly when an hour exists on more than one branch.

**UI scale** sizes the screen-space map interface: counters, map icons, VP/city labels, combat bubbles, the combat window and map tooltips. The default, *Match game*, draws them as large as the game shows them on screen: its effective `gui_scale`, clamped as the engine does while it reads `settings.txt`, applied to its frame, times the stretch of that frame onto its monitor. The game is not DPI aware, so Windows stretches its window by the monitor's display scale; a borderless frame is the monitor's desktop as the game sees it (2048x1152 for a 2560x1440 monitor at 125%). Mode, size and monitor are `settings.txt`'s with the user folder's `pdx_settings.txt` applied on top, in the engine's order ([settings.rs](../installed-content/src/settings.rs)); the game's command-line display overrides are not visible to the viewer. Without readable display settings it draws at 1.0 and says so in the warnings. The standalone window keeps a manual value in `viewer.json`; the desktop host sends its own. World-space names and the 3D map are not scaled. Dumps render at the game's frame size with scale 1.0, the verified comparison pipeline; `--ui-scale <factor>` changes that for `--dump` and `--window-dump`.

### Diagnostics

Technical stats (layer build times, table row counts, raw hours, branch evidence) and data limitations are hidden during normal viewing. **Diagnostics** in the header or F3 shows them and saves the choice in `viewer.json`; `--diagnostics` shows them for one run without saving. The desktop app has its own switch (see the [desktop guide](../desktop/README.md#where-to-work)). Over embedded maps they sit in a box laid out in UI-scale interface pixels, like the map's tooltip. Hidden diagnostics cost nothing per frame: their text is not built. Machine-readable outputs are unaffected: `--dump` and window captures print every limitation, `--counters-json` is unchanged, and the desktop's Settings > Diagnostics report builds them on request.

For offline shader comparisons, `BATTLE_PLAN_MAP_SCENE_RGBA16F=<new path>` also saves the resolved HDR scene before grading. The file contains tightly packed little-endian RGBA half floats at the dump dimensions; it refuses to overwrite an existing file. The extra readback runs before benchmark frames and is excluded from their per-pass timestamps.

The ignored `map::offline_scene::content_stack_scene` integration check reads `BATTLE_PLAN_CONTENT_SCENE_INPUT`, a JSON file with ordered `layers` (`root` and `replace_paths`), a new `output` directory, `cameras` as `[x,z,height]`, `size`, `hour`, `language` and `camera_tilt` (the game setting, normally 100). It uses the production content resolver, source audit and scene renderer for static geography and ambient placements. It creates no recording and does not establish historical political state, units or particle populations. Optional `presentation_steps` and `presentation_dt` advance the shared ambient/particle player. Initial and advanced images, per-step particle packet counts, warnings and any refusal are saved beside its PNGs.

`--perspective <TAG>|recorded` chooses the viewing country. `--fog on|off` controls fog; turning fog off does not remove the country perspective. Missing or mismatching covered content is refused. Some visual assets are outside the recorded hash policy; the [installed-content guide](../installed-content/README.md#asset-contracts) explains that warning. See `--help` for the full CLI.

## Rendering rules

In the desktop dashboard, `dashboard_maps.rs` owns map instances on the same graphics device; the [dashboard crate](../dashboard/README.md) owns recording sources and leases shared with the widgets. Map registry entries keep their renderer on the heap: moving inline renderer state through tree nodes can exhaust the Windows UI thread's stack. Scene permits remain charged through cancelled builds and deferred destruction. Source bytes and compatible CPU content are shared. The political fill's static parts (province IDs, kernel and strategic-layer output) are shared per content and device. Maps showing the same fill also share its state and texture pair; other mutable scene state and graphics assets remain per map.

Use the source map below for implementation and the existing [reference captures](../../reference/) for matched comparisons. Native evidence and remaining assumptions live beside each pass, not in a separate rendering diary.

The map size is the content's provinces bitmap (`MAP_SIZE`), carried by `camera::MapSize` and the shader globals.

Windowed playback and headless export use the same wgpu rendering path. Preserve the game's verified camera, asset selection, texture colour spaces, shader inputs, blend/depth states and draw order. Do not hide a missing rendering term with a fitted global brightness or colour correction.

Playback runs at the chosen speed whether or not the hour builders keep up (owner decision, 2026-09-27). The map shows the playhead's hour once it is built, else the newest hour built before it, all layers at once and with that hour's date, never a lagging label. Hours in flight at or before the playhead are finished rather than cancelled. Paused seeks, exports and captures wait for their exact hour. Across a forward skip, including the final catch-up after pausing, the building history passes over hours the builders did not build, and trains and unchanged weather regions keep their live animation. A seek (even to the same hour), step back, branch change or recorded gap restarts the animation, and the building history too unless a forward seek passes only over built hours; a viewing-country change restarts only the animation; camera and fog changes restart neither. Dashboard targets and full Campaign map clock commands say whether they play and carry a separate seek counter, so coalesced playback updates preserve this distinction ([presentation.rs](src/map/presentation.rs)); maps acknowledge the hour they show ([hours.rs](src/hours.rs), `Viewer::refresh_hour`).

Queues between the window and its threads are bounded by concurrency, not by data: finished hours wait at most one per hour in flight, and deferred destruction holds one frame's retirements per builder, beyond which a frame frees its own (`hours::Dropper`).

Unit models keep viewer-owned province history in [unit_history.rs](src/map/unit_history.rs), advanced once per frame as the game advances its own. Crossing a camera cutoff grows or shrinks a model's uniform scale (not its alpha) at the content's `MESH_POPUP_SCALE_UP_SPEED`, `MESH_POPUP_SCALE_DOWN_SPEED` and `SHIP_POPUP_SCALE_DOWN_SPEED`. A province panned out of view keeps its models, still animating, until its turn in the game's 100-frame off-screen cycle destroys them, so a quick pan back keeps the same entity and clock. (A model already shrinking past its cutoff, with unit arrows also hidden, survives that turn, as the game's early return keeps it.) A formation's hulls share one popup scale, its root's. Unit entities restart where the game recreates them ([presentation.rs](src/map/presentation.rs) `UnitRestart`), not by the rules above: a seek, step back, branch change or the first hour recreates all of them, a viewing-country change only those in the new country's provinces, and a recorded gap none. `--dump` and `--window-dump` settle model visibility for their camera, including at an explicitly supplied animation time; an F12 or Export capture shows the live history. Native capture-time entity phases and the existing stack/formation reconstruction limits remain unrecorded.

[mesh_budget.rs](src/map/mesh_budget.rs) shares the content's `MAX_MESHES_LOADED_PER_FRAME` allowance across buildings, hulls and land figures on that frame clock. Provinces update in ascending ID order, buildings in authored file order before each province's units, and hulls in formation-slot order. Held creations retry on later frames, with their own creation clocks; building replacements and support hulls disappear while held, and a formation's first hull keeps its old model. Skipped built hours carry building selectors and hysteresis, with creation waiting for a rendered frame. The native allowance is **not a hard total cap**: each province queues land against the counter before its hulls attach, and the deferred land pass creates every changed definition without rechecking. Land can therefore take the total above the define. Naval combat graphics, which the viewer does not draw, also attach hulls against it in the game. Dumps settle all admitted models, including with a zero interactive allowance.

Scheduling uses the existing reconstructed stack and formation targets: land visual-slot order comes from the route, with representative identity breaking ties where reconstruction has multiple stacks in one native slot; formations retain their existing stationary reconstruction order. Historical native slot ownership, roster reuse and parallel land-worker completion order remain unrecorded. The deterministic viewer request order does not recover native RNG ordering.

For offline diagnostics, `BATTLE_PLAN_VIEWER_MODEL_FRAMES=<count>` writes additional `*-model-frame-000.png` frames after the settled dump, restarting only model histories and advancing them at 120 Hz. `BATTLE_PLAN_VIEWER_BENCH_MODELS=1` makes the existing `BATTLE_PLAN_VIEWER_BENCH_FRAMES` run exercise live model histories after its settled PNG. These use the normal renderer and do not advance the recorded hour.

Recorded values remain exact. Do not interpolate recorded data between hourly samples: a moving division's counter and figure stand at the game's settled route point (one world unit along the route spline from the current province's anchor) all hour, as the game draws them. Effects whose seeds, phase or runtime state were not recorded must remain explicitly identified as reconstructions, not exact observations.

Show gaps, unavailable tables, wrong-viewpoint inputs and unsupported content honestly: in diagnostics mode and in the machine-readable outputs for agents. A carried background sample does not become fresh because the map renders another hour. New visible features may require new recorded operands; do not fabricate them in the renderer.

The main map is an HDR scene. World-space country names draw before post-processing; screen labels and counters are output overlays. Water samples a separate single-sample underwater target and blends over ordinary terrain. Preserve the target formats and pass/depth order in [scene.rs](src/map/scene.rs): changing a transparent pass can alter later layers even when its geometry is unchanged.

Keep coordinate conversions with their caller: bitmap rows run downward, world Z uses `height - 1 - row`, and height sampling has caller-specific half-texel offsets, clamping and rounding. Preserve native traversal and tie order rather than replacing them with an apparently equivalent sort or sampler.

Counter type icons use the recorded representative's roster and logical countries, faction/subject/war relations and the viewing country's ordered sent-volunteer references. [type_tint.rs](src/map/counters/type_tint.rs) holds the native predicates and precedence. The three colours come from the content stack's graphics defines; hidden question marks follow the same rule, and port hull icons keep their separate untinted path. The same decision picks the plate's allegiance colour (ours when the roster owner is the viewing country); counter grouping (1418BF940) and port plates (14197B4F0) are separate native rules this does not change. Missing inputs withhold detailed type icons, draw plates not our own as other, and name the limitation. Each hour resolves only the viewing country's referenced volunteers; the per-country index is rebuilt only when the relation tables, that host list or a country id's sign change, and a counter's lookup is constant-time.

### Compiled map shaders

Every map pass runs the content stack's own shader file through the shared [compiled pipeline](../shader-pipeline/README.md); vanilla and mods take the same path and no hand-ported map shader runs. [shader_sources.rs](src/map/shader_sources.rs) lists the passes and their effect files (the arrow and arrow-text effects come from `maparrows.txt`) and compares each pass's shader and recursive includes with the installed base game's bytes. Diagnostics and dump logs name and count the affected passes and the changed files, including additions, removals and unreadable sources; identical copies are not reported. Shader bytes are outside recorded hash coverage, so the audit does not certify a recording's vanilla source.

Each adapter binds what the engine binds for that draw, with the native address beside the code: the technique the engine or the content selects (the quality and reflection settings, `meshsettings`, `maparrows.txt`), the physical texture and sampler slots in the draw's positional order including null slots, per-stage constant buffers at their native allocation sizes, native vertex layouts and topologies, and the authored or engine-forced blend, depth, stencil and raster states. The engine writes constant buffers by offset rather than by member name, so a mod that changes a declaration still receives the native bytes ([shader_constants.rs](src/map/shader_constants.rs)). Read ranges come from the compiled program: a read of bytes the engine leaves uninitialised inside an allocation refuses the pass by stage, slot and range, while reads past the allocation return zero as in D3D11. [shader_scene.rs](src/map/shader_scene.rs) carries the renderer state later draws inherit (program, bindings, vertex streams), for example for particles whose technique the content omits. Vertex allocations are bound by handle, as in D3D11, so a ring's later append is what an earlier bind reads. Each frame's constants and repacked streams go through the scene's one upload arena ([shader-pipeline](../shader-pipeline/README.md)).

Three runtime shaders are the viewer's own, not game ports: the political fill compute (the game fills that texture on the CPU), the `--postfx off` copy, and the unpack of non-block-aligned BC artwork, which the hardware decodes into logical-size RGBA8 per face and mip. Fog, the viewing country and the layer toggles reach the game's shaders only through its own inputs (the intel and snow/mud textures, the selection colour, the graphics settings) or by skipping a pass.

A pass that cannot be built or bound (no DXC, or the wrong one, on a cache miss; a program that fails to compile; a slot or byte the engine does not supply) returns its named reason and the map frame is not drawn; there is no vanilla fallback.

Pass-specific rules:

- World draws complete each wrap view before the next (141268C60): terrain, land borders, rivers, railways, trees, water, sea and secondary borders, straits. Borders return their 32-byte selection/time/alpha block, which the later world draws retain; the 16-byte light grid stands in when no border draws. Underwater runs before the current shadow chain and samples the previous frame's shadow target.
- Terrain keeps the approved uniform LOD with native signed16 position and height streams, checkerboard indices and per-block constants. The retained stream the engine uses with `draw_hires_terrain` is unverified.
- Arrows bind the 128-byte arrow constants in four native modes: main before the entity passes, seethrough and late after the particles, and shadow in the caster pass. Late arrows keep their authored depth state with stencil reference and masks 2 and zero normal and shadow factors; each mode draws its admitted arrows' labels with the `arrowText` effect. Raid arrows share the plan's definition buckets. The head follows the authored head length, not the technique.
- Meshes share one adapter: native local geometry, source-order skin palettes, per-descriptor squared-distance LODs, material alpha-test and shadow selection, and the regular queue of every layer before the alternate queue. Trains always use the alternate queue and the optional `Alpha` variant. Parts with one program and state share a pipeline, resident geometry shares pooled vertex and index buffers, actor poses are computed once per frame, and a queue invocation's retained binds (which the particles inherit) are applied once after its draws, per slot as its last draw left them.
- Tree caster, receiver and lit draws share native camera visibility: four side planes, a 25.5-unit partition ceiling and one nearest surviving wrap view per partition, with the first view retained on ties. Tree casters do not use the model layer's expanded caster rectangle. Partition pitch is integer dimension/(dimension>>8); bitmap X/Z spacing is independent. Batches follow native palette/distance ordering, including equal-key permutations, and LOD selection compares squared thresholds until the first failure ([tree_order.rs](src/map/tree_order.rs), [trees.rs](src/map/trees.rs)).
- The map frame's ambient actors come from the complete descriptor roster with native placement height, scale and rotation, DLC predicates, bucket admission, spawn counters and lifetimes; meshless event actors emit their particles without invented geometry.
- Particles group packets by the native type registration ordinal; each actor submits ordinary packets before trails, and the ordinary instance ring keeps the native no-overwrite and discard behaviour: appends write the ring's written prefix and known ranges in place and a discard renames the allocation; neither copies nor uploads the ring's capacity.
- The scene uses a depth/stencil attachment and clears stencil to zero before the world draws, following the native D24S8 target and clear. Compiled mesh and arrow techniques supply their authored native stencil writers. wgpu's `Depth24PlusStencil8` permits backend-dependent depth precision; current replay checks cover the Vulkan adapter, not every backend.

Known limits, named in diagnostics where they apply: presentation history the recording does not hold (ambient activation, RNG and phase, particle populations, pre-observation motion and actor enqueue order, and the transient `CArrowObject` and `CAnimatedMapText` producers); the first-frame and resize contents of retained targets, which wgpu clears and the engine leaves uninitialised (dumps render a warm-up frame); the shadow light projection. Matched replay controls on vanilla and an offline Old World Blues content scene back the migration; they are not a blanket screenshot-parity claim.

## Fidelity limits

**Five-hour ETA operand staleness (accepted limitation).** The travel-time tooltip uses each division's latest recorded ETA operands with current movement/progress and shared hourly map data. Moving divisions refresh on a changed route/target/mode/location, on entering or leaving combat, on first observation, or on their stagger slot; unchanged operand rows can be four completed hours old. This allowance cites the native counter cache's five-hour TTL (`140be98e0`, hourly expiry `140bf0300`), but does not recreate that cache's UI-dependent history. The viewer's destination duration follows the stored route; the game's map counter can use a different pathfinding estimate (`140bed3a0`). Future or expired row provenance refuses the calculation.

Naval weapon totals and ship organisation bars require complete recorded ModifierDefinitions and LexicalTokens whose names match the shared fixed-key contract. Missing definitions or a patch-renumbered key suppress those calculations and produce a named combat diagnostic; the viewer checks the recording even if its recorder predates the guard.

A replay can preserve exact simulation values without preserving the native rendered instant. Water/global clocks, camera fades, overlap/stencil producers, particle populations and previous renderer state can require inputs that an hourly sample lacks. A seed alone does not recover their update history. Do not replace these omissions with guessed visibility, fabricated data or fitted colours.


Map text uses the configured user folder's game language (`settings.txt`), not the recording's. Text the game stored already localised without its key, such as a state's custom or owner name, is drawn only when that language is the recording's and refused by name otherwise (`dashboard::scripted_text::stored_text`, shared with the dashboard).

Land combat hovers ([tooltips.rs](src/combat/tooltips.rs), [division_tooltips.rs](src/combat/division_tooltips.rs), [commander_tooltips.rs](src/combat/commander_tooltips.rs)) are rebuilt from recorded operands, the content and the viewer's localisation. Modifier lines follow the native formatter ([modifier_text.rs](src/combat/modifier_text.rs)) over the recorded `ModifierDefinitions`, `LexicalTokens` and `SimulationFeatures` tables. Trait content is read as the game's reader reads it: its number scanner, file-local `@` variables, the sub-unit database order for `sub_unit_modifiers`, and the hash-table order of `custom_modifier_tooltip` keys. What cannot be rebuilt is refused, named and counted in diagnostics, never approximated:

- the reserve reinforcement hover's per-source lines for the country and the commander: the game labels them with localised names that its modifier trees store without a source identity;
- the default hover of a division invading from the sea whose landing progress the hour cannot rebuild (a route content cannot place, or missing movement rows);
- the default hover of a division whose template's recorded name is empty: the game then localises the template's name key for its country, which no table records;
- every trait's effects and the skill levels when a `common/unit_leader` file's reading cannot be followed (a block read by key that the port cannot settle): the unread rest could merge another body into any trait or add a level;
- trait text that is not UTF-8, a modifier name two recorded tokens fold to, and missing definition, dictionary or DLC tables;
- advisor unlock lines for ranks between specialist and genius;
- the skill progress and the learning-trait lines of a commander whose country link the hour's CountryLinks cannot resolve: the game shows them only for the viewing country's commander.

Modifier names, trait keys and sub-units that the game's own reader drops or reads as zero are treated the same way in the hover, and counted.

Planned follow-up layer, after the political layers merge: the reinforcement breakdown's per-source lines. It records each modifier source's identity and value in the order the game adds them: the sources of `CCountry::RecalculateModifiers` (1406CE2A0) for the country tree, and the leader rebuild (140C12A60, 140C12010) for the commander's.

Battle plans show the viewing country's own plan only: the game's allied-plan toggle is not recorded. Ribbons use the native fixed-point smoothing, control-point tessellation, terrain height and texture-side rules; the desktop shader includes terrain/water normals and the no-head shader's second shadow factor ([orders.rs](src/map/orders.rs), [arrow_shader.rs](src/map/arrow_shader.rs)). Army-group front child sections, the extra offset unit a bound front takes from its child count, and the transport count on long invasion and paradrop labels need operands no recording holds and are not drawn; offset fronts skip the game's intersection-tested resubmission. The limitations list states these when a plan is drawn.


Mixed-country plate flags are a known limitation. A land plate draws the flag of its first admitted division: `CUnitCounterItem::append_member` (`1418BE9E0`) stores the representative at `1418BED2C` only while the plate has none, and the coarse plate draws that division's roster owner through `1418C537F` -> `1418C7FC0`. Across provinces, which division comes first follows the same unrecorded source array and cursor (`14162E2C0`) as the column order. By owner decision (2026-09-28) the viewer keeps its deterministic cursor-0 order, so a plate that mixes nations can show a different nation's flag from the one the recording player saw, with the same members and count. This is expected. See the [selection rule](src/map/counters/land.rs).

The lead type also belongs to the first admitted representative (`1418C5862`): its fake-preferred template supplies the plain glyph, while disclosure permits its real template's custom picture. The supply crate uses the last fully visible member that is not in naval transfer (`1418C4B50`). Changing member order to arrival order can change either result; these are different selection rules, neither a majority nor a worst-supply reduction.

Counter flag owners follow the game per counter kind: coarse division, railway-gun and at-sea task-force plates show the representative's own owner, detailed ones its positive expeditionary owner if any. A port counter shared by several countries shows the one with the lowest total current ship strength ([port rule](src/map/counters/naval.rs)); with an incomplete Ships census the viewer withholds that flag and counts it in diagnostics.

Naval combat icons ([naval_markers.rs](src/map/counters/naval_markers.rs), [naval_combat_occurrences.rs](src/map/naval_combat_occurrences.rs)) are placed by the native direct and spillover passes (`14127C6B0`) from the recorded province combat vectors, transfer vectors and live transfer units, and stacked by their ordinal. Every engaged flag is the viewing country's, from the shared engaged index, and the progress widget's size counts engaged combats of every class in the combat province's vector. The recording also stores each naval side's engaged byte as the recording client held it; the engaged index also folds the derivation for the recording's own player (LocalPlayer's viewing choice, `+0x520` when positive, else the observer's `+0x524`; a change of it rebuilds every side for the new player only: a tag switch at once, so the sample that shows it holds the rebuilt flags, a view set by an `observe` (the client's own or another player's) or by `CSetCountryControllerCommand` at the next tick, which the fold takes one sample later; not followed are a controller given the newly viewed country in that interval and a side's own rebuild from a command after the view change in the same batch, which test the new view at once), serves it whenever the viewed country is that player (the client's combat icons keep their frames from the same history), and [combat/naval_check.rs](src/combat/naval_check.rs) compares its naval flags with the byte side by side and hour by hour. Agreements, mismatches (the first five named by branch, hour, combat and side; the counts are exact and the pass keeps no other mismatch), side-hours the derivation leaves ambiguous or unknown and sides without a byte are counted, with the coverage: hours folded and with naval sides, hours whose player the recording does not name, unreadable hours and blocks, and hours with an incomplete naval census; the diagnostics and map details show the counts over the hours the engaged index has folded, and `--dump` folds the whole recording and prints them with the first mismatches by id. Where the derivation is undecided, the byte settles the flag for the recording's player only, never for another viewing country. The naval combat window opens only for a combat engaged for the viewing country and refreshes only while it stays engaged; any other hour keeps the contents of the last engaged one (owner decision, 2026-09-27), and an hour whose flag is undecided or whose combat is absent says so in the window's diagnostics. Kept contents belong to the branch, choice and resolved viewing country they were read under and to later hours; without such contents a disengaged hour closes the window and an undecided one shows nothing. A convoy battle slot is a rebuild trigger only against the previous hour's observation: an hour whose participant census is incomplete may hide one, so the flag it holds must agree with the recorded lists. Retained result icons are built only from complete result, member and country tables, since every visible result of a province decides the sprite and frame. Placement, the member censuses, the HQ frames and each province's result icon are decided once per hour and perspective, reading only the units the hour's naval combats name from the key-sorted censuses; a camera change only places and draws them, and an hour without naval combat reads no unit census. The game keeps combat icons as client objects, erased only when their pass is off, the combat is gone or a side is empty, which the viewer rebuilds every hour and says in the diagnostics whenever such an icon is drawn. An unengaged combat's rotating icon keeps the frame of its last engaged update (`1418E3E30` sets it only while `1413CD880` holds), which the engaged index carries per combat as it carries the land icons' (owner option B): drawn and named as carried, or withheld with the index's reason. A spill-over icon, which is never rotated, shows its pooled icon's last frame (`140B63DB0`; `Release@1418E3C70` keeps the frame); the viewer draws the base frame and says so, until L5c2's persistent icon pool models it. The combat window's `bg_btn` and `frame_btn` are drawn only centred, unscaled and unrotated, and the result window's `bg_btn` only from the window's upper left, uncentred and unrotated; another authored form (which the game's own layout places) is refused by name, and each icon it leaves undrawn is counted, until L5c2 draws both windows through the native GUI layout. Every combat icon or part the hour omits or cannot decide is listed by cause with the combats it affects (`Naval combat icons: N undecided: cause; combats …`: a province without its Standstill anchor, a missing details or census row or table, a third recorded side, an undecided engaged flag, a stopped spillover pass, an unknown stack place, a refused layout child, an HQ frame's unresolved ship, task force or country, a progress bar's undecided size or side), and every omitted icon is counted; result icons the hour cannot decide or place (an undecided decision, a refused or undeclared result window, a province without its anchor) are counted by reason (`Naval result icons: …`); camera culling is not an omission. The window, the map details and the dump print the same lines.

Faction-theatre pins show the settled state. The game keeps a theatre's pin only while a province of its first strategic region is in the frame's update list; after a pan an off-camera province leaves that list within 100 rendered frames, or stays while a selected unit stands in it. The viewer draws the pin while a province of that region is camera-admitted, so it omits that brief lingering and the selection's, which no recording holds. Anchor, count, emblem, hidden set and priority are exact, from `FactionTheatres` and the content; [faction_pings.rs](src/map/counters/faction_pings.rs) cites the native functions.

The co-belligerent byte counter grouping reads (`CRelationStatus+0x310`) is derived from the recorded war and faction relations as `RebuildWartimeAllies` (`140D31E20`) builds it, not recorded: the stored matrix is country by country. Invasion routing reads the raw bytes recorded for its route unit's owner instead. **UNVERIFIED**: the byte can lag a same-hour relation change until the game's rebuild, and retired war relations still in an owned relation list would add parties the derivation omits.

The combat window's possible-tactics list ([combat/tactics.rs](src/combat/tactics.rs)) has no entry tooltips. The list itself is derived: side, candidate order, selection chances, the locked background (from the recorded `CountryTacticUnlocks` census and the content's tactic registry) and the `only_show_for` filter. The list, the tactic hovers and the tactic pictures share one read of the tactic file, `installed_content::combat_tactics`, and find a recorded tactic by its database ID and name through the registry's refusal checks. `has_trait` and the trait sprites read installed-content' one trait-name inventory, and `has_artillery_ratio` its one sub-unit database. A trigger key the tactic evaluator does not reproduce goes on as the game's `CTrigger::LoadKey` does ([combat/trigger_names.rs](src/combat/trigger_names.rs)): a coded trigger is refused, a scope key's block is checked in the scope `dashboard::scope` resolves, a building, resource or ideology count is read from the recorded hour (the building and ideology names come from the databases the document already loads, the resources from `ResourceDefinitions`; a resource count in a state scope is the state's amount from its recorded resource operands, which the shared trigger evaluator reads through the same code, [dashboard state_resources.rs](../dashboard/src/state_resources.rs)), an equipment category key is the share of the side's combat units whose recorded stat block mask (`LandCombatDivisions.categories`) meets the category, a scripted trigger's body is evaluated, and a key that names nothing adds no condition. Every trigger first checks its class's accepted scopes (vtable `+0x70`), and a scope it does not accept makes it false, as `CTrigger::Check` does. The game's per-entry tooltip, which explains a tactic's trigger conditions and why it is locked, comes from `CTacticsListEntry`'s tooltip provider (`141C5B520`), and it is not ported. The viewer doesn't show the selected-tactic tooltip in its place. The missing tooltips are listed among the data limitations.

Performance profiling uses environment variables. None of them costs anything when it is unset.

Measure complete views with the profiling above too, with no simultaneous builds and affinity set before startup.

Political gradients use [political_gpu.rs](src/map/political_gpu.rs) and [political_fill.wgsl](src/map/political_fill.wgsl). Hour workers retain compact region tables; only a displayed state updates the field. Province IDs upload once, packed into two 16-bit IDs per word when their range permits. Static pixel counts and province boxes stay on the CPU to update areas and form the indirect dispatch list. Changed province boxes include the native search halo and optimization range; colour or thickness changes also invalidate every province of that region. Updates diff against the fill state's previous tables, including after skips and seeks. Only a new fill state needs a full refill. The loader warms the static parts once per content and device: the province upload, the compiled kernel shared by both layers, and the strategic layer's output. It also allocates each map's first fill state, so the first hour allocates nothing on the frame path. A map draws no fill until its own first state is filled.

Each distinct displayed fill has its own country state and texture pair: 48,080,508 bytes on the default map (46,182,400 for the textures; the rest is boundary masks and tables). The dispatch scratch (packed output and distances, 23,248,896 bytes) is shared by every state of the map, and so is the strategic output. Copies reach only the cells a dispatch recomputed, so another state's bytes in the shared scratch are never copied. Maps with equal tables share one state, for example the same hour from another perspective. A map that alone shows its state updates it incrementally. When a map leaves a shared state, it moves to another state. A state no map shows any more is kept in a pool, at most one per live map. A map needing a new state reuses a pooled one before allocating, diffing from the tables that state last held. A map returning to a pooled fill takes the state back without a dispatch. So maps stepping through hours together alternate between two states with incremental updates. There are never more states than twice the maps, and all are released with the last map. Maps are created on loader threads, dropped on the dropper thread and shown on the UI thread. Finding, reusing, pooling and claiming a state therefore each happen under one registry lock, so no map can pick up a state another map is changing. Repeat frames dispatch nothing, whatever hours the other maps show. The region and lookup tables grow geometrically. An update that would exceed the adapter's storage limit is refused before it changes any state.

The shader preserves boundary scan order, the native search's early exit, coastal colour extension and vertical-then-horizontal integer truncation. Alpha lookups use the existing CPU f32 formula, with one retained lookup per active distinct thickness. Radii and lookup extents follow content defines and the searchable map extent, bounded by the adapter's storage/texture limits. Packed output bytes copy into the existing sRGB channels, including their existing layer layout; terrain shaders are unchanged. Compute-less/downlevel devices and unsupported dimensions or storage requirements return `UnsupportedPoliticalCompute`. There is no production CPU fallback. The original field and texture assembly are compiled only for tests.

The window, the dashboard maps and `--dump` choose their adapter the same way (`render::choose_adapter`). First they take the hardware adapter that `request_adapter` would pick at the `WGPU_POWER_PREF` preference (high performance by default). Only adapters that can run the map qualify: compute shaders, BC texture compression, `render::MAP_SAMPLED_TEXTURES` sampled textures per stage, and presenting to the window. If none qualifies, they fall back to the platform's software adapter, the one `force_fallback_adapter` selects: WARP on DirectX 12, lavapipe on Vulkan. A map drawn on the software adapter shows a notice over itself, in the window and on dashboard maps, and states it on stderr. The map is correct but slow. If the software adapter is also missing or cannot run the map, the viewer refuses with `UnsupportedPoliticalCompute`: a DirectX 12 or Vulkan graphics device is required.

The normal gate runs `political_gpu_fallback_exactness` on a forced fallback adapter (WARP/lavapipe), reporting a clean skip only when no fallback adapter can open the viewer's device with compute. It checks full/incremental and unchanged states, large mod-defined radii/reaches, and thousands of equal-thickness regions. Separate fallback tests cover two states dispatching through the shared scratch in one submission, and maps stepping together, which allocate nothing after warm-up and update incrementally. A further test covers each pool interleaving in both orders. The exactness test also checks maps on different hours, which dispatch nothing on repeat frames, and maps on equal fills, which share. It checks splits, joins and release, and the strategic layer every state copies. GPU test harnesses run one at a time, each taking a process-wide lock before it requests an adapter: several WARP devices used concurrently in one process fault inside `d3d10warp.dll`, while one device shared by several threads does not. The viewer creates one device per process: the window's, shared by its dashboard maps, or the `--dump` device. Larger hardware exactness sweeps are opt-in: `cargo test -p viewer --release political_gpu_ -- --ignored --nocapture --skip political_gpu_recording --test-threads=1` checks synthetic full and incremental updates. For recordings, set `BATTLE_PLAN_POLITICAL_REPLAY`, `BATTLE_PLAN_POLITICAL_GAME_DIR` and `BATTLE_PLAN_POLITICAL_USER_DIR`, then run `cargo test -p viewer --release political_gpu_recording -- --ignored --nocapture`. It resolves the recorded content, compares both channels at every available hour and alternates CPU/GPU execution order. `BATTLE_PLAN_VIEWER_GPU_PASSES` adds dispatch timestamps; `BATTLE_PLAN_POLITICAL_STEP=6` measures displayed states at 720 h/s and 120 frames/s after the exhaustive default run. Run timings without simultaneous builds; normal workspace tests also validate WGSL offline. The earlier unequal-span playback timings were confounded and do not establish a regression.

For local checks and the coordinated end-to-end smoke workflow, see [AGENTS.md](../../AGENTS.md) and the [recorder guide](../recorder/README.md). Embedded lifecycle/control belongs in [desktop](../desktop/README.md) and the [dashboard crate](../dashboard/README.md), not the renderer.

## Executable game shaders

[shader-pipeline](../shader-pipeline/README.md) provides the shared native effect compiler and disk/device caches. Vanilla and mod shaders use one compiler path; there is no filename whitelist in the core. Shipped desktop builds include DXC and its licences beside the viewer. The map's passes are described under [compiled map shaders](#compiled-map-shaders).

Naval invasion arrows use the native forced-transfer sea search through the raid movement world ([route selection](src/map/orders/invasion.rs), [search](../installed-content/src/unit_path/invasion.rs)). Source and destination ports resolve their stored port sea or first sea neighbour. The unit is the native one: the first assigned member, else the group's first member, else the request country's recorded first roster division; without one there is no route, even between ports on one sea. Costs read the recorded operands of that unit's owner (InvasionPreparations); a missing row, or an owner that differs from the viewer's unit, and unsupported content increment named invasion refusals. The route uses the last path province as its search destination and the first as its drawn landing; geometry wraps centroids and raw crossings before move smoothing.

The recorded perspective follows LocalPlayer at each hour, including an observer's selected country. A switch invalidates the same vision cache as other perspective inputs. Missing, partial, unselected or unresolved client references use the existing lowest-slot presentation fallback, identified in diagnostics; multiplayer participants are never used to guess the client.

Raid trigger evaluation imports [dashboard::triggers](../dashboard/src/triggers.rs), also used by scripted localisation. The map keeps its content facts and tooltip rendering; both consumers share the same recorded trigger decisions and named unknowns.
