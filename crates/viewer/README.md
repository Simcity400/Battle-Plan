# viewer

Native map, playback and image-export process for the desktop app. It resolves a recording's content and uses one wgpu renderer for the Campaign map, dashboard map widgets and headless exports. It has no interface of its own: the [desktop host](../desktop/README.md) starts it, owns every control, setting and timeline, and sends bounded commands to it. Started on its own, it runs only the tooling below.

Installation-dependent loading initializes `engine::executable_tables` from the configured game folder before reading settings or presentation content. Document workers and corpus runs validate their selected installation before consuming the shared tables. Executable metadata and shipped variable documentation remain in memory; recordings and disk caches contain no copies of these tables.

## Use and export

From the repository root:

```powershell
cargo build -p viewer --release
.\.cargo-target\release\viewer.exe --dump <campaign.battleplan> --hour <n> --branch <id> --out <frame.png> --camera <world-x,world-z,height>
```

Interactive maps open in the desktop app. The host passes its effective game/user folders on the viewer's command line and later changes as a `Folders` map action; the viewer saves nothing. Tooling defaults to the desktop app's saved folders (`APPDATA/battle-plan/content.json`) unless `--game-dir`/`--user-dir` name others. Select branches explicitly for overlapping hours. `--perspective <TAG>|recorded` chooses country; `--fog on|off` retains perspective; `--day-night on|off` and `--allied-plans on|off` choose those display switches (default on and off). See `--help`/[main.rs](src/main.rs).

`--free-camera <x,y,z,yaw,pitch[,roll[,fov[,near[,far]]]]>` replaces `--camera` with a free eye at world `(x, y, z)` turned by degrees, for dumps and window dumps of horizon and low views; `--free-overlays on|off` chooses whether it draws the map's interface, as the fly and walk modes' Overlays switch does (default off). `--window-dump --fly <x,y,z,yaw,pitch[,roll]>` instead flies the window's flying mode with its aircraft placed at world `(x, y, z)` and turned by degrees, seen through `--fly-view chase|nose`; `--fly-steer <turn,climb,throttle>` holds those controls (each -1 to 1, as the controller's left stick and triggers) and each frame `--window-frames` samples flies one `--animation-step`.

`--window-dump --walk <x,z,heading[,scale]>` draws the walking mode instead of a camera: the figure stands at world `(x, z)` facing `heading` degrees clockwise from north at `scale` (default 1), seen from behind. `--walk-keys` holds keys through every frame (`w`, `a`, `s`, `d`, `space`, `shift`, `ctrl`, `plus`, `minus`), `--walk-flying` starts in flight, and each captured frame moves the walk on by `--animation-step` seconds.

The camera moves by the game's law ([motion.rs](../viewer-foundation/src/map/camera/motion.rs)): edge scrolling (when `corner_scrolling` is on, within 2 pixels of the map's edge), the arrow keys, the wheel and Page Up/Page Down move a target camera, and the shown camera eases towards it. The content's `CAMERA_ZOOM_*` and `CAMERA_INTERPOLATION_SPEED` defines and the user's `scroll_speed`, `zoom_speed` and `camera_speed` supply the operands. The wheel acts on the map under the pointer. Keys and edge scrolling act on the focused map: the window must have the system's focus, and on the desktop dashboard the map must also be the one last pressed with a mouse button (Escape and Tab do not change that), so passing over another widget's border on the way somewhere does not pan it. Middle-button drag panning is a viewer addition the game does not have; it moves the shown camera at once, and the target with it. A fitted camera stays fitted until the camera actually moves.

*Match game* rasterises screen controls/text at game framebuffer/gui scale, then linearly stretches the completed image. Hit tests undo stretch; interface-pixel layout scales corners at upload. World names/geometry stay unscaled. [Unreadable display settings](../installed-content-settings/src/settings.rs) use 1.0 with warning. Dumps use game frame size/scale 1.0 unless `--ui-scale` overrides it.

### Diagnostics

Diagnostics default off. The host owns the choice: Ctrl+F3 in a map asks the host to toggle it (F3 alone selects the air map mode, as in the game), and the host sends the result to every map; `--diagnostics` enables one run. Hidden diagnostics build no frame text. Dumps, window dumps, host exports, `--counters-json` and on-demand `MapDetails` always report limitations, lazy uncovered reads and reachable counter-hover refusals; dump warnings use stderr.

Partial recordings play verified prefixes with always-visible failure status; only known failed hours become gaps. The host's diagnostics list recorded event losses (a same-process reattach) over the interval leading to their second read, whose recorded events are incomplete, and the gaps. Unavailable recording inputs remain distinct from zero/empty and refuse only dependent features.

Readable damaged recordings use the shared replay reader's warnings and gaps.
Trailer warnings remain visible in map diagnostics; unreadable blocks show gaps
through the existing playback path.

## Camera modes and controls

The full map draws through the game's look-at camera unless a controller orbits it or a free mode is chosen: by the host (`MapAction::CameraMode`: map, fly or walk) or by the map's own shortcut, F12 or the controller's View (Back, Share) button, which cycles map, fly and walk. No interface shortcut in the game's content binds F12, and the game reads no controller. The viewer reports every change of the mode or its overlay choice to its host (`NativeEvent::CameraMode`). Every map window has its own mode, the pop-out's included, and its own shortcut. A [free camera](../viewer-foundation/src/map/camera/pose.rs) keeps the game's world axes and conventions with its own heading, pitch, roll and lens. Its terrain is the content shader's block scheme by distance ([terrain.rs](../viewer-world/src/map/terrain.rs)) on every map copy its far plane reaches; province, model, tree and icon admission test its view volume out to the content's `DRAW_MAP_OBJECTS_CUTOFF`, the distance the game removes map objects at, while the content's height cutoffs for models and effects read the eye's height; its map icons stand in its world ([map icons in a free view](#map-icons-in-a-free-view)); picking walks the height cells along the cursor's ray and finds no ground above the horizon; shadows are fitted to its capped water-plane footprint as the game camera's are, and turn on and fade by eye height; and the content sky fills whatever the terrain leaves. The game's camera draws exactly as before.

[controls.rs](src/controls.rs) is the one input layer for keyboard, mouse and controllers. Frame time is wall-clock time, at most 0.1 s a frame, whatever the replay speed. Controllers are read by the desktop host and handed to the map whose window is in front ([desktop](../desktop/README.md)): Windows.Gaming.Input reports them only to the process owning the foreground window, which the map's child window never does. The host alone decides which map holds the controller, by the window in front (the map's own focus never touches it): a map taking it reads what is held without pressing anything, a map released lets go of everything without pressing anything and drops any state sent before its release or for a handoff it does not hold, and presses count against the last state read, so a button held through a handoff is never pressed twice. Xbox, PlayStation and other gamepads Windows recognises work alike. Sticks have an 18% radial dead zone, count as full at 95% and follow a 1.6 power curve; triggers have a 6% dead zone. Moves ease in and out over about a tenth of a second.

In map mode a controller [orbits](src/controls/orbit.rs) the game's camera. While the view is the game's own (no heading or tilt), the keyboard and mouse keep the game's law above, and a controller's move or zoom replaces the law's target. While it is turned or tilted, the arrow keys and edge scrolling move the map through the orbit as the left stick does, the middle-button drag keeps the ground point under the pointer, the wheel zooms keeping the point under the pointer, and Page Up/Page Down still set the height by the game's law.

| Controller | Action |
|---|---|
| Left stick | Move the map relative to the heading, at a pace set by the height; faster with the stick pressed in |
| Right stick | Turn around the point looked at (left/right); tilt towards the horizon or straight down (up/down) |
| Right / left trigger | Zoom in / out within the content's camera heights |
| Right stick press | Ease back to the game's north-up view, which then draws exactly as the game's camera |

In both free modes, click the map to look with the mouse; Escape or losing keyboard focus gives the pointer back and forgets held keys. The controller stays with the map until the host hands it on.

The map's interface is hidden in these modes unless the host's Overlays switch (`MapAction::CameraMode`'s `overlays`, off whenever a viewer starts and kept as the shortcut cycles the modes) shows it: borders, demilitarised zones and strait crossings, country names, battle plans with their labels and raid paths, the selected units' movement arrows, floating map text, and every map icon (counters, port stacks, bases, combat and raid icons, theatre pins and city labels). Hidden, they keep stepping and keep their state; only their drawing stops, and each also keeps its own display switch. Shown, the ground-draped layers draw in the world as they do for the game's camera, the icons stand in the world as below, hovers and tooltips follow the pointer while it is not held for looking around, a click on a map icon acts as on the map (a combat opens its window, a counter selects) and a click elsewhere takes the pointer. Escape first gives a held pointer back; another closes the battle window and clears the selection, as on the map. `--free-overlays on|off` makes the same choice for a dump or window dump from `--free-camera`, and for a window dump's placed `--walk` or `--fly` (default off).

Fly flies an aircraft ([flight.rs](src/controls/flight.rs)) in arcade fashion. The pilot points where to go and the aircraft follows, banking into its turns; it never stalls, never flying slower than its least speed. It goes where it is pointed, into the ground too; it never climbs past the content's `CAMERA_MAX_HEIGHT`, slides along the map's top and bottom edges and flies on round the world east and west; let go and it levels its wings and holds the pitch it was given. It can crash: every step sweeps its origin, nose, tail and wingtips (its model's bounding radius from its origin, along its attitude) along their paths against the drawn ground or water raised by the content's `NAirGfx.AIRPLANES_GROUND_COLLISION_OFFSET_Y`, exactly, testing each path where it crosses the surface's cell edges and diagonals, between which the surface is planar, so no speed carries it through a ridge or over a crest. Where it strikes, the controls stop and the camera holds where the chase view stood; the aircraft plays its entity's `explode` state and goes once its own player has played the content's `AIRPLANES_GROUND_EXPLOSION_TIME_DELAY` of it, read as the map's aircraft read it (the root's play position, at its clip's authored speed and start), or at once if it has no such state; an explosion is over, too, when the aircraft shown gives way to one without that state, or to none, before it has played. Once the explosion has gone, and at least two and a half seconds after the crash, it flies again level on the same heading at the same throttle, four clearances above the highest ground within its bounding radius of the next three seconds of flight, over the wreck when that height fits under the content's `CAMERA_MAX_HEIGHT`; otherwise at the vertex of the whole map nearest the wreck, across its east-west seam too, whose own footprint's height fits (the heading's side first on a tie), found in one pass over the footprint heights the map builds once for the aircraft's size; what it then flies into, it may crash into again. A map with no such vertex leaves the wreck where it lies, and the warnings say so. The chase view follows from behind and above, at a distance set by the model's size; the nose view looks out from the nose and banks with the aircraft, with no cockpit and no part of the aircraft drawn. A flight starts over the ground the map camera looks at, heading its way, each time the mode is chosen, and leaves the map camera where it was. The keyboard and mouse steer it while the map has keyboard focus, and the controller wherever the host routes it, focused or not; with neither it flies on as if let go.

The aircraft ([fly.rs](src/app/fly.rs)) is the one the user chose ([Fly aircraft](#fly-aircraft)); there is no default, so until one is chosen the flying mode is a free eye with no model. It is drawn as one [player model](../viewer-world/src/map/scene.rs) of the flying aircraft's kind: its entity in the idle state the game's flying aircraft play, with its attachments and authored animations such as turning propellers, lit and casting shadows wherever it flies, whatever the content's height and distance cutoffs and the unit and aircraft display switches. Its shadow fades with the eye's height at the content's `DRAW_SHADOWS_CUTOFF` as every other shadow does. A chosen aircraft that cannot be flown leaves the flight without a model, and the map's warnings say why, as they name ground defines that do not read.

| Action | Keyboard and mouse | Controller |
|---|---|---|
| Steer | Mouse while the map holds the pointer; A / D or Left / Right turn, Up / Down climb and dive | Left stick |
| Throttle up / down | W / S | Right / left trigger |
| Faster | Ctrl | South face button, or left stick pressed in |
| Look around (chase view) | C held, with the mouse | Right stick |
| Chase or nose view | V | North face button |

Walk puts the viewing country's infantry on the ground the view looks at, facing the way the view faces, and follows it from behind ([walker.rs](src/controls/walker.rs)). The figure is the entity the game's land ladder gives that country's infantry sub-unit: cosmetic tag, tag, graphical culture and bare name, the sub-unit's key and then its sprite, then the placeholder entity ([unit models](../viewer-world/src/map/unit_models.rs)). It is chosen again each hour and whenever the viewing country changes, and a figure that cannot be chosen is named in the diagnostics. The figure always draws, lit and casting shadows, whatever the unit layer's cutoffs and the map's display switches. It stands on the drawn triangle surface or the water above it, so it walks on seas and lakes, plays its entity's `move` state while it walks and `idle` otherwise, and turns to face where it walks.

Every length follows the figure's height times the user's scale, where scale 1 is the size the game draws its units: walking (one figure height a second), flying, falling, the view's distance and its near plane. The scale runs from one height-map step tall to where the figure and its farthest view reach the content's highest camera, and is kept while the mode is left. A double tap of Space flies as in a creative sandbox: the figure holds its height, Space and Shift rise and descend, descending onto the ground lands, and another double tap falls back to the ground under gravity. Flight stops rising where the figure and the view behind it reach the content's highest camera.

|---|---|---|
| Look around the figure | Mouse while the map holds the pointer | Right stick |
| Walk, relative to the view | W A S D | Left stick |
| Faster | Ctrl | Left stick pressed in |
| Start / stop flying | Space twice | South button (A, cross) twice |
| Rise / descend while flying | Space / Shift | South / east button (B, circle), or right / left trigger |
| Grow / shrink (doubling or halving each second) | + / - held | D-pad up / down held |
| View nearer / farther | Mouse wheel | Left / right bumper held |
| View from behind the figure again | | Right stick pressed in |

### Map icons in a free view

A free eye, and the game's camera while a controller orbits it, shows the map's icons standing at their anchors ([free_icons.rs](../viewer-foundation/src/map/free_icons.rs)). Every content rule that reads the camera's height for an icon reads that icon's distance from the eye instead: its kind's cutoff (`UNITS_ICONS_DISTANCE_CUTOFF`, the base, combat, mission, raid and city-label cutoffs), its counter grouping level (`MAP_ICONS_GROUP_CAM_DISTANCE`, `..._STATE_...`, `..._STRATEGIC_...`; an icon joins a group only at the lowest of its own and every member's level, and only if every member still shares the group's place there), coarse plates (`MAP_ICONS_COARSE_COUNTRY_GROUPING_DISTANCE`, per column; ports beyond it show empty boxes), a column's priority, its lift above the 3-D units and whether a selected unit splits from its group. Theatre pins, which have no cutoff, end at the eye's `DRAW_MAP_OBJECTS_CUTOFF`. An anchor behind the eye is not drawn.

Each icon keeps its screen size near the eye, shrinks gently to three fifths of it between a twentieth and three fifths of the object range, and fades out over the last fifth of its cutoff. The whole icon fades when the drawn terrain or water hides its anchor: one sight line from the eye to just above the anchor over the drawn triangle surface ([terrain_sight.rs](../viewer-foundation/src/map/terrain_sight.rs)), never per-pixel clipping, fading over a band below the surface that widens with distance so icons fade rather than pop as the eye moves. An icon below full opacity draws offscreen and blends in as one image, so its overlapping parts fade together ([sprites/fade.rs](../viewer-foundation/src/map/sprites/fade.rs)). Nearer icons draw over farther ones, and an anchor's icons keep the game's order among themselves; the combat window and tooltips stay screen interface above them. Floating map text stands the same way: at the screen size the game's camera gives it at half its cutoff, shrinking, fading and hidden like the icons. A city label's name fades by its own text cutoff and its dot by the dot's.

Hits follow what is drawn: the pointer is taken back into each shown icon's own layout, the nearest icon under it wins, and icons fainter than half opacity take no hits. Province hovers take the ray from the cursor into the terrain.

## Playback, threading and frame budgets

[map_checkpoints.rs](src/map_checkpoints.rs) supplies exact-hour `Current` values
to playback through dashboard-base's shared `prepared_map::Reader`. Seek restores the
nearest independent native checkpoint, then reads selected recording tables
through the target hour and applies fewer than 720 recorded updates. Source
parsing still begins at the source block's keyframe. An exact checkpoint needs
no source payload. Steps advance the native decoder in place; a needed source
load retains the rest of that accepted block for later steps. Only one parsed
source block remains between requests. No hourly updates or packet seeds are
stored in prepared data. Checkpoints retain availability, partial counts and
supplying-read hours. The selection is the union of native map inputs and the
shared authored-trigger operands, so mod-defined predicates keep their inputs.
Other tables remain explicitly unavailable. Header/gap searches run on disk;
source reads skip interleaved branches and stop at the accepted hour/block.
Targets after accepted preparation use ordinary playback.
Playback releases its previous local decoded output before advancing; externally
retained displayed hours remain immutable. Hour builders install the results
through the same displayed-hour and presentation path, retaining native routes,
clocks and seek intent. Cleared or corrupt prepared data uses ordinary playback.

The ignored `map_checkpoints::tests::measurement::checkpoint_disk_seek_measurement`
test measures growing prefixes in a release build. Set `BATTLE_PLAN_MAP_BENCH_REPLAY` to
the read-only long campaign, `BATTLE_PLAN_MAP_BENCH_PREFIX_HOURS` to increasing elapsed
hours such as `8760,43800,87600`, and `BATTLE_PLAN_MAP_BENCH_BURNIN_REPLAY` to the continuity
recording. Prefix hours include the first recorded hour and round up to a source
block boundary. Every prefix and the burn-in compare checkpoint strides 360, 720
and 1440. Set `BATTLE_PLAN_MAP_BENCH_EVIDENCE` outside Git, `LOCALAPPDATA` to a private
directory within it, and `BATTLE_PLAN_GAME_DIR` to the configured installation. Optional
`BATTLE_PLAN_MAP_BENCH_PROCESSOR_AFFINITY` is a decimal or hexadecimal Windows process
mask, applied before worker creation. The harness uses its runtime working
directory, so the same test binary can run from a shared measurement worktree.

Each row reports actual checkpoint-only Store bytes per 1,000 recorded hours,
checkpoint load times, empty/repeated/earlier-decoder seeks at 41 equally spaced
clock-hour targets per branch including the last 10%, every consecutive-hour
step and native update-application timings. Source block load stalls, selected
source parse time/frame counts and retained-block steps are reported separately.
Preparation, attribution and source reads stop at the accepted prefix. Whole
checkpoint and ordinary accept times are upper bounds including Store writes.
The production-stride candidate also compares the recording's own keyframes,
without prepared checkpoints, using sequential and parallel selected reads.
Its estimated Store bytes exclude the omitted checkpoint payloads and entries.

Completed prefix reports and `prefixes.jsonl` are synced before Store cleanup;
each completed stride is also saved in `partial-report.json`. Growth reports
include byte/byte-per-hour, timing and memory ratios, with dominant native tables
named in `table-checkpoints.csv`. Native row payloads are independently compressed
by table for attribution; their proportional shares of whole checkpoint bytes
are estimates. Recording section bytes are actual selected source sizes and are
not written to prepared storage. Private bytes are sampled every 10 ms within a
prefix; the Windows lifetime peak commit is separate. Memory includes attribution
and parity alternatives. A separate 438,000-hour projection supplements the real
prefix measurements; integrated dashboard acceptance measures the whole store.
Exact selected rows, availability, metrics and supplying hours are compared with
the ordinary replay decoder. Timings end at decoded `Current`; hour builders,
GPU work and presentation need their separate native checks.

Source loaders bind the host's committed lightweight map-progress page to the
shared decode worker; Campaign map decode lanes carry the same source context.
Requests beyond the known prepared prefix read newly committed progress without
starting preparation. Native widget source ownership comes from the host DTO;
its path and revision open/share the recording on one background source worker.
The host's source ID is echoed for ownership and lifecycle and is never looked
up as a viewer-local analytics lease. Engagement append inheritance checks input
and index/branch/session/gap metadata without rereading compressed block bytes.

[hours.rs](src/hours.rs) builds simulation layers off frames, with read-ahead Campaign map/source-shared widget decoding and one bounded pool per native root. Views cancel independently. [parallel.rs](../viewer-foundation/src/parallel.rs) preserves input order at process parallelism; raid batches borrow idle builder turns.

Playback keeps speed when builders lag. Show the playhead hour if ready, otherwise the newest built hour before it, all layers/date together. Finish in-flight hours at/before the playhead. Paused seeks, captures and exports await the exact hour. Coalescing preserves playing state/seek counter; hour distance cannot identify a seek.

[presentation.rs](../viewer-foundation/src/map/presentation.rs) separates continuity from unit recreation:

- Forward playback skips/paused catch-up preserve train/weather animation and advance building history over skipped hours.
- Explicit seeks (same-hour too), step back, branch changes and gaps reset continuity. Forward seeks preserve building history only over built hours. Country changes reset entity animation but preserve movement animators; camera/fog changes reset neither.
- `UnitRestart` recreates all on load/seek/step-back/branch change, only the new country's provinces on perspective changes, and none on a gap.

Equal layers share identity/skip uploads. Keep decoding, content/localisation reads, simulation joins and whole-map CPU rebuilds off frames. Builders/destruction run below UI priority, engagement refinement lower. Borrowed work runs at least at its waiting thread's priority. Completed-hour queues follow concurrency; `Dropper` bounds retirements and frees locally when full.

Heap-own dashboard renderers to protect the UI stack. Charge scene permits through cancelled builds/destruction. Share immutable content/sources; each view owns mutable history and follows the [upload-arena contract](../shader-pipeline/README.md#gpu-draw-contract).

Advance the shared [province schedule](../viewer-foundation/src/map/province_schedule.rs) before icon owners/rendering; models/buildings/counters share [admission](../viewer-foundation/src/map/province_admission.rs). Off-screen dirty provinces retain history until phased updates clear it. Present while transitions/dirty owners require frames.

[mesh_budget.rs](../viewer-world/src/map/mesh_budget.rs) shares the content's frame allowance in native province/building/formation order and retries held creations. Deferred land can exceed it; it is not a total cap. Popups change scale, not alpha. Dumps settle even at zero allowance; live exports retain history.

Raid offers keep their rolling cursor/content batch size, stale targets during playback and paused batches until current. The lane keeps shown/predecessor hours and presentation-reset/country stamps; install only matching results. Replace raid quads alone; parallel batches must equal row-order evaluation.

## Rendering rules

Preserve native camera, traversal/ties, assets, sampling/mips/colour spaces, constants, states and draw order. Never fit brightness/grading to hide missing terms. Content supplies map dimensions. Bitmap rows run down; world Z is `height - 1 - row`; height offsets/rounding/clamping belong to each caller.

Do not interpolate hourly simulation. Moving division counters/figures stand at the settled route point; progress drives arrows for the viewer's locally selected units. Movement shares content geometry; unavailable routes fall back to the province with a warning. A seed alone cannot recover runtime history.

The scene is HDR: world names precede post-processing; screen labels/counters are overlays. Water samples a single-sample underwater target. Finish world passes per wrap view; underwater precedes current shadows and reads their previous target. Preserve [scene formats](../viewer-world/src/map/scene.rs)/[pass dependencies](../viewer-world/src/map/scene_passes.rs): isolated failures skip dependent outputs/count once; interleaved-chain errors prevent submission/invalidate post caches.

### Compiled map shaders

Map/GUI effects compile recorded content through [shader-pipeline](../shader-pipeline/README.md), equally for vanilla/mods. [shader_sources.rs](../viewer-world/src/map/shader_sources.rs) owns selection and diagnostics. Viewer-authored shaders handle political compute, atlas quads, post-off copy and BC unpack.

Bind native slots/nulls, stage buffers/physical allocations, byte offsets, layouts/topologies and authored/forced states even when mod declarations change. Retain bindings across refused/missing-technique draws. Unknown in-allocation bytes refuse; reads beyond allocations are zero. Never invent padding.

Decode/globals share client `force_pow2_textures`. File textures retain padding/block extent/mips; generated textures retain size. Font UVs use loaded page extent. Preserve native precision/[colour spaces](../installed-content/README.md#asset-contracts). Adapters own arrow modes/labels, regular-before-alternate queues, tree visibility/ties and particle rings/order. Meshless actors still run state/attachment/particle/light/sound events; retain producer-selected states/clocks and count unsupported events.

Counter type atlases pack complete loaded strips. Each plain sprite retains its horizontal or vertical frame grid, loaded dimensions, native block rounding and fractional UV boundaries; drawable and hover geometry use that sprite's operands. Other sprite kinds are withheld with named, counted geometry refusals.

### Political fill and devices

Fill uses recorded controllers; ownership/control/vision/fog remain distinct. Derive selected-country fog from simulation. Recorded perspective follows LocalPlayer/observer selection; unresolved references use the diagnosed lowest-slot fallback, never guessed participants.

[political_gpu.rs](../viewer-world/src/map/political_gpu.rs) diffs worker-built tables against displayed state after skips/seeks; unchanged frames dispatch nothing. Loaders warm shared content/device static data. Equal fills share states; distinct fills use a bounded reusable pool. Claim/reuse/pool under the registry lock across loader/UI/dropper threads. Copy only recomputed scratch cells; reject storage-limit updates before mutation. Preserve native scan/early-exit/coastal/truncation rules and content search extents.

Political naval FX consumes the recorded native sorted supremacy cache, with control and gaining-side bytes derived for the viewing country. Timed acquisition certifies its native midnight cache epoch; unknown or crossed epochs withhold affected regions with named counts. Equal-current top/second candidates require identical output. Family precedes directed war; gaining neutral rows read the directed naval-blockade pointer from complete relation tuples, with Country0 refusal at that reached operand. Terrain minimums, thresholds and shader artwork resolve through the recorded content stack.

No production CPU fallback. [render::choose_adapter](src/render.rs) selects qualifying hardware at `WGPU_POWER_PREF`, then WARP/lavapipe with notice, equally for windows/widgets/dumps. Unsupported devices/dimensions return `UnsupportedPoliticalCompute`. Share one device per process; serialize GPU harness device creation to avoid concurrent WARP faults.

## Native GUI and hover ownership

Use native resources/byte-preserving names and one retained [Instance](../viewer-foundation/src/map/native_gui/lifecycle.rs) per window. The shared walk owns integer viewport layout, clipping, grids/scrollbars/reparenting and authored controls. Queried extents truncate; rasterised frames can stay fractional.

Hours hold ordered calls; frames apply them. Retain bits/writes/drawables/clocks until overwritten. Undefined/unchanged sprite names keep the drawable; replacement starts fresh clocks. Tick all related instances' clocks, reverse-registration transitions, then draws; present while `Instance::active` holds, including inherited shader clocks.

Pools belong to type/view, reusing state in native request/erase order; grid keys include pool/slot/place. Draw `Pool::visible` only, excluding erased fading icons/items. Refused updates retain membership/place but withhold draws until writes repair every unknown part; structural failures require reconstruction. Hide alone cannot repair unknown drawable state.

Producers own text/values, clipped geometry owns hits, and [ToolTip](../viewer-foundation/src/tooltip_painter.rs) owns wrapping/baking/placement/delay. Hit-test reverse paint/child order with transparent-text pass-through; pool order is not paint order. Disabled raid frames own hover. Combat windows precede map hits; map order is raid, land marker, naval marker, counter, province. New targets reset delay; same-province refresh preserves it.

Cache by content/frame/perspective/vision/settings. Raid text coalesces off-thread with same-icon carry. Use shared typed localisation/scripted-text evaluators. Acquire inline sprites from all loaded/runtime-selected text; absent declared artwork refuses layout. Count occurrences, keeping independent fragments.

Faction-pin highlights reuse the displayed hour's political regions and demilitarised zone. The [highlight lane](src/app/faction_highlight.rs) queues border plans on the hour builders and installs only results matching the current hour, perspective, border identity and hovered regions. Clearing or changing hover restores the prepared ordinary plans while the new highlight is pending.

In the Operatives map mode the province text is the game's [network section](../viewer-counter-products/src/map/province_tooltips/operatives.rs) alone. Province text covers the default political callback only, with fog-gated buildings and potentially empty stateless sea/lakes, and then appends the viewing country's [air region statistics](../viewer-counter-products/src/map/province_tooltips/air_region.rs) for the province's strategic region: the received-damage grids the strategic air view draws in its default state, ours and the enemy's, each item its tooltip key's first line and its value as the game writes it, from AirRegionCombat after the latest [daily prune](../replay/README.md#derived-on-playback) that visited the viewing country, which the hourly AirDailyRoster of the frame's branch decides: a lowest-priority worker reads the recording's blocks for it and wakes the window, and until it answers the hover shows no statistics, so drawing decodes nothing. The worker searches only the latest question, stops between block reads when a newer one or closing supersedes it, and keeps each distinct roster once however many samples repeat it. The native view draws them in its own panels, which the viewer does not have; a region without records adds nothing, and a recording without the table, a roster gap before the visiting pass, or a roster that changed within a pass's tick refuses them by name. [Picking](../viewer-foundation/src/map/province_pick.rs) uses native ray/height cells, not terrain triangles. Province local time/night read the record's clock: a held clock as recorded, an updated one derived for the row's hour from the recorded content ([replay derivation](../replay/README.md#derived-on-playback)); recordings without clocks derive only when the recorded suspension gates prove the update ran. Province temperatures are the recorded ones before format 102 and otherwise the [replay derivation](../replay/README.md#derived-on-playback) from the frame's anchor with the recorded content, which steps on from the last frame of the same anchor; a refused derivation refuses the temperature line. Other map modes/selection additions need inputs. Ordinary maps keep carrier wing stacks empty. Battle plans include the viewing country and, when the local Allied battle plans option is enabled, native admitted allied occurrences. Unit selection stays local: owned-counter clicks select, Shift-click toggles and Escape clears; branch or viewing-country changes clear it. Complete censuses retire missing handles while unavailable censuses retain selection. Selected province text uses current-hour route operands through [selected movement](../viewer-foundation/src/map/movement_reads/selected_common.rs), with named refusals for missing inputs. The native move-rejection search reads the recorded controller and owner areas (`Provinces.controller_area`, `.owner_area`, `.area_node`; an area's land count is its provinces with that label and its first land's nonsea index comes from the content), a selected army's exile from its DivisionStatus exile bit and its commander's retreat bans from the hour's DivisionRetreatBans, which the game reads live (recordings before format 102 refuse them by name). Its transport fallback answers the game's naval-base branches and refuses by name at the retired admission operands past them.

Snow/mud display takes retained edges and refresh operands from the recorded native boundary. Dirty refreshes preserve the previous plane and advance a local fade on presentation frames, including paused playback. Seeks, step backs, branch/perspective changes and gaps rebind the target snapshot; forward playback, camera and fog changes preserve phase. Historical absence and read refusal remain named gaps.

The selected transport line follows the [native law](../installed-content-unit-path/src/unit_path/selected/transport.rs) over what is recorded: a hovered province without a naval base, a selection with no army or railway gun, or one whose units stand at the target or in its controller area without a naval base has no transport fragment, and the game's naval-base rejections are exact. The stages before it and after it refuse by name, since the army's real-template coastal test, the transfer, convoys, sea route and risk are not recorded, so the line still refuses before access is reached; it never shows zero risk. Railway callers retain their own early returns and append laws.

## Map modes and the picker

A view's map mode chooses what each of the political fill's two channels shows, as the game's own per-mode layer pairs do ([map_mode.rs](../viewer-world/src/map/map_mode.rs)): the strategic regions with their naval effects, the country layer (political, or its factions, players or ideology variant), the mode's own layer, or nothing. Each region carries its colour's alpha as channel opacity, a pulse and a fill factor that widens or narrows the colour band; a layer moving between channels refills its whole field. The states (each state's live category colour, States `category`), resistance, compliance, manpower (each state's population over the content's range), infrastructure (each state's level over its maximum, [derived](../viewer-world/src/map/map_mode/infrastructure.rs) from the content, the state's live category and the controller's completed technologies), operatives and diplomacy layers draw from the hour's tables and the recorded content, with the viewing country as the selected country; the terrain layer ([terrain.rs](../viewer-world/src/map/map_mode/terrain.rs)) is the content alone: each province its own region in its terrain category's colour (water provinces their strategic region's naval terrain, else `ocean`) at the content's land or naval transparency, under the countries; diplomacy's war-goal test reads the selected country's owned war goals (Capitulation `war_goal_recipients`), and a recording without them refuses by name the countries below war and faction. The operatives layer colours each state of the viewing country's intelligence networks that the network's target controls by its recorded strength (IntelNetworks), in the content's quiet pair for a quiet subnetwork, and in that mode the province hover is the game's network section alone: the state's network strength, daily growth and strength cap with their parts, the quiet note, and the network's effects on both countries. In the terrain mode a province hover is the game's terrain text instead of the location text ([terrain_mode.rs](../viewer-combat/src/terrain_mode.rs)): a sea province's naval terrain text, a land or lake province's highlighted category, its land terrain text and its local effects, which describe the province's recorded weather modifier accumulator (`WeatherProvinces.modifiers`). Layers the viewer does not build leave their channel empty and are refused by name with the overlays their modes add: the air and navy region colours. The resources mode is the countries alone under each state's [resource icon](../viewer-world/src/map/resource_icons.rs). The raids mode has no layer of its own: the countries alone, with its raid icons and what it hides; the raid source stripes belong to the game's raid creation window. Scripted modes from `common/map_modes` resolve through the content stack, bottom layer in channel 1 and top in channel 2; a layer that hands over to one of the game's layers draws it. A `country`, `state` or `state_controller` layer runs its `color` script per target through the shared trigger evaluator ([colour_script.rs](../viewer-world/src/map/map_mode/colour_script.rs)): ROOT, THIS and PREV are the viewing country and FROM the target (for `state_controller`, FROM.FROM the portion's controller); the temps `red`, `green`, `blue` and `alpha` (clamped, unset reading 0), `highlighted` and, with `thickness = yes`, `thickness` (starting at 1, the region's fill factor at the country high thickness) colour the target's own region, and without it the region fills flat. A `targets` block selects countries as targeted decisions do. Each target's border is kept: a refresh clears it when its province list changed and recolours it only when the script holds with alpha above 0. Refreshes run on the first hour shown (a seek or open acts as the game's load) and, for `update_daily` modes, at each day's first hour, the political builder carrying the borders from the hour before. A trigger the evaluator cannot decide is refused by its name and counted per target, as is a `targets` block on a state layer and a state divided between controllers on a `state_controller` layer, whose controller grouping recordings lack; refreshes a script forces with `force_update_map_mode` mid-day are not recorded, so the next daily refresh catches up. `--map-mode <token>` opens a window or renders a dump in a mode (`default`, `states`, `factions`, ... or `scripted:<name>`).

Each mode also decides what the map shows of its other layers, as the game's renderers do ([visibility.rs](../viewer-world/src/map/map_mode/visibility.rs), carried as `viewer_foundation::map::mode_visibility::Visibility` on the view's `CounterView` and given to the scene): the `NMapIcons` priority table its icons sort by; unit counters (none in the resources and raids modes, only fleets whose first carrier has an air base in the air mode, none in the operatives mode apart from port counters, armies at half opacity in the navy mode, strategic country grouping in the air and navy modes); the raids mode's clearing of victory points, air and naval bases, combat and combat-result icons, land unit models and unit arrows, keeping capitals, facilities and naval headquarters; empty victory-point and capital names in the resources mode; raid icons only in the political, air, navy, operatives and raids modes, out to `RAID_MAP_ICON_MAX_DRAW_DISTANCE_IN_RAID_MAP_MODE` in the raids mode; naval mission icons hidden in the air and raids modes; state resource icons only in the resources mode, below `UNITS_ICONS_DISTANCE_CUTOFF`, their rows and flags below `RESOURCE_MAP_ICON_TEXT_CUTOFF`; faction pins only in the political, air and navy modes; the fog of war only in the political, navy, resistance, compliance and players modes; and province borders hidden in the resources, infrastructure and manpower modes. The navy, supply and resources modes add the viewed country's [trade-route lines](../viewer-world/src/map/trade_routes.rs), drawn by the battle-plan arrow manager with their convoys sailing among the unit models below `UNITS_DISTANCE_CUTOFF` while units are drawn, and each adjacency rule's [strait or canal icon](../viewer-world/src/map/adjacency_icons.rs) below `ADJACENCY_RULE_DISTANCE_CUTOFF`.

The game's picker (`MapmodesInterface_Ingame`) draws over embedded maps through the retained native GUI ([app/picker.rs](src/app/picker.rs), [viewer-combat picker](../viewer-combat/src/picker.rs)). The fourth large button follows the recording's runtime DLC mask. Slots start from the game's defaults; the content's configurable range reassigns on right-click through `WindowWithMapModeSlots` and `WindowWithAllMapModes`, whose default button restores them, and `mapmodes_all` lists every mode. Supply is offered disabled, its tooltip giving the reason: its province supply comes from the supply network's per-province sources and hourly hub amounts, which recordings do not hold. Each mode chooses whose names the map writes: the factions mode writes each faction's name across its members' connected areas (countries outside a faction keep theirs); the players mode writes each player's name on the country they hold, and other countries carry none (factions or players the recording cannot group write no names, refused by name); the air and navy modes write strategic region names, which are not drawn, so they carry none; every other stock mode writes the countries' names. These are the far names, shown at or above `NGraphics.DRAW_COUNTRY_NAMES_CUTOFF`; below it they fade out over a second and the near names fade in, which stock modes leave empty. A scripted mode writes its `far_text` far out and its `near_text` close in (`country`, `faction`, `player`, `state` for each state's name across its provinces, or `none`; an undeclared one writes none). The mode lists start at the content's `UI_CONFIGURABLE_SLOT_FROM` and grow a slot height upward for each scripted mode, their bottom edge fixed, as the game's do; they take no scrollbar, so the wheel does not move them. The authored shortcuts select slots and toggles, on the map that owns keyboard input (the one last pressed, or the hovered one before any is). The counter-colour toggle acts on the view; fog, day/night and allied plans ask the host to flip the setting, and it flips its own value, each click in order on its one write path (the view's fog switch, the campaign map's options, or the widget's map settings, which the dashboard service flips under the lock its saves take, so an edit or reset made meanwhile is what a click flips), so quick clicks each count; player-only counters acts on the view too, drawing only the counters on the viewing country's own roster (within the widget's counter filter); radar is disabled, since the viewer does not draw it. Each toggle shows the host's value as the host last applied it, with nothing pending in the view, so it can lag a click by one round trip but never stays wrong. The picker owns only the map mode and slots: a change goes to the host in `MapOptions` (the campaign map's under `campaign-map`, returning in its Configure options), and the view keeps its choice until the host's options carry it back. `pickerHidden` hides the picker for the map-only window; its keys keep working.

## Fidelity limits

- The game's camera draws terrain on a deliberately uniform full-resolution grid, differing from native distant-coast LOD; free cameras use the content's block LOD by distance.
- Interface text holding the 0x14 or 0x1A control refuses by name: the game draws them from a per-font sprite table it allocates but never fills, so their pixels are undefined. Map names and order labels read 0x14 as a codepoint without a glyph, as the game's map glyph runs do; a country name's fit still counts the 16 pixels the text measure gives it.
- Map text uses configured game language. Stored localised bytes without keys require recording-language agreement; proven literals follow the shared stored-text rule.
- Division arrival times are [estimates](../viewer-foundation/src/movement_timing.rs): the native walk over the recorded route, each edge at the native land speed ([eta_derive](../replay-derive/src/eta_derive.rs)) of the recorded base speed times the common modifier plus the edge's terms, then the organisation and fuel factors, the native 1 km/h floor and the content's movement scale. The common modifier adds the owner's (expeditionary, else roster) country army speed and, for a hostile move (the recorded route ends at a province controlled by a country the logical owner is at war with), attack speed; the selected commander block's army speed (DivisionStatus.commander_modifiers); the location's province and region weather speed and, for a hostile move, attack speed entries times the acclimatization factor; the out-of-supply term (the received ratio and remaining grace, exact for a division with days out of supply (DivisionStatus.supply_ratio_exact and supply_grace_exact), whose penalty alone reads them; days out of supply, the country's and commander block's out-of-supply factors and the recorded defines; an exiled division bypasses it); the enemy air term where the logical owner holds a war relation (the owner's RaidAirScores pair and movement impact over the location's strategic region, the air speed define and the stat block's anti-air reduction, never above zero); and a retreating division's retreat terms or a withdrawing one's withdrawal term. Each edge adds the stat block's terrain movement and the terrain's own adjuster movement, its fort movement into a fortified province and its snow movement into snow, the direct commander's terrain movement, the destination state's infrastructure term and, across a crossing, the river terms with the commander block's river crossing factor. The organisation factor is the low-organisation slowdown of a hostile move from the organisation and maximum at their display steps; the fuel factor the recorded fuel over the stat block's capacity. Every modifier entry takes its recorded definition and the DLC feature mask. A division with a commander whose template's priority sub-unit (DivisionTemplateIcons) has the content's `armor` type takes the country's and commander block's armour speed, and the special-forces out-of-supply factors apply at the template's special-forces share (its recorded composition with the content's sub-unit `special_forces`). A strategic redeployment that no disable-redeployment modifier blocks (DivisionMovement.strategic_action) moves at the larger of the road speed over the destination state's `railway_infrastructure` and the rail speed over the departure province's directed railway percentage (RailCooldowns, RailEdges), under the content's strategic speed defines and the outer scale; a blocked one moves at the ordinary speed. Land edges past a landing move at the content's invasion speed. They omit the location state's speed modifiers, the template's priority sub-unit category speed terms, the noncore-supply term (shown nowhere when the recorded bypass byte is set) and a relation's `river_crossing_factor_against`, whose operands are not recorded, so they drift from the game wherever those apply. A division in combat that is not withdrawing refuses its estimate by name: the combat's movement factor replaces the modifier's one and is not recorded. So does a naval transfer or a route edge to or from the sea, which moves at the owner's transport speed, not recorded since the selected transport preview retired. A missing operand of an applied term refuses the estimate by name; progress and arrows remain. Selected travel times the native route search's result the same way. Railway guns keep fresh current-hour native route queries; a sea-crossing or naval-transfer leg moves at the gun's logical owner's recorded transport speed in the leg's source strategic region (OwnerTransportSpeeds, recorded for the regions the owner's guns stand in or route through), and a leg whose speed was refused, or lies in a region off those paths, refuses the duration by name. The duration follows a route searched afresh to the endpoint, which can cross a region the stored paths do not (a selected destination, or the counter's own endpoint once conditions changed since the gun's path was stored). Task forces walk their stored route at native per-region speeds; their prospective travel refuses because route admission inputs are not recorded. The native client counter cache remains unrecorded. Counter hovers append no date.
- Recordings store drifting values at the precision the game shows them ([display steps](../replay-data/src/display.rs)): division organisation and strength, supply ratio and grace (exact beside the steps for a division with days out of supply), the unit supply footers' amounts, the land combat window's stats, scales and modifier values, the CAS hover's prevented damage, combat commanders' skill and learning-trait progress, and naval combat organisation and escape progress. Values the game prints directly read the same; derived displays (combat progress, strength shares and bars, stat boxes, damage estimates and the heading built from them, and the CAS hover's enemy strength and organisation totals) can differ from the game in their last digit at boundaries.
- Counter attrition hovers show the counter's cached hourly total (the game evaluates it afresh) and the lines the division attrition calculation writes whose operands are recorded: upkeep, the route province's terrain, the out-of-supply line (the exact received ratio and grace of a division with days out of supply normalized by the army attrition supply threshold, days out of supply, the country's and selected commander block's out-of-supply factors, the special-forces factors at the template's special-forces share and the recorded out-of-supply attrition define), training and border war ([attrition.rs](../viewer-counter-products/src/map/counter_tooltips/attrition.rs)); a moving unit's weather, heat and winter lines are absent where its province's recorded weather entries write none. Its equipment, state, moving-state and modifier-source lines, and the weather lines' source trees where they appear, refuse by name, as does a supply line whose special-forces factor applies to a template whose composition was unreadable when recorded. A division counter's supply child adds no footer: the hover's supply status line is its total, without the consumer breakdown (demand, receipts by source and hub, air drops, disruption) that railway-gun and task-force supply children keep. The selected-army hover shows the blocked-strait notice without attack-modifier previews. The selected-army hover's attack modifiers are the [replay derivation](../replay/README.md#derived-on-playback) against the retained route's last move; an entry whose operand is missing is refused by name and counted while the others stay.
- A counter's supply child appends the native [supply footer](../viewer-counter-products/src/map/counter_tooltips/supply.rs) (demand, receipts by state and hub, air drops, flow reduction, disruption) for divisions, railway guns and task forces. A footer sums its members' recorded hundredths, so a footer over several units, its received and flow-reduction percentages, the order of hubs whose receipts print equal and the 0.05 hub cut-off can differ from the game at boundaries. Recordings without the division footer refuse it by name.
- Hover parts whose per-operand breakdowns or operands are not recorded refuse by name and are counted; the window and counter values beside them remain. The [combat guide](../viewer-combat/src/README.md) lists the combat hovers; the naval positioning, screening-correction, escape and carrier-sortie source lines read the recorded source trees, whose stored labels show in another language only through the keys that render to them. A port counter's strike-force status keeps its in-combat, not-ready, engagement, aggression-rule and intel arms; the readiness arms that weigh ships' strike words refuse.
- Cursor-zero counter columns can differ from the client's ordering/mixed-country flags. Preserve recorded members and native first/last representative rules.
- Engagement keeps native lag through the shared index. Pending/ambiguous history stays diagnosed; recorded naval bytes settle only the recording player's view. Naval windows refresh only while engaged and otherwise retain compatible earlier contents. Unseen frames use view/index history, then land authored/naval binding initial values with counted reasons; fallback establishes no history.
- Presentation history follows the game's laws but is not the captured instant. Ambient actors, weather and entity-event particles, entity lights, and unit, building, train and aircraft animation phases run on the viewer's clocks from fixed seeds, with the content's producers, assets, counts, durations and timelines; the game's wall-clock random draws and process clocks are not recorded. A fresh post chain takes its first adaptation value at once, the underwater pass's first previous shadow target is clear, and shadows are projected for the viewer's camera. What plays is exact where the recording decides it: ambient kinds and placements, weather regions, unit and building states, flights and their paired outcomes, train routes, and nuclear impacts, whose type's effect entity plays at the province's standstill anchor from when the impact's hour is presented, because the instant within the hour is not recorded, and critical shore bombardments, which play the game's small missile explosion entity the same way. Missile bombing scenarios fly from the recorded base-equipment wings (the game's client-side missile air scenarios, scheduled after scouts with `MISSILES_DIVISION_FACTOR` and `MAX_MISSILE_BOMBING_SCENARIOS`) to their mission's last target, and each that finishes plays the content's `missile_explosion_entity` in that province's effect slot on the aircraft clock; A bit-17 mission (while the other side holds aircraft) or a launch-flagged definition starts a launch effect at its base instead: a base holds one live record over every region, and the record spawns the wing's primary equipment type's `<token>_entity` in its default state after a `RANDOM_SCENARIO_ANIMATION_MAX_DELAY` draw (a negative define reads as zero), turned by a whole-turn draw, at the base's position, until its root reads its clip's length; a launch-flagged record then plays `missile_explosion_entity` in a drawn province of its mission's strategic region. The next record comes on the first two-second regional pass after that. A name no entity declares starts no record (counted). Every state base stands, and its flights take off, where the game's base position finder puts it: the finder walks the provinces the state lists for the base's kind and takes the first admitted slot that matches: for a rocket site or gun emplacement one in the explicit bucket a `rocket_launch_capacity` or `gun_emplacement` type binds as its `spawn_point` (a type without one matches nothing), for an ordinary air base one whose own type is an `air_base = yes` one; every province with an admitted slot whose bucket holds an `air_base = yes`, `rocket_launch_capacity` or `gun_emplacement` type owns an air-base, rocket-site or gun-emplacement icon, shown while its state holds a recorded base of that kind, whichever such type raised it; it stands on the province's first slot in the first bucket of that kind's queue that the province holds a slot of (the kind's types' own buckets in database order, then the explicit buckets their `spawn_point`s bind to), and otherwise on its unit-stack slot 0. Each icon reads its own state base: a rocket site's or gun emplacement's buttons show frame 3, disabled, without the viewer's access, and otherwise frame 2 while the site holds a wing and frame 1 when it is empty. A province whose recorded strategic locations (its own, then its state's anchored on it, each in stored order) are not empty shows a `strategic_location_mapicon` at its victory-point anchor below `AIRBASE_ICON_DISTANCE_CUTOFF`, its button taking `GFX_strategic_location_<first location>` where the content defines that sprite and keeping the window's retained sprite otherwise (initially the authored one). Only a state's locations anchored in its own provinces count. In a live session the game's state appender also marks a foreign anchor's province directly, so that province shows the icon with the window's retained sprite (initially the authored one; a recycled window keeps its previous occupant's) until a load recomputes the marker through the province's state; the recording does not carry the marker, so the viewer follows the post-load rule and misses that icon for pairs added live. As the game's icon keeps the list it gathered when it was made, the viewer's icon keeps its first location for as long as its window lives: until the province leaves the cutoff, the map mode or the screen and the window is released. Across a seek the game's icon history is not recorded, so the viewer keeps its own window's choice. A province with an admitted slot whose bucket holds a `radar` type owns a radar icon, placed by the same queue over the radar types, drawn below `RADAR_ICON_DISTANCE_CUTOFF` with priority zero (the game's priority tables leave it zero) while the viewing country, a member of its faction, a direct subject or its direct overlord keeps a recorded radar group hosted in the state and the state's controller keeps one there. A slot the game does not admit is ignored; an admitted slot naming a building declared more than once differently is refused by name only where it could change a base's or icon's place. Types are resolved through the content, whatever a mod names them. Each frame an aircraft's drawn transform eases toward its pose as the game's does (`AIRPLANES_SMOOTH_INTERPOLATION_MOVE` and `_TURN` per elapsed 30 Hz frame, the turn scaled by the clock's speed), starting a new cycle on its take-off route's first point and carrying over to the next hour's plan; the band reads the pose. The game draws the delay, heading and province from unrecorded wall-clock state; the viewer draws the delay once per launch and the heading and province per record from fixed seeds. The scenario's rocket rides the rig's `rocket` attachment node. Like every slot the game gives no landing route (the rocket, kamikaze fighters that succeed, the defending slots of a successful interception or dogfight and the attacking slots of a lost dogfight), it meets the near-ground band through the rig: the rocket is done at or below the terrain; at or below the terrain plus `AIRPLANES_GROUND_COLLISION_OFFSET_Y` an actor plays its entity's `explode` state where it is and is hidden once that has played `AIRPLANES_GROUND_EXPLOSION_TIME_DELAY`, or, without that state, is hidden at once. A scenario whose actors are all done in one frame ends there without a landing; otherwise those actors are hidden for it. Anchors, route minimum heights and the band sample the terrain with the game's clamped bilinear sampler. Vanilla's v2 rocket mesh, like every mod in the corpus, has no `rocket` node; the game logs that and the rocket rides the scenario entity's root, so it flies from its base to the target at `NAirGfx.ROCKET_SPEED`, lands on the terrain there and explodes as the rig starts. Missing `MISSILES_DIVISION_FACTOR`, `MAX_MISSILE_BOMBING_SCENARIOS` or a zero factor omit only base-equipment wings (counted); a missing `ROCKET_SPEED` refuses only a rootless rocket rig, and missing band defines only rigs with a slot that does not land. The band is tested at the viewer's own frames on the pose each actor draws, hidden missions included, as the game tests it at its frames; the explosion's delay is read from the actor's own player, which keeps reading its previous clip when `explode` plays no animation, and a cycle that ends early starts its next take-off on that frame. A scenario rig of any kind whose mesh or animation file does not read is refused by name and its flights are counted; the map still opens. The explosion stands on the province's standstill anchor, as a nuclear impact's does, while the rocket lands at the scenario's integer centroid, as in the game.
- Floating map text plays the game's animated text for the recorded map events (fake division reveals, railway gun overruns, critical shore bombardments, general captures, paradrop landings, resistance activities and building damage): each event is admitted for the viewing country by the game's own local filter, reconstructed from the hour's recorded relations, fog, intel and modifiers; its text is localised through the recorded content stack and drawn with the content's text type, font, colour, speed and the game's rise-and-fade transform in the province's queue. The hour builders interpret each hour's events for the viewing country (admission, localisation and explosion placement); presenting an hour only queues them, each recorded event once, including one a later interval lists because it was in flight at its cut. An event's instant within its hour is not recorded, so its text starts when its hour is presented; continuing playback also starts the events of hours a forward skip passed, and a seek, step back, branch change or viewing-country change starts the queues again. Toggling fog keeps what was presented; a failed hour retried at the same hour presents nothing twice. Intervals with incomplete coverage are named in the diagnostics, and the events they hold still show. A no-pair land model whose fallback rows name different entities takes the second row of the game's labelled option list, built in the display language from the recorded variant names and country tags; a label that cannot be built refuses that figure by name. Warm-up/settling does not recover a captured game instant; consult producer refusals.

## Campaign appearance

Every map choice resolves on its own HOI4 -> global -> campaign -> widget ([map_display.rs](../dashboard-core/src/map_display.rs)): a scope stores only the choices it overrides, and each unset choice takes its parent's resolved value, so changing one leaves the others inheriting. The HOI4 level is the game's own value where `settings.txt` stores one (the map-rendering options, `multi_sampling`, `template_counter`, `hide_daynight_cycle`, `show_allied_plans` and the master, ambient, sound-effect and voice volumes), else the default. Null visual mods inherit independently, and the root shows none. Read game settings on source-open/settings jobs, never per frame; failures keep last values with diagnostics. The host tells the viewer when it saves settings, and the viewer reads them again.

Visual mods are any installed mods the user selects, mounted in the engine's order above the verified recorded stack as its [presentation stack](../installed-content/README.md#visual-mods). The document load ([document.rs](src/document.rs)) hands the presentation stack to every artwork loader, each through `ResolvedLayers::artwork` so a loader the mods break loads from the recording instead, by name: map textures (the world normal map too), map shaders and post-processing ([map_assets.rs](src/map_assets.rs)), the shader source audit, borders, rivers, railways, map icons, counters' sprites and interface windows with their fonts, the map frame, map names and their localisation, unit, aircraft, train, bridge, building and tree models with their entities, weather particles and order arrows. Each map effect a mod replaces is used only when every technique the recorded effect compiles also compiles from the mod's sources; otherwise the recorded effect is drawn and named ([shader-pipeline](../shader-pipeline/README.md)); the same holds for each variant, and every pass and native draw that cannot build a pipeline from the replacement builds it from the recorded effect instead, named. Every model library baked from visual mods bakes an entity the mods break from the recording instead, named, and keeps each mod entity's recorded counterpart, baked from the recording's own files apart from the mod's and drawn with the recording's own shaders (`ModelLibrary::alternatives`); a mod entity whose draw is refused is drawn from it from the next frame, named. As a backstop that relies on no knowledge of what the mods replaced, one owner decides every map's visual mod fallback ([visual_fallback.rs](src/visual_fallback.rs)), shared by the Campaign map and the dashboard's maps. A decision is keyed exactly by the recording and the revision its visual mods held, and never applies outside that key: another recording, or a mod updated since, shows the mods. It is `Probing` (without the mods while the recording alone shows whether it refuses the same), `Confirmed` (without them: it did not) or `Restored` (with them, the recording's own refusals excused). Content records the key and what it was built under, and is shown, lent and reused only while that is what its key holds. Each frame, every map reports what it refused, by stable name (a native draw by its label, effect file and technique, a model by its pass and entity, a world pass by name, a GUI draw by its quad, effect and technique, early refusals included; compiler output names its scratch folder the same way on every run), its frame's own failure, what its content's loaders refused to draw (a model entity no descriptor decides, `ResolvedLayers::note_refused`), and whether it drew settled: by the viewer's own render result, the hour the playhead asks for drawn this frame, built without error, with no lazy icon queued or decoding. The owner reduces a frame's reports in one place, whatever order the maps sent them in. Content with the mods that refused anything not excused probes without them, needing as many settled frames as it drew; content without them adds what it refuses to what its key has seen, and the moment that includes every failure, the mods return with them excused, before anything else is decided; otherwise a probe that has drawn its frames is confirmed, still watched, so the recording refusing the failure later brings the mods back. A scene that cannot be built with the mods probes without them, as often as it takes, and is an error only when it cannot be built without them either. A dashboard map never installs a scene built from content its source has dropped. A load whose visual mods changed while it ran loads again, and a Refresh that arrives while any map loads checks the maps again once every load is installed (`DeferredCheck`), so what is shown is what the mods hold. Inside a loader, an item the mods break is read from the recorded layers below them, named (`ResolvedLayers::artwork_item` and its kin): a tree kind, a battle-plan arrow page, an aircraft scenario rig, an interface, counter, portrait, flag or movement-arrow texture (`resources::stack_texture_or_recorded`), a font file or font page, a model or naval formation animation, a descriptor file or an interface sprite file that does not read (the recording's file of that path), and the unit model layer itself when the mods' content (their naval combat formations) breaks it. One neither stack gives is refused by a stable name (`tree kind 3`, `arrowType <name>`, `aircraft scenario <entity>`, `model layer: unit models`) for the owner. An entity a visual mod's unreadable descriptor leaves undecided, though the recording declares it, is drawn from the recording (`ModelLibrary::load_recorded`), for unit models, aircraft and city sprawl alike; city sprawl, rivers and railways load their artwork through the artwork fallback, their placement recorded. So a broken mod never leaves a recording unviewable. A font or unit model the mods supply that does not load, or fonts that leave no bitmapfont declared, is a refusal too: the recorded one is drawn, never no text or no model. Every artwork consumer reads the graphics defines: the recorded defines with the graphics sections (`NGraphics`, `NAirGfx`, `NInterface`, `NFrontend`, `NMapMode`, `NMapIcons`) of the defines merged with the mods' scripts (`Defines::with_graphics_of`), so camera zoom and motion, counters and their cutoffs, the combat window, raids, railways, aircraft, arrows, map text and every other loader honour a graphics value a mod sets, while every simulation section stays recorded for every consumer. A graphics value the mods give in another type than the recording's keeps the recorded one, named; a loader that cannot use what they give falls back to the recorded defines by name (`map_assets::graphics_define`, `ResolvedLayers::graphics_define`, or the loader's own artwork fallback), and a mod's scripts that cannot run fall back to them whole, named. Unit models the mods' defines cannot load load with the recorded ones (`UnitModelAssets::load`). Because a mod shows only under artwork roots, scripts, history and the bitmaps that place provinces, terrain, heights, rivers and trees stay recorded whichever stack a loader gets, so a mod's map changes never move anything; the analytics views keep the recorded content. Artwork painted for another map (a colour map, tree tint) is stretched over the recorded one and can misalign; that is expected. A mod file the loader refuses, or one the upload would refuse in the colour space it is drawn in (faces, non-square cube faces, a format without that colour space, an empty extent), is drawn from the recording instead and named. Device size limits remain upload failures, as they are in the game. Counter building icons admit their slots by the entities the presentation stack registers, as the building layer draws them. Renderers key maps by the set of chosen mods, so equivalent choices share one load. Each loaded map keeps the revision of what its mods held (`Content::visual_revision`). Saving map preferences or pressing Refresh checks every open map's mods off the UI thread, and reloads only the maps whose mods were installed, updated or removed since they loaded: the Campaign map reopens at its branch, hour and camera while the host's clock keeps playing it, and dashboard maps reload in place, never reusing content loaded with the stale revision. A Campaign map found stale while a load runs reloads after it, unless that load mounted the current files; a map loaded again since the check is kept. Any non-empty selection has a revision, including one none of whose mods can be shown, so such a map is not reloaded again. Each check's outcome is a named line in the map details, and visual mod lines lead that report so its size budget never drops them. Mounted mods and every one that cannot be mounted are named in the load warnings, and the files each mod supplied are counted with the read diagnostics.

Show/hide switches gate drawing only: simulation, hover and picking, selection, combat windows, engagement, presentation clocks and the other layers carry on, and a hidden world object stops casting its shadow without changing anyone else's. Everything a frame advances (model histories and placements, train and aircraft plans with their random streams, strikes, map-frame actors, movement arrows and world text) is stepped in one place that reads no switch except to mark placed actors hidden, so a hidden layer shows again exactly as if it had never been hidden. The weather switch is the one exception, as in the game, whose weather update rereads `draw_weather_effects` each time: turning weather off releases its particle pairs, and turning it back on builds new ones from a freshly seeded random stream. Each item has a main switch; its parts (border kinds, rails, bridges and trains, unit figures and aircraft by mission, counter and icon kinds, battle-plan families and labels) draw only while the main switch is on too. Hidden borders, demilitarised zones, straits and selected movement arrows still leave the passes after them the inputs they retain. A demilitarised zone splits its edges out of the ordinary border buckets, so while the zone display is hidden its edges draw as the ordinary land borders they are (no highlight, the class fade), and not at all while land borders are hidden; the faction hover outline is interaction feedback and keeps drawing. The counter filter also covers ships in port, by their task force's owner. The map table, nuclear impacts, critical bombardment explosions and missile explosions share one pass, each kind with its own switch: a hidden one stays placed, so impact admission, clocks and retirement carry on, and only its drawing, shadows and effects stop. Floating map text has a switch per recorded map event family; a hidden kind keeps its queue, phase and lifetime and only goes undrawn. Hidden counters and icons stay laid out, hit-tested and reported, so their hovers and combat windows still open; the tooltip switch hides only the painting. The counter filter draws all countries, the countries a human controls at the shown hour, or chosen tags; an hour lacking the tables it reads draws everyone. Battle-plan families filter arrow admission, so their labels follow, and raid paths share the battle-plan main switch. A hidden aircraft mission (missiles in flight are one) keeps its flights placed and animated and only stops drawing them, their shadows and their events, so a hidden missile still explodes where it lands. Fog of war stays a perspective choice, not a display switch. MSAA covers world/post/overlays; sample changes retire scenes, retaining compatible content/cameras. Quality selects authored textures; cache by recording, visual mod selection and quality. VSync updates the root surface. River/water/reflection choose native techniques; full map resolution renders the world at full size or truncating half dimensions with the compiled restore pass; matched visual/runtime validation remains separate. Gamma changes nothing, as in the game: its renderer applies the stored `graphics.gamma` only through a DirectX 9 device ramp, and the DirectX 11 renderer the viewer reproduces applies none, in a window or fullscreen. Day/night is a local display choice: disabling it fixes virtual lights while simulation time and province clocks remain authoritative. NATO choice also governs technology, carrier and nested scripted unit icons.

Widgets keep independent perspective/fog and export by view ID; missing/loading views refuse. Simple draw switches retain assets; artwork changes reload affected maps.

## Map audio

Interactive maps play the game's sound effects for the entity events they present and the game's music, through [viewer-audio](../viewer-audio/README.md). The scene lists each frame's events that name a sound effect ([sound_events.rs](../viewer-world/src/map/sound_events.rs)) after the model passes animate, weather entities and the default-state sounds of still ambient objects included, and each hour's recorded battle list (`BattleSounds`, the recording client's, with the divisions of each battle's member provinces' land combats) for the battle ambience (`Hour::battle_sounds`; without the table no battle plays); windows load the map-frame pass (ambient objects and nuclear impact entities) as dumps do; the content's sound and music definitions load with the content ([document.rs](src/document.rs)), and samples decode on the audio threads. The camera eye is the listener. Each hour build evaluates the enabled songs' chances for the viewing country (`Hour::song_chances`).

One map sounds at a time: the map last pressed, dragged or scrolled, else the first visible one. A map that is not drawn (hidden, scrolled out, or the Campaign map while dashboard maps show) releases the audio, and a document without sound definitions silences what the previous one played. Mute and volume changes apply at once, and new dashboard maps start with the current mute. Presentation resets and recreated units silence the sound effects and do not replay events already present; music plays on. Dumps and exports stay silent; a window capture traces audio without a device only when `BATTLE_PLAN_VIEWER_AUDIO_LOG` is set. Volumes are the resolved settings' `MapAudio` (`master`, `ambient`, `units`, `combat`, `voice`, `music`, 0-100), inherited HOI4 -> global -> campaign -> widget with the other choices from the game's `master_volume`, `ambient_volume`, `sound_fx_volume` (both groups), `voice_volume` and `music_volume`, kept exactly as the game stores them (49.6 stays 49.6; only a value outside 0-100 is brought into range); `dev_master_volume` is always the game's. The desktop's playback strip mute button is saved by the host and sent as `MapAction::Mute`. Audio refusals, unanswerable song conditions and a missing output device appear in the diagnostics.

## Fly aircraft

Fly mode flies whichever aircraft the host chose (`MapAction::FlyAircraft`, sent to the campaign map and the pop-out alike): the exact name of an entity or bare `pdxmesh` of the map's content stack, as the [aircraft catalogue](../dashboard/README.md#aircraft-catalogue) lists it, or none; there is no default. [fly_aircraft.rs](src/app/fly_aircraft.rs) bakes the choice on its own thread from the open map's aircraft assets (`AircraftAssets::player`), with the roster checks and lazy entity bake recorded flights use, so a name the catalogue refuses is refused before any file is read and one whose files do not load is refused with why. A map that loads again bakes the choice again from its own content. Each change (loading, ready, refused with the reason) goes to the host as `NativeEvent::FlyAircraft`; Fly mode reads the baked library slot from `FlyAircraft::ready`, against the aircraft assets of the map document the frame is drawing.

## Compare changes

Tests that read interface grammar, content registries or fixed modifier names initialize runtime metadata through `engine::executable_tables::initialize_for_tests()`. Set `BATTLE_PLAN_GAME_DIR` to the supported installation; those tests fail explicitly when it is unset. Pure geometry and recording metadata fixtures need no installation.

Use [AGENTS.md](../../AGENTS.md) for scoped checks and [recorder](../recorder/README.md) for oracle/smoke integration. Match hour/branch/perspective/camera/resolution/settings; report scores and inspect images. Compilation, identical-input pixels, live fidelity and performance are separate checks.

```powershell
.\.cargo-target\release\viewer.exe --compare <game.png> <viewer.png> --exclude-game-ui --diff <difference.png>
```

UI masking supports 2560x1440/3440x1440 only. `--layers trees` omits trees; `--counters-json` exports submitted plates/diagnostics; `--province-hover <id>` prints a province's hover text in the dump's map mode, control codepoints escaped, with its refusals, once the air roster history it asks for has been read. `--window-dump` opens a window of its own only to check the windowed loading/rendering path against `--dump` (the [smoke run](../../tools/smoke.ps1) requires identical bytes) and for profiling sweeps, with repeatable animation controls. Headless presentation/map clocks are separate/default zero. Dumps settle pool requests at fixed hour/clocks; `--settle` advances the interval. Actor-local failures omit all parts; infrastructure/identity/frame/output errors remain fatal.

CPU GUI checks use synthetic technique, sampler, blend and clock metadata. Installed effect checks compare compiled submission with independently packed direct draws using resolved shader sources. They use `BATTLE_PLAN_GAME_DIR` and the configured compiler; `BATTLE_PLAN_SHADER_CONTENT_OVERLAY` adds an ordered, platform-separated list of content folders above the game layer. Module-local tests also cover political full/incremental/multi-map exactness and recording sweeps, plus [content-only scenes](src/map/offline_scene.rs), which prove no recorded unit/political history. Serialize GPU harnesses. `BATTLE_PLAN_VIEWER_CHECK_OVERLAY` verifies raid replacement equality.

| Profiling switch | Use |
|---|---|
| `BATTLE_PLAN_VIEWER_PROFILE` | CPU laps; `--window-dump` sweeps: `play:<hours/s>`, `pan:<units/s>`, `zoom:<factor/s>`, `hours`, `seek_end`. |
| `BATTLE_PLAN_VIEWER_PROFILE_HZ`, `BATTLE_PLAN_VIEWER_PROFILE_SWEEP` | Sweep pace/length. |
| `BATTLE_PLAN_VIEWER_NO_VSYNC`, `BATTLE_PLAN_VIEWER_GPU_WAIT` | Uncapped presentation; GPU drain. |
| `BATTLE_PLAN_VIEWER_GPU_PASSES` | Frame-correlated pass timestamps; measure frames separately because collection waits. |
| `BATTLE_PLAN_VIEWER_BENCH_FRAMES` | Extra dump frames with CPU/drain timing. |
| `BATTLE_PLAN_VIEWER_BENCH_MODELS`, `BATTLE_PLAN_VIEWER_MODEL_FRAMES` | Live model histories after settled dump. |
| `BATTLE_PLAN_MAP_SCENE_RGBA16F` | New-path HDR readback before grading, outside benchmark timing. |

Choose matched game/viewer baselines from your own recording and installation. [Scale tests](src/unit_scale_tests.rs)/[fixtures](examples/unit_scale_fixture.rs) check volume, not fidelity/frame acceptance. Measure whole views, set affinity before startup and keep builds out of timings. Captures and reports stay outside Git.

## Mod corpus check

```powershell
.\.cargo-target\release\viewer.exe --mod-corpus --out <run> --workshop <steamapps/workshop/content/394360> [--game-dir <game>] [--user-dir <user>] [--cache <cache>] [--only vanilla,<stack>,...] [--jobs <n>] [--values[=text]] [--sounds-only]
.\.cargo-target\release\viewer.exe --mod-corpus-diff <base-run> <head-run> [--out <diff.md>]
```

[corpus/readers.rs](src/corpus/readers.rs)/[dashboard::content_check](../dashboard/src/content_check.rs) own coverage. Runs use vanilla/individual mods with dependencies/DLC/language and scratch descriptors, not loose user files. Name missing dependencies/unrun readers; reuse external hash caches and keep installs read-only.

Driver findings never pollute live catalogues. Typed channels decide kinds; `content` reports content interpretation, while `offline` reports missing recorded context. Preserve those distinctions, actionable refusals/fallbacks, occurrence counts/examples and shared notes once. Diff diagnostic multisets from manifests only.

`--sounds-only` runs only the defines and the map audio's readers: `viewer.sounds` (every sound effect entity events name, the sound definitions, the battle defines and every sample an effect can choose, decoding those a DLC or mod supplies), `viewer.battle_sounds` (the `sound/combat_sounds` layers and the effects they name) and `viewer.music`. `--values` hashes normalized values; `--values=text --only <stack>` writes the same stream. Preserve list order; normalize hash containers/exclude timing/caches. This checks interpretation, not pixels/shaders/recorded evaluation. Runs stay under external captures.
