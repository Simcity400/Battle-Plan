# engine

The boundary between HOI4's native memory and the recorder. This crate owns the supported executable identity, native layouts and offsets, guarded readers, table walkers and hook site descriptors. Replay encoding belongs to [replay](../replay/README.md), hook installation and acquisition to [collector](../collector/README.md), and presentation to the consumers.

Shared rules and checks live in [AGENTS.md](../../AGENTS.md).

Executable version text is loaded into owned metadata from the hash-verified installation before recording. Offsets, widths, calling conventions and field-specific limitations stay beside the reader. Stored fields, calculated getters and renderer caches are different sources; a similar save value does not establish equivalence.

Fixed modifier keys and lexer tokens require the live layouts to match the verified executable's registration names; a mismatch refuses fixed keys by name. Dynamic definitions size and resolve from live data.

## Executable metadata

Call `executable_tables::initialize(game_dir)` or `initialize_executable(exe_path)` before using installation-dependent tables. Initialization reads one owned executable buffer, verifies its size and SHA-256 against [the supported build](src/build.rs), and decodes keywords, modifier names, trigger/effect registries, equipment metadata, rules, AI enums and numeric properties. Variable names come from the selected installation's shipped documentation. Each decoded table must match its semantic digest before publication.

The public `EXECUTABLE_TABLES` holds the immutable `Arc<ExecutableTables>` for the process. Repeated initialization still verifies the selected executable bytes and variable documentation before returning that handle. `get()` reports a programming error if initialization has not succeeded; failures never supply empty registries. Runtime names have process lifetimes, and no table cache is written to disk. Shared registry and variable views use `RuntimeTable`, whose once cell can retry after an access before initialization; that access still reports the missing setup.

`PeImage` validates AMD64 PE32+ headers, section ranges, directories and exception-directory function extents. RVA reads require complete raw file backing in one section; virtual zero-fill tails do not authorize reads. Instruction decoding uses preferred virtual addresses for instruction pointers and operands, while image reads use RVAs. The crate never invokes code from the executable.

Registry factory decoding follows bounded instruction branches and tracks the object identity returned by each reachable path. Known allocated objects exclude their null-failure paths; unknown conditions retain both paths, and conflicting returned identities are refused. Constructor calls preserve receiver identities and derived overrides, while embedded helpers retain separate identities.

Ordinary decoder tests use small synthetic PE and documentation fixtures. Installation digest tests explicitly use `BATTLE_PLAN_GAME_DIR` through `initialize_for_tests()`, which checks that the variable is set on every call and caches the initialization result once per process. Returned failures preserve their kind and message without poisoning later test calls. These tests read the installation without launching the game.

## Reader safety

- Use `Memory` and the guarded read helpers for every native span. Check nulls, address arithmetic, lengths and the reader's vtable, reference-type, identity and ownership requirements. A readable address alone does not authenticate an object.
- Preserve native order, repeated occurrences, signed widths and arithmetic. Deduplicate only where native behaviour permits it. Scope shared reads to the selecting table, identity and occurrence; address equality alone is insufficient.
- Command-power ownership authenticates the country independently of political status. Political-power ownership also authenticates the selected political status and its backlink.
- Preserve the first independent failure and each consumer's failure boundary. A short or failed read cannot become a complete row, empty table or zero. Distinguish known absence, unavailable data and capacity truncation, counting unread occurrences as the walker requires. Do not retry to hide a failure; the only second read is a batched walk's or gathered acquisition's one serial fallback for a batch that did not read whole (see below).
- A walk may batch, gather, reorder and read ahead across objects (several objects' spans in one guarded `copy_records` or `copy_scattered`, children read before their parent's checks, the next rows' objects read early) when, on healthy memory, its published output is byte-identical to the serial walk's and, under any fault, it refuses or withholds no more than the serial walk could. A fault that clears after its first touch may land on another table, row or reason. Speculative reads use guarded copies, follow only validated pointers, and their values are used only after the serial walk's checks. After a batch fails, the walk reads that batch's remaining objects alone, as the serial walk does, once and counted in status; a persistent fault therefore gives the serial result. All these walks record their bounded fallback in [batch_fallback.rs](src/batch_fallback.rs), published under collector status `batch_fallbacks` by the names below. The orders group root census gathers each 64-bucket chunk's validated groups in one copy (`corders_group::walk_roots_buffer`, `order_roots` in `batch_fallbacks` status). The order census gathers root slots and identity/path/target headers in roster chunks of 16, while entering roots and their descendants in serial DFS order (`order_census`). Plan records, named-order headers and assigned member hosts likewise retain a complete gathered prefix and decode their incomplete suffix by the serial reads (`order_plans`). DivisionStatus gathers distinct unheld stat-block maxima, the first acclimatization entry blocks and non-carried naming member spans in batches of 64 (`division_maxima`, `division_acclimatization`, `division_naming`); held rows supply no native request, and longer acclimatization arrays continue in native order without a cap. Movement and the core division census gather memo-missing province identities and their authenticated registry slots, retaining the original memo keys and admission order (`division_provinces`). Movement gathers admitted ordinary movers' base speed in 64-row batches after the route prefix (`division_movement_speed`). The collector's Naval copy takes each order-of-battle root's member and child entries in runs of up to 64 per guarded copy and each member's host identity and group backlink in one, every span, failure included, logged as its own take logs it; a run that stops at a failed entry goes on after it, and a member whose host identity failed takes its backlink alone (`order_of_battle`). A run is batched only when its whole worst case fits the storage the log already holds: an entry span and eight bytes per entry, a span for a failed entry, and per entry a member's two spans and 40 bytes or a child's span and 16 bytes; then neither the run nor the per-entry copy can overflow within it. Any other run is taken and visited entry by entry exactly as the per-entry copy takes it.
- A gathered acquisition copies several objects' fields together, or a child's before its parent's checks, through guarded copies only, and uses a value only after the serial checks pass. Its published values equal the serial reads'. When any copy fails or any check refuses, it is withheld and the serial reads run exactly once, counted in status; a persistent fault then refuses where the serial reads always did, and a fault the gather met once refuses nothing they would not. The air loss writer's operands (`air_loss_sites::gather`: six gathered copies plus the country resolution) are acquired this way, with `serial_fallbacks` in the hook's status.
- A pass meets its objects in the walk's order, which is ours where the game has none. Passes over the order census (plans, execution operands, child-front areas, invasion preparations) meet its orders in census order, groups in handle order and then each order as the census entered it (`corder_instance::census_orders`), when the complete census of the same pass retained that order. Without it (an empty census, a failed one, an order that could not grow or failed its own consistency check, or a caller that supplies none) they iterate the census table; its slot layout is ours, not the game's, and decides nothing else. The plan walk instead takes the order its census's own sequences give (`corder_instance::walk_plans_ordered_with_sources`), so its rows and link, member and name arenas are laid out alike whether or not the census kept its order; the game keeps no such arena (each order's vectors are its own, serialized per order), so census order decides it. Two kinds of result follow that order. A whole-pass refusal (the plan walk, invasion preparations) is the first failure met. An optional per-order result that survives other orders' failures (an order's child-front area, its execution operands) and the shared observations behind them (execution's scalar, country and modifier memos) are attributed in that order: under a fault that clears after its first touch and is shared by several orders, the first order met records the failure, and a later order that attempts the read again records the value; a shared memo instead keeps its first success or failure for every consumer of that observation, without another read. Independent acquisitions that run as separate jobs (the Fronts job and the Orders job's invasion walk) meet a shared fault of that kind in time order: whichever reads it first records it. Each such fault is recorded exactly once, never more harshly, and nothing retries it or fabricates a value, except the owner's bounded batch fallback: after a gathered or batched copy fails, each object it covered is read once more by its own per-object reads (a run's or object's worth at most, never a loop), so a lasting fault gives the per-object result. A gathered span the gather failed on is kept as a failure for an exact read of that span, while a smaller read inside it, or a later span, is read from the source. A census split into parts over consecutive group ranges (`corder_instance::walk_listing_successors_part`, `stitch_census`) is the single census for every persistent input: its rows, geometry, census order (built from the sequences by the single census's rule, which keeps none when an occupied slot is `u32::MAX` or more, so only tables of at least 2^32 slots can differ, the slots being ours) and outcome, the first failure in group order included with the rows, geometry and visits it retains; the plan walks over its parts, stitched (`stitch_plans`), are likewise the single plan walk, with the arenas and assigned hosts acquired before its first failure. Within a part census order holds, and across parts a fault that clears after its first touch is met by whichever part touches it first in time. A part's own memos see only what the single walk's would, since memory stays fixed while the pass holds the game thread. Published rows are sorted by key regardless (the collector's `spooling::table`, which the frame encoder requires), so no table's row order depends on a walk's; their values can, as above.
- Read passively at the collector's established boundary. Never call game getters, refresh caches, wait for memory to change or infer freshness beyond the game writers. Registry walks require a quiescent boundary.
- Copy everything deferred decoding needs into owned storage during acquisition. Deferred code must not follow game pointers. Native string descriptors, including ace portrait descriptors, authorize immediate acquisition only; copy their payload before deferring work.
- Reuse buffers and plans only within a verified identity, ownership and invalidation lifetime. Reloadable defines, weather and mutable definitions are not automatically session-static; a sizing hint is not a recorded value or validation of a later read.

Size variable capture storage from live demand. Use [allocation.rs](src/allocation.rs) for potentially large or live-sized buffers, reserve a known batch before filling it, and keep callback reads within caller-owned capacity. Preserve the existing growth boundaries when filtering determines the output count. Allocation failure must retain its terminal `OutOfMemory` distinction through the collector callback, including readers that otherwise return a static refusal or optional value. See the collector guide for accepted standard-library allocation residuals.

A pass that repeats a read may serve the repeat from the bytes the first read returned, since memory stands still within the hourly callback, but only for reads that succeeded and without reading anything earlier (a gathered acquisition, below, may read ahead under its own rules): the [production hover trees](src/attrition_modifier_breakdown/repeats.rs) walk each country's accumulator once per key, and every key after the first reads only the nodes, labels and entry arrays the earlier keys did not, while a read that failed is made again by the next key, as the uncached walks make it.

Allocating worker readers use [growing buffers](src/walk.rs) to extend storage from acquired headers without restarting native reads. Fixed slice readers retain explicit shortage outcomes for callback storage and fault fixtures.

Nested growing suffixes keep the original vector owner, so a later country's header can extend the same acquisition after earlier rows were filled. Text, catalog, graph and memo arenas follow their original selecting controls before payload reads. Owned decoding prepares complete destinations from retained controls. Capture allocations keep terminal failure handling; advisory demand reads use nonterminal allocation without supplying recorded values.

Wrap complete optional sizing and plan preparation in `allocation::advisory`, including nested constructors. The scope is thread-local, leaves capture hooks installed, and excludes hints from terminal fault ordinals. Checked `allocation::boxed` and vector/map reservations preserve fallible allocation. Preparation demand follows requested sizes and original acquired counts; allocator spare capacity belongs only to storage checks and byte accounting.

DLC/mod names, descriptors and mount paths use native stored lengths. `cdlc_manager::prepare` grows owned text off-thread; `observe_prepared` reauthenticates controls and copies current values into that storage without allocating. A changed or unprepared span keeps its named refusal.

Preparing a read plan is fallible; executing it does not allocate. Its controls must cover every owned operand that selects later addresses. Hints run only after those controls pass and acquire no bytes. A stopped plan reports its completed prefix and attempted failure so continuation need not reread them. Valid geometry alone proves neither dependencies nor object lifetime.

The governance readers gather a country's slot pointers and each slot's existing four fields, assigned technology operands and selected template fields in pass-local exact records ([governance_batch.rs](src/governance_batch.rs)). Research modifiers gather assigned technologies, idea contributions and scripted-source pointers and contributions; focus reads gather the progress object's existing fields, selected string headers and completed-focus pointers and string headers. Each record stays within its native object's fields. Children are followed only through pointers from complete guarded copies, and the original identity, ownership, ordinal, count and string checks still decide publication. Storage follows the live roster count and is advisory: a storage miss uses the serial reader. A failed full-read batch discards every partial byte and permits one original serial pass for that batch, with a typed [batch_fallback::Batch](src/batch_fallback.rs) counter published under `batch_fallbacks`. Healthy rows, token arenas, reasons and table outcomes are identical to the serial readers; persistent faults retain their serial result, while a one-shot fault may move or be consumed by the optional gather without withholding additional data. Frozen serial readers and guarded-call censuses cover 5,000 countries, capacity boundaries and operand faults.

The `batch-fallback-test-counts` feature exposes thread-local shared fallback counts for dependent crates' synthetic tests; production counters are cumulative atomics.

## Adding a layout or reader

1. Establish each field's width, signedness, ownership, gates and arithmetic, including whether it stores a value or exposes a calculated or cached value. Preserve the selecting branch's operand reach and failure order.
2. Keep one source file per game struct and register it in [lib.rs](src/lib.rs). Name constants for their purpose and document field contracts, calculations and limitations beside the reader.
3. Implement guarded reads with the existing containers, gathers and caller-owned arenas. Preserve independent failures and game reach: skipped branches should not acquire operands, except the fields a gathered acquisition (below) copies ahead and uses only where the per-object reads would. Resolve content through [installed-content](../installed-content/README.md); built-in modifier names and fixed tokens use verified executable metadata, while dynamic definitions size and resolve from live data.
4. Add synthetic-memory cases that fail on the old behaviour: aliases, invalid identities, short reads, overflow, cycles where relevant and insufficient capacity. Follow AGENTS.md for scale and local checks, and the [recorder guide](../recorder/README.md) for the affected capture oracle and smoke workflow. Update the collector, replay and consumers together when the recorded meaning changes.

## Adding a hook site

Put the site's purpose-named RVA, exact instruction sentinel, operand layouts and caller requirements in its domain module. Establish whether it is a function entry, CALL or interior instruction, and document the register/stack ABI, original continuation and safe observation phase. Pre/post readers must reauthenticate identities when the game call can replace or free objects.

Verify both [the pinned executable](src/build.rs) and the site's bytes before installation. A matching sentinel alone proves neither executable support nor hook, lifetime or unwind safety. An interior site must resume its relocated instruction and original continuation correctly; it cannot be invoked as a function. Collector owns patching, dispatch, teardown and runtime coverage. Keep engine operands separate from replay event IDs and never publish a native pointer as history identity.

## Game distinctions to preserve

[world_lifetime_sites.rs](src/world_lifetime_sites.rs) authenticates current-world invalidation markers before reset, deletion and construction publish or retire data. These markers supply occurrence changes to collector; they do not infer successful load completion from a clock or singleton address.

- [War overview](src/cwar_relation/war_overview.md) builds viewpoint-dependent temporary groups of bilateral relations. These have no stable native war-object identity or stored participant join dates.
- [Peace settlements](src/peace_settlement.rs) need the pre-destruction finalizer boundary: a conference can appear and disappear between hourly samples, and finalization destroys its action history.
- [Equipment destruction](src/equipment_destruction.rs) retains signed pre/post pool differences, including gain corrections and supplemental writers; requested removal does not prove actual removal.
- [Air loss](src/air_loss_sites.rs) and [building damage](src/building_damage_sites.rs) retain native bookkeeping and signed health changes, including gains above a full level, independently of returned budgets.
- [Event feed](src/event_feed_sites.rs) reauthenticates action roles and reciprocal war links after native execution; world lifetime comes from the collector's reset/construction signal, not from these reads. [Its provenance sites](src/event_feed_sites/provenance.rs) list the entries of the operations that join and end wars, start and apply peace conferences, annex and release countries, and every direct caller of those and of the diplomatic dispatch, civil war start and state owner assignment, each by the replay route that names it; a caller outside a list is refused, never guessed.
- [Nuclear strikes](src/nuclear_strike_sites.rs) are applied only by the impact, which every launch path reaches through its nuke's delayed queue; a strike's outcome is what runs before the impact's tail jump to the notification, which dispatches the authored `on_nuke_drop` effects. The war support recipient is the state owner, not the province controller.
- Cached rates and tooltip inputs retain native gates, stale values and source order. Their formula and lifetime requirements belong in the corresponding reader; save serialization may omit those operands.

[Retained naval result sides](src/cnaval_combat_result_side.rs) visit the borrowed HQ range only when the retained HQ commander resolves, as the native result window does. A known absent commander supplies no HQ; an unreadable registry or borrowed input stays unknown.

## Measurement

The air joins gather across objects. [Base witnesses](src/map_air_base_reference.rs) (`Pass::read_bases`) take up to 64 handles' first registry buckets in one copy, their bases' six fields in one, and their states' and cached provinces' identities in one each; later probe buckets and the manager's first-province lists are read as `read_base` reads them. [Sortie inputs](src/map_air_sortie_inputs.rs) copy each batch's mission operands with their CAS ratios in one copy, and up to 64 pools' definition pointers, then the definitions' identities and flags, in one each. Each value is used only after the per-object checks pass. These gathers are the exception to reading nothing earlier, acquiring no skipped operands and never retrying: a gather that stops keeps the objects it completed, and the object it stopped at and the rest of the batch take the per-object reads exactly once (a stopped mission copy repeats the operands without the ratios, then reads each ratio). Each such fallback is counted where it starts, whatever the reads after it return ([batch_fallback.rs](src/batch_fallback.rs), collector status `batch_fallbacks`). So a persistent fault refuses where the per-object reads do, and a fault a gather met once refuses nothing more; a speculative read (a null definition's flags) never refuses at all.

The [AirWing census](src/cair_wing.rs) reads its roster (the manager, owners, pools and each pool's wing pointers, a run of up to 64 pointers in one copy) in the serial walk's order and queues its steps. It replays them in that order, so owner witnesses, storage growth, admission and every visitor run as before. The first queued wing that needs its row gathers the row fields and the 32-byte stored-name header of every queued wing from it on, 64 wings to a record copy, and name capture takes the gathered header (`Admitted::name_header`). These reads run ahead of earlier wings' visitors, and each value is used only where the per-object walk would have read it, so healthy output is the per-object walk's. A gather that stops keeps the rows it completed. The wing it stopped at and the rest of its queue take the per-object reads once, as does a pointer run that does not read, and each such fallback is counted where it starts ([batch_fallback.rs](src/batch_fallback.rs), collector status `batch_fallbacks`), whichever walk ran it. A persistent fault therefore refuses what the per-object walk refuses, and a fault the gather met once refuses nothing more. Walks whose consumers need no rows (the demand counts) gather none.

DivisionStatus gathers the first 32 acclimatization entries of 64 admitted census divisions in one guarded scattered request. The source addresses come from authenticated owned CData headers; empty or invalid headers supply none. A failed batch retains only its complete prefix and each later division reads its own array once. Longer arrays keep their serial 32-entry continuation, and a failure withholds only that division's optional camouflage/weather fields.

The first status loop gathers 64 distinct unheld stat blocks' identity, maxima and exfiltration byte. A held block or one acquired by the status memo supplies no request. Values enter that memo only at their original division's identity checks. The naming pass likewise gathers non-carried member spans in 64-row batches; carried members and cached text avoid reads.

Its exercise predicate uses the pass's country reader and observes AI control once per raw owner, retaining one AiControl's headers and acquired chunks for the pass. The first exercise gate acquires those inputs in their original order; any failure stops Status. The preallocated autonomy memo is sized from the division census, cleared every capture, and never changes a division's own deployment, strength or level reads.

DivisionMovement retains successful combat identity and registry joins for its current capture ([`cunit::combat_references`](src/cunit/combat_references.rs)), once per module and primary combat pointer. The game remains parked until every worker joins; combat link rebuilding and registry filing cannot replace those identities during the pass. Failed identities are read again at the next occurrence, and each division still reads its tail pointers and rechecks its own vector header. Memo storage follows the live combat-reference arena; a full fixed memo falls back to the ordinary read without allocating.

Movement hints owned route and combat-vector payloads four census divisions ahead. Its 32-seed province chunks gather at most 64 memo-missing identities, then their uncached authenticated registry slots; the exact geometry memos and diagnostic hit/miss counts are admitted by the serial checks. The core division census gathers its province misses in 64-row chunks while preserving its successful direct-mapped memo. Movement's optional speed suffix gathers 64 admitted moving rows' stat-block vtable and +0x290 after the established prefix finishes. Each incomplete batch keeps a complete prefix and reads the remaining objects alone, once and counted; stationary and omitted rows supply no speed read.

A batched walk reads several objects' spans in one guarded copy and reads ahead of the serial order only what a validated pointer leads to, using each value only after the serial walk's checks; its healthy output is the serial walk's byte for byte. A batch that does not read whole is read once more object by object, as the serial walk reads it, so a persistent fault gives the serial result and a one-shot fault refuses no more; each such fallback is counted per walk in [batch_fallback.rs](src/batch_fallback.rs) (`batch_fallbacks` in collector status), which also holds the next census slot a walk reads ahead (`Ahead`). [Country resources](src/ccountry_resources.rs) read each pool's values for up to 32 consecutive resources as one block, nine value spans per batch of up to 32 stored resources, and read the next census slot and its resources link while the current country's values are read, hinting its resources object's identity and pool headers. A link whose read ahead failed is read again at its country's turn and counted as a fallback. [Intelligence agencies](src/cintelligence_agency.rs) read each agency's row bytes, from its vtable to its defense, as one block after its link, and [cryptology](src/ccryptology.rs) reads up to 64 decryption states as one block; both read the next census slot and its agency link while the current country is read, hinting the agency's lines, and count a link read again after its read ahead failed. [Unit intel](src/unit_viewer_entry.rs) reads the first viewer entry block of sixteen shared-census divisions in one scatter. CountryFactories gathers a batch of countries' production status pointers, then their statuses' identity, owner and factory span ([cproduction_status.rs](src/cproduction_status.rs)); RelationLinks gathers one batch of an owner's distinct political candidates' matrix cells, then their statuses' link fields and transport subject pointers ([crelation_status.rs](src/crelation_status.rs)). The AirWing census and the air joins (AirReferenceWitnesses' bases, AirMissionInputs' missions and pool definitions) count their fallbacks here too. The [owned subject walk](src/csubject_relation.rs) reads 64 of a country's owned relation entries at a time in one copy, their type words in one gather and the subject relations' own fields (vtable to autonomy ratio) in another.

Measure acquisition with the current [read counters](src/read_counts.rs) and their definitions. Decoding an owned copy is not another native read. [Unit-scale fixtures](tests/support/unit_world.rs) and the opt-in scale tests model native walks; synthetic timings do not establish gameplay slowdown or live hook correctness.

[Country stability](src/country_stability.rs) retains the first exact spans of a country's modifier children and sources for pairing and emission. Its [guarded batches](src/country_stability/batched.rs) gather candidate heads and modifier blocks across each pointer page, and the first entry/display payload windows across children and sources. The original per-object checks still validate every value before use. Its [observation memo](src/country_stability/observed.rs) reserves optional retention before a speculative batch; allocation failure stops speculation for that country and leaves the serial readers to acquire those spans. Dependent preparation uses only retained controls and never acquires missing scalar headers. A failed batch installs none of its prefix and yields once to the serial readers, locating persistent faults with their original reason or recovering a one-shot fault. `Scratch::batch_fallbacks` reports those batches even for a refused country. Authoritative failed observations stay retained without partial bytes or retries; ordinary retention failure leaves a span as acquired and allows its next use to read it again. Inputs and the child-count consistency reread acquire their operands afresh. A caller may pass an hourly memo for selected static sources and their names; it must clear that memo before each new context. Defines, language, bound static slots and modifier metadata are already read once in that context. Owned spans grow from acquired data without a country, entry or text-size cap.

[Selected transport inputs](src/selected_transport_units.rs) borrow the pass's [original unit observations](src/selected_unit_originals.rs) (each shared stat block and template authenticated once), movement and railway observations within their callback lifetime. [Convoy inputs](src/cconvoys/transport.rs) retain the original cache attempt, ordered pool and signed reservations. [Mission observations](src/transport_ledger_observation.rs) keep strict icon results independent from nullable transport receivers, authenticating class, full handle and registry identity. Optional failures and capacity omissions retain their separate meanings; loans never wait for tasks, retry reads or refresh native caches.

[Country movement inputs](src/carmy/country_movement_inputs.rs) query each logical owner's complete source-region transport domain once per pass. The pass-local [transport memo](src/cnaval_unit_transfer.rs) keeps every input's first observation, copies each enemy navy's regional operands for the bound domain in runs of consecutive region ids, and reads only a region's own element after a failed run.

[Division movement](src/carmy/movement.rs) records the base speed of a division whose ordinary route count is positive: a batch gather of its stat block (`CArmy+0x138`) authenticates the `CSubUnitDefinition` vtable and copies the signed fixed5 maximum speed at +0x290. No field caches the current speed: movement-speed calculation starts from that value, the hourly step adds vslot 0xD8's result to CUnit+0x240 without storing it, and the division view recomputes it.

No ship field holds a maximum organisation: the organisation-maximum calculation recomputes it from ship modifier operands on every call, so the [ship model readers](src/cship.rs) run every hour. They read about thirty fixed fields of a ship, its task force, the task force's location and the game singleton; [`cship::ShipFields`](src/cship/gathered.rs) gathers each object's fields in one guarded scattered call (a task force and its location once per run of consecutive ships naming them) and `GatheredMemory` serves the readers from them: a read inside a gathered field is served, a read of exactly the field a gather failed on fails without another read, and every other read goes to the source, so rows and failure reasons are the direct readers'. A pool of up to two entries is gathered too, with the variants the model reader reads from it, and recent variants are kept for later ships of the capture. The maximum-organisation memo keeps the recent terrain, terrain-class, commander-class, pride-ship and doctrine-key observations of the capture, not only the last ship's, and terrain lookup's ocean fallback, which is content, is scanned once per capture (also by the task-force ETA reader, which also keeps each accumulator census of its capture, since task forces share their country's, terrain classes', weather regions' and commanders' sources, and reads each roster ship's vtable, parent, class and handle in one call). The naval combat weapon contexts likewise walk the lexer's modifier-key dictionary once per doctrine selector per capture, not once per doctrine node of every ship, walk each task force's doctrine tree and read its roster country, its location terms (relation, terrain, weather region and province records, night), each terrain's class records, its HQ influence sources, its fleet's default leader and its commander's class records once per capture, and the module's fuel defines and eligibility flags once per capture, re-emitting the same sources in the same order for its later ships (`SourceMemo`), and read the modifier definition table header and each key's metadata once per capture ([`TermMetadata`](src/naval_ship_modifier_inputs.rs)), not once per accumulator entry, and read a live combat ship's fixed fields in one gathered call. The same gathering serves any one object's fixed fields to its readers ([`GatheredObject`](src/cship/gathered.rs)); a walk's collectors built once read each task force of the hourly counter walk through a [`SwitchedObject`](src/cship/gathered.rs) the walk's caller points at it (`ctask_force::TASK_FIELDS`, one guarded call per task force). A ship's own gathered objects can be kept as a [`cship::HeldShip`](src/cship/gathered.rs) and served to a later hour's readers (`ShipFields::visit_held`, with `SnapshotArena::hold` for its modifier arrays) while none of the writers in [ship_model_mutations](src/ship_model_mutations.rs) touched them; `OrganisationMemo::hold_doctrine` and `ShipFields::task_force` serve a task force's doctrine contribution and expose the fields its other carried terms are compared on. The counter walk's fresh ETA graph gathers each object it reads a fixed set of fields of (the task force's stat block, its location province, strategic region and template, its fleet and fleet leader) in one guarded call when it reaches it, serving its unchanged readers; a field a gather could not copy is read alone (`fresh_eta_gathers` in [batch_fallback.rs](src/batch_fallback.rs)). The fleet census gathers each fleet's census fields (vtable, handle, owner, leader, task-force roster, home base, name) and each task force's (identity, TaskForces row fields, ship roster) in one guarded call per object (`cship::SwitchedObject`), serving its reads of them from the gather; a field the gather could not copy is read alone, as the per-field walk reads it (`fleet_gathers`, `task_force_gathers`). It reads each ship roster a page of pointers per guarded call and queues the ships, hinting their census fields, across task forces, fleets and countries; every 64 queued ships (and the Ships-table failures between them) are read in one guarded `copy_records`, then checked, emitted, visited and failed in census order. The ships still queued when a failure ends the walk are read, emitted and visited before it applies, as the per-ship walk visited them. On healthy memory, and into fixed buffers of any size, the rows, names, outcomes and visits equal the per-ship walk's. A run whose copy stops early reads its remaining ships once more one at a time (`ship_runs`), which gives the per-ship walk's failure for a lasting fault; a fault that clears after its first touch may let a ship through that the per-ship walk refused, never the reverse.
