# Hourly cadence audit

Every recorded table on the Hourly cadence in [cadence.rs](src/cadence.rs) (a retired table is never read), with the native writers of the fields it records and the fastest of their cadences. A table reads less often than hourly only when every writer of every field it records runs on that slower cadence, or is a hooked site whose notification certifies carried rows, so that the value recorded for each hour equals the game's, or when an owner decision accepts a day's staleness for a table only panels read. Script effects, decisions, event options, on_actions, diplomatic actions, player and AI commands and the console run at any hour, and a mod can reach any effect, so a field one of them writes is never daily-only.

## Writer cadences

| Class | Meaning | Tables |
|---|---|---|
| hourly tick | At least one writer runs on the hourly tick (game-state updates, the pre-hourly stage, AI, unit, combat, supply and movement updates), so the value can change in any hour. | 117 |
| any hour | No hourly-tick writer, but effects, commands, actions or the console write it, so it can change in any hour; daily writers may also exist. | 67 |
| hook log | A collector hook log drained at the hourly boundary; each hour holds that interval's native events. | 17 |
| load | Written only while a game state is loaded or reset; read as part of an hourly walk another hourly table needs. | 2 |
| recorder | Recorder bookkeeping written with each hour's reads. | 1 |
| total | | 204 |

No hourly table is written only by the daily tick or slower: each has an hourly-tick writer, an any-hour writer, or is a hook log. The daily-only tables (`CountryIntel` and `LogisticsEquipment`, written inside the daily game-state update) already read on daily slot 0.

Owner decision 2026-10-11 moved tables whose only consumers are panels and the decorative supply trains to daily owner slices although they have hourly or any-hour writers; each is up to a game day stale. `SupplyNodes` and `TrainInventory` (the hourly supply update rebuilds every node and resets train and truck demand) feed only the supply-train animation and the `get_supply_vehicles_temp` effect description; `AvailableAdvisors` (membership and other pool writers run at any hour) feeds only the advisor-idea lookup of effect descriptions. Their map, trigger and derivation neighbours stay hourly: `ProvinceSupply` and `AdvisorTokens`.

Owner decision 2026-10-11 also holds raid inputs to the game's hour, since its offer cache re-checks every offer at least hourly. The sliced raid state tables (`StateResourceInputs`, `StateResources`, `StateDynamicModifiers`, `StateCores` with its cores, claims and strategic locations) and `CountryBuildingResources` read, beside their daily owner slice, every state or country a hooked writer marked since the previous hour (the collector's raid_changes, building_changes forwarded), and every owner when the marks are not certified; only `StateResourceInputs.supply_route`, which the supply update rewrites every hour, waits for its state's next read. `RaidCountryInputs` and `AceRangeInputs` are read for every country each hour in `CountryCommandPower`'s pass, and `DivisionRetreatBans` for every division, carrying each commander's bans while no forwarded writer touched its blocks (retreat_ban_changes). `RaidAirSites` reads, beside its daily owner slice, every country a hooked site list writer or changing capacity store marked (raid_changes). `StockpileArchetypes` is read for every country each hour, keeping only the archetypes a raid type lists as essential, in whole units capped at the largest amount any raid type requires (owner decision 2026-10-11).

`RelationOpinions` and `RelationTuples` likewise read, beside their daily owner slice, every owner a hooked writer marked since the previous hour (the collector's opinion_changes: changed opinions from recomputation; every reset and every call of the sixteen relation slot replacements, the only run-time writers of the serializable relation vector, with the war body forwarded by country_input_changes), and every owner when the marks are not handed over. `NavalMissionCountries` and `NavalMissionCommanders` read, beside their daily slice, every country whose certificate moved: its task forces' leader and commander references, the naval tree certificates of its accumulator and its fleet leaders' (naval_tree_changes, with country modifier recalculation and appearance reset forwarded), its navy's stored hubs and its headquarters commanders' skill objects.

Three sliced families hold the game's value every hour through the country input hooks (the collector's country_input_changes). `ResearchTechnologies` reads, beside its daily owner slice, every country whose technology level, classifier, researched membership or applied bonuses a hooked writer changed, so `has_tech` answers within the hour; only progress, which the daily research step advances once a day for a country owning a state, waits for the slice (a stateless country's slice reads nothing, unless it gained or lost its last state since its last slice): no trigger reads it, and as a number only the research panel shows it may be a day stale (owner decision 2026-10-11). `Focus` and `CompletedFocuses` read every country owning a state at the first hour after the daily tick (the daily game update runs focus progress; the country's daily update returns before it when its owned-state count is below 1) and, in between, every country a hooked focus writer marked (selection, cancellation, continuous focus, completion, completed-focus insertion and removal, the tree setter, reset, copy and database clear), so `focus_progress` and `has_completed_focus` answer within the hour. `Projects` and `ProjectHistory` read every country owning a state at the first hour after the daily tick, whose pool pass advances those countries' projects, and, in between, every country a hooked project writer marked (start, stop, cancel, complete, progress-ratio addition, prototype reward-option application, forced update and pool database resync), so the project triggers of scripted map offers answer within the hour; `ProjectPrograms` and `ProjectBreakthroughs`, which only panels show and whose walk is separate from the pools', keep their daily slot.

Tables with any-hour writers stay hourly unless a hook family observes every writer. Those under an existing family carry rows between hours while no hooked writer touched them, and read every hour only what certifies them (the collector's [acquisition rules](../collector/README.md#acquisition-rules)): `HiredAdvisors` (advisor_pool_changes, character_changes, roster_changes), `CountryLocalSubunits` (local_subunit_changes), `DivisionTemplates` (template_changes, name keys only), `Characters` (character_changes, roster_changes), `CountryLeaderRoles` (character_changes), `AdvisorRoles` (advisor_changes, character_changes), `CharacterRoleTraits` (character_changes, roster_changes), `CharacterPortraits` (portrait_changes), `CountryAppearance` and `CountryCounterInputs` (country_input_changes, with the families that forward their writers), `ScriptFlags` (flag_changes, roster_changes), `StateBuildings` and `ProvinceBuildings` (building_changes), `AdvisorTokens` (advisor_pool_changes), `PartyLeaders` (party_leader_changes, character_changes, political_status_changes), `ScriptVariables` (variable_changes, roster_changes), `PoliticalParties` and `ActiveIdeas` (party_changes, political_status_changes), `Politics` (political_status_changes), `WingEquipment` (wing_changes), `AirRegionalMissions` (mission_changes), `RailCooldowns` and `RailEdges` (rail_changes, building_changes), `States` (territory_changes, building_changes), `DivisionRetreatBans` (retreat_ban_changes), `WarRelations` (war_changes, casualties read every hour). Others are read whole and published from the held read on an hour none of their writers ran (world_input_changes): `ProvinceNames`, `NavalRegionAccess`, and `WorldTension`, `ThreatSources` and `ThreatCountryAggregates` together; `DynamicModifiers` carries each country none of its writers touched (world_input_changes, naval_tree_changes).

Several tables share one native walk; moving one of them saves none of that walk while another table still needs it. The evidence names the shared walk where it matters.
