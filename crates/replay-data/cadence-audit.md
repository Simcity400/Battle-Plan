# Hourly cadence audit

Every recorded table on the Hourly cadence in [cadence.rs](src/cadence.rs) (a retired table is never read), with the native writers of the fields it records and the fastest of their cadences. A table reads less often than hourly only when every writer of every field it records runs on that slower cadence, or is a hooked site whose notification certifies carried rows, so that the value recorded for each hour equals the game's, or when an owner decision accepts a day's staleness for a table only panels read. Script effects, decisions, event options, on_actions, diplomatic actions, player and AI commands and the console run at any hour, and a mod can reach any effect, so a field one of them writes is never daily-only.

## Owner exception - 2026-10-21

The owner accepts up to one day of staleness **only** for
`UnitLeaderTraitExperience` (whole table), `UnitLeaders.experience` and
`CombatLogObservers.a/b` and `DivisionStatus.supply`, `experience`,
`officer_experience`. They share daily slot 12, previously unused by a
fixed daily family. All row membership and other columns of the hourly
tables stay hourly. Off-slot column samples follow the current occurrence and
referents; a new row reads its first value, never an invented zero. Full
refresh/load/attach/recovery reads fresh. Training uses ordinary skipped-table
carry with its supplying hour. Other tables, including IntelContributions,
FactionAccounts, WarParticipation, States and TaskForceCounterInputs, keep their
existing rules. Numeric sampling does not thin retained/terminal battle events.
The division footer includes requested/received amounts and ordered origins;
its whole read and origin traversal are skipped when carried. Stored/officer XP
use the existing occurrence-aware scalar stores. Daily/full preflight revokes
these samples even if dispatch fails; owned FIFO settlement makes no live read.
Supply ratio, exact ratio, grace, movement/attrition and exercise stay hourly.
Exercise accepts held XP only with its exact current writer certificate and
otherwise reads its independently demanded XP fresh before resume.
