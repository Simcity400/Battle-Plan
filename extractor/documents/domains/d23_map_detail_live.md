### Province supply remaining

The displayed province supply-remaining value is not save-backed: the
time-aligned melt has zero hits for `remaining_supply`, `province_supply`, or
`supply_available`. Exact-a729 computes it at draw time. The live root is
`CGameState=u64[module+0x3316E90]`, then
`CSupplySystem=u64[CGameState+0x3D8]`. For a province supply context, source
elements begin at `+0x60`, count is signed i32 at `+0x6C`, and each eight-byte
element contains `node_id:i32` at `+0x00` and `type:u8` at `+0x04`.

The node lookup requires two pointer hops:
`node_array=u64[CSupplySystem+0x108]`, then
`node=u64[node_array+node_id*8]`. Treating `+0x108` itself as the array base is
wrong. Per-node supply is signed i64 fixed-100000 at
`u64[node+0x80]+0x138`. Type 1 contributes a truncating half
(`supply*50000/100000`), type 2 contributes the full value, and all other
types contribute zero.

Let `S` be that sum. The draw-time outer law clamps negative intermediate
inputs through helper `module+0x14CE920` using the cap at RVA `0x33717E8`,
with `A=clamp(S)` and `B=clamp(-100000)`. It computes
`elapsed=i32[module+0x331BFE0]-i32[province_ctx+0x94]`, using rate
`i64[module+0x331D160]`, then
`timeTerm=trunc(elapsed*rate*100000/100000)` and
`net=A-timeTerm-B+carry`. The still-untraced formatter carry remains part of
the law. The result clamps `net` to non-negative, then scales it by:

```text
denom = i64[province_ctx+0x38] + i64[province_ctx+0x20]
      + i64[province_ctx+0x48]
factor = 100000                                      if denom <= 0
factor = clamp(100000 - i64[+0x48]*100000/denom, 0, 100000) otherwise
result = trunc(max(0, net) * factor / 100000)
```

The carry provenance and the semantic names of the three globals remain
unproved, so this is derived-with-residuals rather than an authenticated stored
field. A same-frame supply-map tooltip capture over at least eight provinces
would settle the byte-exact decimal presentation.
