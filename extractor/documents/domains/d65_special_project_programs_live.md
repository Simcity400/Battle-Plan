optional `PLCF` trailer whose parser requires exact end consumption and its
facility rows are a flat, non-owner-joined global list. D65 owns the
per-country, owner-joined program-facility projection without changing that
payload contract.

The wiring report's rooted walk begins at
`CCountry+0xFA8 -> CProgramStatus`, with up to `3` inline status records of
stride `0x160`. Each record's vtable must be
`module_base+0x295AC88`; a mismatch ends the record walk. Record `+0x20` is the
`vector<CProgram*>` begin and record `+0x28` is its packed count/capacity
header. Every element must have vtable `module_base+0x295AC30`, and the exact
wiring predicate is `count!=0 && count<=capacity`.

The wiring report states that the packed header's low 32 bits are `count` and
high 32 bits are `capacity`. Present exact-a729 code states the reverse,
low32=`capacity` and high32=`count`, and contains a claimed stable
`low32=2/high32=1` observation across `1,022` frames. The eight-source packet
does not independently authenticate that later observation, so this ordering
conflict is unresolved; neither ordering is promoted here as mechanically
proved current layout.

The wiring-established `CProgram` fields are `program_id@+0x0C`,
`province@+0x174`, and `unread_prototype_rewards@+0x178`; owner is initially
the walked country's tag-db id. Present code additionally claims duplicated
owner handles `@+0x18/+0x170` and duplicated province ids `@+0x1C/+0x174`,
requiring both copies to agree. Those later claims are not independently
proved by the eight sources and conflict with the wiring report's unresolved
owner attribution below.

The earlier owner-attribution experiment had no validated intrinsic owner
field and therefore admitted a pointer only when reachable from exactly one

`PARTIAL_DATA`; `+0x170` was only a one-dump candidate requiring unpaused,
multi-country validation. Present code claims that duplicated
`+0x18/+0x170` owner fields resolve the gap and emits `dropped_ambiguous=0`,
but this source packet does not supply the validating observation. The
owner-join conflict therefore remains open; the `21/26` unique-reachability
result is the last source-authenticated disposition.
