## UI ATLAS CAPTURE — CRASH DOSSIER (read before ANY further live attempt)

Eight live sessions on 2026-07-03 hardened ui_pass substantially and ended at
a genuine unresolved interop hazard. Fixed and committed along the way (all
live-verified): session finished before UI states could capture (three
stacked causes: readiness ignored the armed sequence; ui_pass wasn't pending;
the DLL finisher had a hardcoded 180s timeout that --dwell-ms never reached —
dwell now rides the control file); the ui_pass open condition required
depth-off but the game draws its whole UI with a DSV bound and DepthEnable=TRUE
(open now keys on backbuffer-RTV match alone — diagnostics events count every
rejected leg); per-draw capture panics are contained via catch_unwind; the
harness map phases now render offscreen like the real game.

THE UNRESOLVED CRASH: with ui_pass armed, UI draws 0 and 1 capture perfectly
(byte-exact payloads); UI draw index 2 (a 4-vertex non-indexed Draw) kills
the game with EXCEPTION_ACCESS_VIOLATION at the SAME address every time,
d3d11.dll D3DKMTOpenResource on top of our DLL frames. Progressively
disproven: NOT a Rust panic (catch_unwind in place); NOT the staging
CopyResource of a shared buffer (guarded by MiscFlags shared-mask — same
crash); NOT the CB byte readback at all — the final attempt captured CB
binding METADATA only (VSGetConstantBuffers/PSGetConstantBuffers + GetDesc,
zero copies) and still died at the same address at the same stage
(breadcrumb 'constant_buffers', draw 2). CONCLUSION: merely RETRIEVING that
draw's constant-buffer object through the immediate context triggers a lazy
kernel-mode resource open that faults. Hypothesis with the best fit:
cross-device shared-handle interop — the game's UI embeds a browser overlay
(Paradox social/DLC bar) whose resources are opened from shared handles of
another device; the proxy object faults when first realized from our call
context. Draw 2 is plausibly the browser-overlay composite quad.

NEXT STEPS (offline, in order): (1) skip the ENTIRE constant-buffer stage
(not even Get*) for ui_pass and see whether draw 2 then dies at draw_state's
OMGetRenderTargets — cheap, but costs a live run; (2) proper root-cause:
WinDbg attached with our DLL's symbols + D3D11 debug layer, capture the
faulting call precisely; (3) consider draw-2 avoidance: skip capture for
draws whose PS/VS were never seen through our create hooks (browser overlay
shaders are created before injection or on another device — our shader-file
events for draw 2 would show unknown bytecode); (4) alternatively defer ALL
ui_pass introspection to a Present-time snapshot instead of mid-draw hooks.
Evidence: breadcrumb trails in C:\Users\Example\AppData\Local\hoi4_captures\
live_UI_ATLAS (+ live_UICRASH_DIAG), the game crash reports under Documents\
Paradox Interactive\Hearts of Iron IV\crashes\hoi4_20260703_15*/16*, and the
ui_pass_open_diagnostics event (backbuffer detection is proven: 0 mismatches).

## 2026-07-04: water-pass world seam root-caused and fixed

The straight seam across the ocean (water surface missing north-west of the
map diagonal (0,0)-(5632,2048), mismatched water color across a dead-straight
world-anchored line) was an out-of-bounds vertex fetch. The capture records
the byte range a draw consumed, not the game's full pool buffer; live_PAN2's
water quad declares POSITION as R16G16B16A16_SINT (8-byte fetch, 4-byte
stride, 16-byte recorded buffer), so the 4th vertex's fetch ran past the
replayed buffer and the GPU returned zeros, collapsing the triangle strip's
second triangle. Sessions whose capture recorded a single-element layout
(session_20260702d) never hit it — which is why parity gates stayed green
while the product view was broken. Fix: every replayed vertex buffer is
zero-padded by 16 bytes (exact for consumption; in-bounds components are
untouched). Debugging law reinforced twice tonight: python os.path on the
OneDrive worktree silently fails past MAX_PATH — compare capture payloads
with bash md5sum or short-path clones, and never trust a "file missing"
result from python on long paths.
