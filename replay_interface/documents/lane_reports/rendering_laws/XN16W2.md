# XN16W2 — exact future-capture admission gate

Status: **PROVEN — fail-closed admission validator frozen; known replacement rejected**

XN16W2 consumes the proven XN16W retained-corpus absence and defines the only
admissible future closure for the `live_trees_measure` synchronized water+rivers
gate. It does not change XN16's current disposition. The normative contract is
`replay_interface/re_evidence/rendering_laws/XN16W2/admission_contract.json`.

## Admission law

The validator admits only one capture-root/round tuple containing terrain,
water, rivers and trees with:

- exact `hoi4.exe 1.19.2.0.a729` SHA-256
  `870ebf1f615262facca48a3b947775c41f0a5338f3068c40958209f5c41c65ad`;
- terrain draw 6 VS/PS `e5a0acbee3ae07a2` / `ce5e5185d46e214b`
  and exact CB0 `619059c647782be4`;
- water VS/PS `d79141c041404109` / `5939c77566452cc9` and byte-identical
  terrain CB0 `619059c647782be4`;
- rivers VS/PS `8eb490dfbd97857c` / `5be8efce15bc2c80` and exact CB0
  `9c2d9a7336c291e4`;
- trees VS/PS `02bd512fa7acd53f` / `277b7b5e8964214f` and byte-identical
  rivers CB0 `9c2d9a7336c291e4`.

All four bundles must be `pass_close` finalized, blocker-free and nonempty. Each
must carry post-pass RTV/DSV bytes and both clear records. The same local
`map_capture_session.json` and ordered `terrain_capture_events.jsonl` must prove
one clean `terrain -> water -> rivers -> trees` round. The capture-root manifest,
production verification and event start/finish paths must independently bind
the same round.

After scene identity succeeds, every bundle/runtime/output payload must remain a
local descendant of that round, match its declared length and FNV-1a64, and have
exact size/SHA-256 membership in the same capture-root evidence manifest.
Pointers, view handles and RenderDoc ResourceIds are never admission identities.
Any failed check produces `REJECT`; the sole success status is
`ADMIT_EXACT_SYNCHRONIZED_TREES_MEASURE`.

## CLI and result interface

```text
python replay_interface/re_evidence/rendering_laws/XN16W2/validate_xn16w2.py \
  --capture-root <capture-root> \
  --capture-round <capture-round> \
  --output <result.json>
```

The result schema is `hoi4-rendering-laws-xn16w2-admission-result-v1`. A result
is promotion-admissible only when `status` is exactly
`ADMIT_EXACT_SYNCHRONIZED_TREES_MEASURE`, `rejection_codes` is empty, every check
passes, and `admitted_artifacts` contains all four pass identities. A missing,
unreadable or nonmatching artifact fails closed.
