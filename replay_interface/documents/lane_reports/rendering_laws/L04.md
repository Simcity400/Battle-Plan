## Exact promotion law

The compiled shader executes the following ordered scalar program. This is stricter than the HLSL
source expression because it freezes the compiler's base-2 exponential lowering and operand order:

```text
sum_f32 = nested y-then-x ordered accumulation of t0.r samples
tap_count_f32 = GatherSize.y * GatherSize.x
mean_f32 = sum_f32 / tap_count_f32
target_f32 = exp2(mean_f32 * 1.442695f)
target_f32 = max(target_f32, MinHdr)
target_f32 = min(target_f32, MaxHdr)
last_f32 = point_sample(t1, uv=(0.5f,0.5f)).r
difference_f32 = target_f32 - last_f32
decay_f32 = exp2(CB2.z * -1.442695f)
gain_f32 = 1.0f - decay_f32
adapted_f32 = mad(difference_f32, gain_f32, last_f32)
current_r16 = D3D11 R16_FLOAT render-target conversion(adapted_f32)
```

The verifier requires 12 ordered disassembly anchors from the tap-count multiply through the final
`mad`. Therefore the closed semantic order is:

`ordered reduction → exp2 lowering → min/max clamp → previous sample → exponential easing → mad → R16 conversion`.
