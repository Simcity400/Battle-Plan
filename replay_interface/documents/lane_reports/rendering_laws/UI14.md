## Production promotion law

The extractor/replay seam records the order instead of guessing it.

For every active source layer it must retain:

- a stable layer ID and kind (`vanilla`, loose/archive DLC, loose/archive mod);
- descriptor identity and SHA-256;
- the observed engine descriptor or mount ordinal;
- source namespace digest and, when materialized, staged namespace digest;
- every `replace_path` in descriptor order;
- exact content-root provenance.

For every effective relative-path key consumed by UI or scripted UI it must retain:

- the normalized key and consumer class;
- candidate layer IDs in observed low-to-high precedence order;
- `replace_path` exclusions in application order;
- winning layer, concrete loose path or archive-member identity, byte length, and SHA-256.

The recorded engine ordinal and effective winner row are authoritative. Launcher-array position, descriptor filename, DLC/mod display name, category, and storage kind must never be invented as precedence. In the proven loose-mod case, later observed engine descriptor ordinal wins. Other mixed layer cases require a recorded effective winner or exact admission by the UI15 staging matrix.

Normalization follows the already-tested replay namespace law: separator folding, duplicate/dot removal, and ASCII case-folded collision keys. `replace_path` removes lower-layer files only in the exact immediate-parent directory, non-recursively, before the current layer may re-add a file.

Archive mods are admitted only with the selected launch's authenticated UI14 layer/order and complete collision-winner roster. UI15 additionally requires stable container hashing, safe member normalization, exact source/staged namespace equality, and playback-side container/payload authentication; any missing or contradictory join fails before renderer handoff.
