# XN15 — effect-trigger recording

Status: **PROVEN — recording contract ready to promote**

XN15 defines the semantic event/state stream required to reproduce XN12-XN14 at the same identity, position, phase, ordering and engine tick. It does not restate their renderer equations. The normative machine contract is `replay_interface/re_evidence/rendering_laws/XN15/recording_contract.json`; every binary/static/capture provenance tuple is in `replay_interface/re_evidence/rendering_laws/XN15/evidence_ledger.md`.

## Exact production stream

The stream has six synchronized tracks under one monotonically increasing `sequence_u64` total order:

1. **Effect lifecycle events.** Record spawn, activate, deactivate, stop-emission, destroy and reparent with stable effect-instance id, exact case-sensitive registration token and FNV-1a32, resolved effective-VFS definition digest, producer identity/event ordinal, parent entity+node or world transform, initial RNG words and runtime flags. Process pointers are never recording identities.
2. **Submitted particle packets.** At every retained render submit, record the engine-sorted post-simulation packet sequence from the `0x14227f420` boundary: instance/material/effect identity, packet matrix and flags, live records/transforms, strides/counts and draw ordinal. This is the sole admitted v1 particle-runtime mode.
3. **Entity presentation.** On change, record stable entity id, resolved entity digest, semantic state/animation/transition/phase, chance resolution, world transform, visibility/selection/damage flags. At each retained entity submission, record pass ordinal and either explicit `NotSkinned` or a content-addressed 3,200-byte 50-matrix palette reference. A palette is deduplicated only when its bytes match.
4. **Direct visual producers.** For strategic-air scenes, naval combat scenes and trade-route convoys, record the direct create/show/hide/state/effect/expiry/destroy sequence with stable producer/entity/effect ids, resolved entity source, authored state/event ordinal, live animation or motion phase, exact transform and node/locator, visibility, direct live-list count, RNG words and effect expiry. Checkpoints preserve the ordered active producer/entity/effect membership. A4R1 and SCH1 accounting snapshots never synthesize this track.
5. **Entity lights.** Preserve the exact authored state/event ordinals and ordered scalar payload, then record lifecycle operations with stable light id, exact resolved-or-null token, actual trigger tick, animation phase and parent anchor. Every retained tiled-light submit carries raw `GridStart_InvCellSize` float4 bits, the complete 64×64 BGRA8 index payload (four ordered u8 slots per cell; `255` sentinel), the complete 128×1 RGBA32F data payload (two texels per light: XYZ/radius then post-evaluation RGB/falloff), writer/update/submit indices, content hashes and stable slot-to-light joins. Authored animation and tile selection are never re-evaluated as a substitute.
6. **Weather state.** On change, record region id; the rain-light, rain-heavy, snow, blizzard, sandstorm and arctic-water flags; the exact signed fixed-point value at `+0x138` (interpreted as value/100000); the absolute game hour at `+0x150`; the priority-derived airborne runtime code; and the resolved-or-null weather-effect token. For every ordered position record its ordinal/class, instantiated-or-explicit-empty resolution, selected authored-effect index, primary and fading entity ids, ordered effect-instance ids and resolved variant. Code zero requires a null global token and explicit-empty/null membership at every position. A nonzero code requires a global token. A big position uses the big vector only when nonempty and otherwise selects the small vector; a small position selects the small vector. If that selected vector is empty, membership is explicit-empty and no PRNG draw occurs. Sandstorm's sole authored row is `small=no`, so a small position still resolves to explicit-empty membership. The airborne producer has no intensity scalar and no weather-transition interpolation: a visual-state change destroys and recreates airborne entities while primary/fading membership is preserved explicitly. Particle lifecycle/phase remains in the effect and submitted-packet records. Snow/mud accumulation remains the existing, separate ground-state stream.

The standalone XN14 weather-interface slice freezes these field types, nullability, priority, membership and exact selected-vector branch independently of XN15; the exact immutable tuple is recorded in the evidence ledger.

Each update and submit records the engine update/submit index, simulation tick or interpolation phase, and its inclusive sequence range. Engine floating-point inputs are serialized as raw IEEE-754 bits. The consumer may not re-sort by token, id, producer or authored file order.

The packet/palette stream is render-submit cadence, not hourly-snapshot cadence. Short-lived effects can begin and end between two gameplay snapshots; an hourly diff cannot recover their tick, population, phase or order.

## Why lifecycle events alone are not exact

XN12B proves that the two RNG words are initially seeded from high-resolution wall-clock time, then particle state evolves through arbitrary elapsed-time substeps, parallel workers, attachment transforms, recursive subsystem/child updates and camera sorting. Live state includes `0x88` subsystem blocks, `0x70` particle records, `0x30` transforms and emission accumulators. Effect token plus start tick—even with a nominal seed—cannot recreate the same submitted packet sequence. The exact v1 handoff is therefore the post-simulation sorted packet stream, not an inferred replay-side particle simulation.

## Static joins and VFS identity

The recording does not duplicate authored particle/entity files. Its header pins the effective ordered-VFS manifest plus effect and entity/animation catalog hashes. The static catalog supplies event `time`, `node`, `particle`, `keep_particle`, `trigger_once`, subsystem definitions and asset/material/texture resolution. Duplicate tokens resolve only under that pinned effective VFS. Unknown particle identity is the engine's exact null/no-spawn outcome; no alias or substitute effect is permitted.

XN15B found 816 authored light-bearing events and ten shipped light tokens. Preserve duplicate authored scalars in order: `nuke_big_entity.attack` event ordinal 2 carries times `[4, 0.5]`; runtime `actual_trigger_tick` is authoritative, and undefined `nuke_flash` is explicit null/no-light, never an alias to `nuke_big_light`. The excluded carrier row with ordered nodes `[idle_foam, flying_plane_loc]` likewise uses the recorded runtime parent anchor—never a static duplicate-node winner.

## Unit pose and pass semantics

The retained XN13 capture shows that a skinned submission consumes exactly 50 float4x4 matrices (3,200 bytes), not 80. Palettes can legitimately advance between pass groups for the same object, so an object-level or frame-level palette reference is insufficient. The key is `(submit_index, pass_ordinal, entity_instance_id)`. Semantic state/phase remains required because it selects authored particle events, including aircraft trails and naval wakes, but it cannot replace the exact per-pass palette until a separately proven evaluator produces byte-identical palettes.

XN14B validates the weather handoff capture-side across 199 retained frames: 22,133 matched draws / 805,249 instances, including 5,759 exclusive-weather draws / 562,284 instances, with zero event-only misses. Every label is joined through same-RDC payload identity; capture-local RenderDoc ResourceIds are never transported between captures.

## Cold seek and scrub

Packet and palette records are indexed by submit. A cold seek loads the exact records for the target submit and joins them to lifecycle/entity/direct-producer/light/weather state reconstructed under the authoritative sequence order. Required equality is not visual tolerance: seek-to-submit must equal linear play for active effect identities, ordered particle packet bytes, ordered entity submission/palette bytes, ordered direct-producer membership, ordered light submissions and weather-instance membership. Missing sequence ranges or records fail closed.

## Storage law

The stream is compact where semantics permit it:

- lifecycle, entity presentation and weather records are change events;
- static assets are referenced through pinned catalogs, not copied per event;
- packet blocks and 3,200-byte palettes are content-addressed and byte-deduplicated;
- per-pass references preserve order even when the referenced bytes deduplicate.

No lossy quantization, phase resynthesis or visually similar effect substitution is allowed. Promotion must publish measured byte totals for event log, packet blocks and palette dictionary so the product can choose retention cadence without concealing cost.

## Fail-closed rules

Reject unknown/mismatched build or catalog identity, missing sequence ranges, duplicate live ids, transitions for unknown instances, unresolved anchors, missing packet records, missing per-pass palette for a skinned submission, incomplete tiled-light payloads or slot joins, and weather effect ids absent from the particle packet stream. `NotSkinned`, engine-null particle lookup and measured-empty weather membership are explicit states, not missing data.

## Current recorder disposition

The existing typed replay view does not expose effect instances, particle records, animation phase or skinning palettes. Its division movement and weather kind/intensity data remain useful gameplay state, but are not substitutes for this stream. Promoting XN15 therefore means adding this contract to the extractor/container/replay ingest path and passing byte-roundtrip, ordering/lifecycle, catalog-resolution, cold-seek, per-pass palette and weather-membership gates. The remaining work is implementation against a proven schema, not unresolved reverse engineering.
