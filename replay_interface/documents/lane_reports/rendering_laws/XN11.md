## Exact replay law

The production replay layer must parse the effective mod-aware
`common/map_modes` database, retain its deterministic database order, and assign
each accepted scripted mode `id = 40 + index`. Selection stores the selected
mode object and installs its two gradient sources.

For a scripted layer of type `country`, `state`, or `state_controller`:

1. Evaluate `targets` if present; otherwise enumerate every legal object of the
   layer type.
2. Establish ROOT/FROM scopes exactly as stated in XN11-04.
3. If thickness is enabled, seed `thickness` to fixed-point `100000`.
4. Evaluate `color`. A false result emits no border record.
5. Read `alpha`, clamp it to `[0,100000]`, and stop if it is zero.
6. Read and clamp `red`, `green`, and `blue` in that order. Convert all four
   channels to floats with `channel / 100000.0`.
7. Apply `highlighted`; select static thickness code `0xf4`, or the dynamic
   path described in XN11-06; append the target province IDs in evaluator order.
8. Commit bottom slot `15`, then top slot `16`, then update the map compositor.

Layer `none` emits nothing. Hard-coded layer enums delegate rather than entering
this evaluator.

## Registry, defaults, and strings

The loader allocates `0x118` bytes per mode and initializes each layer with
`type = country` and `thickness = false`; text defaults are `none` and
`update_daily` defaults false. The mode database is also the source for UI
enumeration and localization identities. Dynamic entries follow the built-ins
in database order. The engine derives `MAPMODE_<UPPERCASE_NAME>`, plus the
documented `_NAME`, `_DESCRIPTION`, tooltip, and sprite-key families.

This corrects the preliminary attribution in `UI_LAYOUT_LAW.md`: function
`0x140aa0680` is the scripted-mode database loader/object constructor, **not**
the per-border colour evaluator. The evaluator is `0x140aa14a0`.

## Production audit and fail-closed contract

The current `native/map_viewer` has explicit built-in map-mode modules but no
generic `common/map_modes` registry/evaluator. Promotion therefore requires a
new generic scripted-mode adapter, not additions to those mode-specific
modules. It must consume the production mod-aware resolver and the replay's
captured country/state/controller/player/script inputs.

Fail closed for any of the following:

- parse errors, unknown properties that affect evaluation, or invalid type/text
  enums;
- a requested dynamic ID/name absent from the effective database;
- unavailable target, controller, ROOT/FROM, scripted trigger/effect, or temp
  variable semantics;
- missing built-in delegate for a `game_map_mode_*` layer;
- incomplete replay state for a selected scripted mode.

Do not substitute a default colour, guessed target set, tuned thickness, or
mode-specific implementation. Vanilla remains unchanged because it defines no
scripted modes.
