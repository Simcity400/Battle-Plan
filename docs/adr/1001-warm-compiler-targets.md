# 1001. Publish warm Cargo targets after validating them against a worktree

An active seed record points to one of two checkout and build slots. Refresh the other slot and publish its record after the build and index are ready. A warming job holds its seed slot until it finishes copying. A writer holds the update lock, honors active readers, and creates its ownership record atomically. Older launcher and lock formats are recognized so they cannot race a refresh. A scheduled refresh uses the launcher at the seed commit or the fallback tool when that revision has no launcher.

A second updater is refused even in the same process. A missing or empty PID in a newly created legacy lock can mean a writer has yet to publish its identity. Reclaim it once it is stale, but let competing updaters recheck the claim under the lock. When the scheduler runs without an explicit repository, resolve the branch from a slot checkout even if that checkout's HEAD is older. An interrupted replacement that never publishes its slot leaves the previous seed available. A worktree builds into its own copy and cannot change that seed.

Seed the same test units nextest will run and keep all successfully compiled useful units even if some crates fail. Drop outdated units and large incremental sessions tied to individual compiler runs. Cargo recreates top-level uplifted artifacts and locks from its dependency outputs. The copier treats partial Robocopy results as failures. Choose additional storage by available space, but preserve the worktree's target path through a junction so emitted paths remain consistent. Record the staging owner before copying. Only a previous warm's owned directories can be swept. Verify the Git top-level before checkout so an incomplete slot cannot modify its enclosing repository.

Index the pinned toolchain's dep-info with package and target roots and track the environment with each unit. Handle absolute paths outside the package, prefer the longest match where roots overlap, and decline path forms the rewriter cannot safely transform. The target index must agree with the seed stamp before reuse. Retain timestamps of target-root files and backdate only inputs proven to match the seed. Recheck them before publication so an edit racing the comparison or an older worktree timestamp cannot make stale outputs appear current. Publish the fully prepared target only after all sources that differ from the seed appear newer than its builds.

An in-place path rewrite must preserve its encoded byte length. Equal character counts can still differ in UTF-8. Respect Git's checkout settings so equal sources have equal line endings. Relative references can reach the seed through a parent component, and a partial path match cannot certify an artifact for reuse. The latest fingerprint identifies the owner of a shared unhashed executable. If a build script watches its whole package, file additions and removals invalidate its unit. Keep a worktree's valid junction and replace one whose target is gone. A later warm can sweep the removed worktree's owned profile after validating its marker and junction relationship.
