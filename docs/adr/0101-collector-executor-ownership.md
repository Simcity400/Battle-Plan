# 0101. Transfer each executor slot's ownership exactly once

The acquisition pool reserves heap cells before an hourly callback. A slot packs its generation and phase into one atomic word. The queue mutex serializes admission, cancellation and priority order. A submitter owns a vacant slot, initializes its job, and publishes pending before enqueueing. A worker removes the sole ready entry, claims running, and borrows the request in place outside the mutex. It ends job and native borrows and initializes the completion and its counters before publishing. Observers can see that publication before active accounting retires. The worker never accesses the cell again after publication. A live detached notification can advance successors using its separate ledger and retained context, which survives until all admissions and publishers settle.

One acquire transition from published to collecting gives a matching ticket's sole collector the initialized cell. Copying a report uses the same exclusion but restores published without transferring the request. Collection moves the completion directly into caller-owned empty storage before releasing vacant. Pool identity and generation prevent foreign, stale or racing ticket collection. Cancellation owns only queued requests and fills a stopped completion without running them. Parked work occupies a cell without admitting, queueing or counting a job. Parking prefers its partition and can use a spare cell. Rejection and unpark access the single initialized request under the queue lock. A rejected completion is initialized in the existing cell to avoid a job-sized stack temporary.

The callback collects every accepted request and deferred producer before dropping the live-world lease. A parent's exact child may run inline while still queued. Optional callback join help claims other eligible queued work only within its first budget and time prediction. Spurious wakes do not replenish either allowance. Candidates are charged by their predicted maximum, and the prediction is checked again after searching because bodies can progress while the queue is held. No learned history means no help. Unclassified pools disable this policy. Zero-worker pools can execute accepted requests on the collector.

An address waiter publishes its registration, then reloads the awaited word. The publisher stores the completion before loading the registration in the same sequentially consistent order, so one side witnesses the other. A value change before the actual OS wait still prevents missed completion. The active-zero barrier uses the same ordering and counts independent waiters so one exiting waiter cannot cancel another's registration. Worker joins leave the callback's awaited-ticket slot untouched. Readiness waits register before taking their notification sequence and recheck the dependency without taking an unrelated job's result. Parking holds no queue lock.

Runner failure stops new admission and cancels queued work before publishing its own result. Running peers retain their ownership. A contained panic leaves partial request observations available for teardown, with no usable report or retry. The last pool owner drops only fields initialized for each slot phase. A user panic payload can itself panic on destruction. The unwind boundaries retain it and allow other cells and tickets to drain. Context can reset only with both uncollected and active counts zero. This includes the native body and the detached notification.

Workers run above normal priority when the game is held. When the capture runs beside the game, regular workers run below it and avoid its physical core while reserves rest. A waiter can bring up reserves and raise already-running worker handles under the queue lock, while the join owns those handles until close. One wake starts a held burst, and claims relay the remaining wakeups. The reserve count follows the game's process affinity with a one-worker minimum and the executor's maximum. Memory-latency-bound reads benefit from logical siblings. The naval ancestor-reading fallback requires a worker stack reserve matching the supported executable independently of `RUST_MIN_STACK`.

Tests use observed worker entry, active-settlement watches and controlled releases to check the relevant concurrent state. Hang guards may rescue a deliberately lost wake so the fixture fails by assertion. The allocation accounting fixture includes alignment padding, Arc headers, reserved vector space and zero-sized closures. The optional submission benchmark measures submission wall costs and wake policies under a held burst and busy workers.
