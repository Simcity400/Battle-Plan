# 1001. Require whole playback runs and judge presented frames

Incomplete runs leave verdict rows with reasons and no measured figure. Require the requested playback span, consecutive frames, every seek, valid report and uncut log. A paced run may reach its stop during the last frame even when that frame's recorded head is earlier. A seek-back run must first cover its span, then draw the requested seek and keep advancing. Treat CPU reconciliation failure as incomplete unless explicitly accepted and labeled. Exclude memory-starved measurements. Preserve each measured repeat's spread and name the worst frame or hour.

Map timing requires the presented frame for the requested hour and the intended input and camera. Choose the camera before each case so one case's movement cannot change the next. Test interactions paused and while playing. A rate with no newly installed hours is evidence of frozen content. Compare playing and seek costs to a paused camera floor in the same view. Report achieved uncapped frame rate separately from the 120 Hz frame-work budget. The view acknowledgment records construction time. Use the subsequent frame log's paint completion to find when the relevant frame was shown. Subtract time waiting for a swapchain image from map thread work and join delayed GPU timings by the frame they measured. Missing frame timings or GPU observations remain explicit. For a pop-out, time its own first presented frame at the clock hour rather than the later process status report.

A hover case begins from a confirmed neutral map state. A province has a tooltip without a highlight. Grade highlights from the next frame and tooltips after the game's deliberate tooltip delay. A settings probe compares actual values independent of JSON object key order and requires evidence that the saved settings were drawn. The control budget spans trusted input to paint and accounts for intentional tooltip delays. Cold interactions are judged and their warm reversals appear beside them. For first-content reporting, count a placement once where it first showed content and use the slowest visible widget's readiness to judge the page.

The dashboard phase requires complete, session-scoped performance records. Check the actual clock speed, timestamped and dated widget presentation, and displayed refresh intervals. Require timing for every measured frame, because untimed frames can hide a failure. The dated path waits two 60 Hz frames for a worker to adopt a new anchor. A seek transition can temporarily unmount every canvas, so take the placement baseline only after a dated surface appears. A widget with no dated worker surface is explicitly unjudged there. Exclude anchor settling, follow protocol messages and paused requests from playback request budgets. Each chart tile or list window should be requested once. Judge list requests against the crossed blocks plus two ahead, and chart tile requests against the crossed tiles plus one ahead. Flag any lost measurement or relevant console error.

Use DevTools traces in a separate window to attribute style, layout, raster, script and GPU work without distorting the ordinary playback timing. Sum each span's own time exclusive of nested events. Identify the busiest renderer main thread during the window, because a pop-out has another renderer. Keep the raw trace and describe invalidated nodes that still exist. Golden map sweeps keep unrequested scenes for the same recording and reuse the first scene's shader compilation. Serialize performance measurement with a process-owned mutex and give the program a bounded time. Preserve partial logs and absent metrics so older report columns cannot be mistaken for zero.
