# Map playback reads recording facts in place

The map opens on the recording's main timeline. A recording shares its opened native runs between map readers, while each reader owns a cursor for its branch and hour. Index preparation starts on the first map read. Presentation can take an already decoded frame without decoding again, and retains that frame's identity after releasing the load-time cursor. Once a playhead reader supplies an air-roster sampler, the map and other readers on that recording and timeline share it. Before that, an opened native map source supplies it.

A seek to an exact hour distinguishes a gap named by the recording from a read error or a missing binding. Some row frames leave their map tables entirely in the native capture. A map that needs those tables is refused by name until bound, and re-reads its held hour after binding. An interrupted read can be retried. The row decoder can reuse a decompressed block and pass earlier hours it visits on the way to the requested one. A native map cursor reads each requested hour on its own. If an earlier hour matters, callers ask for it explicitly. Native frame reads validate a complete campaign row against the replay header. The viewer's range includes explicitly lost hours at either end of a timeline.

Background native reads use below-normal-priority workers and leave capacity for interactive rendering, the driver and the game. The regular playback source can apply deltas into storage once it no longer owns a previous frame. Other owners of displayed data keep immutable frames.

## Separate map facts from presentation assets

Map placement data, terrain assignment, sampled heights, rivers and tree positions are recorded facts. Content paths under `map/` are checked against the recording where they supply those facts. A nonzero tree bitmap pixel places a tree independently of the terrain assignment. Terrain, water and city-light textures, the world normal map, shaders and the matching graphics defines are presentation assets. The selected visual mod stack supplies them when it can. If it cannot supply or decode an asset, including its required color space, the viewer names the failure and falls back to the recording. The arrow effect, movement arrows and order label follow the same arrow definition and come from one stack. The reflection texture retains its DDS view type so a cube lookup on a 2D texture reproduces the native hardware result.

Map icon resources are loaded before placing native GUI windows. The initial resource set does not depend on a view's viewport. `WindowCache` places each actual window at its own viewport. Shared GUI registries let later font and color overrides affect both GUI and map text. Static icon pages have stable indices. The localisation pass adds the GUI resources after all other static pages, drawing both registries' extra labels and keycaps from one harvest. Flags and portraits decode on first draw using retained content layers. A refused sprite, font or window resource names why.
