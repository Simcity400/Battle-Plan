# 1191. Keep naval bases written until their drawn state settles

A written base stands after two consecutive updates with the same decided inputs, when the second update is quiet. A first write can set a frame before replacing a drawable that resets it. Similarly a grid can copy its old opacity before its fade ends, or an item can finish moving away from where grid finalization places it. The second quiet write establishes the complete state. A settled base retains the overflow count rather than treating omitted port items as absent input. A decided base that still needs the next write asks the view for a frame.

Use the previous decided roster and its overflow to determine which port items occupy the grid. An item animating and currently visible keeps the base updating and asks for future frames. An item recovering withheld transition history keeps the base updating while its own movement settles and once more afterward. An independently refused part can leave its item undrawn, so its animation requests no frame. An item removed from the roster or excluded by grid capacity does not affect either decision. The base's glyph and its port grid remain one update, with authored order.

An undecided roster never stands. It retains the held items under named part and transition refusals, and waits for fresh recording evidence. A base that structurally fails its update loses its own settled state and is withheld individually. Other bases keep their written state, and a base that cannot apply its update does not owe a redundant frame. Transition unknowns distinguish one-time allocation or pool growth from an update that continues to fail. A one-time event starts a wait that can advance future frames, even when a repeated refusal also touched the window. A recurring refusal by itself cannot advance the wait and asks for no frames until it stops. The frame request combines this settling work, visible animation and outstanding base writes.

A written base can adopt the current hour's country table when every relevant flag input agrees. The comparison runs once per previously held table and adoption lets subsequent updates compare table identity. Kept viewport layout uses a resource stamp covering asset, template, localisation and country identities, viewport and GUI scale, and decoded art revision.
