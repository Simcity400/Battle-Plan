# 1401. Lane acknowledgement FIFO and speculative post-serve hand-over

## Context

`Lane.frame()` previously merged every pending `FrameRequest` into a single `this.request` field (concatenating `installed` and `refused` across frames) and `Lane.run()` re-scheduled follow-up work from `finally` via `queueMicrotask()`.

In a Web Worker, incoming `postMessage` frames (`self.onmessage`) arrive as macrotasks. Because the microtask checkpoint executes immediately after a `serve()` finishes—before queued `onmessage` macrotasks are dequeued—a lane whose paint plus present (including weak-CPU `stretch()`) takes longer than a display frame interval starts the next `serve()` on an already-stale queued request instead of coalescing newer frames waiting behind it in the worker's task queue.

At the same time, deferring idle or exact frames, or merging acknowledgements across frames during a serve or post-serve hand-over, changes user-visible ordering: a pointer after an acknowledgement can hit the previous picture, a `kept content` refusal followed by a valid install can clear the install (#306), and an exact frame or exact `wake()` repaint held behind a speculative hand-over can be lost.

## Decision

1. **Acknowledgement FIFO and single request slot (`ui/src/draw/lane.ts`)**:
   - **Acknowledgements (FIFO of per-frame batches)**: never merged across frames. Outside an active serve (`!this.serving`, covering `idle`, `scheduled`, and `hand-over`), each frame's `installed` then `refused` batch applies immediately on receipt and releases freed bytes so `pointer()` always sees every acknowledgement that arrived outside a serve. While a serve is executing (`this.serving === true`, covering `serving` and `awaiting crop`), batches queue in arrival order and flush in FIFO order when that serve finishes, before any hand-over wake. Processing time spent applying acknowledgements outside `serve()` accumulates in `ackMs` and is consumed once at the start of the next `run()`, charging paint budget, `stretch()` (including on both cancellation exits), `served.ms`, and `overBudget`.
   - **Single pending request slot**: preserves `main`'s single `this.request` and `this.lastExact` replacement rules (exact frames are never kept in a separate mid-serve slot whose unacknowledged `SAME` could leave `Page` in `reading` on a following speculative frame).
2. **Speculative-only post-serve hand-over (`ui/src/draw/lane.ts`, `ui/src/draw/laneDispatch.ts`, `ui/src/draw/lane.worker.ts`)**:
   - Add an optional `schedule?(run: () => void): void` callback to `LaneHost` and `LaneSide`, defaulting to `queueMicrotask` when omitted.
   - Keep `Lane.schedule()` on `queueMicrotask` so idle and fast lanes behave identically to `main`.
   - Exact requests are never held in `hand-over`: at serve completion, if `next?.exact` is true, `finishRun()` schedules immediately from a microtask; if an exact request arrives in `schedule()` during `hand-over`—whether from `frame()` or from `wake()` recreating `lastExact`—`schedule()` ends the hand-over immediately (`inHandover = false`, `handoverToken++`, `working = false`) and queues a microtask so any late wake is a no-op.
   - Export `macrotaskSchedule()` and `cropAll()` from `ui/src/draw/laneDispatch.ts` and wire them in `ui/src/draw/lane.worker.ts` (`startLaneWorker`): when `MessageChannel` is available, `macrotaskSchedule()` binds each posted message to its own token and callback in a `Map` so an invalidated wake from an earlier interrupted hand-over can never invoke a later hand-over's callback; when unavailable, it returns `undefined` so `Lane` keeps `queueMicrotask`. `cropAll()` closes any fulfilled sibling bitmaps before rethrowing if a crop batch partially rejects.
3. **Pre-serve and post-crop superseded-seek guards and cancelled-paint reporting (`ui/src/draw/lane.ts`, `ui/src/draw/laneMessages.ts`, `ui/src/draw/notifications.ts`, `ui/src/dashboard/follow/pipeline.ts`, `tools/e2e/datedPlayback.mjs`)**:
   - Clear older `lastExact` in `Lane.stream()`.
   - Check `seekSuperseded(request.seek)` at the start of `Lane.serve()`: release freed fact bytes, call `host.stretch?.(time() - began)`, emit `host.served` with `changed: 0, cancelled: true`, and skip paint and `prune(request.now)`.
   - Check `seekSuperseded(request.seek)` again after `await this.host.crop(...)` and before `present()` / `prune(request.now)`: close all returned bitmaps, retire `entries` from `this.presented`, clear matching `widget.inflight`, set `widget.forceFull = true` and `widget.sent = {}` (consumed only when a full `picture` entry is built; while true, the widget passes the matching-installed-picture check and bypasses `canRedate`, so neither a queued refusal nor unchanged facts on a pinned widget can suppress the full repaint), restore unsent reset/close flags, release freed bytes, call `host.stretch?.(time() - began)`, emit `host.served` with `changed: 0, cancelled: true`, and return without calling `present()` or `prune(request.now)`.
   - Forward `cancelled: true` onto `workerFrame` records and exclude cancelled frames from worker presentation rate, `workerGapP95`, `emptyMs`, and empty-page baseline `workerMeanMs` in `tools/e2e/datedPlayback.mjs`.

## Hand-over state machine

| State | `frame(speculative)` | `frame(exact)` | `wake()` (data / `touch` / `exact` / motion) | `stream(seek)` | `serve()` completes | Posted wake delivered |
| --- | --- | --- | --- | --- | --- | --- |
| `idle` (`!working`) | Apply acks (`ackMs`); set `request`, clear `lastExact`; -> `scheduled` | Apply acks (`ackMs`); set `request` & `lastExact`; -> `scheduled` | If `!request && lastExact`, set `request = lastExact`; -> `scheduled` | Clear older `lastExact`; seek `Facts`, dirty route widgets | — | No-op |
| `scheduled` (`working`, `!serving`, `!inHandover`) | Apply acks (`ackMs`); replace `request`, clear `lastExact` | Apply acks (`ackMs`); replace `request` & `lastExact` | If `!request && lastExact`, set `request = lastExact` | Clear older `lastExact`; seek `Facts`, dirty route widgets | — | No-op |
| `serving` (`working`, `serving`) | Queue acks FIFO; replace `request`, clear `lastExact` | Queue acks FIFO; replace `request` & `lastExact` | If `!request && lastExact`, set `request = lastExact` | Clear older `lastExact`; seek `Facts`, dirty route widgets | Flush acks FIFO (`ackMs`); if `host.schedule && !next?.exact && (next \|\| overBudget)` -> `hand-over` (arm motion if `!next`), else `working = false` and -> `scheduled` (if `next`) or `idle` (arm motion) | No-op |
| `awaiting crop` (`working`, `serving`) | Queue acks FIFO; replace `request`, clear `lastExact` | Queue acks FIFO; replace `request` & `lastExact` | If `!request && lastExact`, set `request = lastExact` | Clear older `lastExact`; seek `Facts`; crop resolution sees `seekSuperseded` -> close bitmaps, set `forceFull`, `stretch()`, emit `cancelled: true` | Same as `serving` | No-op |
| `hand-over` (`working`, `!serving`, `inHandover`) | Apply acks (`ackMs`); replace `request`, clear `lastExact`; stay `hand-over` | Apply acks (`ackMs`); set `request` & `lastExact`; `schedule()` ends hand-over (`handoverToken++`) -> `scheduled` | If `!request && lastExact`, set `request = lastExact`; `schedule()` ends hand-over (`handoverToken++`) -> `scheduled` | Clear older `lastExact`; seek `Facts`, dirty route widgets | — | If token matches current `handoverToken`: end `hand-over`, `working = false`, -> `scheduled` (if `request`) or `idle` (arm motion); stale token: no-op |

`pointer()` hit-tests `widget.installed?.hit` immediately in every state, reflecting every acknowledgement that arrived outside `serving`/`awaiting crop` and every mid-serve batch flushed before `hand-over`.

## Consequences

- Idle lanes and exact frames preserve `main`'s microtask ordering; cross-frame acknowledgement ordering is fixed both mid-serve and during hand-over (partially addressing #306).
- Speculative frames delivered to the worker before a post-serve wake collapse into the newest before the next paint starts, keeping slow paints close to the playhead.
- Observed on `--profile weak8` at 1,440 h/s across three alternating pairs against `main`, each started only after system CPU was below 30% (all 6 exact audits passed in every run): `game-score` lag p95 dropped from 5,070 h to 87 h (Pair 1: main baseline `usable=true`, branch `usable=true`), 3,477 h to 98 h (Pair 2: main `usable=true`, branch `usable=true`), and 4,552 h to 111 h (Pair 3: main `usable=false`, branch `usable=true`), while the other five measured widgets (`scoreboard`, `occupied-states`, `division-template`, `campaign-clock`, `faction-strength`) stayed within run-to-run noise.
- Superseded serves and partially failed crop batches close their bitmaps without leaking, charge their work to `stretch()` once, never prune facts from a newer seek generation, and do not count toward worker presentation rate, `workerGapP95`, or `emptyMs` in the audit.
- No changes to `Page`, bitmap cropping internals, `stretch()` ordering, or `ui/src/families/`.
