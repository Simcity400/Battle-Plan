# 0301. Keep shared dashboard product contracts at source boundaries

The base layer keeps recording sources, content access, and product helpers used by the dashboard products. The dashboard owns the registry and service and re-exports the old paths. Tests use the viewer’s allocator, and higher layers use opt-in fixture builders. A source’s latest value is retained per branch, while superseded values remain available only as long as a reader holds them. Products distinguish damaged frames from other recording gaps so the former retain storage diagnostics and the latter can say which data was unavailable.

Keep map-recording table selection alongside the native and shared authored readers that need it. Selection includes data used by both the deployed and career experience views, and the trigger and effect operands needed by hover text across map modes. The source census follows Rust’s module graph and checks named table reads and typed schemas in macro tokens. Comments and string literals do not count as reads. Viewer table IDs also declare selection, while helper catalogs can contain unrelated families and are checked through typed operand uses. This keeps future reader inputs from silently dropping out of map recording selection. The coverage test resolves this checkout at runtime when its executable was built on Boat.

The shared core contract names no product. Metadata preserves the recorded campaign key across recordings and keeps coverage separate from capture status. Branch bounds include missing leading or trailing hours. Report capture gaps independently of recovered frames, and keep intervals of missed events separate from frame gaps. Join evidence identifies whether counters, process continuity or a user choice decides a lineage. Unconfirmed joins expose alternatives. The country catalogue starts from each branch’s first complete observation instead of claiming membership for all hours. If no such table is readable, mark that membership unknown. Build warnings are calculated when metadata is served, since the installation can change while recordings stay open. Use the recorder’s content witness for recording verification. Diagnostic identity excludes inventory samples and counts so equivalent findings can be aggregated.
