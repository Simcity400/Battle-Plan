# 1119. Prepare overlays apart from the interactive frame

The map side lays out the overlay against the step's recorded rows, keyed tables, view and counter layer products. The frame installs those together, including which layers the overlay left to the map. Later publications cannot substitute their tables or layer reports into that layout. Counter memory and the painted overlay pass between the side and frame with distinct ownership, with route caches filled away from the frame. Preparing only when the relevant inputs change avoids rebuilding counters, labels and controls on every water-animation frame. Fraction-only changes move the anchors and their sprite rectangles locally. A refused or replaced document retires the old table resources, jobs and combat providers away from the frame.

When the camera only pans within a padded placement at the same scale and extent, project the anchors and offset the existing windows by whole interface pixels. Animated movers use the frame's recorded head and each keeps its own placement history. Zoom, a free-eye change, motion outside the pad, and the first still frame after motion need a fresh placement. The paint and its offsets carry the identity of the layout they were made on. An installed but unpainted layout cannot move a batch from the previous publication. When an icon window changes what it draws it schedules a paint. A pool-only update runs only the relevant pools, and a mover alone can request a frame without rebuilding or ticking the other windows. Province updates precede the icon and unit animation that reads them. The order upload also keys each contributing producer separately, so changing a highlighted air base does not upload an unrelated plan.

Prepared influence, selection and faction highlights use the border picture actually on screen. A worker holds at most one faction job, coalesces the newest input and retires stale products away from the frame. A refused colour withholds just its highlight. A highlight built over an older border revision cannot be installed. Clearing a highlight restores the corresponding plain plans or asks the political layer to write its own current borders. The production hover and upload paths do not rebuild static border classes.

The parity gate rebuilds the shown overlay from the same rows and layer products and compares all quads with the presentation clock set aside, plus the counter, label and raid reports. Each comparison starts its own icon-window presentation and gives both layouts the same bounded pool growth. It skips clearly named cases when art, a layer's product or a needed recorded table moved so it does not compare different pictures. Skips and comparisons are counted so a run without useful comparisons does not look clean. A separate anchor check verifies moved geometry. It judges how the same windows were placed, rather than treating their movement itself as a repaint difference. Tests and profiles exercise both the same-camera layout and kept-window paths.
