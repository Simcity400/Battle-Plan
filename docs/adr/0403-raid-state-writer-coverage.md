# 0403. Refresh raid state and trade-route rows from observed native owners

Raid state observation identifies the state or country whose captured inputs may have changed. It does not call a game function for their values. The resource-gate refresh covers the state's additive gate, resource accumulators and controller-specific hash. Its callers include changes to state modifiers, occupation, garrisons, control, ownership, categories, building levels and cores, daily refresh and construction. Reset and editor paths invalidate the hour or arrive through the building family. Infrastructure changes use the building family's writer notifications. Rebuilt supply-route presence has no independent certificate and is read with the state.

The state-local dynamic list uses both the shared effect path and direct building additions or removals. The daily pass refreshes after expiry removes a modifier. Dynamic-value recalculation alone changes no recorded row. Resource addition and daily timed subtraction cover the pool. Core and claim insertion and removal are separate mutation paths, and nonpositive claim tags leave the state unchanged. Strategic locations append in their own state and province lists. Load can replace both lists. A resource origin is attached to its state on construction and removed on destruction, including the deleting wrapper. Removing an adjacent vector entry does not change another origin's membership. The country override list observes explicit addition and the clear paths used by reset, destruction and subject changes. Loading is a separate boundary.

`MUTATIONS` groups state and country-resource observers, air-site lists, claim and strategic-location lists, and routes, in that order. Every site has one patch owner, supports up to four integer or pointer arguments and preserves the original return value. `state` takes an id from the directly named state, the state owning a pool or province, the origin constructor's explicit state argument or the existing origin's backlink. A missing origin link names no state, and a failed read or zero state id refuses the witness. `country` follows the resource object's owner. `site_country` takes the strategic-air owner, the raw link argument of a constructor or giving host, or the capacity setter's raw link argument. Zero names no country and a failed compound read must be reported. The core insertion site preserves the incoming nonvolatile register save and stack reservation in its relocated entry instructions.

`RaidAirSites` records the country lists of air bases and carriers, and of rocket sites and missile ships. The gun-emplacement list is separate. Sites append after host access, controller, daily repair, construction and ship lifecycle changes. Withdrawal and destruction can remove sites, and host transfer erases the giving country's old entry before using the normal appender for the recipient. Initialization and repair at load finish can populate lists without naming one country. `pool_capacity` reads the container at the canonical link slot, including slot zero for a zero link. A missing container or unreadable input gives no value. Container creation supplies default capacity. Subsequent capacity assignments mark the country only when the stored value changes.

`DAILY_CAPACITIES` applies the same setter in the serial daily country loop after parallel work has joined. `daily_unchanged` certifies the batch only if every pair's supplied capacity equals the present container value and no state base will be withdrawn. Withdrawal removes the base and releases its containers when that air object's own state-base capacity is below one or absent. A host base is exempt from that condition. The original loop rereads its vector and links after each write. The pre-pass reads are equivalent only when no write can change those objects, their link table or the capacities. Unreadability, a changed store or withdrawn base leaves the individual setter's observation in charge.

The state-to-state route updater handles land and general naval builders. Supply routes use their port-to-port updater. Origin refresh uses the former updater, but can clear the route kind and sea-region count directly when it has no capital. `origin_route_kind` checks the only such inline change visible to these rows because the cleared count belongs to sea routes. `route_country` receives the sender, an origin's client country or the link passed by a constructor. The client owns its origin rows independently of the route's sender, including nested origin updates. Constructors and loading establish the route values and destruction removes a census entry. Exchange, lend-lease, market and supply clients are attributed through the fresh route census.
