# 1202. Separate stockpile, availability and need

The stockpile and the native logistics write are independent observations. The game computes surplus or shortage for player-controlled countries and a variant never has its own native balance. Read the signed need from the same native available operand and stored balance, preserving signed arithmetic and the native bound. Old ordinary equipment can recover the operand from nonnegative stock. Special availability, including supply vehicles, can differ from stock, so an unobserved operand retains its explicit reason. If it is observed, the table can name both stock and availability.

Observed zeros count toward an existing group. They do not by themselves create rows. A nonzero or unknown variant with unrecorded type could belong to any included type, making type and arm totals unknown. Likewise, a nonzero or unknown unresolved logistics type can belong to any resolved arm. The unresolved arm sums its own members. A listed unresolved type with zero balance and stock may still have unrecorded availability, so its zeros cannot establish zero need. A filter excludes unresolved types by key, but cannot exclude a variant whose type is unknown. A variant's independently read stock remains exact. Production output sums each line's individually truncated daily speed divided by cost. An older bridge with only a weekly value cannot provide that daily figure. Distinguish an unrecorded cost from the absence of a production line where it was read.

The catalogue supplies branch-wide identity, types, groups, and peaks. Its groups can represent a sum wider than a single native integer. The hour's reply supplies the current values and can add records the previous catalogue omitted. Keep the hour a reply actually answers while a later reply loads. The catalogue's read hours still drive stepping. Read the catalogue once for the chosen holders and types, follow the at-hour values as a live panel, and fetch details for explicit hover or pin. Bucket chart requests to cover a power-of-two hour span starting on a quarter boundary. This avoids replacing a request each frame as playback advances. The detail can show the most recently served hour, with warnings alongside the figures. The balance line breaks on a missing value, and drawability is filtered before automatic groups are picked. A line's preferred color comes from the game's order.

Saved group tokens are scoped to their grouping, and settings encode content keys that cannot be stored verbatim. A variant choice is scoped to the campaign and uses a design witness alongside the handle. Another branch may assign that handle to a different design. The recorded history can match a saved fingerprint before or after a rename, while the displayed name is the one recorded at the chosen hour. A design without a recorded witness cannot be chosen as a saved variant. Deselecting the visible group also drops alternate stored choices for it. Previously pinned groupings still open on their saved group. The table also retains `bars` as the saved value of its renamed table option.

In the type breakdown, model stock shares use one unit, so their bars are comparable. Known model rows can still be drawn when a type's total is unknown. An observed shortage can widen the chart's value axis beyond its stock. Auto-fit includes zero and log scale requires positive visible shares. A nonzero percentage is never formatted as zero. Counts precede model names because the names themselves may contain numbers. The visual tooltip fits the window, while its screen-reader description includes every variant.
