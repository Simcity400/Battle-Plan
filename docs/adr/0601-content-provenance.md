# Verify content at its recorded identity and preserve its lookup boundaries

Capture content identities use machine-free layer IDs and policy-specific byte inventories. The base hash includes built-in roots in their install-relative namespaces even where their mounted paths overlap. Mod descriptors supply replacement paths and dependency order, with their portable fields hashed from policy 5 onward. The installed descriptor location belongs to local resolution. Preserve each earlier policy's own inventory when checking a recording. Name components are length-framed before hashing so path-boundary changes cannot collide with another inventory.

New recordings use the engine's order among installed DLC and enabled mods. Start DLC and mods at their respective default weights, lower enabled dependencies until they precede dependants, and sort equal weights by descriptor path bytes. A mod's display name selects its first descriptor. Cycles cannot produce an order. Each later mount takes precedence, with built-in integrated DLC mounted before selectable DLC and the optional tweaker assets mounted last. The recorded order and replacement paths govern playback regardless of the current launcher. Resolve recorded layers independently so their exact content can be gathered across matching installations. Named gaps remain when a layer or executable cannot be proven.

Playback gets game facts and executable tables only from the recording. An older policy that never hashed a newly covered fact leaves it unavailable. A successful art lookup names the installed layer and may use currently installed bytes. An unavailable fact or layer stays visible as withheld. Directory listings refuse when leaving out a recorded layer would look like proof that it has no matching files. Readers may opt into unhashed reads at an explicit reporting boundary, where successful reads and attempted missing dependencies are distinct. Aliases naming covered entries still go through verification. Existence probes read opening metadata without reading or counting a payload.

Keep filesystem names as inventory bytes through search. Archive member names compare exactly, and folders use the native Windows open to resolve case and file aliases before verifying their inventoried spelling. A lookup uses the game's sanitization, which differs from normalizing a registered replacement path. Directory loaders enumerate direct children by raw case-sensitive suffix and byte order. Layer precedence applies to successful opens and stops at a matching replacement path. Reverify covered hits and misses in every reached layer so a new higher-layer file or vanished entry cannot silently change an answer. A held lookup memo still verifies its reached layers, and each changed mount roster uses its own derived caches.

Use one Windows file handle for identity and bytes. Share direct changes with a held read, let ownership close each successful handle, and release it on failure so sharing does not outlive its reader. Windows enumeration does not promise a fixed result after an ancestor changes. Synthetic fixtures isolate each destructive test case. Asynchronous change readers keep their submitted buffers pinned until completion, with submission and retirement serialized by a mutex. The worker retains the completion status until it dequeues cancellation.

The persistent hash cache is disposable. Key archive probes by digest scheme, parallelize the ordered probe work, keep completed digests across interruptions, and leave the original error intact when cache publication fails. A listing stamp can reuse a digest without another metadata read, but covered reads still verify actual bytes, including stale hard-link stamps. Reject truncated or extended cache encodings. Publish a whole cache by rename and merge entries already published by other processes. Cache or descriptor read failures do not change the authority of the installed bytes or turn a lookup of another valid descriptor into a refusal.
