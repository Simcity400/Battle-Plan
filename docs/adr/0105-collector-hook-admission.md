# 0105. Admit collector hook families through an explicit inventory

The collector admits a family only after the build gate verifies the piece it needs. An essential family's refusal stops attach before any game read or patch. A refused optional family is named in recording and status diagnostics. A resident or polled sibling in a mixed capture pack can still run. The refusal coverage test independently partitions every hook-produced `TABLES` list, with direct acquisition jobs listed separately. Without template observation the collector takes a fresh reading. Without the command-batch family it captures during the game hold and retains the same tables.

Native sites have one patch owner. Families that need the same event subscribe through that owner, including the advisor-pool unappointment, country resets for naval trees, group destruction, the occupation pass's war-goal expiry, and the MIO design setters. The country-input observers forward shared recruitment, exile, crew, and expeditionary events. The inventory includes template and country-configuration changes, occupation lifecycle, HQ deployment, and incoming wing transitions. A descriptor can identify an event whose enclosing call or entry is already owned by another patch. The test checks ownership and overlapping spans independently of timing buckets, which may describe several events under one owner. The inventory records a fixed length for a known entry or direct call patch and lets a tap's span decode from its verified site.

The constructor test reviews `runtime::run` with `syn`. One direct canonical family constructor in a registered closure is the only family construction it admits. A helper body starts a separate scope and cannot borrow its caller's registration. Type and import aliases, constructor values, and indirect calls fail closed. The test visits approved calls' arguments and extracts expressions from status-macro values so an approved call or macro cannot hide an unregistered constructor. Macro definitions are fingerprinted from normalized source tokens because their bodies are opaque to the expression visitor. Other discovered calls and methods must match the reviewed non-construction route inventory. That inventory covers owner setup, verification, acquisition and storage accounting, worker lifecycle, timing, status and restoration, so a new route receives a review before it can ship.

The loader opens capture admission after every family has reported. It can use the capture thread only when the worker starts and command-batch observation is ready. Detach closes admission before joining that thread, drains the last ended hour through a bounded wait, and records any unread hours as lost. It retains any partially published family for restoration, even if the family has provided no table. World invalidation stays published until every other family is restored and running observers have left. A failure applying a shared family publication names the family's registered sites. A constructor failure must already have an installation diagnostic, including failures before native construction.

Before workers start, the loader can publish attach status. Afterwards the spool's coalesced status writer is the sole publisher of the failure registry so temporary files and replaces have one owner. A reader denying Windows delete sharing can prevent the attach status replace without changing the recorded attach result. Callback work avoids formatting diagnostics. Tests that mutate the live application registry isolate the session in a child process, and synthetic producer tests provide a module identity for the code's vtable checks.
