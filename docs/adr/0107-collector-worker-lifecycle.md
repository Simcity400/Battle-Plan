# 0107. Keep status and profiling work outside live capture

Status publishing coalesces pending snapshots by path. The publisher can hand off the next snapshot while a write is stalled. The writer measures spool directory sizes and performs the file I/O with reusable checked buffers. A sharing violation can be retried in the background while the worker remains active, but a newer snapshot supersedes it. The spool handle can exit without waiting on a stalled write. The loader joins the writer later. Tests that stall a write release it before joining the writer, including on unwind.

CPU status uses cumulative thread cycles and user and kernel time in 100 ns units so a reader can compare snapshots. Decode and acquisition workers publish their own IDs. Register a sampler target’s creation time before discovery can open a recycled ID. Compare that recorded identity to the opened thread and refuse an unverified or stale target. Sampling targets are gathered without allocation and exclude roles that the sampler does not support. The exit guard is the first local in a sampled worker, so later locals release their locks before the guard stops the sampler. The game callback has its own gate.

Threads reading live game memory wait until the hourly tick ends, subject to a bounded wait. The ticking thread never waits on itself. Copy-only threads can continue while priority control keeps them away from the game’s core. If a copy-only thread needs a live read, it uses a scoped gate or skips the tick. The recorder’s packer uses the same idle signal.

The first worker panic is recorded with bounded UTF-8 formatting, without allocating. Open the progress file before starting workers so the hook can append without path conversion. Teardown carries the same panic into status and to the recorder. Keep the installed hook while any worker is retained and restore the previous hook after the workers join, before unloading the collector.

Sampler targets and retained attribution references are prepared before a target is held. The hold performs the statically imported context and resume operations and scalar or atomic operations. It neither reads a live stack nor allocates, locks user-mode state, formats, runs TLS work, or runs cleanup. An unsuccessful resume retains the hold, including after a stop request, until a resume succeeds or a signalled thread handle proves exit. Count each failure while the hold remains visible. The game callback’s exit and the sampler’s claim use sequentially consistent flags so callback exit waits for the claim to release. A claim that sees the callback’s flag clear discards the boundary sample. The callback guard drops on its entering thread before running the native original.

Publish the sampler’s control before spawning, allowing an exiting owner to stop an in-progress startup. One caller joins the sampler and publishes its final state before other callers report completion. Wait without holding owner, pool or sampler control locks. Join before an owning worker exits or joins helpers, and release retained sampled targets only after the last resume. Explicitly free retained static storage before DLL unload. Schedule the sampling period from the start of its round. A late round starts its successor immediately, and a timer polling interval cannot shorten a long configured period.

The profiling stream is independent of replay. Its little-endian header names the collector image and debug identity, clock rates and record layout. Each fixed record stores timing weight, instruction pointer and thread or job attribution, with zero for absent jobs and 255 for an absent worker index. Metadata follows the records and a footer locates it. Readers can recover complete records from a prefix without a footer. The chunk buffers have fixed allocation, count rejected records and return storage after writer handoff.

The versioned `HOI4WSMP` header has an 88-byte fixed prefix and a UTF-8 debug path. The 32-byte records contain three little-endian u64 values for QPC, cycle weight and instruction pointer, two u16 values for thread slot and job role, then u8 values for thread role and worker index and two reserved zero bytes. The JSON trailer records reader-visible thread and module identities and loss counts. The `WSMPEND!` footer stores the trailer offset and length as u64 values. The encoder uses a handle to the collector’s own image without extending its DLL reference count. The loader’s authenticated mapped image and explicit range checks bound header and debug-directory reads.

The scale fixture uses one group per 24 divisions to exercise the test topology. Its serial and partitioned walks share the same census, then join the partitions in slot order. Timings of the partitioned fixture include test thread startup, which the production workers do not pay. Tests that suspend or gate a real worker release it before assertions and keep it alive until the sampler stops, including on error. The fixtures use independently authored exceptions and synthetic local regions.
