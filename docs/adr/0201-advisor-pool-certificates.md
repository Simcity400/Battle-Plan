# 0201. Carry advisor pools only across certified reads

The appointed advisor list is part of the hourly recording because the `has_idea` trigger reads it. The available pool serves panels and has a different cost profile. Each country gets one daily pool slice. A new country or a country whose previous read was withheld enters the next selection. A full walk or a capture with slicing disabled reads all countries. The active and retired character arrays share one walk of the country character object, charged to CountryCharacters. The character manager's advisor token set has its own hourly read.

The available-pool store holds one latest complete walk per hour of the day. A pool can reuse its entries only when the country, character object, array data pointer and count match, its watch epoch and sequence match, and each character's certificate matches. Registration precedes the reads. A fresh pool can enter the store only if the character domain stays quiet throughout the read and every row was registered. Invalidation at a load, gap or recovery, a running writer, a writer without a named pool, or an unobserved owner sends the pool back through the fresh read path. Duplicate character object addresses cannot identify a unique held pool. Watch capacity accounts for the census, including countries assigned to other hours.

For the appointed list and both character arrays, the country and link headers and the pool, character and roster tokens identify a complete quiet walk. Each writer that could change an array, role or character identity must invalidate one of those tokens. Appointment mutations touch the pool or advisor domains. The pool family owns registration, retirement, transfer, copying and pool lifetime changes for the character arrays. The roster family observes identity repairs. A changed or unavailable key requires a whole walk. A fresh walk can replace the held read only when those tokens and headers still match at the end.

The token table can carry its entire verified set when the manager, header and certificate still match. Fresh sets sort keys by byte order for stable encoding because bucket order depends on hash and insertion history. A complete fresh set equal to the last published set can reuse the encoder's allocation, including on a keyframe. A partial or refused read has no reusable generation.

Held storage belongs to the loaned capture job. An allocation refusal while holding rows leaves the current result available and forces a fresh read next time. Invalidating the store on the game thread only marks it forgotten. The next walk discards old certifications before reading or carrying. The worker grows owner-selection storage and measures it when the walk finishes. The game thread reads that measured value. A truncated advisor walk reports at least the first unread row's byte demand, and the token walk reports each key's demand. The host owns dispatch, the job loan and final table assembly.
