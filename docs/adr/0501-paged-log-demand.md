# Use server page counts and supplying reads to bound log demand

Represent an unloaded page with one item and its virtual row count so the scrollbar is accurate without every event in memory. Use stable windows anchored to the oldest ordinal. Replace a provisional count with the loaded and filtered count, retain the measured count after evicting its payload, and never resurrect a checked zero-count page. A failed page keeps its count and refusal. When the latest loaded page advertises a continuation, describe it with its loading state before storing it in the chain, and refuse repeated cursors. Keep equivalent page arrays stable so bookkeeping alone does not restart motion or demand. [Page layout](../../ui/src/charts/log/logPages.ts)

Use cumulative counts for keyboard ordinals without assigning one to headings. A destination can refer to an unloaded page and resolves against its filtered rows when available, clamping to the last eligible row if the requested offset no longer exists. Do not focus a future row held ahead of the head. In variable-height logs, page by layout pixels and advance at least one row. Overscan in pixels so one large unloaded placeholder cannot trigger several other large pages; retain a pending keyboard destination until its scroll is measured.
