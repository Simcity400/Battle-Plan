# 0802. Attribute construction only over witnessed intervals

The recorder sees building and rail queues at their stamped daily reads, with building changes available by hour. A queue line begins at its first successful read or an earlier output observation. Building rises can be claimed as new levels only where the queue count falls and the observed rises can explain the fall. The date is exact when the rises and fall agree. Repairs and damage follow the building while the line is listed. A stretch with missing hours, a concurrently open line at the same building, or a newcomer which may have worked there leaves the uncertain work unaccounted. Rail segments count from a fall in the recorded remaining count.

A departed queue line receives a provisional ending. Final output settles an observed completion or cancellation, or records a removal when a complete observation reports no outcome. Without its final observation, the ending stays unknown. The final row lives for one hour before deletion, at which point the separate end log records the result. Queue fields written without a sample stamp do not create a queue read. The project writer persists its observations, outstanding building changes and each active line's claim state so resume can recover a partially observed stretch.

Spend rows group exact factory output by queue owner's country identity, work type, building type and state. Railway rows use both endpoint states and reuse the building-type key field for the last state. State and building identifiers are kept whole, including modded keys wider than 24 bits. A restarted observation keeps earlier output and starts a new baseline. A changed attribution leaves accrued work in its earlier row and counts later work in the new row. Inexact observations count as unknown pending a complete observation. A line that ends unwitnessed leaves its unknown count in the row. Spend rows remain after their lines finish. Resume stores each active line's baseline, output and attribution.
