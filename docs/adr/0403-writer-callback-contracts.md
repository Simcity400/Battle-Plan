# 0403. Keep mutation receivers and callback boundaries explicit

Writer observations preserve the original call's arguments and result. A family table and its callbacks share the same order. The reader recovers the watched object from the argument that actually names it, which can be an embedded field or a pair of objects. If a writer cannot identify its owner, invalidate the appropriate wider certificate. The patch owner validates that a function entry covers whole instructions, or verifies and replaces one specific call where the function entry is unsuitable. A single writer can notify multiple families through one owning patch.

## Character and advisor sites

`advisor_pool_mutations::MUTATIONS` receives a country pool for status updates, commands, retirement, transfers, construction, destruction, appointment and record operations. The manager owns token set changes, clear, construction and destruction. Role removal receives only effect and scope, so it revokes all pool certificates. Retiring reports a boolean and pool construction returns the pool. Civil-war retired copying names the destination before the source. Token updates take the manager, character, erase list and insert list. The status update entry requires the stack-pointer copy and following home-slot spill to relocate together. Registration and retired-copy entries preserve their saved registers and stack setup.

The roster table discriminates array changes from scientist roles. Append and clearing receive the array. Scientist construction receives output, character and definition. Attachment and clearing receive the character, while trait edits receive the scientist and trait or token array. The trait-removal entry preserves setup and the initial trait count load. Trait reset relocates the stack-pointer copy with the following spill. Shared lifecycle notifications use the explicitly forwarded owning sites.

`character_role_mutations::MUTATIONS` gets the character through the leader or advisor back-link on modifier rebuild and destruction. Map insertion names the embedded leader map. The role builder receives output and then character and definition. The ideology effect receives effect and scope and names no character. Name setting and identity repair receive the character directly. In `census_mutations::MUTATIONS`, the operative setter copies the named reference into the character before returning. Relocation at `set_operative_reference` stops at the return. The observed census writers have at most three integer or pointer arguments.

## Building, air-base and wing sites

`building_mutations::MUTATIONS` identifies the affected status from a building's back-link or directly from a status argument. Level setting receives building, level and notification flag and returns a boolean. Damage, repair and destruction write the building and carry their original output parameters, including damage arguments on the stack. Lookup and creation return a building pointer. Status readers and clear have the status as their first argument. Nudge entry receives five arguments and exposes no affected status once the editor starts. Preserve stack arguments through the original call.

`air_base_mutations::MUTATIONS` matches a base from its handle or a wing pool from its associated base handle. State-base creation identifies the manager and the kind of slot affected. Creation and access removal receive a base and tag. Pool registration and erasure receive both objects and return a boolean. Wing addition and removal receive the pool and wing and their flags. Removal returns a boolean, splitting returns a wing and the pool deleting destructor returns the pool. In the wing-destruction entry, the stack-pointer copy and spill relocate together. Capacity refresh preserves the original saves and reservation.

`air_wing_equipment_mutations::MUTATIONS` receives one wing, source and destination wings, or an embedded pool. Pool subtraction at the over-capacity and daily return calls resumes at the instruction following the original call. Aircraft movement names source, destination and count and relocates its stack-pointer copy with the following spill. Inline wing state and raid lifetime writers use keys separate from the pool. A coverage writer names the wing in the third argument, a mission setter uses the embedded mission in the first, and the remaining writers name their first-argument object. Construction and load use the ordinary lifetime admission path.

## Division, sub-unit, naval and province sites

`army_stat_mutations::MUTATIONS` receives a division for active statistics and a name member for a single cached-name refresh. Country-wide name refresh receives the name group and tracker, with the country in the second argument. Distinct entry spills precede their original body, and relocation preserves the indicated first spill before the later saved registers. The stored-experience witness is independent because template rebinding can rescale experience before later refresh. The experience history and store writers follow the independent stored-value writers in callback order.

`local_subunit_mutations::MUTATIONS` receives a deployment status for ensuring, clearing and initialization. A rebuild names the deployment bonus list in its third argument and the clone in the fourth. Recover its owning status through `BONUS_LIST`. Definition lookup and equipment reload are shared dependencies and invalidate all countries. The definition-site relocation covers the stack-pointer copy and its subsequent spill together.

The first `naval_tree_mutations::COUNTRY_SITES` receivers name country trees and the following receivers name the complete unit leader. Both `navy_ledger_mutations::MUTATIONS` entries name the navy in their first argument, with registration and erasure following their own first register save. The orders-group family normally receives the group directly. Group assignment can name a second group through a separate argument, while the remaining group-change sites take at most three arguments. Province combat and occupant writer families receive province and combat or unit. Each uses one distinct entry for addition and one for removal. The relocation spans preserve the first whole prologue operations before handing control to the original body.

## Faction and political sites

Faction goal progress is observed at its owning call with status, incoming cache and update flags. The parent retains the faction in its preserved owner register. Cancellation append receives the status's embedded history vector. The doctrine effective-gain intercepts observe the direct copy of the stored operand in both branches.

Party leader insertion, movement, removal, retirement, death and clear name the party directly. Transfer names both parties and preserves the entry's equality check and relative branch. The vector save reader receives reader, token and the leader vector. Recover its party from the third argument and `VECTOR`. Validation and deletion name the party. Party creation and name assignment use the same political-party receiver type, but their entry spills are tied to the particular site.

Political-status mutation distinguishes a function entry from a call to the clamped popularity setter. Capital setting, politics setting, ruling-party selection, idea replacement, addition and redistribution have direct entry observations. Redistributing assignment and addition can share a prologue, so the resolved site identity discriminates them. The political-party effect and the plural popularities effect are observed at their separate calls to the setter. Direct and forwarded sites own distinct patched bytes even when a patch is inside a function used by another observer. Forced ruling-party selection affects both structure and popularity. The politics capture family forwards appearance reset and daily updates.

Relation opinion sites name a live status except the constructor, which receives its uninitialized storage. Serializable relation slot replacements take status, replacement and slot. They replace the typed slot, delete the displaced object and maintain subrelation and serializable membership. The original first endpoint owns serialization, so applying or clearing on both endpoints may name a superset of the actual writes. Runtime nonwar replacement preserves the type, endpoints, hour and cancellation fields established at construction or loading. The serializable order changes through swap-removal. War writes are forwarded by the country-input family. The daily parallel sweep can reach embargo clearing.
