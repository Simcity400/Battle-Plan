# 1306. Reuse scene weather state and preserve each pass's inputs

Water compiles for the chosen settings before the sea-bed targets are drawn. Low graphics takes precedence over refraction selection. A technique that only samples scene UVs can use a half-size linear sea-bed target. A texel-addressed read requires output size, with a diagnostic naming the read that prevents shrinking. The half-pixel refraction offset is still in output dimensions. Use the actual compiled pixel-stage texture reads to decide if snow or ice can show, including compiler elimination of unused reads. The strip uses signed packed dimensions. Bind only the native pixel texture and sampler slots, restore the raster and depth contract from the preceding world passes, and retain the known light-grid input. Clear the second constant buffer. The fourth has a 16-byte allocation with only time and the two half-pixel offsets initialized.

Snow and mud refresh on the presentation clock independently of replay hours. Graphic delta trims the 32-sample ring after sorting its retained storage in place, averages the middle 26 and mixes it equally with the current sample before clamping. Future samples overwrite that sorted storage. The replay can pause while frames finish a fade. A restarted presentation clock clears history, and a frozen timestamp reused for an export or allocation retry consumes no new sample. Pending skipped hours do not change displayed planes. A new native refresh identity still matters when the texel bytes are equal.

Immutable page identity tells which raw snow and mud pages were rebuilt. An immediate install keeps each page backed by the target byte buffer until a blend or a read needs its displayed planes. A write of a rebuilt page does not require byte comparison. Blending only affected pages avoids reapplying a non-idempotent blend. A blended page can differ from its raw bytes or acquire different planes and must be included in the next immediate install. Raw bytes are arranged symmetrically by plane. Rectangle uploads are equivalent to immediate whole-grid installs, so they are available on reset and on an equal-size continuation with no refresh due or pending. Merge nearby writes when uploading the intervening bytes is cheaper than another call.

The hatch mask includes an unknown from the pending, shown or fading-from snapshot. Fold only when one of the three source page identities changed, and upload only the changed mask ranges unless a new grid needs a whole mask. Count unknown cells per finest terrain square. A changed flag affects that one square and the renderer draws only the terrain blocks that overlap covered squares. The coverage rows count from the map's bottom. Use the same height stream, coast caps, terrain triangles and snapped edges as the main pass. Draw the ground hatch immediately after terrain and the water hatch immediately after a water technique that reads the weather texels. Depth-test the hatch against world geometry and leave the depth and scene alpha unchanged, so later passes retain their normal layering. Use the heightmap to decide on which side of a coastal triangle the hatch appears. The shader uniform and placement layout are documented with the shader interfaces.

The hatch reuses persistent parameter and instance buffers across wraps. Each draw takes a parameter slot at the WebGPU uniform alignment and a block range. If a range grows past capacity, earlier commands retain the buffer they bound. Height-stream bindings survive only while in use in adjacent frames. Resource creation captures validation or allocation errors by name. Geometry tests compare capped and uncapped terrain at several depths and isolate sea and ground on a shared coastal triangle. Presentation tests compare rectangular updates with whole-grid installation.
