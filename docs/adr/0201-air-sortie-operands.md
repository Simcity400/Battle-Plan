# 0201. Record flying-map sortie operands and lookup witnesses

Playback reconstructs the game's count from stored operands for the registered missions. Capture records the mission, reached-province roster order, effective-country base containers and modifiers, plus the static helper metadata on its own cadence. The hourly inputs share an outcome so a failed operand cannot leave a partially credible sortie table. An unavailable modifier override vector has an explicit unknown outcome. When available, console overrides follow keyed modifiers in slot order, with duplicate slots refused.

Base-resolution acquisition keeps each attempted result. A successful miss and an unreadable lookup have different meanings. The conversion retains a successful base's fields only where the complete AirBases census lacks them or disagrees. The host pass groups complete raw handles so repeats share either a found host or a completed miss. A fault interrupts the pass, and witness order is restored for the sortie reader even when it failed. The host supplies an owner through its task force. The dedicated flag marks a host whose task force is absent. The viewer names the wings it could not resolve after a base or host lookup.

Capture groups operands by base and effective country and reads each country's volunteer-host vector once. It memoizes the weather header for the hour, the containers for a base and the region map for a country. Fuel-bearing container keys sort before matching non-fuel requests, so deduplication preserves the fuel the law uses. A region-zero weather lookup is refused. Only a held original region with nonzero disruption needs a held night marker. Successful reached-province copies retain the native order because the scenario indexes that order. A short destination counts the unretained mission and withholds its reached IDs. Definition flags are batched by distinct pool, with the first unfinished copy and remaining pools handled by the normal read path.
