# Keep recorded content identity separate from display selection

Content readers preserve the identity and load order the game used. Localisation, artwork and scoped evaluation are separate projections. A display value can fail or fall back without replacing the stored identity or hiding ambiguity.

## Decisions and relations

Load category names before decision bodies in the recorded stack. The first registered category and decision definitions win. Balance files bind categories through their `decision_category` field, and a repeated balance definition rebuilds its bindings. A decision seed uses the ASCII-folded first-NUL identifier. Preserve the presence of an empty target object and use actual trigger consumption to determine whether the state highlight has a child. Unknown highlight tokens take the reader's single-token path. Retain targeted modifier occurrences in order, record effects for fresh country scopes, and keep scoped variable operands until their consumers have the matching context.

Decision names test cosmetic tag, current tag and unqualified keys in that order, trying the ideology suffix before each base key. Localisation presence chooses the key before scoped expansion. Retain separate icons in declaration order. Scalar icon text terminates at NUL, while a block's text fields replace earlier values and its conditions append. A sole icon bypasses condition evaluation. With multiple icons, the first true condition wins, and the first icon provides the fallback when every condition is false. A condition that cannot be evaluated stops the choice. Artwork looks up the decision token, the prefixed selected text, the direct selected text and the unknown sprite in sequence. The recorded event scope and hour supply the context for triggered icon text.

Diplomatic payment names use the recorded action token and nonzero evaluated cost. A relation's daily row uses its own title. Scripted action keys uppercase the stored name up to NUL and leave the suffix bytes intact. Use the relation effect's shared label for relation displays. Other action kinds require the matching identity or recorded operand before their names can be selected.

## Doctrine definitions and tactics

Load tracks before grand doctrines and subdoctrines so references see the complete track registry. Subdoctrine loading reads immediate subdirectories before root files and keeps archive names as bytes. A repeated token reuses the existing object and preserves its first spelling and any fields omitted by the later declaration. Folder choices have unique registration order, while each authored grand-doctrine occurrence remains in the tactic source list and points at the final object. The folder lookup tests the exact authored token before trying a stripped suffix. Presentation lookup and technology descriptions do not depend on a successful name projection.

Each doctrine reader retains its native consumption. Track token values, dynamic-token raw lists, statement reads and scalar mastery operands follow different shapes. An unresolved track stays a lookup dependency even when it cannot supply a native reference. Append resolved tracks, unlock conditions, milestones and reward occurrences in their authored order. Pair milestones by the resolved track index. Visibility does not determine whether an entry can supply a tactic. A zero mastery value uses the recorded define, and a failed value scan keeps the earlier field. Doctrine bonuses share the unit-stat and modifier readers used by technologies.

## Faction templates, goals and modifiers

Templates merge field by field in stack order and fill an unnamed faction through bound localisation. A template token does not become the caption. Read template goal statements through the same native field consumer used by the goal catalogue, even when a caller only needs the template name. The declaration assigns identity, so a goal body's `id` cannot rename a registered or inline object. Inline declarations remain independent, and a token-only reference that cannot select uniquely is refused by name. Keep the authored group and progress operands for artwork and localisation. Member-upgrade names are also authored localisation operands independent of their registry identity. Cache the catalogue, including a refusal, against the recorded layer roster.

Known limit: a template file whose first read fails before the file itself is witnessed, with only its folder witnessed, keeps that refusal after an edit in place that leaves the folder's stamp unchanged. Restarting the app or touching the folder reads it again.

Dynamic modifier definitions use exact byte identity even though icons can change. Direct files insert each definition at the front of its native bucket. The last authored icon wins. The constant classification uses only the native digit and punctuation set, including empty text. Other operands retain scope, separate occurrences and individual description lines. The scoped branch uses the key token directly, so a quoted key does not resolve there.
