# Invalidate world capture where its inputs can change

The collector uses observed writer calls to discard carried rows. It does not invoke a writer to obtain an observation. Each certificate belongs to one observation epoch. Reset invalidates the world before the first destructive write, even if a load later fails. Construction and deletion have their own boundaries. State-template and adjacency reloads affect their respective content because they can rebuild live state and neighbour data without replacing the whole world.

Railway information is certified by its manager slot and province definition. The cooldown setter names that slot, while an information-object writer names its province through the object's definition. A null slot is a known absence. Daily cooldown advancement covers each occurrence in the native cooldown list. A lifetime or load operation that cannot reliably name the affected slot invalidates all held information. Building health writers and railway neighbour updates affect the same evidence, while static neighbour geometry is authenticated by the province definition.

Territory certificates distinguish province writes, state writes, and state writes that also affect associated provinces. Province controller notifications cover both direct and state-driven changes. Province state-link initialization can relink provinces from another state. State reset clears the held tags, name and links. Receiverless owner-area rebuilds affect every province. Border conflict insertions and removals affect the implicated state and provinces. Owner name and custom name have separate writer paths. The map editor's shared entry is observed through the building family. Changes without a complete writer certificate, such as hourly manpower, border-war input and state flag updates, stay on hourly acquisition. Infrastructure operands from loaded content are compared on each acquisition.

The world-input observer distinguishes whole-table invalidation from a dynamic modifier container tied to one country. Province rename and reset, naval access changes and reset, and threat recalculation cover their carried tables. Threat update can erase exhausted sources and rebuild both the total and country aggregates. Dynamic modifier retention includes insertion, renewal, removal, daily expiry and rebuild or reset forwarded by existing observers. Policy reload, score inputs and organisation configuration are separate certificate sources. Both policy observations must stand before the policy data can carry. Design author, source and bonus values are frozen native payloads with their own mutation and lifetime coverage. The game fog flag is process-wide.
