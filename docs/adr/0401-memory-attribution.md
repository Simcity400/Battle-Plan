# 0401. Attribute memory to originating work across threads

The measurement build tags allocations with the thread's current owner and kind, then charges deallocation to the original label even on another thread. Task handoff carries the same label. An explicit owner represents a family, and unattributed work and process-wide setup remain separate. Overflowed owner names contribute to the other bucket. The feature is reserved for measurement because the allocator wrapper and its counters add their own work. Allocation denial can be enabled independently for targeted tests.

Each phase records the per-label peaks, total tracked peak, the nearest per-label reading and OS memory counters. An allocation still held at the reading is tagged with the epoch it precedes. When the family's emit frees it afterward, that amount identifies projected output that was still in flight at the peak. Process-lifetime memory peaks cannot restart for each phase, so a sampler tracks the current working set and commit independently. The recorded hour is the most recent hour named at the peak reading. The wrapped allocator can report its own effective committed bytes and size classes through callbacks that allocate nothing.

The tracking header records label and epoch, keeping the block layout aligned. Attribution overhead and allocator rounding have separate categories. Size-class increases caused by the header are measured separately from the header's own bytes. The thread's counts are batched by moved bytes and label count. Sampling pauses shared counting while holding every listed slot so the allocator call and its count cannot straddle a snapshot. A slot enters the list only outside the allocator and remains alive for reuse after its thread ends. A thread without a slot uses the shared gate. Snapshot allocation occurs before stopping counting, and measurement callbacks cannot allocate while the gate and slots are held.

Owner names use a per-thread cache so entering an already named label avoids the registry lock. zstd working memory has its own context owner so it does not disappear into the native library's default heap. In a regular build the attribution calls are no-ops.

`Slot::with` and `Stilled::drain` access a slot's `UnsafeCell` only with that slot's `busy` lock held. `Local::guard` initializes a slot's link before publication and claims it exclusively. The published slots remain allocated so `slots`, `Guard::drop` and `counted` can dereference them through the list and thread-local pointer. The label type's scope cannot move to another thread. `rounded` and the committed-byte sampler load function pointers stored by `measure_sizes` and `measure_allocator` respectively, with matching signatures. The OS sampler passes the current process pseudo-handle and an owned writable block of the requested size.

The `tagged` helper writes the counting allocator's header in the prefix created by the widened allocator layout. Allocation supplies enough aligned prefix space before the requested bytes, and `tag` is only valid for a pointer handed out by this wrapper. The header remains readable when freeing or reallocating that block.
