# Lease one division census to independently gated capture jobs

The input worker captures immutable native roster slots and scalar seeds once. Dependent jobs borrow that packet until they join, so it remains immutable and retained through their leases. The packet preserves every counted roster slot, including nulls that typed seeds omit. Unit intelligence requires the original slot ordinals. Private core row failures must not stop that roster or make its independent consumers unavailable. The core consumes retained roots once and leaves the first result in place on a repeated call.

The worker uses the callback's authenticated country census when available. Otherwise the reader performs the normal identity and link checks without reclassifying an unreadable roster. It preserves the original native roster header if a load exceeds its sizing hint. When fixed roster storage is exhausted it continues to count later rosters, using the unread slot counts as an upper bound on nonnull entries. This grows to the complete observed demand in one step without pretending the unobserved entries were read.

Capture can walk consecutive owner ranges in parallel. The worker sizes its future split at country boundaries from the complete preceding census and reserves join capacity with growth headroom. The join appends census entries, roster slots, seeds and counts in slot order, ending at the first failure as the serial walk would. A larger census may still grow. Split planning and selection memo allocation are advisory. A refusal leaves consumers free to use their independent original reads. A refused core row reports its cause when installed, independently of output buffer growth.

Commander selection gathers each mover's route head and location and reuses group inputs shared by divisions. It carries unit-leader identities and order-group fields only under certificates taken before their successful reads. The watched writers and lifetime notifications cause only their affected group or leader to be reread. The daily group update invalidates the training state when it trains to its maximum. Missing witnesses, an invalidating hour or a disabled observer require fresh reads. Damage attribution uses the signed-positive expeditionary owner when present, otherwise the roster owner, while the core already has the row.

The callback holds the game through the input and core jobs. A core walk may reuse validated province, template and group identities within that walk. A conflicting cache slot replaces only a successful entry after original validation, and the hash disperses consecutive allocations to avoid a self-evicting sequence. Failed, null and partial reads are not cached. Template validation retains the original nonzero-handle predicate and records the reveal-skip byte separately. Theatre lookup uses the roster country that supplied the run of divisions.

The approved bounded read reordering of 2026-10-12 permits speculative province and owner batch reads, while the original identity and owner gates still decide which projection rows are valid. Under persistent faults, batched acquisition preserves the serial rows and first relevant refusal. Every guarded record batch follows one rule. A row the batch completed is never read again. A faulted row is read once more by its reader's own serial path, in the same capture while the gate still excludes game writers, and a recovered row is kept. If that read also faults, its refusal stands and later independent rows continue. Nothing is retried across captures or after the gate reopens. Transient success may therefore extend the serial prefix but neither shorten it nor change a row already proved by it. The batch tests keep an independent scalar reference with fresh identities per row.
