# 0301. Isolate saved-recording preparation and ordered read-ahead

The headless desktop role receives saved-recording requests from a queue under the app’s local data folder. A request names a canonical path through a hash stable across builds. Each ask has a separate file, so completing one cannot remove a later ask. Report readable recordings newest first and keep unreadable ones visible. Treat a file withdrawn while the queue was being read as no longer requested. A shared lock admits one preparer. Its versioned status keeps both the process ID and creation time so a reused ID does not look like an existing preparer. Distinguish ready, in-app, withdrawn, off and failed outcomes, and report incomplete parts by name. The preparer holding the lock alone publishes status.

Read blocks ahead to overlap decode and scan work without reordering what the callback receives. All concurrent scans share one core budget. Keep a bounded history of ahead work so completed reads do not crowd out demand. A decode walk joins consecutive blocks in a segment and includes the campaign table. If the walk meets damage, preserve the error for the reached block and the segment’s lost remainder, then begin a new walk at the next segment. A scan that stops reading one block can move on without incorporating its remaining hours. Cancellation or a finished scan ends the walk. Prepare the worker cleanup before spawning so a refused worker can wake and join those already started. Charge decode timing to the scan that requested it.
