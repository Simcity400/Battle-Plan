# 0907. Read one committed revision with independent table state

The byte source ends at the opened revision's verified footer even while a writer appends a new revision. A saved-only open reports an unsaved recording distinctly. A file truncated underneath an open handle is an I/O failure. A subrange read checks its extent bounds and leaves checksum verification to the caller, which verifies the entire stored extent once. Facts packs, summary pieces and span indexes retain their own stored representation. Other frames undergo checksum verification and decompression.

Open retains the root, its record and facts extents, and readable run directories. Unreadable directories leave named damage and give their runs no playback coverage. Closed spans cache their directory and lazily read each table's index row. Table parts, clocks and strings are loaded when needed. Reader projections share page caches but keep their own table selections. Damage is scoped to the root, run, page, extent or table that depends on the damaged bytes. Allocation and I/O errors pass through without being recast as recorded damage.

The container framing and row format are distinct. Control records report the row format, and the root identity proves the corresponding schema. Only the current and verified older formats can open. The older schema preserves retired positions and frames each table at its then-recorded field count. Later columns and tables read as not recorded. Changed layout or meaning is withheld by name. A page reader refuses entries for tables the recording predates. A column projection also yields not-recorded cells outside its selection. Opaque cells decode under the recorded row format. When unreadable or absent records cannot identify a format, only the current schema can be proven. The restore includes the last complete read of the designated division and sunk-ship tables.

Each table owns one state of its selected columns and referenced strings. It restores independently and advances across blocks from the less expensive baseline when a later restore cannot shorten the walk. The first restore already contains the run's first hour, so subsequent block-zero changes start at its second. A step across a packed block can renumber slots. A log instead lists rows by ordinal and applies its appends and forgets, using the lowest free slot for a new row. An insert and forget within one hour is absent from both reported sets. A partially read log retains what it listed before and carries no state-row read marks. Ordinary stretches expose track events, insert/delete positions, status and partial read marks in one advance. Track events for a part are captured before traversal and can be retained by a seek for the following stretch. Numeric track differences measure from zero for missing/unrecorded values only to decode their arithmetic. Text tracks store string ids and list tracks report that value bytes were written. These track representation rules do not turn unknown values into recorded zeros.

An unchanged table can share its last view across frame consumers. After building one hour and taking a single step, a complete view can apply that step's changed rows and deleted keys. It patches storage in place when no earlier frame retains it and copies otherwise. Previous Snapshot update storage is reusable under the same ownership rule. A jump, a keyframe, a withheld baseline or a failed patch builds from the recorded cells. A keyframe publishes Snapshots independently of which blocks preceded it. A valid step can expose change facts and field stamps against its built baseline. An inserted row carries all its fields, and a row inserted and deleted within the hour does not enter that baseline. Row framing errors withhold the affected table by name. The block clock reports observed reads without inventing missing timing measurements.

Reader pools can use threads isolated by priority and lifetime. Each executes the startup callback once. Pool destruction tells Rayon to terminate before joining thread handles. Dropping the final owner on one of its own workers skips the join, because waiting there would deadlock. A failed pool construction releases and joins any workers it started.
