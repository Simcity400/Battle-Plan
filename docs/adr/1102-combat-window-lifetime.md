# 1102. Match combat bindings to the displayed view and its read identity

Playback and still export share the game-authored combat windows. A direct air region, state or naval region selector opens without first resolving a combat handle. A naval map icon can also open a completed result. An open land combat list keeps its displayed order when each unit remains in the same committed or reserve array and the count matches, while refreshing values. Membership changes or interface-setting changes rebuild the relevant grid in native array order.

An open window has a local presentation state for tactics, dragged position and retained result details. The bindings are identified by branch, hour, selection, perspective choice and the country resolved by that choice. Land combat refreshes at the current hour, hides for a known disengagement, and remains available with a named gap if engagement is unknown. A naval combat only refreshes while engaged. It can hold previously acquired bindings that match its scope and are at or before the current hour. Disengaged naval windows keep those contents hidden. A missing or undecided engagement has a named reason, and a never-engaged window may close. Naval holds survive local icon or playback toggles. The map's marker diagnostics carry provenance when engagement was rebuilt on load.

The rendering side publishes an asking that owns the content, selection and related settings and can be evaluated at each publication's hour. The producer makes an owned read under an asking, branch, seek and hour. The consumer holds no more than one result per hour of its current asking. It can keep a future read until the map reaches it. Results for expired hours, old seeks and older askings are retired, including when a seek returns to the same hour. A changed setting at a fixed hour needs a new read. On content replacement, discard all bindings and outstanding results scoped to the previous content. An outstanding current read draws nothing and publishes no old refusal. Move discarded reads and old bindings off the rendering frame for disposal because they can own large battle data.

An air menu read takes the daily roster pass at the hour being read and applies its recorded feature mask. It selects its initial side only once the frame can answer. Naval region dominance consumes sources derived from that read's own frame and viewing country, and the required-rule hover takes its current relation through the content's provider. The providers live across opening and closing windows until content itself changes. A still export reads its target frame directly and can wait, using fallback engagement reconstructed at that frame when no index is supplied. It lays the window out where its opening motion settles. Tests use the viewer's allocator.

Layout and hit rectangles are in interface pixels. Use a hit-only pass that neither collects hovers nor advances the animation clock before applying input, followed by the draw that advances it once and collects hovers. The window takes the pointer across its controls, including protruding children and popup. The popup's quads sort above all window quads in the GUI band, which itself sits above map icons. The title strip can capture a drag for its own window. Record sounds and ordered clicks on the frame that made them; reusing a settled picture emits neither again.

Topmost hover wins, with the map supplying hover text only when the window does not. Explicit anchors keep position while the tooltip hides. Use the pointer, naval window or an authored anchor as specified by the control. Immediate and delayed strings can share bound text allocations. A dynamic owner replaces both authored hover strings or presents its own refusal. Apply the authored shortcut tail after the tooltip strings. The game can derive a text-scroll step from newline count. A missing picture can preserve an existing drawable when the provider asks. Retain native conventions for caret position, centre-relative stretch, authored enabled state, and shared or per-entry grid templates. For inline flags, resolve the atlas key before adding the viewer's unambiguous marker so a literal authored at-sign still receives the usual unsupported-control handling.
