# Compare saved values only to observations the writer establishes

Save readers preserve physical occurrence order and serializer omission independently of the richer live capture. A missing block or value can imply an exact default only when the writer omits that exact value. For signed-positive guards, it establishes a nonpositive class and does not establish raw zero. An emitted name can be empty because the text was cut at its first NUL, so it remains distinct from a name absent from the save. Keep repeated records and literal child keys rather than assuming map ownership or substituting a canonical identity.

Country projection uses the capture's authenticated physical country census. It pairs all saved occurrences with that layout before checking structural equality of repeated emissions and choosing a representative. Tags alone do not identify the object. The reserved pointer remains reserved even with a positive slot. Keep the ordinary parser's duplicate checks for callers without the census. For state control a nonpositive owner is a separate emission class, which carries no omitted controller value. For a positive owner, a missing controller is the owner's link, and an emitted zero controller is known zero. The province writer emits only a positive controller different from the owner. An unknown province membership leaves the state, owner and any omitted controller unknown.

Air histories and economy retain physical ring slots and the order of repeated vectors. In particular, the air daily history keeps the prior and current physical records without supplying dates or a guarantee of a completed day. A history writer that omits its record data only when every field is zero allows zero-valued records to be recovered only inside an otherwise valid history window. Retain absent logistics, supply and market objects separately from present empty ones. Read fuel fields in exact serializer order, including the pending record and 24 ring slots. Convert save text with a wide decimal numerator and verify the native Q15 preimage by re-encoding. Resource pools retain duplicate resource names in index order.

Character records carry each roster and its status ordering separately, including active and retired lists. A missing manager is distinct from a present manager with an empty roster. Reading a load-time view drops unnamed characters and their roles, independently of what the writer saved. A scientist's level and experience are omitted independently when each is nonpositive. The intel reader retains distinct operation instances even when they share their authored definition. History entries never establish an active operation reference. Operation slot ordinals remain present when a both-zero operative handle is omitted, and each slot retains its literal saved mission block payload with absent, empty, and populated blocks kept distinct. Keep absent operation and intelligence containers separate from empty ones supported by the serializer, and retain raw parallel arrays and ordered entries rather than folding them into maps.

Character identity keeps the authored token, name and optional template separately. An omitted flag vector is empty, and an omitted variable object has neither an entry nor an advanced seed. The optional operative reference preserves both id words. Roles preserve authored ideology tokens, separate trait vectors, signed timed-trait days and pending experience. Status records keep absent and stored false separate where the save allows either. Faction accounts and decisions preserve sparse indices and their source order. Governance stores doctrine choices as IDs in serializer order, preserves a null character parent as two zero words, and retains repeated research slots and timed ideas. A renamed party emits both keys and may emit an empty one.

Intel queues keep the ordinal even after the writer skips a null slot. An action's definition token is held by its body key, separately from its type and initiator flag. The captured roster retains the saved country of a reference, which does not establish its operative's resolved owner. Keep authored upgrade levels in saved order even when loading would merge them. Some fields have no proved gameplay or cross-format interpretation, including the raw value written as `max_operative_count` and unavailable cryptology bonus mappings. Preserve observable values without assigning an interpretation. Mission targets, cooldown, portraits and recruitment retain the serializer's explicit omissions. A variable block reserves `random` for the paired companion and seed words, and duplicate emitted names do not establish native key identity. Saved names that are sorted by the writer do not establish their live order.

Country-owned goal references and diplomacy's serialized goal objects are independent. Goal type comes from the object's current definition, since replacing it can leave the dynamic child key unchanged. Manpower pools append every repeated wrapper in original order, including the empty persistent wrapper before the explicit payload. State-history resources and membership come from the separately verified content. Runtime pools come from the save.
