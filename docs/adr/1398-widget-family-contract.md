# Declarative widget families with one projection for drawing and audit

Dashboard widgets do not wire playback loops, canvas surfaces, hit testing, tooltips, keyboard mirrors, or separate exact-read audit row builders. Every family (table, and any subsequent chart, card, or list family) upholds five contract properties:

1. **One projection for drawing and audit.** Each widget registers one pure, deterministic projection `(readView, options) => model` with its family over a time-bounded `BoundedReadView` (ADR 1402). The family runs that same function inside the worker lane to paint frames and inside the main-thread audit reader against exact replies (keyed end-to-end by `auditId` and pipeline generation to the exact frozen snapshot of options, settings, expansion state, viewport width, visible row window, country colours, and frozen gate that produced each painted picture, refusing missing ids rather than substituting a later snapshot). Audit coverage splits into three classes: (a) **data**—everything in the projected row model, table chrome (visible column layouts, summary pill, notes, warnings, total row count, refusal/empty state), ordered group headers and data rows (rank, tree level/open, muted), every painted cell field (`resolveCellPaintModel`: family value, format, bar fraction/alert/raw fraction, tone, status, country, resolved country colour, icon/flag identity, iconSlot, missingName), and each visible row's data-only tooltip model (`deriveRowTooltip`)—is canonically serialized (`canonicalAuditData`, which type-tags `Map` and `Set` in deterministic order and throws by name on unsupported container types) and compared; the painter reads resolved country colours exclusively from `CellPaintModel`. (b) **Layout**—column widths, elided text, row heights, and viewport-dependent geometry—is verified by layout tests and not audited, alongside transient interaction state (hover, selection, keyboard focus, glide animation, and rank-change markers). (c) **Presentation time**—the tooltip's formatted date line—is added by the host from the shown hour and excluded from the audited tooltip model so a picture painted at hour `h` and still valid at `h + k` never fails falsely on its date subtitle. Audit serialisation runs only for the visible window and only while an audit capture is active (`useFamilyAuditing` bound to capture start/end, rebinding mounted surfaces on transitions), so performance measurements outside a capture perform zero audit serialisations. Snapshots referenced by an active capture survive widget unmount or pipeline restart until verification drains (`deferUntilAuditDone`), then are released. Every painted picture in an audited window must carry audit rows regardless of owner; any unaudited painted picture fails the audit by name.
2. **Sources and time shape declared once.** Every widget declares its `SourcePlan`, coverage mode (keyed vs. population), country policy, and time shape (`point`, `range`, `branch-to-hour`, `trailing-window`, `pixel-binned`, `exact-hover`, or `paged-rows`) in one place (`ui/src/families/plan.ts`); shared family orchestration (`ui/src/families/broker.ts`, `host/useFamilyPlan.ts`, `sources.ts`, `holders.ts`, `cadence.ts`, `audit.ts`) derives followed, static (freezing one complete displayed static snapshot—reply, span, selection, options, gaps, holders, looks, and gate—while a newer request is in flight so projection, derived availability checks, and exact audit read only that snapshot), and exact-audit requests, dated slot holders (lowest covering country id, breaking ties by earliest `firstHour` then native UTF-8 `compareTags` order as Rust `Holders` does, retaining unresolved existence spans, deeply frozen and pre-indexed for O(log N) boundary and overlap lookups), dated country colours, group coverage refusal (`hour` masks unobserved hours, `end` checks the endpoint, `ever` refuses on both `multi` and `filter` policies when any gap makes campaign membership incomplete), faction coverage, and single-throttle trailing-flush mirror/tooltip cadence.
3. **Dated facts resolved at the model's hour.** Country existence, slot holders, faction names, player names, flags, colours, and membership are resolved at the projected hour (or a row's own observation hour when older) and advertise their next boundary via `nextChange`, never by looking up the end of the branch. Whole-panel and ranking refusals are represented explicitly (`TableModel.refused`) with the native refusal reason and warnings on both followed and exact paths, and rendered through `WidgetState` without swallowing refusals into empty pictures.
4. **Typed values everywhere.** Every rendered scalar passes through the family value contract (ADR 1397), formatting integral numbers at or above `2^53` through the `BigInt` path to match bigint cells, rejecting blank text and non-finite numbers, and never substituting `notApplicable` for unread or unrecorded facts. Missing country or player names remain explicit `notRecorded` values with their reason, never internal identifiers or placeholder strings.
5. **Host-owned playback discipline.** The family host delegates chrome, body states (`WidgetState` with `data-state` attributes, neutral refusals without Retry, typed retryable failures with `restartPipeline` for follow errors and local retry for exact/static errors), skeletons (`useWidgetSkeleton('table')`), notes (`WidgetCaption`), summary pills, and live announcements to the widget frame (ADR 1398), caches viewport geometry, focus anchors, and fitted tooltips outside `install()`, uses worker-supplied `focusedIndex` without scanning navigation rows on install, releases all resources on unmount (deferring active-capture audit snapshots until verification drains), and executes zero React commits and zero layout or style reads while playing with unchanged structure.

For the table family, ordinary widgets declare their sources, country policy, settings, and columns as data (`TableWidgetDeclaration` + `declareTableProjection`); the registry renders them through the one `DeclaredFamilyWidget` with the table's pure host adapter (`table/hostAdapter.ts`) and its header chrome (`table/TableChrome.tsx`), so ordinary table widgets carry no component file, no time gating, no request wiring, no exact-read builder, and no body-state `WidgetState` code. The shared `FamilyHost` subscribes declared sources on the playback `Pipeline`, binds a worker-painted canvas surface with fixed per-column numeric widths (avoiding per-frame text measurement growth and audit column-layout drift), and caches viewport dimensions and focus anchors from `ResizeObserver` so `install()` performs zero layout or style reads and zero React commits while structure is unchanged. The worker caches projected models and layouts across unchanged sources, builds mirror rows at 1 Hz while playing (flushed via cadence timer and immediately on pause) and audit rows only when requested, and paints only visible cells whose content or geometry changed since the previous frame.

Interaction is identity-tracked: pointer hover resolves to a stable row key (`inspectedKey`), a click acts on the inspected row even if rows reorder beneath a still pointer (cancelling on >4 px drag or `pointercancel`), and hit testing accounts for animated glide offsets. Hover (`fields.tooltip`) and keyboard focus (`fields.focusTooltip`) stay independent: hovering another row never hijacks keyboard pinning (`P` pins the focused row's tooltip at the cached focus anchor). Keyboard focus lives on visually-hidden mirror `<tr>` elements, moves with the focused row across re-sorts, and draws a 2 px accent ring on the canvas.
