# 1105. Keep naval counter admission and retained port plans separate

## Decision

Derive placement and port membership from the hour's operands through `naval_member`. The ordinary map path and the naval layer use the same decisions with different joins. The ordinary path walks mixed occupant arrays with the same province admission as land counters. It excludes combat task forces and docked task forces, while still preparing ship-model buckets for them. A carrier air base on the first carrier in roster order admits an at-sea counter in air mode. An unknown model operand reached before that carrier makes admission unknown. Ordinary counters draw no task forces in operatives mode. Use the movement map's land flag when present and the content's province kind otherwise.

## Naval counter presentation

- Group counters by roster owner in country-colour mode and by allegiance otherwise. Coarse groups and groups shown to someone other than their owner may combine different fleets. A detailed group shown to its owner combines its own fleet with another only when both are reserve fleets. The reserve decision comes from the first task force in the recorded fleet roster. A missing roster or mission leaves that decision unknown. The sea marker uses a non-reserve own representative's fleet colour. The port marker uses an own item whose first and last members have the same nonzero fleet.
- Keep the representative's handle as the counter identity. The representative's logical owner supplies country tint and can supply a sea ideology frame through its ruling party and civil-war status. Retain the raw signed frame argument, including a reset value of minus one. A port item uses its own window, has no coarse variant, and omits the ideology frame. A detailed sea counter can use the representative's detailed flag owner. The coarse one uses the roster owner's canonical slot.
- At sea, average the fixed-point ship ratios of fully visible task forces. A port item shown to its owner bypasses the representative's full-visibility gate. Every member contributes to the port mean when it draws. Missing required operands make the bar fill unknown. A complete empty task-force roster has zero ratios. The detailed selection outline requires a fully visible member. The combat and port items use the first member's visibility for the no-intel hull and the count range, and every member contributes to ship and capital counts. A visibility below 150 uses the no-intel mission hull. Pride needs a qualifying member, and the port item also requires full visibility of its representative. Unknown ship counts stay unknown even if the roster itself is known. Unrecorded carrier operands retain every possible icon state when they can affect the answer.
- For a single-owner port item the representative's detailed flag supplies the flag. For a mixed item sum each canonical owner's ship strength with wrapping arithmetic. The lowest signed total wins, with the owner's first raw country reference supplying the signed tie key. The mixed-owner flag requires a complete ship census. An own port item shows a mission when its first and last task forces carry the same mission. Its tooltip metadata is kept independently of the visible text.

## Port admission and caching

- Walk the base province's naval occupant array. The port admits a task force with a fleet, ships, an empty ordinary route, a linked visible owner and an ordinal in that base's array. An operand missing from an incomplete census leaves the roster undecided when it could change membership. This covers a missing force row named by the base, the route, the owner's link and a missing ship count. A known force with no ships, no occupant entry, or a route under way is out. Keep an incomplete occupant array distinguishable from an empty one.
- Build port membership and anchor facts once per hour. Record handles with their occupant ordinals, including repeated handles. A layout that joins another hour's rows uses handles. If a referenced force is gone, refuse that base by name. While a seek awaits newly prepared tables, use the rows associated with the displayed tables. A retained plan belongs to that preparation and cannot carry across hours.
- Sort own forces first. Native fleet comparison subtracts the low words in signed wrapping arithmetic and then compares high words when needed. The resulting order can cycle. The native stable algorithm matters, including its ordering of otherwise equal mission keys in the coarse comparator. Coarse sorting depends on mode and camera distance. Political mode or strategic grouping replaces the comparator run boundaries with allegiance boundaries, keeping the selected own run separate. A closer strategic view keeps fleet, mission and selection splits. These cutoffs are independent content values.
- Memoize only the ordered flotillas. The key includes the handle occurrences and their order plus the grouping state. A free eye bypasses the memo. Generate native calls and resource requests in the same order on every preparation. Base icons have their own distance pass and still draw with no port items. Clear their items for a coarse political camera, a viewer in a peace conference, or each base beyond the free eye's grouping distance. The province-icon gate clears the bases and their items together. Report each item beyond the window's authored capacity.
- The at-sea representative for placement is chosen by individual strength, so a single stronger cruiser can set the anchor even when grouped destroyers have a greater combined strength. A route whose point the hour cannot place keeps the province placement with its named gap. The ordinary counter pass reads no naval unit inputs when its camera gate hides the counters.
