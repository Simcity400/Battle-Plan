# Rebuild retained script state only from certified boundaries

Baselines establish existing registry membership without assigning it occurrence times. Retain duplicate members and replace or remove only one matching entry when the native operation does. Pending removals swap with the tail. Feed delivery and retained state are separate. Events can remain visible while an owner's registry is unusable.

Reduce delayed-event timers in native vector order. Visits apply signed decrements. Queue edges preserve swaps and effects that schedule a new entry during the current pass. Distinct timer labels are required in each admitted queue. Writer deltas can extend an open baseline or a certified queue. A gap, loss or owner refusal retires the queue and any baseline before applying later changes so stale labels cannot collide. Other owner queues remain valid after an owner-specific refusal. Complete transport alone restores nothing. A new baseline within a partial interval or an explicit empty certificate can restore the owner. An unavailable interval cannot certify a baseline.

Decision owner membership, candidate containers, flags and ordinals retain their distinct operands. Candidate clearing uses a dedicated bit that member operations use as part of the ordinal. Each clear can discard one kind or every kind. Use the certified fixed5 political balance at the final roster boundary only. A refusal closes an open baseline, leaving its subsequent Ready with no baseline to complete. Owner-level touches and versions represent what the part holds and which rows may have changed. A countdown alone does not move a part version, and availability is checked separately. Versions never repeat across generations. Preserve the first witness within a continuation and use the published link to identify an owner. Serialize owner maps as ordered JSON pairs so tuple keys survive serialization.

Prepare each pack once. Keep its header, coverage, sequence boundaries and only the retained-state changes, then intern payload content independently of date and sequence. Small tokens live inline. A walk tries the previous payload's successor before hashing, since recurring changes tend to recur in order. Include the political balance when distinguishing roster rebuilds. A pack brings every new payload it introduced in ID order. Consumers admit every pack of the walk even if they skip its reduction; a skipped or failed reduction invalidates trust in target writes from the preceding packs. Starting a different walk starts a fresh payload set.

A prepared plan may omit duplicate target writes and candidate changes cancelled by a later clear or baseline. When reduction fails before that clear, restore the cancelled candidates the unoptimized order would have applied. Rebuild roster observations remain their own occurrences and move owner state only if they create, rename or lose the owner. Use the straightforward reduction as the oracle for prepared state, touched parts, boundaries and outcomes, including skipped reads and a failure in the middle of a pack.
