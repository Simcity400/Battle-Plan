# 0301. Keep equipment icon choices reproducible across presentations

Production and stockpile resolve images through the same ordered equipment rule. The kind-1 automatic `"."` entry asks the creator’s graphic pool with its ideology group and graphical culture regardless of the stored active flag. Any other active entry validates its kind and tries the sprite or path; an inactive entry of any other kind falls through to fallback. If neither supplies an image, an existing origin takes precedence over the creator for fallback; otherwise a static creator keeps its incoming handle without requiring appearance data, while a dynamic creator substitutes its recorded `original_tag_reference` when positive or falls back to the country object's own handle (and when `dynamic_tag_boundary` is unavailable, still resolves whenever both branches agree). The fallback tries the type and valid archetype using the raw handle's witnessed tag spelling (withholding lookups whose handle spelling is missing), then each type’s sole enabling technology and its parent, then the country’s pool, proceeding through family links. An unknown capital continent preserves consistent continent hypotheses across the entire icon fallback chain (sharing one hypothesis across countries or states with the same recorded continent token, or the same recorded capital state when the token itself is absent, across family links and prepared iterative `IconChoice` branches, keeping raw handles for tag lookups, and reporting a proven continent disagreement for the splitting capital ahead of a reached asset error on another branch) and across single-winner aircraft-override lookups, keeping exact native uncached visit order when the continent is known, resolving whenever every possible continent chooses the same available asset (or none) and withholding otherwise; full candidate-list lookups still withhold when any matching continent-specific pool exists. Capital ships try their specialized suffix first. A static slot uses its own witnessed tag for technology sprites without requiring appearance data, while a dynamically named country uses its original tag (resolving when both agree if `dynamic_tag_boundary` is unavailable). A registered empty string differs from the native null archetype and remains a valid named lookup. The null archetype supplies neither sprites, technologies nor pools.

An unknown country operand withholds only a path that reaches it. Once an earlier candidate’s result is unknown, a later candidate cannot stand in. The content loader resolves equipment and its technology guards in the recorded stack. Guards run in a fresh empty content-load scope. A script whose enabling effect is unknown can withhold the affected type’s technology step. An icon found before that step and types the script cannot enable remain available. The lexer recognizes case-folded forms of equipment tokens, and sprite keys match byte for byte. Pool entries can denote a declared sprite or a path, as distinguished by the save loader.

Prepared choices keep the rule’s artwork probes in priority order. These probes ask only whether a sprite is declared or a texture exists. The answer can choose the first successful probe or stop on an unknown result. It cannot change later candidates or recorded facts. Each presented catalogue can replay the probes using current art and redo the complete draw in the recorded catalogue on fallback. Keep the graphic-pool, geography and recorded DLC inputs in the preparation key. Stamp all required content inputs, including paths map defaults can indirect to. Unstamped input prevents reuse.

Parallel content reads must preserve the native read order for first failure and diagnostic credit. Reusing the equipment registration still requires the normal verified reads. A partial prefix cannot manufacture a complete equipment database. Keep absent and refused sprite declarations distinct throughout lookup.
