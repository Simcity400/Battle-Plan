# Admit acquisition after collector attachment completes

The process-start identity distinguishes instances of the game even if Windows reuses a process ID. Each game process admits one collector through a named mutex before game reads or hook installation. A refused detach keeps the mutex while it retains the published shared state. Its live relays still belong to that attachment, so another collector may not take over.

The recorder creates the session folder, names the lifecycle events, and supplies immutable demand up front. Absent map event choices admit every family. Campaigns on the history exclusion list omit their previous recording history. The collector and recorder hold the same exclusive output reservation during capture and finalization, including for campaigns with no replay yet. The collector unlocks before signalling completion because the recorder can finalize immediately after seeing that event.

The runtime prepares immutable metadata before publishing hooks and resolves game sites through the located image. The game executable remains mapped for the process lifetime. An unknown build warns, then verifies or withholds each part by name. On the reference build every resolved site must match its expected position. Essential families must verify before the remaining game reads and hook installation can proceed. A nonessential family that fails its sentinel check leaves its observer uninstalled and uses the normal unobserved read path.

Prepare the worker-panic guard and any early-exit diagnostics before spawning workers. A request for an unavailable diagnostic sampler fails at attachment. Hook timing starts before installation; the sampler itself starts paused to keep it out of the publication suspension. Its failure goes through the common unwind path. The runtime joins the sampler before restoring hooks or joining the workers it samples. Conversion helpers, sizing, and the frame builder participate in worker quiescence, even though the spool owns their handles. A missing helper falls back to serial spool work. A missing sizing worker moves that work to the spool, and a missing builder leaves frame construction to the capture that needs it. Without the off-thread capture worker, captures hold the game.

Sizing starts with the live country registry and weather demand. The registry may be empty at the menu, so sizing grows again after load. Weather capacity includes retained edges from a native rebuild before attachment. Occupation watches are prepared off-thread from state demand so the first capture can certify its initial hover rows.

Plain hook families publish under a shared suspension. Taps with unwind retention, split or multi-step publications, the hourly hook, and world lifetime use separate publication. A collect error limits the batch to its eligible prefix. Report every result in chain order, including rollback failures, and run each family’s original validation and bookkeeping. The hourly entry is ordered last. Its published hook can run before the reports settle, so admission remains closed until every family has finished reporting. Open admission before enabling off-thread capture. Status names the family that failed or was busy at the installation deadline. Build that borrowed reason once on the runtime thread and retain it until unload.

Lifecycle events can be signalled, reset, or waited on from any thread. Their owner closes the handle only on drop. Production refusals and regression cases share the same detach refusal boundary.
