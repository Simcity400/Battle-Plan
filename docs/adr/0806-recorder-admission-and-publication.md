# Scope publication to loads the tray recorder admitted

The tray and command-line recorder share a capture path but have different admission policies. Before starting the collector, the tray opens an empty admission record and writes its session marker. The initial selected load is admitted before capture. A probe asks about each newly identified load while recording. Finalization asks about loads the spool identified that were never probed. Earlier hours of the same campaign count as an existing recording, including a pending New file. A refusal during capture ends the session. A refusal names its cause when known, but the refusal record never grants admission.

The tray publishes only the logged campaign and load-signal pairs. Decisions reach disk atomically before they take effect in memory. A missing or unreadable admission record for a marked tray session refuses publication. The command line omits the marker and publishes every load. On a load the spool cannot identify, no admission is inferred. An ended session has no remaining decision maker. Omissions preserve their hours and any known reason, including disabled automatic recording, another publication destination and unreadable settings.

Each campaign has one writer that consumes its journal captures in order. The journal is the evidence of what the collector wrote. Only closed spool segments may be deleted before the collector releases the last one. A later segment or released handle lets the writer finish the captured prefix even without a detach record. Loads are identified once and ordered on the session's shared performance counter. A recorder restart records where it happened without treating it as damage. A failed writer retries from the latest verifiable revision, and an interrupted initial write with no verifiable footer is rebuilt from the journal. Finalization can leave some campaigns incomplete while publishing the others.

Before first save, a campaign's recording lives in its destination's hidden unsaved folder. A named recording and a hidden recording for the same campaign is a conflict. Readers continue seeing the last saved revision while new hours wait. Save publishes a new revision, then chooses the name under a directory lock. A rename refusal leaves the existing recording visible or waiting where it was. If a capture still has hours since the last closed block, an explicit live save becomes a request to save subsequent revisions and finish at session end. Prediction can omit a name when one or more loads have no decision. The output folder, autosave decision, preserved user name, and name refusal are recorded distinctly from what capture produced.

The session writes its initial revision and later explicit save points so a Stop discard can roll back its own contribution, even hours that automatic saving exposed. A waiting-list discard instead drops all sessions' hours beyond the newest saved revision. A live writer closes its own reader before checking whether the collector still holds the newest journal because the handle probe cannot tell the two apart. A deferred discard records its intent before touching the recording. The next recorder can resume the cut and remove the resume state and spool after the collector releases them. Repeating a step is safe, and the note remains until all work is done. An explicit save preserves the game facts its revision needs.

Tests cover in-place first publication, reader visibility of the saved revision, crash restart before first commit, multiple campaigns, explicit save before discard and a discard interrupted while the collector holds the journal. The recorder's inspection distinguishes an unfinished capture from one whose collector detached normally.
