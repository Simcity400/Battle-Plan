# 1109-D. Retain a GUI instance across presented frames

The viewer constructs one instance per window identity against an immutable template and resource registry. The instance and draw walk resolve the same authored and inherited objects. Scrollbar parts, named scrollbars, drop-down windows and fixed-window backgrounds each keep their own constructed state. Repeated authored paths resolve to the first occurrence. An equivalent copy of a template may be used, but it takes the full traversal and validation path. The construction viewport is the device extent divided by interface scale. A window nested in another window is laid out inside its content. A separately built window uses the holder's viewport-sized position object.

Prepared hours carry ordered calls by instance and element path, which the presented view applies. A borrowed stream stages mutations and commits only after every call succeeds. Resource lookups can still run before a later call fails. Text writes with a scrollbar must resolve in order with the other calls, because each one refreshes its scrollbar. Frame, text, colour and progress writes stay in force until superseded. A sprite setter preserves both drawable and clocks when its lookup fails or the name is unchanged. Successful replacement preserves the control state and resets the drawable's clocks and frame, including when hidden. A frame or play call made before replacement reached the previous drawable.

One presentation time in seconds is shared across instances in a view. Each frame runs drawable clocks, then window transitions, then draw bookkeeping. Related instances complete each phase together. Windows register after their children and transition in reverse registration order. A drop-down's header and expanded window register too. Their construction is outside the ordinary child list, which keeps them out of inherited opacity writes. Draw bookkeeping marks the first draw, records trigger times, and restarts an effect's state clock at the first draw after a change. Saved pictures can finish configured fades and movements in one step while drawable clocks keep their own time. A live frame advances by its own step.

Construction starts controls and windows hidden and starts fading subtrees transparent. A hide guard blocks a later Show, while changing that guard leaves current visibility alone. An ordinary Show without movement preserves child visibility. GUI Show traverses admitted children and owned parts, with each child's own guard. Hide can wait for fade or movement to finish before hiding children. When the parent has no hide fade the request reaches child windows. A window-only Hide affects the window's own visibility and leaves its children's drawable clocks running. Plain scrollbars can show constructed range icons even under an authored hide guard, until a code Hide reaches the bar. Fixed windows use the background and each attached child's visibility calls, without container fade or movement.

Ordinary position writes preserve the stored anchor and coordinate bounds. Percentage axes use the parent extent and round half away from zero. Flag-zero size writes update the wrapper, backgrounds and scroll without changing the children's constructed reference extent. An immovable window snaps to its previous target before retargeting. Movement can apply its final hide on a later tick. A settled capture applies that hide immediately in its transition pass. Extents and hit geometry measure the same retained drawable that draws.

Container scrollbar smoothing preserves the retained target, using wrapping fixed-point arithmetic. A hidden slider or a value close enough to the target snaps. Wheel input snaps and applies the new offset without the ordinary notification, while a hidden bar leaves the content where it was. Hiding a bar during grid synchronization clears the content offset but retains the bar's range and target. Text scrolling has its own notification. A text write replaces its range, updates the slider and can change visibility, while a limit-only clamp does not move glyphs.

Frame animation interprets the stored frame count as unsigned for timing. It enforces the native minimum duration and retains a code-selected frame until playback writes one. A loop wraps by its duration plus pause and uses frame one during the pause. Pulse and frame wraps that cannot progress are refused. A drawable state effect settles only while the clock stays within its finite range. A draw that keeps the previous technique inherits that program's settling behavior. Unknown inherited state or a refused layout keeps the instance active, and a kept draw after a refused program remains refused. Quiet instances can stamp the shared clock without advancing the revision. A move changes placement without dirtying the layout. A kept layout is keyed by revision, root, caller resources and whether it includes regions. [Native layout revision](1192-native-layout-revision.md) Hiding a root can skip the draw walk after clocks and transitions have run, when it cannot bypass resource or text validation and the root cannot still draw scrollbar icons.
