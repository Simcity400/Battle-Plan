# 1102. Bind commander artwork and tactic entries with exact fallback semantics

Read direct textures through the effective content stack. Keep GFX declaration names and file paths in their separate native namespaces. Recorded asset paths are content-relative and cannot authorize a read outside those layers. Select the commander's role and size, with the first entry of that size as fallback. A matching entry that is unset still takes precedence over a competing role. Use a direct fallback texture when present, and only a verified graphics tag for a country-specific candidate.

A missing assigned portrait name displays the authored unknown commander sprite. An undeclared selected portrait sprite leaves the widget's existing picture and records the refusal. A portrait selection that cannot resolve hides the image. A tactic icon comes from that side's resolved definition after identity and refusal checks. Missing selected tactic artwork clears the previous image. The null singleton can attempt its own artwork and leaves the previous image if the texture is unavailable. Compare both sides' recorded counter IDs when the tactic really is the null singleton, while a null pointer carries no ID.

Render assigned trait icons in their recorded order after applying both filters. Use the exile template with its country flag for the corresponding entry. An unregistered or missing trait sprite has a distinct diagnostic even when a fallback image draws. The trait registry and content stack govern eligible sprite registrations.

The popup's entry tooltip is distinct from the selected tactic tooltip. Its main text describes the authored attacking or defending stat polarity and the counter. The last duplicate counter definition wins against the completed registry; a missing counter has the null ID. Requirements, side conditions and weights are delayed text, and a lock replaces only the immediate text. Even a locked definition can contribute the condition explanation. Preserve the ordered, potentially repeated lock sources and their leading newline. The hover sums signed weights, while list normalization only uses positive weights. The root owns its hover, and each independently refused fragment is named without displacing valid ones. Missing localization keys can display their own names; reached unsupported text controls are actual refusals.
