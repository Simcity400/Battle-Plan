# Keep token identity and trigger admission on the content reader

Reader lookup depends on the original lexer token. Bare names fold ASCII case and quoted or numeric keys do not enter keyword dispatch. C-string names end at their first NUL. Empty, digit-leading and minus-leading names share the rejected token. Other names match by folded bytes. Stored-order lookup returns the first entry for a token and uses the native null object for a miss. A reader that recognizes only names already registered distinguishes absence from rejected names.

Trigger dispatch checks immutable built-in classes from verified executable metadata before scopes, content counts and scripted triggers. Authored registrations come through the recorded content stack. Dispatch carries errors from dynamic count or scope lookup. Conflicting building declarations can leave its provincial classification unknown. An unread content tail can define otherwise unregistered names, so it cannot prove absence. The parser preserves each child's key, operator and value as a conjunction; the dashboard evaluator alone decides the body from recorded state. Nested collection and priority readers inherit the enclosing key registry. A specialized body reads its own fields before fallback trigger dispatch and skips a reported unrecognized block when that reader provides a block skip.

A later conditional limit is read only while the prior limit holds no children. Skipped limits introduce no variable definitions. A registered scripted trigger can fill that first limit, an unregistered key cannot, and an unread registry leaves its result unsettled. A scalar body reports the form and supplies no children, leaving the caller to refuse the shape where needed. A variable-check body consumes the scoped value without a block skip. Preserve these distinctions when projecting from text and when constructing a parsed body for the evaluator.

The variable stores resolve built-ins on demand before stored keys. Names preserve their exact byte spelling, without operand suffixes. The character store uses the executable's unit-leader table and purchase contracts and factions have no built-in table. Medal definitions retain duplicate entries in content order, reserving ordinal zero for the null definition.

Layered reader tests create independent base and mod roots. Synthetic ZIP records can set the version-made-by host byte, general flags and stored or raw-deflated encoding. A synthetic self-extractor prefix precedes the archive without contributing to any ZIP offsets so the fixture reproduces relative offsets.
