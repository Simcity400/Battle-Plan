# 1121. Draw each dashboard frame for the display it reaches, and never decode a product's table on the stepper

A drawing lane reads no clock: it draws the hour the page asks for, and the page dates every picture from the hour it published and installs it in the commit of that frame (0505). The page measures the display interval from short gaps between its playing frames and tells native that rate with the clock.

Only the dashboard playhead's stepper runs time-critical; the map's stepper runs at normal priority. Its step helpers and its share of a seek run at normal priority, and fetching runs below normal. A product's step reads its tables from the step's lanes. If the step lacks a lane that the host will give it, the reader looks among the placed tables the product pool holds near the hour and steps one forward. If none is near, the reader places the table on its own thread, with every column the pool already holds for it, and reports the read pending. A pending read sends a waiting record at its hour. Queue pressure never merges a message that holds a waiting record, because no compaction of waits and readings keeps every unread hour unread across resets and piece crossings. Pressure on such a queue fails the stream, as any unmergeable overflow does. Panel messages merge only under pressure, which normal playback never reaches. The page covers that product's picture only through the hour before it waited, whatever later steps complete, until a record of its own arrives. A native reset on the same seek likewise holds each shown picture to the hour it was confirmed through, until the product's own record after the reset arrives. The host reads that product again at the same hour, whole, and finished placement asks the playhead to run its hook again, so a paused or ended playback still retries. A retry plans every stage again, because the read it replaces may have consumed changes its plans depend on. A seed has no step, so it reads directly and leaves its tables placed, and the step after it can use them at once. A table that cannot be placed is read directly, as before.

A product's live values are current only when it builds a reply or a caller asks for them. A seed, a resend and a complete read ask, and the reader fills them at that hour without rebuilding the reply. A streamed reply that only carried moving values keeps its data, and the page reads those values through its followed cells. An advance that only reads the held reply leaves it shared, and one that writes it copies it first.
