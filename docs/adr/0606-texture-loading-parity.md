# Keep texture sampling consistent with the resource loader

Art readers reproduce the resource loader's fallbacks and output formats because consumer UVs, compositing and colour depend on the resulting texture. Try DDS magic first, the native Targa reader when the requested resource name ends in `.tga`, then FreeImage's content-based plugin selection. An unsupported or undrawable format produces a named refusal, separate from an undefined read, an outcome that depends on the graphics device, or a caller budget refusal. Budget checks count the padded texels before allocating. The test vectors compare the software readers with FreeImage 3.17's 64-bit decode using flags zero and the same texture conversions.

For DDS, preserve the classic loader's block-rounded extents and the mip prefix present before a file ends or an axis reaches one. Cubemaps store each complete chain in face order, and a file that cannot establish the whole cube is refused. Nonblock formats keep the selected layout, including unexpanded 16-bit channels. Turn X1R5G5B5's spare bit into opaque A1R5G5B5 before padding, modelling a device that supports that format. BC7 via a DX10 header is a separate supported format. It uses the logical extent and complete authored mip chain. Both zero extents produce at most two empty levels because further empty levels cannot change whether the device can create the texture. The UI's CPU expansion honours the decoder's admitted extent and samples 16-bit channels as the device does.

The client's power-of-two setting places each old level at the top-left of a new zeroed level, preserving the number of levels and copying compressed formats in whole blocks. Consumers use the padded extent for sizes and UVs. A zeroed texel samples as opaque black in a format without alpha and as transparent black where the stored zero is transparent. A padded level with zero extent cannot establish the texels the device would upload and is refused.

The native fallback uses the FreeImage Targa path for formats the engine path refuses or when the logical resource name never selects its Targa reader. Keep authored origin flags and the native palette, packed-colour and row handling. An early end in an eight-bit raw row keeps the bytes read into the zeroed bitmap. Other reads of uninitialised or stale storage are refused. In the direct Targa reader the stored alpha byte of a 32-bit pixel remains coverage even when the descriptor declares no alpha bits. A 16-bit pixel is opaque X1R5G5B5, since treating its spare bit as coverage would erase flags the game displays.

Match the FreeImage JPEG wrapper's IJG 9a settings. It uses the fast eight-by-eight inverse DCT and disables fancy upsampling. Larger or smaller authored blocks and scaled component sizes use the corresponding integer inverse DCT from IJG. The port preserves signed 32-bit wrapping, the AAN loading scales and the upstream statement structure for comparing the integer transforms. Keep the natural-order table tails because the decoder indexes them, and latch each component's quantisation table at its first scan. Run the decode over the whole image while preserving the scan output from the library's streaming path. Its source supplies end-of-image markers when the input runs out. The wrapper tolerates the unknown-marker result and stops on other decode errors. Output rows run top first, with Adobe's inverted CMYK converted by multiplying each inverted colour by K. EXIF rotation is disabled under flags zero. [IJG licence notice](../../LICENSES/IJG-libjpeg-README.txt)

PNG follows FreeImage's libpng chunk ordering, warning and colour-space handling. Critical stream faults fail the decode, while a bad ancillary chunk may be discarded. Preserve the consecutive `IDAT` run and require the end marker. Invalid colour metadata clears the file gamma. A structurally accepted `iCCP` profile is treated as sRGB under the bundled profile settings, and only a bounded window is needed while examining it. Gamma applies when the file and screen gamma product differs from one by more than the library threshold. Apply it to colour channels after comparing raw samples for transparency, taking significant-bit declarations into account for the 16-bit table. Alpha stays untouched. Preserve the PNG and ICO paths' distinct texture conversions, the half-row upload layout of 16-bit RGBA, and the order in which `PLTE` and `tRNS` affect transparency. The ICO path loads page zero, selecting the PNG loader when its embedded image is PNG. Flags zero supplies no AND-mask alpha pass. The BMP path retains native header and palette distinctions for Windows and OS/2, including bottom-up run-length data. It keeps deterministic partial true-colour rows in a zeroed bitmap where the native reader does, and refuses outcomes that would overrun the bitmap.
