# Key orders and naval inputs to their own mutation domains

The naval hover observer owns the commander writers. The country-input and politics owners forward country modifier recalculation and country appearance reset. The observer admits a certificate only while all three owners observe their sites. A writer in flight, missing receiver, poisoned watch or epoch change forces a fresh read. Forwarders withdraw availability before removing their patch and announce availability after installing it. Commander writers also forward retreat-ban and trait changes and leader lifetimes. Occupation uses separate certificates with the same owner lifecycle.

Held trees reuse a receiver's certificate only when its accumulator is unchanged. A held tree owns its preorder and the arena of its display bytes. The naval combat capture owns the store for its whole attempt. A failed capture drops that store so the next attempt reads fresh trees. Naval missions use the same certificates for country and leader rows and reread an affected country within the hour. The counter, reserve and raid-intel reads also use or size these watches. Size the watch table off-thread from every consumer that registers receivers. This includes the country and fleet leader of each ship-model task force, even in a recording with no naval mission or combat. A first table can install immediately. A larger replacement waits for an invalidating hour. A range consumer may make provisional passive lookups, but a cold receiver enters the watch table during ordered admission. A diagnostic build independently reads each reached tree for the sample oracle.

Orders-group carry depends on its own writer family and the template family's destructor forward. This prevents a newly allocated group from inheriting the certificate of a destroyed group at the same address. The daily update can clear training for a group training to its maximum. Other groups need only the running guard, which protects detach without changing that group's certificate. An unreadable training operand is treated conservatively. The division census also consumes a distinct order-membership certificate, since changing status membership and changing a group's measured fields have different writers. The census counts groups before watch installation and uses the peak observed count for off-thread sizing. Hook failure diagnostics allocate only after an attach or detach failure, and the runtime retains them for its static error interface.

## Callback and release contracts

- Fleet region `SITES` have a fleet as their first argument, accept at most four integer or pointer arguments and return through RAX. The authenticated native method owns the live fleet during `region_count`, which uses a guarded copy without allocating or calling the game. `Hooks::drop` releases its watch table after restoration and drain. Each of `writer_spans_original_preserves_arguments_and_invalidates_only_its_fleet`, `unchanged_membership_keeps_certificate_and_a_count_change_revokes_it`, and `a_fleet_the_full_table_cannot_hold_is_certified_by_the_family_quiet_token` releases its watch table after the synthetic original returns and its notification ends. [Fleet region observer](../../crates/collector-observers/src/fleet_region_changes.rs)
- In `naval_tree_changes`, each callback receives its receiver in RCX, forwards up to three further integer or pointer arguments in RDX through R9 and returns the original's RAX. Its notification spans the native call. The modifier recalculation tail, HQ modifier update, construction and destruction receive the leader first. Copy construction also receives the source leader. `Hooks::drop` frees the naval, retreat-ban and trait watches only if the hooks were never enabled or after they are removed and drained following the last capture. [Naval tree observer](../../crates/collector-observers/src/naval_tree_changes.rs)
- In `orders_group_changes`, `trains_to_maximum` uses guarded reads on the native calling thread. Each `NativeFunction` site uses at most three integer or pointer operands. The callback forwards RCX through R9 and returns RAX. Only a normal return ends the notification, so an escape retains its ownership. `Hooks::drop` releases the watch table only if both its own hooks and the template forwarders were never enabled or after both are removed and drained following the last capture. In `order_membership_changes`, `Hooks::drop` likewise releases the registry only after its relays and callbacks are quiescent.
