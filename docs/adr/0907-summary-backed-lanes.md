# 0907. Answer dashboard lanes from summaries and exact tracks

Storage-level requests take a run and game hours. Table snapshots decode complete selected columns from the most useful restore. A key selection reduces returned rows, since the column-major format cannot decode just those rows. Explicit keys and ordered disjoint ranges identify owners without visiting other returned rows. Partial reads show only the rows read in that hour. A batch sorts requests by hour and key and advances one cursor through shared parts, restoring again when a later restore saves work. Missing, unrecorded and unread row states remain distinct from numeric zero.

Runs of equal values and cell histories read tracks instead of visiting every hour. Equal text is compared by content even when its string id changes. A list or opaque write marks a change hour, and callers can batch reading those payloads at their change hours. A row's insertion carries its original cell values and a row that is no longer visible stops contributing. If every selected key is absent from a block, the block's key summary can skip walking it. A facet summary of an event log does not prove that a row key is absent. Logs stored as append/forget streams do not expose state-table histories. Read hours and statuses come from page entries and keep the recorded distinctions across block boundaries.

Charts fold on the absolute hour grid. They use a suitable summary level when it covers enough hours per bucket and walk finer or uncovered ranges. A walk begins with the previous hour's cells when it exists, then uses the same visibility and aggregate rules as the summary builder. Each key can fold into its own output slice independently. Lifetimes combine the highest available pieces with exact uncovered hours. `next` skips buckets whose pieces prove a value held steadily, then examines the first possible change range from the tracks. If the pieces lack the column, it walks that column's tracks directly. Coarser pieces convert first, low and high bucket positions to the first level-zero bucket, and the last value to the last level-zero bucket.

Top-N ranks break ties by key. The last-value ranking uses the last bucket that has a value, so a key whose last observation was in a prior bucket does not qualify. A bucket split across pieces has distinct ordered positions. A recorded summary rank can select keys when the piece has at least the requested capacity. Otherwise each worker folds one key at a time in scratch storage, retains its top candidates per bin, and merges only those candidates. Log counts use an absolute grid of six-hour multiples and decode only the requested facets.
