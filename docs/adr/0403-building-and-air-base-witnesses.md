# 0403. Carry building and air-base rows only across observed writes

Building rows use the locations, flags, identity and country from the authenticated status and each building's level, health and ordered membership. Build status and province links need their own authenticated layout. Level setting is the sole runtime level writer, applies health changes and rebuilds active membership on zero crossing. Damage, repair and healthy-level destruction can change the remaining health fields independently. The building backlink names the affected status. Only lookup and creation write building and index membership at runtime. They initialize the new building's identity and the caller uses it through the observed setters. Save reading reconstructs buildings and active membership. Status clearing and zero-count index initialization take place on reset or nudge, while construction and destruction follow the owner.

State owner and controller setters do not change the status identity fields. Load, reset and nudge can change location tables, ids, membership and province state links. Nudge can rebuild a state at the same address or move a province without a normal writer notification. Its entry therefore disables reuse for the attachment. Ordinary building writes run on the game thread.

Air-base registrations index both the dense registered-container list and the slot vector. At runtime only container creation and access removal write those collections. A registration captures the container's country, capacity and pools, including pool identity and wing backlinks. Registration and erasure edit the pool list, while wing creation, transfer, addition, removal, destruction and splitting can change the pool contents. Empty-pool removal, withdrawal and teardown can destroy a pool. Rebinding its subtype to an updated local clone separately revokes held definition metadata. Scalar fuel reads are independent.

Base identity comes from its handle. A destroyed base's address may be reused with a new handle and fresh internal lists. An unlinked pool has a null or invalid handle. The collector carries a base only if every held pool still names it. Creation copies the base handle into its container and pool assignment stores it before registration. Capacity updates from the raid family, destruction from the ship-model family and editor entry from the building family are forwarded. Construction, loading and resets establish new identities. The hourly strategic-air stage joins its workers before the game thread changes registrations.

State-based air, rocket and gun installations each have a state-indexed slot. A creator returns its existing base or registers a new one and writes that slot. The building listener also clears destroyed rocket or gun slots. The manager notifier identifies slot changes without naming a base. Base construction establishes the host, kind, state, province and initial capacity. Capacity is later refreshed for level changes, carrier setup, refits and equipment recalculation. Load completion can rewrite a state base's province. Stateless bases are read every hour. State and province identities and their association only change on a load, reset or editor session.

Wing equipment capture keeps the variant handle from its authenticated pool entry. Relevant writers include bank changes and variant and pool addition, setting, subtraction, scaling, clearing, assignment and loading. The equipment destruction path owns the aircraft removal site and forwards its notification. Reinforcement, upgrades, deployment and rocket creation reach addition. Movement or consolidation can change both pools, and reserve moves and trimming can subtract from a wing. The hourly trim and daily return calls identify this pool specifically, while unrelated primitive callers can pass different pools. Construction, destruction and load bound a wing's lifetime, and ordinary base ticks, manpower updates and external stockpile copies are reads of the wing pool.
