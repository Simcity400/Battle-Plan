# 0901. Frame recording extents and run lanes independently

Clock, summary, and unit leaves use the same LEB128 integer encoding, with signed values zigzag encoded before serialization. The common primitive keeps their decoded integer representation consistent.

Recording extents carry the location and length of stored data, its kind and scoped tags, and the first 128 bits of the BLAKE3 digest of its stored bytes. Readers validate the location within the committed file and the digest before decoding. The footer stores the root offset, stored length, digest, and magic. Only the last block of a run may contain fewer than 720 ordinals. A span page indexes sixteen blocks. A block's clock writes the per-ordinal flags before the metrics. The table lanes hold independently addressable units, end-of-block restore points, and summaries. Span directories locate clocks and table rows. Span indexes store those row bytes without outer compression. Index extent streams name their tree level, and the owner assigns the tags of opaque data and stored extents.

Extent tags identify the table for units, restores and summaries. The ordinal tag gives the first ordinal for units, clocks, pages and summaries, and the last ordinal for restores. The covered count is zero for extents without an ordinal range. The recorder can add epoch reason codes without requiring a known reason list on readers. Preserve unknown codes. Load starts a game branch, rewind changes the parent, a world rebuild may occur within the same session, and continuation resumes the same campaign in a later session. Recovery after a crash starts the next hour-log generation, while admission refusal and an earlier write failure have their own restart reasons.

The immutable identity seeds the extent chains and holds the table schema digest, campaign identity, recorded content and mod stack, and capture mode. It computes the schema digest over the ordered column kinds in each table. A prefix digest accepts only the same tables and no more columns than the full schema has. Capture identity can be decoded without the final recording's version because the collector and recorder agree on the capture row format. A recording header requires a supported container version. Current format history added saved revision markers before separate lanes and span indexes, then switched each table unit to per-column streams ordered entity by entity.

Each block page names its clock, per-table parts and summaries, restore frames, status runs, strings, and chain. Each frame has its own location, stored length, and digest. The block chain hashes the previous chain and this page's body, whose references bind the frame digests. An individual string is read from one independent chunk of roughly one MiB, cutting between strings once the raw target is reached. Each chunk stores its first id and its length-prefixed strings. A span directory holds the block heads and the span's terminal chain. A table row within the span index can be read by itself and gives the table's blocks in order and its higher-level summary pieces sorted by level. The run directory is rewritten on each commit and names the closed spans and the open span's block pages. The first restore comes from the first block. A finished partial span retains its table summary pieces at the next level above block summaries.
