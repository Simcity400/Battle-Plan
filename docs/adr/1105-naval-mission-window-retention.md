# 1105. Retain naval mission window state across frame updates

## Decision

Prepare membership and controls once per hour. At presentation, reach each admitted region through its first scheduled province and process regions in that order. Visible provinces and presentation-dirty off-screen ones share the schedule. An off-screen region remains reached through its dirty phase without a refusal, then its icon is swept. Mission icons draw strictly below the content cutoff. Air and raids modes clear them. The cutoff erases the icon from the manager's visible list, even during its remaining hide animation. Returning uses the pool cursor and restarts a fading root.

Resolve the root, its content container, the list and the entry template through their authored hierarchy. The visibility walk requires containers and refuses fixed entry windows by name because it otherwise reaches control-array storage that was never initialized for that path. Build one entry per supported mission kind when the slot is first used. Ticking an entry never shown would leave it unchanged. The layout tests use independently authored fixtures whose dimensions, resources and text are synthetic and whose lookup names are interface contracts.

## Recorded inputs and visible controls

- Preserve the viewing navy's ledger registrations in stored order, including repeats and references beyond available region lists. Region zero represents no current mission region. Index the pride references the ledger reaches. For the shared pride choice, each counted pride registration replaces the previously chosen kind. Missing linked owners, pride references or required ship rows can leave the marker unknown.
- Register entries in mission-kind order and keep the authored sprite if the selected replacement is undefined, reporting its name. Replacing the sprite drops authored rotation while selecting the same sprite retains it. A progress-bar button accepts the selected frame number as its value. Vertical sprite strips advance by rows. Include the root's and entries' assets through native traversal, including inline sprites from authored localized text. Generated count and efficiency strings use digits, punctuation and colour controls and add no sprite lookup.
- Count text uses the overall count or `active/total` for kinds with activity, including patrol, strike force and invasion support. A listed zero-active ratio uses the font's red control and includes its reset in the same write. Use zero-decimal efficiency percentages, red below 75 percent. Hide and name each child with an unavailable required input. Keep readiness, activity and efficiency decisions independent where the update reads them. An unknown pride operand prevents its visibility write and keeps the entry unknown until a decided write.
- Apply alert, efficiency and pride writes to every mission record, including unlisted ones. Without a registration, patrol alerts, raiding alerts with zero efficiency, escort waits for its operands, and other mission kinds have no alert. Start buttons on frame one and select frame two for counted kinds. Unlisted entries keep their last count and list position, including any prior unknown count. Only detailed naval UI mode supplies regional unit and mine counts. Other modes clear grids and keep their authored backgrounds while hiding unused counted containers.

## Layout and lifecycle

- Use native layout and appearance calls in their authored order. Before `Show`, clear the child's hide bit. For hiding, call `Hide` before setting the bit. Apply grid resets and prepared membership after the common placement and visibility update. Position content using the measured first entry, the content's center and the displayed row's width. A root or list that does not draw leaves the retained entry places unchanged. Root margins, clipping and percentage geometry apply to nested entries. List spacing compresses only as needed, and `first_on_top` reverses paint order while preserving positions. A hidden content container can still leave the root artwork visible. An icon whose admitted region has no shown mission entries keeps its root and constructed list position.
- Keep the list's current records distinct from its retained attached entries and move appended entries to the end of attachment order. Clearing the list detaches nothing. Entries leaving the list can draw through their Hide transition below the current entries. A window without movement or fade hides immediately. A listed entry can restart its fade through the list's Hide and Show sequence. Hide movement already running continues after Show. Successful list layout reparents and places each listed entry again. If placement is unknown, withhold the entry until a later listing places it. Leaving the list before that update leaves the entry withheld through its hide.
- Pool slots retain their own history. Logical slot admission is independent of screen paintability and unknown mission censuses: an unknown mission census holds the retained pool untouched and withholds drawing by name rather than erasing slots with empty reach entries, and a registered region whose icon position is missing or unprojectable still admits and keeps its logical slot while withholding drawing by name until its position can be projected. After an unreplicated allocation or erasure, later assignments may differ from the native slot sequence. Treat retained list place, entry count and place, fade and movement as unknown on the affected allocation. An update can recover parts that it writes again. A structural refusal during owner processing leaves unreached icons unchanged and withholds the frame until the windows are built again. A refusal within an icon's update withholds that icon and its entries through reconstruction. A later successful partial update cannot repair the structural failure.
- Advance sprite clocks for all shown controls before transitions, then tick transitions in reverse registration order and update draw state. A root whose hide ends can hide descendants that already advanced their clocks, including attached entries outside the visible list. A reused slot keeps that animation phase. Unknown transitions after pool divergence or a tick failure withhold drawing until the longest registered transition has elapsed out of transitions. A window without transitions is known immediately. A pending pool growth, movement, fade or dirty off-screen region can require another frame.
- Draw visible icons and attached entries in their live and paint orders, after the common naval tick. Count the omissions of refused windows and entries, regions with no icon position, undefined replacement sprites and named undecided child inputs. The retained report carries the counts into the map details and the dump.
