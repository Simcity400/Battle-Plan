# 0707. Keep operative assignment, missions and appearance independent

The active agency roster is read in occurrence order. Recruitment holdings cannot supply missing active entries. The assignment selects cooldown operands, while the active mission is retained whenever its own variant is present. Pending and active missions remain independent. An operative's portrait comes from its own sprite. Sizing still reads the demanded fields, so a refused field cannot present as a capacity shortage. Retain the first failed operative and roster owner and withhold the affected table. [Roster capture](../../crates/engine-native-intelligence/src/operative_missions.rs)

Mission implementations retain raw country targets. Authenticate the implementation against its variant and the shared target getter. The executable getter witness can be shared per authenticated vtable, including its failure, while each object still checks its own identity. A country variant does not have a state operand. State-targeted and boost-ideology actions acquire their own nullable state and ideology operands. Pending, state and ideology targets have distinct presence. Resolve mission definitions through recorded lexical tokens. [Mission variant](../../crates/engine-native-intelligence/src/operative_action.rs) · [Mission implementation](../../crates/engine-native-intelligence/src/operative_action_implementation.rs)

The same 32-bit variant selects dispatch and serialization. Pending variant and targets are relative to the pending mission, not the active object. The implementation vtables follow native dispatch order independently of loaded definitions. An operative's ideology tooltip requires a valid group and exact string bytes. A length, header or terminator failure remains a refusal, and sizing reports every declared portrait length even when an output buffer omits a row. [Mission variant](../../crates/engine-native-intelligence/src/operative_action.rs) · [Roster capture](../../crates/engine-native-intelligence/src/operative_missions.rs)

Root-out-resistance alone asks for the effective owner and operative factors and a nationality match. Its modifier key resolves by script name under the current definition-table header. An active target state's positive resistance country takes precedence over the mission target. Nationality tests accept raw matches and canonical aliases at the native sorted bound, with the null tag equivalent to itself. Failed references or metadata are unavailable. [Roster capture](../../crates/engine-native-intelligence/src/operative_missions.rs)

Assigned-operative records retain the complete native reference and opaque selection bits. The low unsigned 32-bit type also appears in operation-instance references. The all-zero reference is a known unassigned slot. Serialized omission of zero operands does not change the live reader's interpretation. The null leader-skill sentinel has its own pointer global independent of the skill database.
