# 0105. Retain naval and air observations only under their own certificates

The existing mission worker demands ground-crew pairs. Notifications use separate key domains for pairs and allocator changes and do not scan memory or allocate. A collision may invalidate an additional pair but cannot approve a stale one. A quiet failed read remains unknown, and without a certificate the worker cannot read a flag through that observer. The enclosing observer owner drains notifications before releasing its registry.

The navy worker reuses regional mine slices and standing reports across frame buffers under independent writer domains. Lifecycle changes revoke every held identity for that navy. Mine decay cannot revoke a standing-report certificate. Each certificate comes from the current pass and is checked again by the publisher. The mine writer is marked active before it reads its receiver's event metadata, so a metadata refusal cannot let another thread accept a snapshot while a writer is running. Frames own their emitted rows while the worker shares one acquired snapshot.

The same navy owner observes mission-set and regional-ledger writers. Registration, removal, reset and construction share the set and ledger lifetime, so a proven empty set lets the worker skip region headers. A proven quiet navy can reuse registrations and read only current presence counts. Both ledger sites must be admitted. Without them the cadence reads every navy's headers, and the owner forwards reset from the one published patch. Per-navy notifications begin before the native write and revoke only the appropriate certificate, except collisions conservatively revoke more. The worker reports its read, skip, carry, and fleet-leader resolution counts off the game thread.

Naval result observations distinguish persistent combat from stack-local strikes through constructor witnesses. A result is copied into an owned event and published in push order so a later call can see the ordering even when an allocator reuses a receiver. Construction alone does not publish a result. The hourly drain folds a finite interval and discards its birth witnesses after it closes the interval. A refused event on the drain boundary cannot be placed unambiguously, so both intervals are refused. Refused intervals stay withheld until a new valid capture interval. Population and attempted event counts size later storage off the callback. Restoring a new attach uses the exact retained sequence before publishing the first observer, and a campaign or clock transition does not rewind it.

The naval bridge preserves the native call state and leaves unwinding to the normal native and Rust frame metadata. The native foreign-unwind tests use independently authored fixtures, distinguish constructor calls that have no birth witness, and check the relative stack depth through the actual production bridges. They serialize changes to the test-owned native sites and keep the release veto active while an original callback is live.
