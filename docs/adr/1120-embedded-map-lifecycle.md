# Keep independent map bodies on the host's shared device

The Windows host owns the child window's geometry and the map thread handles commands only when work arrives. The campaign and dashboard use the device together. Compatible sources share immutable textures and decode work for the same recording revision and visual choice. Each drawn widget owns its own hour state and render targets. Only one cold source starts at a time because each content load already creates concurrent asset work. Viewers live off the tree's stack copies, which would otherwise risk exhausting the UI stack. Closing or cancelling a scene load drops its work away from the UI thread. A hidden or clipped map releases its targets and reader, and its export ends with an explicit answer even if the widget disappeared.

The campaign map and dashboard share one visual fallback owner. A scene inherits the source's content identity and may install only while that identity remains current. Stale results from an earlier probe do not refuse the new scene. A visual-specific scene failure can trigger a recorded-content probe, followed by a named error if the scene still fails. Folder checks carry the revision they checked, so newly built content survives an outdated check result. Retry can reopen a failed source, including when the host hides and shows the widget again.

One visible map owns audio. The last map the user interacted with stays owner while visible, and otherwise the first visible map in dashboard order takes over. Muting applies immediately because a view may cease drawing. Each view uses its recording's executable tables. Loading remains visible independently of the optional diagnostics.

A new open invalidates earlier seeks, and close is terminal. The host receives an export's answer on the map thread before it can refuse unanswered requests on shutdown. Map acknowledgement sends use a dedicated thread. Clock-only progress is coalesced at the reporting interval. A changed mode, seek result, tooltip, highlight, camera, options, load or refusal can reach the host immediately. Replacing a queued state keeps its FIFO position so a busy view cannot starve its neighbours. Matching drawn states retain the first drawing timestamp for their hour or mode. Toggles are kept in order when each press flips host state. Diagnostics toggles can cancel in pairs. Shutdown signals the writer with its condition variable mutex held and waits only for a bounded time for outputs to drain.

Followed panel queries share decoded recording data but run on a distinct display-paced playhead. They put replies on their own sender and never make the stepper send synchronously. A concurrent request for the same recording, branch and clock can share a pending build without waiting on other keys. The first panel opens the row store and the last closing allows it to stop. A read error is reported at the last delivered hour. Before the playhead exists, follow reports unavailable and the widgets retry.

A fixed-hour dump anchors its own reader and uses the tables and formed layer products at that head. The political layer supplies default-mode fill and border keys at the recorded perspective. The dump separately composes products whose layers do not expose the dump format, including other political views. Combat controls draw from loaded sheets as well as resources declared by the interface. A dump settles queued art and refreshes its combat resources so the first snapshot can include decoded portraits. Window quads draw above map icons and retain their push order. The engagement index retains an unseen icon's last seen frame across a seek. A new instance with no seen hour uses its authored starting frame. An emptied and refilled side is a new instance. If playback lacks the index, it names the missing history.

`NativeWindow::new` checks the map handle's parent. `bounds` and `visibility` send changes asynchronously to the map window so its own thread applies them. `map_views` reads the client rectangle through the map window's parent handle, with a live output rectangle. The borderless map's client and window origins agree. The region is the visible views' clips, or the whole campaign map, minus the popover holes, in the map window's own coordinates; a campaign map with no hole over it has no region. A dashboard window whose region leaves nothing is hidden. Transfer ownership of the final region to Windows only if setting it succeeds, and answer a hole change only after setting it.
