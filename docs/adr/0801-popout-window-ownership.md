# Serialize pop-out requests and surface ownership

One owner processes pop-out lifecycle inputs and performs their effects in order. Each window reserves a generation before creation. A late report or command for another generation leaves the current window alone. An open received while releasing a window waits for the next generation. Creation reports queue behind work already pending, so a close received during creation can cancel it. An outcome answers its own request before release can start the next window. App exit cancels a pending reopen and waits for release.

Only the owner publishes frontend state. It attaches a monotonic sequence to the complete state, and the frontend requests a fresh publication after subscribing. Each restart has a new viewer identity so the frontend resends state. Opening, closing and failure completion resolve the waiting requests for the corresponding generation. User unload closes a window showing that recording. Reconnecting retains the window and follows the reopened recording. Host-wide presentation settings reach the pop-out too, while perspective, camera choices and exports address the window they belong to.

The shell uses a borderless window filling one monitor's physical work area. Signed positions support monitors above or left of the primary display. Monitor removal selects a remaining monitor. Same-DPI monitor moves can lack a DPI message, so the position-change event also refits the window. Focus transfers to the map child window. Closing or destroying the parent would also destroy the child; the owner waits for the viewer to release its surface before retiring the parent. The Win32 state box transfers to the window on `WM_NCCREATE`, and `WM_NCDESTROY` releases it. If creation fails before transfer, the creating thread releases it.

`run` owns creation and the Win32 message loop. `window_proc` and `fill` access the live state pointer in `GWLP_USERDATA` only when it is set. The `monitors` callback receives the caller's live vector and only appends monitor handles during synchronous `EnumDisplayMonitors` enumeration. Other threads use a published opaque window handle. `client_size` returns no size when `GetClientRect` fails. `next_monitor`, `hide`, `raise`, and `Shell::drop` tolerate the window disappearing before their Win32 calls. `initial_monitor` and `current_monitor` use the nearest-monitor fallback of `MonitorFromWindow`. `work_area` passes a zero-initialized record to `GetMonitorInfoW` and does not dereference the monitor handle.
