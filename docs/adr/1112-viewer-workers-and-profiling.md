# Keep viewer work and diagnostics responsive

Content can have tens of thousands of assets. Bounded parallel file loading partitions work into contiguous runs, whose results are joined in input order. A failed thread spawn returns its run to the caller. Batch helpers are limited by processors available to the process, including Windows affinity. Batches use the caller and whatever pool threads become available, with the caller's priority inherited during each turn when necessary. Preparation recruits helpers only if they actually reach admission during preparation. A busy pool leaves the caller able to finish alone. Optional work beside a batch must not affect the result, since a helper might never take that turn. Scope cancellation releases waiting helpers. Finishing closes the admission to borrowed work and waits for registered calls, including when a task panics.

Windows presentation runs above normal, ordinary makers below normal and refinements lowest. A worker that holds a lock acquired on every frame uses normal priority while holding it. `waking` uses this rule for the window's own lock. Work taken on behalf of a higher-priority caller temporarily raises the executing thread to the needed priority and restores it afterward. Test support leaves priorities alone so saturated concurrent tests can make progress. Baking instead caps its own priority while restoring the exact original value on exit.

An hour swap hands over one batch of retired values to the normal-priority retirement thread. Sending does not wait for a busy destructor. The channel is unbounded so a frame never has to destroy an hour merely because the retirement thread is behind. The payload drops on the caller if the worker is gone and cannot receive it. A deterministic test waits on a sentinel behind the queued work to witness FIFO destruction instead of depending on a timeout.

Profiling options are sampled once per process. Disabled scopes avoid allocations and clocks. A paced sweep starts after warmup and its range uses saturating arithmetic. The profiling output thread uses a bounded queue so a slow stderr reader cannot stall the frame. It reports dropped-line counts, and an explicit flush waits for admitted output. Playback measurement records scoped counts and levels only when its view record is enabled.

Job-local timing records travel with completed products or through ordered joins. An error that returns normally finishes a scope, while an unwind has no invented sample. Worker CPU stays attributed to the executing thread and wall scopes may overlap. Frame owner and epoch checks reject contributions from another view or a previous frame. Keep unavailable CPU distinct from measured zero. Ordinary short laps may be filtered, while explicitly measured coarse laps, required zero scopes and counts remain visible. GPU pass counters are attributed to the lap that consumed them.

On supported Windows systems, thread CPU is calculated from thread cycles and one process-wide rate calibrated against the invariant counter. Calibration brackets reject excessive unmatched clock edges. It runs before taking the thread sample so its own CPU use is excluded. Optional profiling counts, view levels and GPU counters remain independent of playback data.

`Turns::new` erases the lifetime of both borrowed callbacks for work submitted to the pool. The `task` callback is `Sync`, the other fields satisfy the same shared-access requirement, and callbacks are invoked by `Turns::work` and `Turns::help` only while registered in an open run. Both callers of `Workers::run` finish before their callbacks expire. `Turns::finish` closes registration and waits for every registered job to leave. These are the conditions for `Turns` to implement `Send` and `Sync`.

`usable_processors` passes live stack outputs to the Windows affinity query and uses the current process pseudo-handle. Thread-cycle sampling, `set`, `current_priority`, `at_least` and its restore guard, and bake's `set_priority` use pseudo-handles for the calling thread. Sampling supplies a live output counter. Priority calls neither take ownership of nor close those handles.
