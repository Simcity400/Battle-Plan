# 0105. Capture each map source once within its worker pass

The capture workers own the combat, ship, and order censuses. A completed source includes its outcome, so each dependent visitor must finish even when the source census was empty or refused. The map stage attributes each visitor's measured read time to its own table. Map conversion on the spool keeps native ordering, full identities, and arena bytes. Bad bounds and duplicate identity within a native side refuse that data. Cross-side or cross-combat exclusion needs its own evidence. A damaged name span withholds the affected name column and leaves healthy numeric state available.

The ShipModels worker owns the fleet, task-force, and ship census that supplies its model details. An air-wing worker may install a complete map projection for the current callback. An accepted source failure likewise remains final until frame reset. These states keep the callback and dependent visitors from retrying the native snapshot. A missing source is reported as unavailable. When a worker transfers complete storage to a frame, it takes back the old frame allocation for reuse off the game thread. Combat workers similarly return the original source outcome with its storage. Their progress visitor runs only for a capture mode that records progress.

The callback authenticates order-group roots once per pass for both the order and naval jobs. It holds the game until those workers finish, so reusing those roots cannot select a different snapshot. Single-worker walks consume the same-pass roots once. Hourly order jobs partition the prepared roots. The principal Orders job takes part zero, other jobs borrow the remaining parts, and the stitch restores the geometry, visit, and row order of the single census. Failures before parts were prepared preserve the original root refusal. The fixed projections for stitching reuse part zero in unused array slots, which callers omit. Plan gathers are timed for ArmyOrderPlans even when the order census performs them. Each hour takes the latest split planned from measured part cost and stitched census geometry, regardless of which pooled frame it receives. Sizing retains headroom for gradual growth.

An order part reads only its consecutive range of handle-sorted roots, and the stitch does no native reads. The split targets a quarter millisecond of measured work per part to offset root census, dispatch and stitch costs, up to the reserved worker slots. Range cuts weight the cost of a group roster and its orders separately. They use handles rather than prior array positions, so a changing roster remains covered and some ranges may be empty. With no complete preceding census, the first or next hour uses one part.

One worker acquires the two raw players sources and a FIFO decode worker runs the original readers on the captured byte spans before ready publication. Acquisition preserves the original roster, descriptor and string-read gates and the canonical controller census. Each source independently stops at its first failure and a failure does not require repeating the native read. Raw storage grows before reading the original span, and decode can grow its row and text storage independently. Bulk capture spans authorize enclosed reads, including unaligned reads, but do not authorize straddling the span boundary. The raw capture flag prevents the typed map fallback from rereading these sources and clears after decoding or frame reset.

The wing gather also owns the attachment pointers. Its only mapping to a recorded group handle is a unique identity from the same-pass group census. Null is detached. A partial census can prove a match, but it cannot prove an unmatched pointer absent. Combat participant keys reserve one bit for the authenticated side-vector selection.
