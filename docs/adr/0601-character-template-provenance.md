# Resolve character roles from the template recorded with the holder

The character database first registers folded lexer tokens before the resource pass and reads bodies later, after ideas have registered their names. The file's own mode-one reader owns variable definitions, consuming fields in token order even when the value has a shape a balanced syntax tree would handle differently. A body begins with one plain template or a sequence of leading `instance` alternatives. Each instance starts with an `allowed` conjunction. An unsettled recovery marks the current character and unread suffix unknown, naming the file and cause.

Retain alternative templates without deciding which startup conditions passed. Use an authored value only when all alternatives and competing declarations agree. Retain the first folded spelling of an advisor's idea name, but preserve original spelling for display and art. If an advisor or country's complete leader-role set is disputed, use the holder's recorded template, matched by byte-exact path, starting line and folded tag. A plain template starts at its body and an instance at the token closing its `allowed` block. Match the template registry against the character projections in declaration order. A tag or line mismatch makes that template and the unplaced suffix unavailable. Preserve source gaps even for absent names because unread content can still supply a template. A plain template or empty `allowed` condition can establish a startup registration without rerunning game conditions.

Within one template, apply fields in order. A scalar portrait supplies the large size, and repeated portrait blocks update the same object. Choose the lowest available category of the requested size as fallback. `airforce` is an intelligence lane. Advisor tags compare as stored folded strings, while characters, traits and ideologies use registered lexer tokens. Failed fixed5 cost scans retain the earlier cost, and repeated traits, bonuses and modifier objects accumulate. String readers use the first NUL and some fields deliberately use the lexer's current token instead of resolving its value. Missing advisor tokens and invalid unit or ideology identities remain representable without creating named lookups.

Use ordered keyword dispatch for leader and scientist fields. Unit-leader and scientist fields can consume an object even from a scalar, so following tokens can belong to that role. A later role replaces an earlier one, and repeated visibility blocks within a role append to its AND conjunction. Preserve refusal for a visibility payload the reader cannot follow. Scientist visibility, and the role of a unit leader whose template `generate_character` made, use the recorded origin of the role's last visible block, separately from any effect origin. An officer-corps idea group listed by the content define supplies a template under its idea key, with a default slot from the group, a default name from the entry, and a small army portrait derived from that name. Reuse the same advisor field application, then set the idea token back to the entry key.
