# Read chart spans from aligned columnar summaries

A chart can answer a long range from a few summary pieces of one column. Base buckets cover six absolute game hours. Each higher level folds sixteen lower pieces, and a bucket aligns at a multiple of its width even for negative game hours. Adjacent pieces each contribute only the hours they cover at a partial edge. A fold merges those contributions once, preserving the boundary change when the neighboring hours are contiguous.

Keys carry the hours lived under an available table, including only the rows read during a partial capture. Each numeric column keeps an independent token stream per key. Nothing recorded is distinct from a recorded zero. Tokens encode absent and equal runs, a constant value, or varying values with first, last, minimum, maximum and count. Only declared aggregates add hour-weighted sums, sums of magnitudes and hour-to-hour change or fall totals. A computed column has a separate source ID and a bit mask over the columns it reads. Ranked columns retain the greatest last values in a bucket, excluding absent values and using keys for ties. Its ranks encode an unchanged run or reuse positions from the previous list. Log pieces count inserted or appended rows by up to four facets, each 32 bits; a missing numeric facet uses the reserved maximum value. Lifetimes pieces carry keys and life alone.

The stored directory contains the covered range, bucket metadata, shape and each frame's offsets and lengths. Separate frames hold keys and life, each column's tokens, and each ranked column's ranks. Per-key length prefixes make it possible to read just the requested keys. Recompression may change stored sizes but preserves decoded frame bytes.

The builder holds a row's current cells and its change events instead of reserving a stream per cell. Changes are recorded in application order in compressed chunks. An event packs its kind and column, delta to the prior track, and cell value relative to the previous one. An hour is stated once for its events. The baseline cell is recorded on the first change in the block. At close the changes are split by track into one allocation and replayed into each key's tokens. A covered key's life records how many hours are covered and the first and last offsets, so callers can distinguish gaps inside the interval.

A fold merges ascending input keys without gathering, sorting, and deduplicating every key first. It counts the merged keys before allocating their output and reads each input's keys and one column frame at a time. The recorder budgets the peak across table-order finalization. At any point, earlier output pieces coexist with later builders, current output frames and compressed copies. The cost model accounts for dictionary slack, raw/packed frames, the first-value baselines and a token per changed bucket. Tests check the previous gathered-key result byte for byte and bound both memory paths. Memory observations take turns because phase records are process-wide.
