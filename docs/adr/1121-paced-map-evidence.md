# 1121. Measure the map's production frame at explicit playback times

Paced playback validates the requested path, output and options before creating a worker or window. The run gets a new directory under the capture root and owns its scratch settings, caches and output. A run can seed its shader cache from an earlier run. Set process-wide harness state before device creation and before viewer workers read the environment. A windowed run uses the app's own host and swap chain. Lean timing accepts only runs that can exercise that production frame without extra harness work, including checks for settings that are enabled by variable presence alone. Pixel evidence settles visual resources within the frame, so its thread-cycle accounting has a different contract from paced CPU timing.

Place each scheduled frame on an explicit refresh grid and let an overdue frame start immediately. Budget at the rate left by combining the display refresh and the app's frame cap. Use the frame's due time to sample a repeatable camera flight that crosses unit and shadow cutoffs, so identical schedule frames show identical views. CPU reconciliation allows five percent disagreement with the process CPU-time counter, with an absolute 0.25-second floor for short runs because the process counter advances coarsely per thread. Separate a late frame explained by the previous frame's work and GPU wait from residual harness delay.

Report the oldest contributing layer hour separately from the frame's steering clock and the hour of its overlay. The gap between the playhead and the oldest layer measures how far the product on screen lags. Compare overlay lag to the layer picture, including a negative value if the overlay advances ahead. Count a publication once when a measured frame actually draws it. Visual-mod toggles run repeatedly through the app's path with two sets and measure the transition and the output. Viewpoint switches measure to both the first changed frame and the fully settled picture, where the report identifies the last part to reach it.

The paced, proof, toggle and viewpoint `run` entry points put app data under their requested output directory before creating viewer workers. The process environment changes at that startup boundary so the map settings, content caches and shader cache are isolated for the whole run.
