# 0101. Admit hourly capture only at a witnessed write boundary

The game writes simulation state inside its per-frame command batch. A hook that can prove all batches since publication are observed lets the collector read at the outermost batch's return. That frame includes the commands that followed its hourly update. The read can run alongside the frame on a separate capture thread, or hold the game at the same boundary when the capture thread is unavailable. If publication cannot prove that no batch crossed it, its returns cannot certify quiescence. The collector holds the game and reads at the hourly update's return before any later command. The runtime attempts the verified publication a bounded number of times before using the unverified mode. The verification requires the matching command batch function with its single return and no branches outside its inspected extent.

The command batch counts a thread entering its outermost batch before it passes the gate, and the capture closes the gate before inspecting the count. A racing entrant or capture must see the other. In the count, a thread waiting outside the gate has no active writes. Capture admits one reader and ignores its own batch nesting. Portrait writers may proceed and log changes across the capture, which still uses the portraits at its original boundary. Every admitted capture reopens the gate on exit, including a panic.

The first hour ending after a refresh request waits for the next update entry and reads in full. An already-ended hour remains eligible for the ordinary read. A newly loaded world is read at its first update entry. Each update carries its own entry classification through nested calls. Arrival, return, and final-loss accounting distinguish updates that ended, were still running at the final account, or entered after it. A replaced world or unread hour that has been overwritten is lost by count. The next accepted frame accounts for previous losses before its own hour. Detach stops admitting future refresh waits, attempts to read the pending hour at the next batch return, waits for the outstanding read, and accounts for the remaining ended and running updates once.

When capture runs alongside the game it starts below game priority and avoids the game's physical core. A waiting writer raises the reader and releases that placement restriction for the capture. A waiter counts itself before loading the capture thread handle. Stop joins the capture thread and closes that handle only after all counted waiters leave. A panic in the capture thread makes its patch of time unaccounted again and switches later captures to holding the game before opening the gate. Detach joins the thread before taking the final account.

The foreign-unwind oracle exercises the production Tap from an authored native test frame under a separate parent process. The observer has a system-unwind callback signature. Its synthetic patched span has no interior entry or stack dependence. The stack oracle includes the DTO, flags, saved nonvolatiles and call return slot. It witnesses the native stack pointer at entry and uses an observable Rust write to keep a Rust frame during the check. A registered native frame or escaping production flight remains owned until native unwind has finished. Rust cleanup alone does not witness that point.
