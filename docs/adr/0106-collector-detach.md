# Prove capture and relay quiescence before unloading

Keep observation installed until the hourly entry is restored and every admitted acquisition finishes. Restore independent families even if another family refuses. An ended hour waiting to be captured can drain at the next command batch’s return, including while the game is paused. If the wait expires, preserve the loss in the recording. Once admission closes, an acquisition counted before close remains active until its lease drops. The sequentially consistent ordering excludes later entries. Stop the capture thread after all acquisition leases finish. Windows can reuse IDs, so remove exited capture and sampler threads from the quiescence exclusions.

Each restore round visits every unfinished family. Shared restoration uses one thread census and suspension for its participants, preserves per-family results, and runs the other families’ separate publication paths. Prepared restoration visits each family’s next publication. World invalidation stays installed until older native invocations can no longer reach post-readers. Recheck that readiness after restoring other families within the same round, because those attempts may consume the deadline. A world family that became ready still receives its first attempt. A successful publication advances the round without an idle delay. A prepared attempt already counts toward repeated restoration failure.

Stop the sampler before any restoration suspension. Thread snapshot and open may allocate beforehand. During suspension, use only scalar counts and instruction pointers and avoid dropping owners. A mutation can still be in its native original outside collector code, so suspended and unsuspended checks use the same flight predicate. Resume every owned suspension or prove its thread exited before reporting any resume failure. A reported failure prevents releasing the retained roots. Shared-suspension timing belongs to the individual family whose checks and writes produced it.

Stopping acquisition and joining readers does not prove callbacks and relays are safe to unload. Teardown retains every object a live relay can reference if a patch cannot be restored or the final quiet check fails. Its published pointer prevents unload and preserves the first terminal fault alongside the new stop diagnostic. A callback that escaped its runner guard can leave a running marker after worker shutdown and also refuses release. On successful restoration, join spool and status readers before releasing the final hook state.

Detach drains decode first in FIFO hour order. Decoded frames go to the spool’s ready queue, and undrainable work follows the existing loss path. Only after producers stop can the spool consume the final loss batch. The recorder reports changing queue length as drain progress. Report safe retention through `collector.resident.txt` when collector-owned threads remain or quiescence cannot be proved. Retaining a resident image avoids unloading memory while a thread may still execute it.

The restoration test treats a cache flush still pending as incomplete and verifies that later independent cases are still visited. The attachment publication guard test uses capacity overflow to exercise refusal classification without modifying allocator hooks or attempting an enormous allocation. Its stage tests use an absent temporary directory so an unavailable progress file does not create capture files in the checkout.
