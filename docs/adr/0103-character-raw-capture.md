# 0103. Separate character acquisition from typed publication

Size the first full pass from the live roster, counting each occurrence and its literal text. Take unit and trait demand off the game thread independently of country count. When separate owners acquire role and trait tables concurrently, part zero supplies the callback's portrait census. The owned tables include terminal failures. The typed fallback only visits tables without another acquisition owner. A missed request leaves the failed table with its refusal. Reset keeps pending raw ownership until the decode worker consumes it. The spool thread converts completed buffers after they leave the callback.

The callback copies raw spans and the FIFO worker runs the typed `walk_family` against its owned mirror. The mirror records repeated reads of the same address and length in occurrence order, including failed reads. Bytes a view already owns need no additional log entry. Use the typed cursor's 32-entry roster pages so the same spans replay. A failed span ends exactly the same subpath as the typed walk. The trait row and byte budgets bound the acquired prefix. Other tables acquire their original observations and truncate against the pooled buffers during replay. Independent trait vectors can still publish when scalar capacity or a skill or name fault leaves only an authenticated parent identity. Attribute fallback identity faults to the reached trait read without changing the already decided unit outcome.

Each owned job hands off only tables it admitted. If acquisition staging cannot grow, take the existing typed fallback without enqueuing a partial payload. Use the roster job's borrowed role census when admitted, and the direct roster walk when it is absent. The borrowed view contains no names. Any Characters rows in that path must come from the completely certified quiet roster. Preserve native result order, exact text, availability, and failure precedence through decode. A gap in a stored prefix remains a gap even when later owners can supply counts. The typed walk validates all ranges before publication. A roster loan owns the daily experience cache only through capture and stores the supplying bytes in the payload.

Cache template identity by character ID and the current template pointer. An unchanged pointer retains the immutable identity fields. The decode worker replaces that cache after a complete Characters read and forgets it on a full hour, changed scope or incomplete read. Ambiguous repeated identities have no held entry, while ordered normalization preserves the first occurrence where applicable. The template generation keys the prepared read plan. Character names retain the game token in the saved name field and the separate native display name remains outside that saved value.

Persistent row buffers retain their complete publication keys across reset and capacity growth. A typed walk or republication clears the old key for each buffer it writes. On a matching quiet key, return the held Characters, UnitLeaders, UnitLeaderTraits or AdvisorRoles result without rewriting it. Only bypass leader or trait rebuild when every fresh read still projects the held result. A full refresh can publish training but cannot borrow the old quiet-layout certificate. A truncated scalar prefix leaves missing leaders' training progress unknown. Tests serialize acquisition against shared roster sizing, daily state and census history to model a fresh attachment.

Keep original demand and failure boundaries through capacity changes. A stopped prepared program cannot retry native capture. Later independent fields may resume once after a fault if the typed consumer would continue. Short appended suffixes refuse only their corresponding field and cannot consume the staging a later original field needs. A failed guarded copy may modify its output prefix, so decode must still reject the whole failed span. Reserve from visited role and trait occurrences, including any attempted failing occurrence whose absence would change error precedence. An unvisited advertised tree tail does not establish storage demand.

Use the original ordered observations, including repeated reads of equal addresses. Advisor root authentication happens before either roster body, with separate programs for the historical and generated array geometry. A change isolated to a generated roster leaves the historical read program valid. Local views preserve each occurrence's fields. Read-ahead hints overlap independent future work without changing the required observation order. A prefetched view can expose a successor fault early, and the predecessor's body must still run before settlement exposes that fault. A deliberately changing synthetic source can make different schedules see different instants. Compare the native and owned paths running the same wave. Preserve predecessor writes even when a later global refusal withholds the public prefix.

Heap strings copy their original terminator before the payload, including empty heap strings. Those failures precede output capacity checks. When tight staging precludes batching, the scalar path preserves the original retained prefix and growth demand. Distinct byte reads of equal keys retain distinct cursors. Role maps preserve the bounded successor order, and a failed map's later reads cannot affect an independent batch. Reuse a skill definition only within its current acquisition, still recording the raw observations for each requesting occurrence. An advisor's country or heap name bytes stay fresh even when their shape remains reusable. Training cadence is independent of hourly roster, role and assigned trait capture.

The hourly planner keys each table owner's raw program to the template identities and carried names it actually uses. A daily experience carry cannot reuse a program that would reread a held residual column. A partial diagnostic pass can preserve a roster program only if every planned occurrence stayed identical. Otherwise retire it to prevent an intervening roster mapping from being mistaken for the original one when native addresses return to their former values. After a census grows, rerun full discovery before publishing. If a loan extends through recycle, disable sharing without waiting or allocating.
