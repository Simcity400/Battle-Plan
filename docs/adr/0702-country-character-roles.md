# Keep country character records and advisor roles independently available

The country character owner keeps appointed advisors, available advisors, and active and retired character records. Authentication includes its country backlink. A persistent role is not an appointment. Appointed occurrences are ordered by idea hash and then idea text. Record the observed order, which the country's modifier walk and save preserve. Exact-name queries walk the separate available pool and need the character and idea, without acquiring the appointment slot.

Active records are ordered by name token, with null records ordered as zero. The retired array shares the layout and order. Retirement moves a record from active to the retired lower bound, and both arrays preserve all occurrences. The row needs the authenticated character identity or an observed null, without storing the adjacent status bytes. Batch bounded identity reads, then authenticate each occurrence in native order so the first fault is the same as with scalar reads. Active and retired outputs keep their own earliest failure before considering a later shared census failure.

Each selected available pool is independently authenticated and yields the same rows as in a whole walk. The pool's identity and header must still validate on a carry. When the caller proves a previous complete read remains current, reuse its character and idea rows and their text offsets without rereading the payload. An unselected country reads no pool. The sizing walk counts exact headers and certifies idea text before growing storage. A readable terminator alone does not prove a heap string's declared length is readable.

Country-leader roles are persistent entries reached through a character's role map, independently of which leader currently rules. Match the exact role object. A current ideology change does not rekey the signed map. Retain role pointer order while reading and leave sorting and validation to the caller. The constructed null ideology is a known definition with a stored token. A null pointer is an ordinary absence, while an unreadable definition is a refusal. Record role trait tokens in occurrence order, since traits with the same name can be distinct definitions and trait conditions compare exact objects. A role id with the observed absent sentinel is omitted by native serialization.
