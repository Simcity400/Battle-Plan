# Keep combat hover facts exact where playback depends on them

Current land-combat side inputs hold the CAS anti-air cache and prevented strength and organization damage. Historical formats through 101 carry those values in the original side details and playback can still read them. The opposing hover uses every digit of the anti-air cache in a nonlinear calculation. Prevented damage and progress can use the hover's own displayed precision. The ground-damage channels belong to simulation and save paths, so recording them would add no presentation input. The marker's survival estimate needs only the wrapping sum of 24 organization-loss samples, with no sample read before the ring reaches 24.

Keep the side layout in declaration order and use the high half of the committed-list count range to encode the inline loss-sum layout. An ordinary count cannot reach that range because the handles each need eight bytes. Inverting a current count therefore distinguishes a loss-sum payload from early format-102 captures that still hold the sample array. Older readers refuse the marked count as exceeding the payload. Historical test encoding puts the known sum in the first of 24 samples because the reader uses only their sum. Side detail fields have no display step.

Capture fresh hover inputs during the same side read and keep a failed input local. An invalid next skill level has a different progress sentinel from a refused read. Ratio calculation preserves the game's sentinel for zero requirements or sentinel experience. Skill and learning lines print whole percentages, but the live threshold deciding which learning entries appear applies before rounding. Timed entries retain native order for the first matching expiry, with the signed non-expiring sentinel distinct from an expiry on day zero. The portrait localizes its stored name and description and uses the contextual modifier selection for the chosen unit. Army HQ formation references apply only to the reached commander categories. Naval timed-trait data is absent in recordings predating the field.

Committed division membership uses combat, side and native occurrence ordinal. At the same capture, a member can reuse its division's panel, status and movement operands if the corresponding rows hold them. A division outside the roster needs an inline copy. Join the full commander handle to the same-hour leader and trait rows. Preserve attack, defense, direction and equipment-category inputs separately. The panel columns provide the exact stat words and ordered selectors, including initiative because every truncating reinforcement product reads its digits. The reserve speed share is computed at capture from base speed, reached movement modifiers and the live speed floor. Limiting the share to the native range avoids recording the underlying drifting movement values. Unreached or refused shares are absent. Combatant modifiers use an independent row per visited member, including empty lists, so one changed member's entries leave its siblings unchanged. Older recordings store one list on the side. The side's modifier-context read remains its own availability boundary.

Tactic weights use the side's present country set and recorded content unlocks. Exile inputs preserve native core and occupier order and the fallback country when the template's origin does not select one. Border-war rows preserve event identifier bytes whose presence is determined by length. Stored nonzero transfer-state bytes indicate a transfer. The side marker and its ordered primary and roster-owner country sets are recorded facts; viewer-relative shared vision remains playback policy.

Naval combat preserves full task-force membership in native order so engagement compares the same identities across hours. Wing subunit indices align by occurrence. Historical wings which no longer resolve use a sentinel, and paired-only groups have no forward ordinal. The presence of a carrier member is acquired separately from its state. Keep the recorded air-efficiency modifier metadata and feature gates with the native operands. Active custom sea values use little-endian signed 16-bit channels in strategic template order and a separate read-failure tag rather than a per-row error string. Referenced resolved bases have rows even when their dense wing list is empty, and repeated wing handles are meaningful. Keep exact strength, maximum hit points, damage, weapon operands and oracle-only caches since the combat threshold comparisons and arithmetic depend on them.
