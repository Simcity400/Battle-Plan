# 0107. Preserve per-owner provenance across spool publication

The spool thread converts, compares and durably writes captured data outside the game thread. A prepared frame owns one hour of converted input. Its comparison tokens belong to the current encoder, so preparation and admission must be consecutive and precede any flush or detach. Conversion helpers can take whole movable packs in any order. The first helper takes the map tables, and the spool thread retains the core tables and its own packs. Each pack has exclusive output slots, so completion order does not change the frame. Conversion failure is applied after all shares merge and covers every affected pack. Borrowed conversion caches are lent only for that join. The single-thread path produces the same result.

A complete owner read replaces the owner's rows and sample hour together. A tracked census stamps only visited owners, including a visited owner that yields no rows. A complete untracked census counts each covered owner as read. Unread live owners retain rows and provenance, even if their earlier read yielded none, and an owner absent from a complete census is removed immediately. Returned owners take precedence over selected empty reads, which take precedence over carried provenance. The merge walks sorted keys without sorting the result. Any normalization at that stage covers provenance only. The encoder still validates original rows and reports refused keys.

The first complete baseline on a branch needs a full read. A truncated read can publish frame-local provenance for owners it reached, while the held complete baseline and its owner read hours stay intact. A failed walk publishes the failure and keeps earlier rows for a later successful slice. A slice without a complete baseline is unavailable and requests a full refresh. If acquisition reported success yet conversion or merging withheld that result, notify the capture thread to forget the affected family’s fingerprints. Drop its previous held rows because already queued slices could rely on the withheld result. A full read restores both rows and provenance. Supply trains use daily country slices with one read hour for the related nodes, vertices and train inventory.

When the cache and encoder share a complete baseline, a frame between keyframes carries updates for the owners read. The producer releases replaced rows before admission so the encoder can update storage in place. On success the producer adopts the encoder’s rows. If a write fails or never runs, the producer retains the merged rows as the next input, and a restarted encoder writes the next complete keyframe. SliceReads has no producer baseline to share. It starts from owned rows, then replaces changed hours when owner keys match. The encoder withdraws comparison tokens at keyframes, gaps and recovery. A truncated ordinary refresh clears the encoder’s baseline, so the next refresh of that table is a snapshot.

Before comparison, display fields use the game’s display steps so a sub-step change preserves equality. Projection already rounds its rows. Conversion rounds a shared table only while that hour holds its sole reference, and the encoder rounds the remaining inputs. A redundant refresh may carry its committed rows through a later periodic keyframe. CountryIntel's daily sample can outlive an encoder reset, but a certificate still needs freshly acquired exact native input and applies to that sample alone. A refused naming prefix stays refused. The recorder panel’s viewed-country flag uses committed operands and withdraws them when a required row is unavailable.

The campaign holds accumulated production and construction output for the branch. The spool adds observed increments before applying staggered carry, and publishes totals with the corresponding census. When a write fails, the next census retains final totals for a line that ended. Table read metadata follows the actual sampling hour regardless of whether a sibling paid the timing cost. An unvisited table contributes no read timing. Border conflict rows can be complete only after their province walk finishes, then can fail independently. The row spool contains its designated tables, subject to the recording mode, while the native capture holds the other recorded tables. Omitted and retired tables retain their distinct recorded reasons.

Keep the carry confined to the spool so encodings stay byte-identical. Native comparison applies to hourly tables, and the encoder’s validated complete baseline can supply a carried marker without a clone or second check. Refused tables leave producer caches. The capture thread receives a bit per sliced family whose walked input was withheld. Allocation failure ends capture and puts required detach ahead of discretionary work. Convert validation detail to bounded checked owned text before dropping the original error. The fixture installs the process-wide allocation hooks in a child process, and uses only processor-local gauges for repeatable status comparisons.

A state row gets both display names from the captured frame arena, with a table refusal when a name span lies outside the copied bytes. Equal IDs from separate native unit namespaces stay separate rows. The recorder-panel flag keeps the previous allocation when committed operands are equal, and its original tag can be unknown. Production and construction output exclude increments from before branch observation.
