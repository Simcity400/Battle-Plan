# Share dashboard histories and generate one transport contract

The query service answers series and product requests from the recording. Indexes belong to the open recording and its runs so windows that overlap a run can reuse the same history. Opening builds independent run histories and timeline indexes in parallel. A first read can load a missed history, and the context can retain it past the original borrow. Some indexes keep only the preparation data their readers need, such as a division template from its first log witness and an ended casualty lifetime's final counters. Followed requests resolve a recording path rather than a lease.

The exporter combines shared transport declarations and every product's request and reply declarations into one deterministic TypeScript file. A shared type name is emitted once. Two different declarations with the same name refuse generation, because accepting either one would discard part of the frontend contract. The export feature is only needed for contract generation. The dashboard's contract test writes the file into the worktree it runs from when `BATTLEPLAN_WRITE_CONTRACT` is set, and otherwise fails on a stale one.

The producer may automatically retry named capacity and transport refusals, including a refusal with appended advice. Other failures remain visible until retry or a context change. Maintain the retry messages as part of the shared transport contract. Tests use the viewer's allocator. Test localisation reads use folder layers, and preparation test fixtures avoid durability work that they do not observe.

Offline content checks run in registry order with the product readers and the recorded content stack. They report products with no offline inputs and name any runtime-only limitation. A missing authored flag candidate continues the fallback search quietly. An authored file that refuses to decode is a diagnostic. Try the null-group candidate only if every group/set was absent, and report one visible fallback per tag.

The development bridge exposes the data service over stdio and has a separate folder-picker mode. The benchmark aligns its sampled step ends with storage block boundaries so a fixed number of steps can fill the selected preparation window. It caps the clock advance by the newest prepared hour to keep the independent clock from eliding a test step. Reply checking independently serialises service replies, compares supported requests with a reference transcript, assembles tiled responses as the UI does and accounts for index and catalogue setup separately. Transport preparation metadata is excluded from the data comparison.
