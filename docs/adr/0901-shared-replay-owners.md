# 0901. Share dated context across replay families

Each segment instantiates one owner for each shared kind of context. An owner answers from its own copied storage, never from borrowed decoder buffers. A reply can be borrowed until the next applied hour. A family that needs it beyond that hour copies it within its own memory budget. Every owner advances in hour order and reports changed keys in that order. A query beyond an owner's watermark fails. An hour before the first version is unrecorded, and an hour outside retained history may no longer be answerable.

Character and country names use recorded identity and naming inputs at the requested hour. Character name changes include changes to the spelling of the lexical token. When the Characters table is complete, an absent row is known absence. Country appearance retains empty tags. Resolve original or own tags through the recorded country reference and reserved slot zero. An absent `CountryAppearance` row remains a known absence when its table is complete. A static country has a false civil-war result. The country naming owner uses the row order and per-field failure precedence of the recording. It keeps fields independent and leaves the request hour off the failure reason so a lasting failure does not generate repeated changes. The owner also advances war-end deadlines.

The roster distinguishes the native country identity, its canonical slot, and the link through which a row names it. A link can alias a different slot. The roster visits live countries by id and a slot's holders in recorded table order, so callers can select the last holder's tag or require a unique holder. It retains raw tag bytes even when they are invalid UTF-8. Reverse tag lookups order slots by the first holder's id. Reverse link lookups order links numerically. Completeness determines whether an absent row or empty result is known. An unknown slot invalidates a reverse tag answer because it could contain the requested tag. A census change can therefore change a reverse lookup without a key edit. The identity epoch advances on a rebuild so downstream identity caches rebuild even if no individual row changed.

Recorded ownership preserves province state zero as a known value. State-name resolution tries the recorded custom name, then the recorded owner name, then the recorded language template. It distinguishes an unreadable stored name, missing template content, no template, a refused template key, and a non-plain expansion. A change to any input that can affect a state's name produces one notification per state and hour across all name usages.

The in-memory test owners use the same dated contracts and distinguish a complete census from incomplete input. A forget records a gap or damage and makes held answers unavailable. Variant naming retains original dates for unchanged answers when a complete naming read follows a gap. Footprint deadlines belong only to the evaluation whose footprint remains in force at that deadline.

Each literal's content identity is shared only with equal bytes. A family subscribes only to the tokens it reaches. The variant owner assigns one id per handle on first sight for use by every family. Typed change-log references reconcile variant ids across segments. Equal naming operands share an identity so a consumer can compare versions without copying the operands. Families retain their own selection and dates. A complete census or a complete nonempty change ledger supplies the naming evidence. After a gap or incomplete input no earlier version is available until a complete naming read. An unchanged version then keeps its earlier date. A definition's disappearance also changes its version. A type token can have no observed spelling, while the design name separately distinguishes the absence of an explicit name from refusal.

One trigger dependency registry per segment allocates query ids so families can register the same text independently. It retains the static union of holdable reads compiled from the recorded mod stack to hydrate queries registered later. Evaluation remains in the family. A query has no invalidating dependencies until its first footprint, and any later footprint replaces the old one. Unregistering a query requires its registered id. Footprints can depend on a whole field, a particular row even if absent, or a deadline such as a relation's end hour. An invalidation is reported when a watched input changes or a deadline falls due. A family can price the uncached reads, and uncompiled text remains unavailable even for a deadline query.
