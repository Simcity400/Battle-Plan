# Select effect operand grammars with verified reader identities

Read the native effect key and value reader identities from the verified executable tables. The recorded content stack supplies authored operands, dynamic token interning, registered modifiers and scripted effects. Preserve dispatch order across the registries and only attempt a scope target after effect lookup fails. During parsing, represent the operations as effects and operands. Description projection reuses the same nested grammar and knows a body's scope only when that grammar forwards effects.

Native consumption distinguishes a fresh token from a retained slot, and a raw token list resolves names without replacing that slot. Some grammars enter their field loop after a scalar or reuse an already-retained value. Nested constructs differ in whether anonymous bodies are skipped, whether an empty assigned key is kept, and whether extra components are consumed. Check block termination before a peek is resolved when the grammar would no longer recognize the resolved token as a closing marker. An unavailable named component refuses the reader rather than substituting a value. Quoted, dynamically interned and stale operands cannot be decided through the executable's static vocabulary alone.

Conditional tails share their reader and skip `limit` for the terminal fallback. While no existing condition has contributed a child, the limit reader can use a later condition. Other grammars, such as AI strategy helper triggers, read each body unconditionally. Strategy helpers retain allocated context across numeric assignments, keep the old type on a failed scan, and let a negative global index represent an absent helper. Generated-claim names register immediately in their own space. For operative fields, gender uses the current token while state uses the retained slot. Unit bonus helpers use the recorded registries and preserve the one-token consumption of unknown support multiplier fields.
