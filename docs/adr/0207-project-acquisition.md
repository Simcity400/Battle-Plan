# 0207. Keep project acquisition paths independent

Only ProjectPrograms and ProjectBreakthroughs use the daily raw-copy path. They share one authenticated country census and one status read per canonical country. The FIFO decode worker runs the existing typed readers against recorded spans. Exact keys shared by several reads can be staged once. Each table's own failure remains local; a failed common census or status stops both readers at the same prefix. Failed raw acquisition withholds those two tables while leaving the independently captured tables intact. The raw-mode gate survives reset until decode completes and clears it.

The programs reader first gathers candidates from every admitted country. Row validation cannot cancel any part of that earlier census. The mirror stages both phases, using the shared assignment reader for children, so assignment refusal can leave an independently valid program row standing. Use the authenticated owner's staged status when already available, and stage any needed resolution spans outside the census prefix. A validated array header proves its full range before chunk offsets are computed. A full-group optimization may fall back to scalar admissions without losing their exact prefix or demand. The breakthrough walk validates sentinel, parent and ordered successor links with a cycle guard. Reuse staged nodes within the local cache. Once it fills, stage additional observations normally. The owning log preserves each attempted field and the stop point for replay. Extra staged data never grants admission to a read the typed walk would refuse.

Projects and ProjectHistory retain their typed sliced acquisition. Read every country on a forced hour or after the daily pool advance. Between those boundaries, read new or unpublished countries and countries marked by a project writer. A country's aliases all participate in the same decision, and its rows retain the owner's stored raw id. An incomplete census cannot prove that an owner disappeared. At the daily boundary, state ownership determines which countries' pools advance. Changes that were missed by observation are recovered on that boundary.

The existing project walk supplies the authenticated variable store address and row identity. A worker copies selected variable data when first observing it or after a marked write, then freezes it without a live memory capability on the decode worker. Register initial stores serially before dividing owned work, so two lanes cannot refuse one another's registrations. Keep membership during a refused read or a same-key pointer replacement. A single row's refused runtime does not prevent later rows from refreshing. Command and effect writers, and the daily pending-offer iteration, determine which pending values remain current.

The rest of the project capture is independent of the sliced family. A worker can take those buffers while project acquisition runs. Return them before conversion, or publish the lost tables unavailable. The two views of raid targets share one native walk. Unassigned and refused outcomes still report exact sizes to worker-owned pools for their next acquisitions.

Tests place typed and split readers over the same synthetic memory and compare outcomes, rows, names and candidate counts. Their scale digests exclude authenticated native addresses, which are acquisition metadata. Fault cases include aliases of the zero object, changed child populations without a country-count change, and later lookup spans reached even when the census stops. `projects_copy_bench` can use guarded memory reads because the synthetic address space remains immutable and alive for the whole loop. It evicts source data before measuring daily reads.
