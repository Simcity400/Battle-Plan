# 0303. Use the recorded character and division identities in shared text

The shared trigger evaluator and tactics read the same hourly character inputs. A direct unit leader takes precedence over a resolved referenced one. Missing skill operands remain missing. The native no-leader skill case is zero, while a tag test uses the leader's owner or the character's country and rejects the null country. Retirement comes from the character's country and the recorded retirement roster. Operatives can pass the trait gate even when retired. The character table projection reads the keys and the operands each caller needs, with failures surfaced only if an expression reaches that operand.

Trait names resolve to the first case-insensitive definition in the applicable catalogue. Unit-leader and country-leader role membership compares the selected definition's recorded ordinal. Another definition with the same spelling cannot satisfy it. Scientist traits use the recorded lexical token. Multiple direct leader rows remain distinguishable from an unambiguous association.

Division history reads the same description keys, date argument and province separators for the map tooltip and service record. A custom entry names its own key, and an unsupported kind is named by number. Dates follow the game's fixed 365-day calendar.

The cryptology threshold and progress arithmetic are shared between dashboard and raid tooltips. A recorded active bonus answers even if the otherwise required threshold is missing. Fixed-point division reports unavailable for an invalid result, rounds to a percentage and clamps the meter frame. Rust and frontend tests consume the same decimal-string inputs to preserve the full integer range.
