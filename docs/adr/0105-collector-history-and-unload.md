# 0105. Prepare history before capture and quiesce work before unload

The collector prepares previous branch history before installing the hourly hook. It identifies recordings by their headers, with the uniquely matching unsaved recording taking precedence because it contains the saved history and later work. Preparation refuses ambiguity and cannot assume a file with an unreadable header belongs to some other campaign. When the header identifies a campaign but no revision verifies, only that campaign fails. The recorder may explicitly omit a campaign's history so its unreadable file cannot block capture. A recording that appears after preparation needs fresh preparation. A prepared history lease keeps the snapshot readable through append and rollback. Saving may temporarily release the lease and restore it to the file that now owns that campaign's history.

When resuming a process, the prior session's content metadata seeds the prepared tracker. Consumption waits until the new in-memory observation can confirm it. Event identifiers, including loss and damage ledgers, are seeded from maxima across retained history and partial prefixes. An empty later hour cannot erase an earlier identifier. Map events continue their epoch and reached sequence across process sessions. A branch keyframe begins without truncated delta rows.

History load uses its own worker scope and joins those workers before it returns. A process-global pool could resume on code in the unloaded collector image. Detach also verifies that no live non-calling thread was started inside that image. The caller holds the image mapped while the collector checks its span. A snapshot thread that disappears before it can be opened no longer holds unload, but query and wait failures prevent the collector from proving quiescence. The Windows thread query asks for the original Win32 start address. Only a signalled result proves a waited thread has exited.

Attach and detach append milliseconds since open, the step, and an optional count to the session's `progress` file. The recorder uses the last line to explain a stopped attach or detach. Each append formats into a bounded stack buffer so it works after the allocation gate closes. Opening progress truncates the session's previous file and append mode preserves lines from a worker panic's separate handle. A failed append loses one line, and attach retries report a family only when they first reach it.

All Rust allocation uses the collector's private heap, including infallible bootstrap allocation. The DLL refuses load without allocating if that heap cannot be initialized, and defers ordinary loader work until it is outside the loader lock. An explicit unload follows joined and quiescent teardown, after the detaching thread's Rust TLS callbacks have run. Process termination leaves reclamation to Windows. The test binary keeps its fault-injection allocator and reserves more default thread stack for the larger test-build frames, except when the environment already sets a minimum. Explicit DLL worker stacks are independent. Threaded tests synchronize on events or claims and use a hang guard only to diagnose a stuck scenario. When a scenario reports progress, it resets that diagnostic wait.
