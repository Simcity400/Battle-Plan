# 0203. Validate a tap's continuation against its native frame

The tap verifies whole instructions covering its owned span. Typical relocated data instructions must be independent of the inserted call's return slot and instruction address. A narrow set of stack-local and branch-tail forms is permitted because the continuation preserves those forms' original stack or branch behavior. Register-only arithmetic, compares, conditional moves and selected data stores carry the original operands and flags. Unrecognized or implicit control forms are refused by name. Verification distinguishes an address with no index from an unsupported base-less operand.

The ordinary hook uses a nearby relay so a relative jump can span complete relocated instructions. A tap's redirected return must preserve the original frame and handler scope at its destination. When the original sequence returns through a native epilogue, the patched call return lands on the preserved epilogue and the moved tail target sees a restored native stack. The bridge keeps fixed frame storage for the registers and saved flags, restores the native nonvolatiles, and records the correct unwind state along each path. Interior call sites can have different incoming stack alignment, so a frame register keeps unwinding valid across the bridge's dynamic alignment and transient stack changes. The observer runs with the direction flag clear and the native flags are restored afterward. The retained flight count covers the relocated instructions as well as the observer. The continuation is frameless when it no longer owns the saved native frame, and the stack adjustment and returned instruction ranges have matching unwind records. [Windows x64 prologue and epilogue rules](https://learn.microsoft.com/en-us/cpp/build/prolog-and-epilog)

The tap tests author instruction fixtures independently of the production bridge and inspect real instruction offsets independently of its unwind array. The cases include adjacent stores, nonvolatile preservation, carry preservation, register-addressed data forms, state and membership branches, and a branch tail that must skip a deliberately wrong result. Tests snapshot flags before fixture arithmetic changes them. A nested unwind steps through the actual Rust callback and then its generated caller. The test fixtures use authored code and restore or release only their own buffers.

Script-variable and flag observations keep the original native operation in flight under their guards. They identify the affected store or manager from the call's arguments, including functions that receive a nested row array. The original arguments and return are forwarded. Observation does not infer an owner or mutate the operation. Party and party-leader observations follow the same rule, including the incoming stack arguments of a leader transfer.
