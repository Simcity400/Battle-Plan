# 1001. Stage one installable desktop bundle and verify it before publishing

The shipped-file manifest enumerates the Tauri application, Cargo-built companions, the pinned shader compiler, and repository-provided files. Tauri embeds resource configuration, so stage resources under the desktop crate and embed neither absolute build paths nor hook paths. Keep launcher, forwarded Cargo, and application arguments separate and leave them outside shell interpolation. Resolve a relative Cargo target directory consistently before invoking Cargo from different crates. The launcher follows Cargo's target precedence from overrides through the environment to the nearest config and then Cargo's home. Development and packaging stages share the same profile. Build the UI before Rust embeds it, then link companions and the Tauri application serially because fat-LTO links need substantial memory.

The SDK compiler can advertise SPIR-V without the required backend. Fetch the pinned upstream DXC release, verify its digest, stage only the designated DLLs, and install the accompanying licences. Viewer builds and development resolve that compiler beside the program. Native desktop tests drive the actual application WebView and use the same compiler placement. Windows already delivers an attached console's Ctrl+C to Tauri. A second emulated interrupt from Node can kill it before it stops Vite. Drain child output before reporting its result.

The release runner is a user logon task outside any worktree and inherits low CPU and I/O priority. Start it again after self-updates, discover Git Bash from the installation because only its command folder may be on PATH, and point the jobs at dedicated build, toolchain, cache and temporary directories. Preserve valid signatures on third-party components. The release smoke compares actual installed files. NSIS internal folders and its install-time uninstaller are separate, and 7-Zip may expose the install directory nested under its NSIS variable name.

Inspect the contents of installers and archives instead of relying on compressed bytes. Scan raw bytes and both UTF-16 alignments for sensitive content. Restrict email candidates to known top-level domains to avoid false positives from compressed data. Include text and encoded signing-key representations. Resolve the scan target relative to its caller so failure logs do not print the build machine's directory. Encode release notes in UTF-8 and send them through the leak gate before displaying their contents. Signature verification distinguishes the Tauri formats that sign the file and the file's BLAKE2b-512 digest.
