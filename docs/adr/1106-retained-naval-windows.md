# 1106. Keep naval window instances through partial updates

The view owns separate pools for naval combat, base, result and mission icons. The instance key includes both pool and slot. A grid item further includes the owning icon and its item pool. A port wrapper, combat tile, convoy addition and at-sea counter never share an instance. At-sea counters belong to their source task force. A complete census that loses the source destroys its instance, while an incomplete census retains it with a refusal. Changing registry or GUI viewport reconstructs the windows. Hidden native constructors do not run an update until a pass reaches them.

Preparation builds a plan with ordered writes and no window ownership. Presentation uses the shared province schedule to request or erase owners, handle visibility and placement, apply icon and item writes, finalize grids and tick the instances. It then draws only icons admitted to the pools’ visible lists. Retained detached windows can finish transitions without drawing, and their Hide reaches their held items in order. An offscreen dirty province retains its owners until its scheduled cleanup. A clean offscreen province consumes no new pool slot, and only the offscreen dirty work that can next disappear asks for subsequent pool passes. In-view admission tests authored rounding and anchor in the integer GUI viewport including edges. A refused anchor leaves a placed window where it stood and withholds known placement for a new owner.

A view whose ownership requests differ from the game’s can no longer assume the same round-robin slot history. Unreproduced requests, erasures, admissions and the unrecorded frame when pool growth completes can all cause this divergence. A new allocation after divergence may inherit another owner’s held parts and transitions. Existing owners in established slots remain valid. Result icons retain their last admitted province results through uncertain censuses. A missing result in a whole table expires it, but it still counts in the held reference total for majority. A live icon with a result missing from an incomplete table can neither draw nor be erased by that evidence.

Maintain unknown parts per instance and report why. A write repairs only its own part. A definite Hide removes a drawable’s refusal from the visible set without establishing its value. A Show that preserves the unknown drawable reinstates the refusal. A structural call failure withholds until rebuild. An omitted icon rotation retains the owner but can leave bars, grids, background and placement unknown. Its items can have been altered or created in the missed update. A subsequently constructed item inherits that uncertainty once, and later partial updates must repair every required visible part. Supply is set only by full first-member intel. Undefined content preserves the existing selected sprite. An unresolved choice withholds that sprite. When a base refuses layout, count each omitted child under the refusal. When preparation already counted an omitted icon, drawing contributes no duplicate warning.

An unengaged rotating icon keeps an established frame for its own pool slot. Otherwise the engagement index can establish a carried frame and report its provenance, with the binding’s frame one as a provisional fallback. A later index can replace that fallback. Global spillovers keep the slot frame. A live combat still writes the headquarters frame when an update does not rotate it, so this write alone does not repair unknown bars and grids. Coarse or peace-conference base passes empty port grids. Items retain authored slot positions even while hidden or refused. The base glyph and port grid share a successful layout, while separate paint batches protect label ordering. Counter drawing moves the graphical parent and leaves the logical viewport and child clipping in place. Pass-through plates have no pointer target, and an unresolvable alpha hit is refused.

Window graphics time and frame step are separate. Advance frame-animated drawables before the reverse-registration GUI transitions. This includes a child hidden by a parent’s completed fade in that tick. An idle tick can stamp time and reuse a settled layout. When a window’s transition history is unknown, withhold it until its instance has spent the longest transition of its registered graph continuously outside any transition. A further divergence restarts that wait. A graph with no transitions can settle immediately, and an absent instance is forgotten. Tick failures, missed updates, first allocations after divergence, and new items the game might have allocated during a missed update all participate in the same transition rule. Only an advanceable settling wait can request a new frame. A base and its visible port items can stop being written after the same decided inputs receive two writes and the second is quiet.
