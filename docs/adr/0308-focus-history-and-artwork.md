# 0308. Date focus completions by continuity of the recorded list

The focus products share one fold of the `Focus` and `CompletedFocuses` histories per tag holder and branch stretch. They read the hours where rows change, with an opaque cell fetched at its write hour. Reading native focus lists respects their 512-byte token limit. Dated completions require an observed hour immediately before an append to the same holder's list and tree. A reset, holder change or missing hour can hide a completion, so newly seen entries after those transitions stay undated. Existing completion dates survive a missing hour when their earlier evidence still applies. Progress and its previous day's rise require matching holder and active focus evidence.

Whole history, hourly state and order pages read the same fold. An order-page request must present the hourly page counts it received, so it cannot browse a different order under stale counts. The four focus inputs are checked individually for refusal or partial rows. Dated focus presentation reconstructs an exact hour and refuses a run that witnessed a different campaign, even if a later read leaves the identity unknown. Reconstruction misses share one serialized pass, while cached hours remain available without waiting for it. Already verified preparation frames use the same presentation boundary.

National and continuous focus databases may name different focuses with the same token. Completed and current focuses use the national database. Continuous focuses use the continuous database, with its own missing content and cache. Static content provides authored duration and country-independent text. Visible titles that require country scope keep their dated reads and explicit refusals. The artwork reply measures escaped JSON before retaining lazy items to enforce its actual size limit.
