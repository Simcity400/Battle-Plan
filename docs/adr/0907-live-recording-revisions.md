# 0907. Commit the recording and its source cursor together

The live writer applies each capture hour to the recording store, runs derived writers, and writes the resulting parts as they close. A block closes with a page, clock, appended strings and summaries. Spans index block pages and fold their summaries. A short block ends a run. A revision commits the new blocks and its control records together with the source cursor, giving the source a durable boundary for releasing journal segments.

The writer asks the host about a branch before writing its first hour. While the host defers, its records are held aside and the source retains its first hour. The capture end forces a decision about branches still waiting. Writing starts with a restore of the accepted run's first hour, and subsequent changes start with the second hour. The writer creates the recording on its first accepted hour or when the capture ends with only records to keep. Re-delivered session and control records are deduplicated. An interrupted capture records the branch and its last held hour. Damage can lack a trustworthy hour, so recovery notes carry source segment and byte position.

A journal's initial capture record identifies exactly one session. A live writer reads controls against their branch context and checks that a complete Campaign table identifies the recording's campaign before it writes that hour. When a live source has produced no more records yet, the writer yields `Waiting` without finishing the capture. Saving creates a revision over material already written. Earlier committed roots remain readable while new blocks append.

The resume slot keeps the matching capture's cursor, deferred records, run metadata, encoder and adapter state, derived writers' state, and summary ladders. Its tables are reconstructed from the recording. Another capture starts at the last published block boundary without taking over that state. A failed publication leaves the previous root authoritative, so the writer cuts a torn tail and takes up from its committed cursor. Exclusive writer access permits readers and renames. Each participating part publishes its own extents and optional resume entry in the same revision. A final revision releases the resume slot.

Summary builders start from the preceding hour's table state. A block's level-zero pieces are read back when their span closes. Higher ladder pieces hold verified extents, retaining the highest written piece when several levels folded together. A run ending before a span is full writes its last partial span as a tail.

Campaign control extents (`H4CR`) carry each revision's additions, in source order within each kind. The capture control format instead begins with its version and can name the encoded session/control facts that pair it with its source capture. The reader accepts current and proven earlier layouts. Recovery writes added records in the recording's own format and refuses changed layouts by name, so revisions cannot silently mix formats. A failure while adding records to a closed recording cuts it back to the revision originally opened.

A session facts pack keeps its own compression and offsets. The writer prefers a file extent, reads and copies it incrementally, and hands requested definitions to derived writers when the pack arrives. On take-up it reads definitions from the recording's own facts. Block string chunks keep whole strings and their starting ids so the store can read discarded text back from the file. The encoder reuses a single compression context when it takes over frame compression. A capture-path write failure uses an error kind without allocating a diagnostic string.

The append-only journal is the cross-process source for the live writer. Each `columnar.<capture>.<segment>.h4j` file carries at most one block of one run, with `Next` on rotation or `Finish` at capture end. A segment starts with versioned magic. Records carry an eight-bit kind, a little-endian 32-bit payload length, the payload, and a CRC-32 over the preceding record bytes. A torn or damaged tail stops the readable prefix at the last complete record. The initial record holds file identity and the capture record. An hour puts its optional performance counter and load marker ahead of the manifest and orders its sections as the manifest does. The reader checks long records incrementally and reads these sections separately, avoiding a second whole-world allocation at a restore.

Rotation gives the caller the ended file to sync and opens the next segment without waiting for that sync. A liveness probe releases its own reader handle first. It holds a segment it found free while listing again so a concurrent rotation can show its new segment and a concurrent retirement can be retried. Read-only fixture readers never retire or move a segment. A live-smoke build can archive retired segments for comparison with the final recording.
