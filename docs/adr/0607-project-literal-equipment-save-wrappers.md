# Project equipment data from its literal save wrappers

## Decision

Use the wrapper and subtype witnessed by a caller. A production line projection is not evidence that its manager census was complete. An absent full equipment registry, deployment wrapper, country roster or mandatory bank remains absent. A present wrapper can instead prove that its vector was empty. Search no alternate subsystem for an apparently matching pool. Keep stored line order, signed fixed5 values and subtype distinctions among military, naval, refit and railway-gun lines. For conditional fields that serialize only positive values, absence proves no more than nonpositive.

| Save structure | Writer evidence |
|---|---|
| Occupation and deployment selections | A missing occupation wrapper is distinct from its default priority of one. Defaults, group selections and explicit state overrides are separate scopes. An absent deployment wrapper differs from a present wrapper with an unset selection. Nonpositive order counters are omitted. The deployment wrapper also holds configuration, so only actual conveyor entries belong to the ordered queue. |
| Production history and stockpile | Stockpile entries come from `equipments`. Keep histories in table slot order. A history block names its variant and ordered date/units values. Units and other unconditional numeric writer fields preserve their own types. A saved scalar named `random` is also a stored variable even though loading reserves that name. |
| Licence and conveyor | Licence fields are unconditional and repeated variant handles remain distinct. The template is always present for a saved conveyor, and its role spelling comes from the lexer. Preserve a positive exile-reference emission even when its comparison is unavailable. A line without a deployment disappears. |
| Division name and queue | The type word is unconditional. Zero name order is omitted and `is_name_ordered=no` appears only when the ordered flag is clear. Keep custom name presence even when comparison lacks the corresponding recording field. Training, its max and max manpower are emitted only when positive. Equipment is absent unless an allocation row is nonzero. Halting reason has an explicit presence flag. Priority is omitted at one. |
| Equipment line | Only an all-zero MIO handle is omitted. Each counted Q15 factory efficiency serializes through division by 32768 in array order and a missing array is empty. `is_converting` is emitted when set. The required bank wrapper remains distinct from empty. Groups with no request or delivery entries have no serialized priority. |
| Equipment variant | Keep the literal enclosing definition key and explicit model entity. An active override icon emits its string with no kind. The optional version byte is zero-extended and constrains only that byte. Trait count is signed and omitted at zero. Required text such as name and icon can be emitted empty, while absence is malformed. |
| Line and pool values | Keep raw signed cost and exact unconditional priority and amount. Status is omitted at zero and only status one has serialized progress. The relevant fixed5 default 100000 is omitted. The produced pool wrapper is unconditional. Preserve both words of handles, including an ID of zero, and retain surviving repeated variant entries without inferring their native positions when zero entries were skipped. |

Persistent unit bonuses in `deployment.unit_modifiers` are read per country. A missing list is empty and a malformed list refuses only its owning country's result. Preserve saved list order and direct target keys, with exact targets written before categories and no serialized discriminator. Keep repeated targets, nonzero stats and ordered battalion multipliers. Preserve source kind and number, with absent ID for the `none` token and absent localisation key for an empty string. Requirements, terrain and other adjusters, priority and sprite fields do not certify corresponding recording rows. Refuse a new array in a wrapper whose expected arrays have been identified.
