# 0401. Verify the runtime's content mounts separately from its roster

Requested mods, discovered entries, reported active DLC and mounted files are distinct observations. DLC's report flag represents activity before the exclusion list. The game consults the list by exact descriptor bytes and updates it during startup. The runtime feature mask and the older game-state word are also distinct. Consumers use the runtime mask for its feature predicates. Map enumeration preserves the observed roster order without treating it as mount priority or proof of success.

The cached mount array records successful PhysicsFS mounts, highest priority first. A missing cache or partial traversal cannot certify the stack. A valid empty terminated list and an unavailable cache are distinct. After output fills, pointer counts can still size the next capture without reading strings that cannot be stored. Native count hints can size prepared storage before sampling but do not establish content membership. The loader worker prepares owned data without using text-width limits, so callback reads can reuse it. Local path bytes stay observations rather than replay identity.

Compare expected and observed mounts position by position. Equal Windows notation requires no file access. Different spellings can still name one directory by the volume and file identity, including short names, junctions and substituted drives. Preserve the root marker distinguishing a drive's root from its relative current directory. An unopenable path with different notation cannot establish a match. An empty expected list cannot establish even the vanilla root. The requested-mod match separately compares the final two descriptor components case-sensitively, following the native separator handling. The native map count bounds malformed cycles and preserves real population demand.
