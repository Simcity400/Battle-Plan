# 0103. Revalidate held roster and leader data before reuse

The roster pass rereads identity, country and roster position each hour. Omit name, token, gender and template reads only for a character with the held pointer and ID and the same writer epoch and sequence. Store watched rows with text offsets relative to their own arena span. Include the carried-pointer set in the prepared program key so a changed set requires rediscovery. Register before the reads it certifies. Unchanged domain tokens preserve the individual certificates without per-character lookups. A writer removes its character from the set. Newly eligible characters join after rediscovery when the carried set is empty or their number reaches one thirty-second of the roster. Rebuild held rows from complete rediscovery, with one visit per roster occurrence and exact roster order.

A quiet roster hour uses the held census without walking the roster when it can certify every occurrence's matching pointer and identity. The held order gives a direct entry lookup for unchanged positions. A moved occurrence uses the pointer lookup, and an unheld one produces no carried row. Read current country from the census and rebuild only from complete admitted observations. Summarize carried table capacity once for a pair of census generation and unique held version. If the new held set cannot be stored, take the ordinary acquisition path.

The roster domain observes append, array clear, manager replacement and a rostered character's identity repair. Every pooled job takes its token before registration and retains it with that job's latest complete full census. Full capture, scope changes, failed reads, staging overflow and in-flight writes rule out quiet reuse. Roles use the same complete census once per callback. If a quiet attempt already tried and failed to gather it, the fallback does not repeat the failed read. The census and template or leader watches can be unavailable independently.

On a quiet capture, read unheld unit leaders from the census in roster order, including appended formation fields. When no leaders carry, a prepared program uses the exact census generation and table set as its key and remains distinct from the full roster program. It checks every byte that selects a later read before replaying that read. A changed selector stops execution at that point and ordinary reads continue there. A completed plan uses the original text demand. A fault stops at the same refused read as the ordinary pass and leaves no prepared replacement. Published Characters rows depend only on the role census and the carry version, so a matching complete quiet result can publish again without rebuilding its rows. Retained output with only leader work decodes just the visited leaders.

For a unit leader or assigned trait occurrence, capture the appropriate watch before any leader read. A same-certificate entry must match the census character and unit pointer. When the census generation and quiet token both match those of the last held certification, reuse the ordered visits without looking up every leader. A fresh equal read renews only that certificate. Changed membership or rows rebuild the retained layout. The layout and census generation identify a whole carried table. A refused row or invalid text span invalidates only its leader while the unrelated leaders can still carry. A truncated training slice or factor fault may leave an acquired valid prefix, so compare its outcome as well as its bytes before reusing the leader's row. Storage growth is advisory. A pass that never ran certification clears the hold. Copy text from owned spans and shift the offsets during publication. Skill and trait definition fields follow the recorded definitions and change as content is replaced at a load.

The country leader role job carries rows under a matching character pointer, ID, map header and writer sequence. Publish current country from the admitted census. A writer that cannot identify a character revokes the whole role domain. A duplicate pointer evicts its held entries and forces fresh reads of those occurrences. If no census is admitted, forget the cache and walk the roster. Fresh empty maps can consume the batched sentinel in the same way as the full typed walk. Other reads continue through the census view. Only a complete capture of every occurrence can certify the whole table. Recycle a published carried job even if it acquired no raw log, so later jobs keep the cache.
