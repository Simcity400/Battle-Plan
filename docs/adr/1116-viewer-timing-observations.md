# Viewer timings report work and waiting separately

An opt-in window log writes one file per map as `<BATTLEPLAN_PERF_MAP_LOG>.<map>.jsonl`, or next to the host's log prefix when supplied. Maps receive their numbers from their first record. Requesting a log enables CPU accounting from the beginning of each frame. The bounded writer queue will drop records to keep a frame moving. It reports accumulated loss before new lines and before idle or close marks, so the host knows whether a gap means silence or data loss. Idle marks say the queue did not hold older lines. The host may stop after any frame, and shutdown drains all queued and outstanding loss records.

The host and page correlate by Unix epoch milliseconds. Window records distinguish application work from Egui tessellation, painting and presentation. A subsequent record identifies the earlier frame's paint and image-acquisition cost. GPU timing may be unavailable and is attached when ready with its own frame id. A free camera can see multiple map copies, so the frame records camera kind and height. Scope records use differences over 30 frames rather than charging every frame for collection. They record cycle reads to expose measurement cost and serialize the record cost under the following window. Each stage reports wall and on-core times separately, so a slow stage can be attributed to work or waiting. Accounting reads between layers or tables, and the next measurement includes the intervening loop bookkeeping. GPU write counters can include concurrent writes from another owner.

The side tracks layer backlog in publications, retaining applied hours and their times. A product reaching its bound causes a named wait. A rated layer may set a different bound. A seek resets comparisons so a new generation can show an earlier hour. `Current` says the layer owed no product for the step. If it subsequently shows an older product, the apparent fall is reported separately from actually publishing older data after newer data. `BATTLEPLAN_VIEWER_CHECK_STEP` and `BATTLEPLAN_VIEWER_CHECK_RATES` check the relevant lag and stopped-picture expectations. `BATTLEPLAN_VIEWER_CHECK_PUBLICATION` checks GPU completion and that layers claiming to be current do not go backwards within a generation. Independently paced products are tracked separately when a changed step pace invalidates their speculative work.
