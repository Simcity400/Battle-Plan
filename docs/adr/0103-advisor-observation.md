# 0103. Observe advisor definitions and modifier caches separately

Split advisor definitions between historical and generated roster sections. Generated roster growth should not invalidate the historical section. One root acquisition serves both, and alternating owned arenas let one changed character grow without moving subsequent cache keys. When the roster supplies an admitted census, it provides each occurrence's identity, country and map header, so the section's read plan traces sentinels only. The direct roster path traces roster, character views and sentinels. An in-view sentinel must use the ordinary copy, and a header failure before its sentinel ends the batch.

Treat country as a result value. In a direct roster plan bind it to the exact read occurrence for its character. Address equality is insufficient evidence for that binding. A changed or unfamiliar reader shape keeps the full equality controls. Read-ahead hints follow their selecting pointer. The prepared executor issues them only after its exact pointer comparison succeeds. Only the exact character-view read shape identifies a candidate map header. Role payload reads cannot choose other characters or certify reuse. Decode prepares or grows arenas before any later capture uses them. Cache-line writes for country stay conditional on an actual change.

Modifier accumulators and tooltip key sets have their own per-role certificate, acquired by registering the character before reading it. Reuse only a position from a complete last capture whose role, character and watch epoch and sequence still match. Trait edits, hourly upgrades, role factories and role updates reach the observed rebuild. A role without a watch is read again. Each hour acquires the pre-existing numeric cache for every role before appended tooltip keys can consume the byte arena. A tooltip refusal does not invalidate the separately observed definition. Hold the preceding arena only once it completed and has a suitably sized spare for the new capture. Otherwise read all roles. The owned decoder needs no surviving native objects.

Republish the entire table without lookups or native reads when all entries were watched under both families' quiet tokens and the current census matches the last complete observation. The domain token avoids individual lookups for unchanged characters while their identity controls still apply. Take tokens before any reads they certify and verify them again before publication. A frame already holding the content's version can republish its rows without rewriting them. Refresh the content version on a fresh capture. An epoch change, unobserved writer, or changed census eliminates whole-table reuse. The parity tests compare independent observed sequences so two distinct reads at the same address cannot be accidentally conflated.
