# 1101. Resolve combat-window content and names from their recorded context

Combat windows load authored operands and current art through the resolved content stack. Traits, tactic triggers, division naming groups, terrain definitions, static modifiers, tooltip placement, and opening delays come from those layers. Borrow immutable declarations and share the inventory with counter and tooltip painters. Lazy leader portraits resolve on demand under unique sheet identities and inventory their literal references once per content set. Preserve compressed texture payloads through upload and preserve declared dimensions until a native walk decides actual placement. If a visual mod breaks a replacement, fall back to art resolved through the recorded mod stack and report why. Missing or undecodable sprites remain distinguishable from pending ones. Compare full language-family keys, and use the reader's byte spelling for archive assets even when caller names are constrained to UTF-8.

Some resources are named by code after the declared GUI is read. The find view names its victory-point frames, the state view names icons for its buildings, occupation laws and modifiers, and aircraft use their country and archetype fallback cascade. Inline map icons share the global sprite inventory. A missing declaration stays missing, including when both NATO frames depend on it. The first rule that names a required province supplies its rule icon. Duplicate registrations do not replace it. Metadata for naval intelligence count estimates, weather and screening comes from the defining content rather than example values.

Resolve a naval title from the battle province's region before considering a province substitution. The region's authored name key is what playback localises. A port-strike title always uses that region name. For an ordinary battle, substitute a qualifying province only when the region's best score reaches the recorded threshold. A pixel-less province retains the native zero position. The province-name chain uses a proven rename, then one victory-point localisation, then the state's display name. A province without a state may use its region's name, and the final fallback is its id. The qualifying tag uses the canonical state owner's original tag when positive, else its own tag, and uses the reserved zero country's object for absent or null state links. The qualified victory-point key wins when present even if it yields empty text, which advances to the state ladder. A partial rename table can prove a present rename, while only a complete table proves absence. Stored state names lack a re-localisable token, so the recording language applies to them. Definition keys can render in the current language.

The dashboard joins the land and naval battle logs to place-name history at each battle's first recorded observation. Equal plain titles share one ordinal sequence per recorded timeline, including its ancestors and gaps. A single battle keeps its plain title. A missing place keeps its reason. The map and dashboard use that revision's title index.

Numbering uses the retained result identity where available and the live battle identity otherwise, folding a linked report into its live battle.
A date change on merge keeps the same battle and its first observed place and date.

The air graph's channels, colours and scale come from recorded executable tables, and the daily air reader uses the latest pass that visited the viewed country at the selected hour. Report combat window table gaps only while a combat is selected. Refusals survive both render paths, and matching absent inputs never substitute authored examples or previous rows.
