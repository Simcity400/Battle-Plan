# 0505. Measure, paint, and commit in one dashboard frame loop

The dashboard advances its playback clock, lands data in arrival order, measures layout, paints, commits React work, then runs after-frame tasks. A task for a later phase can join the current frame. The measure phase owns layout reads so position changes, canvas painting and React commits do not interleave with measurement. Geometry that depends on a frame's own commits, such as the cells of a drawn panel, is read once in the after phase, all reads before any write, so a frame lays out once however many commits it holds; geometry asked for by a commit between frames is read right after that commit. React work that frame listeners ask for commits in that frame's commit phase: a listener hands its state change to that phase (`inFrame`), because React does not commit an ordinary state change made outside the commit phase in that frame, so the frame would read geometry before it. A hidden page or a runtime without animation frames uses a timer, and the frame time step is bounded to avoid animation jumps after a stall. Offscreen widgets stop receiving frames and repaint once on return. Their clock methods keep stable identities.

The dashboard engine drives row entry, exit and gliding with the same curves used for table motion. Transform transitions on many individual elements caused the browser to restyle a compositor layer for every moving element. A single paint-phase task updates the styles instead. Retargeting starts from the value already drawn. Reduced motion snaps directly to the target.

Draw commands take layout coordinates, with source raster rectangles and image resolution in raster pixels. Retained paths bind their components to the chart axes that should move with the view and can be revealed at a specific clock position. A retained backend uploads only the changed raster columns.

A followed reading has one owner: the drawing lane of its subscription. The page owns the clock, the DOM and one install operation per widget, and holds no reading values beyond what that operation installed. The page runs clamp(logical processors − 2, 1, 4) lanes; a widget gets its lane at mount, by load, with copies of one widget kind kept on one lane while its share allows, and every hook of a widget subscribes through that widget, so its subscriptions are joined. A subscription id carries its lane (id = n × lanes + lane), native allocates a panel's cell groups in its owner's lane class, and the pull worker splits each pushed message by id, gives every lane the route-wide parts (confirmed hour, resets, completed steps) and transfers the rest undecoded.

A fact is a value or refusal native stated at hour h and confirmed through c ≥ h. Panel data and refusals start a fact at c = h; STANDS extends and reopens the latest fact; WAITING closes it through the hour before; COMPLETED extends every open fact of a stepped subscription; a follow message starts a fact per answer at c = max(start, its limit or the message hour) and extends every other open answer and cell group. A later fact at the same hour replaces the earlier one, a successor caps its predecessor, and no fact is extended from another. A follow reset withdraws the route's follow facts, including a picture carried across a seek, and raises the route's reset generation, which every lane counts from the first header of its native route, bound or not, and presents even when nothing repaints; panel facts stand. Changed rows merge only onto a table of their own seek: a message of an older seek is dropped and one of a later seek waits for it. A seek keeps per subscription only the picture covering its target. A panel with live cells is a picture only where its fact and one fact of each cell group intersect, found by a search over start hours. Selection at a target takes the covering join from the latest fact, else the latest complete join, else the carried picture, else nothing, which is the named state "Reading hour T". Every picture carries the window of targets it stays the selection for; the window also breaks at the product's own change hours (a day count, revealed rows, a built table's stretch), and the lane paints at the window's start, so a stepped panel at 96 confirmed through 140 shows the day count of 124 at 124, and never past its confirmation: paused at 150 it keeps the day of 140. Each widget selects, prunes and paints at its own target, its pin or the hour plus its offset. A widget over several subscriptions shows their join: the latest hour, the earliest confirmation and the common window, and nothing new while they share no certified hour or window. The lane keeps the installed and pending pictures' facts, the picture selection would fall back to, and every fact a later selection can use; it releases the rest, cell versions included, and returns their bytes as credit.

The follow wire marks an answer whose rows ascend by their 128-bit key and carries a text-offset column, so a lane adopts a whole table as received and merges changed rows by walking keys, resolving each changed reason in its own answer and copying the base's names and texts as they are. A ranked series answers each row's rank and a window version; the follow-window command moves the visible rank range and adds selected holders outside it, a window on a series of every country answers only its countries, a follow can name its first window, and a window change wakes a paused query. Copies of a widget sharing a subscription each name their window and native answers their union; the page installs only entries of the current version, and a table never paints a member its columns' window lacks. Native reserves credit for the bytes it sends and holds a send until lanes release bytes, one message always going when nothing is in flight and a message the clock has reached always going, so lanes holding a picture can always receive its replacement; a lane charges the bytes a merged table holds beyond its wire size, and the pull worker returns the net through push.localhost/credit. Only hours the clock has passed merge into one answer, so pressure never merges ahead of the clock; past the byte budget the stream fails by name. The `.battleplan` format, the collector and the recorder do not change.

The clock publishes the hour first in every publish: the page revalidates installed pictures on a seek, installs the entries that arrived, flushes React in that task, and asks each lane for a frame at a speculative target (the hour plus the step times the lane's measured reply delay, never moving back while playing) or, on a pause, seek, speed change, rebind or focus, at the exact hour. A lane serves only its newest request, keeping every acknowledgement and refusal, selects each subscription, and paints due widgets whole within its budget: widgets whose data changed first, least recently served first, then motion steps at any speed; a widget whose painter reports motion stays due, and each step installs like any picture. An entry holds the widget, binding, entry id, h, c, window, seek and reset generation, mode, every surface and field or SAME naming the content id it keeps, and the inspection for the current key; content ids come from fact versions and exact equality of inputs, never a hash, and a drawn surface names new content exactly when its painter drew pixels; a mirror, a tooltip and a row list each carry their own. The page installs an entry only if its seek is current, its reset generation is not older, its binding and ranked window are current, the widget is not named failed under that binding, the actual target lies inside its window, it is not older than the installed entry, and every SAME part names exactly what the page shows; otherwise it refuses it by name. Every offered entry ends acknowledged or refused: a displaced early entry and early entries retired by an exact request included, and a paused commit tells its lane at once. A failed transfer leaves "drawing failed" with the surfaces cleared. The widget shows the fact hour, displayed through min(t, c), and is dimmed when paused past c or bound to a stale binding.

A binding generation increments on any change to size, settings, scroll window, pinned hour, offset or subscription; a change of pin, offset or subscription revalidates the installed picture in that commit, so a widget showing 96 rebound to a pin at 20 shows "Reading hour 20". A rewind keeps a picture only where its confirmation and its painted window cover the new target, redated; a widget's first canvas and a change of painter keep the installed picture dimmed, while new canvases replacing drawn ones clear it, and a pipeline widget keeps its canvas across a remount of the component that shows it; a paused forward step keeps the picture actually shown, dimmed; pausing and speed changes hide nothing. While paused a lane presents on its own when its selection at the last exact target changes, and the page commits it in one coalesced frame. Inspection and pointer hits are answered by the lane from the installed picture and shown only while they answer the current key. A clock step tells a widget only when what it shows changes; dates go to date listeners. Every follow-clock request is numbered per route; a rejection or {available: false} fails the stream only while it is the route's latest command. A refused registration, a missing follow channel, a pipe failure, a lane failure and answers lost before registration are each named states that queued work cannot overwrite, every followed consumer shows the reason, and no followed consumer has a request path at the moving head: head products, the Scoreboard, keyed series, MeasureRace and MeasureWidget show the named state instead. Pinned and historical reads stay.

Widgets drawn on the page install their model (the panel, kept while its structure is equal) and live values as fields; drawn panels install their values as page text written into their fields in the install task, which needs no geometry round trip and leaves nothing for an overlay to mix; tables and the arsenal race install lane bitmaps on bitmaprenderer canvases, the page never setting their backing size; the date face is page text. Earlier designs failed in ways this one makes impossible: a page mirror of worker readings dated by the worker's own hour, structure keys that let a canvas advance while text described the previous hour, worker-committed canvases reaching the compositor apart from the DOM (92% of captured frames ahead), entries matched to an exact publish discarding work forever, coverage inferred from leads, hourly fallbacks asking at the moving head, signature hashes that reused old pixels under new text, and merges ahead of the clock that starved every lane.

The differential test (`ui/src/dashboard/follow/differential.test.ts`) drives native answers through the lane split, the lanes and the page install under random seeks, pauses, steps, speed changes and channel delays; the emitter sends multi-row tables as whole rows and changed rows, lagged readings confirmed only through their limits, not-recorded spans with their reasons, and a lane failure; an oracle that reads only the synthetic recording checks every committed frame of every widget, a joined one included, for dates ahead of the target, values of the fact hour, reasons, certified coverage true of the recording, dim, blanks and named failures, each reported separately. A browser fixture (`ui/src/draw/tables/table.dom.test.ts`) runs a production table on real lanes and checks its pixels, mirror and inspection across a same-layout value change against a fresh table, and its limited and missing readings. The probe (`ui/src/dashboard/follow/pipeline.probe.ts`, Node, unthrottled, data path only, every message cloned, an install listener per widget, changed rows after the first frame as native sends them) measures 114 widgets on two lanes at 1,440 h/s, one day a frame. Message size, lane ingestion, lane frame and page commit, p50 / p95: 114 copies of 128 countries every row changing, 8 KiB, 0.04 / 0.08, 0.75 / 1.35 and 0.18 / 0.35 ms; copies of 1,500, 97 KiB, 0.14 / 1.13, 2.38 / 4.01, 0.29 / 0.50 ms; 114 distinct of 128, 475 KiB, 0.85 / 1.76, 0.99 / 2.36, 0.23 / 0.44 ms; 114 distinct of 1,500, 5.4 MiB, 7.67 / 10.85, 2.76 / 5.60, 0.47 / 0.62 ms; with 5% of rows changing, 281 KiB, 2.74 / 6.05, 2.04 / 5.59, 0.41 / 0.55 ms. Merging changed rows by re-encoding the base's texts took 107 ms a frame for that last page. Painting, crops and page rendering are not in the probe; the acceptance run on four cores at ×4 with integrated graphics decides product performance.

Chromium's slowdown affects the page's main thread and leaves drawing workers at normal speed. The worker benchmark therefore accounts for the measured frame work and adds a proportional delay by occupying that worker. Rate one adds no delay. The fixture checks repeatable outcomes separately from measured frame timing.
