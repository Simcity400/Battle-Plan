# 0505. Measure, paint, and commit in one dashboard frame loop

The dashboard advances its playback clock, lands data in arrival order, measures layout, paints, commits React work, then runs after-frame tasks. A task for a later phase can join the current frame. The measure phase owns layout reads so position changes, canvas painting and React commits do not interleave with measurement. Geometry that depends on a frame's own commits, such as the cells of a drawn panel, is read once in the after phase, all reads before any write, so a frame lays out once however many commits it holds; geometry asked for by a commit between frames is read right after that commit. React work that frame listeners ask for commits in that frame's commit phase: a listener hands its state change to that phase (`inFrame`), because React does not commit an ordinary state change made outside the commit phase in that frame, so the frame would read geometry before it. A hidden page or a runtime without animation frames uses a timer, and the frame time step is bounded to avoid animation jumps after a stall. Offscreen widgets stop receiving frames and repaint once on return. Their clock methods keep stable identities.

The dashboard engine drives row entry, exit and gliding with the same curves used for table motion. Transform transitions on many individual elements caused the browser to restyle a compositor layer for every moving element. A single paint-phase task updates the styles instead. Retargeting starts from the value already drawn. Reduced motion snaps directly to the target.

Draw commands take layout coordinates, with source raster rectangles and image resolution in raster pixels. Retained paths bind their components to the chart axes that should move with the view and can be revealed at a specific clock position. A retained backend uploads only the changed raster columns.

A followed reading has one owner: the drawing lane of its subscription. The page owns the clock, the DOM and one install operation per widget, and holds no reading values beyond what that operation installed. The page runs clamp(logical processors − 2, 1, 4) lanes; a widget gets its lane at mount (and re-places on remount) by measured smoothed paint cost with count tie-break, with copies of one widget kind kept on one lane while its cost share allows, and every hook of a widget subscribes through that widget, so its subscriptions are joined (see [ADR 1397](1397-follow-pipeline-cost-and-isolation.md) for why mounted widgets do not migrate live between lanes). A subscription id carries its lane (id = n × lanes + lane), native allocates a panel's cell groups in its owner's lane class, and the pull worker splits each pushed message directly by lane for directed records, gives every lane the route-wide parts (confirmed hour, resets, completed steps) and transfers the rest undecoded.

A fact is a value or refusal native stated at hour h and confirmed through c ≥ h. Panel data and refusals start a fact at c = h; STANDS extends and reopens the latest fact; WAITING closes it through the hour before; COMPLETED extends every open fact of a stepped subscription; a follow message starts a fact per answer at c = max(start, its limit or the message hour) and extends every other open answer and cell group. A later fact at the same hour replaces the earlier one, a successor caps its predecessor, and no fact is extended from another. A follow reset withdraws the route's follow facts, including a picture carried across a seek, and raises the route's reset generation, which every lane counts from the first header of its native route, bound or not, and presents even when nothing repaints; panel facts stand. Changed rows merge only onto a table of their own seek: a message of an older seek is dropped and one of a later seek waits for it. A seek keeps per subscription only the picture covering its target while retaining cell-group ownership across seeks so subsequent changed rows always find a base answer; a protocol or merge fault on one subscription isolates only the widgets depending on that subscription or its cell groups rather than failing the whole lane. A panel with live cells is a picture only where its fact and one fact of each cell group intersect, found by a search over start hours. Selection at a target takes the covering join from the latest fact, else the latest complete join, else the carried picture, else nothing, which is the named state "Reading hour T". Every picture carries the window of targets it stays the selection for; the window also breaks at the product's own change hours (a day count, revealed rows, a built table's stretch), and the lane paints at the window's start, so a stepped panel at 96 confirmed through 140 shows the day count of 124 at 124, and never past its confirmation: paused at 150 it keeps the day of 140. Each widget selects, prunes and paints at its own target, its pin or the hour plus its offset. A widget over several subscriptions shows their join: the latest hour, the earliest confirmation and the common window, and nothing new while they share no certified hour or window. The lane keeps the installed and pending pictures' facts, the picture selection would fall back to, and every fact a later selection can use; it releases the rest, cell versions included, and returns their bytes as credit.

The follow wire marks an answer whose rows ascend by their 128-bit key and carries a text-offset column, so a lane adopts a whole table as received and merges changed rows by galloping/binary key lookup onto persistent 8-row chunks (copying only touched chunks without mutating the base or retaining stale texts, serializing a flat wire answer lazily only when a main-thread field needs it). Ranked widgets (the Scoreboard and Measure Race) follow their configured top N as one answer; ranked windows over a longer ranking are deferred. Each byte has one charge owner: native charges every answer and panel record at twice the size its lane will hold, written in the record header, once for the lane's copy and once for the page's copy, so changed rows are charged at the whole table they land on, and it reserves that charge when the message is queued. Only the lane releases it, once no installed, offered-but-unanswered or carried picture holds the fact, and the page keeps one copy of each content from receipt, shared by queued, held and installed entries however many widgets show it; a merged table that outgrows its charge is recompacted. A record whose decode or merge fails is released when it is refused. The pull worker reports through push.localhost/credit the cumulative bytes the page has released in its session, so a retried report frees nothing twice; native keeps each session's cumulative charge, stamps every queued record with the session that produced it, and a restarted page retires the old session's queue and registrations together; the desktop relay is a plain queue of its session. A route with no follower is sent no clock command. A send waits for credit unless nothing is in flight or the clock has reached it; while the budget is full a reached message goes out past credit only if the page has reported releasing bytes since the last one that did, so a page that keeps working can always replace what it shows, bytes it keeps for display never block that, and a page that stops releasing is sent at most one; later passed hours merge behind it meanwhile. A send may pass a waiting message of another route but never one of its own, so lanes holding a picture can always receive its replacement. Only hours the clock has passed merge into one answer, so pressure never merges ahead of the clock. Past the byte budget nothing is refused or failed: the playhead builds no new read-ahead until bytes are released, and hours not read reach the page as waiting. The `.battleplan` format, the collector and the recorder do not change.

The clock publishes the hour first in every publish: the page revalidates installed pictures on a seek, installs the entries that arrived, flushes React in that task, and asks each lane for a frame at a speculative target (the hour plus a clamped frame step times the lane's bounded reply delay, never moving back while playing) or, on a pause, seek, speed change, rebind or focus, at the exact hour. Early-arriving entries wait in a bounded per-widget sorted queue so later speculative windows do not displace earlier upcoming ones. The lane keeps the newest speculative tick and applies each page message’s acknowledgements and refusals in arrival order. If an exact frame from the page is pending in the same seek, the lane serves the tick’s current hour exactly before drawing ahead. The page can then install its current picture while the next one waits for its hour. Each serve visits only widgets whose subscriptions, windows, motion or inspection changed, redates confirmation-only advances without repainting, and paints due widgets whole within its budget: widgets whose data changed first, least recently served first, then motion steps at any speed, skipping past an oversized widget when remaining budget can still serve a cheaper due widget; a widget whose painter reports motion stays due, and each step installs like any picture. An entry holds the widget, binding, entry id, h, c, window, seek and reset generation, mode, every surface and field or SAME naming the content id it keeps, and the inspection for the current key; content ids come from fact versions and exact equality of inputs, never a hash, and a drawn surface names new content exactly when its painter drew pixels; a mirror, a tooltip and a row list each carry their own. The page installs an entry only if its seek is current, its reset generation is not older, its binding is current, the widget is not named failed under that binding, the actual target lies inside its window, it is not older than the installed entry, and every SAME part names exactly what the page shows; otherwise it refuses it by name. Every offered entry ends acknowledged or refused: a displaced early entry and early entries retired by an exact request included, and a paused commit tells its lane at once. A failed transfer leaves "drawing failed" with the surfaces cleared. The widget shows the fact hour, displayed through the least of t, c and its painted window's end, and is dimmed when paused past either or bound to a stale binding. An entry that changes only dates tells date listeners, not install listeners.

A binding generation increments on any change to size, settings, scroll window, pinned hour, offset or subscription; a change of pin, offset or subscription revalidates the installed picture in that commit, so a widget showing 96 rebound to a pin at 20 shows "Reading hour 20". A rewind keeps a picture only where its confirmation and its painted window cover the new target, redated; a widget's first canvas and a change of painter keep the installed picture dimmed, while new canvases replacing drawn ones clear it, and a pipeline widget keeps its canvas across a remount of the component that shows it; a paused forward step keeps the picture actually shown, dimmed, and while paused a different picture that does not cover the target does not replace it; pausing and speed changes hide nothing. While paused a lane presents on its own when its selection at the last exact target changes, and the page commits it in one coalesced frame. Inspection and pointer hits are answered by the lane from the installed picture and shown only while they answer the current key. A dimmed picture is muted and busy: whatever shows it (a head product's root, a follow's element, a drawn panel, a table or the race) holds that element through `holdElement`, owned per reader, so `[data-held="stale"]` and `aria-busy` last while any reader is dim; inside a held element no row offers a tooltip, description or menu, no head offers its inspection, and the race withdraws its ranking and actions, so nothing of the hour it holds is read as current. A paused read that has not landed is reading, never outside the recording. A clock step tells a widget only when what it shows changes; dates go to date listeners. Every follow-clock request is numbered per route; a rejection or {available: false} fails the stream only while it is the route's latest command. A refused registration, a missing follow channel, a pipe failure, a lane failure and answers lost before registration are each named states that queued work cannot overwrite, a pipe or lane failure fails its stream on the page and in the lanes and holds through any rebind or remount until a new seek recovers the stream, a widget's own named failure holds until its subscription or canvases change, every followed consumer shows the reason, and no followed consumer has a request path at the moving head: head products, the Scoreboard, keyed series, MeasureRace and MeasureWidget show the named state instead. Pinned and historical reads stay.

Widgets drawn on the page install their model (the panel, kept while its structure is equal) and live values as fields; drawn panels install their values as page text written into their fields in the install task, which needs no geometry round trip and leaves nothing for an overlay to mix; tables and the arsenal race install lane bitmaps on bitmaprenderer canvases, the page never setting their backing size; the date face is page text. Earlier designs failed in ways this one makes impossible: a page mirror of worker readings dated by the worker's own hour, structure keys that let a canvas advance while text described the previous hour, worker-committed canvases reaching the compositor apart from the DOM (92% of captured frames ahead), entries matched to an exact publish discarding work forever, coverage inferred from leads, hourly fallbacks asking at the moving head, signature hashes that reused old pixels under new text, and merges ahead of the clock that starved every lane.

The differential test (`ui/src/dashboard/follow/differential.test.ts`) drives native answers through the lane split, the lanes and the page install under random seeks, pauses, steps, speed changes and channel delays; the emitter sends multi-row tables as whole rows and changed rows, lagged readings confirmed only through their limits, not-recorded spans with their reasons, and a lane failure; an oracle that reads only the synthetic recording checks every committed frame of every widget, a joined one included, for dates ahead of the target, values of the fact hour, reasons, certified coverage true of the recording, dim, blanks and named failures, each reported separately. A browser fixture (`ui/src/draw/tables/table.dom.test.ts`) runs a production table on real lanes and checks its pixels, mirror and inspection across a same-layout value change against a fresh table, and its limited and missing readings. The pipeline is designed to be correct with any number of countries in a recording, with no caps and costs that scale with what is followed and shown; widgets do not display 1,500 rows, so dense 1,500-row workloads are neither gates nor design drivers. A Node test (`ui/src/dashboard/follow/countries.test.ts`) plays a recording of 1,500 countries through the lanes and the page and checks that every widget is current, every value right and retained bytes bounded. The real-recording acceptance run on four cores at ×4 with integrated graphics is the performance gate.

Chromium's slowdown affects the page's main thread and leaves drawing workers at normal speed. The worker benchmark therefore accounts for the measured frame work and adds a proportional delay by occupying that worker. Rate one adds no delay. The fixture checks repeatable outcomes separately from measured frame timing.
