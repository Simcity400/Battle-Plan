# 0505. Measure, paint, and commit in one dashboard frame loop

The dashboard advances its playback clock, lands data in arrival order, measures layout, paints, commits React work, then runs after-frame tasks. A task for a later phase can join the current frame. The measure phase owns layout reads so position changes, canvas painting and React commits do not interleave with measurement. Geometry that depends on a frame's own commits, such as the cells of a drawn panel, is read once in the after phase, all reads before any write, so a frame lays out once however many commits it holds; geometry asked for by a commit between frames is read right after that commit. React work that frame listeners ask for commits in that frame's commit phase: a listener hands its state change to that phase (`inFrame`), because React does not commit an ordinary state change made outside the commit phase in that frame, so the frame would read geometry before it. A hidden page or a runtime without animation frames uses a timer, and the frame time step is bounded to avoid animation jumps after a stall. Offscreen widgets stop receiving frames and repaint once on return. Their clock methods keep stable identities.

The dashboard engine drives row entry, exit and gliding with the same curves used for table motion. Transform transitions on many individual elements caused the browser to restyle a compositor layer for every moving element. A single paint-phase task updates the styles instead. Retargeting starts from the value already drawn. Reduced motion snaps directly to the target.

Draw commands take layout coordinates, with source raster rectangles and image resolution in raster pixels. Retained paths bind their components to the chart axes that should move with the view and can be revealed at a specific clock position. A retained backend uploads only the changed raster columns. Worker clock anchors carry a generation to discard queued notices from an earlier anchor and a seek count to discard prepared steps from the old path. The host keeps moving canvases hidden during a rate change until the worker has painted under the new anchor. A drawn panel whose subscription, pinned hour or offset changes keeps its canvas. When the page text of the new binding is exact (a pinned hour, or a paused clock), the commit that changes it hides the canvas and shows that text; otherwise the old picture stays, dimmed and busy, until the worker presents the new binding. It never goes blank. Drawing workers post at their own frame rate whatever the page manages, so a notice about a surface reaches only that surface's host.

The playback clock publishes one page hour per frame, and everything on the page uses it. Its publish listeners run first in every publish, before anchor, frame and React listeners, and the follow connection places every subscription's readings there, at the published hour: nothing samples the clock's extrapolated position, so a reading never becomes current ahead of the hour the page shows, and a seek has replaced what it discards before any frame listener of the new position runs. Drawn pictures are timed by the shared anchor to the display frame that shows them, so the canvas and the published hour differ by at most that frame.

Followed readings reach the page through one ordered channel, the first drawing lane's, with one structure message in flight: until the page has taken it, the worker sends nothing more and builds the next message from its state when it sends it. Every reading carries the hour it is due, the hour its data was read and the hours its data covers. The page keeps, for each subscription, the readings it was sent, keyed by due hour, and shows the latest one due at its own hour, dated by the reading's own coverage and never past its own hour; a reading is dropped once a later one is due. The worker mirrors what the page holds and sends only the difference: readings that are new or changed, the coverage of readings the page holds and the due hours it dropped. It evicts only below the hour the page reports having consumed, so a worker that drains ahead of the page never takes away the reading the page still shows. A reading it drains past within one frame is still sent, and a reading it holds for the page is dated through the hour before its successor once the native stream has confirmed it. A coverage-only confirmation keeps a reading's due hour and goes as a coverage patch. Readings sent ahead are bounded to two frames of playback.

Panels stay in the drawing lanes. The worker computes each reading's structure with the product's own structure function (`readingStructure`, the same function the widget renders by), and a panel crosses to the page only when its structure differs from the last panel it sent; otherwise the reading names the panel the page already holds and carries only its live values. The page decodes a panel once per structure, React re-renders only when the structure changes, live values reach their readers each reading, and coverage advances are delivered to live readers as a dated update that changes no structure. A widget supplies its identity fields, such as a source, branch, assignment or episode, by putting them in its structure function; no structure includes the hour it was read. Drawn values, tooltips and accessibility text come from the lane: inspection asks the lane that paints the surface, which returns the texts and live values it painted and the date of that picture, or nothing when it presents nothing, in which case the page shows no tooltip; a focused or hovered field is inspected again when its lane presents a new picture. Products the worker has no structure for cross whole and are decoded on the page. Computing render models for every widget in the worker, as was considered, would have copied each widget's rendering into the worker before the widgets are redesigned; the structure function is already the contract that decides what React renders, so keeping the panel of each structure gives the same page cost without a second renderer. Measured in the Node probe (`ui/src/draw/followMessages.probe.ts`) with 114 subscriptions of 128-country arsenal panels changing every day at 1,440 h/s and 60 frames/s, unthrottled: each frame carries 114 readings and no panel bytes, 13 KiB, posted and received in 0.24 ms at p50 and 0.32 ms at p95, and landed and placed in the page store in 0.13 ms at p50 and 0.28 ms at p95; the first message after a seek holds 342 readings, 4.0 MiB, in 2.6 ms. The cost moves to the first lane, which validates each new panel and computes its structure: 6.3 ms a frame at p50 and 12 ms at p95 for 114 distinct subscriptions. Widgets with the same query share one subscription, so a page of copies pays this once per distinct query. Before, the page decoded every new panel to compute its structure, 7 to 8 ms a frame unthrottled and 28 to 32 ms on the weak tier.

A seek, a pause, a paused step and a stream failure start a new epoch for the branch; the worker learns it in the same ordered message that tells it to forget its copy, and the page takes messages of its current epoch only. A backward seek discards what the page showed. A forward seek, a pause and a paused step carry it: until a reading of the new epoch is due, the page keeps showing the carried reading, as current when it covers the hour or the clock is playing, and held when the clock is paused past what it covers. Held content is kept apart from current content, and every drawn host shows it dimmed and busy, withholding hover, inspection, tooltips and menus, until a covering reading lands, which a coverage patch alone can do; resuming shows it as current again with no new native reading. Pausing never hides a picture: only a speed change while playing, a backward seek, a rebinding to an exact text, or a failure releases one. Tables follow the same rule as panels and races: a table the worker cannot paint at the paused hour keeps its pixels and reports that it waits. A pinned rebinding whose new hour is not read yet keeps the previous reply, held, until the new one lands. A follow failure is terminal for its epoch on both sides: the worker takes nothing more of that stream until the next seek, and every head-product widget and the scoreboard show the failure by name, with no switch to hourly requests, until a reading of a later epoch lands. A surface's own failure is reported by its surface id, reaches only its host and fails any picture audit running; an uncaught worker error fails the page and the audit. An hour outside a track's branch shows the same outside-the-recording state in every head widget.

The differential test (`ui/src/dashboard/follow/store.test.ts`) drives the production connection, page store and worker readings through random seeks, pauses, steps, resumes, failures, late and early native readings and held channel messages, and checks after every clock publish and every delivery that each subscription's rendered model (structure, values, date, held or current, empty, failed) equals what a direct read of the native readings gives at the page's own hour, computed without any production code. The page may show such a read up to three frames old, with the channel holding a message at most one frame; nothing else is accepted.

Earlier designs failed in ways this one makes impossible. Version stamps made where data was queued described a packet or a route rather than what the worker held. Replacing a subscription's whole message showed the worker's reading of its own, later, hour and resent every native lead. Each subscription sampling the clock's position, and handling a seek after frame listeners, let a reading be current ahead of the page's hour and showed a discarded picture for one frame. Evicting by the worker's own hour took away the reading the page still showed when the worker drained a frame ahead. A pause that forgot the page's readings blanked the picture and needed a new native reading to resume. Decoding every panel on the page to learn its structure cost more than a frame on the weak tier.

At integral playback step sizes the worker uses the first display frame after the native step becomes eligible. Refresh-rate measurements use short animation-frame intervals so occasional dropped frames do not determine the display period. Workers share the dashboard's timing curves without starting a second dashboard frame loop.

Chromium's slowdown affects the page's main thread and leaves drawing workers at normal speed. The worker benchmark therefore accounts for the measured frame work and adds a proportional delay by occupying that worker. Rate one adds no delay. The fixture checks repeatable outcomes separately from measured frame timing.
