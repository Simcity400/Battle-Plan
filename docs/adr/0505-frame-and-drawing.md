# 0505. Measure, paint, and commit in one dashboard frame loop

The dashboard advances its playback clock, lands data in arrival order, measures layout, paints, commits React work, then runs after-frame tasks. A task for a later phase can join the current frame. The measure phase owns layout reads so position changes, canvas painting and React commits do not interleave with measurement. Geometry that depends on a frame's own commits, such as the cells of a drawn panel, is read once in the after phase, all reads before any write, so a frame lays out once however many commits it holds; geometry asked for by a commit between frames is read right after that commit. React work that frame listeners ask for commits in that frame's commit phase: a listener hands its state change to that phase (`inFrame`), because React does not commit an ordinary state change made outside the commit phase in that frame, so the frame would read geometry before it. A hidden page or a runtime without animation frames uses a timer, and the frame time step is bounded to avoid animation jumps after a stall. Offscreen widgets stop receiving frames and repaint once on return. Their clock methods keep stable identities.

The dashboard engine drives row entry, exit and gliding with the same curves used for table motion. Transform transitions on many individual elements caused the browser to restyle a compositor layer for every moving element. A single paint-phase task updates the styles instead. Retargeting starts from the value already drawn. Reduced motion snaps directly to the target.

Draw commands take layout coordinates, with source raster rectangles and image resolution in raster pixels. Retained paths bind their components to the chart axes that should move with the view and can be revealed at a specific clock position. A retained backend uploads only the changed raster columns. Worker clock anchors carry a generation to discard queued notices from an earlier anchor and a seek count to discard prepared steps from the old path. The host keeps moving canvases hidden during a rate change until the worker has painted under the new anchor. A drawn panel whose subscription, pinned hour or offset changes keeps its canvas. When the page text of the new binding is exact (a pinned hour, or a paused clock), the commit that changes it hides the canvas and shows that text; otherwise the old picture stays, dimmed and busy, until the worker presents the new binding. It never goes blank. Drawing workers post at their own frame rate whatever the page manages, so a notice about a surface reaches only that surface's host, and a surface's failure fails only that surface and any picture audit running when it happens; a page-wide failure reaches every host.

Followed readings reach the page through one ordered channel, the first drawing lane's, with one structure message in flight: until the page has taken it, the worker sends nothing more and builds the next message from its state when it sends it. Every reading carries the hour it is due, the hour its data was read and the hours its data covers. The page keeps, for each subscription, the readings it was sent, keyed by due hour, and shows the latest one due at its own hour: a reading the worker drained ahead of the page waits for its hour, and the page dates what it shows by the reading's own coverage, never past its own hour. The worker keeps an exact copy of what the page holds and sends only the difference: readings that are new or changed, the coverage of readings the page already holds, the due hours it dropped and the hour before which nothing is needed. A value that changes under an unchanged structure is a changed reading, so nothing the page renders freezes. Readings sent ahead are bounded to two frames of playback, and panels cross as their encoded bytes, which the page decodes only when something reads them. Measured in a Node probe (`ui/src/draw/followMessages.probe.ts`) with 114 subscriptions of 128-country arsenal panels at 1,440 h/s and 60 frames/s: each frame sends 114 readings, 1.6 MiB, posted and received in 0.8 ms at p50 and 2.7 ms at p95; the first message after a seek holds 342 readings, 4.6 MiB, in 7 ms. Resending each subscription's reading with its 30 native leads as decoded objects, as before, was 119 MiB and 1.4 s. Decoding every new panel on the page takes 7 to 8 ms a frame at p50, paid only by what renders them.

Every forget of the page's readings (a seek, a pause, a paused step, a stream failure, a removal) starts a new epoch for that branch, which the worker learns in the same ordered message that tells it to forget its copy, and the page takes a message only of its current epoch and only once it has handled the clock change: a frame listener that runs before the anchor listener shows nothing. While paused, the page takes a reading as current only if its coverage includes the paused hour; otherwise it empties the entry and keeps the last landed panel apart, which drawn hosts show dimmed and busy, withholding hover, inspection, tooltips and menus, until a covering reading lands; on resume it shows the latest due reading again with no message from the worker. Everything a widget draws from a held reading is dimmed, its legend included. A request-backed head offers an asked reply of another hour only as held, and a refused ask of the paused hour is the head's own error, not a held reading to wait on. An hour outside a track's branch is outside the recording whatever the data source. Inspection asks the lane that paints the surface, which describes the picture it presents.

Earlier designs failed in ways this one makes impossible. Version stamps made where data was queued described a packet or a route rather than what the worker held, so two readings could share one or a stale one could outrank the current one. Replacing a subscription's whole message showed the worker's reading of its own, later, hour, froze values whose structure did not change, and resent every native lead each time. Resending paused readings on resume ordered them against leads by luck. A pause forgot the page's readings without changing the seek number, so a message built before it was taken after it.

At integral playback step sizes the worker uses the first display frame after the native step becomes eligible. Refresh-rate measurements use short animation-frame intervals so occasional dropped frames do not determine the display period. Workers share the dashboard's timing curves without starting a second dashboard frame loop.

Chromium's slowdown affects the page's main thread and leaves drawing workers at normal speed. The worker benchmark therefore accounts for the measured frame work and adds a proportional delay by occupying that worker. Rate one adds no delay. The fixture checks repeatable outcomes separately from measured frame timing.
