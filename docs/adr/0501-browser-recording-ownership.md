# Own browser recordings by page load

A browser page owns the recording sources it opens and the temporary imports it creates. Reserve an open before the first asynchronous validation so an in-flight open holds its import even if the page has gone. End the reservation exactly once. A late successful source open from a departed page goes straight to native release. Keep knowledge of departed pages for the server lifetime so this also applies to an open that returns after navigation. Wait for the page, its opens, and every source from its import to be gone before unlinking the import. [Browser recording bridge](../../ui/browserBridge.ts)

Release and page-departure notifications bypass the browser request budget so a full queue cannot strand a lease. Send an empty summaries request as a barrier after releases because the native bridge handles these commands in input order. Deletion may still meet an open Windows file handle while prior work settles, so the import cleanup retries. Shutdown waits for the bridge to close before deleting this server's import directory. A new server can clear dead servers' directories because each directory identifies its owning process. Child termination uses the owned child handle on Windows. [Browser recording bridge](../../ui/browserBridge.ts)

Resolve saved game and user folders before starting the child because those folders are launch arguments. Send applied changes to the running bridge and hold them for later launches. Read the replay-folder settings path at each use because the parity adapter sets its isolated `APPDATA` after imports. Match native service admission at 64 concurrent requests so a restored dashboard can load the same consumers in the browser and desktop. For map settings, reject a binary whose modification time precedes the checked map-settings source marker, so a known older binary is refused before sending the command.
