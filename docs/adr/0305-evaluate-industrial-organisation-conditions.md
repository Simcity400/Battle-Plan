# Evaluate industrial organisation conditions in their own scope

All industrial organisation triggers use the recorded instance and the definition from the recorded mod stack. A named instance uses its holder's roster order, while an identity predicate compares the definition token. A missing definition is a missing operand because replay cannot infer its conditions. The recorded persistent store is exact and per-instance. A missing key is known absent only after reading the whole store. A duplicate key is invalid. Built-ins take priority when reading a value, while existence queries inspect stored keys. Quoted token operands do not share the bare token's registry identity unless the native reader accepts that form.

Policy membership reads the allowed token list without evaluating policy conditions. The active-policy predicate compares the attached token independently, retaining the representation of no active policy. Assignment counts task slots, including retained empty ones. Trait queries find the first ordinary definition, excluding the initial trait. Completion also requires the recorded completed set to contain the token. The completed count requires distinct keys, with outer equality selecting the `value` block grammar and scalar greater or less selecting the integer reader. A missing threshold or a scope selector leaves the threshold at zero. Size has a scalar grammar only. Equipment types expand their groups and retain their group names, and research categories use the authored list. Those two comparisons fold case.

Trait availability checks definition existence, required parents and completed exclusions before visibility and availability. Both structural checks default on and may be disabled. A parent group succeeds when the count reaches its required value at the point the native loop checks, including its zero-count edge case. A trait's completion and the organisation's own conditions do not gate that trait query. Organisation row gates check availability before visibility, while the attachment quote's traits check visibility before availability. Treat an empty condition as true and evaluate each nonempty condition with a fresh organisation scope and owner scope, regardless of the caller's carried objects. An unresolved owner remains an unknown link. A later proved blocker can decide an ordinary unknown. A reached recursive condition that never returns instead refuses the enclosing composition because a later condition would not run.
