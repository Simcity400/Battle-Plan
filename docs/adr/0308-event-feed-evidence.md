# 0308. Present feed occurrences with their recorded evidence

`event-feed` pages the typed occurrences and derived rows from the declared feed log. `event-feed-span` adds coverage and events supplied by other product families. The code-only span request returns facet codes without opening those histories. The full request counts refused or incomplete reads from indexed summaries and gets a few examples through short pages. One read can mark coverage and refuse several script families. The reserved all-ones facet value raises no notice. Unread families are identified in the reply. The nuclear strike log is read directly when its category is requested.

An event has a display hour, a read hour and a naming hour. A live view can show it once it has been read. A ceased country keeps its last witnessed name. A guarantee is dated at its start only when both tags held from then to the recorded read. War and faction histories report inferred transitions only next to observed time. When a native war end covers the same pair at the transition hour or the hour before, it supplies the peace row. Distinguishing a declaration from a war join requires native evidence. A subject relationship predating the timeline supplies no start row. A project completion retains its game date and the earliest read that witnessed it.

The recorder writes each script occurrence's continuation link. Event and decision cards use that link and the opener's read-hour facet to retrieve continuing rows in stream order. A continuation with no witnessed opener gets its own card. The recorded decision costs are the proven fixed5 balance changes, with spending represented by a negative amount. Optional operands distinguish missing reads from a recorded absence. Native roles and scope references require the link and holder witnessed at the naming hour, with the recorded identity guarding a reused reference.

A scoped request matches actor, target or joining ally at the event's naming hour. Each run gets one index covering all three roles, warmed when opening the recording. A simultaneous request shares the pass. Counts and page ordinals use admitted rows on the declared log's absolute bin grid. The naming cache holds forward readers stopped at known hours of the same run. A reply takes the latest at or before its first hour and advances through its occurrences in chronological order while retaining the requested output order. Keeping at most four sets bounds their memory and saves repeated restores for nearby pages.

Presentation expands event text from the recorded content and the occurrence's scope operands. A missing value in scripted text is represented by U+FFFC and its reason, so the frontend can identify each unavailable token. A decision title uses its owner's scope and the recorded FROM target, which links to itself in this title scope. Recorded snapshots cannot establish an effect's execution-time world. Effect descriptions therefore use only the recorded operands. Native cause descriptions retain the recorded operation, its enclosing operation and relevant operands without inventing unobserved causes.

Nuclear strikes report the impact before authored drop effects. A part with an incomplete read supplies no total. The supported totals convert the stored building, war support and equipment units once, and count wing crews with manpower losses. Attackers and targets are linked at the impact hour. A civil-war outcome, separately, can use a native annexation observed in its resolution route.
