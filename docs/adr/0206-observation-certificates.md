# 0206. Carry collector rows only while writers are observed

The collector uses writer notifications to decide when a complete earlier read can be carried into the current hour. The guard starts before the call and marks its return on drop. This gives the reader a way to detect in-flight writes without allocating on the game thread. The hourly boundary runs before captures. A load, continuity gap or recovery starts an epoch, so certificates from before it expire. A running writer, unavailable observation or owner that cannot be named prevents reuse at the affected scope. Capacity is prepared and retired off the game thread using the latest completed walk. The first table can be installed immediately. Later growth waits for an invalidating hour so it cannot drop a certificate still in use.

Families depend on every patch owner that can write the values they cover. A forwarding family enables observation after its patches are installed and disables it before removing them. A shared publication round checks and changes one family's sites together. A thread in any of its sites or taps holds the family back. Local safety contracts define when the retained patch and watch storage can be released.

An unrecognised executable raises a warning. A piece that depends on a native layout must be admitted by the located executable before using it, and each game site verifies before observation. An unavailable piece is reported by name. Status carries the withheld entries for executable tables, game sites and capture pieces.

The railway domain covers cooldowns, selected building inputs and edges. The daily countdown marks the reserved province-zero entry because province zero cannot hold rail information. The reader then includes the provinces on both the previous and current cooldown lists. The setter and constructor use the signed province argument, while a rail object names its province through its definition. Manager lifecycle or load writers can change information without naming a slot and force a new epoch. The building family forwards status changes. A province status marks its railway slot, while a state status has no rail building. An unlocatable writer makes the reader refresh all affected rows. Map editing disables carry for the attachment.

The territory domain uses separate marks for state rows, province rows, state writes that reach their province rows, and forwarded state modifier writes. The raid observer forwards modifier rebuilds and destruction because the affected state contributes to province bunker values. Each set has one consumer. A province read consumes both associated sets even if one refuses, so the other does not retain already-consumed marks. The province capture also hands changes to the area observer. The building observer forwards state and province writes and poisons carry when entering the map editor. Without an attributable building status it invalidates both scopes. A zero or unreadable object ID leaves that object unnamed. Optional scripted writers are installed only when a consumer requests their rows.

Roster and scientist observers use whole-domain tokens because their readers carry a complete walk. The roster requires manager construction and identity-repair forwarders in addition to its own writer sites. Research inputs and the role census share those observed scientist boundaries. Tests inject isolated observation domains because independent tests must not share the production token. Unit leader and trait readers instead certify individual leaders. Lifetime forwards invalidate entries before a reused address can inherit a prior leader's rows. Trait changes reach the naval modifier recalculation tail, and load invalidation covers direct writes. Retreat bans follow the same lifetime policy and rely on the naval family's modifier recalculation and HQ scaling forwards. The worker acquires the held commander store or starts empty. It sorts the pending certificates so fresh results can be matched by commander. Capture republishes that store only after a complete walk and forgets leaders it no longer visits or cannot read.

The war reader can carry fixed relation fields when all participating domains are quiet. Combat settlement updates casualty counters independently, so the reader refreshes those every hour. Relation, opinion and country-input observers forward writes to the war set. The participation owner registers before capture admission and withdraws before releasing its state. Shared hook owners retain those callbacks through native quiescence, and notifications never allocate or wait. Participation observes each exact status or diplomacy root before and after its writer under the same notification. War-goal watches use aligned keys so dense country identifiers map to distinct registry inputs. The daily diplomacy forwarder watches the same diplomacy receiver through expiry, which can delete an entry before progress is read. The goal observer filters for justification activity, while an unknown activity type or unreadable owner is treated conservatively.

Air-wing equipment watches identify equipment pools. The loss writer belongs to the destruction family, which forwards every relevant call. Both families must be enabled before equipment rows can be carried. Inline flags have their own receivers so they do not invalidate equipment certificates. First resolution of a raid and reads before a watch table is available use the quiet domain. The wing floor accounts for the pool, stop flag, coverage flag, raid reference, live raid and incoming destination. Its completed hour totals all split-part counts and only updates sizing after walking the whole census. An existing base patch owner forwards the wing preference's publication and split return, so workers can refresh only new or invalidated one-byte bindings. Their observer side retires prepared entries without walking the wing population. Division career and medal watches share lifetime witnesses across the army and ship-model observers. The consumer takes the officer, career, history-root and medal receivers the writers marked. A prepared range can reuse a checked watch slot. The ordered acquisition still admits cold receivers and handles full-table accounting.

## Callback and retirement contracts

The callback macros in `rail_changes`, `roster_changes`, `territory_changes`, `unit_leader_changes` and `wing_changes` forward up to four integer or pointer arguments and return the original value in full. The guard remains open throughout the native call. Each family uses its receiver description to choose the words to observe. `rail_changes::target` and `territory_changes::object_id` use guarded live reads on the calling thread while the receiver is still available.

The arguments that identify each affected object are fixed at the native boundary.

| Family | Wrapper arguments in call order |
| --- | --- |
| Railway | `set_province_on_cooldown(manager, province, ticks)`, `update_cooldowns(manager)`, `set_railway(info, neighbour, level)`, `construct_info(info, province)`, `destroy_info(info, flags)`, `read_info(info, reader, token)`, `construct_manager(manager)`, `destroy_manager(manager, flags)`, `read_manager(manager, reader, token)` |
| Roster | `roster_push(array, unique_ptr)`, `roster_clear(array)`, `scientist_build(out, character, definition, unused)`, `scientist_attach(character)`, `scientist_clear(character)`, `scientist_trait_add(scientist, trait)`, `scientist_trait_remove(scientist, trait)`, `scientist_trait_reset(scientist, tokens)` |
| Territory | `province_controller(province, tag, flag, flag)`, `victory_points(province, value)`, `read_province(province, reader, …)`, `insert_border_conflict(state, combat)`, `erase_border_conflict(state, combat)`, `rebuild_owner_areas()`, `initialize_provinces(state)`, `state_owner_entry(state, tag, flag, flag)`, `state_controller(state, tag, flag, flag)`, `reset_state(state)`, `read_state(state, reader, token)`, `state_name_effect(effect, scope)`, cached controller grouping `(state, optional change result)`, contested owner insert and erase `(state, tag)` |
| Unit leader | The first argument names the leader, except at exile sites, where it is unrelated and the notification invalidates broadly. |
| Air wing | `add_airplanes(wing, variant, count, …)`, `add_equipment_pool(wing, pool, …)`, `move_airplanes(source, destination, count)`, `subtract_equipment_pool(wing, pool)`, `destroy_wing(wing)` |

`state_owner_entry` retains the native caller's return address so the event feed can assign state-transfer provenance. The wing `call_site!` wrappers cover capacity trimming and daily return. They receive `(pool, variant, amount)`, call the authenticated subtraction function, and continue after the original call site through its relay. `SUBTRACT` retains that native target.

`rail_changes::Hooks::drop`, `territory_changes::Hooks::drop`, `unit_leader_changes::Hooks::drop` and `wing_changes::Hooks::drop` release their registry storage only when hooks never became live or after restoration and the last capture and callback have drained. Rail must also restore the building family's forwards before dropping the hooks. The naval tree forwarders quiesce and are dropped before the unit leader registry. `roster_changes::Hooks::drop` has no table to free and uses `release` to advance its epochs once the restored hooks have drained. The release entries for retreat bans, unit history and unit leader traits likewise require the owning and forwarding callbacks to be quiescent.
