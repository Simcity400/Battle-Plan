# 0103. Scope retained daily observations to complete acquisitions

Character residual experience is retained across rotating capture jobs. The cache key comprises the role address, character and full leader ID, so a replacement at the same address cannot inherit the former leader's experience. Fresh and consecutive acquisitions may keep ordinary writer certificates. Returning from held daily samples revokes those certificates, since off-slot rows can hold older experience beneath a current writer witness. A load, failed time boundary or spare store starts without a certificate, including when the refresh request never reaches a worker.

The experience cache appends an unsorted tail of current puts and sorts once during settlement, keeping the most recent value for each key. Cache growth is advisory. A failed reserve does not discard a value already acquired and an uncached role will read fresh. A completed fresh prepared read can supply experience bytes without calling the unit-copy function again, since it has the same authenticated identities and field geometry as the walk that prepared it.

Land-combat loss capture shares the land-combat census. It retains daily observer rows in acquisition state, so a new frame can still use the latest complete acquisition. Fresh work revokes eligibility before dispatch on a required refresh, even when the dispatch is refused. Beginning acquisition takes the previous census so abandoning that acquisition also loses its carry. An owned capture completes before the game resumes. Side pools grow from authenticated loss-plan header demand, outside the shared capacity lock. Recycled allocations can be reused after their witness is revoked.

The combat walk checks exact per-variant membership and amounts. Equal entry counts and totals cannot certify individual amounts. Daily observers keep a visit-order cursor for the common unchanged traversal and a separate unique-key order for fallback. Membership is visited every hour so new entries acquire their first value. The capture's combat progress operand is the full combat handle. Playback derives progress and direction from LandCombats, Divisions and DivisionMovement. The tests use synthetic memory through the live read path, serialize the shared carry fixture, and start each test without inherited rows. The scale fixture uses complete side pools, allows changing its synthetic population, and times only acquisition.
