# Prepare replay deltas ahead of the frame

A lane holds the chosen columns of one table at one run's playback head. Seeking starts from the last applicable restore and replays to the chosen hour. Fetching verifies, decompresses, and opens chained parts off the step path. Stepping uses only the parts supplied, reports a stall if they end early, and hands retired cursors to another thread to release. It stops at a packed block boundary for slot renumbering. Dated playback queues share a payload budget. Recording pages come from the format-12 envelope, whose version is separate from the recording's row format. Older recording columns the lane did not read remain unrecorded. Opaque cells decode at the recording's row format. A damaged run directory leaves that run unavailable by name. Opening a span begins far enough back to include every table's prerequisite restore.

A step carries owned changes to its readers. They apply deletes, inserts, cell writes, and then slot renumbering. The cell positions use the slots before renumbering. Cell widths match held values, except staging can use eight bytes per numeric cell before packing them. Missing and unrecorded cells keep separate ascending indices and preserve their positions in the packed values. Numbers and text identifiers are little-endian; signed numbers are extended on read. Lists use preceding and current ends to locate their bytes. The row key is included when declared. A reset supplies no row changes; a reader with a rebuilt state swaps it in, and a reader with no supplied state keeps its own.

A passing lane copies only rows born and gone during the step, with their values at their last live hour and in birth order. Existing rows are identified by one live bit per slot. Multiple lives at the same slot are paired with their own births in order. The optional per-hour change sets share the step's single walk and contain that hour's lives and cell values. They leave text, status, renumbering, and passing rows to the containing step. A transient status departure is reported even if the latest state returns to its original status before the step ends.

At a continuous piece boundary, state-table changes compare rows by slot and key and write text references afresh because a new run numbers its strings again. A reader receives the new run's strings. Log tables reset at the boundary because their ordinals belong to the old run. Within a run, a log retains the total appended ordinal and the current live set. It drops empty words at the ends and compacts empty interior words together to avoid moving words on each forget. The space tracks the rows still listed. Output reports appends first in ordinal order and forgets afterward within each hour. Seeking restores the prior live set, then advances through chained parts. Demand reads walk through the part with the largest requested ordinal in each relevant block, and refuse ordinals outside the run. Unsupported log events are named. The event match stays exhaustive so a new variant cannot disappear into a fallback.

The local playback clock holds at a sought hour until the reset for that seek is shown. It starts from the frame that first shows the reset, and applies pending pause and speed changes from then. A stale reset changes nothing. Page anchors convert to the native monotonic clock, allowing small message reordering; a page reload uses a new origin.
