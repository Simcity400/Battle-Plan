# 0207. Carry ship model rows only from complete ordered observations

Ship models share the authenticated map census, then acquire details over contiguous ranges in native roster order. The family retains the first range and lends additional ranges to workers when the live census justifies dispatch. Size each part for the widest range it can receive from observed demand. A worker that cannot admit or return its assigned range makes the family unavailable. Join completed parts in census order so the earliest failure keeps its place. Apply census truncation once for the family. No part restarts live acquisition or retains callback-scoped pointers after its range settles.

Each ship's held record is keyed by native identity and task force. Its observation certificate covers the ship, medal store and carrier base, with an absent receiver represented explicitly. Slot hints are valid only after receiver and epoch checks. The active writers can run on either the game thread or hourly workers. Unobserved, refused, running or invalidated writers cannot certify state. The per-range store moves owned read boxes forward, looks up census positions first and falls back to a pointer index if entries reorder. Compact records allow a complete row to carry without reading its cold payload. A family that did not complete retains no certified range.

The current task-force terms must agree before a finished row carries. Observe doctrine with both the task-force and country naval-tree certificates, weather with the region and country certificates, the fleet leader with the binding and leader-tree certificates, and location inputs within the epoch in which they were read. The mine-exposure term selects the associated modifier array. Weather also depends on the applied night factor. These observations are taken before the reads they certify and reused once per task force in a range. A current failure wins over carried values. Independently, the refit observer certifies the carrier-capacity predicate; the replay's formation flags already hold the answer without a second wire field.

The design family supplies an independent capability for equipment variants. Retain it as a live stamp, validating before and after variant observation. An unwound writer or a bulk update with unknown identities invalidates that evidence. Share gathered variant bytes only when the pointer and every observed value agree. If a writer moved the ship's own certificate, reread and compare the object and modifier inputs before renewing it. Missing critical fields may hide a receiver or a payload, so missing evidence cannot certify carry. If the model inputs are still complete and equal but organisation inputs changed, keep the model and recompute current organisation through the original arithmetic. Carrier bases require a current read. Hull tuple and definition ordinals are independently observed, so their field-local failures can recover. Current fixed-source model suffixes are acquired independently of a core model refusal.

Each range retains its generation only when every finished row carries whole in the same published roster position with no duplicate. A complete family can then republish the table using all ranges' generations and the current split. The previous pooled buffer may still contain a certified row, in which case only its roster position needs updating. Do not certify an interrupted or partially acquired range. Diagnostics sample row, model-only, light-reader, fresh and revalidation paths separately. Counts measure logical accesses rather than hardware cache traffic, and the largest successful census sizes receiver storage without imposing a fixed country limit.

The observer forwards carrier-base destruction from its installed patch to the air-base owner. Install and retire hooks under shared family publication, preserving process-static forwarding storage while its owner can still notify. The original receives the native operands unchanged. Capture publishes owned observations only, while optional refusal aggregation is deferred to frame settlement.

## Safety contracts

- `ship_model_changes::Hooks::new` follows runtime build admission and requires the memory source and base to identify the authenticated executable in this process. The caller owns the sites exclusively and must restore the hooks and quiesce native calls before code release or unload. A failed site lookup leaves the family uninstalled so ShipModels reads ships afresh.
- `ship_model_changes::Hooks::drop` releases receiver watches and relays only if the hooks never became active or were removed and drained after the last capture. Keep the variant registry available for notifications from the separate design forwarder.
- `ship_model_changes::variant_capability_is_current` reconstructs a function pointer only when `VARIANT_VALIDATE` is nonzero. `variant_availability` is its sole writer and stores a `fn(u64) -> bool`.
- `ship_model_changes::forward` notifies the appropriate receiver and forwards the four original register arguments in RCX through R9, returning the original result in RAX. None of these writers takes stack arguments.
