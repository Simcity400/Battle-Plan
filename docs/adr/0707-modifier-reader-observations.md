# 0707. Separate raw modifier values from effective values

Raw accumulator values retain their original signed fixed-point representation and remain present even when a feature disables their effect. Effective lookup first follows the native key probes and checks eligibility, then reads the value and its selected clamp metadata only if needed. Absent keys never consult that metadata. A requested-key probe reads only the reached search keys and demanded value. An owned whole-array observation has a stronger contract and validates the full ordered suffix, even when every selected key has already been found. [Accumulator readers](../../crates/engine-native-parts/src/modifier_accumulator.rs)

An acquisition arena owns raw arrays until cleared. It retains one observation per exact address, including the first failure and complete prefix. That retains original failure order when a batched payload read passes an earlier invalid key. A writer certificate may supply an older complete array, but an observation already made in this pass wins. Arena growth occurs while its containing frame is off the acquisition threads. Effective lookups still use their own current metadata. [Accumulator arena](../../crates/engine-native-parts/src/modifier_accumulator.rs)

The owning caller authenticates each accumulator graph. Country and explicit-address paths can share a node only when their actual accumulator addresses agree. Each native entry is an unsigned definition key and a signed 64-bit fixed-point raw value. Native requested-key lookup uses the data pointer and signed count, ignoring reserved allocation capacity. A negative extent skips the search probes but still reaches the final dereference. A whole-array visitor gives consumers only the complete ordered prefix. Its batch callback can observe bytes acquired before semantic key validation. [Accumulator readers](../../crates/engine-native-parts/src/modifier_accumulator.rs)

Definitions distinguish registered rows by their stored table index and nonzero token. A default gap has neither. An inconsistent row is an unsupported layout. A definition snapshot or cached name resolution can serve while the table's data pointer and count remain equal, with closing validation for table changes. The native eligibility callback is accepted only when authenticated as the feature-flags reader. A null callback leaves selected features ineligible. A disabled key does not read the clamp flags. Pass-local metadata memoizes successful reads by module and key. A failed read can be observed afresh where the ordinary lookup would read it. [Modifier definitions](../../crates/engine-native-parts/src/modifier_definition.rs)

The registered rows preserve their lexical identity, exact name, postfix and optional substitution strings. The native table index casts the unsigned definition key to signed before indexing. A gap leaves those strings and its flags empty and uses the default all-bits category. A replacement registration retains the latest name, and only registered names are resolved through the current lexical dictionary. Sizing from native row and string headers gives the next provable allocation step. Short storage retains the completed row prefix and required demand. A header change invalidates the whole acquired walk. The preferred-tactic weighting factor comes from a signed 64-bit fixed-point global. [Modifier definitions](../../crates/engine-native-parts/src/modifier_definition.rs)

Breakdown trees preserve occurrence order and refuse ancestor cycles. A repeated child under a different path remains an occurrence. The full static source roster includes empty modifiers and stays independent of a cached tree's read outcome. The printed preorder reads stored labels only for nonzero leaves and keeps other label slots empty, with no depth or node cap invented by the recorder. Source names and printed labels have separate meanings. [Breakdown readers](../../crates/engine-native-politics/src/modifier_breakdown.rs)

Rebuilding clears the cached tree and applies each static source in roster order. Adding a source appends its occurrence and applies the same filtered modifier-addition rule. A source with children, a custom tooltip or any eligible entry contributes a clone. Newly created and cloned nodes have different depths. Playback reconstructs these trees from the retained roster names and recorded content, so collecting the roster does not read the live accumulator or invoke its getters. [Breakdown readers](../../crates/engine-native-politics/src/modifier_breakdown.rs)
