# 0310. Bound dashboard work through delivery

The native data service owns recording sources independently of window visibility. Bounded JSON responses cross the desktop pipe. Separate whole-branch scans and opens, interactive reads, query replies, and pages that replay recorded tables to their displayed rows' hours. Replay pages also use the shared Rayon pool, so their lane takes a smaller share. Within each lane pick the oldest job of the kind with the fewest jobs running. Lanes with more than two threads reserve one slot from saturation by a single kind. On queue pressure, evict canceled work before returning a retryable capacity error. Drop evicted jobs after releasing the queue lock. A loader performs idle cleanup without the queue lock before waiting, so freed job state can be returned without blocking another loader.

An admitted request keeps its cancellation token through work, serialization, and every fragment. Completed responses count against admission until the final fragment. Keep capacity rejections and pre-admission cancellation history bounded separately. Delivery holds no service lock, and the host discards a fragment it already received if the request cancels. If an open response cannot deliver its source lease, roll the lease back. A native map shares a source without a frontend lease. A rejected or unwound host callback stops admission and the loaders. Service workers request stop without locking the handle list or joining themselves. The owning caller joins them after cancellation.

Duplicate opens share a gate per path and revision while disk reads and optional cache inheritance stay off the global sources lock. Recheck the revision after opening, since a publication can race the initial check. Register an opening source for rebinding before its first bind and before handing it out. Recording work executes against the recording's own executable tables. A legacy recording with no fact packs can receive a separate revision from the existing verified fact-enrichment path. If proof from the configured installations is insufficient, the recording keeps its current identity and any unavailable facts stay withheld. With no current game folders, playback retains recorded facts and uses placeholders for unavailable artwork.

Capture the source's binding when admitting content-dependent work and keep that binding across its reads and reply. Compute replacement identities outside the configuration lock and publish the whole binding only if the configuration still agrees. A failed visual-mod lookup creates a distinct unavailable identity, so later recovery invalidates content caches. An installed or removed mod changes what a binding can mount, while a saved missing selection keeps its name. A committed configuration change owns its rebind catch-up even when its initiating request cancels. Source binding retirement cancels old ahead work. Save flips under the settings lock so they act on the current value. Read mount order from descriptors and report any later failure after the save as a presentation diagnostic.

Index recording histories at source open. Use background work for event-feed naming and scoping, and ledger coverage so later pages can resolve their operands without taking over the open path. Warming failures are reported by the reply that needs the result. First-window prefetch starts after the open is answered, resolves its own mount, and cancels with the admitted binding. Its weak source ownership lets an abandoned source go. Record changes to continuation choices as a new revision so clients reopen under the new selection.
