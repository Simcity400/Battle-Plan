# 0201. Certify receiver reuse only while writers are accounted for

The collector captures native fields without changing them. An observing writer records its receiver if one is known, and the original call completes under a guard that brackets the write. A registered receiver certificate pairs the epoch with its sequence. A whole-domain quiet token pairs the same epoch with its revision. A notification bumps its receiver sequence and the domain revision only on entry. The return drops the running count and can repeat a dirty mark, without a second sequence bump.

The running count and revision share a cache line isolated from read-mostly state so notifications avoid invalidating that state on every entry and return. One checked compare-and-swap updates the word. A count approaching its admitted limit or an exhausted revision makes the word permanently untrusted for the attachment before either field can wrap. An untrusted value never reports quiet or allows retirement. The active status for that case remains nonzero and small enough for callers to sum across families.

A certificate reads the sequence and verifies that the writer word is trusted and quiet. If a writer entered before the sequence read, the certificate includes its bump and must see completion or refuse. If it entered later, a subsequent certificate includes the bump or refuses while the writer is active. The same argument applies to the revision read with the count in one word. An unnamed writer invalidates the epoch at entry and return. A running-only guard temporarily blocks certificates without revoking them when a call makes no change. Its dependency stamp is for a hook's before-and-after check while it is the only writer. Acquisition still requires an ordinary quiet certificate.

Bounded probing counts refusals. Receivers may be dense identities or aligned pointers, so the hash retains every bit and probing is tested against both populations. Provisioning keeps room for receivers no longer live. A retaining registry holds them until invalidation. Capture registration occurs before the read it certifies. Passive range lookup avoids changing registration state or refusal counts, and its slot hint must still identify the same receiver in the installed table. Parallel ranges can register newly reached receivers and leave final full-table refusal accounting to ordered admission.

A marking registry also records one bit per watched slot for its single consumer. Dense IDs use `DirtySet` directly, since a hash lookup per receiver would cost roughly as much as reading the large population. The bitmap costs one word per 64 IDs before visiting the set bits. The worker swaps each word to zero after the boundary. A mark after its word was exchanged remains for the next take. If a mark is already set, its sequentially consistent load is enough because any later take consumes it and an earlier take would have cleared it. Entry and return marks bracket the native write, and publication requires a quiet matching epoch for the entire take. Because a take consumes marks, a failed or dropped capture invalidates the evidence for reuse. A named ID beyond bitmap capacity records growth demand and invalidates the epoch instead of silently dropping that write.

Off-thread code offers storage, and game-thread boundaries handle ordinary install or clear. Most replacement waits for an invalidating boundary because discarding old registrations or marks forces a full read. A first table or a dense bitmap outgrown by a newly marked ID can install earlier. Replacement and clear bracket state with epoch changes. Old storage moves through draining and retired states and is freed off the game thread after no writer can still hold it. The quiescent growth path for non-marking registries can preserve admitted sequences and the quiet token without native reads. It still retires or rejects storage outside the lease, and a rejected offer cannot prevent a retry for the same unmet demand. Enabling observation begins an epoch because disabled writes are not known.

Shared reload observation also has one patch owner for each command so all dependent baselines retire together. The forwarding receiver is installed or removed during attach or detach once callbacks are quiescent. Its absence costs a null check. The bridge preserves the original call's arguments and result.

`DirtySet::installed` and `WatchRegistry::table` borrow the published allocation. Consumers run after the boundary, and writers remain counted until they stop using it. At `boundary`, taking an offer from its atomic pointer transfers ownership to the installer. `DirtySet::offer` and `WatchRegistry::offer_slots` recover superseded unpublished allocations from the same offer slot. `collect` in both types recovers only allocations already drained and retired. Their `Drop` implementations have exclusive access and can use the full release path.

The worker growth tests own each synthetic registry on one thread. In `faction_goal_worker_growth_preserves_live_certificates_and_quiet_token`, the call to install growth owns the only read path and teardown follows the last query. The deliberate running guard in `faction_goal_worker_growth_waits_for_writers_and_never_takes_marking_storage` exercises the installer refusal while the synthetic registry remains owned by that thread.
