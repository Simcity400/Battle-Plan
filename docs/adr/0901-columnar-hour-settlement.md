# 0901. Settle each writer hour before publishing its events

The journal starts an hour with its dictionary appends, sample metadata and statuses. It applies typed changes the collector already certified, without comparing old values. Apply table sections before settling the hour and encoding its closing parts. If packing changes store slots, retain the collector's journal slots through a mapping. Persist these maps, each log's slot-to-ordinal entries, seen keys and refusal in the resume state. Derived tables belong to their producers. A collector section that names one is refused. Refusal strings take ids downward from the end of the dictionary, apart from upward journal appends.

The adapter decodes consecutive numeric data in fixed-size pieces, and it keeps complete presence words for optional data. It splits list data in row pieces after reading the encoded lengths, using more than its usual item limit only when a single cell needs it. Process inserts' column values only when rows were inserted to preserve column alignment. The scratch capacity used by a large read is discarded after the first hour of a run and at block boundaries, together with the store's hour-log scratch.

An entire log section is examined before applying any of its changes. A repeated key, any write to an earlier appended row, or a slot-width refusal withholds the offending table from that hour while other tables land. The refusal survives resume and later sections of that table are skipped. An inserted row receives its hour's final cells, including any same-hour fills or unrecorded marks. Key deltas are decoded one at a time as rows arrive. Deletions of journal slots translate to forgotten ordinals, and inserts are appended with new ordinals. A log view exposes that hour's appended rows and carries the log's status. At the next hour it starts empty again. Forgetting changes which ordinals are listed while preserving the recorded rows at their original locations. Forget requests may arrive in any order. Emit them in ordinal order after appends, and verify an entire forget range before changing it. A log's summary normally counts the hour's appended rows including rows forgotten in that hour. During the run's first hour it instead counts rows still live at the end.

In the run-first hour all live rows were born that hour. Consumers read them directly and the writer skips a per-row hour log. Views and summaries still match an ordinary hour, including the final live rows of partially read tables. Later hours order the log by slot and retain requested before-images. The first before-image of an older cell is its pre-hour value. The dropped-row log captures cells when the deletion found them. A new row starts with every cell unrecorded unless its producer promises every column. Settle finds every unwritten cell before adding it to the written-cell index, so later searches use the same order. The first hour counts cells not supplied, excluding explicitly unrecorded ones. Closing block parts uses the settled state and allows the hour log to be released first. Finishing a run closes its last short block.

A producer can temporarily take one state table while continuing to read the others. During the lend, new rows occupy real free slots and changes to older rows wait for landing. A view during the lend answers earlier rows as at the start of the hour and new rows as written. Reject a second set of the same key. A pending delete defers to a same-hour set. Undo drops newly inserted rows and restores the prior slot count. Landing gives the same encoder and hour log as setting rows by key through the regular entry point, then applying the remaining deletes. Swap keys, cells, and recording bits together when reordering the new rows. Logs and tables retaining their last complete read cannot be lent.
