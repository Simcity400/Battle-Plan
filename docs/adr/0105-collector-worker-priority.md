# 0105. Keep frame pressure off the game thread

The callback publishes pressure and tick placement through atomic words and wakes one owned reconciler. It never applies Windows priority or CPU-set changes. Collector workers register their own handles after normal-priority initialization. Decode pressure and spool-side pressure can choose different priorities between ticks. Boosts run within a bounded time budget and must return to normal before the rest timer begins. Starting a new tick clears the previous boost deadline.

Copy-only workers stay off the physical core containing the game thread during its tick, including that core's sibling logical processors. They normally run at idle priority during that interval. A tick with at most one free frame raises them to normal priority while preserving the CPU-set selection. Sizing reads live game memory, so it waits out the tick at its own priority. Unknown placement, an unsupported processor group, missing topology, and a machine with no other core leave the worker unconfined. The first topology lookup runs off the game thread. The reconciler uses a fixed group-zero table indexed by logical processor and core, with one immutable alternate selection per core.

The reconciler makes one attempt at its gate per pass, reconciles only retained collector-owned handles, and bounds native writes per handle. It clears pending work before applying its snapshot and publishes the applied pressure before validating desired pressure again. An update racing the final validation either prevents completion or wakes a later pass. The idle timer also recovers from a failed event wakeup. A CPU-set reselection that fails can leave the earlier selection active, so teardown and tick exit still owe a clear. A worker's own selection used by `AwayFromGame` retries on a placement change and reports refusals through the status counter.

Waits use a retained event and an owned timer. The worker releases them after joining, and their ownership is independent of the game. `GetSystemCpuSetInformation` fills an aligned buffer whose records declare their step size. The reconciler reads the CPU-set union arm only for records of that type and uses the Windows limit of 64 logical processors per processor group.

Hour timing diagnostics keep an allocation-free span log while capture jobs run. A span identifies the worker and its role or serial substage. The live log uses performance-counter ticks and the status snapshot uses nanoseconds. A new hour starts after the previous jobs finish. Status keeps the latest forced hour and the slowest other hour, and a concurrent status read can cause a sample to be skipped. Status sorts the owned snapshot in place under the allocation guard to keep the callback independent of serialization.
