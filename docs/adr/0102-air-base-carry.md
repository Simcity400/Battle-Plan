# Carry air-base reads only while their witnesses still hold

The manager, the ordinary, rocket and gun slot headers, and stateless bases are read every hour. A state slot array's words can carry when both its header and membership certificate match the last fresh read. A state base's row carries when its address, array and slot still identify the base and its handle certificate matches. Capacity refresh invalidates the row, a creator invalidates membership and destruction invalidates both. A moved header or a new base is read even if the other entries remain eligible to carry.

The same worker loan holds each state base's registration subtree as the spans and bytes consumed by its replay walk. Carry also requires matching the slot-scan mode and resolving each nonzero container country's link to its recorded slot again. The link reads themselves are excluded from the saved spans. A registered pool must name its base so the observer can attribute its writers. If it names another base or none, acquire the subtree afresh. Dense scans must prove that the occupied slots are distinct. The complete-slot fallback preserves repeats. Host bases read afresh because their carrier fuel changes each hour.

The snapshot excludes changing bytes that do not contribute to the result. It retains the container country and capacity and the wing's identity, while leaving hourly sortie and fuel operands to the host observer and leaving selection state to its own readers. Failed required spans or missing certificates make a read ineligible to carry. A failed optional summary stays missing until a writer changes the certificate. This preserves the observed absence while avoiding speculative reads.

On the first pass the store still counts state bases visited for watch sizing, even when no watch table is available. Both stores keep only entries visited by the latest complete pass. An incomplete pass invalidates the hold, and marking the store forgotten requires no game-thread allocation. The workers account for retained memory when finishing or growing independent state inputs, so the game thread reads the cached total. Cache allocation is advisory. Entries that cannot be held are read again next hour.

Each accepted registration segment receives a process-unique identity. A fresh read and an hour carrying that same segment report the same identity to decode. When the current country links have been checked, decode can append the cached registration rows and wing handles, adjusting the per-base wing offsets to the destination. A changed or missing segment is walked, and any failure to index the reported segments causes a full walk of that pass. The decode cache keeps only the bases visited by its latest pass. The benchmark uses one synthetic host buffer and compares fresh reads, held segments and cached decode results at late-war and mod scale. Results distinguish fresh, fresh and held, and carried work so costs are attributed to the right path.
