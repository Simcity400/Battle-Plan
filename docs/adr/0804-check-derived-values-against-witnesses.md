# Check derived values against independent recording witnesses

The derivation check streams replay blocks and counts every mismatch while listing a bounded set of examples. Its content comparison requires every session to attest to the same recorded stack. Recordings of different stacks are checked separately. Tool build changes do not change that stack identity. The independent content-reader check initializes the game executable tables to validate the movement modifier keys, as the live save comparison does. Day/night checks compare only where the recorded weather gates and a nonzero slot establish that the native writer ran. The optional census reports changed rows and fields for each table. [Derivation command](../../crates/recorder-derived/src/derived.rs)

Some comparisons require captured diagnostic rows. Attack checks compare each witnessed scalar and terrain operand against the stat block and the terrain adjuster resolved by native database order. A mismatch on a carried row can expose an uncovered write, and common mismatches for one terrain can expose content resolution. Power balance compares witnessed description trees to the derivation from recorded sources and content modifiers, using bytes before the first NUL for modifier names. The naval hover check joins each occurrence as playback does and compares its identity and all trees with that occurrence's fresh read. A build without the diagnostic samples reports their absence separately from a mismatch. [Attack check](../../crates/recorder-derived/src/derived/attack.rs) · [Power balance check](../../crates/recorder-derived/src/derived/power_balance.rs) · [Naval tree check](../../crates/recorder-derived/src/derived/naval_trees.rs)

Temperature checks compare each hour's witnessed pass. An anchor's words and cursor can be independently checked when the preceding frame proves that a normal pass reached it. An unproven anchor remains a baseline for future checks without counting as a reproduction. [Temperature check](../../crates/recorder-derived/src/derived/temperature.rs)

Movement speed is observable as the progress added to a division that stays on the same path edge across consecutive hours. This comparison treats a stopped numerator as its own category and accepts an exact step clipped at the first-edge distance. Movement runs after other writers within the next update, so neither endpoint always holds the exact operands. The checker distinguishes a match with the later endpoint from a mismatch with both. Its progress classifications are diagnostic and do not fail otherwise valid content, and its fuel classification reuses the derived movement calculation so fuel is reported only when it actually changes movement speed. A transfer edge can also supply a speed without a panel row. [Movement check](../../crates/recorder-derived/src/derived/movement.rs)

## Live movement map load oracle

Playback rebuilds province neighbours and terrain from the recorded content. The separate load oracle reads the running game's province definitions once using a read-only process handle, after the game proves the mounts that establish the same content stack. An incomplete or misordered stack cannot establish parity. The oracle preserves native province and neighbour order and compares entry fields where both lists name the same neighbour at that position. An unavailable read fails the comparison rather than counting as a zero value. It is invoked explicitly, outside the timed capture path. Synthetic fixtures cover order preservation, unreadable memory and unclaimed map colors without opening the game. [Movement load oracle](../../crates/recorder-movement-oracle/src/movement_oracle.rs)
