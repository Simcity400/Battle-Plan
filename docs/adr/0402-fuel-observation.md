# 0402. Keep fuel status, applied awards, and required use separate

The status walk reads each authenticated canonical country's shared fuel root once for the status and consumer tables. Fuel quantities and lend-lease amounts use signed fixed15. Rates, gain and cost modifiers, and requested or received consumer lanes use signed fixed5. Preserve the native dormant value and its raw owner reference. The surrender target is optional and stays separate from fuel-update identity.

The fixed history ring contains one written entry per hourly update. Its cursor names the next slot to receive the pending entry, which is omitted from the sums. The status row contains current tank level alongside exact totals from the completed ring. The totals include gain, consumption, other debits and the received lanes. Summation is wide enough to accept an intermediate value outside the result type when the final total fits. An out-of-range final result withholds the row. Admission requires the expected native count and complete backing for every required span. The two tables can fail independently after their shared root is authenticated, and a later common failure preserves either table's first reported reason. When a failed consumer copy intervenes before the ring in a shared read, the reader can still copy and validate the ring on its own.

Applied receipts and debits come from observed bookkeeping entries during the actual update. Later rates and changes to the tank cannot reconstruct them. Copy signed fixed5 inputs before aggregate conversion, and preserve fixed15 applied debits. The conversion truncates toward zero and uses quotient and remainder terms to avoid an overflowing direct product. A zero native gain divisor uses the application's observed unsigned sentinel for oil demand. Source breakdown labels come from loaded content.

The beginning and settling reads can share a country witness only for the same authenticated world, hour, status and update invocation. When the witness does not apply, the reader checks the complete identity chain. Reusing reference-registry headers within one update still validates each recipient. Division, task-force, and air-container operands represent distinct recipients. An air-container receipt establishes no individual wing award. Unit names come from the stored name cache without invoking generation.

Required use is a current supply-rate observation. It preserves native roster occurrences, including repeated units and all naval missions. Workers may reuse packed inputs, native failures and already joined weather data inside one quiescent callback. None of that state crosses the callback boundary. Raw modifiers remain separate from eligibility and clamp decisions. Air owners use native signed references, including the reserved slot selected by zero. The air reader uses an engaged module cache when present and otherwise walks stored variants and modules without modifying the game. A selected missing country entry remains unavailable even where another native path legitimately skips work and returns zero. Off-hour length and header reads provide capacity hints, never captured values.

The weather context reads a manager only when a slot has a positive province occurrence and applies the threshold after the complete slot average. Scope-local indexing preserves failed packed contexts across reindexing. For air demand, the native signed shift selects the highest bit from a positive mission mask. A negative mask is withheld because that path does not terminate. Read base fuel before ace and owner modifiers and use one stored period sample before the weight is applied.

## Fuel status and award guard spans

`ccountry_fuel_status::VTABLE_RVA` names the primary fuel-state vtable. `fuel_awards::BEGIN` follows rate refresh and incoming lend-lease and reaches the pending-gain update. Its eight-byte span admits no interior branch. `END` follows completed awards and fixed15 debits before the pending and history clear, with an eight-byte load span followed by the original clear. `LAND` covers unrolled and residual stores. RAX gives the division and RDX the actual signed fixed5 receipt with parity rounding. The unwind chain ends in a handler-free body, and the return point of each five-byte patch stays in its entry. `NAVAL` is a handler-free leaf that takes task force and signed fixed5 receipt in RCX and RDX and preserves the original return. The `AIR` store admits a non-null container and receives base, container and receipt in RDI, RDX and RBX. Its seven-byte store ends before register restoration, and its five-byte return point remains within the handler-free body. `RESET` uses RSI for status and observes reset during initialization or country reuse even if a pointer and zero identity recur. The eight-byte span follows the handler-free prologue and admits no interior branch or return point. Its five-byte return uses the same unwind state.
