# One five-state value contract for every dashboard family

Every dashboard family renders values through a single discriminated union with five states: `known`, `zero`, `notRecorded` (carrying a non-empty reason), `notApplicable` (carrying a non-empty reason), and `partial` (carrying the measured value and a non-empty reason). Bare `null`, `undefined`, `NaN`, non-finite numbers, blank or whitespace-only scalar strings, and empty reasons are rejected by the TypeScript type and by a named runtime error (`InvalidFamilyValueError`) at the boundary where wire answers, live cells, or exact replies enter a family. Unread or unrecorded fields always emit `notRecorded`, never `notApplicable` (`notApplicable` is reserved for values that genuinely do not apply to the row).

Two adapters own conversion into this type: `valueFromWireCell` / `valueFromNamedAnswer` / `wireFloat` / `wireWhole` map followed wire cell states (`Value`, `Missing`, `Unrecorded`, `NoRow` and whole-answer `notRecorded`) while preserving exact `bigint` magnitudes and reasons; `valueFromNullable` and `valueFromRawBigInt` convert exact reply fields using the widget's explicit declaration of whether `null` means `notRecorded` or `notApplicable` and why.

Sorting treats `notRecorded` and `notApplicable` as last in both ascending and descending order. Measured values (`known`, `zero`, `partial`) compare by exact value (numeric or exact `bigint` without precision loss, or collated text) and break ties deterministically by primary display name A–Z (`Intl.Collator` with numeric order) and then stable row key, never by input array index.

One shared presentation specification renders all five states identically in DOM (`components/ValueState`) and on Canvas (`drawValueCanvas`), both reading `--hatch` and `--hatch-edge`: a known zero always draws `0` in foreground text (never `None`, never blank, never a dash); `notRecorded` draws a hatched swatch and muted `Not recorded` label; `notApplicable` draws a muted em-dash with no hatching; `partial` draws the value with a hatched tab and muted `partial` label. Screen-reader text carries full spoken reasons (`Not recorded: <reason>`, `Not applicable: <reason>`, `<value>, partial: <reason>`), while audit rows carry canonical type-tagged scalars (`str`, decimal `int` unifying `bigint` and integral finite `number` including `1e21`, and non-integral `num`), unrounded state, exact magnitude, `atLeast`, and reason (`canonicalAuditValue` and `canonicalAuditData`).
