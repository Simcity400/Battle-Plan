# Derive spending from covered publications

The power ledger attributes a payment to the canonical slot of its raw country at the hour the payment was read. An unresolved link keeps the explicit no-holder identity. Items are identified by typed operands, assigned an ordinal at their first payment and disambiguated when their length-delimited hashes collide. A charge distinguishes an unevaluated subtraction from a change that is not a payment. Daily upkeep, costs and deficits are merged by the native day. The totals preserve payment counts, balance changes and credits separately.

The first hour of a run exposes the existing game backlog. Its power changes and cost publications do not count toward spending or holds. Totals and open-day parts reflect the input coverage. If a required input is partial or missing, its named status propagates and the affected totals are withheld. Coverage is taken from the last linked raw country with a capture and is published per currency and hour. A payment requires a witness covering its epoch, event hour and currency at the read hour. A daily cost also needs a covered daily cost stream and a batch that reconciles with the recorded political application. A query uses an open part only when its currency has been covered since the day began.

`CountryPowerDaily` holds the latest daily application, so a replaced or deleted row closes the previous day using its retained cells. The latest observed daily costs of an open day are grouped by holder, application and item. A complete republication of today's batch replaces it: an open-day part of the same day and application that the latest batch no longer holds is withdrawn, while parts from power changes stay. A batch that only lost rows acts on the parts its application already holds, grouped as they were published: a part its remaining rows still pay exactly is kept, one they pay differently is rebuilt from them, and one they no longer pay is withdrawn. The application's remaining parts keep their coverage, and its holder counts as reconciled, only when a daily application read that hour matches the remaining sum. A country with no cost rows withdraws its batch only when a covered daily application read that hour records a zero cost; otherwise the missing rows are missing evidence and withdraw nothing. Parts do not name their raw country, so for a holder shared by several raw countries a part a deletion changes or drops is kept with an unknown amount and no coverage rather than rebuilt or withdrawn. The no-holder identity gathers every unlinked country and is never reconciled. An earlier day is settled at once. Positive daily costs count as payments, negative ones as credits, and costs without a matching application on the gains row as unmatched. A batch at or before the run's first hour is omitted. When a value would exceed its stored integer range, it remains unknown until the observation is rebuilt.

Covered command power allocations add a hold. Releases and refunds remove it, and an unattributable refund invalidates all of the holder's holds. Holds are carried while their capture stream remains continuous and reconciled against its allocated total. The recorder rebuilds the ledger indexes from their own tables on resume. The resume blob only keeps the last hour and the run's first hour.

Table layout is handled in one input module. Power changes come from rows written in the current hour, including available rows from a truncated read. A daily cost publication starts from a country with a cost row written or deleted in that hour and reads its batch in ordinal order, starting from zero.
