# 0706. Give ship observations explicit capture lifetimes

Model and organisation readers share the fixed fields of each ship and the task force and location it names. The census visits a task force's ships consecutively, so the gather keeps the latest task force and location. It reads the singleton once per capture. Each object's gather combines the exact spans required by the readers into one guarded call. The selected-object adapter also supports walks that construct a reader once and change which object it can serve. Its field list is sorted, disjoint and limited to spans of 32 bytes each.

A read wholly inside a copied span uses the gathered bytes. An exact read of the field at which the gather stopped repeats the failure without another native read. Partial overlaps, unread fields after that failure and reads that cross a span boundary go to the source. A scattered copy serves local spans and sends the live spans before the first failure in a single guarded call. Empty placeholders keep the source's completion counts aligned with the original span order. The earliest failure determines the copied prefix, including when one of the earlier live spans fails. Address overflow fails at its field. Record copies use the original source when no record intersects a gathered field.

A ship's pool entries and the fallback sprite's heap payload and terminator can be gathered after the fixed fields establish their spans. They use the same ordered failure rules. Larger pools and strings exceed the inline storage and use the direct reader. The selected variant is the first entry with the largest signed amount. Positive entries contribute variant flags independently of the selection, so an observed variant's flags remain relevant even if that occurrence cannot win. A recent-variant cache shares complete reads in one capture without displacing another variant still referenced by the current ship. Native pointers do not cross the recording boundary.

A held ship stores its own fixed fields and heap observations. The collector may serve them across hours only while the writer witness covers them. A moved certificate can be revalidated only if both observations copied every input they may serve, including the sprite terminator and the independent power suffix where used. Failed gathers are refreshed. Variant observations have their own keys and comparisons, separate from the ship bytes. A held row that only needs a variant check does not gather the ship, its task force or its location. Serving held variants requires a separate witness. Task force, location and singleton data otherwise come from the current hour. The task force's mine exposure and modifier accumulator enter the organisation calculation, and its attached headquarters list is cleared and refilled each hour.

The optional tie-break and power operands are read after the original model and maximum-organisation readers succeed within the same stopped census. The original model's sequence, failures and outputs are independent of these additions. The selected-source identity, token and definition are validated before serving the optional packet. The optional terms fail independently. The definition or database can withhold the ordinal without withholding unrelated operands. A consecutive repeat shares even a partial observation. A different or null source breaks that adjacency, including on rows that did not request the packet. Only complete packets are eligible for reuse after visiting a different source, and the cache resets at the next capture.

Live module count, upgrade and signed priority terms and the retained organisation marker can change without a different variant pointer. The daily variant table cannot supply them. Authenticating the selected definition requires checking its actual slot. The ordinary guard is widened only for the actual native null-definition singleton, with its identity and active state witnessed. Its reserved ordinal stays distinct from the first real equipment definition. A fault in an independently authenticated term remains absent. A nonship definition supplies known zero for the power operand. Definition-derived power terms may carry only while equipment reload and world-lifetime witnesses hold. Power cannot affect variant selection and is gathered only after a winner exists.

Ship name capture authenticates the ship first and copies the stored operands without running the name generator or refreshing its cache. The operands include a saved override even when the native name selection currently hides it.

Ship-refit work orders keep a separate registry identity. Their shared production fields are read through the generic production-line and equipment-line definitions.

The tests compare the gathered path with direct reads and sweep faults at the edges of each read. They also check the omission and reuse of shared objects, separately exercise failed fields and heap terminators, and verify that the next capture re-observes the same addresses. Organisation tests retain scalar rounding at each term and include repeated effect occurrences, distinct ship-owned operands, and shared task-force terms under changing classes and owners.
