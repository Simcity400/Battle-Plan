# 0402. Scope executable facts to the work that consumes them

Each executable table locates and verifies itself. A build the release does not recognise produces a warning, and failed parts are withheld by name. Within the auxiliary table, independent parts can still succeed. Decoders with independent inputs run in parallel, and a decoder panic on an unexpected image withholds its part. A caller that cannot continue past a withheld view reports that refusal at the product or content boundary.

Live collector and recorder processes can set one installation as their process default. Playback supplies each recording's own decoded facts through the job context, including workers that inherit it. If a replay has no facts in scope, its readers report the missing tables by name. A tool that works on only one recording can enter its context for the rest of its work. The installation cache is for information about the active installation, such as its settings, and refreshes when the executable's size or modification time changes. It stays separate from the process default. Reading facts for an older recording from an executable requires an exact SHA-256 match with the recorded identity.

The registry keeps published tables for the lifetime of the process so stable references survive changes in the active recording. Deduplication compares the build identity and the independent content digests. Lazy views are keyed to the actual retained table set. Initialization runs outside the view lock because one view can read another. The second lookup chooses the published view when two callers start together.

The recording stores decoded values and named refusals, with the executable size and digest identifying their source. The encoded executable-table version that added character folding appends its table. Older recordings still open and report folding as unrecorded. Version 4 appends the equipment category families to the auxiliary table: the land, air and naval masks from the game's category-family switch, and the ship, tank and plane designer masks from its DLC-gated designer routine. Each designer mask is matched to the one family that contains it, and the whole set is verified against a pinned digest. Playback takes family and designer membership only from this part, so an older recording reports it as unrecorded. Installed version text is accepted when the read-only strings matching its expected form all have the same value. Fixed modifier names come from verified executable metadata independently of content load order. Dynamic keys come from live data.

The live fixed-layout check uses built-in modifier rows, the sentinel before dynamic registrations, and the static lexer tokens fixed-index readers depend on. An incorrect built-in row or sentinel invalidates every fixed modifier key because the index contract has changed. Static tokens fail individually. It uses a witnessed dictionary and verifies that the table and dictionary stayed stable throughout the read. An interrupted check can retry on a later hour, including when startup registration had yet to finish. The final report uses storage prepared before hooks and defers string formatting away from the game thread.
