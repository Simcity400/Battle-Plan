# Separate live packing budgets from lossless recompression

Live packing owns its workers and caps playing work at four active CPU credits and 32 MiB/s of logical I/O. Catch-up leaves Windows background mode while keeping the playing limits. Final promotion releases them, with workers refreshing their state at work boundaries and inside long operations when the coordinator cannot sample progress. Packing waits out the game's hourly tick at those boundaries. Progress on long reads and compression checks the gate each 64 KiB before calling anything that may lock. I/O is charged once for the actual bytes transferred, including short operations. Limiter waits are the sum across threads, while phase metrics are coordinator wall time exclusively within phases entered after Stop.

Offline helper work consumes available credits while retaining one for the calling thread. Credits are returned even if work ends early. A failed helper spawn leaves work for the remaining lanes. Workers complete their batches without waiting for the coordinator to feed or accept entries. Errors, panics and ordinary results are observed in item order. Closing a lane always wakes its workers to stop.

## Rewrite the stored bytes without rerunning recording

Recompression reads each stored frame or extent, validates its digest, and checks compression by decoding the output against the same raw bytes and prefix. It does not decode rows or invoke a row writer. The decoded-content digests stay unchanged. Offsets, compressed-byte digests, pages, directories, chains and the root are rebuilt. Dictionary and chained-frame references are carried to the rewritten locations, and restoration chunks that reused frames from the last full restore still reuse those frames. The world log is emitted in file order including closed-span and run metadata. Other sections are copied or reframed by their extent kind.

CPU workers take jobs in file order while the writer accounts for raw work in flight and compressed bytes waiting to be written. The soft window leaves room for several normal frames per worker so a long frame can finish while later units are processed. An item's writer waits for every frame and the part-decoding task that handed those frames out, even if that task's acknowledgment arrives last. This lets other workers stay busy without breaking deterministic output. The late-task and held-large-frame tests exercise these cases separately.

Recompression requires a complete saved revision with no resume state or torn tail. A live writer, a held file at replacement, or an observed length/footer change leaves the recording in place. A root already at the selected level is left byte-for-byte alone. Work produces a sibling file that the recording listing ignores. Interruption leaves the original untouched and the next attempt starts from the original again. The outer operation acknowledges replacement only after collecting and syncing the new file. Optional below-normal priority reduces competition from the process and every compression worker. Priority calls use Windows pseudo-handles for the current process and thread. The test restores normal process priority after measuring the worker's priority.
