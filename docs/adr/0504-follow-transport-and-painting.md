# Share live dashboard queries and paint their moving values by frame

Live widgets share an `at`-shaped query by canonical JSON. A holder acquires a share and the final release tells the service to unfollow. Until the service accepts a follow, the widget can request its value at playback anchors, including paused seeks. Widgets and followed queries share the dashboard's near-screen margin. A target using `display: contents` takes visibility from its current children so exchanging a loading child for a rendered child does not drop the query.

The service sends all answers for a playhead step in one binary message. Its eight-byte section alignment lets independent answers share typed views after a single copy if needed for alignment. Keep the key halves, cell values, insertion hours, cell states, and text references as views in that message, decoding text on demand. A follow can replace its rows, append log rows, or overlay changed rows by key. A seek reset restarts the log. Store the answer's own hour separately from the latest message hour through which it holds. A step can leave an unchanged answer in force without resending its data. A transport failure makes follows unavailable and preserves the request fallback. The cross-language golden fixture comes from the Rust writer.

Each cell distinguishes a recorded value, a missing optional value, an unrecorded value, and an absent row. Only an actual zero is painted as zero. A pending answer differs from an answer with no usable value. Read safe integers directly from the two 32-bit words in hot paths, and keep the exact integer and the normal fixed-point formatter for larger values.

The worker pulls the host stream by session. The first empty response claims the stream before any page request needs it. Each response can carry multiple length-prefixed payloads. A request can wait for host data, and the worker can fetch the next response while delivering the current one in order. Say once when the stream starts failing and delay subsequent retry attempts.

Availability and row structure can trigger React renders. Stable text nodes and bars take their moving values on the engine's paint phase, so values that arrive during a frame can paint in that frame. Use compositor transforms for scaling bars and let the engine drive their glides. Paint a visible target at most once per frame, repaint after a layout commit replaces its rows, and catch a target up as it reappears. A changing group of countries can retain recently seen members and their lookups until the size bound is exceeded. This avoids reissuing follows on each reorder without letting the query grow with hours played.

Queue data updates once for the next engine commit. An on-screen row can use the same queue's urgent priority for an answer such as a name. This avoids a lower-priority transition delaying that answer behind work for later rows.
