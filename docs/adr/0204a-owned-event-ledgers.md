# 0204-A. Assemble event ledgers from owned observations

The host dispatches leader and ledger capture and owns their loan and table assembly. Ledger workers project owned increments without following game pointers. Each air-loss row keeps the original event's hour, even if a later frame drains it. A projection that exhausts allocation reports failure instead of publishing the partial result.

The event feed prepares a snapshot at the observer boundary, then seals it after that hour's country census so its markers describe the same hour. A successful seal clears the prepared state. If sealing unwinds, the outstanding prepared state lets the failure name the right hour. A failed preparation is already sampled and keeps its original refusal when sealing or joining is attempted. The spool encodes and acknowledges the sealed handoff.

Market state and market events have separate coverage. Country, contract and agreement state needs either a certified projection or a full snapshot. Every admitted event stands alone, including an event that names an unavailable holder amount. A complete event table survives a keyframe even when state reconstruction fails. A loss of spool continuity invalidates observation without requiring a game-clock jump. The next census owns recovery and preserves the first refusal through off-slot recovery. Writer notifications from unrelated variable stores do not authorize reads of those stores. An unobserved exception in a context that may change held variables requires a refresh of those contracts before they can be carried again.

Nuclear damage pairs an after-read with its own damage call's before-read for the same handle and class. The same unit can appear in multiple calls within a strike. An unmatched before-read is counted as unobserved damage. An unmatched after-read follows a refusal already recorded by the failed before-read, so it creates no second row or refusal. A changed class is reported separately instead of being treated as a pair.
