# Preserve commander and sub-unit registration boundaries

Commander loading first registers names across the content files, then replays their bodies. Every definition consumes an ordinal after the null definition, including repeats and names that cannot be displayed as UTF-8. First spelling and first ordinal win under ASCII folding. Repeated trait bodies merge into that first definition. A missing suffix of a file can contain another body or skill table, so a stopped body pass leaves all traits and skill levels unknown. The registry from the recording can settle otherwise ambiguous modifier names by rereading the same files. Preserve byte identity even after a display refusal so the body still defines its file-local variables and does not alias distinct invalid names.

Every file has a fresh lexer and variable store. Readers vary by field and by how they consume tokens. Quoted keys do not enter ordinary keyword dispatch, but a modifier name can still be looked up by text. A quoted token also retains its kind when supplied through a variable. Advisor references and slot read the current token, including a variable's original name instead of its resolved value. A reference can resolve to a registered name or the reported null object. Tooltip strings copy C strings and preserve the distinct handling of line feeds in modifier tooltip fields.

A block-valued modifier can change precisely where reading resumes. A registered modifier takes its opening token as the value, while an unregistered modifier skips the block. Carry the condition to the affected trait or skill table and all later readers in its file until recorded modifier metadata settles it. This also applies to quoted modifier names. The registered terrain and static condition names dispatch before the shared modifier reader. Each adjuster preserves the first appearance and registered spelling, with repetition or double reading governed by the default adjuster's token. A repeated non-default adjuster can end its enclosing block early. Unknown fields in parent and mean-time readers preserve their distinct token recovery. Variable definitions are created only by a reader that actually enters the relevant keyed body.

Trait hovers retain component skill slots, ordered common and specialized modifier blocks, sub-unit modifiers in read order, and the difference between authored zero and unavailable text. A custom override supplies the complete effect tooltip when present. Category masks merge valid entries and keep their default if none is usable. Current country tag selects a tagged display name before the registered spelling, and the assignment tree uses a different sprite path from ordinary exile rows. Component skill tables keep the latest entry for a category and positive level. Missing or invalid entries remain null; the next cost can instead be unknown or a known signed whole-XP value, including zero and negative costs. Skill construction defaults to an unregistered category, with exact lexer categories required to select one. A failed conversion keeps the previous field, an EOF scan stores and reports nothing, and the building-module block is separate from the displayed modifier. Division experience is already normalized by current manpower. Read thresholds in the authored order and clamp displayed progress only at the final level.

Sub-unit names and their registered categories and modifiers share one ordered database assembled from the direct files of each configured directory. The first appearance determines spelling and index. Subsequent appearances reset artillery, special-forces and type mask fields while retaining a prior group. Boolean fields accept exact yes and no only. Several type fields inside one appearance OR their masks, with scalar categories using the current token and raw-list categories consuming their first token unconditionally. Quoted and numeric names do not set the support bit. Re-registration after an unread tail can settle values reset on each appearance, while that unread tail leaves earlier values unknown. A missing or refused name stays distinct from the null definition. Equipment needs use the last definition, resolving named equipment to archetypes in first insertion order, replacing later amounts for the same archetype and diagnosing an unregistered equipment type. Carrier admission uses the first authored equipment requirement; wing size alone cannot prove it. Finalized wing sizes preserve signed inputs except for native defaults and invalid incompatible combinations.
