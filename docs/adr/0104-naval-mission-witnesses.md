# Acquire naval mission operands with their owning census

Replay derives convoy efficiency and mission icon values from recorded operands. Capture walks each country's fleet once in owner-slot order, keeping contiguous task forces and their roster, mission and expeditionary owners. Complete membership lets the sliced family identify every country whose inputs it needs. A short census withholds its dependent publications and sizes storage from the walk's full demand. A discarded cut forgets the partially maintained caches before reuse, retaining allocations. A failed accepted worker publishes none of its partial data.

On an ordinary hour the task-force and ledger tables refresh from the live census and the authenticated physical navy pass. Sliced modifier and commander rows change on an observed input change. The country witness includes task-force leader and commander references, escort-tree demand, naval tree stamps, native hub data, and each HQ commander's selected skill objects. An unreadable or unobserved operand takes the fresh-read path. In the absence of a store every selected country is read. There is no rotating fallback slice. A refused demanded escort tree invalidates that country's reuse slot so the next hour retries it even if the other operands match. If refusal scratch cannot grow, every country is reread. Escort trees stay inside the already certified owner slice. They are unavailable without its first owner observation.

The leader memo reuses a resolved navy leader under its current naval-tree stamp. When the stamp moves, it resolves the native reference, takes a certificate and authenticates the object in that order. An unresolved reference and an unreadable or unobservable reference remain distinct. The next memo holds only references used by the completed scan. Commander operands are kept distinct by fleet leader and the four commander source kinds, and sorted once per kind. Raw owner references survive missing links so playback can name the missing link. The family census itself only uses resolved references.

The physical navy pass authenticates each country's navy by its canonical slot and manager backlink. A conflicting stored owner does not change that association. The ledger path needs a navy for every positive canonical country, including any beyond the available manager slots. A verified empty mission set proves empty ledgers because native registration, removal and reset update each record and set together. On quiet hours a navy with an unchanged ledger certificate can reuse its stored-order registrations while reading new presence. A full hour rereads every navy. Unlisted escorts that are still fading retain their live presence counts. The first registration's owner is the one used by escort text before mission filtering. A roster owner or another context cannot stand in for it. A rejected or unvisited navy cannot keep an old ledger in the next hold.

Mine and incident reports derive from the physical pass independently of the mission census. Only a complete country roster certifies omitted zero amounts and empty lists. Weather failures do not erase the mission roster witness. The worker reads distinct located regions' weather once, keeping it available for later native demand. Shared HQ lists retain their identity until an observed value changes. Optional registered strike range rows borrow the same frozen authenticated pass. Failure rolls back only the optional suffix. Its rows retain their already observed weather and patrol context even when they reorder the initial mission rows. Only initial rows receive weather fan-out during the FIFO tail, which holds no native memory capability or writer decisions.

The guarded-reader benchmark holds the synthetic world's bytes owned, immutable and live until every read has finished.
