# 0802. Keep tray recording separate from panel and library work

The recorder is a Windows tray process and closing its panel leaves the worker running. Tauri tray and menu callbacks run on the event loop, so building a webview directly in a callback would block the same loop that services creation. A separate thread constructs the window and the first fit shows it only after the panel provides its content height. A release build needs the embedded UI to reach this point. The panel uses the dashboard webview's appearance when its options are accepted and falls back to its own storage otherwise.

The panel places itself beside the recorded tray rectangle in physical pixels or restores its dragged position using the selected monitor's scale and work area. A removed monitor falls back to the nearest available work area. An absent tray anchor uses the primary corner, and an auto-hidden taskbar is located relative to the icon and monitor edge. A focus loss closes only a panel that has already held focus while shown. The hidden-icons flyout can lose focus before the panel appears, and native dialogs take focus without closing it. A short reopen guard recognizes the tray click that prompted closure. Start and Stop menu items have separate identities so an event still corresponds to the item the user chose as the menu changes.

The recorder opens saved and waiting recordings on demand. Directory versions gate file scans, and names for ended sessions are computed off the listing thread against the appropriate session's content. A delayed IPC open cannot reopen a visit already closed. The running session retains the target folder it started with. A save-directory change still lists earlier sessions that need a decision, including sessions on an unreadable drive. A settled root is checked again under the settings lock to avoid forgetting a session that started while listing it. The waiting list merges spool contributions for the same final recording and counts a session's spool once. Missing readable bounds or metadata stays unknown.

The target chooses by campaign identity from the recording header. A pending New file choice is consumed on the next admission and creates a new numbered folder only when there is a recording to keep separate, including unsaved earlier loads. A changed capture mode can also require a separate folder to avoid combining incompatible capture plans. An unreadable recording is left to the writer to diagnose. The installer and the recorder panel both use the same Windows Run entry as the autostart setting. The worker guards saving and discard from updater interruption. Startup holds a Windows session mutex and exits when another recorder already holds it. If Windows cannot create the mutex, the recorder logs the error and continues so a failed check does not prevent recording.

The viewed country's flag is decoded from the session's recorded mod stack with the same key order as the replay app. The original-or-own tag participates in the search. An undecodable or absent candidate falls through to the next candidate. A key that escapes the flag directory stops the search, and a wholly unresolved flag leaves the slot without a substituted country image. The panel receives bounded, straight-alpha pixels.

Recompression uses the canonical path to avoid duplicate queued and running jobs. Auto Compress runs after a low-compression save when enabled. A background child lowers its priority and is attached to a Windows job whose closure ends it with the recorder. The current recording remains usable until a whole smaller replacement is published. Publication can keep the old recording when another handle opened it. The panel shows why it was kept and permits a retry. A compress whose replacement could not be confirmed on disk, or whose outcome is unknown, is shown as not confirmed, never as kept. Interrupted automatic jobs can be recovered when their settings still apply.

`Bound::new` creates an unnamed job using the default security attributes. It takes ownership of the non-null handle immediately so a failure to set the limits also closes it. The Windows `JOBOBJECT_EXTENDED_LIMIT_INFORMATION` structure permits zero initialization with no limits. `SetInformationJobObject` receives its exact size, the matching extended-limit class, and a live pointer for the duration of the call. `Bound::bind` borrows the live job and `Child` handles for `AssignProcessToJobObject`. `Bound::drop` calls `CloseHandle` once on the job it owns.

The snapshot reports actual saved bytes separately from the active spool. An absent hour, identifier or size stays absent. Backlog appears after it exceeds the collector's steady retained frames and clears when it catches up. A problem takes priority in the tray indicator. Icon rendering competes against both light and dark taskbars, with appearance checked even during unchanged status polls.
