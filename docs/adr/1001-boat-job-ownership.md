# 1001. Coordinate remote builds by claim, content and cache identity

Boat clones an image warmed with the UI and a whole-workspace check (ADR 0007). Release and test builds start cold on each VM and fill its compile caches. Keep check metadata, release outputs and tests in separate targets and key reusable objects by the inputs Cargo reads, including build script and applicable dev dependencies. Release and test caches remain separate so tests cannot evict release objects. Incremental test binaries remain in the dedicated target because the compile cache does not retain those binaries.

Another helper's run invalidates the recorded target tree while its input-keyed cache entries remain usable. A checkout with ordinary compile failures can still warm the image with completed units. A failed infrastructure step cannot publish it. Tests exercise resume and hydration with an injected clock advanced by fake pauses.

One local lock holder updates a VM's pool record. Pool selection favors usable hydrated machines and matching lanes or inputs, and avoids a cooling or stopping VM. Keep a reused VM warm briefly to avoid its observed resume latency. Hydration must progress and finish before operations that read cached files. Resume without the CLI's long automatic wait so the runner can pass over a stalled VM. Grow a VM that needs more memory because a shrink can refuse when its data no longer fits. Shorten the idle lease before making the machine available again to avoid cutting short the next owner's lease.

Run jobs detached so a dropped connection leaves them running. Retry a potentially state-changing call promptly only when the local launcher proves it never started. On reconnection, stream offsets discard verified duplicate output. Prefer repeating a range to dropping it if the CLI did not preserve its bytes. Own and kill only the work the caller started. A lost outcome can still have a live command and keeps its claim. A successful remote outcome is written before the job exits. Procfs process start identity and boot identity protect against PID reuse. When the group leader exits, retain a surviving group as claimed rather than signaling a possibly reused ID. Release the VM before running downloaded tests locally.

A cache server can outlive Cargo's process group and continue writing into its target. Mark the claim as stranded before such work and clear it only after verifying the server and job drained. Older helpers must not acquire a stranded claim while its processes can still mutate the target. The cache server's output goes to a file to avoid holding the command's pipes open. The runner prunes accumulated incremental sessions before they exhaust the disk, limits parallelism using memory measurements, and timestamps a failed cache download to keep every job from retrying it.

Small uploads use base64 arguments that fit the Windows command line. Large ones use a separate Git index because the normal capture ignores would omit their staging files. Include only the parts of the current transfer and clean partial runner files on exit. Downloads use base64 parts capped below the CLI output limit. Compute manifests from bytes actually transferred, and remove the remote manifest before mutating its tree so a partial sync is rehashed next time. Hash caches skip newly written files until their timestamps can reliably detect another edit. Staging and local test-owned directories reject filesystem links, which could redirect cleanup outside the intended tree. A test folder stays claimed from artifact download through local execution and may replace only its own files.

Tests and benches can receive compile-time folders pointing into the VM. Preserve compile-time file inclusion on the VM and supply binary and temporary paths locally for integration tests and benches. A test-owned folder with only an earlier run's unlocked lock file remains reusable. A test program receives everything after `--` unchanged. Tests and staged map binaries take the pinned DXC adjacent to the program. The wrapper fails a filter which ran zero tests even though Cargo would exit successfully. Preserve exit statuses across Windows and Python's signed process exit interface.
