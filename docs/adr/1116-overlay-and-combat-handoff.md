# Overlay layout and combat reads have separate handoff rules

The side asks the overlay worker at step apply. The worker reads views of the side's own mirrors while other layers settle. The host holds every written table whole and keyed for the makers, including tables that record a missing status. A script can then learn a new table without waiting for the clock to pass a held stepped hour. The maker declares only the views it needs. Known tables are declared up front, along with vision and the icon families the camera, zoom target or mode can draw. A view that cannot draw a family leaves its tables out unless somebody else already needs them. Tooltips and click readers can ask for the broader set. When a build learns another table, it is added to future requests and the previous product stays as it was.

## One in-flight layout and two memories

The overlay publishes tables as soon as they are built and publishes layout separately when ready. The step takes ready tables before the counter layers that consume them settle. It does not wait on a paced join. The frame projects and draws a ready layout at its own camera. A whole settle first asks for tables alone, settles the dependent counter layers over them, then asks for layout at the target hour. Strict joins wait for their own ask within the deadline, repeat after a missing table is learned, and refuse by name if the request is not met. A held layout can cover a later hour with unchanged inputs. This lets the frame stand at an exact hour without waiting for a layout it will never receive. A saved frame can explicitly request a fresh layout at that same hour when art was loaded during its draw.

Layouts use two memories, one at the frame and one at the worker. A layout and the memory it was built on travel together. The worker cannot lay out another paced picture until the frame takes what it has published and returns the other memory. This prevented a faster worker from producing a layout for one memory while the frame was still drawing the other. Live counters keep native window histories in the view, separate from camera-independent preparation. Exact settled frames may use the view's memory directly because the frame is waiting exclusively for that picture. An independently drawn test or snapshot has its own memory and does not share window history or movement.

The pending request is latest-wins, and superseded waits terminate even on a seek back or when the worker is stopping. Replacing a request does not erase the intermediate movements it carried. Refused and tables-only builds retire no movements. When a build lays out a picture, it retires only the movements through its rows' hour. A seek resets the generation and its old requests, products and moves cannot appear in the new picture. Layout identity includes the read and table products, view settings, counter memory, versioned layers and art. Projection location does not by itself require another layout. A pressed or hovered plate can change its own drawing without layout. Moving units can request another frame without scheduling every native window manager, since tracks can be placed at the display head. Layer products are given to a layout only for the same perspective, and published vision is copied off-thread with a changed-province update. A strict frame needs the vision of its own picture.

The counter owner filter follows canonical slots. If an incomplete table or missing human-country link prevents an answer, it shows all counters rather than hide those of a player. The filter refreshes no more than four times a second during running playback and caches by filter and table allocation identities, which prevent reusing another recording's owners. Prepared views can inherit the shared province schedule and movement history without competing for the frame's working memory.

## Combat reads belong to one publication

The step asks for the open combat window at apply and takes a successful read at the end of that same publication. A result that missed its step cannot be delivered with a later one. Paced steps wait one publication interval only if the last read fit that interval. A stopped picture or saved frame waits within its own deadline. A read can add tables it discovers to the declaration for later attempts. Reset generation, view, engagement cover and exact hour identify the request. Even a reset back to the same hour cannot be answered from the pre-reset rows. A newer request or a closed window cancels a pending read. The join reports which request it actually took, independently of any earlier result the frame has yet to take.
