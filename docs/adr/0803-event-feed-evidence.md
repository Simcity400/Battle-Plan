# Build event feed cards from witnessed occurrences

`FeedEvents` gives each captured occurrence its own row by generation and sequence. Use the canonical country slots witnessed at the read. Preserve the typed script operands and scopes so the reply can render localised titles, bodies, options and icons. Registry updates are not occurrences. An incomplete read gets a coverage row even without occurrences. An absent captured token is unknown, while a captured empty token means the occurrence has no script. The current `EventFeedHistory` input supplies the occurrences for its stamped interval, rather than a carried list of earlier events.

An event dispatch stays open until its choice. Match by native event, instance and receiving country. A negative option ordinal records immediate effects without closing the dispatch. Match a decision's selection or activation by country, token and targets. An activation without a witnessed selection opens its own episode, such as a mission or a selection made before the recording. The open tables store changes once at the end of a read, so a card opened and closed within one read leaves no open row. A missing or discontinuous read drops decision links. A new generation closes every opening. Show a decision's political and command power charge only when both captured power streams prove changes under the execution or timeout key for that hour and country.

The writer derives two other event kinds after the first hour. It compares owned states with the last complete counter read to detect a country losing its last owned state. It adds a guarantee created after the first hour when a complete relations read first shows it uncancelled. Retain each guarantee while any relation row holds it, including cancelled rows and occurrences listed under both countries. Moving between ordinals or being relisted by another country cannot duplicate that event. An existing guarantee at the first hour is part of the baseline.

The writer restores open cards and guarantee state from its own tables. Resume preserves the generation, cursors and last complete counter evidence. Published feed rows live for their read hour and are removed by the next writer hour. This lets the uninterrupted and resumed runs expose the same events without persisting scoped title or description strings in the derivation.
