# 1119. Save exactly the map frame that was rendered

The window and headless dump render into the same offscreen, graded 8-bit target. The window gives egui the resulting texture, and both paths use the same PNG readback and verification banner. Surface presentation, multisample resolve outside this target, and egui's colour handling occur after the captured bytes have been produced. Window dumps pin the requested camera and framebuffer dimensions, and use the dump's interface scale unless overridden. They draw the same pair of frames for luminance adaptation. The clocks cannot otherwise match between the paths, so a saved still uses zero animation time and a sequence uses its explicit clock. A frame holding a placed walk or flight advances its controls on that clock and consumes no live input.

Stepped captures and window dumps ask for a complete picture at the requested hour, including the unit meshes, combat markers and orders prepared by the map's side. They wait for the workers themselves and any tables learned by a build. No overlay is requested before a first picture can compose or before a camera and extent are known. A desktop export saves the frame on screen, and reports the branch and hour read back even if the clock moved after the request. Captures inventory reachable counter hovers and include the same limitation report as a comparable dump. Ordinary frames avoid building that diagnostic text.

Art can decode after the layout that requested it. Compare the art version against the one the overlay used, including when late flags or portraits are the only missing part of a named combat window. A saved frame close to readback repeats the layout over new art and retries its icon pools. If it still cannot settle within the art retry count or the time bound, it refuses the picture by name. The time limit starts when a map is loaded and the requested frame is waiting for a drawable picture, so opening a recording and early frames of a paced run do not consume that bound. A paced run otherwise draws what has arrived and lets art land on later frames. An explicitly named window must appear. A direct region or state selection can open without recorded rows. A named combat that never resolves, closes, lacks visible contents after settling, or is hidden is a named refusal. The bounded count for a still-unresolved combat starts when its picture stands.

For a window dump, a failed load, recorded gap, refused picture, or window closure before its last readback fails the process. A desktop export answers its request once even when a frame returns early, its view goes away, or teardown follows a panic. Export failure does not reset the map's own error and permits the next request. On a refused saved step, the overlay handed over still belongs to the viewer, and the failed frame is skipped before ordinary playback resumes.

Profiling uses the production Campaign frame path. CPU laps exclude pacing sleep, while the reported inter-frame gap includes work such as egui tessellation and present. GPU submission waiting is opt-in because it serializes progress. A paced window dump uses a configurable display rate so advancing the playback clock per frame does not outrun workers operating in wall time. A synthetic hover supplies framebuffer coordinates to the hover path only and never creates live OS input. A diagnostic warm-up composes and uploads the first picture without rendering, so it does not advance render histories. Both render coordinators record the submitted picture before audio and readback can delay observation.
