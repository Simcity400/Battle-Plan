# Stitch parallel template walks as one serial census

Parallel template acquisition splits contiguous country slots into ranges balanced by both template and country counts. Small walks and single-lane runs stay on the template job's own thread. The ranges borrow the original stores read-only and walk into separate arenas. Each records country visits, each batch's roster occurrences and decisions, where each row ended in the four arenas, and the speed keys. Reusing a held row also reuses its held keys. Missing lookup slots cost a live lookup. Ranges may complete in any order.

The stitch applies results in slot order against the real stores, through the first failed range and its last serially reachable occurrence. An earlier occurrence can change a later decision for a repeated template. In that case the stitch substitutes the current held row or reads that one occurrence with current requirements. Before applying the decisions it reserves all entries and scratch space required for the stitch. A repeated template in a failed range's last batch can make its recorded prefix ambiguous, so that case, missing parts and refused admission fall back to serial without applying speculative store changes. The stores return from their shared loan only after every range releases its reference. If they are still in use, a serial walk proceeds without them. The first native failure remains the published reason.

Joining replaces a changed occurrence's original row and span slices, then rebases every placed span in the byte, count, variant and name arenas as the serial walk would. The accumulated difference between an original and replacement span can be negative, so the shift is represented with wrapping addition. A carried row places core spans. A fresh read also places its group key, allowed forbidden-equipment span, and cells while its extension is fresh. These rules preserve the native row order, arena layout, carried flags, diagnostics and final store identities across worker counts.

The loader prepares observer capacity before hook publication and the first boundary. The native walk runs in the hourly job and transports the publication with its owned settlement, so adopting the result does not reread live memory. A capture taken while the stores are out uses fresh reads. Synthetic tests run process-wide observation in a child to isolate other tests, validate split and serial parity including first failure and recovery, and encode the actual table columns through the spool preparation path.

In the worker parity test, the synthetic world stays owned until the batch drains, so the submitted request's borrowed source is valid through its completion.
