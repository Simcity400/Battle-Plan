# Confirm recorded evaluation inputs before reuse

An evaluation can reuse its result at a later hour of the same branch only after confirming the inputs it actually read. Record the first value for each key in order, including the full value returned by a query and failures reached while resolving it. A failed join can make an apparently unchanged result uncertain, so it belongs to that result's fingerprint. Reads inside a query or while building shared state are suspended, because the requested query's result represents them. External table reads record the whole view or only named fields when the result builds from those fields. A view identity keeps its allocation alive so a later view cannot reuse the identity accidentally. Query values use the same deterministic fingerprint within the process when they are recorded and checked.

A dependency names the table, field mask, inclusive row range and optionally the country whose rows are relevant. Table availability, reasons and row keys count even when no data fields are read. Raw IDs can resolve through different recorded country tables. Include the selected canonical country's rows and any unresolved rows, and invalidate if the mapping changes. Share the changed country slots by read shape, irrespective of the individual requested slot. Compare branch and hour before trusting changes, and compare relation times across a span even when no bytes changed. Treat unreadable rows and missing dependency declarations conservatively. An old format's absent columns can affect a read when a row changes. A mask whose field name is absent falls back to all fields while the debug build exposes the error.

Use the recording's changed and quiet spans and retained field stamps to confirm unchanged dependencies without reconstructing a trigger world or walking every row. A rebuilt table can be unchanged for a declaration that watches only its stable columns. Insertions, deletions and field changes affect reads according to their keys and masks. Advance a confirmed input to the hour at the end of the span. An input that might differ is reread against its prior value. A quiet span may use the earlier decoded rows when their ordering keys and fields remain unchanged. A dependency bit that covers multiple overflowed entries remains conservative if any of those entries changes.

Nested evaluations credit their reads to the outer capture. A helper continues the caller's capture and credits its reads on return. Capture unwinding restores the thread's state. Check mode rereads skipped dependencies and reevaluates reused results to detect declarations that missed inputs. Preparation enables this with `BATTLE_PLAN_REUSE_CHECK`. Tests enable it by default and can measure ordinary reuse with checking disabled. A missed-check diagnostic belongs to the checking thread, so concurrent scenarios do not affect its test assertions.
