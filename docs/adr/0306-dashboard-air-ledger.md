# Fold air events by read hour and date them by game hour

Loss and bombing displays need both the hour an event happened and the hour its drain was read. Range dates filter by game hour. Points, ranking changes and completeness follow read order. Resolve an event's raw country against the slot's holder at the read hour. Keep holder identity as canonical slot plus raw country ID so two holders sharing a changing tag remain distinct. An unresolved endpoint is attributable to neither side and stays separate from a proved opponent.

Observed stretches come from the event table's and country links' status runs. An hour contributes coverage only when both certify the event read. An uncovered or unavailable hour interrupts that proof, even if the preceding total remains interesting. The first read containing events after an unread stretch may restart event identities only when all its events date within or after that stretch. A preceding date means the earlier events can have been repeated. Bombing only counts the air-mission and air-naval callers of building damage. Keep a caller whose membership is unknown as an incomplete read.

Each window carries the totals before it and points for the events read in it. Read the opening values from derived totals at the edges of earlier stretches when they are usable. Fold any unavailable or overflowed stretch from events, and fold the possible late reads around a range's first hour because the count excludes events dated before it. Each leaf is split by holder, side, cause and the relevant region or building/state. Air-loss leaves also keep recorded opponent status. Regroup leaves by increments and run totals forward in read order so a part equals the sum of its leaves. Positive holder totals alone enter a top-N ranking.

Each window reaches back through contiguous observed stretches to the beginning of the proof, never before the first counted hour. It can consequently report whether its total is complete without fetching earlier windows. Cache these spans by run and family at open, sharing an in-progress read across requests. The independent full-branch test folds events and joins windows as the frontend does to check late events, open totals, contiguity and ranking across a boundary.
