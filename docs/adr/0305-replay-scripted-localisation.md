# Replay scripted localisation from recorded operands

Preparation records what each localisation command read at its hour so playback can expand the same text in a different language without reading the game installation or rebuilding the historical scope. It keeps the first result for each key, including named refusals, and keeps a separate ordered command list for each nested scripted localisation. The recorded country entries use canonical slots and include the overlords that naming can reach. Slot zero has its own recorded indication of which names were built. Overlord information is fetched only for properties that need names, so tags and flags remain usable when naming operands are unavailable.

Record numeric values, dates, country naming operands and selected localisation keys so the viewer can format them with its own localisation. Preserve literal identifiers, empty names and null results as text. A property that already expanded to language-specific text can be replayed only in the language that produced it. A property records its whole result and marks whether the computation could change the values later commands observe. Its internal expansions stay out of the caller's command list. Nested selections preserve the outer selection and use their own scope and command context. The normal event entry point uses the root country's own event scope. The unseeded entry point allows a caller to name values without supplying random lanes.

Language changes can reorder independent commands. Playback keeps the common in-order path and looks up the next occurrence by command name after a reorder. Playback refuses the affected text if a translation reorders or omits a variable read, scripted localisation or property whose triggers may set temporary variables. Nested evaluations use a larger stack after the shallow threshold, with the same depth limit and stack allowance as the hour's evaluation. The scoped worker returns before preparation takes ownership of the recording.

Build only the catalogue readers a reached command uses. An unavailable file leaves unproven localisation names unknown while names already read stay available. Capture warnings and refusals within the reply that reached the read, and replay those diagnostics when a later reply reuses the cached result. A strict trigger caller's missing inputs must stay local to that caller. Scope promotion carries the full active scope through `ROOT`, `FROM` and `PREV`, and each bracket starts from the caller's scope. A promoted object clears fields its constructor does not carry. A proven absence can keep the context unchanged or produce a native null object. An unresolved reference is refused at the operation that reads it. A unit leader's name resolves through its character, and numeric state lookup needs a country only when the current scope has one to search. Occurrence text can use names captured with the occurrence so later changes in the hour do not alter them.

Numeric localisation parses grammar exits before selecting a property on a live character scope. Defaults, indices, target operands and prefixes use their own default scope. The parser normalises the first flag-control byte back to `@` before the scoped variable reader. Flag ages are distinct from ordinary variables and refuse by name while unsupported. Formatted numerics are appended directly, preserving colour controls and newlines without opening another expansion. Weighted entry selection uses the event scope's recorded lanes, a promoted object's native constructor seed, or an explicit seed when supplied. A sole entry reads neither seed nor weight. Multiple entries evaluate signed weights before reading the seed, with wrapping arithmetic and an empty result for a nonpositive total. Selection leaves the underlying random state alone. Alias trigger writes during the seed read remain visible to the selected entry.

List weight modifiers accumulate their additions and factors separately, without evaluating their conditions. A zero factor makes later operands unnecessary. An explicit seed takes the raw operand's low word plus the selected object's native identity. Use the recorded full reference where that kind is hashed and the recorded instance ID where the kind supplies it directly. Projects contribute no seed identity.

Country name case changes use the C locale's byte rules, including first-byte capitalisation. Party-group tokens fold ASCII when read through the lexer, while a group name compares exact bytes. Party support normalises the ruling group's popularity against the sum for every party and formats the result without a percent sign. A party leader property uses the first entry even if it is null. Its pronouns share the character pronoun keys, with female selected only by the recorded female value. Explicit party or organisation names stay independent of lexer availability. Missing localisation keys are copied at the point the native reader would copy them. A party name probes the original-tag key only when the earlier keys and stored name did not decide it, and uses the `_long` suffix only after finding a party key.

Manpower combines the country residual and available controlled-state pools with signed 32-bit wrapping addition. A state proven to have no provinces is omitted. A missing province witness that leaves the count uncertain causes refusal. An agency row distinguishes a created agency's stored name, including an empty name, from the default localisation key. A missing agency row is an unknown input because every country has an agency object. Old names fall back to the current naming operands only when the retained bytes are empty. Dates use the sampled hour and native 365-day calendar, with the leading space and hours numbered 1 through 24 where date text requires them. State event names prefer recorded names, while country-key localisation uses the original controller tag before the generic key. Capital victory-point naming uses the cached state choice and then the province name fallback. Faction names use one localisation pass that preserves bracket text. Power balance descriptions derive from the recorded operands and content definitions. The witness trees verify the derivation.
