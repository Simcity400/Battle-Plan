# Give every capture frame and live input one owner

One capture runs at a time, either holding the game thread or beside it while native writers wait at the capture gate. Capture reads the state left by the hourly update. When the command-batch observer proves every return, capture includes the commands after that update. Without that proof it reads immediately after the update and records the earlier boundary in session status. A beside capture records the last observed group-zero processor when the machine’s processor group can be represented. It does not raise its priority above the running game. A held capture temporarily raises priority so the game thread can regain a core from acquisition workers, then restores it before native execution even on a contained panic.

Each frame index has one current owner. The free queue contains prepared frames with stable indices, and capture publishes each frame only after finishing all writes. The decode worker can acquire exclusive access at enqueue, so its later ready-queue publication cannot synchronize a write made after enqueue. Every frame goes through the same decode FIFO in hourly order, then the spool’s ready FIFO. Both queues link through frame slots. The capture sequence can be zero and belongs to both the frame and its single decode job. The decode worker restamps allocation metrics after its own growth.

The frame builder wakes when the next hour or its spare needs a frame, keeps them ready when it can, and parks without other work. It checks stop and free-frame count before each build and park. A stop lets a build already running finish, even if an internal wait consumed an earlier wake. Capture takes the newest free frame or builds one without waiting. It never frees surplus storage. A stalled spool stops new growth and records losses when the pool runs out. A returning spool frame can be kept, made newest, or freed if surplus. Sizing restores an idle lease at its prior age. If freeing a surplus frame would hold a lock the game thread can take, return the owned box and free it after releasing the lock. Reset verdicts and take whole-frame measurements during exclusive preparation; if a frame returns without reset, its next capture does that work.

The loader may prepare the capture’s private campaign clock buffers and the free frames before publication. Spool preparation between ticks leases only free frames beyond the next hour’s and its spare. If that optional preparation misses or fails, the capture grows the frame it takes. The running capture alone changes its private buffers and reads one entry clock before acquisition. Check actual buffer capacities because clock witnesses trade places. An exact full-byte campaign identity change advances the attachment-local epoch. A failed clock delays the once-only roster observation, even if no frame can be obtained. Publish the roster independently for the spool to take once, and preserve loss witnesses when no frame can carry them.

The running capture owns pending losses, the country cache, fingerprints and other capture-local cells. The loader may initialize them before publishing the hook. A capture swaps in a prepared country cache using a nonblocking lock only after previous leases have returned. The spool frees the retired cache. Acquisition workers own raw requests and their loans while active. Only the callback takes and returns their shared stores, and it returns them only after join establishes that the worker retains no reference. A doctrine observer binds to a stable allocation after attach allocations complete and the allocation remains stable through restoration and quiescence. Spool reads the final pending loss batch only after quiescence.

The principal loan groups are Weather carry, Late’s raid-air and rail stores, the character role store and roster loans, IntelResidual’s flag and variable stores, Governance’s building and leader/party stores, the wing and air base or mission stores, States and occupation, Wars, and the provinces and areas stores. The Slow job takes advisor, local-subunit and doctrine state. The Countries and Ordinary counter jobs take appearance and counter stores. Slice fingerprints travel with their respective family. The capture owns all changing splits and returns parts in slot order. An occupation snapshot holds immutable output instead of borrowing its store. Division presentation’s attack-operand store is an exception to immediate return. FIFO decode returns its settled store, and a capture that finds it still out uses its own storage. The weather temperature tracker belongs to the single decode worker in hour order.

Core capacity slots count countries, provinces, links, states, divisions, wars, factions, faction members, faction name bytes, border-conflict provinces and admitted group handles, and state name bytes. Countries uses canonical slots while links use raw identifiers. A country appears at most once in faction membership. Country capacity also supplies order counts and the war snapshot. Synthetic frames own their homes. Production frames borrow the shared homes and check their allocations before publication. An allocation refusal names the responsible phase instead of aborting. The two display names in each state row index the same arena.

Record the session’s capture mode and score setting before installing hooks. When score is off, no score operand reads are added. The recorder can wait on the event that says the game is between ticks before packing. Use no processor number from several processor groups because their numbers are group-relative and the recording’s core table cannot place them.
