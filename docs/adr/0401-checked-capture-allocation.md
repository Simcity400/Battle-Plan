# 0401. Report allocation refusal at the owning capture boundary

The collector and spool writer use checked reservation rather than the process-aborting heap paths. Allocation-free hooks admit or report checked growth. Operating-system memory, resource and commit-quota exhaustion count as allocation refusal. Capture normally becomes terminal on a refusal. Advisory sizing is optional and never stops capture. A contained operation reports failure to its owner while advisory work nested inside it remains advisory. A writer can finish a payload handed to it before capture became terminal, but a new refusal still fails that write. The process-global hook tests isolate that state in a separate process.

There is an empty-vector fallback for checked construction behind the pre-install and publication guards. Advisory constructors can abandon optional storage. A contained caller discards the result on refusal. The resulting empty vector carries no usable capacity guarantee and must not be grown in place of the refused allocation. Batch reservation follows sequential vector growth to keep capacity-based capture metrics comparable. Exact boxed-slice conversion avoids an infallible shrinking reallocation.

Worker calls return freed pages between tasks, limited to one collection per interval and thread. Otherwise their allocator can wait until a future allocation in the same segment to return pages. A shared value uses one checked allocation and supports strong owners without weak references because stable `Arc::new` cannot return a refusal. Allocation failure drops the value. The owner count follows the usual reference-count bounds, and only exclusive ownership grants mutable access.

`collect`, `oom` and `allocation_attempt` only cast raw function pointers stored by their typed setters. `boxed` allocates a writable block for `T` or uses an aligned dangling pointer for zero-sized `T`, moves the value into it once and gives its layout-matched ownership to `Box`. `boxed_slice` transfers elements once and removes the old vector's element ownership. `SharedBox` only crosses threads with `T: Send + Sync`. Each owner keeps its allocation live and exposes only shared access until `get_mut` proves uniqueness. The last owner's release/acquire synchronization leads to one drop of the original box.

Compression and decompression contexts use the same global allocator, with checked growth attributed to the context holder. The compression window can cap the match-table shape based on the requested window alone, even when a dictionary prefix is supplied. Prefixed frames require the original prefix at decode. Unknown and erroneous advertised content sizes are excluded, and a frame-size read reports the stored length of the first complete frame. Decoding into uninitialized storage relies on zstd reporting exactly the prefix it wrote.

`Holder::memory` supplies a static holder to the zstd allocation callback. `allocate` and `free` agree on the aligned header that carries the allocation size, and allocation failure returns a null pointer to zstd. `Error` reads a static terminated name or a numeric code without passing a borrow to native code. Frame-size and content-size helpers pass only the supplied input extent. A context may move to another thread but is used by one owner at a time. One-shot methods pass live buffers and expose only the output zstd reports writing. `compress_append_prefixed` completes the prefixed frame before the call returns. `decompress_append_prefixed` clears the native prefix reference even on failure. `stream` commits only the bytes zstd advanced past in the reserved destination.

The spill scope travels to worker threads with their other task context. A family emit gets its own retained state while using the shared spill folder. The first request constructs a value, and a later request of another type receives none.
