# 1001. Share the ordinary build and isolate release optimization

Editing, testing, and application development use the same optimized incremental dev build with debug and overflow checks. Stable dependencies use higher optimization because their builds are reused. ThinLTO was a substantial part of compile time without making the test suite faster, so the dev profile disables it. CI's test builds use a `ci` profile instead, which optimizes dependencies like workspace crates: measured on a 4-core runner, the workspace's tests built in 60 minutes against 80 and ran in 5 against 7.5, and leaving dependencies unoptimized was slower at both. Workspace crates in that profile are unoptimized, since a pull request's legs mostly rebuild workspace crates: on a 4-core runner they compiled in 3,400 core-seconds against 15,200 at the dev optimization, while the tests ran in 1,400 against 670. `dashboard-query` was once optimized like a dependency, but since the crate splits its tests spend their time in other crates' code: optimized, its library and test binary compiled in 103 core-seconds and its tests ran in 289, against 26 and 150 unoptimized on a runner whose dependencies built about a third faster. Optimizing `replay` saves about 560 core-seconds where its own tests run, but costs about 200 more on every runner that rebuilds its library, which most pull requests that rebuild it pay several times over. Unoptimized frames are larger, so CI's test threads get the 32 MiB stack the collector's tests already reserve. Shipping cross-crate inlining shortens the collector's hourly pause and related background acquisition work. Iteration keeps the ordinary release profile because a fat-LTO link cannot be cached. The shipping collector keeps line tables for stack and profiler inspection.

The bundled COFF linker supports MSVC libraries, Windows resources, and x64 exception unwinding. The workspace avoids mimalloc's bundled v3 configuration after observing a null thread heap on a first allocation through in-place realloc. The fuzz workspace uses the ordinary application profile so its artifacts reproduce consumer behavior.

Resolve `windows-sys` with the feature union of the workspace and its dependencies. Separate selected package builds would otherwise compile different feature sets and rebuild their consumers. Derive the union from `cargo tree --workspace -e features -i windows-sys@0.61.2` after dependency changes. Individual crates still declare the features they use. Test feature unification resolves host and target uses separately. Common third-party crates are in the `test-unify` crate, while unusual ones are declared by their consumers. Run Cargo metadata before parallel locked resolutions because it may need to update the lockfile. Cargo admits a package version under one name and omits build metadata from dependency requirements. Search feature forwarders first and fall back to naming all unresolved features if an iteration cannot make progress.

Nextest starts measured long cases before ordinary tests so a slow case cannot wait until the end to start. Preparation parity runs ahead of ordinary dashboard tests. Nextest isolates tests in separate processes. A nextest filter naming a package the workspace lacks stops nextest before it compiles, so a repository check refuses one.

Repository checks compare agent context in bytes after normalizing checkout line endings. File enumeration is NUL-delimited because Git quotes unusual names in text output. Machine-path fixtures construct their specimen paths in parts so they do not themselves match the rule. Map native GUI code may reach dashboard data through the game-window crate. Its dependency boundary keeps viewer edits from rebuilding every product. Recorded row readers use the replay facade. Security advisories fail on vulnerabilities and direct unmaintained dependencies. Transitive unmaintained toolkit crates are reviewed without blocking the gate.
