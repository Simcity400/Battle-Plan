# 1001. Share the ordinary build and isolate release optimization

Editing, testing, and application development use the same optimized incremental dev build with debug and overflow checks. Stable dependencies use higher optimization because their builds are reused. ThinLTO was a substantial part of compile time without making the test suite faster, so the dev profile disables it. Shipping cross-crate inlining shortens the collector's hourly pause and related background acquisition work. Iteration keeps the ordinary release profile because a fat-LTO link cannot be cached. The shipping collector keeps line tables for stack and profiler inspection.

The bundled COFF linker supports MSVC libraries, Windows resources, and x64 exception unwinding. The workspace avoids mimalloc's bundled v3 configuration after observing a null thread heap on a first allocation through in-place realloc. The fuzz workspace uses the ordinary application profile so its artifacts reproduce consumer behavior.

Resolve `windows-sys` with the feature union of the workspace and its dependencies. Separate selected package builds would otherwise compile different feature sets and rebuild their consumers. Derive the union from `cargo tree --workspace -e features -i windows-sys@0.61.2` after dependency changes. Individual crates still declare the features they use. Test feature unification resolves host and target uses separately. Common third-party crates are in the `test-unify` crate, while unusual ones are declared by their consumers. Run Cargo metadata before parallel locked resolutions because it may need to update the lockfile. Cargo admits a package version under one name and omits build metadata from dependency requirements. Search feature forwarders first and fall back to naming all unresolved features if an iteration cannot make progress.

The daily run schedules measured long cases before ordinary tests so a slow case cannot wait until the end to start. Preparation parity runs ahead of ordinary dashboard tests. Nextest isolates tests in separate processes and caps individual runs at an hour. The runner's shorter deadline leaves time for cleanup and reporting before the scheduled task expires. Run folders expire after 30 days and the compact history remains. Reserve free space for an entire replacement build alongside the old target and test outputs. Fingerprints identify the newest build of each unhashed unit. When a fingerprint folder serves several units, retain it if any unit uses it. Daily clean compilation gains little from incremental files, and the sweep removes abandoned link objects. The sweep consumes Cargo's JSON separately from the nextest summary.

Repository checks compare agent context in bytes after normalizing checkout line endings. File enumeration is NUL-delimited because Git quotes unusual names in text output. Machine-path fixtures construct their specimen paths in parts so they do not themselves match the rule. Map native GUI code may reach dashboard data through the game-window crate. Its dependency boundary keeps viewer edits from rebuilding every product. Recorded row readers use the replay facade. Security advisories fail on vulnerabilities and direct unmaintained dependencies. Transitive unmaintained toolkit crates are reviewed without blocking the gate.
