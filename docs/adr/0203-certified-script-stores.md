# 0203. Carry script rows under scope and writer certificates

Script flag and variable snapshots belong to the current acquisition job. They hold rows from the last complete walk and release them with its store. Storage follows the size of the live world. Failure to reserve a held copy withholds its use in a later hour. A load, gap, recovery, running writer, lost registry or failed acquisition also invalidates the relevant hold. This keeps failed or uncertified reads from masquerading as unchanged values.

ScriptFlags watch flag manager addresses. Scope roots do not need an independent watch because native changes to global, country and state roots also build, destroy, replace or clear a manager in the same call. Global construction and teardown follow the game state. Country reuse clears its manager during the appearance reset. State creation and destruction update the roots and managers used by the state table. Those operations move a structure token. A separate character roster token covers the embedded manager scopes and character identities. Daily expiry moves a manager's write certificate only when it holds a positive remaining duration and the update writes it. The non-structure writers mark the individual manager. Notifications track the original call in flight and leave the recorded operation unchanged.

A flag walk checks each scope's kind, ID and manager address against the held one, then compares the manager's registration epoch and sequence. A character's identity and embedded manager header are gathered together. Other unchanged scopes need no manager header read. A complete indexed walk with certificates can skip enumerating scopes in a quiet hour once its scope, structure, roster, census and take epoch agree. The quiet path takes the marked manager IDs before the walk, looks up their scopes and rereads them in walk order. It copies ranges between those scopes whole. A repeated manager cannot establish one distinct stored read. If the quiet path cannot publish its replacement or hold the new ranges, the next eligible walk reacquires them.

The flag sizing census counts managers even when their rows are empty. Before initial installation its complete scope census augments the existing embedded-store sizing offer. A partial census keeps its named refusal and does not size the watch table. Subsequent growth waits for an invalidating boundary. Reuse depends on the certificates, so a sizing hint cannot make a missing read current. The spool can republish an adjacent hour's immutable Flag result without conversion when its held generation agrees. A gap, different witness or refusal requires comparing or dropping that result. Unused arena capacity carries no recorded data.

ScriptVariables keeps the latest complete scope rows, hash headers, entries and key bytes in their published order. It records the scope list using the global root, authenticated country census, state array header and slots, and character roster token. Construction of an owner or loading a character creates its store. A release moves the structure token on entry and return. Native node, header and seed writes mark their stores. A seed-changing context starts only on the main thread, which the hourly callback parks. Because unwinding can write a seed outside a hook, an allocation-free vectored handler moves the structure token on every first-chance C++ exception and lets the exception continue. The next walk reads every seed afresh. Unreadable contexts also revoke the certificates. A fresh registration occurs after its first header and seed read, so that store is reread once in the next quiet hour before future reuse.

The variable family starts observing only when its exception handler can be installed. On detach it counts the handler's active calls as well as writer notifications. The DLL quiescence check also covers instructions on either side of the count. Temporary thread-local stores are excluded when their address is known, since they do not belong to any recorded scope. Locating this address uses native caller-owned thread query storage and caches the result per thread. An unreadable temporary store location keeps the notifications conservative. The ordinary dirty take does not consume the embedded stores' certificates. Initial sizing includes ordinary, industrial organization and faction stores before the first table is installed, without forcing a later invalidation solely to compete for space. In `flag_changes::test_globals`, all tests that notify, size or capture through the shared registries hold the test guard. No game hook is installed in those tests, so the guard makes resetting the registries safe. `Hooks::drop` in both `flag_changes` and `variable_changes` releases watch tables only for hooks that stayed disabled or were removed and drained after the last capture. The variable family normally removes its exception handler during disable and also calls `remove_handler` on drop.

`vectored` borrows the live exception pointers supplied by the OS and treats absent pointers as no record. `install_handler` registers a callback owned by this DLL and `remove_handler` uses the exact handle returned at registration, before the module unloads. The test `the_vectored_handler_moves_the_structure_only_for_a_cxx_exception` passes either pointers to its live local record or a null pointer and exercises both paths.

In `locate_temporary`, the thread query uses the calling thread's pseudo-handle and a caller buffer sized for the documented result layout. It checks success before using the initialized result, then reads the calling thread's TEB and TLS array through guarded reads. The `context_site` observers use the same guarded memory boundary when inspecting the context passed by the original native call.

When the scope witnesses, structure, roster and marked-take epoch agree, variables reread only marked stores and unconfirmed scopes. Unconfirmed scopes include shared store identities and newly registered or unobserved stores. A changed entry range or key span can move later arena positions, so the quiet path either patches only the visited scopes in place when their ranges are unchanged or copies the whole successful output. Other hours visit every scope and read its header and seed. They carry a scope's entries and key bytes only when its scope, store, header and registration are proved current. A changed seed causes a fresh read even for an otherwise unmarked store during such a walk.

The spool's encoder may compare just the scopes a capture reports changed when the baseline token identifies the exact held generation it continued. Otherwise it compares the necessary scopes explicitly. Canonical country order can differ from raw IDs, so an ordinal is a checked lookup hint. A scope addition, removal or key membership change updates that scope's own row. A comparison validates scope and literal-name membership, including duplicate detection. Ineligible or malformed inputs take the complete conversion path with its original refusal checks. New branches, keyframes and restarts can leave no reusable baseline. The optional verification build compares both paths cell by cell after each has left rows in the encoder. Its scratch bitsets and counts belong to the spool, independently of the capture lease. Measurements distinguish comparison, row building and baseline selection and retain both totals and the largest hour.
