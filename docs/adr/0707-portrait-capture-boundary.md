# 0707. Keep portrait arrays at the start of the capture

Portrait holder writes can overlap acquisition. The first writer logs the holder's pre-write array. The reader takes the live array bytes and then consults the log. A writer not visible in that lookup could not have begun writing before the live reads. If a writer did change the array, the reader uses the logged preimage. An absent or incomplete witness leaves the affected source unavailable. A per-thread override applies only to the selected array during that read. [Portrait cache](../../crates/engine-native-politics/src/portrait_cache.rs)

Unchanged descriptors are reused only under a quiet revision covering their holder's writers. Unwatched reads need the revision that includes writes to all holders so they can detect concurrent changes. Every occurrence still checks current owner and array dependencies. Preserve aliases and occurrence order when comparing the census. Cache metadata refers to bytes owned by the acquisition's existing arena, and a changed arena offset misses. Off-thread growth appends unused entries without changing valid offsets. Shrinking the census invalidates slots that were not refreshed because their bytes may have been reused. [Portrait cache](../../crates/engine-native-politics/src/portrait_cache.rs)

The capture retains each entry's role, size, set flag and kind prefix and its identity bytes. The store uses the first installed provider. A fully held walk requires a revision for every key because an unwatched holder still needs live reads. [Portrait cache](../../crates/engine-native-politics/src/portrait_cache.rs)
