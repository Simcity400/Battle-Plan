# Preserve naval and railway save occurrences

## Decision

Read naval save rows in physical writer order, including repeated tags and keys. Anonymous sunk-ship rows keep their vector positions and gain no inferred identity from names or equipment variants. A missing sunk container proves zero rows. A region roster key is a runtime slot and a missing region root remains distinct from a complete empty root. Dominance rows may be omitted for empty values, including inactive slots. Different references can serialize to the same country tag, so keep repeated tags and their values. Sunk and archived records keep raw attribution positions and the literal saved token spellings. Snapshot names can be omitted by writer mode and attribution serializes only when nonempty and permitted. Preserve attribution's byte length. Null or unresolved references are omitted without proving raw zero. A battle reference is unconditional and can hold two zero words. A location is emitted only for a nonnull pointer. Assist records use boolean truth. Ship blocks retain order and can include convoy handles, country tags are not sorted, and the `air_wing` key is independent of its caller's kind.

The launch-base projection takes the shared parser's original country occurrence sequence, with position and literal tag rather than a tag map. The game writes physical countries after slot zero. A navy with no base list is known empty and a missing navy stays absent. Retain signed province key order and repeated keys. The base holder's raw country word is unsaved. `disabled_for_repairs` retains each serialized country occurrence including empty and repeated tags. Use the authenticated save country projection for standing orders and repair work too. Preserve missing unconditional fields and accept native false and empty meanings for omitted conditional fields. Mine reports retain victim then mine owner through their repeated country keys.

The mission writer always writes mission and underway replenishment. Fuel and requested fuel appear only when nonzero. Headquarters repeat once per attached headquarters and a leader appears when different from the invalid reference. Convoy counts appear only when strictly positive, so omission proves nonpositive rather than raw zero. Presence rings retain head-to-tail positions. Patrol, spotting and raiding-grid operands bind their authored spellings through recorded lexical tokens. A stale patrol target full reference is still present and only zero progress and chance are omitted. Spotting caches are only emitted when positive.

## Theatre and railway operands

A land theatre keeps the unit reference order, the member of each controller area that the native writer selected as representative, and the ordered embedded group definitions. The representative list is one anonymous `area` array and omission is empty. A keyed entry is malformed. Keep regular-group and army-group occurrence arrays separately. Their shared reader uses the saved field-marshal flag to interpret each row rather than assuming the type from nesting. Nonempty names serialize outside checksum mode to their first-NUL prefix. Member, child-group and headquarters/leader references retain occurrence order and absence. Motorization and the field-marshal flag are unconditional. Withdrawal is emitted for a nonzero byte. Negative stored distances and region operands are omitted, with no evidence of one specific sentinel. Saved theatre-group references remain separate from the definitions they name.

Railway saves hold neighbour-indexed levels in province definition order, using the same adjacency walk as movement and bottom-first stored bitmap rows. They do not use the live sorted railway pairs. Definition position must agree with ID for the template roster and colour lookup, and known empty adjacency differs from an unknown province. Nonpositive cooldowns are omitted. The parity fixtures cover the game's fixed pixel start for 24-bit files and refuse a top-down file the loader's read cannot establish.
