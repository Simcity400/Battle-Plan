# 0007. Snapshot a verified Boat toolchain and dependency cache

Routine Rust checks clone the `hoi4-record-once` image. `boat.py snapshot` rebuilds it from itself, or from the `hoi4-check` base when it is missing, so a new base reaches checks only once `hoi4-record-once` is removed first. A clone takes the machine size the run asks for, or a large machine when the image's disk does not fit that size. Updating the base is a provisioning task. Start a fresh VM, push a clean main worktree to the source directory expected by `boat_setup.sh`, copy the setup script, and run it with that worktree's commit SHA. Snapshot `hoi4-check` after provisioning and verification succeed, then shorten the lifetime of the provisioning VM.

The image warms test targets and operational artifacts with the toolchain pinned by the worktree. Its Clang wrapper translates the forced-include argument used by `libudis86-sys` to the spelling supported by the CL driver. The release snapshot includes the viewer, recorder, collector and columnar check tool under Cargo's normal release profile. Provisioning records the source revision and toolchain versions so failed or mismatched image changes are traceable.

A resumed or cloned VM accepts commands within seconds, but a run waits until Boat reports its filesystem hydrated. Until then, files from older snapshot layers show whole-second mtimes, and Boat's final reconciling pass resets mtimes that were restored earlier, so Cargo's freshness checks are only sound after hydration. To hide the wait, `boat.py wake` starts resuming or cloning the VM a run would take before the caller's local work, with the run's normal lease and no idle tail of its own. A run gives up on a VM whose hydration advances less than 0.5% of its entries, and does not change phase, for three minutes. Claiming a VM checks that its toolchain runs; a VM whose toolchain does not is quarantined, and the run takes the next.
