# 0007. Snapshot a verified Boat toolchain and dependency cache

Routine Rust checks clone the `battleplan-check` image. It holds the toolchain pinned by the worktree, the Windows SDK, the UI's node modules and the dev-profile outputs of a whole-workspace check. It leaves out incremental sessions, release and test builds and compile caches, so its disk fits a default machine and hydrates quickly. Release and test builds start cold on each VM.

Building the image is a provisioning task. Start a fresh default VM, push a clean main worktree to the source directory expected by `boat_setup.sh`, copy the setup script, and run it with that worktree's commit SHA. The script ends by pruning the VM to what a check reads. Verify cold and resumed checks on default clones, snapshot the VM under the image's name, then shorten the lifetime of the provisioning VM. `boat.py snapshot` refreshes the image from itself on a default VM. Use `--from <snapshot>` to provision from a named image. The build clears every build output, checks the tree whole and prunes the same way, so outputs of crates the tree no longer has do not accumulate. A check clones at the machine size it asks for, or a large machine when the image's disk does not fit that size.

The image's Clang wrapper translates the forced-include argument used by `libudis86-sys` to the spelling supported by the CL driver. Provisioning also builds the viewer, recorder and collector under the release profile to prove the toolchain, then prunes them. It records the source revision and toolchain versions so failed or mismatched image changes are traceable.

A resumed or cloned VM accepts commands within seconds, but a run waits until Boat reports its filesystem hydrated. Until then, files from older snapshot layers show whole-second mtimes, and Boat's final reconciling pass resets mtimes that were restored earlier, so Cargo's freshness checks are only sound after hydration. To hide the wait, `boat.py wake` starts resuming or cloning the VM a run would take before the caller's local work, with the run's normal lease and no idle tail of its own. A run gives up on a VM whose hydration advances less than 0.5% of its entries, and does not change phase, for three minutes. Claiming a VM checks that its toolchain runs; a VM whose toolchain does not is quarantined, and the run takes the next.
