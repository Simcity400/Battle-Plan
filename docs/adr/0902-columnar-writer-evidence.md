# Stage columnar updates and commit through the reader

A table writer compares candidate rows against held state. Changed cells use ADD or PATCH when they cost no more than SET. A FILL can represent an equal value shared by at least sixteen changed cells and at least half the table's rows. Both one-row-at-a-time input and batched input generate the same section. Commit applies that section through the reader so the writer and journal walker keep the same state, read evidence, sample hour, and truncated view.

A complete census deletes held rows it did not visit. A partial read records the visited rows as its view and cannot infer deletion. A certified sparse update changes only visited rows and explicit removals. A kept cell requires a held row and bypasses comparison. An unrecorded cell carries explicit missing-data evidence. Sample hours distinguish a successful read at the current hour, an untimed reset, and carrying an acquisition from a known hour.

Each prepared section belongs to one writer. Staging normally clears only the columns used in the current or prior hour so quiet hours avoid per-column work. After refused, dropped, or unwound staging it clears all columns so residue cannot reach the next commit. Batch storage is held for reuse and cells can only follow an emitted row key.

The newest preparation alone can commit and belongs to the writer that made it. Commit failures before table mutation leave the writer available. An error during mutation poisons it because held state may no longer equal the reader's state. The restart stores enough evidence to resume with the same bytes, including the last complete read when the table preserves one and the current view is not that read. Complete batches that repeat the exact held order can use known slots without a key lookup. New keys are staged in visit order but take the lowest freed or unused slots in key order, then grow the table. The free heap remains unchanged until commit. A truncated view excludes deleted rows and includes a reused slot once. Producer NOOPs preserve explicit writes of an unchanged visited cell. TOUCH records a producer witness without substituting for a cell value.

Strings use append-only IDs for exact bytes, published before use. Parallel preparation may read the shared dictionary but cannot assign a new ID. If it meets a new string, the table is prepared again in table order with interning enabled, yielding the same IDs as serial recording.

The PATCH matcher tries a cheap prefix, suffix or same-length edit first. For larger unmatched interiors it probes nearby equal windows for moved runs, making forward-only copies so the resulting hunks can be applied in order. The search is bounded and preserves the moved-run edit only when it beats the cheap edit and costs no more than half a full cell. An unrecorded inserted cell carries an internal type-correct placeholder, distinguished by its independent missing-data marker. FILL records explicit exceptions among the final live slots, accounting for inserts and deletes.

Byte-wide integers remain raw. Larger signed differences use zigzag, while unsigned negative differences wrap to the width before size comparison. A value becoming present after an absent or unrecorded state uses SET because the old state supplies no numeric baseline, even when the held bytes look close. A uniform run may still select one SET over individual ADDs. The writer validates row shape, duplicate visits and removal conflicts before committing. A quiet partial read still records the rows read, and a later complete read clears that view. A quiet partial read can retain known row order, but adding or removing a row invalidates the shortcut.
