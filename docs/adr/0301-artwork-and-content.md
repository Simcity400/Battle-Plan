# 0301. Resolve artwork from recorded choices and current assets

Focus products keep national and continuous definitions separate even when the databases share IDs. A refused definition file can make a focus’s definition unknown only in its own database. The focus tree tests its country-and-ID and ID overrides in authored order, ending at the first declared or refused override. A definition icon’s conditions need the recorded country and hour only when the selected draw can reach them. Event rows evaluate the definition at their own recorded hour and carry that sprite choice into a later draw. History can report a definition’s static duration without expanding dated names and descriptions or selecting icons. Requests for title, details and icon each plan only the inputs they can reach. A country-qualified override can make an otherwise static icon depend on the requesting country.

The context for scoped expansion reads immutable inputs at one hour and caches shared recorded rereads. Each item owns its own scopes, variable session and random counters. Clock and the exact focus ID seed expansions when they use random values. The rendered name uses its recorded scope, while descriptions that require a country suffix use the owner’s own tag. Empty and key-identical authored localisation values remain valid. A missing key is unavailable. Focus text can be scripted, while full technology names use the plain view. Unknown definitions and missing art have named findings in both offline preparation and interactive answers. Separate folder warnings stay on research replies. A failed icon batch retries through ordinary individual reads, preserving named outcomes for each item.

Technology names fold ASCII for matching, retain content order, and use the recorded template index when a token has multiple definitions. An unread file can make later indices unknown. Without an index, merge only equivalent presentation values and refuse conflicting definitions. The recorded DLC roster, independent of the row-hour scope, supplies content-load category and feature conditions. Folder definitions group and colour the result and cannot withhold artwork or text. Use the first eligible folder in authored order. An earlier unknown eligibility keeps the answer unknown, since the earlier folder may take precedence. Undefined folders are unavailable and named. Technology icon tokens select badges independently of the recorded definitions used for text and findings.

The exact-sprite route accepts authored keys without suffix guessing and uses the native zero-based sampler, including offsets past the authored strip. Validate without decoding the image so an absent key, refused definition and missing texture can be reported individually. The supplied recorded choice is reused on fallback when a presentation chose a different sprite. Nested strict draws repeat the entire choice under the same rules as catalogue artwork. The stockpile icon is named by the topbar stockpile container’s sole artwork item. Ambiguity is reported by the authored paths, and positive authored frames are converted to zero-based indices. Preview images have a bounded maximum edge. A native no-texture outcome leaves a named, visible placeholder. A whole sprite request that exceeds the reply limit is refused as a unit.

Portrait roles select the recorded holder for the requested role and size, with the first entry of that size as a fallback. An unset entry requires native generation whose inputs the recording does not carry, so a generated and a missing portrait remain distinct outcomes. Draw through the catalogue’s transaction and credit the recorded-style fallback on every reuse. Images are drawn outside shared cache locks.

One art status travels unchanged from a product's reply to the painted slot and its hover: ready, pending, not recorded with what is missing, refused by name with why, failed (retryable or not), and confirmed missing. Confirmed missing needs a completed search of every layer that could hold the file, so an unmounted layer, a path no layer can hold, an artwork that names no texture and a file the decoder refused are refusals, never misses; only an affirmative relay counts as evidence. Undecoded art keeps its address and draws as pending, so the painted window knows it before any decode. Each status has its own slot: nothing while pending, the hatched tile with initials or tag only for confirmed missing, a plain hatch for not recorded, a struck tile for a refusal and a dotted tile for a failure; the hover names the reason, and "art missing from the current installation" only for confirmed missing. Table cells carry the status and the handle key; the audit compares the key, never the status.
