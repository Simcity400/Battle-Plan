# Columnar streams preserve missing data and bound replay work

A block's table unit is partitioned into parts in hour order. Pending events arrive in hour groups of slot gaps and payloads. A zero slot marker followed by the hour starts a group, including when events go out of slot order. At close, events are stably sorted by slot and split into separate tracks when slots are reused. Inserted rows carry the final cells of their insert hour in insert order. The first part captures both raw and difference codes so its choice of numeric model can stand for the run. Repeated list literals can be pooled, with separate bits for a pool reference and an unrecorded cell.

A part closes at the pending cap, the combined pending and chaining budget, or the block's end. When the shared budget is reached the largest table closes first. The directory stores each column's model, track lengths and the boundaries of its pool, inserted values and events. Track headers record slot gaps, event counts and an insert hour for tracks born in the part. Lifetimes encode hourly deletes and inserts as runs of slot gaps and key differences. The strings stream names IDs absent from its last restore. Read and touched streams track slots without cell payloads. Large streams compress individually against the preceding corresponding stream in the block. Small streams share one frame. Compression runs off-thread and delivers frames in close order.

The budget schedules a close without dropping data. Waiting raw jobs are tracked separately from open parts. The same compression worker handles file-owned frames behind previously submitted jobs. A frame entry carries the first 16 bytes of its stored BLAKE3 digest, and page entries encode frame offsets as differences. Small-frame headers give each stream's ID and length. Table entries retain status, read and sample runs and whether a table was packed, with the table class shared by its parts. Sample codes use 0 for absent, 1 for the current hour and a zigzag value plus 2 for any other hour. That lets consecutive current-hour samples stay in a single status run. A correction within the same hour replaces its run entry and refusal reasons are named strings.

Fetching verifies and decompresses a part using the preceding part as its prefix. A cursor can advance through several fetched parts in one call without reading the file, and reports when it needs the next part. It applies older tracks, lifetimes, then newly born tracks. Opened directories validate stream bounds before event decoding. Frames share their padded storage across streams and spare backing allocations can be reused across threads within a process-wide cap.

Each thread keeps its own decompressor and stored-byte scratch buffer, with a fresh one when a fetch is reentered. Adjacent stored frames can share a read. A prefix owns just the prior part's shared raw streams. Missing predecessor streams are refused by name. An old row and subsequent rows in its slot are distinct tracks in directory order. A step normally avoids materializing a row both born and deleted during it, unless its slot requires growing the table. Observing deletes requires applying a newborn row's own tracks before the callback. Long contiguous deletions can clear a slot run at once when no callback is watching. Inserted columns without a stream begin as unrecorded even if the same slots held recorded values. Read and touched markers do not change cells, and passing a part does not move them. List patches may update the page in place while rebuilt cells are written once at the step's end. An opened track can expose pool references as literal events to its consumers.

The writer compares encoded sizes before choosing literal, same-length patch, front-and-back edit, or copied pieces for a list or opaque cell. A tie keeps the literal. Patches apply to the held cell, while edits and copied pieces rebuild another cell. A copied piece stores its source position relative to the previous copied piece's end, can include small differing spans, and ends when matching cannot justify running farther. The reader must be able to skip a payload with the same boundaries it uses to decode it.

Numeric tracks hold values, missing cells, and unrecorded cells separately. Their event code puts zigzag numeric payloads under a clear low bit and uses separate set-bit codes for missing and unrecorded. The stream models cover differences, raw values, second differences and repetitions of an event's gap and code. A step skips groups whose earliest event lies beyond the target hour and writes each reached cell once. The numeric loops check the padded frame and each track's own boundary, report damage after the loop, and resume at the same track after widening its column or allocating presence bits. Insertions and deletions within one step still advance their tracks. Any deleted row requested by the caller is handed over at its last live hour before the slot can be reused.

Whole restores establish each stream's chunk boundaries. A later restore compresses each changed chunk against the corresponding whole chunk so restoration needs at most two extents per chunk. Restores scatter rows and numeric values by live slot and pack list cells by page, avoiding per-cell row construction. Rows store live bits and key deltas, or only the key changes from the whole chunk. Lists store length, the unrecorded flag and bytes. The meta stream retains status, sample hour, rows read, named strings, and a distinct last complete read. A log restore stores its count and listed row ordinals, with the lowest listed ordinal followed by its bitset. An empty set starts at the count. A log stores no keys or columns in its restore.

The run's first hour supplies its first restore and has no ordinary state events. Log appends are still read in that hour. At block end the encoder restores after the configured changes or blocks, periodically writes a whole restore, and can pack sparse live slots during a whole restore. Each whole stream fixes the next chunks' offsets and boundaries. A restore reuses unchanged chunks with matching bounds, and can reuse the entire restore when the table has not changed. New chunks past the old extent have no prefix. Incremental restores list only strings missing from their whole one. The parts name other strings afresh. Log hour scratch allocation is dropped when a part closes to keep resumed budget decisions consistent with an uninterrupted writer.

A saved encoder restart names each table's restore rule, its last whole restore, the run's raw or difference choice, the strings named since the restore and the last status. Restart comes from a closed block with no pending data. Counting touched or read rows into slot order avoids sorting each mark and uses two bytes of hour scratch per mark. A run's final block holds no raw streams for another part to chain to.

Logs hand each hour's appended rows over before its forgotten ranges, even when both occur in the same hour. Hourly callbacks use slots within that hour's appended rows. Ordinal queries use slots in the selected rows of the enclosing part and require strictly rising exact ordinals for `log_rows_at`. Queries hand newly named strings over before each row, drawing from the current block's preceding restore and decompressed parts as necessary. A cursor exposes its strings separately. Parts chain for decompression, and ordinal queries only walk the parts and decode the cells they require. A run whose table changes between log and state is refused by name.

Log ordinals are 64-bit. A batch of forgets is validated atomically, normalized to ascending order and encoded the same as individual forgets. An unchanged log can reuse its restore, while a status change alone is enough to refresh it. The journal adapter maps inserts and deletes to appends and forgets, with no inserted values on a deletes-only hour. A later update to an inserted log row or reuse of a prior key refuses that table from the affected hour, without invalidating neighboring state tables.

The journal walk keeps state and last-hour changes for synthetic journal construction and grammar tests. Recordings are read through the columnar unit reader. Older journals hold a prefix of the schema's columns and the remaining columns of inserted rows are unrecorded. For a truncated read, the walk reports live rows actually read and new rows, with a reused slot appearing once. Resampling can reset the sample hour even when the table still holds the same rows.
