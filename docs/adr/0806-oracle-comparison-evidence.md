# Compare oracle operands at the boundary that produced them

The oracle distinguishes evidence a save can compare from facts it omits, a table retired by the format, and a reading that is missing or refused. Compare a forced read or an owner's scheduled read at the selected hour. A carried row is left incomparable to a later save. Only a proven full walk makes other owners current. A held shared buffer can shift one walk without making it a full read. An owner with no rows still counts if its read ran, while an alias link cannot make its canonical owner current. Apply this rule before resolving a carried row's links because those links may already have changed.

Saved relations use the recorded tag dictionary and one canonical slot per owner, including ordinary self relations. Unknown spelling leaves other fields comparable. Offered access reverses endpoint direction. An attache comparison uses the receiving slot, while a relation written by both endpoints remains one pair. A signed-high navy access mode is omitted by the save and remains a named limit. Current logical ownership does not constrain a historical set. Frame evidence may explain a timing boundary, but never waive a discrepancy. Tests using synthetic saved operands exercise the comparator without claiming native acceptance.

Use each field's actual save representation. Camouflage follows the ordered nonzero weights, the save's maximum when present, and the recorded threshold define. A force refresh performs work even off-slot. Exact organization and grace comparisons require exact operands when the format recorded them. Displayed grace follows a whole percentage of the loaded maximum toward zero. An omitted block cannot prove a serialized zero where the field is written unconditionally. Grid placement remains distinct from grouped battalion totals, and the parser treats partially zero handles as real values. Color compares through the save's truncating conversion, including its out-of-range result. An absent saved control value cannot be reconstructed from raw zero.

A recorded template's fallback key can require comparison even if the string has a leading NUL. The save truncates a key at NUL, while the hourly stored-length check can still select a nonempty stored value. Daily key presence is tested independently of hourly selection. Movement speed keys only include nonzero modifiers, while the selection cache that derived them is absent from the save. A save parser fixture reads those operands through the public reader so test values exercise the same presence logic.
