# 0308. Keep battle identity, observation and finalization distinct

Land battle identity, peaks and ends come from the recorder's derived tables. Recorded combat, side and progress histories supply sizes, countries and loss counters at the hours those data change. Edges and rankings read the needed spans and battle rows. Settling the date of a carried counter starts with a one-day lookback, which expands sixteenfold for the keys that remain unresolved and never crosses that combat's earliest possible hour. The combat's native duration advances within a run. A terminal flush becomes known when the end row is written, which can be later than the game event. An older replay without terminal equipment rows leaves that information absent. A window carries the last observed loss read into its starting hour with its original date, and a window holding an end can display the last census run. When a result arrived without a battle, its write hour is part of its identity and limits when it appears. Several result writes can share the same combat and end hour without representing one event.

The loss course uses exact signed fixed5 design counts and keeps identical names distinct by handle. It emits every design for its first read and whenever the design set changes, then records which positions changed. Land rankings read the last hourly loss counters before an ended battle's final flush. Casualties rank falls back to peak size if no battle in the range has recorded casualties. Country filters include a side whose roster is incomplete, since the missing members could belong to the requested scope. Terrain labels use the matching category from the recorded mod stack's province map and localisation. A missing label remains unavailable.

Naval live battles use recorded participant histories and the derived battle identity and size. A participant without a ship denotes a convoy. Retained outcomes join only through `NavalResultObservations`. A result's countries are retained with their own observation evidence. Window rows cut on changed visible values, and the ranking uses the last state in the requested range. Several battles at the same hour share their fleet reads. A forward seeker reuses each table across the hours. A sinking list carried into a read uses the last actual read at or before the hour, including at block boundaries.
