# Preserve project identity and independent table outcomes

Project status belongs to each authenticated country. A missing status is a failure because serialization and daily updates require it. The project pool uses the native live extent and includes projects that have never started. Project IDs are local to their owner, and the raw owner link survives alias authentication for this census. A selected walk skips unselected status and pool reads. Partition walks defer global duplicate validation to the ordered join.

The project and its history share an authenticated census. An identity failure can withhold both. Lifecycle or state-machine failures withhold project rows and can leave history usable. A malformed history withholds the history only. Counting can stop reading payloads once their table's capacity is exhausted. Identity and state-machine words are gathered in bounded batches before row validation. The batch width affects precedence when an early validation failure and a later read failure share the same batch. A failed lifecycle field is never retried or used to select a state-machine read.

The state machine keeps one prototype and three simple states inline. Capture validates the selected state as one of those four. The phase gather stays within the state machine even if the pointer will fail validation. The row records signed fixed-point progress and a signed whole-unit target. Prototype progress and iterations are separate from the history count. History keeps the parent identity and vector ordinal. Its reward handle can repeat. The pending reward is identified by its occurrence in the authenticated template, because identical tokens can name different offers. Optional historical references are copied only when their native presence byte is set. Absent payloads may be uninitialized.

Programs are rooted in country status. A program can appear through multiple roots. The caller supplies candidate pointer scratch so the census can deduplicate before materializing rows and account for the complete input demand. Insufficient scratch refuses the census because the skipped pointers might be aliases. The program's own owner is independent of the rooting country. It verifies both copies of the owner and province links. A presence flag determines whether the active project handle is read. The native index resolves that handle. Scientist references retain the distinction between a zero and a typed null. Primary assignment precedes supporting scientists in native order. The acquired membership feeds details without a second native roster walk.

Breakthrough progress walks the tree from its sentinel's minimum link and verifies the exact count and signed key ordering. Its cycle detection uses the existing link stream, avoiding extra reads and allocations. The sentinel's payload and node padding are outside the link read.

Daily facility details retain the signed widths and rounding rules of their native numeric operands. They visit the selected building, project, assigned scientists and project-requested modifier keys. A complete skill roster without the requested specialization supplies the native zero level. Assignment records and facility details can fail independently. The application idler used for current map presentation is separate from game state. In-game activation sets both owner roots, while frontend activation can set only the primary root.
