# 1303. Publish exact political fill updates on encoder submission

The GPU field follows an independent CPU oracle, including both channels and delayed and incremental updates. Map IDs, geometry and the compiled kernel belong to a weak, device-specific shared owner. Each distinct displayed fill has its own tables, boundary masks and textures. Equal tables can share a state across views. One view can update a state it alone shows. If another view still shows it, take an unused state from the pool or allocate. Keep at most one spare per live view and reuse its retained tables to make the next update incremental.

Loader, display and teardown can run on different threads. A single registry critical section owns every claim, release and pool transition. A recycled or exclusively claimed state stops advertising its former fill before the lock drops. A claimed state is published only once its new tables are installed. Local strategic styles can vary per view without cloning hour geometry. Moving a layer between channel halves recopies its whole output while an unchanged layer stays incremental. An unshown layer may retain pending work until shown.

Dirty province boxes cover the full search halo, including wrapped cells and candidates crossing another shape. A changed region style invalidates all member provinces. Exact membership includes nonzero keys with no bitmap pixels. CPU region lists let a partial update mark members without scanning the full map. Plan allocation and validate limits before mutating state so a refusal preserves the current fill. A new state begins with a copy of warmed strategic output. Its first update only redraws differences. Region or lookup growth can require a whole update with all pending modifications included.

Dispatch and copy each state's output together in command order. The distance and output buffers can be shared because copies read only the rectangles recomputed by that dispatch. Boundary masks cannot be shared because an incremental update reads retained cells. One compute pass records the ordered steps to avoid repeatedly opening passes on the display thread. Texture copies preserve exact bytes in both channels. A pending update is finished only after its encoder submits. Dropping an unsubmitted frame releases its recording token without clearing the pending update, allowing the next frame to record it again. Regression cases exercise the registry interleavings and shared scratch across views as well as aborted frames.
