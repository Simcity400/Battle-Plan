# Keep script-variable reads and writes in the game's evaluation order

An operand can invoke an alias condition, write temporary state, or advance a random stream. Playback therefore preserves evaluation order and reaches an input only where the game would. A second authored read is unsafe to substitute for reusing an evaluated value, and reusing a value is unsafe where the game performs a second read.

## Storage and scope identity

- Persistent global, country, state and character stores come from the recorded `ScriptVariables` rows. Project and industrial organisation definitions use separate recorded stores. A store the complete recording does not supply is withheld. An existing complete store can prove a missing key, which uses its authored fallback or zero. Ordinary duplicate keys use their last value. Organisation entries were sorted without tie order, so a duplicated organisation key is withheld.
- Built-ins take precedence over stored keys. `has_variable` checks stored keys only. A temporary operand checks the thread-local store alone and does not read its default on a miss. A literal is present. Saved targets consult the described event chain before the global registry. An unsupported writer can invalidate even an injected temporary, and an outer script context the recording lacks can leave unwritten values unknown.
- Numeric localisation sets its character fallback only for the outer operand. Its nested targets, indices and defaults use normal evaluation. A bounded roster permits a known character lookup even when unrelated recorded rows are truncated. Ideology specifiers decode their already evaluated value so a random or temporary read is not repeated.
- A scope identity uses its encoded country tag or state ID with the corresponding discriminator. Turning a country leader identity into a `var:` scope decodes its country through the clearing setter. A null state reads the global store, while a missing state ID is only known null if recorded state membership and recorded content justify it. A positive integral fixed5 can also name an existing state.
- Store selection precedes random and built-in callbacks. Organisation and project selection takes precedence over the generic store path. Built-in callback indices evaluate in the caller and their targets in the store's scope. A faction leader callback reads its first stored member. Constructed variable keys use lowercase country tags, state IDs, or whole and fractional numeric suffixes. A numeric suffix evaluates its target again. An indexed target's check runs before the next index because it can write a temporary that the next index reads.

## Numeric and temporary evaluation

- Scope and comparison operands that parse into an existing object can retain previous fields. A numeric replacement changes the literal state while keeping fields the explicit TLS lookup can still use. A comparison reads its value side before its variable side, then compares signed fixed5 values. A variable reader that sees no supported block starts from the game's initial zero values. Array membership uses a truncated signed length, exact fixed5 comparison and an early exit on a match.
- Mutable temporary lookup always uses the shared thread-local store, even with a persistent-looking prefix. It evaluates the initial operand and inserts before evaluating the right side. A plain assignment can overwrite an unknown initial value without reading it. Arithmetic reads the target only as required, because a right-side alias can change it. Clamp reads minimum then maximum and applies maximum then minimum. Modulo caches the floored, narrowed destination before evaluating its divisor. The divide effect reads its supplied fallback through the thread-local store even when it will not need it. The divide trigger's reader treats that field differently and a zero divisor leaves the inserted destination untouched.
- Temporary descriptions execute before evaluating their displayed right and left operands. A failed writer leaves dependent results unknown. Persistent descriptions do not execute writes. Random setters read both endpoints before the destination and consume no random value for reversed bounds. Supply setters use only the bare truck and train forms, and apply the native fixed5 rounding and minimum to those operands. Unsupported expression instructions are refused only when reached.
- Variable seeding owns a different stream from event iterators. Initialise it lazily from the original context's `THIS` and immediate `FROM`, using country, state, character, combat leader or global scope in the game's order. Organisation and project stores do not seed it. An unknown writer forbids reseeding. Scope identity display uses canonical slots, while the country-presence gate uses the signed raw reference. Narrow arithmetic at the native steps and clear only the high state bit when storing the newly mixed seed.
