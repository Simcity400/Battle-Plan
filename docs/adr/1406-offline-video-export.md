# 1406. Offline deterministic MP4 video export

BattlePlan exports smooth, constant-frame-rate MP4 videos offline rather than screen-capturing live playback, so slow GPUs, high speeds, and background work never drop frames or show half-loaded assets.

## Encoding and safe file publication

1. **Shared `VideoSink` (`crates/video-export`).** Both map and dashboard exports feed opaque sRGB RGBA8 frames (and optional 44,100 Hz stereo PCM) into one `VideoSink` abstraction. Dimensions must be even (required by H.264 `yuv420p`) and are validated against GPU and encoder limits with named refusals rather than arbitrary caps.
2. **Windows Media Foundation + system FFmpeg.** On Windows, `MfSink` delay-loads `mfplat.dll` and `mfreadwrite.dll` via `LoadLibraryW` + `GetProcAddress` so Windows N editions launch cleanly and return a named refusal when the Media Feature Pack is absent. It converts RGBA8 to BT.709 limited-range NV12, negotiates `MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS` with automatic software MFT fallback, and sets `MF_MPEG4SINK_MOOV_BEFORE_MDAT` for fast-start playback. `FfmpegSink` locates `ffmpeg` from Settings or `PATH`, pipes raw video on stdin while writing optional stereo PCM to a sibling temporary file, remuxes audio with `-c:v copy -c:a aac -movflags +faststart` (avoiding dual-pipe deadlocks), drains stderr on a dedicated thread, and binds the child to a Windows Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. No runtime binary downloads are performed.
3. **Staged publication and close guard.** Long exports never hold a `replay_settings::exit::EXIT` receipt during rendering. Frames are encoded to a sibling staged path with an explicit MP4 container; closing BattlePlan while an export runs prompts via `Leaving` ("Keep exporting" vs. "Cancel export and close"). On completion, finalization acquires an `EXIT` receipt only for atomic staged replacement (`Receipt::replace_staged`), preserving any prior file on cancel or error. On render-side failure after frames have been written, the sink is finalized first; only when a valid playable MP4 prefix exists does the UI offer "Save partial through [date]" via `Receipt::publish_distinct` to a non-clobbering filename.

## Deterministic timeline, map rendering, and offline audio

4. **Shared frame schedule.** Every export builds a deterministic `FrameSchedule` from `dashboard_query::timeline::resolve` (actual recorded stretches, load joins, and unheld gaps). Linear mode draws an explicit dated gap card over unheld hours; opt-in gap skipping inserts a fixed-duration dated cut card (counted in output duration, visible even when the corner date stamp is off). High-speed linear frames scan the full traversed interval so short gaps and loads always reset visual continuity. Multi-track comparison pages advance on one clock and skip an interval only when every advancing visible track lacks coverage.
5. **Private isolation.** Offline map exports allocate a private playhead (`playhead_host::open_private`) and private source lease so they never move or disturb the live map playhead. Camera placement (`Camera::placement()`), map options, and proportional `ui_scale` are frozen at export start; static crops project through that placement without post-scaling blur. Unverified-content banners are preserved even when interactive diagnostics and popups are hidden. Quiet unchanged hours resubmit the previous RGBA buffer at constant frame rate.
6. **Offline audio.** Map exports with audio enabled drive `viewer_audio::OfflineMixer` (a private `Engine` with synchronous WAV/OGG decoding and a 1,024-frame callback accumulator) to emit exact cumulative 44,100 Hz stereo PCM per video frame without opening an OS audio device. Audio defaults ON near real-time speeds and OFF on fast timelapses, and remains user-toggleable.
