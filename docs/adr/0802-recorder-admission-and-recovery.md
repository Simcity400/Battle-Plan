# 0802. Bind each recording session to its admitted loads and output

The recorder worker observes one game process at a time. It distinguishes processes by PID and start time and retries temporary probe failures. A withheld probe due to an unrecognized build stays withheld for that process while admission can still attempt capture. A manual Record pressed at the menu belongs to the first campaign evidenced by the spool, including a campaign loaded and closed before the next probe. That choice follows the same campaign to its proper folder when a session rejects the load as belonging elsewhere. A failed settings read cannot admit the load or choose its destination. The recorder reports any omitted loads that recorded hours, and gives a common reason only when it applies to all of them.

Capture targets and mode are fixed for the admitted session. The worker retains the session root even if settings changed as capture began. It rereads the Auto save preference when deciding what to do, using the last successful setting if the read fails. Abandoned captures are revisited at startup, after a game process exits and on subsequent idle checks with backoff. Their collector must leave or the game must exit before they can be finalized as waiting recordings. A capture failure holds the game until restart or a manual Record. Stop holds only its load, so a later automatically admitted load can record. If rerouting a refused load requires a probe that cannot identify a loaded campaign, it holds the game to avoid repeatedly attaching at the menu and encountering the same refusal.

The worker decides Stop against the same state lock used for completion, so a late request cannot carry into the next capture. Quit waits for the selected Save or Discard, the unload observation and any pending discarded-spool removal. The dismissed Stop prompt cancels a Quit waiting on it until saving or discard has started. Replacement by the installer goes through the record loop's idle boundary and waits until pending actions are safe. An updater request can be withdrawn while queued but needs its actual answer once the worker takes it.

The panel holds a finished result or failure until the panel has seen it. Live status from a previous load does not supply a date or flag for the next load. When the game can identify a load but its first hour has yet to be recorded, the game supplies the date until collector status arrives. An unread status leaves the last observed progress count. A flag lookup runs off the worker loop and is applied only to its original session, campaign and keys. A current lookup that found none clears the previous display for that campaign. The recorder schedules post-save recompression only after successful publication, and hours left unsaved remain available in the recordings list.
