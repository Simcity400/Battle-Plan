# Keep carried observations tied to the native writers that can change them

One collector observer owns each native site. Other capture families receive notifications from that owner. Installing or restoring a family uses one thread census and suspension shared with other families in the runtime round. A thread in any of the family's sites or taps delays the entire family until a later attempt. The host prepares and frees observation storage off the game thread. The game thread starts an hourly boundary before any capture. A quiet certificate is available only while every relevant writer is observed and no such writer is in flight. Loads, gaps and recovery revoke older certificates.

## Shared capture inputs

- Crew inputs combine the country-input refresh and damage notifications with forwarded equipment-loss notifications. Losing either observer withdraws the quiet certificate. The weather carry diagnostics record work separately from native writer counts and measure province modifier capture time in QPC ticks.
- The division panel checks the live variant capability at admission. A source/provider identity can invalidate the operand domain without identifying a variant to register. Lifetime changes mark old bindings before storage moves so the next worker reacquires membership before following variants. Cold range reads register the receiver they read. Passive lookups preserve pending marks for the ordered consumer.
- Doctrine notifications share the world-input family's publication and lifetime. The parked Slow worker receives coalesced receiver marks, while occurrences retain effective gain operands, grant order and expiry counts. The gain tap already has the native store's operands and can copy them without an extra memory read or ownership scan. Grants settle earlier expiries before reanchoring their owner. Receiver mark storage is prepared independently of the writer tokens that bracket native reads. Preparation uses a complete owned census, including empty censuses. The callback uses a try-lock and records loss on contention so it never waits for that storage or mutates the row journals.
- Occupation certificates let the capture reuse unchanged inputs without validating their native dependencies again. The owner forwards the daily diplomacy update through its original call for both war-goal expiry and exile legitimacy. A failed holder lookup revokes the certificate domain without attaching the change to a synthetic zero key.
- Project variable stores gain an owner from the selected project census. Registration grows with observed demand. A failed lookup or contended map revokes the held detail and selection once so later acquisition can recover. The project certificate remains independently available. A failed lifetime sweep cannot declare a registered owner dead. Project-pool resets invalidate retained stores on entry and return.

## Province and fleet observations

- Province row carry and area refresh consume the same province marks from one drain. State marks also expand through the membership retained by the row carry, so a native reset can empty its own list without hiding affected provinces. If the drain refuses or drops a mark, both consumers read afresh. Either consumer can take marks on its own, and the marks stay available when neither is present. The raid observer supplies the separate state modifier marks used for fortified provinces. Diagnostics count full, quiet and marked hours and distinguish carried rows, read rows and refreshed bunker terms.
- Naval province combat carry retains the prior census of provinces with combats. It revisits those and marked provinces, because a province previously empty and untouched still has no combat vector to capture. The running guard spans each writer. An unreadable ID or the zero sentinel invalidates the domain, causing a full capture. The latest complete walk supplies sizing for the bitmap. First prepared storage can install immediately, and larger replacement storage waits for an invalidating boundary. Diagnostics count reused and read provinces, quiet hours and full reads.
- Fleet region comparisons treat membership as a multiset. Known append, clear, remove and prune paths can change it only when their counts change. Permutations preserve the observation. Construction, loading and destruction revoke any retained observation of a reused address. A fleet the watch table cannot hold may use the whole domain's quiet token, which moves on any region writer. Disabled observation withholds the field.

## Province combat native contract

In `province_combat_changes`, `province_id` uses a guarded live read on the calling thread. `add_combat` observes the unique append from combat creation, joining and link rebuilding. `remove_combat` observes the swap-remove at finalization. Both sites receive the province and combat in RCX and RDX. Their callers use no return value. The bridge forwards RCX through R9 and returns the original RAX. Its dirty guard spans the original. `Hooks::drop` can release the province bitmap only if the hooks were never enabled or after the hooks are removed and drained following the last capture. The relay follows the same lifetime rule.
