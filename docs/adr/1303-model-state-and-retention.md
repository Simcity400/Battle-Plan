# 1303. Keep native model state across ordered passes

Model submission follows the recording's material and actor order. The renderer groups accepted materials before appending unnumbered records, preserves queue order, and tests an actor against its own cull sphere and level of detail. The authored detail ladder is searched backward using squared distance and the last authored entry as the fallback. It stays in content order. Camera slack keeps candidate groups across bounded pans and turns. Each frame tests cull crossings and detail with its current camera. A wrapped view puts the eye and figure on the same map copy, and viewport changes can move a cull plane independently of the eye. [Camera gathering and draw admission](1390-viewer-camera-gather-and-draw.md).

Native state survives individual draw calls. A queue invocation clears its CPU object scratch once. An actor without userdata inherits the prior bytes, and a vertex-only constant bind leaves the pixel snapshot alone. A later world producer can replace the pixel allocation, so an actor without userdata cannot restore an older snapshot. Each retained update replaces only its own physical slot. An empty material sampler retains its previous value. A lit walk carries the last object block, the pixel snapshot, and the final successful material binds into later passes, including a written block from a node that did not draw. The caller's world and light slots stay distinct from material slots.

The frame can reuse the caster list and each lit call's list when their content, view, resources and input shape agree. It refreshes shared blocks and writes live poses or changed instances in place. Only bytes used by draws that changed reach the GPU. The list stores a whole node block for the next pass even when its own draw reads a shorter range. A figure can be spliced by its unique actor and view. Ambiguous matches, palette shape changes, and unsafe reorderings take the original route walk. A partial walk uses the same starting state as a full one, then the retained list replays the ordered effects of all its draws. A refusal or an unfinished build outside a figure invalidates the list. A late part within a figure can be revisited on its own.

Instance groups preserve draw order wherever reordering can affect pixels. Compatible consecutive draws can share one draw by part, view and liveness. Incompatible bands and parts with ordering restrictions retain their own order. Each instance indexes its slot in the group's aligned supplies. Shared blocks reserve the largest reflected range. Runs keep contiguous slots when figures leave, and an exhausted run can trigger a new layout. The annotated draw checks compare kept and rebuilt lists against a fresh walk, including the bytes read, range, part, resource identities and final retained state.

The kept-list GPU fixtures place only the three figures supported by their test shader. Refused actors force another walk, so a fixture containing them would never exercise reuse. The shader reads each figure?s whole world block to expose movement in the comparison. The proof pairs each kept instance with its original walk slot and part, since visually identical draws can come from different parts. It compares pipeline, resources, range and the bytes the shader actually reads, using the bound base and stride for each instance row and the bound offset for every separately shared block. A camera move retains an otherwise compatible caster list. Per-frame equality follows the bytes actually read, while movement and figure changes exercise the affected walks. [Kept-list GPU fixtures](../../crates/viewer-models/src/native/dump_tests.rs).

Persistent geometry uses shared small chunks, so drawing another part can select its offsets without rebinding buffers. Render bundles retain runs of unchanged draw identities and order for a compatible target. Recording waits for a run to settle to avoid rebuilding it every frame. Runs break at stencil-reference changes because a bundle cannot set that reference. A partial run draws directly. A separate render pass can stay on the scene's encoder while keeping the attachment samples, blend, depth and stencil state.
