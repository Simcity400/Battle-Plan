# 1110. Lay out and draw bitmap text with authored font behavior

The text reader follows the native UTF-8 conversion, including its upper-bound-only check on the second byte after ED or F4. A malformed sequence accepted by that check can leave a trailing zero scalar because the result is extended to the count of apparent leading bytes. Unaccepted input refuses the text. Layout uses signed integer advances. A missing printable glyph uses `?`, while a control codepoint has no ordinary glyph or width. Kerning uses the original following codepoint with the preceding glyph's pair table, even when the fallback glyph is drawn. The first font file supplies line height. Missing texture pages preserve glyph metrics and draw through a named null binding.

Zero-height glyphs such as spaces are break opportunities. A pending word normally moves whole to the next line, dropping the final space's advance from the previous line. A word that cannot fit one line breaks within itself. A glyph wider than the box can first produce an empty line. Literal trailing spaces count toward width, and line feeds and carriage returns end a line. The layout holds at most 255 lines. Tooltip prewrap can keep literal leading spaces after a soft line feed when their width remains strictly below the available width. Ordinary preparation leaves that disabled. Single-line truncation stops at overflow or a line feed, and fits up to three dots by replacing preceding characters when the font supplies the dot.

Formatting sequences remain indivisible for wrapping. A color sequence updates the draw's stack, using the font color table before the global table. Every draw starts with an empty stack. A native flag occupies 12 pixels of advance and draws a 10-by-7 rectangle below the glyph line. Producer-bound combat text also accepts the resolved atlas-key sequence, consuming the key while leaving the following character in the text. An unknown key reaches the caller's named resource refusal. Ordinary authored text resolves native flag tags. Currency advances 16 pixels and number sequences eight, but drawing their uninitialized sprite records withholds that text.

Unbound text boxes resolve authored keys through the content stack, retaining an absent key as the displayed text. A direct text setter treats the supplied content as literal text. Scripted substitutions that require unavailable game state produce a named refusal. An undecodable value emits no text and supplies a diagnostic.

Inline icons try the prefixed sprite name and then the bare one. An empty name supplies neither art nor advance, even if a frame suffix was present. A known icon takes its advance from its texture width divided by frame count, and can contribute texture height to its line when the font permits. A zero frame count refuses the invalid division. UVs select the horizontal frame and clamp the upper coordinate, while preserving the selected frame index. Layout and draw intentionally use their respective signed and unsigned width calculations.
