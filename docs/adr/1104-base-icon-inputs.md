# 1104. Resolve base icons through the recorded census and authored buildings

Naval bases draw from their recorded province rows regardless of level. The frame pairs distinguish unknown detail, owned and foreign detail, and prohibition. The ship badge needs a visible occupant or enough port detail to know any occupant. Preserve the unknown badge result when the relevant truncated visibility table could still contain a foreign occupant. With fog off or for the viewer's own units, visibility is known. Availability requires ownership or access without war. A recording does not carry local fleet selection for the gold frame.

Naval headquarters use the first active qualifying template in the authored database order, gated by the recorded DLC feature. Facilities use the first active specialization in recorded building order. Their position comes from the first admitted record of the explicit port or specialization bucket, with the content's coastal offsets, or from the province's slot zero when the bucket supplies no admitted record. An ambiguous bucket refuses before the fallback. Consult all declarations of a repeated building when detecting ambiguous anchor buckets, since even a declaration that was later replaced can affect which redirects are unsafe. Unknown templates that could win before a candidate keep that site's icon undecided.

Building rows name lexer tokens, while the game can distinguish templates by ordinal. Compare spelling under the game's lexer fold across the entire building registry. A case collision or a repeated effective type can make a recorded row unattributable to a template. Name the refusal and keep that token out of icon admission. An active unnamed row can also prevent a decision. Within one branch, carry cached token interpretation for identical rows and extend it only for a true added suffix. Rebuild for a branch change, removed tokens or changed text. A second caller can build without waiting on a lock, and a failed read is never cached. Province and building rows have validated ascending unique keys, so lookups borrow their contiguous ranges and preserve the original core-read refusal. Reject off-map and nonfinite coordinates before truncation to avoid mapping a tiny negative coordinate to a real province.

An air-base, gun-emplacement or rocket-site icon reads its state's recorded base of the matching kind even when a mod uses a different building name. The first two special kinds are distinct and other kinds use the ordinary air-base rules. A province needs a recorded positive controller and the shared sight and map-mode gates. Base access requires a resolved viewing country and controller, state access and an undemilitarized state. Read a surviving state's flag even when unrelated flags were truncated, because access for that state is still known. Combine registered pools with based wings using a positive expeditionary owner before the pool owner. A loaned wing's recorded base override determines where it stands. A foreign occupancy result requires that country's registered container. Count only positive-plane wings and treat a missing listed wing as an unknown possible occupant.

The base badge separates stationing, own and foreign occupancy, and access. A partial registration table keeps those values unknown when no surviving row decides them. Fall back to recorded positive planes only in the legacy frame branches that use that information. Stationing can be known even if the flag that allows the count box is missing. The game stores at most one air base, rocket site or gun emplacement per state in its per-kind state-indexed arrays, so duplicate same-kind rows for one state cannot occur in a valid game state; tooltips, selection and wing grids refuse non-unique same-kind state bases by name, while the viewer's base-site aggregator groups any duplicate recorded bases by state and kind and combines their counts, merging three-valued stationed, occupied and foreign flags with Kleene OR so known-positive evidence dominates while an unknown value never collapses to false when merged with a known-empty base. It keeps that logic outside camera layout. A changed slice relays only the affected sites and a coverage transition can invalidate an entire family. A state building's own state and a province's state are kept distinct when deciding controller and placement.

Strategic locations retain the province's own order, followed by its own state's locations anchored on it. An anchor in another state never joins that list. The first location determines the sprite name. Radar is admitted by a group hosted in the state by the viewer, a member of its faction, a direct subject or a direct overlord. An existing controller's hosted group can keep the icon. Coverage does not need to include a particular part of the state. An unresolved relationship or missing controller is named when it could affect admission. The native camera's cutoffs remain strict, and the free camera applies them at the projected icon anchor.
