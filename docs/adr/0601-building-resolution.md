# Resolve building spawn buckets and caps from authored declarations

Map slots name spawn buckets, while their entities use the building type's name. Generate a bucket for every type, and retain an explicit bucket only when no generated type occupies its ASCII-folded token. Bind an explicit redirect by that same fold and retain the declared spelling for diagnostics. A redirected port type marks the target bucket as a port. Candidate types retain database order, and the map uses the first with positive level. The map keeps fog and detection gates, distance retention and supply-hub routing separate from the bucket identity.

Read direct content files in filename order and declarations in authored order. An empty replacement contributes nothing. The native roster keeps repeated declarations separately. The last declaration supplies fields where a retained type is needed, but the reader tracks every differing record as ambiguous and carries that ambiguity to either redirect target and to factory consumers. Infrastructure uses the first declared type with its flag and refuses an ambiguous matching type by name. Case variants with identical data can share a type, while differing explicit-bucket declarations, including different spelling, are ambiguous. An unregistered resource is ignored, and a raid-only field failure withholds that part without discarding usable map data.

Retain signed authored counts and weights. A type's generated slot limit defaults to zero and its entity count defaults to one. A nonpositive entity count produces no candidates. A positive province cap takes precedence over a positive state cap, then the shipped content define supplies the base maximum. Shared slot, type group and exclusive-type cap rules are evaluated separately, and group and exclusive tokens retain their stored bytes. Validate each completed level-cap block before another block can retain a value through a failed scan. Positive fort weights let the global fort override replace the type's maximum. Factory flags contribute to each group with a positive value, with rocket production independent of launch capacity.

Preserve the reader's actual token consumption. List keys can consume tokens even without a block opener. Fields that accept bound localization recurse, while its localization key reads one string. Integer operands use the native prefix scan, including octal when the token begins with zero, and a failed scan leaves the existing value. Resource keys use their C-string bytes and fold ASCII case before lookup. Keep first encounter order when merging resource amounts and append specialization tokens in authored order. Map slots route the air-base, gun and rocket site flags. The construction queue's icon frame is one-based, the facilities icon uses the first specialization, and the state-view DLC predicate runs in an empty scope.
