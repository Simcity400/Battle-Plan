# 0301. Keep a recording’s catalogue separate from its presentation

The dashboard caches catalogues per source and binding. The binding includes the game and user folders, cache folder, unverified-content choice, presentation identity and texture settings. Caches derived from recorded facts alone omit the presentation and texture settings. A request using no visual mods shares the recorded catalogue with preparation. A request showing visual mods uses a separate slot, so the two forms of work can alternate without evicting each other. Texture settings decide how artwork is drawn. Localisation stays in the recording’s language, and an unreadable texture setting withholds only the artwork that needs it.

Resolve the content mount before entering the catalogue slot. A read-ahead can read only content already bound to its folders and a presentation still current for its source. A late request may complete using the presentation admitted at its entry. Its private catalogue cannot replace a newer source binding or change its warnings. Per-selection redraw caches also bind to both the admitted catalogue and the recording’s catalogue. A redraw made against either can report its own diagnostics on each use, including memo hits.

Where the recording alone answers every read, keep localisation and, with no visual mods selected, interface sprite declarations on disk. These files are keyed by the verified facts and relevant inputs, format, and running build. A source can read the entries it needs on first use and credit the diagnostics their construction produced. Reads outside the recorded facts prevent reuse, since installed content can change between reads. Unverified content requires a user opt-in. Keep installed textures outside this store and read them from the current installation. The full build path also bypasses the kept files, giving tests a reference answer.

A kept part can be discarded and rebuilt on an absent file, key mismatch, truncation, or bad checksum. Concurrent writers use separate temporary files and publish a complete part only if it round-trips. A failed cache write still leaves the built answer usable. Asset reads guard declared dependencies against prepared-store keys, including map file paths that can escape the stamped coverage. Tests check coverage and compare the build and kept paths with the same facts while preserving named read refusals and content order.

Localisation and catalogue warming happen once per opened source so an individual product’s first request does not have to mount them. A product reports any unavailable part it needs. Shared content reads such as equipment definitions and strategic regions also credit their original diagnostics on reuse. Tests mount synthetic content as the game does. The prepared-table tests use decode counts and publish without disk flushes so they can isolate reader behavior.
