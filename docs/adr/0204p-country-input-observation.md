# 0204p. Keep separate country marks for each input consumer

The country-input domain has one take per table family. Stability and research consume their own marks. Technologies mark only the writer's own country, even when other countries use its technology for their modifiers. National focus and projects refresh after the daily tick if a country owns a state. State ownership transitions mark the old and new owners, including countries that gain and lose their only state between the ordinary daily checks. An unreadable count is eligible for drift. Country appearance, counter inputs, unit-speed entries and visibility each keep their own observations. Equipment-design modifiers also have their own accumulator take, so design and visibility reads cannot consume each other's work. Visibility reads the definition and eligibility metadata each hour even when it carries the raw accumulator entry.

Each mark set can observe only while the patches and relevant forwarders for that set are present. An unmarked country can carry until its daily read, and a marked country reads in the same hour. An out-of-range or unidentified receiver, a load or a gap moves the epoch and requires a full read. A writer that can change multiple countries marks entry and return, including a subject's overlord after rebuilding the relations. Epoch and quiet values are independent evidence for country naming, technology sharing and modifier sources. Bitmaps are sized off the game thread from the last complete country census, and retired storage is freed off it too.

The appearance reset precedes the original-tag setter in the same game-thread step, so its mark covers the original tag. Political status, party leadership and character roles forward the inputs those tables read. Scientist role, trait and identity writers reach the research sources. Diplomacy reset changes exile and subject links. Wartime ally rebuilding and relation replacements affect counter and relation inputs. State owner and controller marks cover both sides of a replacement. State reset names no country. Core changes, relation resets and character pool lifetime changes reach the counter tables. The site registry and forwarder switches own the writer inventory and share patches where families overlap. Modifier recalculation also reaches the naval hover tree, and the same existing observer forwards the advisor unappointment and the war body's state changes.

Research slot synchronization, faction sharing base changes and queued leader removal notify only when the relevant native fields change. Their comparison is guarded. An unreadable initial value keeps the writer observed for the whole call. Progress from research effects has its own mark. Other progress sources are daily drift, run under another observer, or are followed in the same call by a writer that is already observed. Ordinary manpower operations do not affect the exile resource certificate.

Intel-network growth and the forwarded country reset are observed outside the normal daily update. A reset invalidates network identity, whereas a console growth operation changes strength while the national caches retain their identity. Weather writers outside the hourly window count entry and return, so an overlapping read must cover all weather records. This includes console commands, load, reinitialization, reload and province modifier changes. Each observer calls its original with the original operands and returns its result. The source distinguishes callbacks with a fifth argument from the ordinary callbacks and distinguishes the expiry rebuild call from the surrounding native operation.

`name`, `remove_unit_leader`, `sync_research_slots` and `faction_sharing_base` use guarded live reads on the calling thread. `Hooks::drop` releases the bitmaps only after the family and its forwarders are restored and native calls have drained, or when observation was never enabled. `accumulator_install_growth` is valid only while the faction acquisition worker holds the native quiescent lease.
