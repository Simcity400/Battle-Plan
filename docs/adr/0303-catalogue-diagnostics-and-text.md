# 0303. Keep content resolution and diagnostic ownership independent

Products share a catalogue of the recording's verified content and a separate presentation view for interface artwork and game-look text. A catalogue belongs to its source, resolved layers and locale. Each demand loads once per binding, including named failures. Cancellation can retry. A per-key cache follows the same rule. A rendered memo carries the same refusals, lazy readers and recorded-artwork fallbacks as a fresh render. Every consumer using it gets credit for those observations, so the consumer that warms a shared entry does not own everyone else's warnings. A failed speculative render is credited to its current caller and is not kept as a rendered value.

Reader warnings belong to the lazy readers a scoped consumer actually used. Text refusals are deduplicated by identity and counted by reason. Reader warnings carry no measured item count. General stack diagnostics that can accumulate from another consumer's work are appended where a reply is served, outside the published result's consumer scope. If restoring a saved consumer's result in a new process, its named reader warnings can be replayed even if the new catalogue has not loaded those readers yet.

Native descriptions distinguish plain text boxes from scripted views. A plain view displays brackets literally. Scripted idea, focus and effect descriptions evaluate in their recording's country scope and name a refusal when no eligible scope exists. An unclosed expression drops its preceding buffered text. Localisation uses the shared native substitution limits and traces recoveries before removing presentation controls. A content key absent from the catalogue renders as its own bytes. Saved byte keys end at their first NUL. Text already rendered by the game follows the recording's language guard. Retained wing names have priority even when their recorded read failed. Only a preceding recording format with no retained wing-name field can use a verified active-raid name projection.

Shared scripted text lives in `dashboard-text` and effect descriptions live in `dashboard-effects`. The catalogue supplies the effect describer when it builds scripted content. Scripted power-balance text delegates activation and deactivation effects to it and reports a named refusal if the describer is absent. Each scripted content instance shares one lazy effect cache and one static-modifier catalogue across those calls and the products that describe effects directly.
