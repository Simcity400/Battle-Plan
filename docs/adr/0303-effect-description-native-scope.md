# 0303. Describe effects with shared scope and formatting rules

The dashboard, map and recorded-unit products share description inputs and name resolution. Each description selects its trigger tables and effect operands at the same recorded hour. The scope graph retains full project owner/ID, raid and unit identities. Scoped variables, inherited selectors and text expansion share the trigger evaluator. Stored names keep their captured language gate. Only an older format's absent field permits the authenticated legacy name projection, and a failed capture remains unavailable. A saved country or state member is read independently. A lookup tests the first saved name match in a store before moving to the next store. Missing state zero can take the native zero branch, while a nonzero state needs its actual recorded owner.

The outer variable session starts from the recorded seed and immediate `THIS` and `FROM`. Nested descriptions share it. Independent ability callbacks create separate sessions so a one-time description cannot seed hourly or daily output. Descending through the terminal `FROM` and creating a fresh scope are distinct operations. Fresh localisation for selected countries, states or characters uses the supplied context without borrowing a caller's unrelated endpoints. A failed title-trigger walk only withholds title text that reads its resulting scope. An unrecognised effect class cannot safely take the default child traversal if it may override it. Known builders can still describe independent children after a local refusal.

The effect reader owns its parsed fields. Generic traversal projects those fields out of the child array, and selectors must follow the reader actually used by that class. The custom readers for puppet creation, declaration of war, wargoal removal, autonomy release and setting, both equipment transfer forms, and fractional unit transfer own the block's country target. Reusing an effect parser's scoped field can retain earlier flags, so a later spelling alone cannot determine its selection. The resulting tooltip matches the class's own line ordering, raw or scoped localisation, whitespace and formatting. The shared modifier formatter keeps definition precision, include and exclude masks, fixed-point scale, and sign/colour options separate. A cached numeric definition can format without re-looking up its name. A nonempty nested effect remains describable even if its wrapper line is empty.

Content belongs to one recorded stack. Shared readers can run in parallel once their dependencies are available, with their diagnostics credited on join. Raid names and event bodies load lazily when a selected effect reaches them. Reachable selectors and resource readers refuse inputs by name, which allows unrelated known text to remain available.

An ability adds raw modifier and adjuster lines in authored order. Each effect callback has its own variable session, and the map caller supplies its own scope and communications fragment. A nonempty description begins with a newline. The ability's heading calls preserve their own appended newline, while the effect result is appended as produced. Project outputs similarly keep the assignment's actual scientist and facility scopes and preserve missing assignments.
