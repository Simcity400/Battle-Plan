# 0402. Verify executable metadata from file-backed evidence

Each decoder reads a PE image from disk. An RVA read requires the whole range to have file backing in one section. The decoder uses the preferred virtual address for instruction pointers. It builds shared indexes of text, RIP-relative references, and MSVC class information, then confirms byte-pattern candidates against decoded instruction boundaries and file-backed sections. Where a locator expects one candidate, absence and ambiguity both withhold that part. Diagnostics name text anchors, while lookups use their length and hash to avoid copying game text into source.

The keyword table preserves original spellings in token order and resolves lookup by ASCII case folding. Fixed modifier declarations must resolve to dense indices with distinct tokens. Later alternatives that reach the same continuation replace earlier names. Fixed-token identities and fixed modifier indices are checked independently against the recognized content. The canonical digest represents decoded values, without referring to executable addresses. Graphic ASCII and a separator between the two nonempty lists make that canonical encoding unambiguous.

Numeric properties preserve exact spelling and registry order. Command tables accept primary vtables of concrete classes and use stable hashes of their decorated names. Each known command owner comes from the operands confirmed by its permission check. The bounded walk follows direct branches and one level of called functions on the command or its fields. Undecodable bytes and routes leaving the image end a path with only the evidence obtained so far.

The find box uses the executable's own non-ASCII to ASCII character map. The decoder requires one complete instruction run with consecutive stack stores and re-decodes the selected run as instructions before accepting its data. Repeated code points keep their first mapping, following the insertion order. The tests include a skipped slot and a candidate inside another instruction so an apparent byte match alone cannot pass.

Auxiliary parts pin masks and structural positions consumed as constants elsewhere. Order types resolve as build-scoped keyword identities. The selector decoder recognizes only the finite arithmetic and branching needed for those lookups. Short instruction and register histories use lists because they hold only a small number of entries. For display colors, verification stops if another call may overwrite an argument, or if the constructor does anything beyond storing the verified components and returning the object the caller reads.

The registries compare verified reader fingerprints and canonical class-name hashes to the recognized build. Mask image-dependent operand bytes, but include jump-table order and the reader's own referenced read-only data. An unrelated callee's data can change without changing the reader. Resolve a shared fingerprint with the class and vtable slot, and use a build-independent stand-in when there is no recognized counterpart. A stand-in cannot compare equal to a recognized address. The pin command writes the reference tables from the recognized installation.

## Keyword and auxiliary locator contracts

The `KEYWORD_SHAPE` witness is the token load and keyword operand following the name load. `MODIFIER_SHAPE` is the returned-token load and call after the modifier index is set. `verify_token_initializer` proves that the token argument is written to the first argument's storage and that the same object is returned. `read_keywords` tracks the earlier ID, initialized token object and name until registration. `read_modifiers` tracks the same token from its original argument through the object to the registration argument, with the index reusing the original token register. The initializer's slot and stack pointer must stay stable. `writes_slot` counts memory writes with an unknown address or overlapping writes as interference.

`BIG_ALLOCATION` selects MSVC's aligned allocation header. The fulfilled and default rule flags use the fifth and seventh caller slots. Display alpha uses the fifth slot. `STRING_OBJECT` describes the native inline-or-pointer storage followed by length and capacity. `equipment_missions` joins the case chain at its common successor and stops interpretation there. `color_constructor` distinguishes the return slot from caller arguments, while `row_layout` maps arguments past both the return slot and the current frame's reservation.
