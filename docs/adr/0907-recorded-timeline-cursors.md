# 0907. Separate stored segments from playback timelines

The recording keeps physical segments so loading a save never rewrites their hours. Playback builds timelines from them. At the save's hour, linking compares the recorded clocks' save counters to the first clock seen after load. A decrease contradicts a candidate, with modular arithmetic for the random-draw counter. Counter evidence is conclusive only when it excludes every competing history, including gap-only segments. A gap in the same running session can also establish the preceding segment as its parent when there was no intervening load. If the evidence falls short, the latest possible history is followed provisionally and a viewer choice can replace it. Play beyond the parent's end extends that timeline. A load into the parent's past forks it. The newest recorded play owns the main timeline.

Each timeline clips physical pages, gaps, stops and event losses to its pieces, and playback identifies views by the timeline while using original segments to look up the data. Commands can precede a segment's first hourly frame. Their piece begins at the segment's declared hour and ends before the next piece starts. A command's hourly context may be observed after its watermark. A zero load marker remains unavailable until the first simulation update. Small command packets are left uncompressed for the shared records-extent compression. The decoder uses the minimum encoded timestamp and duration length to bound the count before allocation.

A frame cursor restores each selected table independently and advances from its current state when that is valid for the destination. A discontinuity seeks from the relevant restore. The first visible hour of a block is a keyframe for readers walking block pages, and an immediate successor can carry change facts and field stamps from the view the cursor built last. A cancelled move leaves the cursor where it was. A failed move or view build resets its readers. No run covering the hour yields no frame, and a damaged table is unavailable by name without stopping other readable tables. A run with an unreadable directory provides no lookup coverage. Movement and build use a configured pool or Rayon.
