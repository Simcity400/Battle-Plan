# 0204m. Certify observer carry by domain and receiver

An observation domain admits carry only while the hooks and forwarding functions it needs are enabled. Shared publication can hold the whole family back when any of its sites is active. The hourly boundary invalidates previous evidence after a load, gap or recovery. An in-flight writer keeps the affected certificate unavailable until it returns. An unidentifiable tracked receiver invalidates its domain. A named receiver has an epoch and sequence, while a domain-wide quiet token has an epoch and revision. A carry may rely on the latter only while all required inputs stay quiet across the read. Capacity offers and retirement work run off the game thread.

Advisor-pool carry watches available and appointed pools, retired character records and the idea-token set. It also requires the listed advisor's character certificate. A role removal that names no pool invalidates all pool certificates. Country inputs own the unappointment patch and forward its observations. The pool constructor and destructor forward changes to the country's character pointer, and the manager constructor forwards roster creation. Character observations take guarded role parent fields and ignore unrelated tree maps that identify no registered character; an unreadable tracked parent invalidates the domain. Scientist role and trait changes use the separate roster domain. The role census carries only when both the roster array and its role writers remained quiet. The census domain needs no receiver registration. Advisor and roster patches forward their covered writers to it, and any unavailable contributor forces a fresh gather.

The air-base carry domain keys a base by its handle and a pool by its owning base handle. An unlinked pool names no registered base. Failure to read a handle prevents carry instead of proving no change. Parent slot membership uses a separate key so creating or destroying a base invalidates the correct result. Capacity refresh changes the base's row and not the slot set. The raid observer forwards capacity only when it changes or its earlier value cannot be proved, the ship model observer forwards destruction, and entering the map editor invalidates carry for the attachment through the building observer. Metrics retain separate counts for reads, carries and splice work.

`advisor_pool_changes::Hooks`, `air_base_carry_changes::Hooks` and `census_changes::Hooks` construct only under the build gate with the authenticated executable's memory source and base and an exclusive family owner. A sentinel failure leaves the family uninstalled and its consumer reads afresh. Advisor-pool and air-base `Hooks::drop` release watch tables only when the hooks were never enabled or were restored and drained after the last capture. `census_changes::Hooks::drop` only advances the epoch because its domain has no watch table, and still follows restoration of its own and the forwarding hooks. `character_changes::release` frees its tables under the same drain condition.
