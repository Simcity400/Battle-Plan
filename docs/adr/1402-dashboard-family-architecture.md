# Dashboard family architecture: source plans, bounded read views, and installed pictures

Dashboard widgets follow one architecture from the recording to the screen so every family shares playback discipline, time safety, interaction soundness, and exact-read verification without per-widget orchestration or duplicate worker pools.

```
recording
  -> Rust products          facts, units, coverage, reasons, dated identities, recorded order, totals and ranks
  -> family source plan     one declaration per widget view: what it reads, its coverage mode, and its time shape
  -> bounded read view      only facts evidenced at or before displayed hour H reach a family
  -> family projection      pure: (readView, options) -> model
  -> lane worker            layout + paint; publishes one picture: pixels + hit targets + action keys + audit rows
  -> family host (main)     installs the picture whole or not at all; pointer, keyboard, scroll, focus, tooltips
  -> shell (React)          frame, title, settings, pickers, pop-up detail host
```

The map keeps its native renderer; game windows (such as the equipment designer) render through the native off-screen renderer inside the shared pop-up host.

## One owner per job

1. **Drawing a widget body (`ui/src/draw/` via `ui/src/families/host/`).** Every dashboard body renders on the worker lanes. There are no main-thread canvas charts, no second worker pool, and no DOM-drawn data bodies. Every family registers with an open `FamilyId` string and shares cost-weighted per-instance lane placement (`widgetId|declarationKind|instanceId` with explicit `kind`).
2. **What is on screen (`InstalledPicture`).** Each installed picture is an immutable tuple committed atomically by `Page.install`: `id`, `owner`, `generation` (`{ seek, reset, binding }`), `factRevisions`, `validInterval`, `through`, branded `hour` (`DisplayedHour`), `viewport` (width, height, DPR, scroll, optional chart `transform`), options and theme revisions, `actionKeys`, `accessibleDescription`, and `auditRows`. Pointer clicks, Enter/Space activation, context menus, pinned tooltips, accessible descriptions, and exact-read audits all resolve against the **installed** tuple, never against live React props or newer data. Pointer coordinates stay in client space and convert through the installed viewport geometry (`clientPointToInstalled`), so a stationary click on a held reply during a resize still hits what is visually under the cursor. Changing `owner` clears the installed picture in both `Page` and `Lane` immediately and rejects any late presentation or hit carrying the previous owner.
3. **Asking for and following data (`ui/src/families/plan.ts`, `broker.ts`, `host/useFamilyPlan.ts`).** A widget view declares `sources(ctx, view) -> SourcePlan` and `project(readView, options) -> model`. Plans declare plain serialisable parameters across seven time shapes: `point`, `range`, `branch-to-hour`, `trailing-window`, `pixel-binned`, `exact-hover`, and `paged-rows`. `planSignature` compares plans cheaply without invoking closures; `FamilySourceBroker` deduplicates concurrent requests by produced parameters (`planQueryKey`), drops stale slot completions, and aborts on unmount. A read no follow query answers asks through the displayed hour and never past it; its reply proves only the hour it answered unless the reply's own evidence (`provenInterval`) proves later hours, and it stays bound to the request that produced it, so a seek back never pairs a held reply with a newer hour. Each widget holds one target, "the bundle for hour T" (`ReadTarget` in `ui/src/families/readUnits.ts`, outside React). Every entry the follow pipeline does not serve in the current mode is a read unit: while following, each entry without a follow subscription that reads without one; pinned, every entry a bounded read can answer, except that an explicit `staticEntry` stands in for the entries that follow. Every unit is asked for T on its own track's clock, branch, coverage gate and recording end; a unit whose held reply is already proven over T keeps it. Nothing advances the target until its bundle settles, so requests are bounded by replies (lag, never a queue) and staggered replies always complete; then the next target is the clock's hour at that moment. A seek, a pin or a change of the widget's inputs supersedes a pending target at once; a seek also asks a failed request once more. A failed unit lets the clock move the target only once no sibling is still pending, so a failure never turns into a request per frame. One pure function, `settleUnits`, answers a complete bundle whose proof is the intersection of every unit's evidence (or the stretch over which nothing can be asked, a known absence) and nothing dated after the displayed hour; at rest both proof bounds must hold the displayed hour, and a held bundle dated after the target is withheld. A bundle is one stamped thing: it is made for the widget's inputs (owner and view, the owner naming the country a selection that follows the dashboard resolves to, the pin hour when pinned, selection, plan request signature, content revision) and carries its replies, its span, its shifts and the proof it settled with. Settling again with the same replies under the same inputs and span returns the same bundle object, so a quiet or merely re-proven hour sets no React state and binds nothing; the same replies under new inputs or a new selected span are a new bundle over the same panel map. While following, a span's end is the clock's, dated by the proof, so only its start is compared. The target's current proof names the bundle it belongs to. The hook withholds, during render, a view made for inputs other than the current ones (a widget with units shows loading, never the previous owner's, pin's or selection's bundle), and the target never holds a bundle across a change of inputs.
   The lane binding carries only its own inputs (kind, view, options, settings, geometry, selection, focus, tiles, hovers, art, audit); a bind happens only when one of them changes. Static panels, the identity snapshot and the static proof's dates reach the lane as their own messages (`Pipeline.supply`). A new bundle is ONE message: its panels, its proof's dates and its stamp (the bundle's revision); a date-only message names the stamp it dates and is sent only for the bundle last supplied (`StaticSupply` in `host/dated.ts`), and the pipeline drops a date-only change for any other stamp. A bind carries the dates last supplied, never newly computed ones, and the host re-supplies statics after any change of owner. Every object that crosses to a lane is a payload with one revision (`revisionOf` in `dashboard/follow/payloads.ts`: the same object keeps its number), sent to a lane once while any widget there refers to it and dropped when none does: the binding's object fields, each static panel and answer, each hover, each tile line and the identity snapshot. Messages carry revisions in their place, the lane resolves them when the message arrives (never at paint, so no bind between paints loses a payload), and the composed binding carries the same `revisions` record. A date-only supply applies only to the stamp the lane holds, also while it buffers supplies for a widget it has not mounted, where new statics bring their own stamp (none on a clear); a new owner clears the previous owner's statics. A finite proof closes an open picture at its own bounds, in the lane and on the page, and a picture whose hours no longer meet its proof is withdrawn rather than shown as current. A supply never bumps the binding generation, so it retires no picture in flight; a picture made before it still installs, dated by its own window, and the next paint uses the new inputs. A paint or installation that fails names the stamp it was made from; a widget whose newer bundle has already been supplied is retried once on it, whichever of the failure and the bundle reaches the main thread first, and the same bundle failing again stays failed.
4. **Coverage of partly read hours.** Reflecting the query layer's coverage rule, every plan entry declares either `mode: 'keyed'` (explicit keys, independent per-key cells, row-level coverage allowed) or `mode: 'population'` (`all`, `top`, `least`, `parts`, or `total`, computed in Rust with table-level coverage). `compileFollowPlan` rejects row-level coverage on population forms and `top`/`least` on keyed forms. Families never rank, sum, total, or assign category order from partial client data.
5. **Time safety (`ui/src/families/boundedView.ts`).** Every source is asked to the displayed hour: a span or point request that names the hour, tiles, paged rows or a followed answer, so no reply carries records dated after it and no projection does the cutting itself. `tools/check-future-reads.mjs` builds every manifest view's plan, asks each entry's request at hours across the branch through the broker's own request builders, and fails on an entry whose request is the same at every hour unless `tools/future-reads-ratchet.json` lists it; the list only falls. Families read only through `BoundedReadView`, which enforces nothing-after-`H` across panels, answers, live cells, pixel-binned series, approximate spans, missing spans, marks, hovers, paged row sources, and `who(kind, key, atHour?)`, throwing `FutureDataError` on any read past `H`. Advancing `H` costs O(what changed), never O(history): closed bins, runs, missing spans, approximate spans, and marks before `H` pass through by reference via binary-search index bounds (`BoundedSlice<T>`), and quiet advances inside `validInterval` reuse the cached view with zero visits and zero allocations (`BoundedSeriesCursor`). A bucket straddling `H` is cut from witnessed prefix runs or points before any range, scale, total, order, label, or hit is computed; when no witnessed prefix exists, the straddling bucket is omitted and marked `straddling: 'loading'`. A slice keeps its backing array private, so a family can reach only what is at or before `H`. The body's not-recorded reason is the one in force at `H`, re-read only when `H` crosses one of its boundaries.
6. **Identity and art seams (`IdentityProvider`, `ArtProvider`).** `readView.who(kind, key, atHour?)` and `readView.art(handle)` give every family one time-bounded path to dated entity identities (holder, tag, name, colour, flag choice at a row's own observation hour or at `H`) and mod-stack art results, registering pending demands with the broker so the family wakes when they settle.
7. **Body states and trailing gaps (`ui/src/dashboard/model.ts`, `regionTime.ts`, `regionGate.ts`, `families/host/FamilyBodyState.tsx`).** Host body states (loading, outside, not recorded with reason, refused with reason, failed with retry) live in one place. Campaign-mode windows (`resolveWindow`) and end pins (`recordingEndTime`) resolve to `lastRecordedBranchHour(branch)` so recordings ending in a trailing gap settle on their last recorded hour instead of hanging in `outside` or `loading`.
8. **Verification (`ui/src/families/host/auditBinding.ts`).** `createPlanAuditVerifier` and `createBoundAuditReader` re-run the exact same `project(readView, frozenOptions)` on an independent exact read at the installed picture's hour, never using streaming `Facts` or `TileCache` as their own oracle.
9. **The lane view skeleton (`ui/src/families/laneRuntime.ts`, `scene.ts`).** Every family's lane view is `createLaneView(family, wake)`; a family supplies only its boundary (when its model changes), its redraw (when its drawing changes while the model does not, such as a playhead), status, layout, paint, hit, tooltip, structure fields, mirror (or none), audit and visible art. The runtime owns the rest once. `projectScene` turns the lane scene into the bounded read view, runs the projection, and returns the identity and art demands it raised together with the reads it made, so demands can come only from the call that ran the projection. A held model is reused only while the scene's facts are the same, the kind, view and owner are equal and the revisions of every projection input (options, source mapping, static panels and answers and their clock shifts, hovers, tile lines, head configuration) are unchanged, never by object identity, the hour lies inside the interval it was proven for (from the hour it was built at to the earliest of the projection's next change, the model's own boundary and the end of every name read at the displayed hour), and every identity and art read still resolves the same (the whole observable result: interval, status, reason, retryability, URL and frame, and the URL the read would demand); the identity index is built once per snapshot revision in a worker and shared by its placements; anything else rebuilds, so after a seek back, reorder, owner change or same-hour correction the picture equals a fresh paint. The end of the current drawing (the earlier of that interval and the redraw) is returned as `nextChangeAt`, and layout and paint see the hour that drawing began, so quiet hours redate the installed picture without painting. Outside a held model's interval the runtime locates no change (`next()` answers `null`), and the lane paints at the target hour bounded by the facts' window, never walking hours from the window's start. A family that animates a change gets the frame drawn before (and its layout its previous one, for reuse only) only during continuous forward playback of the same placement (same seek, both frames playing, a later hour, no pin, same owner, kind, view, options and sources). Continuity is judged at every paint against the last DRAWN placement, not only when the model is rebuilt: a frame at the same hour of the same placement is an animation tick and keeps the transition; anything else (a seek, a pin, a pause that moved the hour, any change of those) discards it even when the model is reused, and a refused frame leaves no drawn placement to continue from, so the first frame after any of them equals a fresh paint. Transition state (a glide, a rank marker) is derived only from the frame drawn before and the time the model changed, and cached only against the frame's continuity number, never by holding an older frame. A family with no mirror declares none and arms no mirror timer. Layout reruns only when the model, surface or the family's view fields change; drawing only when the layout, scroll, inspection, selection, focus, identity, art or motion changes. Every published field belongs to the painted frame (model, layout and drawn hour) it was derived from and is derived again only when that frame or its own key changes: a tooltip and a focus tooltip at once; the mirror, while playing, no more than once a second, and withheld until it is due rather than published beside a newer picture. A family's layout never depends on scroll: the visible window is computed apart from it, so a scroll derives no structure field again, and a hover derives only what the hover changes. A view that cannot paint yet (its projection is loading) answers `waiting`; the lane presents nothing and paints it again only when the view wakes the widget. Unmount releases the placement's registry wait, and a family switch disposes the outgoing view's state. A widget holds at most one wake timer, never re-armed while one is pending at or before the time it needs. Hits and audits read the frame of the picture that was painted.
10. **Options (`ui/src/widgets/manifest.ts`).** A stored option key means something only for a view: a named view stores its fields under `key@view`. One mapping turns a widget's stored record into the resolved options of a view (`widgetViewOptions`), writes one option for the active view (`setWidgetViewOption`), stores a preset through the field set of the view it opens (`presetStoredOptions`), and turns a view's resolved options back into stored shape for a legacy chart embedded in a family view (`viewOptionsAsStored`). The renderer slot hands every view body, chip and detail window those resolved options and the manifest entry's declaration; a family view body never receives the stored record (its widget's `options` is sealed in the type), so it cannot read a key without the view. The picker counts placed widgets from resolved options. The pattern check refuses new stored-option reads under `ui/src/widgets`.

## Invariants

- Register each widget kind, its views, sources, time shape, coverage mode, country policy, settings, and audit projection together.
- Never read after `H`; clip history and cut straddling buckets before computing scale, totals, order, labels, or hits.
- Paint and interact exclusively from the installed picture; carry `(installedId, owner, subject, hour)` on every action.
- Steady playback frames perform zero React commits, zero DOM layout reads, and zero history copies; quiet ticks inside `validInterval` perform zero projections and zero paints.
- Delete superseded renderers, schedulers, and orchestration hooks in the same PR that replaces them.
