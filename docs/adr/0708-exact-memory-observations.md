# 0708. Preserve ordered outcomes at the guarded memory boundary

The collector counts guarded crossings and copied spans separately. `ReadCensus` counts completed spans and their bytes for deterministic cost tests. Production request counters sit immediately above the raw source, below owned snapshots and caches. They count attempted work, including empty calls and the first rejected or faulting nonempty request, while stopping at an encountered control. The wrapper delegates batch requests to the underlying batch implementations so measuring the work does not add guarded crossings. Nested job owners drain and restore thread-local counts so caller-assisted work is charged to the correct owner once.

An off-thread prepared plan owns its geometry and expected control bytes. A comparison runs after the stated number of original reads. Its builder must cover every dependency used to choose subsequent addresses. A changed comparison stops before a previously selected child can be read or even hinted. Hints only advise caching of endpoints of already admitted ranges and observe no data. An empty span completes without checking or dereferencing any source. Rejected geometry, a changed control and a faulting read have distinct outcomes. A failed exact copy may have written part of its own span but cannot publish that span as complete or reach any later span.

The native guard handles faults during its active copy and lets unrelated exceptions reach the normal handler chain. The single-span copy admits faults in its exact source and destination ranges. A prepared plan handles only its active source read, outside recorder-owned comparisons and metadata. Rust rejects noncanonical source spans before normal guarded copies. The single-span guard still handles the address-less Windows fault report during the exact copy for direct FFI callers. Fixed and packed copy paths preserve the generic path's source widths, field order, duplicate observations, destination padding and completed-prefix witness. An unaligned source can span two cache lines. A partially admitted row falls back to generic handling, and pointer and descriptor evaluation stay inside the admitted prefix. Source and destination bounds, including checked strided arithmetic, are established by the Rust caller. Fixed-width scalar results use a separate success marker so a successfully read zero is distinguishable from an unreadable source.

The walk API grows owned vectors from admitted headers without restarting original reads. Fixed slices are reserved for callers with exact same-observation demand or a no-allocation requirement. A count-only probe retains demand without storing rows. In slot-ordered pointer arrays, slot zero is reserved and null holes produce no row. A fault cannot turn a prefix into a successful table, and validation of each admitted row takes precedence over a later fault in the same batch. The callback-local recent-entry cache stores completed observations only. A miss reads again.

On Windows x64 with MSVC, the pinned Rust standard library keeps the const-initialized, destructor-free read-counter cell in fixed native TLS. `CountedMemory::new` takes a private thread-bound handle and `add_counts` uses it only on that thread. Collector quiescence ends accesses before unload, and draining the cell replaces its contents in place. This permits nested reader wrappers and short shared borrows without extending the cell lifetime. The native control boundary, read failure and accounting tests keep source arrays immutable and alive through all guarded copies. Deliberately unreadable test sources reach only the native guard.
