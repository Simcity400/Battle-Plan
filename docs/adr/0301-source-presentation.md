# 0301. Give each request its admitted visual presentation

Widgets show the resolved campaign selection used by the campaign map, in game, global and campaign precedence. A dashboard map widget’s own scope affects that map alone. Each source binds its own selection. The mount order comes from the engine, so reordering a selection alone has no effect. Updating or removing a selected mod can change the binding. Recorded facts, including interface declarations, localisation and scripts, stay in the recorded mod stack. Installed artwork such as textures and fonts follows the selected presentation. The identity includes the recording’s mods where they affect the presentation.

Capture folders and presentation together at admission and carry the admitted state into spawned work. A delayed request must keep the same mount and diagnostics after any number of subsequent changes. Its warnings must also describe admission when the reply draws no artwork or uses a prior memo. Requests with no content dependency require no mount. A configuration update racing a rebind causes the derivation to retry against the newer configuration. Shutdown closes the configuration before unbinding, so an in-flight derivation cannot reinstall it. Cancel read-ahead when its binding retires. An already admitted request keeps its own cancellation.

Compute a mount outside cache locks and share it through its binding’s cell. A slow mount cannot stop unrelated admissions. A cancelled waiter leaves without reading content, and a cancelled computation leaves an empty cell so later work can retry. Read-ahead may warm GUI lookup in the strict overlay mode used by shields. Recorded-only preparation uses the recording’s own catalogue and never mounts the selected visual mods. It can keep an independent cache entry without displacing any entry a request needs.

Each temporary content resolution belongs to the preparation that started it. Requests may claim a finished resolution and reuse its result. Cancellation returns an interrupted result to waiters. A resolution that stopped because the preparation finished, or whose worker panicked, is left for the next reader to perform. Content and recorded mounts remain alive while admitted work holds them and may be reused by a request for the same folders. A weak reference retains the old allocation identity for a recorded mount without keeping the entire content alive. A prior request can report its own read set and changed layers without rebinding the source. Source work scopes the recorded executable tables for derived lookups, and country names use the recording’s language and each country’s observation hour.

Per-product caches serialize work only within a product. A product can opt in to append inheritance by cloning immutable history and giving the new revision its own mutable continuation. Verify the earlier recording’s block prefix before inheriting and do the comparison outside the service’s source lock. Revision-local caches do not take part. Read-ahead takes only its share of processors and yields to the priority of visible requests sharing its results.

Content preferences are shared by the host and development bridge. A sibling file lock covers the full read and replace transaction across processes, and each writer stages to a separate file. The host validates configured folders before saving. Older installation folders can supply game facts for a recording that does not carry them. This is independent of replay-format compatibility.

Draw an entire asset operation against one catalogue, from choosing the declaration to selecting and rendering its artwork. Try the admitted presentation strictly and collect its diagnostics separately. A successful attempt credits those diagnostics. On failure discard that attempt’s diagnostics and rerun every stage against the recording’s catalogue, including any interface choice the draw made. A successful fallback names the original failed stage once and replays that note on memo hits. If the recording also fails to draw, report its own unavailable artwork reason. A nested draw leaves the fallback to the enclosing transaction. Separate strict and ordinary memo entries keep a normal fallback result out of a strict draw.
