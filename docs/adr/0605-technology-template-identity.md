# Preserve technology template identity and admission

The technology catalogue has two identities. Recorded references address a one-based template index in load order, including repeated definitions. Content name lookup takes the first ASCII-folded match while retaining the authored spelling. An unread file contributes no definitions and leaves every later index unknown. Encountered tokens narrow the uncertainty only when the reader proves it reached the remaining keys.

One native read supplies the presentation and equipment links. It reads the direct technology files with a fresh lexer per file and resolves dynamic keys through the content registries. Triggers and effects use country scope. Dispatch uses bare lexer keywords, checks registered sub-units and categories before modifiers, and retains the distinction between raw token lists and value lists. The fixed-length folder position reader can accept exactly two numeric elements or its two keyed coordinates. Unsupported equipment forms are named instead of treating an evaluated conditional loop as a simple list. The research-completion effect reader checks only a leading limit and opens the effect body only if the value slot then contains an opening brace. That slot can retain a scalar after a trigger read. Unknown shapes that would change continuation are refused.

Presentation takes the last parent value as its alternate template key. Equipment links share admission between names and descriptions. Content load evaluates limits in a fresh empty scope, reuses decisions for equal limits, and stops each field at its first false limit. If undecided limits can change the ordering of admitted names, return the uncertainty. A whole comparison of the outcomes of a shared limit can still prove the same children, including cases in which aliases swap. Deduplication folds authored equipment names before resolving registered aliases, so distinct aliases remain distinct children even if they resolve alike. Runtime instance selection still applies validity, category and DLC gates, while classifier propagation uses admitted names without running the limits again. The full name switches to the equipment for exactly one admitted child unless the small-layout flag forces the template key. The description counts admitted names separately and takes its first child.

For production icons, a technology can supply a fallback only when exactly one template enables an equipment type. Enabler discovery reads through the native technology reader rather than marking generic-tree fallbacks proven: when reading or natively parsing the unit registry, key names or any technology file fails (other than cancellation), the failure reason is retained and single-template fallbacks are withheld rather than aborting unrelated equipment sprites or guessing past tokens an effect may have consumed. Deduplicate links within each template, including repeated fields, while keeping repeated definitions distinct. Plain links remain usable when a scripted entry could affect only other types. An unresolved variable makes the affected type arbitrary, with the exception of types already definitely enabled by that definition. Two proven enablers already rule out the single-template fallback.

Research folders preserve authored order, use the last name or available field in a block, and evaluate availability in country scope. The first folder definition wins across files, repeats are named, and a refused file contributes no folders. Description effects can be withheld independently of names. Read tactics only when an exact-name tactic unlock needs them. A building unlock captures the level at the point of definition, defaulting to the then-current maximum level. A failed maximum-level scan keeps the previous value, while an explicit unlock level uses zero on conversion failure. Inheritance visits templates in database order and appends the first matching parent's then-current entries after the child's; a missing or self parent adds nothing. Authored entries stay separately available.

Sub-unit pool lookups use the equipment database's registered names and aliases. Known entries read fixed-point values, missing names are logged, and fallback block-valued scalar fields are refused when choosing a recovery shape needs a missing registry. The game's sub-unit type list consumes its first token unconditionally, so the reader refuses an empty form that would consume its closing token as an entry. The registry reads critical parts before units. Technology-sharing definitions use event-scope localisation; a repeated group replaces the earlier pointer, and a second availability body is reported and skipped. These choices preserve the different semantics of technologies, folders, and sharing groups.
