# 1397. Per-widget playback cost, the weak-machine profile, and placeholder failures

The acceptance suite measures dashboard playback on a reproducible weak-machine profile (`--profile weak`: four cores and 4× CPU slowdown; `--profile weak8`: four cores and 8×). Core confinement is enforced at the OS scheduler via `JOB_OBJECT_LIMIT_AFFINITY` on the app's Windows Job Object, which inherits to every WebView2 child process (`msedgewebview2.exe`), and verified before close via `JobObjectBasicProcessIdList` and `GetProcessAffinityMask`. Because Chromium on Windows reads `GetSystemInfo` rather than process affinity for `navigator.hardwareConcurrency`, the sweep also applies `Emulation.setHardwareConcurrencyOverride` before opening the campaign so the page sees the confined processor count and creates `clamp(cores - 2, 1, 4)` drawing lanes. CPU throttling applies across all measured JavaScript steps (`startup`, `pages`, `pages-at`, `glance`, `seeks`, `catalogue`, `controls`, `playback`, `widget-costs`, and browser traces) and is restored after each step or phase; native GPU viewer phases (`map`, `mapfps`) are core-confined without JS throttling. Every session's own Job confinement, `hardwareConcurrency`, and drawing-lane count are verified individually without cross-session fallback and fail the Cold sessions table if any check misses. The report header states both measured confinement and what the profile does not imitate: graphics card performance, memory speed, and native Rust/IPC decoding.

Per-widget playback cost (`--phases widget-costs`) mounts each registered widget kind alone at its default size on a dedicated page and plays each at 1,440 game hours per second for a fixed window under the chosen profile. Measuring alone avoids cross-widget interference and keeps all 114 kinds well under an hour by reusing one session and flushing the perf log between widgets instead of re-reading the entire log per widget. Because `Dashboard` preloads all widget renderer chunks via `requestIdleCallback` on mount, measuring the empty page cold right after opening the campaign catches idle chunk compilation spikes in the baseline. The harness therefore awaits the loader's explicit completion signal (`whenPreloadComplete()` in `ui/src/widgets/rendererLoaders.ts`, exposed on `window.__perf` only when perf logging is active), runs a short warm-up play at 1,440 h/s, and measures the empty-page baseline twice—once before the first widget (`start`) and once after the last (`end`). Both named samples (`start` and `end`) are required before scoring, and their spread is reported; if preloading times out, either sample is missing, loses records, misses 1,440 h/s coverage across its recorded window bounds, has fewer than 30 frames, has a tail gap (`p95 - p50`) over 15 ms, or drifts across the pass (`Δp50 > 3 ms` or `Δp95 > 8 ms`), the baseline fails by name and no widget receives a numeric `costScoreMs`.

Each measured kind is ranked by `costScoreMs = mainDelta.p95 + worker.p95` (net main-thread p95 frame time above the pooled empty-page baseline plus drawing-lane serve time p95 on changing frames). Both `Δp50` and `Δp95` are reported as separate columns beside raw `Main p50` and `Main p95`. Negative deltas are never silently clamped to zero: they are shown as negative and marked `below baseline noise`. Rows with incomplete windows, lost perf records, stopped clocks, zero timed frames, or an unusable baseline receive `costScoreMs = null` instead of zero; rows with fewer than 30 timed frames report their exact frame count and window duration and are flagged as low-sample. A `content` row whose in-window exact reads fail or that displays a future frame fails the cost report while keeping its signed timing score; any post-pause audit error is reported separately with its timestamp. Results are written to `widget-costs.json` and a sorted table in `e2e.md`.

The `Heaviest` fixture page places the N most expensive measured kinds from `widget-costs.json` (default 30, refusing to run if fewer than N measured kinds exist or if discounting an excluded kind's negative main-thread delta to zero would reach or exceed the cutoff kind's score) packed at minimum size into one 4K screen view with zero scrolling, played at 1,440 h/s and judged against 60 presented frames per second, freshness, and exact reads. The outcome observer arms before Play, scans once on the playing transition, stops activation polling immediately, and thereafter classifies only widgets touched by grid DOM mutations using the same `classifyWidgetSnapshot` classifier exercised by unit tests; any placeholder, refusal, error, loading state, or blank body observed during a dated playback window fails by name, and errors are classified as refusals only when positive refusal text matches. A visible "isn't playing back yet" placeholder always fails its row with reason `not migrated`, while keeping the visual distinction between `not migrated` and a real failure so migration progress remains visible.

To baseline unmigrated widgets before they are migrated, `ui/vite.config.ts` hard-codes `__BATTLEPLAN_MEASURE_UNGATED__` to `'false'` in every mode and environment (dead-code-eliminated), while `suite.py build-ui --ungated` selects the separate `ui/vite.ungated.config.ts` config that extends the stock config with `__BATTLEPLAN_MEASURE_UNGATED__: 'true'`. `build-ui` refuses repo paths, symlinks/junctions (including ancestors), and existing non-empty directories lacking `.battleplan-ui-bundle`; it disables Vite's `--emptyOutDir`, builds into a fresh staging directory beside `--out`, writes the marker only on build success, renames any existing `--out` aside to `.old-*`, and renames `.staging-*` into `--out` (two renames, not jointly atomic: a crash between them leaves both `.old-*` and `.staging-*` recoverable beside `--out`, and the next `build-ui` call reports any such leftovers by path). Ownership is re-checked on the renamed backup before cleanup: only a marked backup is removed with `rmtree`, while an unmarked backup is removed with `rmdir()` so any unexpected file that appeared before the rename blocks deletion and is reported by name. No runtime flag exists, and any run using an ungated bundle displays a prominent banner in `e2e.md`.

Individual input checks in `playbackInputs`, the optional `idleCost` sample, and individual scroll/speed windows in `playback` record their own failures and clean up instead of aborting the phase or discarding completed window measurements. `PerfRecorder` binds each picture audit drain to a monotonic generation token so a stale continuation after a timeout cannot drain or overwrite a later audit window. Perf log files are classified once and tagged with their owning session (including viewer `.map.<n>.jsonl` files), and perf log losses are scoped by time overlap to the playing, input, and idle windows they affect; a playing-window loss fails every placement in that window rather than counting any as passed.
