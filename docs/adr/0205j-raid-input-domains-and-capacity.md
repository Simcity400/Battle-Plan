# Carry raid inputs in separate domains and batch unchanged air base capacity reads

Separate notifications key states by state ID and building resources, air-site lists and resource routes by country link. Each domain has one hourly consumer. A matching epoch allows it to carry unmarked rows. A missing bitmap entry, unnamed writer, in-flight writer, disabled observer or changed epoch forces a fresh read. The state domain also reads the daily origin slice because observation cannot certify its supply flag. Its building notification must come from the existing building owner. A province building status affects no state row. An unobserved building owner or nudge mode invalidates only the state domain. Off-thread sizing uses the complete census, and larger replacement bitmaps wait for an invalidating boundary.

The route observer keys an origin under its census list owner. A rights-held origin can send resources from a different country. Its nested updater inherits the list owner only for that origin's embedded route. An origin refresh can clear its kind inline, so its complete native call holds the running guard and marks a changed or unreadable kind. An unchanged kind delegates path changes to the nested updater. A completed-call counter detects a refresh that begins and ends entirely within the bitmap walk, even if both flight reads see zero.

An air-site setter marks a country when capacity changes or its old value cannot be read. Air base registrations also receive that mark. The daily refresh usually stores the values already present. Inside the serial hourly call, the observer can prove this once for the full pass after parallel work joins. It does so only when every value remains unchanged and no base is withdrawn. The setters then forward the native calls without individual reads. Initialization and any unproved pass keep the per-store path. Count the omitted reads once on the pass's normal return. Every pass keeps its native flight until a normal return and restores its caller's enclosing observation scope.

The air-score observer retains off-phase pairs only under a token that tracks in-place clear calls. Disabling observation revokes the token, so an unobserved clear cannot keep a pair current. State modifier refresh and destruction notify the province bunker terms, and core insertion and removal notify country counters. These notifications share the existing patches.

Callbacks map named arguments through the verified receiver kind into the correct state, country, site or route domain and keep the guard through the original call. Claims, cores and strategic locations belong to the state domain. A province location appender names its owning state. Construction, list rebuild, withdrawal, reset and destruction can change the affected country's air-site set. A valid absent owner names no row, while a receiver that cannot be read forces a whole-domain invalidation. The building patch owner changes its forwarding registration as installation state changes. Failed build verification leaves the read path available and every owner is read when the write evidence cannot be trusted.

`target`, `set_country_pool_capacity` and `daily_refresh_base_capacities` use guarded reads on the calling thread with live receivers. The `callback` macro forwards the site's integer and pointer arguments and preserves the original result, while the receiver kind interprets its first three operands. `Hooks::drop` releases the bitmaps after the final capture when the hooks and building forwarder have been restored and drained, or after an unpublished installation is cancelled. The capacity microbenchmark makes each synthetic raw link name the same canonical slot so the detour exercises authenticated slot resolution.
