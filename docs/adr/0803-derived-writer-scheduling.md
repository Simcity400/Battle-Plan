# Run derived writers from witnessed input changes

Apply recorded tables before invoking writers in dependency order. A writer sees the current input tables and preceding writers' outputs. It runs on the first hour, when returning from unavailable inputs, and whenever a watched input changes. An hourly writer may also run to expire one-hour rows or advance a time window without an input change. A skipped, eligible hour leaves the cells and status unchanged. A writer with a missing required table or definition is withheld with the input's user-facing reason and reads whole inputs when it becomes eligible again. Definitions outlive individual runs, and a change makes each declaring writer fresh on its next hour.

`Changed` watches row and selected column edits. `Deleted` retains the cells present at deletion without retaining overwritten values. `Dropped` retains both, with the first prior value of a rewritten cell representing the value before the hour. `EveryRead` observes a read stamp for the current hour even when cells are identical. An unstamped section does not supply a read. `Appended` is reserved for logs and is the only way to watch one. An incomplete log can supply the output's default status and reason unless the writer supplies its own. Separate readers isolate the schema of an input from the derivation consuming it.

Each table has one owner and declares the state or log path required by the schema and store. The framework lends state tables to the writer for its hour and applies each set immediately. Equal values produce no row or cell operation. The recorder emits changed state in canonical key order regardless of the order of the writer's calls. A writer reads its own output through `Rows::table` so that reads see the updates already made in the hour. `Hour::table` is for inputs. Duplicate sets, wrong table kind, or a read of an owned table as an input are refused. An exact derived sum that does not fit its output value is withheld at the cell.

A writer's data error rolls back its state changes and discards pending log operations and strings. Its tables are withheld for the rest of the run and other writers continue. A non-data error can propagate to the recorder. Allocation accounting charges the writer for its own computation and the store for rows and strings it keeps. Writer strings use their own ID region starting at bit 31. Opaque and list values are handed off to the store when a cell takes them.

A run starts with fresh writers and empty derived tables. A resume restores per-writer version and withholding, strings, and any required bounded state. Missing or incompatible writer state withholds that writer by name. `prime` runs after `load` against the committed tables without emitting rows so the next hour compares like the uninterrupted run. The writer tests check byte-for-byte equivalence of due-only and unconditional scheduling, deterministic slots and row encoding, and rollback of state and string writes.
