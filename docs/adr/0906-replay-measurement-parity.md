# 0906. Compare recording content across storage and reader changes

The digest tools compare logical results at corresponding hours, allowing file slots, restore placement and encoders to differ. For every block, `change-digest` chains the per-hour key-ordered changes and holds a separate digest of its final state. It compares the state reached by walking from a run start to each restart's restored state. An optional seek pass starts with only the selected restore's cells and strings. It must reach the same later states and refusal reasons by their actual bytes. Logged tables compare appended and forgotten ordinals along with status, count and live set. A log can start in an hour after the run opens. The journal mode exercises the read-only journal and columnar store without production writers for derived tables.

`direct-read` measures ordinary table reads, chart shapes, ranks and frame walks. Sampled hours are selected uniformly by a seed and sorted by their position across runs. A chart benchmark chooses built-in test ranges and its longest-lived keys, and measures rank and top results separately. Reopened-handle measurements probe the recording path to surface open failures and label results as fresh recording per sample with process-wide caches retained and an unverified system file cache; the `purge` command is refused by name because opening a handle with `FILE_FLAG_NO_BUFFERING` does not evict or verify the Windows file cache for later opens. Reply and row digests include values, keys, missing status and refusal reasons. They use actual text and stable row identity. `read-hours` counts the sample-hour evidence, read flag and edited cells independently, since a table can change without an identical cadence indicator. The walk compares patched views, sampling and updates with rebuilding by cells when verification is enabled. That check is excluded from measured time. File-read bytes and process-wide CPU counters complement wall time. The Windows measurement calls use the current process pseudo-handle and initialized, owned output records that live through each call.

`columnar-staging` compares writer paths on the same input hours and requires their published sections, manifests, strings and restarts to agree. Alternate evaluation order to avoid giving one strategy the warmer input on every hour. Compare visited cells against the cost of reading the wire fields alone. Targeted modes contrast unchanged hours, visited rows with no changes and hours writing sections, including empty batch probes. Sweep testing compares only touched columns with every column. A memory stimulus can be applied before each measured hour. Log measurement compares append and forget against typed rows on the same synthetic shapes, counts bytes and restores and measures reader/application work.

`journal-encode` creates a fixture with the recorder's live writer without launching the game. Read the original journal only. It can generate a multiplied world, pre-roll before measurement, publish a restricted hour span, stop after a block commit and exercise resume on the same output. An output names how its journal was read, and a resume that reads it otherwise is refused by name. A multiplied or pre-rolled output is read from its start, so it is not resumed. The source path goes through the compatible journal generator even at factor one, where it carries every run of the journal. Multiplication and a start take a journal of one run. Its start parameter still parses the block suffix of an older comma-prefixed argument without reading the reference file. Facts, when supplied, must belong to that exact journal content. A continued output uses the facts it already has. The live smoke feature retains the input journal so the result can be compared after publishing. Optional instrumentation labels peak allocations and counts decode operations by dense registry position, with an extra slot for work outside a table.
