# Ship models reuse certified rows across frames

Ship model acquisition gathers a ship's fields together while using the same native readers as a direct walk. A scalar memory adapter provides an independent check of the failure prefix. A fault following a complete batch records the successful entries before the fault, and the selected source packet is never reacquired during repair. A nonpositive selected pool entry still determines the selected input. A refused sprite or absent naval power certificate remains independent of the authenticated model inputs. A current counter group with zero values remains distinct from a legacy recording with that group absent.

- A carried ship must keep its native handle, task force, and live certificate. All frames in a domain share the most recent complete store. A forgotten store, invalidation, or reused task-force address with a different handle triggers a fresh read for the affected scope.
- A notified ship is gathered again. Equal objects and modifier arrays allow reuse under the new certificate. An organisation-only change keeps the model part when its inputs match. Organisation refreshes can change their own storage before a later field gather fails. Equipment-stat refreshes can change sprite contents without changing the string pointer, length, or capacity, and critical-hit writers reach this refresh even when their own header remains equal.
- Design, fleet leader, doctrine and country terms have independent ownership. Held variants are reacquired on a design write, an unobserved domain, or invalidation. Fleet-leader terms require the same fleet, leader binding and tree. A doctrine or country accumulator read is limited to the owner whose certificate expired. A moved task force gathers its current location. A fresh task-force term does not require a fresh model for its first ship.
- The held generation can be republished without projection only when every range kept every finished row at its published position. A row at the same position can remain in the buffer while other task-force terms are read. A move, recomputation, removal or forgotten store changes the generation. An incomplete hour publishes no generation. A naval-power packet also needs the same certificate that supplied it, independent of which frame owned the packet.
- The native census determines capacity and ordering independently of worker count. Split and unsplit acquisitions produce the same bytes and failure outcome. Census overflow raises capacity for the next preparation. The synthetic coverage includes task force relocation, moved roster positions, failed selected fields and unavailable content witnesses.

The warm-memory benchmarks compare fresh acquisition, model reuse and whole-row reuse at fleet scale. They separately time census visits, certificate takes, field gathering, model and organisation reads. The fixtures arrange ships in both large fleets and small task forces, with a cold-cache comparison and a writer that marks a ship while keeping its bytes equal. These separate compute from live memory latency. Counts inferred from code are labeled as source counts.
