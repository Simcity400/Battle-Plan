# 0904. Keep prepared playback state separate from the recording

Preparation checkpoints have a separate schema so a cache revision can invalidate prepared files independently of the recording and spool. They preserve exact interpreted values, explicit field absence and the last known complete acquisition. Validate the whole provenance array before restoring it. A sample may belong only to a complete table and cannot follow the frame's hour. Restoring a sample does not count as an acquisition, and a resumed decoder still enforces its ordinary branch and baseline rules.

Endpoint steps hold owned typed values and absolute patches between two points on the same branch. Their membership boundaries retain resets, deltas, partial walks and refusals across skipped hours. Seed or replace a complete table when its change cannot be described by the available patch. Validate advance and baseline identity before consuming the held state. A different hour must acquire its own complete clock. Separately prepared steps can be combined in table order if their endpoints agree and their table selections are disjoint. The writer batches ascending keys so a delta can update its membership using ordered passes.

Unchanged tables share their immutable allocation across decoded hours. A write copies the allocation when another view still holds it. A decoder may catch up an unshared spare for the next update while retaining each visible hour's own rows. View identity keeps the allocation's address from being reused and does not keep its rows alive. Prepared spool streams intern the view, its change facts and its field stamp so identities survive a round trip. The frame log instead records the initial frame and subsequent changes. It refuses change facts tied to unrecoverable allocation identities. Logs on the same thread may reuse a comparison for the same two allocations while a log holds it.

For an answer cache, record actual table views and the fields and rows read. An unqualified read means the whole table. Once a product provides narrower notes for a table, it must note all reads of that table. Nested recordings add their reads to the enclosing recording. Thread scopes restore the enclosing recorder if a computation unwinds. Compare a dependent's own previous view against the current one. Reuse only when stamps and change facts prove that the reads agree. Indexing the dependents by table, keys and ranges lets updates visit readers whose dependencies can have changed. A whole-table reader also depends on membership, and a derived read may have no table to track.

At the playback head, hold only requested tables and columns. An undeclared read is a bug and is distinct from recording absence. Debug builds detect it with a panic, and a release refuses it with a named reason. Discovery gathers those dependencies so a later read can request them. Borrowed text and lists taken from a partially held row are also subject to field tracking. Acquisition provenance queried by a leaf is itself a table read. An unselected view is separate and shared per thread to avoid contention on the reference count.

Project typed operands from one supplied hour. The decoded-only boundary exposes the underlying frame to legacy callers, while projected callers use the typed capabilities. Status-only checks describe availability independently of row layout. Allocation identity describes storage, and acquisition provenance describes freshness. Both full-table and single-slot row reconstruction read the recorder store's cells in their source format. A field that cannot represent an absent value refuses the row by table and field name. A masked projection can hold temporary defaults for other fields, with access tracking preventing them from being returned as recorded values.

Enable preparation spans only from the measurement harness. The disabled cost is a relaxed load. Enabled spans record the start and end relative to process creation, together with segment, lane and byte count. Native process creation time uses FILETIME ticks of 100 ns since 1601, normalized to the Unix epoch for conversion.

On Windows, `since_creation` passes the current process pseudohandle to `GetProcessTimes`. The four output pointers each refer to a separate writable `FILETIME` owned by the calling function and live until the synchronous call returns. The creation time is used only after the call reports success.
