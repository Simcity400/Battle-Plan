# 0901. Keep manifest and leaf encodings self-validating

Leaf arrays use little-endian fixed-width values aligned from the start of the containing buffer. Alignment bytes are zero. A finishing reader allows only the established zero padding when the caller expects padding. Cell boundaries encode lengths even when the caller holds cumulative ends. Ordered row keys encode the zigzag of each wrapping difference from its predecessor. Slot lists choose delta or bitmap representation by encoded length. Within a list, sorted distinct positions choose runs or a bitmap. Runs encode a gap from the preceding run's end and length less one. The slot bitmap can represent every `u32` slot. Its count and highest slot must agree with its declared bounds. Refuse impossible counts before reserving storage, and bound a varint array's reservation by the remaining payload.

An hour manifest comes before the table sections so a reader can select or skip sections without decoding them. It encodes branch, hour, flags, timing and pool metrics, dictionary appends, a status per table, then read bits. A `SAMPLES` flag adds an ordered list of tables whose sample hour differs from what read bits imply. With no override, a freshly read table samples at the current hour and other tables keep their last sample. Sample zero encodes no sample and nonzero values encode zigzag hours plus one. The present-table bits precede each section's length, changed-column bitmap, and operation flags in table order. A restart precedes a block-start manifest, and read coverage is independent of which sections are present.

An unrecorded status gives an unknown value. A truncated table carries the count of rows the walk could not enumerate, and an unavailable table carries its dictionary refusal reason. A prefix decoder returns the manifest's byte length so streams can continue past it. During a live capture, return the error kind alone to avoid an allocation.

An hour's table section encodes the partial-read slots when applicable, then changed slots, deletes, inserted slots and keys, inserted values in schema order, column runs, unrecorded cells, and touched slots. Deletions apply first so an insertion can take a freed slot. New rows take the lowest free slots, and a section can grow the table by at most its insertion count. A partially read hour can change an existing row only if the read list names it. It can also set newly inserted rows. A section writer validates the run's type and value count before encoding it.

`SET`, `ADD`, `PATCH`, and `NOOP` address positions in the changed-slot list. A `SET` changes the value, an `ADD` carries a same-width integer delta, and a `NOOP` records a repeated write. Fills store one value and the list of live slots they exclude. A list or opaque patch gives each value's hunk count and each hunk's keep, remove and insert counts, followed by the inserted items. The remaining suffix is kept. A later write can restore a cell previously marked unrecorded.

Consumers see both the changed-slot write masks and a mask without `NOOP` operations. Fill targets may be absent from the changed-slot list, so report them separately along with each slot's filled columns. A common fill targets the same rows as the preceding fill, so update the masks without rebuilding the union in that case. Shared scratch storage decodes and applies one inserted column at a time.
