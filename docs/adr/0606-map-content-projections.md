# Keep naval routes and region projections tied to recorded content

Naval combat uses the replay's matching `NDefines`. Each presentation consumer loads only the values it needs. In particular, an unavailable piercing array withholds the explanation that needs it while leaving the naval summary available. Apply the game's conversion width and lower bounds after conversion. Positioning factors and fleet anti-air are floored at zero, and the four screening ratios are floored at 0.01. The live task force's mission indexes its authored sortie ratio, with a missing index reported as unavailable.

Build region neighbours in province and neighbour order from sea-to-sea province edges. An unrestricted crossing or a null rule admits it. Mark a neighbouring region visited before testing its admission rules, so a denied edge does not reopen the region through another path. A rule without a known answer withholds the result. The port projection uses the recorded port sea. Distance lookups for the current home port can fall back to the wrapped centroid distance over the original endpoints, while lookups for stored nearest bases use the raw matrix and its unmapped sentinel. Relax the graph once per base and share that row across its task forces. The matrix's signed index and neighbour-count widths and unsigned distance quantisation are part of its behaviour. Reject a negative narrowed edge that could prevent relaxation from terminating.

Province area counts the engine's map cells, so northern land is enlarged by the map projection. Streaming keeps the raster out of memory as a whole. Validate the native record positions before counting so a duplicate or ambiguous definition cannot attach area to a different province. Include zero for defined water and land with no cells. Cancellation produces an error without a partial vector that a consumer might cache.

Read each strategic-region directory without recursion, preserving declaration order within each file and applying the content stack. An empty higher-layer file can remove a lower-layer template. Discard IDs below one and take the later complete template for a repeated ID. Keep each region's authored province order, skipping unknown and repeated IDs in that region, even when another region also names the province. Playback reads authored temperature periods and their dates. Other weather simulation decisions are already represented by the recording. Repeated weather and static-modifier blocks append in authored order. Temperature ranges consume raw fixed-five tokens and leave the value slot unchanged. `between` consumes a string list and leaves its last token there. Recognise exactly two dot-separated parts for each date bound, treating them as zero-based day and month in year one and applying the game's calendar normalisation. A period with a bound that cannot be represented carries its refusal reason. Missing bound fields retain their initial values.
