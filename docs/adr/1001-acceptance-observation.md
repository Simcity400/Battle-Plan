# 1001. Judge user actions by observed input, paint and explicit completion

Attach to the main application's WebView. The browser client records warnings, errors and exceptions by test case and filters Chromium's own advice. Inspect the app's last requests at its IPC origin without altering them. The acceptance input process sends native map actions to the desktop app's map child window. Wait for native dialogs to finish building their controls before finding their color and confirmation fields.

Measure a step from trusted input, or the final input of a drag or typed value, to the frame that actually paints the effect. Use Event Timing when it exists and otherwise bound the paint using sampled frames. Run the per-frame observation after the application's animation callbacks. Match a long frame's own measured end when available. Viewport clipping excludes obscured geometry, but ancestors outside an open popover cannot clip its top layer. A pending chart draw or loading place name is still loading. Observe the text, markup and pixels a widget shows so a setting without a visible effect can be reported separately from one never applied. The probe may settle early when the app says it drew the new setting but this check detects no visible change.

Wait for the specific widget under test when appropriate. A map deliberately covered by its menu cannot give a paint witness then, and its visibility-only change does not prove that it drew the new settings. Require a new frame acknowledgment of the map options or recognize an unchanged frame that already proves the same settings. If the application tracks its in-flight work, settlement requires a frame after it reaches zero to catch a request that started late. Otherwise use a quiet window. An unavailable input paint time remains a named failure. Capture visual evidence for failed or requested steps. A timing-only failure need not save a screenshot, and warm reversals are reported without grading their time.

Save visual evidence through the parity manifest so it carries both pixels and visible text, or a map's own export. Move the pointer away from widgets when it would add a tooltip. Allow two browser frames after the change so capture reads rendered content. Record real IPC replies and worker follow messages only during an explicitly requested capture. Timestamp them against page time and the recorded hour, include fixture layouts and phase marks, and record app revision and format digest. Keep text as text when a reply is not JSON. Drain the page in bounded chunks, flushing it during the session, and report a lost target instead of silently continuing a partial capture.

Encode large payloads in pieces so constructing a function argument list cannot exhaust the stack. Bound each debugger transfer and split individual entries that exceed the budget. A condition that cannot yet evaluate stays unresolved until a later frame or its deadline.
