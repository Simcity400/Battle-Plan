# 0201. Keep final combat-log records through prune and publication retry

CombatLogEquipment records the game's equipment-loss and recovery records by country, group, reason, month and variant. Most read at the country's slice. The sample at the last hour before the daily tick also selects groups whose logs are about to be pruned. A country receives a full read when it has no complete read in the session, the clock moved backwards or the retained month window no longer covers its previous read.

A group can disappear during the update after an hourly sample. Observing the prune entry captures each departing log's complete final values before the game's prune runs. The original call forwards its argument and result unchanged. The producer reserves a contiguous range in the installed log or takes an owned spill when a whole reservation cannot fit. The count walk reads demand without reading amount values. If the read exceeds its initial count, the complete row set is retried into a spill. A failed spill or an unobserved prune names the interval's loss. Producer-side storage grows from measured native demand. The hourly consumer drains spills and installed entries in reservation order, discarding only wrong-session or unfilled reservations.

The sample load signal ties the shared capture store and observed final rows to one branch. A changed signal or earlier sample resets the store. A final row selects its owner for publication. Its group identity stays unique after the live log disappears. A complete capture retains those finals for a day so a same-session full refresh or a publication refusal can offer them again. A failed Slow job, dropped frame, or unpublished table marks reads for invalidation without taking the store lock on the game thread. An unreadable viewing state stays unavailable on its hourly table. The original visited owner census is reserved before updating published read hours.

The Slow worker completes during the callback, so captures use one production store serially. Tests use separate thread-local stores. A test that opts into the shared synthetic prune log holds its test lock. A quiet detach releases retained native-observer storage explicitly because static owners do not drop on library unload. Published snapshots keep their independent shared lifetime.

`observe` receives the manager whose prune is about to run on this thread, so its guarded read sees that live object before deletion. `record` enters the active count before testing the handoff and loading the log. Its atomic reservation gives that writer exclusive row and signal indices. `Log::rows_mut` forms a slice only from the element pointers in that range because sibling writers own the remaining elements. Each reserved slot is marked, with no session signal for rows that failed or were never written. `Log` can therefore share storage across threads under its reservation protocol. Only the hourly `drain` and detach replace the installed log. Drain accepts a slot only after checking for writer quiescence and uses the row only when its mark provides the expected session.
