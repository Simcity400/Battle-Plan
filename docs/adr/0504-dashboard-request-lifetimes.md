# Keep dashboard replies tied to their subjects and playback hours

A head product follows playback as a pushed panel. A pinned or hovered view makes a dated request, as does a following view before the first push or when a follow is refused. A prepared copy can populate that first request ahead of time. Once the browser observes that a following widget is off screen, suspend both reads and keep the last eligible reply. Keep a dated result only for the same client and canonical subject, and only when eligible for the target hour. An early native answer can wake the widget when the clock gets to its hour without being shown sooner. Guard the subscription race by checking immediately after subscribing.

Keep the hour of the shown structure apart from the current values' through hour. An unchanged pushed panel can advance the latter without a render. Expose the same live cells to the widget for a pushed or asked reply. Route failures that arrive after data has been published to the widget frame so the failure does not hide that data. Each owner supplies one retry action for its errors. A saved toggle is not safe to replay if its acknowledgement was lost.

Reached-hour queries use transient storage to avoid evicting branch history. A request already running can finish when the next hour is selected. Its result can stay visible while the latest requested hour loads. An identity or content subject change disowns the result and cancels the old request. Numeric projections survive a content-only preparation phase and compare once per new reply. Dated catalogue notes retain the supplying sample hour. No entry applies before the first recorded one, and an hourly history and a carried sample certify different read hours.

Windowed history uses one fixed grid aligned to recording blocks. A widget requests the windows needed for the view and may look one window ahead. Payload shape checks allow additional fields and defer continuity to each product. Artwork is addressed by its content hash and served through the desktop scheme or development endpoint.

A widget reports a changed warning by its text and clears its contribution on unmount. A drill that owns its warning surface can delegate the parent report by passing a null warning list.
