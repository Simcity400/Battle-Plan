# 0207. Recover saved design state at the hourly boundary

Native callbacks observe writer lifetimes and copy guarded bytes into prepared storage. The acquisition worker sizes active and spare buffers from a complete census, including nested demand, and replaces and releases retired storage off the game thread. A full event, claim or watch allocation can grow where it is written. An allocation refusal invalidates only the evidence that was lost. Callback diagnostics use process-static sites to keep refusal recording allocation free. Only workers write the named refusal map and serialize status.

Writer claims persist through the original and the terminal copy. The only nested metadata lock order is `STORE` then `WRITERS`. Release both before entering an original or forwarding a notification. Workers holding `STORE` never wait for a native writer or the game thread. A callback may wait to enter prepared metadata. Workers revalidate the flight and capacity high-water marks after allocating fresh storage, and only a quiescent complete census can reset claims. Invalid admissions use prepared slots and may refuse without growing them. An overflow keeps admission closed until preparation succeeds even if some slots subsequently free up.

The shared native owner installs and observes move writers before dependent forwarding can open. A rejected original still contributes to the owner's flight count through its terminal phase. The control thread opens prepared dispatch, drains outstanding originals and then publishes a capability tied to that baseline epoch. New originals must notify that epoch before it becomes current. Callback invalidation withdraws admission without waiting. Reset wins against old publishers, and any dispatch gap invalidates prior capabilities even when native baselines remain admitted. Consumers validate the capability before and after a read and again before publishing or carrying state. Local log refusal withdraws dependent admission while leaving writer observation running. Its revision and dirty evidence are needed for recovery.

A consuming move saves both old bindings before the original. A surviving destination is read again at the boundary. Its source is never read afterward. Publishing joins the watched set, and destruction retires the binding while its native fields are still live. Unpublished clones and drafts do not produce saved snapshots. A callback admitted while a receiver looked unbound or draft must still recheck membership at its original's return. A recorded receiver claim outlives interruptions in saved membership, including a conflicting writer that completes before the enclosing edit republishes.

Ordinary content conflicts repair the affected receiver. Identity checks of a parent remain valid during ordinary stats changes, while overlapping moves and destruction can invalidate the whole ancestry path, even through an intermediate ancestor. An ancestry claim covers those lifetimes before the path is followed. A derived refresh may update an independently saved version owner even during an enclosing snapshot or draft edit. Claims close and inspect conflict state together, so late writers cannot hide a conflict while bindings appear absent. The last exit publishes its revision before it decrements the active count, and unwind closes the claim without certifying a snapshot.

The parked hourly boundary validates revisions before accepting a batch. A yield or original that crosses an observation gap cannot install old evidence. An occurrence-log refusal alone can leave untouched held values admissible while a census reauthenticates the complete registry and prefixes. Lost membership, lifetime or dependency evidence requires a complete census. A single recovery read may consume its immediate retry. The next scheduled daily census supplies a later admission opportunity. Recovery never fills the occurrence history for an uncovered interval.

An overlapping edit leaves a dirty mark for a terminal read. Remove its untrustworthy snapshots while retaining tombstones, source events and author-liveness occurrences in order. Repair newly published designs that were missing from the prepared registry, scanning watched designs if the publication list could not grow. Check consumed parents against the previous state before replacing it. The live reader also guards its own addresses, since a lost edit can introduce a parent the previous baseline never reached. Carry stays closed until every marked design needed for repair has settled. A failed boundary leaves the touched designs for the census and drops their outdated witnesses and suspended dependency bindings.

A complete design walk records each guarded read's bytes or refusal. When every read repeats in order, a deterministic walk would derive the same addresses and data. That witness lets the next boundary reuse the design without decoding, while still publishing the current touched row and liveness. An unsuccessful witness allocation forfeits reuse and leaves the next touch to walk. Drop witnesses when the corresponding held state changes through a census, native occurrence or retirement. Leave disjoint deep payloads shared. Merge terminal state by stable slot, with a complete census sorted before publication. Keep variant changes in occurrence order, even when only their terminal rows update the held state.

Variants lanes may claim enough independent work to amortize dispatch. Use small parts so any free lane or the parent can finish remaining work. The lanes read guarded spans and decode owned payloads without observable effects. The drain completes effects in design order, including any work that did not finish speculatively. Source bindings used by a marked design are suspended until it proves them unchanged or reseeds them. A forced read refreshes every MIO and only then records new demand. The last notification of each watched source is materialized at the boundary, after retirements. Design-MIO references, raw author identities and current author liveness are reconciled separately.

## Safety contracts

- `design_changes::Hooks::new` requires a verified executable identity and exclusive ownership of its sites. Its owner remains live until patch restoration and callback quiescence are proved. Only then can `Hooks::drop` clear its capture buffers and invoke `repair::release`, which also requires acquisition to have stopped.
- `design_changes::Captured::capture_partitioned` lends snapshot parts that borrow the drain batch and its retained cache. The supplied operation must return every part or drop it and wait for all users before it returns or unwinds. `snapshots::speculative::Part::read` opens live memory only while the hourly original is parked.
- `design_changes::diagnostics::sites` dereferences a linked diagnostic site only because published nodes have process-static storage and are never removed or freed.
- `design_changes::forward::Forwarder` uses process-static receivers. Its callbacks may neither panic, enter registration again, block nor change hook availability. Reset can withdraw capability on a callback while retaining the terminal phase for an active invocation. Validate the live capability each time. A native pointer is borrowed only for that invocation and conveys no longer lifetime.
- `design_template_changes::Hooks::drop` releases the dirty tracker after patch restoration and after both template callbacks and acquisition workers have quiesced.
- `variants_walk_bench` supplies guarded memory reads from immutable synthetic storage held alive for the whole loop.
