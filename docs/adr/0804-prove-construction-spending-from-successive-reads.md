# Prove construction spending from successive reads

The save does not hold cumulative construction spending. Compare successive queue reads, observed target growth and native cost deductions instead. A complete queue includes every live line. Retiring a final row does not erase earlier witnessed spending. Read stamps distinguish a scheduled or forced construction read from an hour that carried the previous sample. A missed line or a window across different targets cannot certify progress. [Construction output comparison](../../crates/recorder-oracle-construction/src/construction/output.rs)

Building lookup prefers a province target, then a positive offsite country, then the resolved state. Offsite health is unavailable. Repair progress uses the stored partial-health scale, and base repair can advance while no IC is spent. A linked secondary line can mirror its primary. Railway progress is shared by both directions of the province pair and can advance without a particular queued line paying for it. A carry forwarded to another segment bounds possible discarded progress without proving where every unit went. Script gifts can also raise levels independent of queue spending. Native progress and deduction operations compare as signed stored words after widening the aggregate arithmetic.

When a count rises or falls by less than the observed completions, exact integral cost deductions and enough observed target growth can witness the completions. They cannot establish an independent queue addition. The current read and save must certify the line's resulting count, and intervening windows still check it. A witnessed reset or an ownership transfer instead establishes that the old owner's quantity and repair levels were cleared independently of spending. Historical rows without the reset witness can compare exact integral deductions within the cleared quantity. The reset itself accounts for no spending. Tests exercise historical suffix absence using decoded rows because the current encoder requires the current fields.
