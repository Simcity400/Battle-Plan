# 0906. Encode changed masks without revalidating whole rows

A row field can be unrecorded separately from every native value, including empty and `None`. Constructors for current producers start with a recorded native default. An older layout fills absent fields with unrecorded and carries field presence alongside the decoder's format. The snapshot's layout supplies presence. A restored whole opaque field recognizes its retired empty payload and can re-encode that payload byte-for-byte. Other nested values use their own structural framing within the parent's bounds.

Declare field position, field type and optional display step together in each typed codec. Wire visitors expose stepped values as step counts, and reading scales back to native units. Both sides of a stepped numeric delta are rounded first, making the delta a whole number of steps. Exact signed numeric differences use zigzag varints. A partial read leaves unselected members at their defaults and cannot assert whole-row validity. Some types need the full decoder and cannot patch a partial row in place. Const field names and masks keep callers aligned to declared positions. A shared error helper names the field without compiling a closure for every schema column.

The encoder walks ordered keys once. After validation, check equality before sizing any changed row's nested payloads. An unchanged table writes no change header or entries. Advisory reporting can collect edited positions and deleted keys without blocking encoding when that report cannot grow. Decoding can own the previous row to retain existing string and list allocations for unchanged fields. A typed application uses in-place edits when only a few keys change. With more insertions or deletions, it moves retained runs into a new table once. Order changes or absent claimed deletion keys use the merge path. If a key is both replaced and deleted, the replacement stands. A shared baseline clones only rows kept or changed, while a validated baseline revalidates the changed rows and their boundary order in acquisition order.

List fields can reference native decoded values or checked wire bytes. Only constructing the owning row needs a list allocation. Older-layout and unrecorded-field fixtures exercise reader compatibility independently of current-assumption row constructors.
