# Separate GUI definition loading from session-dependent inheritance

Use the recorded stack's equivalent of the virtual filesystem and preserve its byte paths. Open the literal `interface/load_screen.gui` request first, applying the folder and archive lookup rules. Then read the remaining files in depth-first order with each directory's files in byte order before its children. Parallel reads retain this order and propagate the first failure in it. Cache definitions before inheritance so different GUI root sizes can use the same content without reusing a previous session's geometry. Apply inheritance to the load screen on its own, then to the completed template registry.

Generated names use one counter across the stack. A file's counter span does not depend on its initial position. The parallel reader can read files from zero, then reread files whose generated names have a nonzero base. Backgrounds and the inner container of a drop-down never take a generated name. Distinguish the authored bytes used for lookup from the lossy presentation name. Keep one reader for the key, operator and value slots, dynamic tokens and script variables. Static keyword identity comes from verified executable metadata, and only synchronized dynamic tokens already loaded from the recording are available at this point. Exact registration depends on order, quotedness, ASCII folding and NUL termination.

Construct each child completely before registration. Ordinary containers keep the first lowered name. Windows and scrollbars resolve the last. A window can register a named background button outside its normal kind and order lists. Unsupported template kinds stay named with their refusal. Typed lookup uses the matching kind's list, position lookup tests exact bytes, and recursive child lookup follows attachment order. The shared registry makes later file registrations visible, including when inheritance targets another file. Iterative construction, post-load traversal and destruction support nested files without tying nesting depth to the Rust call stack.

Inheritance uses the parent's tree where the source element does. Backgrounds outside a container's tree are unseen by that pass. A drop-down and extended scrollbar pass on their incoming lookup, and the drop-down's inner container supplies its own tree. Buttons fill an empty sprite through the parent chain and parse text orientation after loading. Scrollbar and window parents fill whole unset fields by their respective key lists. Window children visit first, and an already visited parent supplies its updated state. Missing, type-mismatched and cyclic parents can prevent a native walk from finishing. The reader names these refusals, including the list-box parent walk that never resolves an unset step. A `max_resolution` axis or fullscreen window needs the particular client's GUI extent, so an absent extent is reported as missing input.

Keep the distinction between an undefined field, an undefined walk that makes subsequent element boundaries unknowable, and a session operand the recording does not hold. Record refusals against element labels before all names are known, then build their full paths at the end. Child paths, external parts and descendants remain available through the same tree model. An element poisoned by undefined consumption cannot be treated as merely absent.
