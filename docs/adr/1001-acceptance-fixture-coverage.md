# 1001. Exercise actual dashboard configurations in isolated acceptance sessions

Use the application's storage writers and validators to prepare every-widget layouts. The compact fixture packs minimum-size widgets into a single 4K view. The legible fixture keeps default sizes, puts as many whole widgets as possible above the fold, and scrolls to the rest. A taller default-size viewport is a stress measurement. Packing obeys the application's vertical compaction and compares candidate orders. Virtual device metrics choose the highest whole UI step that fits the required CSS height onto the exact device pixels.

Each cold session has a fresh profile and empty caches alongside a copy of the same fixture in the app's own library. Compare fixture identity before accepting old pictures as the baseline. A Windows Job Object owns the app and its descendants, with the app initially suspended until assigned. Above-normal priority limits interference on the shared test machine. Keep console handles and the Unicode environment when launching. Release the owned job and allow its children to release files before clearing the session. App records include PID and creation time to distinguish separate runs. Native input is scoped to that suite session. Judge only requested phases, including a phase whose app failed to start. Keep running later sessions and write the report after a failure.

Use trusted input to exercise actual controls. Require the requested page and its widgets to be visibly ready, then scroll one step at a time and capture each visit. Measure page switches from a different page and cold seeks at distinct hours, then revisit those hours warm. Verify the chosen speed and the actual clock rate before judging playback. Arrange one catalogue item at a time on an empty page and wait for the native map's first presented frame after arranging. Clear a failed arrangement before continuing. The quick tier samples the first placement of each widget kind and the previously slowest cards and heaviest playback pages. It installs only its own temporary changes.

Deduplicate a placement only when widget kind, dimensions, settings and neighboring widgets match. Retain previous failing cases and allow the caller to pin either all failures or product failures. A run that did not cover the full catalogue preserves its previous slowest cards. Match each control across menu rebuilds by identity, not its viewport index alone. Test its values pairwise across settings states, including newly revealed controls, then restore state through the same UI. Never choose a disabled option. Preserve inheritance, automatic numeric values and the correct identities when display labels can repeat. Wait for each clock input to take effect before sending the next. Report an unavailable native save or color dialog as a named failure. Reset an unknown custom icon only in the isolated profile because the sweep cannot reconstruct its previous icon.

Capture replies before opening the recording when requested. Reply capture waits for actual in-flight requests rather than the performance timeout, which could leave later requests missing from a test fixture. Run a traced playback window separately because tracing itself changes timings. Measure native map settings after dismissing their menu because it covers and pauses the map. Judge the frame using the options that the app actually saved. Match dropdown and picker rows over the whole virtual list rather than trusting the mounted window. Distinguish setup, committed settings, rendered effect and restoration so a control has a separate result for each kind of failure.

Recognize matching controls by stable setting identity, and use faction IDs where the test can change a faction's name. Cover each reachable control and report unknown controls by name. A mounted worker surface still declares itself while its ink is hidden between reads. Track its visibility separately. A wheel test picks a scrollable node with room left and verifies what the pointer hits at that node's center.
