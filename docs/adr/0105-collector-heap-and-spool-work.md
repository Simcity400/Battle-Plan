# 0105. Reuse collector allocations and move bulk conversion off capture

The collector owns a private Windows heap and has no process-heap fallback. Small allocations use per-thread size-class caches, and acquisition workers hand batches through a lock-free depot because other workers free their allocations. A thread retains a partial list and one full spare, sends each older full batch onward, then refills from the list, spare, or depot in that order. The depot shares one byte budget across classes. Threads outside the game hold can free excess batches to the private heap. Ordinary cached hold-path blocks can pass the limit to avoid those frees. Cold refills, over-aligned blocks and cache bypasses still use the private heap. Wait measurements distinguish the hold path from collector-only workers, and their longest observed call does not subtract when computing a difference of counters.

Free-block links use the first pointer word. A depot batches the block with a Windows interlocked list that needs the first two words, so the batch's next link uses the second word while parked and all classes provide at least 16 bytes. The interlocked header is zero-initialized and accessed only through the list operations. Over-aligned small allocations reserve enough alignment padding and keep the original pointer in the word before the body. Thread-local caches are constant-initialized without a destructor. They track which heap they belong to and are not borrowed across any allocation. Explicit thread exit returns whole batches to the depot when possible and frees the remaining blocks. Later allocations bypass the closed thread cache.

Large allocations use page reservations grouped by power-of-two size. The metadata stays at the reservation base and the word before the body leads back to it. Allocation granularity gives bodies with ordinary page alignment the same offset in matching reservations. A fresh reservation is released if its first commit fails, while a reused reservation returns to its list with its previous commitment. Fresh commits are zeroed by Windows and zeroed allocation clears reused bytes too. Off-hold frees can decommit body pages above the committed-byte budget. In-place resize can commit or trim within a reservation. A failed grow keeps the old block and its payload. Reallocation beyond the reservation, between small classes, or for an over-aligned small block first allocates the new block and frees the old one only after success. The allocator returns null without unwinding and leaves recording-specific failure accounting to checked callers.

Heap creation is allocation-free so attach can refuse before an infallible Rust allocation. The initialization cell caches creation failure. Explicit unload leaves a terminal zero handle, destroys the heap and releases the reservations after worker and callback quiescence.

The spool alone converts packs without a helper marker. Each movable pack is claimed once by the spool or a helper, with the first helper also taking map conversion. The next hour orders unknown costs first in pack order, then known costs slowest first. An unmeasured movable pack needs every available helper. Once measured, the pool size aims to bring total work per thread near the longest movable pack, subject to the available workers. The previous fixed lane order remains a benchmark comparison. Each worker reports wall time, including waits, and costs from its own packs, so merging cannot double-charge those times. An hour without conversion creates no new cost sample, and the current frame consumes its diagnostics once.
