# Acquire division and border inputs from the shared census

Division detail acquisition uses the authenticated census once and passes owned rows across the worker boundary. The decode worker installs the owned packet without rewalking live pointers. Equipment, upgrade groups, requests, deliveries and produced equipment keep separate outcomes and capacities. Upgrade groups have one row per admitted census source. The worker grows from native header demand, and metrics charge the shared upgrades traversal to the group table. The child slots have zero additional charge.

Installation swaps buffers with the destination so the old packet returns to the same pool without a row copy. Before reuse, the packet prepares the displaced group buffer to the census capacity floor so both owners can support the next callback. Tests distinguish demand from the logical headers and retained array capacities, and verify that reads outside the four-byte scalar fast path keep their original behavior.

The design observer owns the variant writer set and forwards changes to division panels and ship models. Edits and roster-wide upgrades affect the ship-model cache only. Global invalidation treats the receiver as the source of the invalidation, so it revokes all variant observations without treating the source as retired variant storage. Move notifications enter for destination and source, finish in reverse order and never dereference storage in terminal callbacks.

Border conflicts can use the controller doctrine of an active province with no divisions. The collector takes the relevant controllers from all active states so the recording serves every hover perspective. The land-membership inputs and controller-doctrine inputs are independent joins, allowing one result to stay available when the other is withheld.
