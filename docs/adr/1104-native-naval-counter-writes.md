# 1104. Carry native naval window updates forward as ordered writes

Hour preparation computes ordered writes for the naval counter, combat marker and convoy addition before the presented view allocates or lays out its native window. Resolve children by authored name and type. A missing or differently typed child has no effective write. Keep sprite and text calls in order, since sprite selection acts on the current drawable and text immediately refreshes its scrollbar. Merge other fields by child. As the window updates, untouched controls retain their state. A drawable whose inputs are unknown remains retained and withholds the window while visible, until a later proved write replaces it. A definite hide makes a part unobservable but preserves its uncertainty for a later Show that keeps the drawable. A hide bit is separate from visibility and survives a parent window's Show. Admit the exact quads of the laid-out window or holder at whole interface pixels and preserve attachment order within its layer. Each missing resource refuses the relevant drawing by name.

Country mode uses the logical owner's current UI colour, including inherited overlord colour. Allegiance mode uses the type-icon relation for at-sea plates and the mission item's own allegiance in port or combat. A mixed-owner port item chooses the owner by lowest total ship strength; a partial census can prevent that choice. Atlas lookup uses the current country slot, cosmetic tag and ruling ideology. Missing input retains only the parts that cannot be written, so a low-intel `?` can still be written even when the census cannot supply the count. At sea, plate frame follows all members' mission activity. Coarse counters use frame 3, keep prior invalid-order glyph state and hide detailed parts. They still update carrier, capitals and pride. Detailed counters use the first member for selection, the expeditionary owner's flag and the logical owner's ruling ideology where bound. The spotting bar stays hidden at sea. Order glyphs are mutually exclusive on screen and a known false no-orders value still gets a write.

Port items and combat tiles retain their authored visibility for the plate, flags and counts. Use first-member intel for exact, ranged or unknown count text. Capital count considers all member ships. Full intel updates the bars and supply from the reached inputs. A lower-intel update can retain the prior supply drawable. Measure a bar using its drawable, including fallback art, and truncate the scaled extent before calculating movement. Hull selection uses the ship definition's sprite at its pictorial frame. An empty, invalid or undeclared selection keeps the current drawable. An undecidable hull instead withholds the visible part. The low-intel hull frame uses the NATO preference. Replacing the drawable between frame writes can reset that frame to its authored value. Carrier, convoy and result sprites use the same current-drawable rule. A declared sprite that cannot be drawn names the missing resource. Mission items unflag before showing, and their grid's spotting operands leave the spotting bar hidden. The mission frame requires own membership and matching first and last missions.

Combat rotation writes independently of the naval-HQ button and only for a matching combat province. Hide and flag both progress bars before an engaged update shows one. The engaged background frame is the zero-based variant plus one. An unengaged update retains it and leaves the grids clear. Progress uses fixed5 and rounds half away from zero before narrowing to the frame value. The reversed direction turns by half a rotation and offsets by the authored drawable's width and negative height. If that extent is unavailable, only the progress move remains undecided. Port and combat grid items construct in the GUI viewport and finalize relative to their holder, with the item offset added to its slot. A slot the content cannot place omits that item.
