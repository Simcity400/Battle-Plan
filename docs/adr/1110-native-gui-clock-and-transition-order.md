# 1110. Advance GUI clocks before visibility can stop them

The frame clock drives drawables while their own visibility permits it. A show can start or resume a drawable, and a hide stops further clock advances while retaining its history. Fallback, inherited and nested parts keep their own clocks. A play call reaches the drawable in place at that point in the call stream. A later successful replacement starts a fresh drawable, including a fresh state effect, frame animation trigger and pulse. An unchanged or unresolved replacement retains prior state and any play request. A looping period whose subtraction cannot progress leaves a named refusal when that drawable is reached.

The native frame runs clocks across every participant, then transitions in reverse registration order, then draws. This lets a child clock advance on the same frame a parent's completed fade hides it. An out-of-order phase is refused. The window factory preserves registration order when a pool grows, and a drop-down registers its header separately from the normal child list. A prepared recording hour retains the control call order and applies it once on the presented frame.

Visibility and fade state are separate. Guarded show does not move or reveal a hidden control. A parent can still reach a child's fade-start path while the child's guard prevents its own show. Immediate hide reaches descendants and relevant parts, and later show checks each guard again. A child can fade on its own clock while the parent draws opaque. The map's bound point can give way to an active window movement. An immovable map icon snaps to its prior target before beginning the show movement. A movable icon begins from its current bound point. When the movement ends the map's point takes over.

A compiled technique's clock analysis determines whether the instance still needs presentation. A direct dependency on advancing time keeps it active. A saturating difference between time and animation time can settle after its final changed frame. Constants and trigger time reflect the drawable's own first draw. The equality boundary of a shader step can require another frame even at its nominal interval end. A program that may later overflow cannot prove that it has settled. A missing technique can inherit the previous program with the current drawable's clocks, including a state effect following a text draw. When that preceding program is unknown, the instance cannot certify settling.
