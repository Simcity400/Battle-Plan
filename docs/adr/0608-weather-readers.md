# Preserve authored weather slots when their contents cannot be presented

The weather readers use the recorded mod stack for weather settings, effect declarations, province inputs and strategic-region templates. The recorded data identifies effect pairs by bank and authored position. Banks follow the region flags for light rain, heavy rain, snow, blizzard and sandstorm, with separate small banks. A repeated effects block clears the banks. Each pair has optional start and fading entities, and a pair withheld by name still occupies its authored slot. Preserve that position so a refused effect cannot shift subsequent effects.

The effect reader reuses the descriptor registry shared by model and light consumers. Clones inherit the parent's registration-time state, including its ordered sound events, so a later definition cannot change their effects retroactively. Parent culling spheres are independent of their particles. The radius is the authored radius scaled by the largest parent basis length. Particle and sound times are seconds from entry into the default state. A particle scheduled later is emitted once when that time arrives. Withhold a named pair when its form depends on a particle replacement, mesh, node attachment, state transition, animation, weighted variant, or a clock offset, scale or loop that playback cannot reproduce.

The weather reader follows native token consumption through the entire file, including settings that can terminate the loader. An unknown setting or malformed interval receives a named refusal instead of publishing later effects the game never reaches. The terrain-modifier dispatcher consumes unrecognized kinds using the default kind's shape, and an unrecognized terrain field still consumes one operand. A failed token conversion can preserve the previous slot value, depending on the field reader. Thermal and snow ranges require two signed fixed5 operands. An unreadable list entry leaves its zero initial value. Repeated settings groups preserve unrelated slots and overwrite each matching pair. A scalar snow ceiling assignment overwrites that ceiling.

Intervals include the lower bound and exclude the upper bound. Unset intervals hold nothing. The thermal modifier is the first matching interval in weather-manager slot order. Ground snow uses the sum of temporary and permanent snow up to the ceiling and prefers the high modifier if both snow intervals match. Inverted and overlapping input survives parsing. Enumerating reachable modifiers only needs the interval boundaries, the lowest temperature and, for snow, the cap. The display shows the null modifier as empty. It does not substitute base game localisation for an unresolved identifier.

The hourly temperature parser preserves full fixed5 settings and the signed integer update window. Each terrain-modifier block replaces earlier entries. A missing terrain kind retains the initial negative ordinal, whereas an unknown name explicitly selects the null terrain. Failed terrain-value conversion leaves its earlier value. A province input is active only for a positive slot with painted geometry. The runtime requires dense province slots indexed by their IDs. The setup keeps recorded neighbours and visits regions by ID, so the last region that claims a province owns its weather link. Null terrain validity stays unknown when it can affect a modifier. Likewise, an invented province for an unclaimed colour does not imply a known default terrain.
