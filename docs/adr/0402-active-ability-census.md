# 0402. Retain ability records as they appeared in the country's array

The persistent record in `active_ability_record` contains a date object with its own vtable. That vtable authenticates the date field only. The country that owns the array and the record's event-scope country can differ. The native array position orders observations within a read. It cannot identify an occurrence across hours because removal swaps in the last record. A caster comes from the resolved unit-leader identity, and a region target needs its own authentication. Preserve the game's hour, signed fixed-point cost, native phase byte, and initializer-backed counters, including when the optional caster or allocation path is absent.

The capacity probe reads the record count and token descriptors needed for sizing. It does not copy the token payload or validate unrelated caster and region fields. A truncated capture can still count all remaining token lengths for a single later growth step. Consecutive references to the same definition can share a validated descriptor within that pass. A malformed or unreadable descriptor stops the count where the reader encountered it.

Definition validity controls the unlock marker. The country-wide target requires no caster or formation match. The duration and cooldown fields determine whether a record remains active or is removed. These definition fields supply acquisition and replay operands. A complete ability-availability decision requires additional inputs.
