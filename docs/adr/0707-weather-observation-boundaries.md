# 0707. Observe weather simulation and display independently

The hourly simulation joins its workers before capture. The graphics publish can still have work outstanding. Read its equality token and queue status around the copy, preserving the ordering of those checks. A token saved before work began is useful only when the opening and closing checks also establish that the relevant work ended. Simulation tables authenticate their array headers independently. Pass-local movement reads retain their first header attempts, including failures, so another region cannot turn a single observation into a retry. [Weather reader](../../crates/engine-native/src/cweather_manager.rs)

The simulation advances its province and region cursors by signed, content-defined windows, wrapping at their respective signed counts. Initialization visits both complete arrays and clears its special mode after the hourly update. The hourly pass adds a synchronized random word to the unsigned seed before hashing each province with it. Weather tests both stored gate bytes before updating. They can hold weather or day/night values, including a known local hour of zero and the initialized seasonal values. An ordinary completed update lets the reader derive seasonal direction from the hour. A held clock needs the stored direction. Content supplies the signed 64-bit fixed-point snow ceiling at load and the graphics refresh interval. [Weather reader](../../crates/engine-native/src/cweather_manager.rs)

Dense weather arrays include slot zero. Gather exact fields in one guarded boundary for a bounded block, then decode and validate the completed field prefix in row order. A matching owned view may avoid the copy but follows the same scheduling and decoder. A valid strided envelope admits the same field addresses without individually rebuilding them. An invalid envelope leaves the existing failed-slot and completed-prefix behavior intact. [Weather reader](../../crates/engine-native/src/cweather_manager.rs)

The movement reader checks an authored region ID or province ID against the live bounds before reading the data pointer. Its weather-row identity is gathered together without walking dense rows. Zero is a known absent movement modifier and a failed read is unavailable. Naval combat uses the active regional signed 16-bit vector, bounded by the selected strategic template and packed into storage the worker sized before capture. The byte view uses the owned two-byte-aligned integer storage and the little-endian Windows target's layout. [Weather reader](../../crates/engine-native/src/cweather_manager.rs)

Ordinary province changes can enqueue overlapping interior rectangles. The count alone can exceed the grid size, and interior entries never reach the last row or column. A complete-grid mark reaches those edges. It is recognized by the first last-column entry at its corresponding queue position. The queue header must hold that entry and match when read again, so a torn growth cannot admit an out-of-range read. Read only the right column, south first without the northern corner, and the complete northern row. Store snow before mud. The dimensions are the live map dimensions quartered, including odd-sized mod rasters. The protocol works at attach because it needs no earlier scene or full-grid copy. The graphics grid averages its display-snow bytes from the province-indexed source array. Display mud occupies the other byte array and retains its binary byte values. The refresh-start floating-point word supplies identity for comparing copies, while the grid pointers and both output extents describe the published planes.
