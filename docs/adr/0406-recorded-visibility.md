# Record visibility history independently of the viewing UI

Unit intel reads stored entries because visibility levels depend on update history. An upsert selects the viewer by its country ordinal, resets the decay accumulator and stores a signed level. Updates advance the accumulator by class and swap-remove expired entries. Keep all native entries, including nonpositive levels, in their stored order. Their key includes the unit handle and slot ordinal, so capture joins them to the unit's own rows without another mapping. Roster order comes from the canonical country census, even when unrelated private division fields or a separate Divisions projection fail. [Unit visibility entries](../../crates/engine-visibility/src/unit_viewer_entry.rs)

Each counted division, task-force or railway-gun member must authenticate and yield its handle and vector. Nulls, a bad identity, invalid vector bounds or short reads withhold the table. Storage pressure omits whole entries and accounts for their demand. The shared division census can supply first-block copies grouped across divisions. A failed scatter lets each affected division take its first block at the normal serial point. That preserves error order and one-shot behavior, and later blocks and non-division rosters retain their original path. [Visibility walk and fixtures](../../crates/engine-visibility/src/unit_viewer_entry.rs)

On-demand unit intel and province fog consume simulation fields without reading a viewpoint or presentation buffer. Unit visibility uses one effective country modifier per live country. A held raw accumulator value still reads its effective metadata at the original position. Province fog reads its state modifier for owned states controlled by another country and retains the census extent, including null slots. The simulation's human-AI and instant-decision values are separate debug bytes. [Simulation operands](../../crates/engine-visibility/src/visibility_inputs.rs)

The local player's raid cache has different provenance. It rebuilds on demand when marked dirty and stores database indices in native order for the country it was built for. Its separate sizing method reads the header alone. The capture copies resolved raid tokens into caller-owned storage, accounting for any that do not fit. [Raid cache](../../crates/engine-visibility/src/cplayer_status_cache.rs)
