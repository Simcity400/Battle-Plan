# 1001. Use native browser input and verify owned process shutdown

Test browser behavior through native input in a fresh Edge profile and load a fixture into that page. DevTools commands await promise results, and callers can open a separate connection to the page endpoint. Recorded replies come from a fixture that must match the current recording format. Stage deadlines fail deliberately when the browser exits or the response never settles.

Terminate the browser within a single deadline and attempt budget, which includes confirming absence. A dead launcher does not certify shutdown because detached WebView descendants or a compatibility relaunch can still hold the exact profile. Match whole process arguments against the owned profile and keep the native child handle. Once a PID-scoped termination request completes, do not reuse its numeric PID because another process can acquire it. A failed CIM query or pending Node notification cannot justify acting on an unrelated process. Verified owned process absence can settle cleanup even while Node's pipe event remains outstanding. Release that child's handles and then remove its temporary profile. Synthetic tests exercise failure, delayed notifications and exact-profile races.

The browser fixture manifest checks the actual static import graph rather than searching source strings. Follow Node's URL rules for imports and filesystem rules for require paths. Node can erase TypeScript namespaces only when they and their nested namespaces contain declarations without runtime code. A fixture that cannot load under Node's stripped mode belongs in the browser list. Run the two test groups serially and report a failure in either. Scope mode environment variables over the whole group because the test runner creates children that inherit them. Tooling tests launch isolated driver children to cover the normal entry context without recursive tests or a browser.
