# Retain raid definition order and unresolved declarations

Load raid categories before types from the recorded mod stack. A later category declaration with the same case-folded name starts a new category. Types retain database order because their indices and the per-target offer order depend on it. A repeated type name leaves its index ambiguous. Keep its understood declarations and refusal reason so offers involving the type remain undecided to consumers. If the equipment database stops early, resolve only the types it encountered and keep remaining keys undecided. An unknown key can alter the parser's consumption of a block, so guessing would also affect subsequent fields.

Read trigger lists, equipment pools, starting points, target selectors, arrows and models into their persistent fields. Triggers append, scalars replace on successful conversion, and reported fields leave previous values intact. An empty `allowed` block admits a country. The generic province target is set through the raid interface rather than offered as a particular target. A type's nonempty custom icon replaces its generated icon name. Try the building-template variant when that sprite exists. Evaluate hover text and chance formulas separately from the available-target icon. Standard modifiers use a folded token and custom modifiers use the authored key. A custom modifier without a formula term is reported and dropped.

Token identity matters when projecting targets and launch requirements. Ordinary lists read the parser's value slot, and building name registration can read the lexer's current token. Preserve selector arms only when they can match. A repeated battalion key leaves its earlier requirement in place, and each equipment module group requires one matching module. An undecided or unmodelled source kind is refused by name. Unit model categories outside the air categories are discarded. Read model scale, offset and speed in fixed five, and retain animation stages in authored order. The graphics defines preserve single-precision values and raise arrow segment and subdivision counts to at least one. Missing sections remain errors.

Map and dashboard joins share the same raid target priorities. For country, use building, province, state, resolved captive's captor, then leader province. A resolved captor's raw value suppresses the last fallback. For plain location, use explicit state, province, leader province, then building state. Province victory-point localisation first tries a qualified name, including for reserved country slot zero. An existing empty qualified key suppresses the bare-key retry, which lets the state display name take over.

Raid unit and ship names use the same name-group database as divisions. Compare groups without case, merge repeated declarations, and apply each group's prefix to both entry lists. A refusal keeps the corresponding group and member names unavailable.
