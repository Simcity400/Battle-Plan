# Measure playback without delaying its frames

The stepped harness holds its clock at each measured hour so a newly joined table reads that hour. A paced run lets the playhead build ahead of the display clock. It holds a seek at the target until the reset first shows, then resumes at the run's speed. The seek report marks reset taken, compose swapped, first political product, all drawn products, and lag within one step. A backward seek needs these publication markers because the previous frame can have a numerically later hour. The next seek waits for all content of the previous seek, while the lag threshold is measured separately.

Windowed runs present through the product's swap chain and separately time image acquisition. The campaign-tab case draws the regular app frame with audio routed to a silent system. Rendering a frame without presenting it still sends its texture changes to the renderer. A later partial update can then use textures allocated while hidden. The paced clock uses a Windows high-resolution timer then a short spin, since ordinary sleep granularity would skew the measured frame interval. The timer takes relative waits in negative hundred-nanosecond units and needs no system-wide change. Lean runs use the product's frame-limit grid and skip per-frame logging and drain. The summary counts intervals after settling, assigning each to the flight leg in which the interval began.

Capture of a paced presented frame copies its output on the device. The run reads the copies and writes PNGs after presentation ends, since synchronous GPU readback would stall a frame and let a moving clock run far ahead. Stepped pictures can settle at a specific hour instead. Picture counting uses bounded windows, compares only consecutive pictures inside a window, and reports frames skipped when the buffer is exhausted.

Detailed records hand each finished frame to a writer thread. They separate product time, swap-chain wait, harness work and instrumentation. Layer records distinguish apply, settle and upload, world-thread build time, retained memory, upload bytes and their queue and resource-creation costs. Wall time and thread CPU time use distinct units. Sampling other readers or the map's working side skips a busy reader rather than holding it. The overlay hour is absent until its first layout. The presented stamp uses the drawn picture and a process-local monotonic time shared by maps. It measures CPU submission only. The profile sweep clock has its own origin and samples only while active.

Additional map readers join in a worker and close off the frame thread. A hidden window lets go of its reader while other maps can continue on the same playhead. Maps of another recording have their own clock. The harness reports reader arrival, first picture and lag after a reopen. Visual-mod and viewpoint tests run the normal settings and frame paths. The former records layer-only readiness separately from full overlay and counter readiness. The latter checks the new country across vision, layer and overlay products, and runs paused and playing criteria separately.

`precise_wait` creates an unnamed, uninherited waitable timer without security attributes. The creating thread keeps the live handle for its lifetime and owns setting and waiting on it. The due-time value lives through the Windows call that consumes it.
