# 0303. Match character effect readers to the role they describe

Character effect selectors use the effect class's own operand rules. A unit-leader scope carries the character reference, and a named lookup follows the active roster before retired entries. Some effects deliberately fall back to the current character, while legacy country-leader creation accepts only its active-roster match. The first equal roster entry wins. Direct and registry-only roles are distinguished by full recorded identity. A registry-only role should retain its own name and codename when the recording format carries them. A proven older field absence may use that class's exact fallback, while a failed named read stays missing. A null army gate does not itself need the naming tables, and an unavailable census cannot prove a null army. A raid falls back from a confirmed absent army to its recorded wing, with the older projection accepted only when it proves that exact selection.

Execution-only inputs such as the assigned traits, gender and portrait do not feed an effect description. Each role wrapper uses its own expected localisation arguments and order. Promotion and demotion require the matching military categories. Nationality and operative actions require their particular character category and positive country inputs. An authored peace tooltip skips its target reader. Free-operative descriptions use the captured-reference roster to establish captured membership. Hiding and harm reach codename lookup only after their positive-duration gates. Unit-leader event titles use a fresh scope with `FROM` from the caller's `ROOT`. Unit-leader and operative event wrappers use different title arguments, and installing a caster character clears the prior carried country. The native root-selection keyword takes its operand from the `set_from` field even when the reader stores a separate root field.

A promoted country leader uses recorded role and trait order before template fallback. The empty ideology selector is unambiguous only for a sole recorded role. A template fallthrough cannot prove presence merely because multiple conditionally registered variants agree. Advisor activation chooses a primary exact name ahead of a retired folded match in roster and map order. Its raw numeric cache and separate string table belong to the chosen role. A character-only lookup cannot establish another role's cache. A historical numeric cache with no separate string witness can derive zero or one tooltip when the own block could not change membership. Multiple tooltip keys need the recorded slot order. Own-block keys are withheld when a refresh could have discarded them. A recorded empty string cache is an observation. It needs no current trait data.

MIO trait text keeps recorded lexical spelling and the organisation's owner scope. A raw fallback is appropriate if the role or trait is absent. Trait policy text uses its grouped bonuses before the cached modifier list and keeps native order and punctuation even for an empty numeric fragment. Production modifiers go through native fixed-point conversion and decimal formatting. Equipment statistic differences share the same named-magnitude formatter as swapped ideas. Eligibility can keep a hidden or zero entry for block visibility even though its numeric line is omitted. A single missing targeted-country operand cannot be guessed. Targeted country descriptions use a fresh empty event scope and distinct category mask. Random trait selection works on a copied scope, filtering already held definitions without changing the caller's recorded seed.

Scientist descriptions check their own role gate. An unrostered character's missing scientist record cannot prove the role absent. Specialisation names may use the localised country-specific variant. Generation preserves authored trait order without describing starting skills. Injury localises in a fresh scope set to the character. Explicit role creation and removal describe a selected character without a separate scientist-role presence gate.
