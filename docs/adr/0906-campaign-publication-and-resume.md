# 0906. Publish only saved campaign history by default

A campaign's recording carries its world log, provenance records and game facts. Columnar runs hold the table hours. The records describe sessions, branch starts, gaps, controls, interrupted captures and recovery. The ordinary reader opens the newest saved revision and reads pages as needed. The recorder explicitly opens the newest revision to resume an interruption or to save or discard pending hours. Opening an older layout reports its format and refusal, and a recording without a saved revision cannot open through the ordinary reader. Summary reads can identify a recording from root and records without walking any pages. Campaign identity and capture mode can be read from an unsaved revision.

Every session in a recording shares one capture mode and compatible content identity. The session facts file carries the identity followed by its pack. A publisher checks the identity against the capture and locates the pack from only its header. The writer and both readers admit the same header: a 32-bit identity length followed by a non-empty pack, bounded only by the bytes the file holds. A recording may carry ordered facts packs, each checked by digest before a caller relies on chunked reads. Resuming an existing recording with facts retains its own pack. Advertised frame read damage is distinct from a capture that intentionally recorded only part of the table or acknowledged spool recovery.

Each block indexes consecutive hours of one branch and its stable key combines the run and page. A segment restart can cover multiple blocks. Carry only actual recorded hours when rebuilding history for a resumed collector. Build that history before the capture queue begins. A resumed process must match saved session metadata. A branch tail can be a witnessed command phase without an hour. Use a matching clock witness only when the last recorded hour lacks its Clock row. Gaps and control records get their own validation. Inconsistent core identities and timelines refuse the recording, while a damaged gap or control list is withheld with a warning.

Replay publication checks new records against the existing campaign and incoming segment context. A retried save deduplicates already committed controls, and a loss retried within a save is kept once. A witnessed command phase also declares the branch when no branch-start record did. Keep recovery notes for damaged segments. Preservation of the revised prefix and retryable provenance avoids turning an interrupted save into extra history.

Fixtures encode through the frame writer and world log or through the collector's journal. They can retain an independent expected derived frame and can deliberately damage page bytes without removing the page from the index. Some fixtures label the same layout with a newer row format to exercise harmless version changes. Others generate the actual historical row schema. Journal fixtures match frame witnesses to their hours in order even when the corresponding control record appears after the frame.
