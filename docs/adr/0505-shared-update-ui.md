# 0505. Keep update offers shared and restart requests scoped to a download

The recorder and desktop app share a build, installer, channel and release version. An installer launch closes both apps, so a reply to the launch request means it did not start. The UI checks whether the recorder can be replaced, and it asks for confirmation after the download. A notice or restart question belongs to the downloaded version and goes away if the offer changes. The current offer chooses the button action even when an earlier action failed. The update listener starts before the first snapshot request so a publish during that request is not lost. While an update is offered, pointing at the update button opens the notes of each release it brings, newest first, and says when older ones are not listed; the notes close when the pointer leaves, never take focus, and give way to a failure or restart question. Settings and the recorder's update section show the same notes.
