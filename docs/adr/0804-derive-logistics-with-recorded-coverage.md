# Derive logistics with recorded identities, inputs and coverage

`StockByVariant` sums fixed5 stockpiles by canonical slot and design because the source rows are keyed by list position. Changing a position subtracts its previous contribution and credits the new design, and a zero-amount row survives while any position holds it. An incomplete input makes the table unavailable. An unresolved country makes all amounts unknown because any holder may be missing a contribution. Wide sums stay exact in memory while their cells are unrecorded, so they can become recorded again if a later change brings them into range. Settlement resolves all the touched sums before publishing them. If the previous output cannot be read, the recorder can rebuild the hour without publishing partial deltas. [Stock writer](../../crates/recorder-derive-equipment/src/stock.rs)

`SupplyHealth` assigns each division to its positive expeditionary owner or, where that does not apply, its roster owner. Classification uses the recorded content's thresholds and supply-grace definition with exact recorded supply and grace operands when present. A naval transfer does not go low on supply. Grace can raise the effective supply above the received ratio. The grace sentinels represent unbounded grace. If supply is low, the icon thresholds compare the received ratio. When a historical row stores only display-stepped supply or grace whose preimage straddles a threshold, the division's state is unknown and withholds all three counts for the affected country. A missing define withholds the table with that define's name. Missing supply data withholds all three counts for the affected country, while an unresolved owner withholds the counts for every country. Complete inputs give an explicit zero to a live country with no divisions. A division whose owner did not change keeps its previously resolved slot. Reclassification writes only affected country rows and avoids writing changes between operands that leave the same icon. [Supply writer](../../crates/recorder-derive-economy/src/supply_health.rs)

`TradeFlows` keys each seller-to-buyer resource flow by both holder identities. Where several tag holders share a slot, the lowest raw ID wins. A missing or unresolved side uses the explicit no-holder identity. An identity beyond the key's 24-bit fields withholds the table by name. The writer can re-key flows upon changed links or holders by rebuilding them from the recorded deals. Each measure is summed independently, so an out-of-range sum withholds that cell while others stay recorded. A flow goes away only once its last deal goes away. [Trade flow writer](../../crates/recorder-derive-economy/src/trade_flows.rs)
