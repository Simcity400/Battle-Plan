# 1110. Retain native widget construction state for later layout

Window controls keep the viewport-relative positions and state assigned at construction. Later parenting preserves that position object. The parent supplies orientation, the child's extent supplies its origin offset, and integer centering truncates the halves independently. Child windows place descendants in content inset by their margins. A root with a size based on its parent needs the parent's dimensions, even when its position is supplied directly. Construction-time overflow checks use the requested type's measured geometry, which can differ from its eventual drawn bounds. Check boxes and position types bypass that check. List rows have no extent before construction, and a smooth list applies its retained anchor twice during placement.

Plain scrollbars use the last own child with a requested name and then search one level of their parent template. Asset collection and construction use the same lookup. The right and left buttons, the track, the slider, and any named range icons are built in that order. Buttons and range icons require button or icon factories. Tracks and sliders require button field layouts. A requested part with no compatible factory is named and refused. A cornered track takes its assigned size and a plain sprite retains its own. Plain scrollbar parts preserve their own visibility and extents, and they do not inherit window opacity.

Scrollbar state uses signed fixed point with a scale of 100000 and a half-away-from-zero conversion. An unusable signed span or zero step keeps the range's sentinel count. Snapping preserves endpoints and chooses the lower point on a tie. The 0.001 step keeps a raw position when snapping, and button input advances it by 0.01. Wheel input uses the step, authored speed and signed delta. Construction retains the raw start value. Bounds updates clamp before placing the slider without snapping. A thumb position converts the range terms to floats before computing the share of travel. Range icons draw only for active limits differing from their corresponding range endpoints. Their placement preserves the track, inset, conversion and wrapping arithmetic. A division overflow is refused.

Standard lists scroll in whole rows and smooth lists in pixels. Row windows retain their own sizes and opacity. The list draws its background first, then rows, then scrollbar parts. It uses the appropriate native factory, including a smooth factory that can interpret a standard list template. The smooth scroll offset starts at the authored start position and approaches the target by 0.2 of the remaining distance. A horizontal smooth list resizes the bar to its width and places it below the content. A vertical smooth list places the bar at the right. Standard lists use the authored side. Smooth clipping and window visibility follow the constructed controls.

Container scrollbars load globally named extended controls, vertical before horizontal, and draw on the outer object after the content and children. Their range follows child overflow, including hidden children where the body requests them. A bar appears only when display is enabled and that axis strictly overflows. Construction clamps the range and snaps zero for the initial content target. Whole-pixel offsets reach observers even for hidden content. The track frame can respond to the target before smooth scrolling reaches it, and the construction and relayout track lengths stay distinct. A runtime smooth bar without its slider leaves a named refusal.

Edit box measurement uses font layout up to the caret. Pointer placement chooses the nearest prefix boundary by the measured width. An inactive box keeps its caret and selection hidden. A drop-down keeps its viewport-relative header, and the expanded window inherits clipping and appears only while open. The header's own hidden state is independent. Browser textures and shown curve graph points need runtime inputs that the recording does not hold. Curves begin hidden and preserve that intent unless the lifecycle specifically shows them.

Text writes refresh the text box's scrollbar in call order. A long value can show the scrollbar even while the box is hidden and a shorter write can hide it within the same frame. Retaining a low-level text write without the ordering would lose that refresh, so the retained control path refuses it. Successive range updates clamp the retained value, and increasing the range after shrinking it keeps the previously clamped value. The text's existing scroll offset is separate from that clamp. Container scroll calls use the smoothed current value for arrow input and the target for a wheel update. A hidden bar can reset the scroll offset without changing the retained content extent.
