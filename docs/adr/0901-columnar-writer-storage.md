# 0901. Hold one live copy of writer state at its working width

The writer stores one typed, slot-indexed copy of each table's live rows. Changes both update the held cell and report the event through the hour's log and attached encoder. Numeric columns hold the narrowest of zero, one, two, four, or eight bytes that fits their values. They widen on demand, cut deltas to the column's schema width with wrapping arithmetic, and can narrow after a whole restore. Presence and recording bits distinguish missing optionals and unrecorded cells from a stored zero. The slot count and string count are 32-bit quantities, so the highest usable slot is one less than the maximum count. A logged row ordinal instead follows the 64-bit append count. The keys split their 128-bit values into two independently narrow columns.

Budget labels separate retained old cells from the hour log's other allocations. Tight growth reserves roughly a sixteenth above demand with a small minimum to bound slack when arrays grow one slot at a time. Shrinking uses enough slack to avoid reallocating on tiny edits. Trim flag arrays through their highest live or set bit. A log's listed bitmap retains only the portion of its ordinal span containing listed rows, with the same canonical representation independent of update history. Log keys seen in a run compress contiguous sequences into inclusive ranges. Reusing an earlier key is a refusal.

Each list page holds slots whose cells point to separate pieces of its item segments. An in-room rewrite preserves the allocation. A longer rewrite appends to the last segment or starts another one near the one MiB target, with a segment of its own when necessary. The reader gives longer cells growing room because it replays updates in place. The writer keeps a tight version of the current world. Compact in place when abandoned bytes pass a quarter of the page. Working segment by segment limits overlapping allocations to one segment. During compaction move held cells down, discard empty segments, keep only the policy's slack, and renumber segments in place. Cells of unwritten pages need no allocation. Trim only dead slots and keep every mask and cell of lower live slots.

Packing moves live rows down in slot order so a moved row cannot overwrite another row awaiting its move. It keeps the values, presence and recorded bits, and provides the old-to-new mapping to producers. Key lookup can use a hint without allocating an index if the hinted live row still owns the key. An index grows below three-quarters occupancy and repairs deletion gaps when a later entry's probe crossed them. Release the index when packing invalidates slots, or after a block with fewer indexed lookups than live rows. The next uncached lookup rebuilds it.

A block can release text that no live cell or refusal names, and a later use of its id reloads it from the run's file. A repeated intern of a released value can instead append the text again under a new id. Pinned writer strings remain for the run. Validate the entire next hour's append count against the recorded string width and the lowest pinned id before changing state. A restore reinstates the run's next id and reloads texts named by live values or refusals. Release the backing string reader's temporary input after the hour finishes.
