# Use the native interface registries

Use the shared GUI template registry for both window-local button artwork and static text. Walk the mod stack in file order, with end-of-file closure and replacement governed by the native readers. A later readable declaration settles an earlier one. An unread suffix after the kept declaration can still replace it, so lookup returns the relevant refusal. Ignore an unrelated refusal. Text lookup uses the first direct child of the requested name as an instant text box and reports missing, empty and refused fields separately.

A graphics file uses the same lexer, scalar scans and variable lifetime as the GUI reader. Sprite declarations and other object declarations enter separate registries. Sprites are matched by exact name, with the latest declaration first. Other object kinds share one registry, so a later differently typed object can replace the registered name. Each object walks its own fields and forwards unmatched fields to common handling. The test fixtures use synthetic definitions and cover the effect of short or malformed fields on subsequent declarations.

Component readers advance for every component, including a component whose scan writes nothing. Model each write only within the known object or live frame and stop with a named failure at the first access that would leave it or use invalid state. A write that native code replaces before any read supplies no data. Absent initialization remains unknown. The string's stored capacity controls whether its buffer is inline or a pointer. An inline read can reach its following metadata when its declared length crosses the inline buffer. Check the enclosing allocation before a C-string reader truncates at the first NUL. Heap-backed text uses only known allocated bytes. Vectors expose the counted prefix, distinguish clear from deallocation and report writes through an invalid or unknown pointer. Never execute the implicated native memory access in the reader.
