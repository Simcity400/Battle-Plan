# 1110. Prepare window resources from the authored GUI registry

The GUI reads one registry in content-stack load order. The latest registration of the same byte name wins. The viewport determines the extent assigned to `max_resolution`. Viewports share a layout when every size comparison evaluated during window inheritance gives the same result. The cache releases each layout with its last consumer. Resource demand follows the same construction paths as layout, including named children, scrollbar parents, edit-box files, localized text and inline icons. A change in viewport can affect layout while leaving asset demand identical. Required naval counter and combat templates have explicit errors. Optional naval base, convoy and result templates can be absent, in which case the corresponding item is omitted.

Resource identity preserves file and sprite name bytes. Lossy names are labels only. The texture resolver tries the DDS and TGA variants before the supplied path and applies its load limit. The loader caches by stack and path so recording and presentation attempts can hold the same name independently. A failed native load yields the null texture and a named outcome. Files whose contents do not establish a deterministic native draw withhold an affected draw, including whichever sprite, font page or edit box first requested them. The CPU alpha mask is shared for transparency-checked sprites and comes from decoded BGRA8 mip 0. Other native formats keep rectangular hit testing. Texture decoding and shader globals use the same power-of-two setting.

Map art retries an unread or hidden visual-mod file from the recording by path. Game windows also know the recording's registry. If a visual-mod texture, effect or font prevents a declaration from drawing, they try the recording's entire declaration for the requested name and its own assets. Path-only texture demand still retries by path. A missing or undrawable recorded declaration leaves the visual-mod result in place. Read failure belongs to the attempt just as absence does. The loader publishes each kept attempt's diagnostics and replays cached dependency diagnostics when another kept draw uses that dependency. A recorded font fallback follows the requested name, even when two requests resolve to the same broken visual-mod font.

An absent declaration can resolve to the registry's fallback sprite. A missing loaded texture keeps a null binding. A font page that neither stack supplies retains its glyphs and a named blank draw. Actual read failure can additionally withhold the affected font's text. The language chooses the font family, `path` appends files and `fontfiles` replaces the list. The first file supplies line height and the first file containing a glyph provides it. Texture pages retain their own dimensions and failure state. Uncovered assets provide diagnostics when their bytes were read outside content hash coverage.

The renderer loads the standard text, linked shield and default sprite effects alongside what templates request. A plain sprite with an empty effect uses the default effect, and a loaded mask selects the masking variant. Deferred plain textures retain eager declaration metadata. The eager animation path uses plain and tile variants only when the selected program declares the needed technique and slots. Frame-animated sprites and masked shields retain their separate paths. Resource metadata preserves the main and secondary textures, mask and animation records each native draw expects.
