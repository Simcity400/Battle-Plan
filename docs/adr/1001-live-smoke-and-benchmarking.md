# 1001. Separate live smoke evidence from matched throughput screens

The smoke verifies binaries against a receipt before driving the game. It takes an owned game lock and restores the input selection on exit. Read the installed game clock through the recorder's read-only command. It locates and verifies the executable once, reports withheld fields by name, and leaves missing fields absent. The driver rejects a path the game's command-line parser would split and derives the reference build from the same source as the binaries. A background launch keeps other windows usable and waits for visible evidence that the map is ready. A clock build without camera evidence can certify only the background window settling. Give the interactive game normal priority when launched from a lower-priority scheduled task.

Coordinates are calibrated against the outer window and mapped to DPI-virtualized client coordinates for posted input. Background screenshots use the composed window and are rescaled to physical coordinates. Posted mouse messages can reach the game without changing the state polled by its menus. The optional input shim supplies that state and the driver always clears its overrides. The fallback borrows focus for the individual input. Some menu sequences require retaining focus across steps. Check ownership before each input and retry focus borrows boundedly before input is sent; multi-step wheel and text sequences re-acquire focus per unsent event and never replay already-delivered events. Wait for a pause or speed change to land before sending another. The save and exit UI sequences verify each menu or dialog transition against calibrated reference patches (validated before acquiring the shared game lock, refusing uncalibrated configs by name), verify starting state before retrying rather than sending blind Escape counts, and require explicit exit confirmation plus a zero exit code before marking normal exit. The menu can close on saving, so a second click at that location would act on the map underneath. Park the cursor on verified inert chrome before comparing visual evidence.

The native background helpers place the game behind the prior application without activation, and capture its composed content with `PW_RENDERFULLCONTENT`. Each posted button event is separate so its shim state can remain held across dispatch. Focus restoration is best effort because the prior window can close or take focus while the action runs. Always release a pressed key even when the target loses focus during the hold.

A refresh defers the next sample until the following update. Wait for the paused hour's existing sample before asking for the refresh, save that next hour, and advance once to capture it. A stale status read cannot certify the requested transition. Open status with delete sharing because the collector replaces it atomically. Check the pinned compiler before capturing the recording so a viewer cache miss can still draw it. Smoke tools redirect stdout and stderr directly to files in the output folder as output arrives and stay tracked until exit so a hang, timeout or lost smoke process leaves the tool's own logs on disk, never launches a second detach while an earlier detach is still alive, and retains the game lock while any smoke-owned tool remains running. Shut acquisition down before other cleanup and leave a failed game paused for diagnosis while a collector may still be attached. Fresh-save oracle and render verification still run even when normal game exit fails so a UI-exit flake does not hide recorder verdicts, while the smoke still fails honestly and retains the game lock when the game remains running.

The benchmark reloads the same save and alternates matched recorder and no-recorder runs. A new candidate begins without warmup. The screen logs its start for external profilers and records the game process's ticks, faults and memory alongside the game hour. Time and process changes during an explicit plan save are excluded only for its confirmed paused span. CPU snapshots identify each process by PID and start time, retain the last sample of exited processes, and count new processes from zero. Background CPU is telemetry. Its thresholds alone cannot refute an otherwise comparable screen. The recorder's exact metrics run after live game work finishes and require a complete replay. Preserve unavailable ratios as absent and drop the raw spool unless explicitly retained.

Express the direct cost from the hourly pause, detours and capture gate waits against native update time measured in the same run. A held capture belongs to the hourly call and a beside-game wait lies outside the detour. The optional net timer estimate is diagnostic, while the raw value is conservative. Indirect contention appears only in matched no-recorder screens. Label an otherwise valid throughput measurement when a collector's CPU counters omit a capture thread. Recompute derived timings from saved snapshots when summarizing old runs.

An attach failure still requires detach. Wait for collector unload and then for recorder finalization, even if the recorder process exited while detach continued. Bound waits by total time and progress stalling. Windows PowerShell requires acquiring a process handle before exit to read its status. Read the newest session progress when a failed attach never published its active session. Keep diagnostic candidates visibly invalid even when their timing is useful. The synthetic tests exercise launch and snapshot, write and cleanup behavior without opening the game or injecting a recorder.
