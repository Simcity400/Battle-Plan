# Compare characters using the saved roster and serializer rules

The oracle fits the saved roster to the memory that produced the sampled frame. Loading can destroy some saved characters and shift later positions, as a Millennium Dawn recording demonstrated. At a load hour it expects the loaded roster. Otherwise, a frame that contains any unloadable character is compared as written and a frame missing all of them is fitted as loaded. A partially missing written roster must remain a difference. The character family is hourly, so no scheduled-slice gate is needed. A textual save hour is one-based. Frozen rows use their recorded fields. The serializer writes the row's token as a name and resolves the name token ID separately for the saved token. Concrete token text with an unproven interior NUL is a named limitation. A C string ends at its first NUL. Quoted name tokens still denote their ordinary dictionary spelling, whereas generic tokens in a trait position may use the serializer's reserved numeric projection. Compare the original bytes before formatting a report. Gender is projected to male, female or undefined, and the serializer emits a template only for a set template pointer. No name text or saved enum is used as a substitute for the stored operands.

Join saved country-leader role arrays by signed map order and advisor arrays by their ordinal. The saved ideology can be changed in place, so it does not identify the country-leader map entry. Scientist arrays join directly. Empty arrays omit their trait key. Advisor traits use the content definition name at the recorded ordinal, with its relationship to the recorded token checked under the lexer's case-insensitive rule. Reusing an earlier case variant does not change which definition name the serializer writes. A lexer refusal, such as an empty key or a key beginning with a digit or minus, requires token zero. A missing key and a mismatched recorded token remain distinct cases.

Compare a character's own operative reference from either nonzero handle word. The referenced leader's naming operands come from the intelligence agency's roster, and the codename follows the division-name projection. For loaded leaders, ownership is assigned through a unique country's active roster. The character's own saved country value does not prove it and ambiguous membership cannot witness load order. The army leader serializer writes a captured flag only for a set byte, and an exile reference only for a positive value.
