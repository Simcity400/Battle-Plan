# Paint live values independently from React chart structure

Use React props for row identity and structure, labels and art. Values come from a `Live` source read at paint, with stable snapshots until their inputs change. Retain the identity of equal values and notify from playback frames, seeks, pauses and landed answers. Absent keyed values report their own missing reason. A table combines values by column and row, preserving missing fields for columns without a source. Live text can depend on both an hour and the versions of followed answers, including while paused. Compute the easing rate from the actual playback clock in each frame. [Live values](../../ui/src/charts/live.ts) · [Live motion](../../ui/src/charts/liveMotion.ts)

Use offscreen canvases for chart drawing so font updates do not make the browser recalculate page style. Dashboards glide bars through scale changes in the frame engine rather than modifying width each frame. A paint-cost fixture measures both canvas kinds, actual frame paints, and layout, text and style requests; it starts counting after the first observer-delivered size. Geometry reads occur on resize reports and actual scrolling instead of forcing layout after each commit. The frame engine owns glide timing, so the browser test checks presentation and compares commit counts across structural changes and pure value movement. Inactive widgets stay out of the paint loop. Nested controls can take focus before parent layout effects, so focus handling must recognise them during commit. Progress geometry and accessible value use the same clamp. A negative native ratio fills no pixels, while a null remains unknown. Reuse shared locale formatters to avoid repeated setup in paint.
