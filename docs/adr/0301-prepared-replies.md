# 0301. Share historical and following product replies

A product’s typed reply function serves both an explicit hour and a panel following the head. The adapter resolves the accepted run and country holder at the requested hour, including slot changes. One reply can request further dated frames through one seeker, restoring each table once and then reading forward. Reads stage sorted unique keys or disjoint owner ranges. A table read again replaces its rows, so the last read must include every requested row. A product can project columns only when its typed reply never inspects the omitted fields. Otherwise defaults could incorrectly surface as recorded zeroes. Retained views use row identity even when storage packs and reassigns slots. Exact and incremental reads report the same first refusal.

The reply contains structural data and keys for changing values. Historical requests include values for the named live cells. Following panels publish structural updates only when their reply differs, and the follow layer carries the changing values by group. If a product did not read every row needed by one of its live groups, the adapter reads all rows needed by every group in that table on replacement. A missing value stays missing by name. Panel work carries executable tables from the recording, since the panel thread has no independently selected executable. Request and panel paths order warnings consistently, with local refusals before content warnings and recorded-style fallback notices.

Serialize a typed reply once with cancellation and a byte limit. Permit the server to set fields only on an object root, reusing the serialized text. For scalar updates, an encoded MessagePack record also keeps the ranges it can patch. The response budget applies to the complete request, so the caller receives a named refusal when its result would exceed it.

Leave space in the transport limit for the lease envelope and the encoded reply. The lease ties a result to the source selected by the frontend. A size-only refusal is distinct so a paged reply can try a shorter page. Interactive one-hour reads and dated log replays have their own workers, so a whole-recording scan cannot delay them. Log paging counts ordinals from the timeline’s first hour and distinguishes a missing optional value, a withheld table and a recorded table without matching rows. Missing spans combine gaps between accepted runs with hours in runs whose table is incomplete. Sparse fixed5 histories store only nonzero changes and preserve the shared missing-reason index. Fixed-width values distinguish native finite values, sentinels and unevaluated caches.

Read country identity through the shared holder rules. For a raw ID, read canonical-slot links once per run and use recorded tag spans to name the slot at the requested hour. A gap keeps the name unknown. A wire endpoint without a warnings field refuses unrepresentable tags instead of silently omitting them. Share reasons across dated runs by separating changing read dates or truncation counts from the stable coverage reason.
