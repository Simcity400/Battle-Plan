# Use the shared trigger evidence rules for raid conditions

Raid scripts use the dashboard evaluator through the viewer's map-facing module. This gives raid, combat and dashboard consumers one implementation of recorded scope, operand and refusal handling. A trigger with a missing input stays undecided where that input could change the answer. A completed but unnamed technology could match a queried technology. A nonempty raw country with no link could own the matching row. Daily rows are read from the current playback state independently of when their owner was last sampled. A trigger with enough evidence to decide may still do so if the missing row cannot change the result.

The evaluator reads scripted boolean templates as yes or no and treats an unexpanded parameter operand as an ordinary operand. A registered trigger or a content building count takes precedence over a scripted trigger of that name. A country exists for these conditions when it owns a state. Building counts include damaged levels and follow the scope's recorded members. Resource modifier and building override joins retain first-entry and scope restrictions. Sibling conditional blocks form one chain. The first passing branch decides, and an undecided branch selection only resolves when all possible branches agree. `ROOT`, `FROM` and `PREV` preserve the scope chain. Authored custom tooltip labels do not alter the conjunction's truth.

Scope-sensitive joins follow recorded identity. Subject predicates read the recorded overlord. Country friendship requires land ownership and checks war before faction and direct subject relations. The evaluator cannot establish that no owning replacement exists for a tag when its original-tag bucket was not recorded. Original-tag enumerations preserve the bucket's native order and duplicates, then append the selected raw reference while keeping the outer root. Their count decrements per passing entry. State arrays honor their global count and element encodings. Null state and unrecorded state are distinct. Neighbor-state conditions need the content order and recorded scopes they visit. Empty complete neighbors satisfy universal conditions and fail existential ones.

Leader conditions need a resolved owner, unique recorded character role and visibility template evidence where the character has a conditional choice. Role `visible` is evaluated in the owner's scope. A complete row absence can establish that no leader exists, while missing character template evidence leaves a conditioned leader undecided. Character flags require the corresponding recorded character scope. Party leadership uses the first leader's identity and recorded character or trait, including the ruling-party restriction. Civil war reads the relevant recorded owner relations. A recorded advisor token uses the country and faction advisor rows, even if an active idea shares its name. A party's orphan leader row is refused by name.

Naval invasion conditions walk regular-group order successors and examine the path provinces of invasion orders. A scalar condition can pass on a touching order without preparation inputs. A bounded query needs the row and content operands for that order. Required days multiply the recorded time and speed factors, truncate to whole days and convert to hours. The leader term participates only where the row says it applies. A withheld table or an absent order operand keeps the bound undecided.
