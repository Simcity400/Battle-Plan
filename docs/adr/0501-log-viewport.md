# Hold enough log rows to reveal a playback block without rendering each arrival

Display rows newest first with stable ties. A row's date can be an upper bound on when the action occurred; its separately recorded supplying hour governs when playback can reveal it. Use a stable logical ID for keyboard focus and tooltips across states, and a state key for entry and reconciliation. In a block of changing rows, reopen or replace a state only at an observed boundary. Keep equivalent states keyed across blocks. Separate date order from reveal order in the loaded-page index, and retain the selected slice until playback crosses an indexed boundary. Use a whole-row first read and direct changed-row reads where the model can identify them. [Log data](../../ui/src/charts/log/logData.ts) · [Log playback](../../ui/src/charts/log/logPlayback.ts) · [Log states](../../ui/src/charts/log/logStates.ts)

Use sorted reveal and departure hours as a cheap key for a visible cut. Rows held ahead, or already gone, add no logical height. Build the held viewport from rows that remain visible through the block, including hidden neighbours that may enter. Keep all future top arrivals while at the top, even if they exceed static overscan. Old overscan alone repeatedly ran out during dense naval battle reveals and caused a render on successive frames. Month dividers follow the rows they head, section headings remain, and a section note gives way to its first shown row or window. An unloaded window cannot be assigned a month before its dates arrive. Month keys stay stable through additions. [Log lookahead](../../ui/src/charts/log/logAhead.ts) · [Log sections](../../ui/src/charts/log/logData.ts)

For a plain following row log, bind visible states into existing DOM boxes. Retain each box while its row is in reach, rebind on a state or binding change, and request more boxes when the pool runs short. A leaving row can fade only if it already has a box; no new box is mounted just to fade. On a reveal, place a stale or newly mounted transform without a transition and restore transitions after that frame. Use one shared glide for the majority offset and write individual transforms only for exceptions. The shared transform stays inside the list's scroll extent. Reveal states, moves and fading are painted directly. Commit only when the existing window cannot serve the viewport. [Log list](../../ui/src/charts/log/LogList.tsx)

Window by outer box height so an overscan row that creates a scrollbar cannot remove its own row and oscillate. Bounds and key movement still use usable client height. Obtain viewport measurements when the observer reports them, keep logical scroll precision even when physical scrolling rounds, and distinguish browser echoes of programmatic scroll writes from recent user input. Use cached viewport geometry for anchor and paint. Measure only mounted cards in layout pixels, retaining estimates for offscreen cards. Invalidate measurements by width and density, or when a retained page releases its keys, and preserve the first shown row across releases and measured heights. A card taller than the viewport keeps its heading in view on repeated keys. [Log list](../../ui/src/charts/log/LogList.tsx) · [Anchoring](../../ui/src/charts/log/logData.ts)

Only a reached row demands exact tooltip and dated label facts. The last pointer or keyboard action owns the log tooltip. Follow the active state by logical ID and hide on removal; a fading row can no longer answer. A nested chip can take hover from its row. A key starts at the newest shown row or advances from the retained ID, even if its prior state became hidden. Cancel a pending keyboard destination on a later reached pointer row, and fit the selected row or card before showing and announcing its tooltip. Publish visible readers with the next frame, deduplicate repeated demand, and retain the current page-demand callback through renders until unmount. Initial rows are already present. New entries require a first reveal during forward playback. Cards leave immediately so a backward seek cannot retain a future card, and remember entry identities so scrolling does not repeat their animation. A continuously mounted animation survives a staying phase. Clock history is committed separately from reveal eligibility, preserving result identity between changes.
