# Widgets

Each folder is one widget: everything it owns lives there, and nothing elsewhere switches on its kind.

```
widgets/<name>/
  definition.ts   pure metadata: kind, version, title, description, icon, time modes, history, sizes
  index.ts        the React renderer (and header controls if any)
  <Name>Widget.tsx
  <name>Data.ts   payload validation and local playback lookups, with tests
  <name>.css
  README.md       what it shows, which product it reads, what remains
```

`definitions.ts` (this folder) lists every widget's metadata and registers it, for node tests and the layout model. `index.ts` pairs each kind with its renderer and registers the full widgets; TypeScript rejects a kind missing from either list.

## Contract

- The dashboard gives a widget `WidgetProps`: its spec, the shared runtime (tracks, clock, client, maps), whether it is on screen, the map options, a header slot and a diagnostics callback. See `dashboard/definitions.ts`.
- Data comes from one product per request through `useProduct` in `dashboard/products.ts`. A product reply covers the whole branch, so following playback is a local lookup with no further requests.
- Playback: subscribe with `usePlaybackHour` only when the widget follows the clock, and resolve the hour with `resolveWindow`. Every widget has its settings behind the gear in its header's top-right corner. A widget with `history: true` also gets a Live switch beside it: off shows the whole campaign as it stood at the end, on follows the timeline. Default to `campaign`. A line chart with whole-campaign playback offers `AFTER_PLAYHEAD_OPTION` (`dashboard/options.ts`): off by default, so nothing after the playhead shows; on, pass `afterPlayhead` to `TimeChart` and draw to `shownUntil(...)`. A widget that only makes sense at the playback moment, such as the map, sets `history: false` and always follows playback.
- **Settings.** The gear opens the same panel for every widget, with sections in a fixed order: Campaign, Countries, Time, Size, Options, Axes, Interaction, Reset (`dashboard/settingsSections.ts`). A section appears only when it has something to set. A widget adds its own choices by declaring `options` in its definition: toggles, choices, numbers, content choices and content sets (`dashboard/options.ts`; a content choice lists things only the recording's content knows, such as its idea categories, through the renderer's `useOptionChoices` hook; a content set picks several of them as chips, up to its `max` and never more than 16, each token at most 160 characters; a chip that cannot be chosen says why), each placed in the countries, time, options, axes or interaction section. A control inside the widget, such as chips above a chart, saves an option through the optional `setOption` prop exactly as the panel does. Read them with `resolveOptions(definition.options, widget.options)`; a missing or illegal stored value falls back to the field's default, so the widget never sees a bad value. `countries: { max, ranked?, aggregate?, all? }` lets the widget show several countries (one by default; `defaultCountries` sets what a new or reset widget shows, such as a race's top 10); with `all`, the widget is about the whole world (every faction, every overlord, every country's construction) and starts on All countries, and chosen countries or a group narrow it (`worldFilter` in `dashboard/groups.ts`, which counts a group's members under its membership setting: at the moment shown, at the branch's end, or anyone ever; a log's `countryMatch` counts them at each row's own hour instead). Such widgets also offer smart groups (`dashboard/groups.ts`, from the `country-groups` product): human players, any recorded faction and everyone at war with a country, with top N when the widget ranks countries. A top-N group resolves to its N (`resolveCountries(...).top`) and the widget ranks every country by its own value at each hour (`rankedCandidates`), breaking ties by tag exactly as the data service does (`compareTags`: UTF-8 byte order, as Rust sorts), so a product's ranking and the widget's never disagree. A time test that a cost grows linearly uses `charts/assertLinear.ts`. Each group counts members at each hour (marking joins and leaves), at the end, or anyone ever, and can be summed into one series when the widget allows it. Resolve a group with `groupRuns` and `groupMembers`; never assume which factions or sides exist. Never store a date: store an offset from the branch start.
- **Saving.** Every settings-panel change saves to the active layout at once. Adding, moving, resizing and removing widgets are edit-mode actions and wait for Save. Stored options stay with the layout even when the widget type is not installed. When a definition's `version` rises, give it a `migrate(from, widget)`; without one, older settings are kept and the widget reports them as unsupported.
- **Header.** The frame draws the icon, title, the campaign name when several are open, the country chip (flag and name, "+N" for more) for data widgets, the Live switch and the gear. A widget never draws its own header or panel.
- **Faction colours.** Colour factions with `useFactionColours`: the user's choice, else a default. A colour the user sets applies in every campaign (stored with the app by the faction's identity, `factionIdentity` in [dashboard/campaignSettings.ts](../dashboard/campaignSettings.ts): its name as recorded, a localisation key or literal and never its translation, else its first recorded leader's tag; until templates are recorded, two factions recorded under one name share a colour and a leader tag is not stable across campaigns) until changed again, unless a campaign overrides it for itself; the Faction colours editor offers All campaigns (the default) or This campaign only. Give faction legend items `onColor` and save with `setColour(id, hex, scope)`. The default is the recorded map colour of the leader the faction had when first recorded (`factionFounders` in [dashboard/factionLeaders.ts](../dashboard/factionLeaders.ts); leaders come from `country-groups`, see [Factions](factions/README.md)), exactly, grey included (the user's decision); only a default that clashes with another faction's colour is nudged, by the smallest change of lightness that tells them apart, never to another hue (`factionColours` in [charts/factionColours.ts](../charts/factionColours.ts)). A faction whose leader or its colour was not recorded (or not read within ten seconds: the founders' colours are read through the shared bounded `FactRequests` store, retried with backoff) takes the first palette colour that clashes with none.
- **Jump to.** Any dated row or chart point offers a right-click menu (`useContextMenu`) with `jumpItem(runtime, trackId, hour)`. It calls `runtime.requestSeek`, which moves the shared clock only when the hour is inside that track's branch; the clock still owns time.
- **Drill-down.** A widget whose value has parts wraps its view in `DrillHost` and lists the parts with `DrillParts` (`charts/drill`). It declares `DRILL_OPTION` (in the widget or beside it) and `breakdownOption(...)` among its options. The breakdown follows playback until a day is picked (`reduceDrill`), and **Pin as widget** adds `pinnedBreakdown(...)` below the widget with `runtime.addWidgetBelow`, as a layout change. Part labels come only from the game or the recording; whatever the recording cannot attribute is its own row.
- A widget never opens files, starts a clock or reads another widget's state. Header controls, icon and country choice come from its definition.
- Validate the product payload shape in `<name>Data.ts`; the transport already checks source identity.
- Register the Rust product in `crates/dashboard/src/products/`; regenerate `generated/dashboard.ts` when its types change.

## Reuse first

Anything a second widget would need belongs in the shared kit, not in a widget folder: fix it once there and every widget, present and future, has the fix. A widget folder keeps only what is about its own content (what its values mean, its rows and wording). Before writing a helper, look in the kit; when a widget grows one that another could use, move it to the kit with its tests. The kit so far:

- **Product batches** ([dashboard/products.ts](../dashboard/products.ts)): `useProducts` shares, validates and caches several independent product requests without a request on each playback tick.
- **Feature availability** ([dashboard/definitions.ts](../dashboard/definitions.ts)): `WidgetMeta.availability` names a lightweight product request. The picker enables a feature only when it reports `available: true`; widgets use `WidgetState` for loading, empty, error and **Not in this recording**.
- **Settings fields** ([dashboard/options.ts](../dashboard/options.ts)): `sectionFields` places declared options in `countries`, `time`, `options`, `axes` or `interaction`; `visibleWhen(options, countries)` shows endpoint or other country choices only when the current selection needs them.
- **Progress meters** ([charts/meter/ProgressMeter.tsx](../charts/meter/ProgressMeter.tsx)): a recorded ratio or null, with live/done/idle state and an optional label.
- **Time charts** ([charts/TimeChart.tsx](../charts/TimeChart.tsx)): layers, zoom, hover and right-click, a value axis sized to its widest label, and keyboard hover (the arrow keys step through `keyHours`, the tooltip is read out, and a key takes the hover from the pointer). Give a chart a `tooltip` and keyboard users get it too; pass every hour a value changes as `keyHours`, and a range starting between two still reaches the value going on into it.
- **Value labels and amounts** ([charts/valueAxis.ts](../charts/valueAxis.ts)): `formatAxisValue` (exact, with the precision its ticks need), `formatAxisPercent` (the same with a percent sign), `formatFixed`, `formatNativeFixed5` (native fixed-digit truncation), `formatAmount`, `formatSigned`, `fixedNumber`, and `rescale` for amounts in a binary denominator (the engine's 32768ths).
- **Tooltips** ([charts/tooltip.ts](../charts/tooltip.ts)): `fitTooltip` (the fullest form that fits the window, else a compact one with its totals kept and the rest counted; the full content stays readable by screen readers through `spoken`), `tooltipText`, `showTooltip`/`hideTooltip`, `refreshTooltip` (lazily refreshes only the current owner's content); `useViewportHeight` ([charts/useChartTokens.ts](../charts/useChartTokens.ts)).
- **Runs** ([charts/series.ts](../charts/series.ts)): `runAt`, `sameStretch` (glide only within an unbroken stretch), `clipToSpans` (a date range or a group membership), `extentOf`/`extentOfAll`, `lineEndHour` (end labels where a line is last drawn), segments and curves; `drawLine`, `drawGapFill`, `placeEndLabels` and the rest in [charts/draw.ts](../charts/draw.ts).
- **Rows with tooltips** ([charts/useRowTooltips.ts](../charts/useRowTooltips.ts)): bar or table rows whose hover and focus show a live tooltip and whose right-click or menu key jumps; moving rows ([charts/useRowMotion.ts](../charts/useRowMotion.ts)) slide to a new order.
- **Overlapping spans** ([charts/intervalIndex.ts](../charts/intervalIndex.ts)): `IntervalIndex` and `intervalIndexOf`, for lookups by hour without a scan.
- **Line looks** ([charts/palette.ts](../charts/palette.ts)): `lineStyles`, `lineColours`, `lineDashes`, `SECONDARY_DASH` (a ceiling or other secondary line); the `chart-line-key` paragraph naming solid and dashed lines, with `LineSwatch` for a line's exact dash; `useChartTokens` for the theme.
- **Bar strips** ([charts/strip.ts](../charts/strip.ts)): up and down bars under a time chart (`TimeChart`'s `strip`), `barStrip` draws them and resolves a hover to the bar drawn under the pointer, so hovering a bar is about the read behind it while the chart's own hover stays on its lines.
- **Reads** ([dashboard/reads.ts](../dashboard/reads.ts)): `readAt` (the read behind a value), `entryAt` (the recorded entry that applies at an hour, such as a name as a read recorded it; none before the first, never backfilled) and `readNote` ("Read …; … are read once a day.").
- **Countries at an hour** ([dashboard/countryFlagsAt.ts](../dashboard/countryFlagsAt.ts), [dashboard/countryNamesAt.ts](../dashboard/countryNamesAt.ts)): `useCountryLabelsAt` (name and flag as recorded then), `useCountryNamesAt`, `useCountryFlagsAt`; `useCountriesAt` ([dashboard/useCountriesAt.ts](../dashboard/useCountriesAt.ts)) names a timeline's lanes in view at a moving playhead, read at most every 400 ms while it moves, under the looks rule of [dashboard/looks.ts](../dashboard/looks.ts) (a look is held only while the next read loads; a read that gave nothing leaves it unknown, never an older one); `useHoverLabels` ([dashboard/useHoverLabels.ts](../dashboard/useHoverLabels.ts)) names a tooltip's countries at the hour hovered, asking only for those, under the same rule. A widget that keeps things by tag joins them across recorded changes of tag with `joinTagChanges` ([dashboard/identity.ts](../dashboard/identity.ts)), so a renamed country never reads as one leaving and another joining; ties between tags break in the data service's order (`compareTags`, [dashboard/tagOrder.ts](../dashboard/tagOrder.ts)).
- **Country line charts** ([dashboard/countryLineColours.ts](../dashboard/countryLineColours.ts), [dashboard/useCountryLineStyles.ts](../dashboard/useCountryLineStyles.ts)): recorded map colours with the Appearance adjustment, and names/styles held between playback requests. [Line settings](../dashboard/lineChartOptions.ts) share playback, end-label and axis options.
- **Choosing content** ([dashboard/options.ts](../dashboard/options.ts), [dashboard/chosen.ts](../dashboard/chosen.ts), [components/ChipSet.tsx](../components/ChipSet.tsx)): content-set options and chips that say why they cannot act; a content key with characters a setting cannot store (such as a type content does not resolve, `?token`) is offered as `setToken(key)` and read back with `contentKey`, so every content item can be chosen, and `storedChoices` lets in-widget chips work on those stored tokens; in-widget chips over a chart choose through `chosenShown` (the chosen tokens this recording has, else the automatic one, such as `largestToken`) and `toggleChosen` (what one click stores, keeping other campaigns' tokens, or why it cannot act). A choice whose identity holds only inside one campaign (such as a variant handle) is stored as `campaignToken(campaignKey, token)`, so it never selects another campaign's unrelated item.
- **Artwork** ([dashboard/artwork.ts](../dashboard/artwork.ts)): `artworkEntry` checks each artwork entry's shape (a malformed one refuses the reply); after that, `keepDrawableIcons` turns any icon a widget cannot draw (`drawableIcon`) into missing art for the widget's placeholder, so one bad mod icon never refuses a whole reply.
- **Lane timelines** ([charts/timeline/](../charts/timeline/)): lanes of spans with keyboard stepping and Jump to; a span's `band` draws a thickness that follows a value (factories each day, a faction's members), a span's `color` fills it (a faction, a subject level) and its `glyph` marks it (a leader), a lane's `depth` and `heading` make a tree (an overlord above its subjects), and a `muted` lane fades. Only the lanes in view are drawn, so thousands of lanes cost a screenful. What a holding's runs say at an hour, honestly about unrecorded hours ("Held before", "Ended by", "Last recorded"), is `describeRun` in [runState.ts](../charts/timeline/runState.ts), with `coverCounts` for a band of how many runs cover each hour, `bandMaxOf` for its scale (a loop, never a spread into `Math.max`), and `bridgeGaps` joining a holding's runs across unrecorded hours, so one continued across a gap is never said to have ended.
- **Moving table rows** ([charts/useRowMotion.ts](../charts/useRowMotion.ts)): rows that slide to a new order, flash in and fade out. [WindowedRows](../charts/WindowedRows.tsx) adds viewport windowing and keyboard navigation for long lists.
- **Event markers** ([charts/badges.ts](../charts/badges.ts)): glyph badges, or triangles in the causing country's colour (`shape: 'triangle'`).
- **Races** ([charts/race/](../charts/race/)): new race widgets use [CountryRaceView](../charts/race/CountryRaceView.tsx), supplying recorded entries, lines, optional type parts/mix and their own tooltip wording. [countryRace.ts](../charts/race/countryRace.ts) supplies exact bar items, content-order part colours and held stack bands. The view composes `RaceChart`, the shared race settings/top-10 default, `TimeChart` with `drawLine({ held: true })`, the half-pixel-thinned [stack](../charts/stack.ts), `useCountryColours`, hour-specific country looks/hover labels, end labels, Jump to and standard empty states; it clears tooltip requests when inactive. `mixCountry` picks the mix's country and [race/lines.ts](../charts/race/lines.ts) cuts its lines to the shown hours. The product ranks the top N through `crates/dashboard/src/ranking.rs`. Factories, Equipment produced and Fuel keep their existing views; adopting `CountryRaceView` is a follow-up for their owners.
- **Equipment names** ([dashboard/equipment.ts](../dashboard/equipment.ts)): a variant named as recorded at an hour (`variantNameAt`, never a later name nor one where its names were not known), the arms (`domainName`) and a type content does not resolve (`unresolvedTypeName`), the same in every equipment widget.
- **Many countries while playing** ([dashboard/countryLooks.ts](../dashboard/countryLooks.ts)): `useCountryLooks` reads names, map colours and flags at one sample hour per country, on its sample grid and never before the recorded stretch or the country's current identity starts. Pass a generic `segmentAt(tag, hour)` from identity data independent of display membership; without it the bound is the recorded stretch. Optional per-country `hours` date each line to its own label hour, from `lineLabelHours` in [charts/series.ts](../charts/series.ts); `TimeChart.onViewChange` supplies the visible range. Every pending part keeps the look shown before within that segment, so playback does not flash; a completed missing part or failed read shows the fallback. A retained look never crosses an identity change, gap, backward seek into another segment, source or content change (`sampledLooks`/`retainLooks` in [dashboard/looks.ts](../dashboard/looks.ts)). Facts are keyed by country/hour sets (`factsKey`), with at most two reads going (`FactRequests` in [dashboard/countryFacts.ts](../dashboard/countryFacts.ts)): re-ranking never cancels a read of an hour still wanted, but leaving an hour cancels it and prunes its failures. Errors stay failures, distinct from answered missing values (`FAILED_FACT`); product/configuration errors wait for retry, while transient refusals (`TRANSIENT_ERRORS`), cancellation and unreachable transports retry with backoff. A new `attempt` retries failures at once. [dashboard/contentRevision.ts](../dashboard/contentRevision.ts) scopes fact stores, retained looks and list flags to the configured game/user folders and content readiness. Only products Rust declares content-dependent in the generated contract include that revision in their cache keys; recording-only replies and loads survive folder/readiness changes.
- **Flow diagrams** ([charts/flow/](../charts/flow/)): a Sankey of sources to targets whose ribbons grow, shrink, appear and vanish with playback, with hover, keyboard stops, Jump to and a summed "other" node kept last; the kit says how many nodes a side fits (`flowCapacity`), and the widget sums the rest into that node.
- **Logs** ([charts/log/](../charts/log/)): `LogList` (dated HTML rows newest first, virtualised, flashing in as playback reaches them, month dividers, density, keyboard rows with read-out tooltips, right-click Jump to, `onVisible` for naming only the rows drawn) and `LOG_OPTIONS`/`logSettings` for the settings every log offers. [logCountryRequests](../charts/log/logData.ts) batches only drawn rows' country names and flags at each row's own hour. A log widget keeps only its rows' meaning and wording.
- **Sunbursts** ([charts/sunburst/](../charts/sunburst/)): a zoomable nested pie for any breakdown in levels (spec 2.4). A widget turns its product into `SunburstItem`s (keys per level from content or the recording, an exact amount, or null with the reason it is not measured or not known, counts of parts not counted by reason) and lists `SUNBURST_OPTIONS` and a `levelOption` per level; grouping, folding, colours, zoom, growth, labels, legend, breadcrumb, tooltips and keys are the kit's. `unknownValue` makes a missing total **Not known** throughout its ancestors, rather than a partial sum; `finalUnknown` prevents an unknowable whole from supplying Fill's denominator. `unknownLevels` and `finalUnknownLevels` limit attribution uncertainty to the shown levels it affects, and `authoritativeTotal` keeps an independently measured country total exact. [Construction spending](construction-spending/README.md) and [Production spending](production-spending/README.md) use the same component and options. Production spending reads one country's exact delivery valuation at recorded line costs and groups it by the content's arm, type and recorded design, with every fractional digit and the reason for a missing amount retained.
- **The construction queue** ([dashboard/construction.ts](../dashboard/construction.ts)): building type and place names (content, else the token or number), and the reply checks both construction widgets need.
- **Tables** ([charts/table/](../charts/table/)): the style-5 HTML table with one column model for custom cells, accessible headers, persisted exact sorting and deterministic key ties, missing values last, cell bars, optional ranks, density-scaled row heights, muted rows, motion/windowing, sticky headers and lazy tooltips. Row activation (click/Enter/Space) is separate from an extensible context menu; include `jumpItem` there when dated. Read its final API and Military story before building a table. Declare `TABLE_OPTIONS` and `tableSortOptions` in every table widget; use `useTableHour` for at most ten playback refreshes per second.
- **Groups, drill-down, jump and states**: [dashboard/groups.ts](../dashboard/groups.ts), [charts/drill/](../charts/drill/), [charts/jump.ts](../charts/jump.ts), [WidgetState](../components/WidgetState.tsx).

## Adding a widget

1. Create the folder above and implement `Product` in `crates/dashboard/src/products/<name>.rs`.
2. Add its metadata to `widgets/definitions.ts` and its renderer to `widgets/index.ts`.
3. Run `npm run check:ui`, `npm run test:ui` and the checks in `AGENTS.md`.
