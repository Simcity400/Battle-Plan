# Decryption

The `decryption` product supplies each recorded decryptor → target pair over the branch. Live follows the shared clock; Live off shows the branch end. Rows appear when work is first observed, retain paused work while its native state is recorded, and disappear in gaps. Missing capture shows **Not in this recording** with its reason; a complete empty hour shows **No ciphers being decrypted yet.** A country selection with no matches says so.

The card follows the Decryption race in mock-up `diplo-1`: 52px rows, a 150px pair column, 21×14 flags, 12px rounded meter and 118px status column. The shared [ProgressMeter](../../charts/meter/ProgressMeter.tsx) owns the fill, live sweep and done state. Names and medium flags use the shared `useCountriesAt` playhead batch for mounted current rows, throttled during playback and held within one recorded stretch. Leaving rows retain their last displayed names and flags together. Opaque tags and empty flag frames are visible fallbacks. Progress orders the race by default; Decryptor groups it by the recorded decryptor tag and then progress. Countries defaults to all pairs; the shared multi-select and smart groups filter the decryptor or target. The endpoint option appears only while narrowed. Removing the last pick returns to following the dashboard's selected country; All countries stores one semantic choice and covers every recorded country.

`WindowedRows` uses the existing `useRowMotion` and `.moving-row` styles and renders only the viewport plus overscan. Leaving rows retain their old content and hour until their fade ends. Arrow keys, Home and End reach the full list. One shared `useRowTooltips` call serves the list's hover/focus, menu key and Escape, with accessible row descriptions: pair title; Progress, Started, Bonus days; a separator; Status. Right-click or Shift+F10 offers **Jump to the start of the current attempt** whenever Started is recorded. Broken rows additionally offer **Jump to the break**, using the latest observed break at or before the row's hour. Both dated actions use the shared `jumpItem` and show **by** for an upper-bound observation. Paused attempts use the meter's muted `idle` state and say **paused**; active attempts say **decrypting**, while the tooltip's Status is capitalised. Decryption opts into the meter's live sweep; the app's resolved reduced-motion setting disables the sweep and row motion. Columns and flags derive from the shared spacing tokens; each row fills the height assigned by `WindowedRows`; unknown-progress text and the bonus pill use the shared type scale and `.pill.warning`.

The shared native arithmetic lives in [dashboard/cryptology.rs](../../../../crates/dashboard/src/cryptology.rs). The meter follows the game's rounded, clamped 1–100% frames, including 1% on newly started zero progress. Thresholds use the target's same-hour recorded cryptology strength and the recorded content stack's defines. An unknown threshold says **Progress unknown** and shows the stored amount as an exact decimal (fixed5 `400000` is `4`). Active bonus days are the game's remaining countdown, displayed only while its bonus byte is nonzero. The **+N bonus days** badge appears only when the cipher is broken at the row's hour. This is an approved deviation from `diplo-1`, whose synthetic unbroken rows can show bonuses; native activation makes the cipher broken.

Native tag bytes that the shared JSON/name contract cannot represent keep their cipher data and canonical IDs. The row names the country ID with **tag unavailable**, uses an empty flag frame and reports the tag bytes in a counted warning. Tag-based filtering cannot select that endpoint until the shared naming contract can represent it.

Started is the attempt current at the row's hour, carried on that numeric run; it is never the pair's lifetime-first start. Starting native work (`1413E3A90`) or observing scripted progress (`1413E1610`) opens an attempt. Stopping (`1413E3AD0`) retains the attempt and its amount, including a zero-progress pause. Bonus expiry (`1413E1DE0`) or clearing stopped work ends it; expiry's retained amount alone does not open another attempt. The next observed start opens a new episode and supplies both Started and its Jump to. A gap ends what can be known of continuity: work observed afterwards gets a fresh **by** start, not the earlier episode's date. A target crypto upgrade can un-break a cipher without ending the attempt. Each not-broken → broken transition adds its own break observation and jump target; a true predicate after a gap or an unknown predicate is an upper-bound break. These are observed hours, since the native date is not recorded. A pair's idle state is known only if its first read follows a complete hour, or after an observed end. Otherwise an initial zero-progress idle row may already be paused, and its later activity keeps a **by** start. A gap or unknown previous break predicate also makes its break date **by**. The product owns these episode and break decisions; the frontend checks payload shape and dates, then displays the supplied observations without re-deriving them. Future dates never appear before their observations. Numeric state and per-pair tag history compress independently; neither crosses missing hours. Inactive native zero rows remain in the product even before the race shows them. Transitions completed entirely between identical hourly reads cannot establish a separate episode or date; only recorded observations are shown.

The whole-branch reply encodes amount and bonus countdown as exact daily linear runs. Native daily update `1406DAAF0 → 140FC6AB0 → 1413E1DE0` adds the truncated power-per-target share through `1413E1430`, clamped to the target threshold; the share stays constant while its inputs stay constant. It also decrements an active bonus while the daily loop is enabled. The encoder learns steps from contiguous reads and checks every observed value, splitting at any mismatch, state or threshold change, or gap. A partial first day stays a separate prefix. Local lookup uses whole days from the run's observed phase, preserving every hourly plateau; it returns values only at recorded integer hours. It never estimates a value between reads. Raw amounts use exact integer arithmetic, native state bytes retain all bits, and progress uses the same wrapping fixed5 arithmetic as the native port above. Serialization round-trip and long-history budget fixtures live beside the product; the frontend tests check every value in their recorded-hour fixture.
