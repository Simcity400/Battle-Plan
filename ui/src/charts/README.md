# Charts

The in-house chart kit every widget draws with. It has no chart dependency: time charts draw on Canvas 2D so dozens of animated widgets stay cheap, and one shared scheduler drives them all. Tables use selectable HTML with native scrolling and viewport windowing. Pure logic is tested with `node --test`.

| Module | What it does |
|---|---|
| [table/](table/) | Shared style-5 HTML tables: one typed column model with arbitrary cells and accessible headers, exact persisted sorting with deterministic key ties, missing-last ordering, cell bars, optional ranks, density-scaled row heights, muted rows, sticky headers, motion/windowing, lazy tooltips, keyboard activation and extensible row menus. The README gives the final API and a Military story. |
| [scheduler.ts](scheduler.ts) | One `requestAnimationFrame` loop. A task draws when woken and keeps frames coming only while it is still moving; hidden tasks never draw; the loop sleeps when nothing moves. |
| [surface.ts](surface.ts) | Backing-store size from the canvas's real on-screen size (which includes the widget's Size zoom and display scaling), and pointer positions in layout pixels. |
| [tokens.ts](tokens.ts) | Theme values a chart draws with, read from CSS variables through a probe element, and `APPEARANCE_EVENT` for re-reading them. |
| [palette.ts](palette.ts) | The categorical palette for categories (not countries), solved per theme for 3:1 contrast, and `nudgeApart` for the fixed-colour setting. Faction colours keep their recorded colour (grey included) and move only by lightness where two clash ([factionColours.ts](factionColours.ts)). `lineStyles` gives any number of lines a distinct look: each keeps its preferred colour (`lineColours`) where free, and every further round of lines the colours again with dashes of its own (`lineDashes`). `SECONDARY_DASH` is the one dash of a secondary line beside a solid one in the same colour (a ceiling such as a maximum or a capacity, demand beside supply, war support beside stability). |
| [timeAxis.ts](timeAxis.ts) | Ticks from the recording's own hours: decade, year, quarter, month or day, with labels centred on each period's visible part (quarters on their first tick). |
| [valueAxis.ts](valueAxis.ts) | Nice linear and log ticks; exact formatting of recorded fixed-point integers (`formatFixed`, `formatNativeFixed5` for native fixed-digit truncation, and `formatAmount`/`formatSigned` for amounts; `rescale` turns any denominator into exact decimal units; `rescaleSum` sums fractions with different denominators and rounds once); and `formatAxisValue`, the time chart's default value label (`formatAxisPercent` adds a percent sign), written with the precision its ticks need, so no two ticks read the same. |
| [view.ts](view.ts) | Zoom state and its reducer (wheel, box, pan, dragging either axis, resets), playback domains (draw-in, cursor, window), how far past the playhead a chart shows, and axis settings. |
| [series.ts](series.ts) | Runs of recorded values: `runAt` for any run type, `sameStretch` (whether a value may glide between two hours: no gap, break or change of country between them), `clipToSpans` (runs cut to a date range or a group membership, keeping a line break only where a run starts), `extentOfAll`, and `lineEndHour` (where a line's end label goes: its last hour drawn in view, even when the playhead or view ends in a gap after it, so a drawn line is always named); gap-aware segments, sampling, a monotone curve and stacking. |
| [intervalIndex.ts](intervalIndex.ts) | `IntervalIndex`: items spanning hours that may overlap (such as trade deals), found at any hour without a scan; `intervalIndexOf` builds one once per product reply. |
| [useChartTokens.ts](useChartTokens.ts) | `useChartTokens` (the tokens, kept current) and `useViewportHeight` (the window height every tooltip is fitted to). |
| [easing.ts](easing.ts) | Shape easing for the app's motion setting and playback speed. |
| [rowMotion.ts](rowMotion.ts), [useRowMotion.ts](useRowMotion.ts) | Table rows that move like the signed-off tables: each slides to its new place when the order changes, a new row flashes in and a row that is gone fades out where it was (`nextRows`, pure and tested). `useRowMotion` renders only from the history last committed (`shownRows`) and updates it after each commit (`commitRows`), so StrictMode's double renders and abandoned renders change nothing. The `.moving-row` styles in [charts.css](charts.css) glide over `--row-glide` and stay still under reduced motion, from the system or the app's Motion setting. |
| [rowTooltips.ts](rowTooltips.ts), [useRowTooltips.ts](useRowTooltips.ts) | Rows (bars, table rows) whose hover and keyboard focus show the row's tooltip, kept current while the hour changes, whose right-click, menu key or Shift+F10 opens a menu at the row, and whose Escape hides the tooltip; out of view nothing shows. Each row takes `rowProps(key)` and a hidden full description at `descriptionId(key)`. |
| [divergingBar.ts](divergingBar.ts) | Bars growing left (negative) or right (positive) from a zero line on one scale, as fractions of the track (mock-up economy-1's surplus and shortage bars), cut at the track's edge, and where each bar's end label goes (`barEndLabel`). |
| [labels.ts](labels.ts) | Non-overlapping end labels and label columns measured over the whole campaign. |
| [tooltipPlacement.ts](tooltipPlacement.ts) | Tooltips beside the pointer, flipped and clamped so they are never cut off. |
| [frame.ts](frame.ts) | The plot frame (hour/value ↔ pixel, linear or log, and where a strip under the plot sits), hit zones for the two axes, the plot and the strip, and where the keyboard hover steps. |
| [draw.ts](draw.ts) | Canvas drawing shared by every chart: axes and gridlines (dates under any strip), gap-broken lines (solid or dashed) with a ringed end dot, a fill between two lines bounded by their drawn curves (coloured by which is higher), stacked areas, event ticks, playhead, crosshair, box selection, an emphasised rule at one value such as zero (`drawValueRule`) and end labels (muted for a secondary line such as a ceiling; `placeEndLabels` places them apart and draws them in one call). A `chart-line-key` paragraph (charts.css) names a chart's solid and dashed lines under its header, so a line never rests on its dash alone; where lines differ by more than solid and dashed, [LineSwatch.tsx](LineSwatch.tsx) draws each one's exact dash beside its name. |
| [strip.ts](strip.ts) | A bar strip under a time chart on the same time axis (mock-up economy-1's daily fuel gain and burn): each bar spans its hours with one amount up from a midline and one down, on one scale fitted to the bars in view, labelled in the value axis' gutter. Bars narrower than two pixels share a column that keeps the largest of each, so no peak is lost. A bar ending after the last hour shown is not drawn, since it is known only from its end. A bar that only touches the view has no column. Hovering goes through the same columns (`stripBarAt`): the bar a hover is about is the one whose drawn rectangle is under the pointer (`stripRects`, the rectangles `drawStrip` fills, topmost first), else, above a short bar, that column's bar for the half pointed at; none in the space after a wide bar, since a shared column may draw its gain and its burn from different bars. `stripKeyTargets` gives the keyboard a stop for each bar drawn in view, one the view cuts off at the view's end, about its read, as the pointer resolves it. Keyboard stops have an identity (`keyStopList` and `keyedStop` in [hover.ts](hover.ts)): a bar cut off at the hour of a read is its own stop after the read's, so every item the pointer can reach, the keys reach one arrow press at a time. The list is built in about linear time and only when the reads, the strip or the view change (`keyStopMemo`). `barStrip` builds a time chart's strip from bars, so drawing, hovering and the keys never disagree. |
| [timeline/](timeline/) | Lane timelines: one lane per slot with bars for who held it and when, a left column naming each holder at the playhead, and the same zoom, hover and Jump to as the time chart. Only the lanes in view are drawn: the canvas is as tall as the scrolling view around it and stays in place (`.timeline-view`, sticky) while a spacer as tall as every lane scrolls the lanes under the time axis, which stays at the top (`lanesInView`, `laneOffset` in [layout.ts](timeline/layout.ts)); `onLanesInView` tells a widget which lanes show, so it asks for their names and flags only. [laneRequests.ts](timeline/laneRequests.ts) reads every lane's name, since lane orders compare names (as the order or to break ties), while flags keep the visible window and its margin. A span's `color` fills it (text inside takes a readable colour) and its `glyph` marks its start where it fits; a lane's `depth` indents it and `heading` makes it the bold head of the lanes after it, for a tree. [runState.ts](timeline/runState.ts) says what a holding's runs mean at an hour (`runState`, `describeRun`: held since or held before, ended or ended by, last recorded) and builds band steps from how many runs cover each hour (`coverCounts`, `withoutHours`, `stretchesOf`, `bandMaxOf`); `bridgeGaps` joins a holding's runs where nothing recorded says it stopped (every hour between them unrecorded, and the caller agreeing, such as one relation). Its pass keeps a cursor into the sorted unobserved spans, linear in runs plus spans. What is said of a run ("Ended by", "Still a member") is said of its stretch (`stretchAt`). With the keyboard, the arrow keys step through lanes and bars and show each bar's tooltip, read out too. A span with `band` steps is drawn as a band whose thickness follows a value over its hours (a production line's factories each day), on the timeline's `bandMax`, so every lane shares one scale; it is drawn in whole pixel columns by one rule (`bandOutlines`, `bandHalf` in [layout.ts](timeline/layout.ts)): a column recorded hours cover fully is drawn at the thickest step touching it; a column a gap also touches stays empty, its thickest passing to the nearest column its own span draws (never across to another span), so rounding never fills over missing hours and no peak is lost; a stretch with no fully covered column keeps one column, its middle, moved one column away from a neighbouring run beyond more than a pixel of gap (resolved forward then backward, so at either plot edge whichever can move does), so no band vanishes and separate runs never touch across a visible gap; where the plot cuts a run is not a gap. A lane's band spans are placed together (`laneBands`), each column drawn by and in the colour of the span whose value it shows, so the rule holds between spans too; each drawn column also records the span and step it draws, and hover, the tooltip and Jump to describe what is drawn under the pointer (`bandHitAt`), even a short band moved off its own hours. Laying out is linear in the steps and the plot's columns, and a lane's layout is kept while its lane and view are unchanged (`laneBandLayouts`), so moving the pointer lays nothing out again. The keyboard stops at each band step shown as well as each bar (`laneStops`, on `keyStops`), so every value the pointer reaches is reachable. A `muted` lane is faded in the left column, such as a line that has ended. What a bar draws inside itself follows its lane's icons and names (`barContent` in [barLabel.ts](timeline/barLabel.ts)): with names off, a bar meant to show art it lacks shows its name instead, and a lane that asks for neither stays plain. |
| [badges.ts](badges.ts) | Event badges: small glyphs along the top edge with a guide line down the plot. Hovering one snaps to its hour and names the event; a click picks it; right-click jumps there. The time chart lists the badges it draws, in its current view, as text for assistive technology. |
| [TimeChart.tsx](TimeChart.tsx) | The time chart component: layers, an optional `strip` under the plot (hovering, wheel, pan and a time-only box zoom work there too; a hover over it is about what its `describe` names from the pointer's position, such as the read of the bar drawn there, even where a zoom cuts the bar off, while the crosshair stays at the pointer, and the plot's `snap` applies only over the plot: `pointerTarget` in [hover.ts](hover.ts)), a value axis fitted from zero or, with `fitValues`, to both bounds of what is drawn, its left side widened to fit the widest value label (unless the widget sets `padding.left`), value labels formatted with every tick drawn so neighbours stay apart, zoom that holds during playback (wheel, box, Shift/middle-drag pan, axis drags, double-click and Escape resets, a Reset zoom chip), live hover and right-click. With the keyboard, the arrow keys hover through `keyHours` (else a day at a time), Home and End go to either end, and Escape leaves; the hovered tooltip is read out, and the context-menu key and Enter act on the hovered hour. A navigation key takes the hover from the pointer, and moving the pointer takes it back ([hover.ts](hover.ts)), so the hour drawn, its tooltip, what is read out and what the keys act on always agree; the menu key opens one menu at that hour, and the browser's own menu event after it opens no second one. Pass every read as `keyHours`: a range or zoom that starts between two reads gets a stop at its start, where the earlier read's value is carried (`keyStops` in [frame.ts](frame.ts)). |
| [tooltip.ts](tooltip.ts), [TooltipLayer.tsx](TooltipLayer.tsx) | One tooltip for the whole dashboard, fed structured rows (never HTML), rendered in the top layer so no widget clips it and the native map stays visible; `tooltipText` reads a tooltip as one line for assistive technology. `fitTooltip` fits a tooltip to the window: the fullest of its forms that fits, else the most compact cut with its totals kept and one row counting the rest, never cut off by the window; the full content (the first form, or a separate `full` form where even the fullest shown is capped, such as a list limited for the eye) stays in `spoken`, which `tooltipText` (and so the time chart's keyboard read-out) reads. |
| [images.ts](images.ts) | `canvasImage`: an image a canvas chart draws (a flag), decoded once per URL for every chart, least recently drawn dropped first; until it loads nothing is drawn in its place and the chart is woken when it arrives. |
| [flow/](flow/README.md) | Flow diagrams: a Sankey of sources (left) to targets (right) for Trade flows and, later, Territory transfers, Casualties between countries, Bombing damage and Who spies on whom. The widget hands `FlowDiagram` nodes (a label, a colour, an optional flag, a stable `order` key, and `last` for a node summing the rest) and ribbons (a value and a colour); what they mean stays in the widget. `FlowMotion` ([layout.ts](flow/layout.ts), pure and tested) eases each ribbon's width toward its value and each node toward its slot, so ribbons grow in, shrink away and nodes glide to their new places. Slots go largest first, with `last` nodes at the end. Inside a node, ribbons keep a fixed order by the other end's `order` key, so nothing jumps. A `stretch` change (such as crossing a gap in the recording) or reduced motion jumps instead of gliding. `scale` gives one value for the full height, so widths are amounts all campaign; `slots` keeps that scale while nodes come and go. **Fitting the height:** every node is drawn at least `MIN_NODE` (2 px) so no trade vanishes, gaps shrink (to `MIN_GAP`, at most a quarter of the height) before nodes do, and `flowCapacity` says how many nodes a side can show with a label row each: the diagram reports it (`onCapacity`) whenever its size changes, and the widget sums the rest into its `last` node, as the race shows "+N more", so no node or name falls off. Hovering a ribbon or node dims the rest and shows the widget's tooltip, kept live during playback. Pass a memoized tooltip callback with every input it reads; a changed callback invalidates the still hover's cache ([tooltipCache.ts](flow/tooltipCache.ts)). Right-click, Enter or the context-menu key ask the widget for its menu. The arrow keys step through each source node and its ribbons, then the target nodes (`flowStops`), showing and reading out each tooltip. Hit testing (`linkAt`, `nodeAt`) follows the drawn curves, with a few pixels' slack for thin ribbons. Labels are placed apart with leader lines (`layoutEndLabels`), flags are drawn with `canvasImage`, and a flag not known keeps its place, outlined. A legend whose colours mean something shows even for one item (`Legend`'s `always`). |

Widgets show loading, empty, error and "Not in this recording" with [WidgetState](../components/WidgetState.tsx). The Appearance settings' **Charts** section holds the app-wide chart motion (snappy, smooth, cinematic) and country colours (raw or adjusted); charts read both from `ChartTokens`.

## Rules

- **Shapes ease; numbers stay exact.** Labels and tooltips show the recorded value at the resolved hour; only positions glide. Nothing eases across a gap, and a gap is never drawn as zero.
- **No fixed dates.** Axes, ticks and ranges come from the recording's start and end; settings store offsets from the branch start.
- **No fixed colours or sizes.** Draw with `ChartTokens`. Countries use their recorded map colours; categories take their content colour, else the palette in its fixed order. Content may have any number of categories, so none is hidden for want of a colour: lines past the eighth repeat the colours with dashes of their own (`lineStyles`), and bands repeat them in order.
- **Sharp at any Size.** Size the backing store with `backingSize` and draw in layout pixels; never stretch a canvas.
- **Zoom holds during playback.** A zoomed axis keeps its range until the user resets it.
