# Frontend

The React/TypeScript interface hosted by the desktop app. It owns navigation, appearance, saved layouts, the shared playback clock and the widget grid. The [viewer](../crates/viewer/README.md) draws native maps into widget bodies.

## Layout

| Area | Responsibility |
|---|---|
| [src/shell/](src/shell/) | App views, Settings, appearance, Tauri API wrappers and native viewer lifecycle. |
| [src/recorder/](src/recorder/) | The Battle Plan Recorder tray panel, the second page ([recorder.html](recorder.html)) of the same build. |
| [src/components/](src/components/) | Shared popovers, tooltips, icons, country flags and pickers, playback and map controls. |
| [src/dashboard/](src/dashboard/) | Campaigns, layouts, widget frames/settings, playback, data clients and product caches. |
| [src/charts/](src/charts/README.md) | Shared Canvas charts, HTML tables, motion, exact formatting and interactions. |
| [src/widgets/](src/widgets/README.md) | Widget registration and one folder per widget. |
| [src/generated/](src/generated/) | Rust-generated TypeScript contracts; regenerate rather than edit. |
| [styles.css](src/styles.css) | Global design tokens and common controls. Component CSS refines these variables. |

## Development

Run `npm.cmd run dev:ui` from the repository root for Vite only. `check:ui`, `test:ui` and `build:ui` are the frontend checks/build; the tests live beside their modules and need no game. Desktop startup and Rust build instructions are in the [desktop guide](../crates/desktop/README.md) and [AGENTS.md](../AGENTS.md).

The [Playwright harness](e2e/README.md) provides `parity:compare`
from the same root package. Installed Microsoft Edge captures every widget's
view-model and screenshot from two instrumented builds, using an existing release
bridge. It never builds Rust.

UI tests run in two groups: pure tests use normal Node concurrency, then browser fixtures run serially with one browser at a time. [test-ui.mjs](../tools/test-ui.mjs) lists the browser files and checks test dependencies for unlisted browser fixtures before running either group. Every test runs once, and a failure in either group fails the command. Browser shutdown shares one deadline and retry budget across graceful close, exact-profile termination and absence verification, reserving a final termination attempt on the owned process handle. Profiles are removed only after verified absence; failed verification reports and retains the exact profile path.

`test:ui` includes representative native Tab differential paths, complete small-list paths and sparse 5,000-row histories. `npm.cmd run test:ui:tab-full` runs the complete generated VirtualList traversal and mutation sweep alone. Both commands validate the complete test manifest and use the same serial browser ownership and verified cleanup. The full command supplies its sweep flags only while that fixture runs; default tests clear those flags so inherited settings cannot change their coverage.

`npm.cmd run audit:ui` audits the root lockfile's runtime and development UI
dependencies using the npm registry. Run it after dependency/lockfile changes
and before releases; review reported advisories before choosing and testing
updates. Rust dependency checks and recording fuzzing are described in the
[root guide](../README.md#recording-and-dependency-checks).

### Real recordings in the browser

Build the dashboard's `dashboard-bridge` binary with `cargo build -p dashboard --bin dashboard-bridge` from the repository root. Set `BATTLE_PLAN_RECORDINGS_DIR` in ignored `ui/.env.local` to a scratch folder outside Git; `BATTLE_PLAN_GAME_DIR` and `BATTLE_PLAN_USER_DIR` enable artwork. The desktop app's saved folders (`APPDATA/battle-plan/content.json`) take precedence, and Settings > Folders updates them. [browserBridge.ts](browserBridge.ts) starts the adapter on demand and forwards cancellation. Production uses the desktop transport. Both transports enforce the generated message-size budget and preserve country selections intact.

The browser admits three ordinary requests, two interactive product requests and one short release command at a time, reserving connections so history loading cannot delay dated titles and images. Interactive membership comes from the Rust-generated product contract. Queued work stays complete and can be cancelled before fetching; active cancellation holds its slot until the HTTP body settles. Source release cancels only that lease's work and bypasses history queues. Page unload releases held leases with JSON beacons.

## Data and identity

The [dashboard architecture](../docs/dashboard.md) and [Rust dashboard guide](../crates/dashboard/README.md) describe the product boundary. [client.ts](src/dashboard/client.ts) defines the frontend client; [nativeClient.ts](src/dashboard/nativeClient.ts) and [browserClient.ts](src/dashboard/browserClient.ts) implement it.

- [products.ts](src/dashboard/products.ts) shares identical requests through `useProduct`/`useProducts`. Full-branch histories support local playback lookups; hour-specific facts use `loadTransientProduct` so they do not evict histories. Closing a source releases its products and list flags.
- [productWindows.ts](src/dashboard/productWindows.ts) bounds dense histories by requested windows. Hold the visible/next playback window and reached tooltip windows, then release unwanted demand. Windows arriving in one animation frame commit together through immutable balanced maps, copying only changed search paths. `useWindowDisplay` retains a loading window at its own hour; pass the client to bind that display to its source owner.
- Hook data, errors and callbacks belong to the client and request identity. A source switch must mask old results immediately. [contentRevision.ts](src/dashboard/contentRevision.ts) invalidates content-dependent products and artwork when content changes; recording-only histories remain independent.
- [numericReply.ts](src/dashboard/numericReply.ts) retains same-request numeric history while labels reload; keep its coverage, errors and pick ownership independent of artwork. [countryIdentity.ts](src/dashboard/countryIdentity.ts) preserves native rows across tag changes without filling identity gaps.
- Validate payloads with [validation.ts](src/dashboard/validation.ts). Keep recorded integer/decimal-string operands exact until formatting; floating point is for geometry. Preserve zero, missing values, refusal reasons, coverage gaps and supplying read hours separately.
- Dated names, flags and colours belong to each hook's client, source revision, branch, content and projection. Each hook owns its demanded reads and cancels them when demand departs. Pending, failed and completed-missing reads remain distinct. Failures belong to exact hour/token demand; departing tokens release their refusals even when another country keeps that hour active. Country/faction helpers preserve these states. Retained looks apply only while the next read loads within the same identity and recorded stretch; a completed missing read stays unknown. Request flags only for drawn countries. See [looks.ts](src/dashboard/looks.ts), [countryLooks.ts](src/dashboard/countryLooks.ts) and [factionNames.ts](src/dashboard/factionNames.ts).
- Content headings, choices and chart labels use localized titles. [contentTitles.ts](src/dashboard/contentTitles.ts) preserves empty titles and supplies explicit loading/unavailable labels; internal keys belong in hover hints or details. Stored literal character, faction and design names retain their own naming rules. Focus text loads independently of images; research history includes text and requests images separately in small batches.
- Dated fact queues normally read in time order. Focus and research artwork prioritize current cards and completion rows in the displayed view while retaining every requested date and token. Follow focus requests newest completions first to match its automatic scroll; other views start at the first completion row. Research requests only technologies shown at the selected hour.
- Dated fact queues retain their exact pending chunks between successful replies. Demand, admission, ordering and retry changes rebuild the plan; completion starts the next chunk without scanning the full history again. Two requests run at once, and completed missing values, failures, cancellation and exact hour/tag ownership remain distinct.

Mounted prepared products publish their initial covered or approximate reply immediately
and replace it only when accepted coverage advances. Partial replies belong to
the mount and never become shared cached results. Completed replies, and replies
without coverage, use the bounded product cache. One-shot reads return the first
available reply. Source release, content changes and unmount cancel departed
requests; a preparation failure retains already published data with its error.

Campaign library context menus expose [preparation and storage](src/shell/preparation/README.md). Progress, cancellation and Clear read real backend state; the panel polls only active jobs and releases temporary archived-recording sources when closed.

## Layouts and playback

Analytics is split into the pages in [pages.ts](src/dashboard/pages.ts); users add, rename and delete them in the sidebar ([AnalyticsNav.tsx](src/shell/AnalyticsNav.tsx)) and reorder them by dragging or Alt+Up / Alt+Down on a focused page. Settings resets the built-in pages and every layout. Inactive analytics unmount their widget bodies. Widget bodies mount progressively within a display-frame budget, in viewport order. Each page has its own saved layouts and a designed default arrangement (empty for an added page); the loaded campaigns, playback and country are shared by every page. A widget may sit on more than one page, each copy with its own settings. The page list scrolls within the sidebar while Campaign map and footer controls stay reachable. If this device cannot save the page list, a warning stays above every view until a page-list save succeeds; changes still apply for the session.

[model.ts](src/dashboard/model.ts) owns templates, tracks and widget time modes; [storage.ts](src/dashboard/storage.ts) saves semantic choices and branch-relative offsets, never runtime handles. Widget titles that follow a content choice preserve authored empty text through save and restore. Unknown widget kinds or unsupported settings retain their saved data. An unstorable country choice reports a restoration warning without discarding the layout or rewriting its saved data. Content/country lists have no shared count or token-length cap.

[playback.ts](src/dashboard/playback.ts) is the single clock shared by Overview and Campaign map. Subscribe only when following it; resolve widget windows through the model. Range scrubbing seeks to each selected position. Animations read `positionAt` between ticks, while the map receives the latest hour. A widget can follow, show its branch end or pin a moment as its definition allows. Settings and Live changes save immediately; adding, moving, resizing and removing widgets wait for edit-mode Save. Campaign assignment opens a recording through the shared source path and keeps it open until sidebar unload.

Use [calendar.ts](src/dashboard/calendar.ts): the game's fixed 365-day calendar, display hours 01:00 through 24:00, and raw engine hours underneath. Never carry values across unrecorded hours. Partial recordings retain a terminal failure notice above both views and marks in campaign/library entries; an unknown failure hour is never guessed. Damaged or modified recordings use that same banner with the unreadable part count and known date range, and a Damaged pill whose tooltip lists bounded technical reasons. A recording that is both damaged and partial combines both facts in one banner and one Damaged pill. Widgets retain their existing gap behaviour.

## Shared appearance and controls

Typography follows T3 Code's simple and advanced controls, using Replay's roles. Simple mode exposes Interface and Tables; Advanced adds Headings and Diagnostics. Interface, Headings and Diagnostics each have a family, pixel size and individual reset; defaults and ranges are Interface 16px (12–20), Headings 14px (12–20) and Diagnostics 12px (8–20). Tables have a family only: empty uses Interface's, and table text takes the interface's small size, as charts do. Headings fall back to Interface's family. In Simple mode diagnostics use the monospace default at 12px; Advanced gives them their own family and size. Hiding Advanced preserves overrides. Word wrapping defaults on for table cells and technical reports; grayscale font smoothing defaults on and is configurable in Advanced on macOS. Settings search reveals hidden advanced controls.

Settings use a centered reading column, divided groups and compact controls. Live previews sit inside their font settings: in Simple mode Interface shows headings and controls and Tables shows a sample table; Advanced moves the headings preview to Headings and adds a Diagnostics preview.

The Campaign map's header shows and changes the full map's camera ([CameraModeControl.tsx](src/components/CameraModeControl.tsx)): Map, Fly or Walk. The viewer owns the mode and the control shows what the host last heard from it, so the map's own shortcut moves the control too. While the map is popped out, Map settings also show the pop-out map's own camera, as its viewer reports it; the [viewer guide](../crates/viewer/README.md#camera-modes-and-controls) lists the controls.

Diagnostics ([MapDiagnostics.tsx](src/shell/MapDiagnostics.tsx)) says how complete the open recording is: its span, a coverage bar marking each reported gap, whether the capture stopped early, and the notes from reading the file, folded away. It also holds the map's technical overlay (F3) and the problems the map last reported.

Font fields open a searchable menu when clicked. Where installed-font discovery is granted, the entire field is a button; otherwise the field remains editable for family names or comma-separated fallback stacks. All fields share discovery, requested on focus or eagerly when permission is already granted. The list renders only visible rows. A custom entry applies after a 400ms pause or blur/Enter only if the browser can use it; Diagnostics also requires monospace glyph advances. An invalid draft retains the current font; Escape discards it. The menu includes System and bundled Inter, Roboto, Roboto Condensed, Source Serif 4 and Cascadia Code, so presets work without locally installed fonts or a font service. Their unmodified upstream OFL notices ship in `LICENSES/` alongside desktop releases. Diagnostics offers System and Cascadia Code presets. A saved custom font unavailable on another computer retains its preference and uses the platform fallback there.

Use [Popover.tsx](src/components/Popover.tsx) for interactive pop-downs, [Tooltip.tsx](src/components/Tooltip.tsx) with `data-tooltip` for hints, [CountryPicker.tsx](src/components/CountryPicker.tsx) for country choices and [Icons.tsx](src/components/Icons.tsx) for the outline icon family. Heavy pop-down contents go in `PopoverBody`, which builds them only once opened. The country picker and Select window long lists; keyboard navigation reaches the complete roster. Select retains its active value when choices arrive or reorder, falling back to the first enabled choice if it disappears or becomes disabled. Tab and Shift+Tab traverse its complete enabled roster and leave at either edge. Its menu sizes from every authored label within the viewport, and measures wrapped visible rows. Expandable focus histories and research columns measure mounted rows. Focus histories retain offscreen expansion state. Their listeners bind to the committed scroll surface; Tab and Shift+Tab traverse the complete logical research columns and their controls. [VirtualList](src/components/README.md#virtuallist) consumers identify noninteractive rows through a stable `isInteractive` predicate; those rows keep their ordered-list positions while keyboard navigation and entry boundaries skip them. Eligible positions are indexed when content or eligibility changes, so per-key navigation never scans static runs. A wholly static viewport retains one real eligible row for native entry; a fully static list keeps native scroller behavior. Long legends window automatically. Flags come from recorded content at the shown hour; a missing or failed flag shows a grey placeholder labelled only "Flag unavailable" (or "Flag loading"), and its reason stays out of sight. The top bar's country button draws its flag through the recorded native top-bar shield sprite, mask and overlay as the game does; every other flag uses the `panel` size, the same shield with the overlay's dark edge shading evened out so only its texture remains. HTML and Canvas fit the artwork into each flag slot without cropping or changing its proportions.

Sidebar navigation and Analytics page icons have separate default colours for dark and light mode. Right-click a navigation button or page (or use Shift+F10) to change its icon colour; the colour picker resets a changed colour. Overrides save with appearance preferences on this device, including added pages and Settings search results.

In the sidebar's Campaigns section, + opens the system file picker and the chosen recording joins the list; clicking a campaign shows it. Right-click a loaded campaign, or use the ContextMenu key or Shift+F10, to rename it, change its flag or unload it. F2 edits the focused recording's display name; Enter or leaving the field saves it, and Escape cancels. In the desktop app names save in the recorder's shared settings by normalized recording path, so Battle Plan Recorder shows them too; names saved on this device move there once, filling in any the shared settings lack, and each later save sends only the names it set or cleared. The browser saves them in this device's UI settings. The recording file and saved layouts keep their own names. An empty name or the file's own name clears the override. Display names appear in recording rows, widget campaign choices and subtitles, Diagnostics and recording notices; search matches both the display name and file name, and tooltips include the file name. In the browser, names share the campaign settings' storage budget without an individual length or recording-count limit. A failed save appears in the sidebar and the name applies for this session. A chosen sidebar flag saves with the recorded campaign identity (in the desktop app in the recorder's shared settings, moved there once like names; in the browser with this device's campaign settings), uses that recording's countries and content, and can be cleared with Use the shown country's flag; tags are non-empty recorded text without NUL or a length cap, and the top bar continues to show its selected country.

An Archive shelf at the bottom, collapsed until opened (and remembered), lists recordings in the replay folder that are not open, ten at first with Show more for the rest. Archive recordings have the same display-name editing controls in both desktop and browser. The replay folder itself is chosen in Settings; in the desktop app it is also the folder Battle Plan Recorder saves into.

Charts that use faction colours offer a Faction colours section in their settings, for the chart's selected campaign. Colours default to this campaign and can also be shared across campaigns; display names apply to this campaign only. Changes use the shared campaign preferences and appear across its charts.

Themes, fonts, chart motion, country-colour adjustment and backdrops belong in [appearance/](src/shell/appearance/). Theme roles drive the entire interface through CSS variables; preserve the clean shared style. Contrast ranges from 50% to its default and maximum of 100%, which shows the theme as defined. The Contrast setting adjusts the text, secondary-text and border roles before they are written, so styles and charts derived from them follow; surfaces keep their theme colours. Default interface typography is the system UI font at 16px, using weights 400, 500 and 600; Inter and installed fonts remain selectable. Outlined fields and controls use `--control-*`; dropdowns use the shared [Select](src/components/Select.tsx), never a native `<select>`, so their menus match the app's other menus; sidebar rows and widget-header buttons stay borderless. The native map sits above the page: menus and sidebar peek hide it while open, and hints stay within their sidebar/header area.

## Battle Plan Recorder panel

[src/recorder/](src/recorder/) is the [recorder-app](../crates/recorder-app/README.md) tray panel, built from [recorder.html](recorder.html) into the same `dist`. [status.ts](src/recorder/status.ts) maps the recorder's snapshot to each state of the panel's design (waiting, not recording, recording, the Stop prompt, problems, saving, saved, session discarded, and the one line naming loads a session left out), with dates from the game calendar, whole-megabyte sizes, display names from the shared recorder settings and the viewed country's flag drawn by the shared flag canvas; [RecorderPanel.tsx](src/recorder/RecorderPanel.tsx) draws them, Settings and its What to record view with the shared controls. The page applies the saved appearance as the app does (its window shares the replay app's WebView storage), invokes the tray app's commands, follows its `recorder-status` event and reports its height so the window fits it. Status text truncates rather than run under a button.
