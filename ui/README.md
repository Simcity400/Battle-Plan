# Frontend

The React/TypeScript interface hosted by the desktop app. It owns navigation, appearance, saved dashboard layouts, shared playback and widget controls. Native map widgets and the Campaign map tab use the existing native renderer; do not recreate it here.

## Develop and check

Run from the repository root:

```powershell
npm.cmd run dev:ui
npm.cmd run check:ui
npm.cmd run test:ui
npm.cmd run build:ui
```

The desktop app uses native folder selection and map rendering. Browser development can read real recordings through the local bridge described below; native maps still need `npm.cmd run dev`. See the [desktop guide](../crates/desktop/README.md).

The browser preview opens directly on Overview. For UI iteration while other work is benchmarking, use `npm.cmd run dev:ui`; it starts only Vite and avoids compiling Rust or launching the native renderer. For a preview on another machine on the same LAN, pass `-- --host <development-machine-LAN-IP>` and open that address on port 1420.

Start in [dashboard](src/dashboard/) for the widget framework and [analytics](src/analytics/) for shared calendar and numeric formatting. Rust-generated data types are described in the [analytics guide](../crates/analytics/README.md). Regenerate them; do not edit the generated TypeScript.

### Real recordings in the development browser

Build the adapter once with `cargo build -p viewer --bin dashboard-bridge -j 1`. Set `BATTLE_PLAN_RECORDINGS_DIR` to a local scratch folder outside Git in ignored `ui/.env.local`. For genuine game/mod flags, also set `BATTLE_PLAN_GAME_DIR` and `BATTLE_PLAN_USER_DIR` to the matching game and Paradox user folders. These environment values provide initial defaults; folders saved in Settings take precedence. Restart Vite after changing environment values.

Recordings lists `.battleplan` files from the configured folder and its subfolders. Listing reads directory entries only, not recording contents. Hidden folders, symbolic links and unfinished files are excluded, and traversal is bounded. The list reloads when opened; there is no Refresh or Replace menu. Each row shows only the actual replay filename, with its full path on hover or keyboard focus, plus Load/Unload and a default star. Paths use a themed, wrapping tooltip kept within the viewport instead of a browser-native title bubble; Escape dismisses the tooltip without closing the library. A search field filters the list, and loaded campaigns remain visible in the sidebar with the same filename and default action.

Settings and the initial unconfigured-library prompt offer a replay folder. Browse opens the Windows folder picker in both desktop and browser development; browser dialogs appear on the computer running the dev server. Cancelling leaves the current folder unchanged. Both hosts persist the replay folder in `battle-plan/replay-folder.json` under APPDATA (or HOME/.config); the browser uses `BATTLE_PLAN_RECORDINGS_DIR` only as an initial fallback. Changing folders leaves loaded campaigns connected. Library files open directly under that folder.

The folder icon beside Find a campaign opens the normal system file picker for a recording anywhere else, without changing the replay folder. The desktop opens the selected path directly. A browser selection streams to an isolated temporary copy on the server (up to 2 GB); the bridge admits only those explicitly imported paths outside its recording root. Selected files remain in the session list after unloading. The compact list places the default star immediately before Load/Unload and reserves no empty star column for unloaded recordings.

`browserBridge.ts` is a development-only Vite middleware with bounded requests, cancellation and recording-root checks. It starts the stdio adapter on demand and stops it with Vite. Browse launches a separate, single-use adapter process for the native folder dialog; only one picker may be open at a time, and disconnection or server shutdown cancels it. The normal adapter creates no window or graphics device and does not access the running game. Production builds continue to use the desktop transport.

## Dashboard responsibilities

The dashboard has a campaign map, a national focus widget and placeholder panels for future widgets. The unapproved current-value and history renderers and their chart dependency have been removed. The query runtime remains available for future code-defined widgets. Placeholders can be renamed, added, removed, moved and resized; they never request data. In Edit mode, all widgets move by dragging the header grip and resize by dragging the bottom-right handle; there is no separate move/size button strip. The new workspace layout uses a separate local-storage key, leaving the older prototype's saved layout untouched.

Each compact widget header opens an anchored settings popup with a Live playback toggle, title, campaign and country. Changes apply immediately without a confirmation button. Empty title edits retain the last valid title and reset on blur. The shared popup heading has reset-to-defaults and close icons. Delete appears beside them only in layout edit mode, including for map widgets. Reset uses the registered widget defaults while keeping its identity, size and position. Layout changes remain available to save through the layout controls. Country selection reuses the header's searchable picker and defaults to the campaign's selected country, showing its name and flag. Choosing a different country overrides that widget; choosing the campaign's current country restores the default. There are no separate track, time-mode or country-mode selectors, help subtext or side drawers. New campaign maps start linked to live playback; other widgets start unlinked: campaign mode holds moment widgets at their branch's final hour and history widgets over the whole branch. Linking follows the shared playback position; disconnecting returns to campaign mode. The choice is saved per widget, and existing saved time modes are preserved. Placeholder link controls configure future behavior without querying or displaying statistics.

`client.ts` separates widgets from the native transport. `model.ts` describes sources, tracks, widget settings and time scopes; `playback.ts` owns the shared clock. Whole-campaign and selected-period views retain their queries as playback advances. Current values and trailing history use bounded exact-window requests. A moving chart marker does not need another historical scan.

The campaign session is mounted with the app and survives tab switches, including unsaved edits, source bindings and reusable query results. Overview and Campaign map share the selected country, clock, date and playback speed. Leaving Overview unmounts widget consumers and stops dashboard map geometry; playback can continue in Campaign map. Settings pauses playback. The top-bar layout picker switches between named templates and remembers the selection across app restarts. Save appears while editing or when changes are pending; its menu can update the current layout or save a named copy. Done leaves pending changes available to save, and Cancel restores the selected saved template. Save or cancel before switching layouts. Failed saves retain the draft and leave the saved layouts untouched.

Overview and Campaign map render the same country picker, calendar, transport, speed and timeline into the shell's top-bar slot. Only Overview includes the layout picker and layout actions. The plus button is visible only while editing the layout and opens a popup of registered widgets. The timeline spans the date, transport and speed controls; dragging it or using its arrow keys seeks by game hour and pauses playback. Its bounds use the shared clock axis, while its accessible date uses the selected reference track. The main area contains the widget grid; Settings lives in the sidebar. The dashboard still owns the clock and source bindings; moving the controls does not create another playback controller. Date selection remains a draft until Go; seeking or playing clears that draft. Unavailable recording controls stay visible but disabled.

`mapPlayback.ts` forwards the shared clock's whole hours to the existing native map seek command while Campaign map is active. It retains the default campaign's source revision, branch and alignment offset, coalesces pending hours while a command is busy, and stops forwarding when switching views. Out-of-branch dates and command failures remain explicit; stale completions cannot replace newer errors or selections. Native renderer delivery and maximum sustainable speed still require desktop integration validation.

The top-bar country picker searches only countries with recorded land ownership at any point in the default campaign, including other recorded branches, and initially selects the recorded country directly. Ownership discovery runs in the background and is cached per native source; the menu shows loading, empty and retry states without falling back to all possible tags. Selection is session state per campaign and feeds widgets using that campaign's selected country; explicit widget country choices remain independent. Switching defaults restores that campaign's selection, and choosing a country does not trigger layout Save. Countries that gain land later or lose all their land remain selectable. The catalogue merges newly discovered identities into session metadata for widgets; missing ownership history remains explicit. Flags come from the native country-flag endpoint, which resolves the recording's game/DLC/mod layers and cosmetic/ideology variants at the recorded ownership witness for each listed country. There are no bundled flag approximations or tag-to-country mappings. Missing artwork stays blank; the picker only shows an artwork error when flags are unavailable, without a generic local-artwork label. The development bridge serves these same flags when its game folders are configured. Playback sits just left of the layout and widget controls, which remain together at the right. Header labels remain accessible but are visually hidden; the built-in template is named Default layout.

Country discovery and flag requests share bounded session caches keyed by source revision and, for artwork, branch, witness hour, size and tags. Concurrent consumers share in-flight work; an effect cleanup followed immediately by setup does not restart it. Closing a campaign clears its entries. Recording leases survive React effect replay during UI hot reload; actual unmount still cancels requests and releases leases. Retry reconnects an expired recording handle instead of repeating requests against it. The first native ownership scan walks the recording history but retains and reconstructs only the four tables required to establish ownership and campaign identity. Development builds optimize the native compression codec as well as the replay crate.

The country section requests the selected country's full game flag, while menu rows request the game's separate miniature assets. These requests share the same recorded content context but keep their images and response identities separate; missing full artwork never enlarges a miniature in its place. The header displays the flag at full height beside the title, with a hover highlight and click-to-select behavior instead of a boxed dropdown or arrow. Country, date, speed and layout controls share the bar's vertical center; the timeline sits beneath playback without affecting that alignment. On narrow screens, playback wraps below country and layout controls with space reserved for the scrubber.

The sidebar owns the Recordings library and compact rows for loaded campaigns. Default selection is a star on the campaign row; there are no per-campaign action menus. Each widget selects its own campaign in its settings pop-down, either Default campaign or an explicit recording. There is no global comparison or alignment control in the top bar. Saved alignment and branch definitions remain readable for existing layouts. The interface has no side drawers. Campaign and widget pop-downs stay within the viewport, dismiss on Escape or an outside click, and hide native maps while open.

`queryStore.ts` owns independently cancellable subscriptions, result identity checks and byte admission; `queries.ts` is its React adapter. Current-hour work and background history have separate admission slots, and speculative work carries its priority through the native transport. `geometry.ts` sends one coalesced snapshot of all native map bodies and their clips, including scroll/DPI changes. A result or map acknowledgement must match its source, revision, branch and target before the interface calls it current. Ready views publish independently; loading and errors stay local.

`DashboardGrid.tsx` uses React Grid Layout. `storage.ts` saves a bounded, versioned library of templates with source roles and semantic country choices, never live file handles or recorded data. The previous single saved workspace is restored into the library without overwriting its storage key. Rebinding a template to another recording must not assume its numeric IDs or dates identify the same entities. Missing bindings remain visible. An unavailable storage area is a layout error, not a recording failure.

## National focus widget

Add **National focus** through Edit > Add widget, or use it in a new Default layout. It follows the header country, with an optional explicit country and campaign in its settings. Campaign mode shows the selected branch's final recorded completion list; Live playback and pinned moments select an exact recorded hour. The header includes the completion count, and the body goes straight into the numbered focus list. Rows contain artwork, name and a date without a clock time; the current or continuous focus appears after the completed list.

The history scan dates newly observed completions as **By [date]**, an upper bound rather than a fabricated completion timestamp. Entries present at the first readable snapshot, or after a reordered/reset list without a matching prefix, show **Date not recorded**. Gaps remain unavailable at the requested hour; a later observation never fills an earlier gap or changes earlier completion counts. Repeated focuses retain their separate ordinals.

Click a row to expand its actual English game-localisation description inline; click again to collapse. The expanded details include the base duration from the authored focus cost and recorded content's focus-day define, before saved progress or country modifiers. Continuous focuses have no finite duration. Names and descriptions use authored localisation keys, with line breaks preserved; borderless artwork uses focus definitions and GFX declarations. Missing assets, scripted durations and unresolved scripted text remain unavailable. There is no country summary, campaign-mode badge, completion tick/label or About panel in the widget.

Requests share the session resource cache and validate source/revision/branch/country identity. The native loader projects all countries in one branch scan and caches those projections under a shared byte budget. Each country loads its full compact history and static PNG artwork once; following playback uses exact local segment lookup, with no hour-triggered fetch, cancellation or loading flash. Cache accounting includes descriptions, warnings, history rows and decoded thumbnails. Content and asset warnings are available under Data diagnostics in the widget settings only while editing the layout. It uses the existing cancellable loader and response channel. Rebuild both viewer and desktop (or the browser bridge) after changing the endpoint.

## Campaign selection

Load adds a campaign to the session; loading the same file again reuses it. The first successfully opened campaign becomes the default. Additional campaigns, failed opens, layout switches and widget edits do not change that default. Change it explicitly in the sidebar. Unloading the default selects the next loaded campaign; unloading the last one clears the default and releases the standalone native map. Reconnecting a stale recording first retires that native snapshot before replacing its lease. If retirement is temporarily unavailable, the existing binding remains available for Retry or Unload. A failed reopen then frees its session slot. The standalone map tab follows the chosen default as well.

Every widget settings popup offers Default campaign or an explicit campaign. Default widgets resolve against the current default's first configured track; explicit choices keep their track IDs. Advanced track selection supports branch and multi-track comparisons. Missing sources, branches and anchors stay unavailable rather than falling back to a different campaign. Pinning stores an explicit track selection. A default change pauses playback at the default track's start; comparisons retain the shared calendar or anchor alignment.

`campaigns.ts` keeps campaign slot identities independent of layout drafts and resolves default selections before passing widgets to their renderers. Cancelling a layout edit or switching layouts does not close campaigns. Templates save the default-versus-explicit choice and semantic source slots, never paths or source handles. Failed opens reserve no saved slot. Unloading frees a session binding. Use **Load into** in Recordings to rebind an empty saved slot, including at the slot limit; track IDs and pins stay intact. On restart, reopen recordings into their slots; the first successful open establishes that session's default. Older unpinned main-track widgets migrate to Default campaign; explicit multi-track and pinned choices remain fixed.

## Campaign map controls

The gear at the right of the Campaign map top bar opens a compact pop-down for Fog of War, campaign graphics overrides and installed cosmetic mods, recording sessions/branches, and PNG export. The map widget header uses the same controls with overrides scoped to that widget and campaign. Branch selection is session state and resets playback without marking the dashboard layout dirty. The country picker supplies the standalone map's viewing country. Map-colour selection, Fit map, and the shortcut to application Settings are removed, including their unused UI and native command paths.

Main Settings owns global graphics and cosmetic-mod defaults without requiring a loaded recording. Campaigns inherit these defaults, and map widgets inherit their campaign settings. Explicit graphics and mod overrides apply independently; Use global defaults or Use campaign settings clears the corresponding override. Apply persists the chosen scope independently of dashboard layouts. The same MapAppearance component renders all three forms. Installed mods are checked against the local game's checksum manifest and the renderer's supported artwork; unsupported entries explain why they cannot be enabled. Later selected mods take precedence, and the recorded selection can be restored. The browser requires an updated data bridge for these real settings and guards the older bridge from unknown commands. No example Workshop mod is bundled.

Game-content folders and a collapsed Diagnostics section live in Settings. The native folder buttons use system dialogs. Diagnostic reports are requested on demand and include their recording/date identity; they do not add a live diagnostics panel to the workspace. Embedded native header/timeline controls are hidden once the shell owns them. Battle markers and their native rendered details are unchanged. The supported graphics switches gate existing native draws. Anti-aliasing offers Off and the counts reported by the native graphics adapter; texture quality selects authored game variants. Revert to HOI4 settings in main Settings restores graphics inheritance from the configured HOI4 settings.txt without modifying that file. Visual mods search filters installed mods only; when settings are unavailable, its status explains that instead of displaying a disabled search field.

Reported capture gaps appear as red marks below the shared scrubber, clipped and aligned to the default campaign's selected branch. Hover shows dates and the recorded reason; the slider announces a gap at its selected hour for keyboard users. These are reported capture losses, which can overlap recovered frames, rather than a new full-history validation scan. Older bridge executables without gap metadata are identified in Diagnostics; absence of the field is not proof of complete recording coverage.

## Appearance

Settings uses a left-aligned column capped at 760px for all panels. The HOI4 installation, Paradox user folder and replay folder use compact labelled rows with Browse buttons in one Folders panel; labels stack above their fields when space is limited. Missing or invalid game locations open Settings on startup. Game-folder selections remain drafts until Apply game folders. Desktop and browser use the viewer's existing folder validation and `viewer.json` persistence; browser changes reconfigure its running data adapter without closing recording sources. Mod descriptors remain resolved through the Paradox user folder and the existing recorded-content resolver.

The compact global Graphics panel keeps native-map VSync, Interface scale and map graphics in one two-column control grid, falling back to one column in narrow panels, with one shared reset/apply area. Interface scale changes app text, menus and buttons. Both values start from HOI4 preferences. Browser preview shows Browser zoom as text instead of an unavailable scale dropdown, and explicitly labels native VSync as desktop-only. There are no resolution, window-mode or refresh-rate controls; widgets resize only through the existing dashboard Edit handles and the standalone campaign map fills its container. Browser development cannot control native presentation or app UI scale. Use the [isolated desktop workflow](../crates/desktop/README.md#test-without-taking-over-the-screen) to exercise native settings and folder dialogs without taking over the visible desktop.

Settings uses the same 10px outer and section gaps as Overview. Theme presets stay compact, with individual colors under Customize theme. Campaign map fills its available area without an embedded native panel margin.

[theme.ts](src/theme.ts) owns preset palettes, validated persisted colors and derived text colors. [Settings.tsx](src/Settings.tsx) offers live preset selection and per-color customization, including a light theme. All interface CSS uses semantic theme variables; native map content keeps the renderer's game-derived colors. Appearance persists separately from dashboard layouts and falls back to a usable session theme if storage is blocked.

Selected sidebar entries use a subtle theme-colored tint with normal text and border colors, alongside the normal hover treatment. The built-in atlas and daylight themes use blue selection colors. Persisted copies of their former red defaults migrate to the updated presets; customized palettes retain their chosen colors.

[Tooltip.tsx](src/Tooltip.tsx) owns the single hover tooltip for the interface. Use `data-tooltip` for hints rather than native `title` attributes or separate tooltip instances. Hover and keyboard focus wait 500 ms; the most recent target replaces the previous one, including when a filename retains focus while the pointer moves elsewhere. Tooltips share themed typography, wrap within the viewport, and dismiss on Escape, activation or navigation. Existing accessible names remain on their controls; the visible hint is associated through `aria-describedby`.

## Adding a widget

Register its type, configuration version, supported time modes, data product and size limits in [definitions.ts](src/dashboard/definitions.ts), then register its renderer in [widgets.tsx](src/dashboard/widgets.tsx). `registerWidgetDefinition` supports registering additional code-defined products before mounting. The add menu, default configuration, query builder and layout constraints consume that definition. Widgets use `WidgetRuntime` for queries, tracks and playback; they never open files or start their own clock. Keep renderer-specific controls beside the widget when extending beyond the prototype's shared settings.

The current country data product provides all supported country measurements together, so changing a chart metric does not start another query. New data products need a typed request/result in analytics, its native adapter and a renderer; no user query language is involved. Configuration versions are independent of the dashboard format. The first unversioned prototype migrates to each widget's initial version; unknown widget types and future configuration versions survive saving as unavailable entries.

`npm run test:ui` runs pure model, persistence and subscription tests with Node's built-in runner. These tests do not need the game, a browser or a recording corpus.

## Values and charts

These guarantees apply to future data widgets; the placeholder panels display no measurements.

Keep exact decimal-string values and scales until formatting. Use integer arithmetic for displayed values; JavaScript floating point is only for chart geometry. Distinguish recorded zero from missing, country-absent, truncated and unavailable samples.

The bounded history response may contain first/last samples and minima/maxima for an interval. It does not retain the complete path inside that interval. Break charts across missing coverage and show aggregation honestly. Do not join branches or give carried samples a new acquisition time.

## Date and time controls

Use the game's fixed 365-day calendar, not JavaScript's Gregorian `Date` arithmetic. The displayed hours are **01:00 through 24:00**, not 00:00 through 23:00. Keep raw signed replay hours as the underlying value.

Respect inclusive branch bounds and validate From ≤ To. A gap can lie inside valid bounds; a parent's load hour does not extend a branch's recorded range. For hours before the supported calendar epoch, preserve the raw value and show explicit unsupported-date behavior rather than inventing dates or silently clamping data.

Calendar navigation changes a draft. Applying the selection commits the range; browsing months or years must not issue history queries. Keep the popup compact and its text readable. Keyboard navigation must leave the focused day visible; Escape returns focus to the trigger. Keep one picker open at a time and preserve visible focus when committing a year.

The calendar's First date and Last date shortcuts select the available endpoints; they do not start or stop playback. Header dates still require Go to seek. Playback speed is displayed in game hours per second, with presets and a custom numeric value. The controller's existing speed limits remain provisional UI limits, not measured rendering capacity. End-to-end maximum sustainable speed validation is deferred while benchmarking owns the machine.

## Requests and navigation

Do not display an obsolete response over a newer request. Use the host's cancellation and file-revision contract, and refuse stale-result map navigation when the file changed. Follow [AGENTS.md](../AGENTS.md) for the full check set.

Global map graphics and application preferences follow the configured HOI4 settings.txt by default. Revert to HOI4 settings restores inheritance; manual graphics edits opt out, while changing only cosmetic mods preserves graphics inheritance. Existing saved overrides are retained. Defaults refresh at startup, recording opens and settings reads, without per-frame file polling or writes to installed content. Unsupported renderer options are unchanged.

Campaign map and map widgets share MapControls. The widget uses a compact header gear with its source/live/layout options under Widget settings in the same pop-down. Graphics/mod controls remain visible without a source, disabled with a load-campaign message; loading/backend failures never remove the section. Each widget resolves its own campaign before loading scoped settings. Widgets with different artwork or texture quality use distinct native content variants; matching variants still share assets and recording decoders. Fog/perspective travels with its native view target; PNG export addresses that widget rather than the standalone map. Native integration requires rebuilding both host and viewer.

## Shared popup UI

Use [Popover.tsx](src/ui/Popover.tsx) (`usePopover`, `Popover` and `PopoverHeading`) for interactive popups: widget and map settings, country selection, date/time, playback speed, recordings, widget picker and layout saving all use it. It owns viewport placement, resize/scroll tracking, opening visibility, initial focus via `data-popover-autofocus`, Escape dismissal, focus return and native outside-click behavior. Only its own toggle events change open state; nested details and popovers cannot unmount the parent form. Top-level panels portal to the document body to avoid transformed grid coordinates; nested panels use `portal={false}` to preserve the native dismissal hierarchy.

Shared panel appearance lives in [Popover.css](src/ui/Popover.css); component styles only define width and internal content. Reuse `dashboard/CountryPicker.tsx` with `field` for searchable widget countries and the shared country-data cache. Simple finite choices use native `select` controls; do not create a separate positioning implementation for their menus. Tooltips retain their existing single shared `Tooltip.tsx` implementation because hints must not dismiss menus or hide native maps.
